### 0v. 🆕 FILED 2026-07-25 — T135: repo-hygiene gates (**bundles §0n + §0p + §0u + §0m**). Needs a spec.

**Why one ticket and not four.** Every strand needs the identical plumbing — a `just` recipe + a
`commands` role in `project/stacks-policy.json` + a pre-commit hook + a `just sdlc-doctor` check —
across the same repos. Four tickets = four passes over the same files and four rounds of the same
review. **Do not re-split it.**

| Strand | What | Grounding |
|---|---|---|
| A | gate parity — stack-matched checks + pre-push coverage | §0n |
| B | required human-facing files (`README.md` et al.) with a **substantive** bar | §0p |
| C | license audit incl. **vendored** trees | §0u |
| D | Infisical **corpus** enforcement (right-sized, see below) | §0m |

🔴 **The two ACs that carry the real difficulty** — do not treat them as boilerplate:
- **AC7: every gate must be proven RED against a real violation, and must start GREEN on the current
  tree.** This project has shipped a vacuous gate **three times** (T127's empty manifest printing
  `0 managed skill(s) match the lockfile ✓`, T130's `enforce_raw`, and the `wom7md` hook that simply
  did not exist until this session). A `README.md` file-exists check would pass `wom7skills`' 16-line
  stub — that is the whole trap.
- **AC8: never add a hook that cannot pass for structural reasons.** Measured precedent from this
  session: `osv-scanner` exits **128** ("No package sources found") in a repo with no lockfile, so it
  was deliberately omitted from `wom7md`. A permanently-red hook trains people to bypass the stack,
  and `--no-verify` is prohibited. **Run each hook in each target repo before adding it.**

**5 OWNER QUESTIONS — answer these before writing the spec:**
1. **What is the substantive bar for a README?** Required sections · a minimum length · a "what is
   this / how do I run it / where are the docs" triple? A file-exists check is vacuous.
2. **Which files are universal vs per-stack?** `LICENSE`, `CONTRIBUTING.md`, `SECURITY.md`,
   `CODE_OF_CONDUCT.md`, `CHANGELOG.md`, `.editorconfig` — currently **zero** repos have the first four.
3. **Which license do the w0m repos themselves declare?** A business decision, not a lint. The gate
   can require *a* license file without choosing which.
4. **Extend pre-push to all repos, or keep it `wom7web`-only by design?** Cost = push latency ×6.
5. **Retire `ruff` from the Rust and TS repos, or keep it for incidental Python?**

**Cheap win already specified (AC11):** `wom7api` and `wom7ext` lack `private: true` (wom7web and
wom7cfworkers have it) and **no repo declares a `license` field** — one accidental `npm publish` from
shipping an unlicensed package. Two-line fix, do it even if the rest slips.
