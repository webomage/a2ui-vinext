## Summary

**Finish F1 — access-token-only data components** — `refreshToken` is threaded from ~50 CP parent pages into ~40 admin islands (**~90 files / 242 refs**, 2026-07-19 inventory) → the refresh token serializes into island props in the DOM (XSS exposure). Scope is systemic, NOT 3 components. **De-risk finding:** `createAdminClient` already auth's via a Bearer header from `accessToken` and only `setSession()`s when `refreshToken` is passed → dropping the prop makes those consumers auto-fall-back to Bearer-only (data queries unaffected). So the sweep = (a) stop parents sourcing/passing `refreshToken` (mechanical, ~50 `.astro`), (b) convert the 2 real `setSession(refresh)` consumers `CandidateManager` (cp+web) + `HealthDashboard`/`ResourceLibrary` args to Bearer-only, (c) drop now-unused `refreshToken` props. Verify: build + CP admin data-load smoke across pages. Do as a dedicated focused pass (whole-CP blast radius). Cookie already HttpOnly (F1 stage 3, live).

## Acceptance criteria

- [ ] AC1 — Remove `refreshToken` extraction from CP parent pages: Eliminate `Astro.cookies.get("sb-refresh-token")` extraction and `refreshToken` prop passing across all `apps/cp/src/pages/**/*.astro` files.
- [ ] AC2 — Convert `adminClient.ts` and `vaultStorage.ts` to access-token Bearer authentication: Update client instantiation in `apps/cp/src/lib/adminClient.ts` and `vaultStorage.ts` to authenticate strictly via Bearer headers using `accessToken`, removing `setSession(refresh_token)` dependencies.
- [ ] AC3 — Transition `CandidateManager` to access-token-only: Update `CandidateManager.svelte` (in `apps/cp` and `apps/web`) to initialize Supabase client via Bearer authorization with `accessToken` alone.
- [ ] AC4 — Deprecate and remove `refreshToken` prop across all Svelte islands: Remove `refreshToken` from prop interfaces and script signatures across all CP interactive components, eliminating DOM serialization of refresh tokens.
- [ ] AC5 — DOM token leakage automated audit: Implement an automated gate or lint check verifying that zero `.astro` templates bind or serialize `refreshToken` into client component attributes.
- [ ] AC6 — Full CP data smoke verification: Verify across key CP routes (`/todos`, `/guild/units`, `/guild/bounties`, `/content/posts`, `/profile`) that authenticated data fetching and mutations function correctly with access-token-only auth.

## Definition of Done

T80 is done when: no `apps/cp/src/pages/**/*.astro` extracts `sb-refresh-token` or passes
`refreshToken` to an island (the ~90-file / 242-ref sweep), `adminClient.ts`/

client-component attribute, and `/todos`, `/guild/units`, `/guild/bounties`,
