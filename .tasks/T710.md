# T710 — Orca Embedded Browser: Load and Persist w0m-ext MV3 Extension in Electron Browser Session

## Summary

Enable installing, loading, and persisting the `w0m-ext` Manifest V3 browser extension inside Orca Desktop's embedded Electron browser (`w0m-pr/orca` + `w0m-ext`). Investigate Electron's `session.extensions.loadExtension()` / `session.loadExtension()` lifecycle on the Orca browser partition, wire a CLI/settings/auto-load hook (`orca browser extension load <path>` or `just orca-ext-install`), and expose extension popup/side-panel or content-script injection across Orca embedded browser tabs.

## Acceptance criteria

- [ ] AC1 — **Electron Partition Extension Loader in `w0m-pr/orca`:** Inspect how Orca Desktop creates `WebContentsView` / `BrowserView` sessions for embedded browser tabs, and wire `session.extensions.loadExtension(extPath, { allowFileAccess: true })` (Electron MV3 extension API) with persistent extension path configuration.
- [ ] AC2 — **`w0m-ext` Build & Auto-Provision Recipe (`just orca-ext-install`):** Build `w0m-ext` (`dist/` unpacked MV3 bundle) and provide a 1-command `just orca-ext-install` recipe (plus `orca` CLI subcommand) that registers `w0m-ext` into Orca's embedded browser session.
- [ ] AC3 — **Content Script, Service Worker & Action Popup Support in Embedded Tabs:** Verify that `w0m-ext` content scripts, MV3 background service worker, and extension action popup/toolbar trigger work inside Orca embedded browser tabs.
- [ ] AC4 — **Automated Verification & Upstream/Fork PR Readiness:** Add automated test coverage verifying extension loading in Orca's browser session and document the workflow in `.agents/reports/` (`w0m-web/docs/reports/`).

## Definition of Done

Per [`w0m-web/openspec/SPEC-AUTHORING-STANDARD.md`](../w0m-web/openspec/SPEC-AUTHORING-STANDARD.md):
- Acceptance criteria AC1–AC4 verified with `w0m-ext` loaded and active inside Orca's embedded browser.
