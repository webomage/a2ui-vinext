# T274 — Review Antigravity disk audit (`163.93 GB` / 66 projects) and set up archiving/handoff processes

## Context

On `2026-08-24 08:53`, **Antigravity** dropped an unrequested file into `wom7web/`:
`docs/reports/PROJECTS_CATALOG_AND_CLEANUP_AUDIT_2026.md` (248 lines, untracked at the time) — a read-only disk-space audit of `~/Projects` (`155.16 GB` across 103 entries / `163.93 GB` across 66 top-level projects, `21.36 GB` identified as cleanable cache/build artefacts).

The numbers were real and useful (`node_modules`, `.venv`, `target/`, `.astro`, `.turbo` sizes across `@wom`, `_proj`, `_self`, `_arc`, `@mob`, `@k7`), **but**:

1. **No provenance header** — the file did not record *who* generated it, *when* (`2026-08-24T08:53`), or from *which scan script*; the numbers were already a point-in-time snapshot that would rot the moment anything was cleaned (`T67` anti-rot rule).
2. **Unsafe recommendations mixed with safe ones:**
   - Phase 1 mixed safe cache deletions (`node_modules`, `target/`, `.venv`) with **`rm -rf` of entire project directories** (`wom7cfworkers`, `dockerify-android`, `.wrangler-noop`) — deleting a directory is a human decision, never a batch command.
   - Phase 1 included **Artemio's `_self/delivery` (`2.65 GB`)** and **Elena's `_proj/bridgeroad` (`876.99 MB`) / `_proj/Evercred` (`3.75 GB`)** — client/colleague workspaces have their own lifecycle (`T265`, `T302`) and should not be wiped from a w0m cleanup script without explicit approval.
3. **`wom7web` was reported at `53.93 GB` with only `4.17 GB` matched as cleanable** — the remaining `~49.76 GB` was unexplained in the original report.
4. **No process existed** for:
   - **Archiving cold projects to `_arc`** (checklist: git clean? pushed? strip `node_modules`/`target`/`.venv` *before* moving? update any workspace configs?).
   - **Antigravity -> Claude Code handoff** so background audits/research land with a ticket link and provenance instead of appearing as mystery untracked files.
