# T358 — Client Alfa Safety Floor: Fix RLS policies, definer grants, and verify Stage 3 exit

## Summary

Measured live on 2026-09-14 while running `just tasks plan --check` for the Client Epic transition:
1. `authz-probe` failed on probe `B1-internal-blueprints`: `psql ... ERROR: permission denied for function is_admin`. The policy `Unified read access` on `public.blueprints` and `public.projects` (rewritten in migration `20260914180000`) contains `public.is_admin()`. Because those tables are `FOR SELECT TO public`, PostgreSQL checks execute permissions for `anon`, which has no grant on `is_admin()`.
2. Probe `C1-dead-role-strings` flagged 2 violations: `profile_skills` and `verified_credentials` policies match `bot` in `p.subject_type in ('ai', 'bot')`.
3. Probe `G2-definer-acl-explicit` flagged 1 violation: `public.wom_can_uri` still has PostgreSQL default `=X/postgres` PUBLIC execute grant.
4. Probe `AC4-blanket-beside-scoped` flagged 3 violations: `orgs`, `org_units`, `unit_edges` have `Admin manage *` policies defined `FOR ALL` (including SELECT) alongside `Public read *` blanket SELECT policies (`USING (true)`).
5. Resolving these 4 policy and grant defects allows `just authz-probe --enforce` to pass 100% green (18/18), which re-certifies Stage 0 ("Safety floor") and satisfies the exit criterion for Stage 3 ("Contracts & delivery visibility"), which already has all 3 constituent tickets ([T198](project/tickets/T198.md), [T117](project/tickets/T117.md), [T325](project/tickets/T325.md)) 100% done.

## Acceptance criteria

- [x] AC1 — Remove `public.is_admin()` from `public.blueprints` and `public.projects` `Unified read access` RLS policies (both are `FOR SELECT TO public`), relying on hat-scoped `public.wom_acting_in('admin', 'manager', 'member')` and `public.wom_acting_is('admin')`, ensuring `anon` SELECTs on `blueprints` succeed without `ERROR: permission denied for function is_admin`.
- [x] AC2 — Remove `'bot'` dead role string from `profile_skills` and `verified_credentials` RLS policies (replace with `'agent'` or check `profiles.subject_type in ('ai', 'agent')`) to eliminate probe `C1-dead-role-strings` failure.
- [x] AC3 — Revoke `EXECUTE` on `public.wom_can_uri` from `PUBLIC` and `anon` (`REVOKE EXECUTE ON FUNCTION public.wom_can_uri(text, text) FROM PUBLIC, anon;`) and grant to `authenticated, service_role`, eliminating probe `G2-definer-acl-explicit` failure.
- [x] AC4 — Eliminate redundant scoped `SELECT` arm beside blanket `SELECT` on `public.orgs`, `public.org_units`, and `public.unit_edges` by separating `Admin manage *` policies into `FOR INSERT`, `FOR UPDATE`, `FOR DELETE` (and declare in `authz-public-tables.jsonc` if applicable), eliminating probe `AC4-blanket-beside-scoped` failure.
- [x] AC5 — Execute `just authz-probe --enforce` and verify it exits 0 with 0 RED and 0 UNMEASURED across all 18 probes.
- [x] AC6 — Execute `just tasks plan --check`, verifying that Stage 0 ("Safety floor") and Stage 3 ("Contracts & delivery visibility") exit criteria pass cleanly. Update `.w0m/sdlc.json` to record Stage 3 `exit_met`.
