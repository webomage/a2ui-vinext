# T211 — Co-locate ticket architecture diagrams (.mmd) with real-time sync to GitHub Issues and zero-width-limit browser viewer

## Summary

In terminal and TUI coding agents (Orca, Claude Code CLI, AGY terminal), horizontal width constraints (<100 columns) prevent Mermaid diagrams from rendering properly, collapsing into unreadable ASCII or truncated text. Historically, agents delayed generating `.mmd` diagrams until writing a post-session report (`.agents/reports/`), which risked diagram loss when sessions ran out of quota or disconnected mid-flight, and decoupled diagrams from the ticket single source of truth (`.tasks/T##.md`).

This change establishes first-class `.mmd` diagram co-location and synchronization for tickets:
1. **Sibling Co-location:** Tickets in `.tasks/` can have any number of sibling `.mmd` diagrams named `T{id}-*.mmd` or `T{id}.mmd` (e.g. `T434-system-one-contract.mmd`).
2. **GitHub Issue Projection:** `scripts/sync_github.py` (`just sync-tickets`) automatically discovers sibling `.mmd` files for each ticket and projects them into the GitHub Issue body inside collapsible `<details open><summary>📊 {Title}</summary>\n\n```mermaid ... ```\n</details>` blocks, leveraging GitHub's native SVG Mermaid renderer.
3. **Local Zero-Width-Limit Viewer:** Adds `just diagram <T##>` (and `just diagram <path.mmd>`) to render any `.mmd` diagram as an interactive HTML page with zoom/pan and open it directly in the default browser.
