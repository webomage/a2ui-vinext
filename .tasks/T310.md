# T310 — Admin unified business access, BridgeRoad entity seeding, and universal project hat switcher in CP

## Summary

Owner ask 2026-09-03: *"so I want to see all the business, contracts and clients sides and put on any hat from any project"*.

This ticket delivers three connected capabilities:
1. **BridgeRoad Entity Seeding:** BridgeRoad (`_proj/bridgeroad/BridgeMvp`) currently exists only on disk and in `clients-policy.json` as a half-managed project. It is absent from `public.clients` and `public.projects`, so the CP business suite has no records to display. Seed `BridgeRoad` as a client, `BridgeRoad MVP` as an active project, and an initial contract record so it is visible and operable live.
2. **Admin Unified Business Access:** Under the current two-domain model, accessing `cp.webomage.com` forces even authenticated admins into strict member view (`effectiveRole = "member"`), which hides the entire "Business" group (Clients, Contracts, Projects, Invoices) and triggers member RLS restrictions. Ensure admins have seamless access to the full business console without forced role degradation.
3. **Universal Project Hat Switcher:** On 2026-08-11, the owner established: *"Admins may wear any hat available on a project, assigned or not, filled or not."* Currently, `public.hats` has 0 rows and `/api/project/hats` only checks profile-assigned rows, causing `MyProjectHats.svelte` to render blank. This ticket updates the CP project hats API and UI so that admins can browse all active projects, view all available units, and wear any unit hat on demand.

## Acceptance criteria

- [x] **AC1 — BridgeRoad entity seeded live in PostgreSQL.** A committed migration seeds `BridgeRoad` into `public.clients` (name: `BridgeRoad`, company_name: `BridgeRoad`, status: `active`), a project into `public.projects` (name: `BridgeRoad MVP`, status: `active`), and a supporting contract in `public.contracts`. Verified live in `public.clients` and `public.projects`.
- [x] **AC2 — Admin business suite visibility without forced demotion.** Admin users accessing the Control Panel retain admin capabilities and full navigation visibility across Business routes (`/business/clients`, `/business/projects`, `/business/contracts`, etc.), preventing accidental forced degradation to member view.
- [x] **AC3 — CP Project Hats API lists all projects for admins.** When called by an admin (`wom_acting_is('admin')`), `GET /api/project/hats` returns all active projects from `public.projects` rather than returning an empty array when no pre-assigned `hats` rows exist.
- [x] **AC4 — Universal hat assignment and wear for admins.** Admins can select any available unit from `public.units` on any project and wear it. The backend provisions or activates the `hats` record for `(admin_profile_id, unit_id, project_id)` and records it in `worn_hats` via `wom_wear_hat`.
- [x] **AC5 — Project Hat Switcher UI active in CP.** `MyProjectHats.svelte` renders an interactive project and unit hat selector in the Projects dashboard (`/business/projects`), allowing admins to switch hats across projects and verifying that the worn hat reflects accurately.
- [x] **AC6 — End-to-end verification.** Verify in CP that: (1) BridgeRoad appears under Clients, Projects, and Contracts; (2) Admin has unobstructed access to Business routes; (3) Admin can select any project and wear any unit hat.

## Definition of Done

BridgeRoad is present as a live client, project, and contract in PostgreSQL and visible in CP; Admin users retain full business console access across CP domains; `GET /api/project/hats` returns all active projects for admins; admins can wear any unit hat on any project through `wom_wear_hat` without pre-existing manual grants; and the CP Projects dashboard provides a functioning hat switcher verified end-to-end.
