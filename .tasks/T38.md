The four apps use `@tailwindcss/vite` (v4, no config file), whose automatic source detection does
**not** scan the linked `@webomage/ui` package. Any utility class used *only* inside a shared
component was therefore purged from the app CSS — a silent under-styling defect rather than a
build error, which is why it survived unnoticed.

It surfaced through a visible symptom, not a test: `flex-row-reverse` was absent from the header's
compiled CSS, so the language switcher grew the wrong way and shoved search and auth aside. That
was worked around inline for the header first (`c54a0bc2`); T38 is the root-cause fix.

The fix was a **one-line off-by-one path correction** — `../../../` → `../../../../packages/ui/src`
— in each app's CSS entry. The original row proposed `@source "../../packages/ui/src/**/*.{astro,svelte,ts}"`;
what actually shipped is a bare directory `@source`, which is the form live in the tree today.
