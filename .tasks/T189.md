# T189 — extend the Python type gate to `wom7api/scripts`

## Summary

[[T188]] gated **`wom7web/project/scripts`** at zero and named this as the obvious next increment.
`wom7api/scripts` is the other half of the estate's tooling code — `gate_advance.py`,
`sdlc_doctor.py`, `check_ticket_paths.py`, `get_keys.py` — and it is still unchecked. The gate,
the config shape and the registry home all exist now; this is applying them to a second path.

🔴 **CORRECTED AT THE START GATE, 2026-08-08 — this ticket's own filing numbers were inflated, and
the correction is the most useful thing in it.** Filed hours earlier claiming *"56 findings, more
than twice T188's, 43% of them in one file"*. Both claims are artifacts of **how mypy counts**, not
of the code:

- **`mypy` emits one error line per UNION MEMBER, not per site.** A single `.get()` on a
  `bool | str | int | float | Sequence[JSON] | Mapping[str, JSON] | None` produces **six** error
  lines. Across the set, **25 `union-attr` lines collapse to 8 real sites**.
- ⇒ **56 error lines = 29 distinct `(file, line)` sites.** Against T188's 27, this is
  **the same size of job**, not double.
- ⇒ The *"24 findings in one 73-line file (43%)"* claim is **void**. `audit_supabase_posts.py` has
  **5 sites** (lines 42, 44, 46, 51, 52) — **tied** with `gate_advance.py`, not an outlier.

⚠️ **This is the estate's own "count the thing, not its container" trap** ([[measurement-traps]]),
committed inside a ticket about measurement rigour, by the agent who had just archived [[T188]] for
the same class of defect. **The count was never re-derived after the first `mypy` run — the tool's
output was read as a defect count when it is an emitted-diagnostic count.** Left visible rather
than quietly restated, because the *filing* is what a future reader would otherwise trust.

## 🔴 One finding that is already worth something, independent of the typing

`audit_supabase_posts.py` is **live** — `wom7api/justfile:607` runs it as part of `audit-media`.
But the recipe line is:

```
-@cd ../wom7api && infisical run … python3 scripts/audit_supabase_posts.py || echo "⚠️ Infisical run failed or skipped for audit-media."
```

**Both `-` and `|| echo` swallow failure**, so the recipe cannot fail no matter what the script
does — confirmed 2026-08-08 by reading `justfile:605-607`. A live 73-line script sits behind a gate
structurally incapable of reporting a problem — [[D37]]'s shape again, and the same *vacuous green*
class this estate keeps finding.

numbers were inflated; the fail-soft recipe is real either way. It is worth noting that the inflated
count is what drew attention to this file at all — a wrong number led to a right finding, which is
luck, not method.
