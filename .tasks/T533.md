# T533 — Upwork linked knowledge store

## Summary

Owner, 2026-10-01: the most valuable part of a proposal is the extra answers submitted with the project details; messages, proposals and contracts must be linked to each other and all synced; find the best storage in our own stack; later process it all with AI, search mentions and proofs, and enhance the resume in Resume Studio.
Research is done and recorded in `.agents/reports/2026-10-01-t533-upwork-linked-store-research.md`. The findings that shape the work:

- **The screening answers exist and were dropped.** 725 of 1,782 proposals carry `questionsAnswers` (1,894 pairs, 550 KB) in the local archive `proposals_archive.jsonl`, and none reached Postgres. So did the terms (rate, duration).
- **Project details are not in the response we request:** the job block holds only `id` and `title`. Whether Upwork can return the description, budget and skills is unverified.
- **Links are mostly missing:** 6 of 1,782 proposals link to a contract (73 are Hired); 9 rooms name a proposal but are unlinked; 40 of 55 rooms have no messages and all 170 messages have an empty `direction`.
- **Storage:** Postgres with pgvector and full-text, one owner-scoped evidence table beside the T468 mirror; the raw response kept in the private `upwork` bucket. The corpus is about 5 MB of text.
- **The existing vectorize triggers are idle** (`app.settings.cf_worker_url` unset) and write into `public.documents`, which is not owner-scoped; they must not be reused as they are.

## Acceptance criteria

- [x] AC1 — **Source verified.** An owner-run, read-only schema probe (`just upwork-schema-probe`) records which fields the Upwork MCP or GraphQL can return for a proposal (screening answers, job description, budget, skills, client) and for an offer and a contract, and which MCP tool fetches an offer. The result is committed as a report; no secret is printed.
- [x] AC2 — **Spec.** An OpenSpec change for the two layers (source layer, evidence layer), the link table with `link_basis` (`room`, `offer`, `title`) and a `confirmed` or `inferred` state, the retention and masking rules, and the decision on the dormant vectorize triggers (retire or repoint). Validated with `openspec validate --strict` and `just spec-standard-check`.
- [x] AC3 — **The answers reach the database.** The sync writes `questions_answers` and `terms` for every proposal; a backfill loads the 725 archived proposals; a row-count probe proves 1,782 proposals and 1,894 pairs, and that no answer belongs to another member.
- [x] AC4 — **Links.** Every room is linked to the proposal it names (55 of 55); proposal to contract uses the offer key where AC1 shows it can be fetched and the title match, labelled `inferred`, otherwise; a probe reports how many Hired proposals have a confirmed contract. Ambiguous matches stay unlinked.
- [x] AC5 — **Messages are complete or the gap is named.** The 40 empty rooms are re-fetched once the feed is alive ([[T535]]) and each is either filled or recorded as empty at the source. Findings so far: `roomStories` already carries the `StoryFilter` fix and throws on schema errors (T89), so the old silent-zero bug is not the cause; all 40 empty rooms were created on 2026-07-20 (the first import) and were retried on every successful run for 61 days without getting a message, which points to rooms that are empty at Upwork, **but that is inferred, not proven**; the poller fetches messages for at most 10 rooms per run (`MAX_NEW_ROOM_FETCH`) and one failing room aborts the loop for the rest (the whole room loop sits in one `try`). `direction` is empty on all 170 messages because the poller never sets it; derive it from the author and test it.
- [x] AC6 — **Evidence layer.** An owner-scoped table of passages with a `tsvector` and a `vector(1024)` embedding, RLS on `profile_id`, built from answers, cover letters, messages and contracts; red probes show another member and an admin in the member hat see none of it. The embedding model and its cost are measured on 100 passages before the full run.
- [x] AC7 — **Search.** A hybrid search (full-text, vector, merged by rank) returns passages for a technology, client or phrase with their proposal, room and contract, tested with fixtures and a live read-only query.
- [x] AC8 — **Proofs in Resume Studio.** A highlight can reference evidence passages; the `w0m-personnel` assistant cites them and its no-invention check reads the cited text; the member approves every change ([[T499]], [[T501]]).
- [x] AC9 — **The Me pages show it.** Proposals show their screening answers and terms; the status tabs and counts remain correct past 1,000 rows (fixed 2026-10-01).
