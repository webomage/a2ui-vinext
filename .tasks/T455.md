## Summary

Build a read-only participating open-source projects and pull requests inventory surface for member profiles in the User Control Panel (`apps/cp`), showcasing all ecosystem-tracked open-source dependencies and upstream contributions across both the `casualuser` GitHub account and the `webomage` GitHub organization.

The tool provides members with an aesthetic, read-only transparency dashboard showing:
1. All participating open-source software projects used in the ecosystem (`headroom`, `omlx`, `orca`, `tart`, `tart-guest-agent`, `serena`, `claude-obsidian`, `webtorrent-desktop`).
2. Fork remotes and ownership status under `webomage` (organization) and `casualuser` (personal account).
3. Live status of active upstream pull requests, patches, enhancements, and fixes contributed back to the upstream repositories.
4. Clean separation from the existing Admin developer tools (T378), ensuring member profile access is strictly read-only, performant, and cached.

## Acceptance criteria

- [x] **AC1 — Read-Only Participating Projects Data Layer**: A typed API/service endpoint in `apps/cp` exposes participating open-source repositories, metadata (upstream URL, fork URL, description, active branch, sync status), and active pull requests without requiring admin privileges.
- [x] **AC2 — Dual GitHub Identity Attribution**: The inventory schema explicitly tags and differentiates forks and contributions originating from the `webomage` GitHub organization vs personal `casualuser` (`casualuser@gmail.com`) GitHub account.
- [x] **AC3 — Member Profile Inventory View in CP**: A dedicated read-only UI component or tab in the member profile/dashboard overview renders the project cards, fork links, upstream tracking status, and live PR badges matching Webomage Design System standards.
- [x] **AC4 — CLI Parity & Caching**: The data layer integrates with or mirrors `scripts/w0m_prs.py` discovery logic with an in-memory/static cache to prevent rate-limiting GitHub API requests.
- [x] **AC5 — Verification & Tests**: API unit tests, component tests, and typechecks pass organically (`pnpm --filter cp build` and `just prs-test`).
