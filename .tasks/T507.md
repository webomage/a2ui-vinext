# T507 — Deploy Observability & Hygiene: Progress Bars, Build Warnings Audit, and Test Runner Lazy Init

## Summary

Following live deploy `2026.09.30-1790800772` and build verification, the estate deploy flow surfaced several monitoring and hygiene gaps:
1. **Unmonitored Build Warnings & Unstructured Log Dump:**
   Deploy transcripts contained Vite dynamic import warnings, lightningcss global pseudo-class warnings, and unresolved slide asset warnings. The deploy wrapper `deploy_logged.py` matched raw keywords (`error|warn|timeout`) and dumped 310 unclassified lines, mixing benign npm deprecation logs with real build issues and test suite outputs.
2. **Missing Progress Visibility:**
   Deploy steps and app bundle compilations ran silently in sequence without visual step progress bars.
3. **Deprecated Slide CSS Invariant:**
   `apps/web/src/styles/global.css` and `apps/cp/src/styles/global.css` carried legacy background slideshow rules (`--bg-slide-1..4`, `.site-bg-slideshow-legacy`) deprecated since T452 (`packages/lib/src/background.ts`). When imported by `apps/join`, `apps/job`, and `apps/demo`, Vite emitted build warnings attempting to resolve `/assets/info*-web.webp`.
4. **Gauge E2E Top-Level Module Throws & Network Error Blindspots:**
   `tests/bot_chaos_steps.ts` and `tests/bot_security_steps.ts` evaluated `supabaseBase()` at top-level module load time. When Gauge loaded step definitions for specs not requiring Supabase (such as `goldens.spec` or `live-smoke.spec`), ts-node threw unhandled exceptions during module evaluation. Additionally, browser console logging captured `Failed to load resource: 503` without printing the request URL.

## Acceptance criteria

- [x] AC1 — Slide CSS Deprecation: Remove deprecated `--bg-slide-1..4` and `.site-bg-slideshow-legacy` rules from `apps/web/src/styles/global.css` and `apps/cp/src/styles/global.css`, cleaning up unneeded duplicate assets in `apps/join`, `apps/job`, and `apps/demo`, ensuring 0 Vite asset resolution warnings.
- [x] AC2 — Build Warnings Elimination: Verify and preserve zero build warnings across all 5 apps (`join`, `cp`, `web`, `job`, `demo`) for dynamic imports and lightningcss pseudo-classes.
- [x] AC3 — Visual Progress Bars: Author and wire `scripts/progress.py` into `justfile` app deployments (`_deploy-apps`) and deploy chain wrappers with comprehensive unit tests in `scripts/tests/test_progress.py`.
- [x] AC4 — Structured Deploy Audit & Warnings Monitoring: Enhance `deploy_logged.py` to parse, categorize (build warnings, test suites, runtime/browser errors, tool chatter), write `deploy-logs/deploy-audit-latest.json`, and output a structured audit summary at the end of every deploy.
- [x] AC5 — Gauge Step Runner Lazy Init & Network Logging: Convert top-level `supabaseBase()` calls in `bot_chaos_steps.ts` and `bot_security_steps.ts` to lazy invocations, and add response status logging in `tests/support/hooks.ts` to capture exact URLs on 4xx/5xx responses.

## Definition of Done

- All 5 Astro apps build with 0 warnings.
- `scripts/tests/test_progress.py` and `just deploy-logged-test` pass 100%.
- Deploy log summary categorizes warnings and writes `deploy-audit-latest.json`.
- `goldens.spec` runs without throwing module-evaluation Supabase URL errors.
