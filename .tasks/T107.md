## Summary

**`graphify update .` is a ~40s no-op at the repo root** — found 2026-07-21 while wiring graph refresh into hooks. At `wom7web/` root it prints *"Code graph updated"* and spends the full ~40s rebuild, but **never rewrites `graphify-out/graph.json`** (mtime unchanged after real source edits), and `built_at_commit` stays pinned to an old commit — which also breaks GRAPH_REPORT's own *"compare to HEAD to check staleness"* instruction. Neither `--force` nor `GRAPHIFY_FORCE=1` helps. **Per-directory works** (`graphify update packages/lib` wrote 120 nodes/147 links), so the fault is specific to the root invocation — plausibly the documented "refuses to overwrite when the rebuild has fewer nodes" guard mis-firing on a large graph (27467 nodes / 27149 links). Briefly wired into pre-push and **removed again**: a 40s step that provably does nothing is worse than none, and it reported success. `codegraph sync` (~1s, different tool and index) works and now runs per-commit in all 3 repos. **Action: try a clean graphify-out rebuild / reproduce upstream, then decide whether full graphify belongs on push at all.**

## ✅ RESOLVED 2026-07-28 — DOES NOT REPRODUCE on graphify 0.9.15

Attempted under [[T151]] AC1, which had just been blocked on this ticket. **The root invocation
writes** — so the block was lifted the same hour it was written.
`graphify update .` run from `wom7web/` root, exit 0, ~4 min:

| | before | after |
|---|---|---|
| `graph.json` sha256 | `fd26a35def7cee67` | `28982c61929d033c` |
| size | 24,030,459 B | 54,867,680 B |
| mtime | **2026-07-21T09:40** (untouched for 7 days) | 2026-07-28T20:18 |
| `built_at_commit` | `fe8b072` | **`25903d99`** |
| nodes / links | 27,467 / 27,149 | 48,727 / 88,425 |

🔑 **`built_at_commit` moved to exactly the HEAD recorded *before* the run** — that is the
decisive evidence, not the "Code graph updated" message, which printed in the broken case too.
The 274-commit staleness was real; its cause is gone.

⚠️ **What this does and does not establish.** It establishes that the root update writes on
**0.9.15 today**. It does **not** establish what fixed it — the version in use on 2026-07-21 was
not recorded, so "fixed by an upgrade" is the likely explanation, not a proven one. Closing as
**not reproducible with evidence**, not as "we fixed it".

⚠️ **Two warnings surfaced by the successful run, neither blocking, both worth a look under
[[T151]] AC4** (a health recipe should report them rather than let them scroll past):
- `130 source file(s) produced zero nodes and are absent from the graph` (mostly `evals.json`);
  graphify's own note says a re-run retries them and points at upstream issue #1666.
- `fail-closed: kept 1 node(s) from 1 file(s) that left the scan corpus but still exist on disk`.

⇒ **[[T151]] is UNBLOCKED.** Its AC3 RED proof (*"commit, then assert `built_at_commit` moved"*)
