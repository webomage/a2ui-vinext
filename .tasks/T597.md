# T597 — Orca cross-workspace tab drag-and-drop with confirmation dialog, session rebinding, and UI state sync

## Summary

Implement smooth cross-workspace tab mobility in [`webomage/orca`](https://github.com/webomage/orca) (`w0m-pr/orca`) so terminal and agent tabs can be dragged and dropped (or moved via context menu / shortcut) between the Floating Workspace (`FLOATING_TERMINAL_WORKTREE_ID = "global-floating-terminal"`) and normal project Worktree tab strips using an explicit 4-step transactional flow:

> **1. Start moving (drag-and-drop) → 2. Confirm in UI with session/worktree info → 3. Update session binding → 4. Update UI state**

Grounded in our code audit of `/Applications/Orca.app/Contents/Resources/app.asar.unpacked/out/`:
1. **Renderer DnD & Store Guards:** `FloatingTerminalPanel` (`FloatingTerminalPanel-DxHe-Yjx.js`) and worktree tab strips (`agent-tab-shortcut-launch-SXXoUDAE.js`) currently mount isolated `@dnd-kit` contexts and reject cross-worktree drops (`if (o.worktreeId !== t) return` and `dropUnifiedTab` in `store-DBDq0ZPi.js`: `if (t.worktreeId !== a.worktreeId) return e;`).
2. **Daemon & Agent Hook Scope (`orcad`):** When `orcad` spawns a shell, `worktree-activation` injects a static `ORCA_WORKTREE_ID` environment variable into the child shell, and `~/.orca/agent-hooks/antigravity-hook.sh` posts `worktreeId=${ORCA_WORKTREE_ID}` back to `orcad` (`127.0.0.1:49152/hook/antigravity`), where `orcad-migration-source-retention` checks `t.worktreeId !== o.scope.workspaceId`.
3. **Why the 4-Step Flow Solves It Cleanly:** Instead of silently mutating React state while leaving the underlying session/hook scope out of sync, dropping a tab onto a target workspace opens a confirmation modal with clear session/workspace telemetry, updates the session binding (`orcad` PTY scope + hook `paneKey -> worktreeId` mapping and/or clean `--conversation=<uuid>` session handoff), and then atomically updates the UI tab strip.
