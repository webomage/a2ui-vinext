# T739 — Adopt Google A2UI 1.0 generative agentic UI protocol across w0m-ext (@a2ui/lit 1.0) and w0m-web (@webomage/ui + AI Agent Helper + CP)

## Summary

Adopt **Google A2UI 1.0** (Agent-to-User Interface 1.0 — declarative JSON generative UI protocol announced at https://developers.googleblog.com/a2ui-10-build-delightful-fast-reliable-agentic-experiences/) across the Webomage estate so AI agents stream structured interactive interfaces composed strictly from versioned, pre-approved native components instead of markdown walls of text or executable code injection. Grounded estate audit confirms `w0m-ext` already ships an early `0.8.x` dependency (`"@a2ui/lit": "^0.8.1"` in `w0m-ext/extension/package.json:31` and `<a2ui-surface id="agent-ui"></a2ui-surface>` in `w0m-ext/extension/ui/popup.html:783` / `w0m-ext/extension/src/ui/popup.ts:3`), while `w0m-web` (`@webomage/ui`, `@webomage/webmcp`, AI Agent Helper / consultant chat, and Client Portal) currently has no A2UI 1.0 renderer or catalog validation layer.

## Research Grounding (`w0m-sdlc-research`)

1. **A2UI 1.0 Protocol Capabilities (Google Developers Blog):**
   - Declarative JSON surface updates & incremental streaming (`A2UI Express` compact format) for low-latency agent UI composition.
   - Strict security posture: zero arbitrary HTML/JS execution; agents can only instantiate components declared in the host's registered design catalog, and sensitive values bind server-side without flowing through the LLM prompt/output.
   - Official web renderers (Lit, React, Angular) and multi-language agent SDKs (TypeScript, Python, Dart).
2. **Current Estate Baseline (`just search "a2ui|A2UI"`):**
   - `w0m-ext/extension/package.json:31`: `"@a2ui/lit": "^0.8.1"` (pre-1.0).
   - `w0m-ext/extension/src/ui/popup.ts:3`: `import '@a2ui/lit';` rendering `<a2ui-surface id="agent-ui"></a2ui-surface>` (`w0m-ext/extension/ui/popup.html:783`).
   - `w0m-web`: Zero A2UI dependencies or catalog mappings today; `AI Agent Helper` (`ChatApp.svelte`) and `/solutions` / `/services` configurators (`ServiceActionOrderConfigurator.svelte`) currently render hand-wired custom widgets rather than A2UI-driven declarative surfaces.
