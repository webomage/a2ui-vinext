# T133 — recover temporary DS proposals from the Claude Design exports

## Summary

Owner ask (2026-07-25): we have **several exports of the Design System from Claude Design** archived
locally, and they contain **temporary proposals** worth recovering — specifically **tech chips on the
main page** and **dotted / staccato hero slogans on every page**. Do the deepest investigation across
all the exports, surface each proposal (with its real markup/tokens), compare against the **live** DS
and pages, and decide adoption.

## What is already known (grounding 2026-07-25 — confirm, don't blind-trust)

**The archive** (`_ds_arc/`): four unzipped exports — `Webomage Design System`, `… System 1`,
`… System 2`, and **`Webomage design import and merge`** — plus `webomage-design-system/`. Source zips
in `_ds_arc_pack/` (`… System.zip`, `… 1.zip`, `… 2.zip`, `…-handoff-w0m.zip`,
`… import and merge.zip`; ~18 MB the largest). Each export has `tokens/`, `components/`, `guidelines/`
(`*.card.html`), `ui_kits/web/`, `templates/{web,capability,cv,case-study}/`, `styles.css`,
`_ds_manifest.json`, `SKILL.md`.

**Proposal A — tech chips on the main page.** File
`_ds_arc/Webomage design import and merge/_ref/tech-chips-preview.html` = **"Tech Icon Set — blue
neon"**: all **92** tech icons rendered as chips in brand sky-blue (`#38bdf8`) with a neon
`drop-shadow` glow; hover brightens to `#7dd3fc` + lift; 15 are flagged "freshly baked silhouettes".
🔴 **This preview exists in ONLY the `import and merge` export** — not in System/1/2 — which is exactly
why it reads as a *temporary proposal* that never landed. (`brand-tech-icons.card.html` in the
guidelines is the related, non-chip icon reference.)

**Proposal B — dotted / staccato hero slogans.** `templates/web/Hero.jsx` (and `ui_kits/web/Hero.jsx`)
carries a **dot-punctuated staccato headline** — `Cloud. Infra. Scale.` / `AI. Software.` — as a
gradient-clipped `clamp()`-scaled `<h1>` over a radial sky-blue glow. "Dotted" = the period-separated
one-word-per-beat slogan cadence, applied to the hero. Hero templates appear across **all** exports
(`System`, `1`, `2`, `import and merge`) under both `ui_kits/web/` and `templates/web/`; the deep pass
must enumerate whether the *other* page types (`capability`/`cv`/`case-study`) got their own
dot-slogan heroes or only `web` did.

**Why "temporary":** these are Claude Design exploration exports, not the live DS. The live runtime DS
is `packages/ui` (`@webomage/ui`, Svelte) and the design-of-record is `wom7web/design-system` (Claude
Design export + `webomage-design` skill) — see memory `[[design-system-reference]]`. The proposals must
be reconciled against those + the live pages, per the T42 audit→master→sync-back-to-code workflow — not
copy-pasted.

## Acceptance criteria

- [ ] **AC1 — Full export inventory.** Enumerate all exports in `_ds_arc` (+ the `_ds_arc_pack` zips):
      which exist, their dates, and a per-export diff of what each uniquely contains (so we know which
      proposals live where and which export is newest/authoritative). Recorded as a findings doc
      in-repo (e.g. `wom7md` or `docs/design/`).
- [ ] **AC2 — Tech-chips proposal recovered + specified.** Extract the `tech-chips-preview.html`
      proposal into a reviewable spec: the 92-icon set, the neon-glow token values (colors, glow
      `drop-shadow`, hover states), the 15 "hot" silhouettes, and where on the **main page** it was
      meant to sit. Render/screenshot it as-is for the owner.
- [ ] **AC3 — Dotted-hero-slogan proposal recovered + specified.** Capture the staccato hero pattern
      (headline cadence, gradient text, radial glow, `clamp()` scale) and enumerate **per page type**
      which heroes used it across the exports; note the actual slogan strings proposed.
- [ ] **AC4 — Gap vs. live.** For each proposal, state whether it exists in the **live** site/pages and
      `@webomage/ui` today, and what adopting it would touch (tokens, components, which pages).
- [ ] **AC5 — Adoption decision (owner).** A recommendation per proposal (adopt / adapt / drop) with the
      token-mapping into `@webomage/ui` (honoring the hex-in-`rgba()` golden rule, memory
      `[[header-ui-spec]]`), scoped as its own build ticket if adopted. No live page/DS edits in this
      ticket — investigation + decision only.
