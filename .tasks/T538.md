# T538 — Scope project people/contacts to project members for regular users, allow managers and admins to see everyone

## Summary

Owner direction (2026-10-02): enforce capability and UI logic separation for people and contacts within project contexts:
1. Normal members/collaborators inside a project context (`/o/:org/p/:project` or project views) only see contacts/people assigned to or associated with that project.
2. Managers and platform administrators holding `people.all.view` can see everyone across the organization/estate.
3. Add a dedicated "Contacts" page in the project context (`/o/:org/p/:project/contacts`) showing project contacts.
4. Scope the People Directory (`/o/:org/people/directory`) so non-managers only see people from their assigned projects, while managers and admins see everyone.

## Acceptance criteria

- [x] AC1 — **Capability declaration and grant (`people.all.view`).** Declare `people.all.view` in `public.capabilities` (migration) and in `CP_CAPABILITIES` (`apps/cp/src/lib/context/catalog.ts`). Grant `people.all.view` to management offices (`tech.lead`, `project.manager`) in `public.office_capabilities`. Platform admins receive all capabilities via `wom_context_capabilities`.
- [x] AC2 — **Project contacts navigation and page (`/o/:org/p/:project/contacts`).** In `apps/cp/src/lib/context/nav.ts`, add a `Contacts` item under `NAV.project` (`path: "contacts"`, `capability: "project.view"`). Create route `apps/cp/src/pages/o/[org]/p/[project]/contacts.astro` rendering `ProjectContacts.svelte` which lists active members/contacts staffed on that project (via `public.hats` and project delivery roles).
- [x] AC3 — **Scoped People Directory (`/o/:org/people/directory`).** In `PeopleManager.svelte`, detect whether caller holds `people.all.view` or is admin. If not holding `people.all.view`, scope the fetched/rendered people to only profiles that share active project assignments/hats with the user. Managers and admins continue to see all directory members.
- [x] AC4 — **Automated tests (unit, capability, and E2E).** Unit tests in `packages/lib` and `apps/cp` covering `people.all.view` and project contacts scoping. Gauge/Playwright E2E spec verifying regular project member sees only project contacts while manager/admin sees all directory entries.
