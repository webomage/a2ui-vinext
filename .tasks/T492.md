# T492 — the estate root should own what is estate-wide; today wom7web and wom7api own it by accident

## Summary

Owner 2026-09-29: decouple and organise the top level away from `wom7web` and `wom7api` — tests, plain files and the rest.
**Measured 2026-09-29:**

- **One 4,782-line `justfile` lives in `wom7api` and is symlinked into `wom7web` AND `wom7func`** (`wom7web/justfile -> ../wom7api/justfile`),
  while the umbrella root has its own 1,003-line `justfile` that mostly forwards (`@just --justfile wom7web/justfile …`). Every new recipe
  needs a forwarder in two places (T335, T453 and name-refs each did). Symlinked files are the "shadow symlink" AgDR-0025 forbids.
- **Estate-wide tests live inside one product repo:** 247 Python gate tests in `wom7web/project/scripts/tests`, 33 Gauge step files in
  `wom7web/tests`, 194 `.spec` files in `wom7web/specs`, versus 23 tests in the umbrella `scripts/tests`. Most of the 247 test estate
  policy (tickets, hooks, deploy), not the web app. T421 (deploy machinery), T411/T419 (`.tasks`) and T430 (decision sources) already
  moved pieces to the root; each left forwarders and a hook that could no longer fire in the old place.
- **Stray one-off files at repo roots** (tracked): `wom7web` has 81 root files including `fix_env.py`, `fix_imports.py`,
  `fix_imports_smart.py`, `fix_static_imports.py`, `fix_ts.py`, `fix_zod.py`, `migrate_svelte.mjs`, `screenshot.js`, `test-login.js`,
  `test_visible.js`, `test_create_user.ts`, `generate_png.js`, `generate_goldens_report.js`, `validate_posts.py`, `clean_logo.png`,
  `webomage-stack.svg`, and a 131-byte `supabase.cookie` (inspected: no token, no reference anywhere; a dead cookie-jar stub).
  `wom7api` has 44 including `test_ats_api.ts`, `test_provisioner.ts`, `test-bind.js`, `logo_check.svg`, `screenshot.py`,
  `interview_aws_devops.md`, `projects.md`, `service.md`. Untracked-and-ignored secret JSONs (`dev_secrets.json`, `prod_secrets.json`,
  …) sit at `wom7api` root too: not a leak (verified ignored), but a root that invites one.
- **A path move is the same problem as a rename.** Moving `project/scripts` or `justfile` breaks every `cd ../wom7web && …` recipe,
  hook `entry:`/`files:`, doc and spec. Use `just name-refs "<old/path>"` for the inventory and `--gate` as the done-check, and put
  the moved file's hook filter under the same mirror test that T430 and the decisions hook use.

## Acceptance criteria

- [ ] AC1 — **Classify before moving.** A table in this ticket: every top-level directory and every tracked root file of `wom7web` and
  `wom7api`, tagged estate-wide / wom7web-only / wom7api-only / delete, with the measured count and one sentence why. `project/scripts/`
  is split by what each script reads (estate files vs web app) — not by where it was first written.
- [ ] AC2 — **Strays: delete or relocate each with proof.** For every stray in the Summary, `just search` shows no live reference (or the
  reference is updated in the same commit); `supabase.cookie` and the one-off `fix_*.py` are deleted, not moved. Owner confirms the list.
- [ ] AC3 — **The justfile is split into imported modules owned by the root** (`import`/`mod` by domain: deploy, release, tasks/tickets,
  hygiene, db, web, cf, ext…), the two symlinks are removed, each repo keeps only its own product recipes, and there is ONE place to add
  a recipe. Behaviour-preserving: `just --list` before and after differ only by intent.
- [ ] AC4 — **Estate-wide Python tests move to a root `tests/`** (policy/hygiene/deploy/tickets suites), `project/test-suites.json`
  keeps declaring them, `just test` still runs the same suites with the same check counts (compare before/after, per suite — a
  suite that quietly drops from 40 checks to 0 must fail). Gauge specs/steps stay in `wom7web` (they test the product).
- [ ] AC5 — **Hooks follow the files.** Every pre-commit/pre-push `files:` filter that moved is re-pointed and covered by a mirror test
  (the T430 pattern); no hook is left that can never fire because its inputs moved to another repo.
- [ ] AC6 — **A layout gate** (`just layout-check`, in pre-push): fails on a new tracked stray at a repo root outside an allowlist with a
  reason, on a new symlinked recipe file, and on an estate-wide test added under a product repo. Red probe for each.
