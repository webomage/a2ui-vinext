# T632 — Surface active-hat tool availability across CP and render project milestones, visual roadmap, progress infographic, and role-scoped stats on both tech and client project vaults

## Summary

Two visibility and delivery-telemetry gaps broke role-scoped ergonomics across CP project workspaces:
1. **Opaque active-hat tool availability & unredacted commercial fields**: Although `hat-visibility-policy.json` (`T609`) narrows route capabilities by worn hat, users switching between `PM`, `TL`, `Dev`, `QA`, `Design`, `Client`, and `Admin` had no clear in-UI overview of which tools and capabilities are unlocked vs restricted for their active hat, and `MilestoneManager.svelte` exposed commercial `amount_usd` columns/inputs even when a non-commercial tech hat (`tl`, `dev`, `devops`, `qa`, `design`) was worn (`AgDR-0020`, `AgDR-0028` §8).
2. **Missing Milestones, Roadmap, Progress Infographic & Stats on Tech and Client Project Vaults**: Both `/o/[org]/p/[project]/vault.astro` (tech side) and `/o/[org]/projects/vault.astro` (client & business org side) rendered markdown notes without project milestones, phased roadmap timelines, completion progress infographics, or corpus/delivery stats — and `/o/[org]/p/[project]/index.astro` promised *"Project delivery overview, active roles, and milestones"* while rendering zero milestones or progress metrics.

## Acceptance criteria

- [x] **AC1 — Active-Hat Tool Availability Evaluator & UI Bar (`hat-visibility-policy.json`, `hat-visibility.ts`, `HatToolsAvailabilityBar.svelte`, `CpShell.svelte`, `shell-model.ts`)**: Extended `@webomage/lib/auth/hat-visibility` with `describeHatToolAvailability(held, contextKind, baseUrl)` returning the active hat label, side, commercial-visibility state, clickable available tool pills, and hidden/restricted capability categories, and mounted `HatToolsAvailabilityBar.svelte` (`100%` `@webomage/ui` primitives) inside `CpShell.svelte` reacting live to `wom:project-hat-changed`.
- [x] **AC2 — Project-Scoped Delivery Telemetry & Commercial Redaction (`project-telemetry.ts`, `MilestoneManager.svelte`, `o/[org]/p/[project]/milestones.astro`)**: Implemented pure `buildProjectDeliveryTelemetry()` and server loader `loadProjectDeliveryTelemetry()` resolving engagement/project-scoped milestones, completion breakdown, roadmap phases, and vault note category counts, and enforced `canSeeCommercialAmounts(held)` in `MilestoneManager.svelte` + telemetry views so `tl`/`dev`/`devops`/`qa`/`design` hats never see USD contract/milestone amounts while `client`/`pm`/`admin` hats see authorized commercial progress.
- [x] **AC3 — Tech & Client Project Vault Roadmap, Progress Infographic & Stats (`ProjectVaultTelemetry.svelte`, `o/[org]/p/[project]/vault.astro`, `o/[org]/projects/vault.astro`, `o/[org]/p/[project]/index.astro`)**: Rendered `ProjectVaultTelemetry.svelte` on both tech (`/o/[org]/p/[project]` + `/o/[org]/p/[project]/vault`) and client/org (`/o/[org]/projects/vault`) surfaces with a SVG completion ring + segmented progress bar, visual phased roadmap timeline, inline client milestone approval/revision actions when authorized, and corpus/delivery stats cards across all 4 `AgDR-0054` responsive postures.
- [x] **AC4 — Synced Obsidian Roadmap & Progress Note (`vault-telemetry-md.ts`, `vault-r2-gateway.ts`)**: Generated client-safe `mocs/roadmap-and-progress.md` virtual/synced vault note (validated Mermaid roadmap + milestone progress table + corpus stats without leaking unauthorized USD figures) so users opening the vault in Web or Obsidian see live delivery telemetry.
- [x] **AC5 — OpenSpec, DS Conformance & Regression Suite**: Documented normative requirements and testing seams in `w0m-web/openspec/specs/per-project-vault-topology/spec.md`, passing `ds_conformance.py --enforce` (`-63` hex, `-61` raw `<button>`), `supabase_surface_drift_check.py` (`0` findings), Vitest suites (`hat-visibility.spec.ts` `6/6`, `project-telemetry.test.ts` `15/15`, `nav.test.ts` `22/22`), and `pnpm --filter cp build`.

## Definition of Done

A user wearing any delivery, client, or admin hat in CP sees an accurate active-hat tool availability bar in `CpShell` that updates on hat switches and hides restricted commercial/admin controls (`amount_usd` absent from DOM when `commercialAmountsVisible === false`); visiting either the tech project workspace (`/o/<org>/p/<project>` and `/o/<org>/p/<project>/vault`) or the client knowledge hub (`/o/<org>/projects/vault`) renders project-scoped milestone progress rings, a phased visual roadmap, and corpus/delivery stats backed by real `client_milestones` + `vault_notes` queries, verified by OpenSpec validation (`163/163`), `ds-conformance`, `supabase_surface_drift_check.py`, Vitest suites (`162/162`), and `cp` production build.
