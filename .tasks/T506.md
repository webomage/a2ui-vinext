# T506 — Security & PII Cutover: Token Encryption, IP Retention, Bucket Hardening

## Summary

Following the completion of [[T505]] (personal contact & identity model), a grounded live database audit against SOC 2, GDPR, and PII standards revealed three concrete security/data protection gaps:

1. **Plaintext OAuth / API Tokens:**
   Migration `20260725180000_t99` added AES-256-GCM columns (`access_token_ciphertext`, `access_token_iv`, `token_key_version`), but live rows in `public.connections` (4 rows), `public.social_integrations` (1 row), and `public.upwork_auth_tokens` (3 rows) still store tokens in plaintext while ciphertext columns have 0 rows. Under SOC 2 CC6.1 / CC6.6, bearer/refresh tokens must be encrypted at rest with keys managed in Infisical (`CRYPTO_KEY`).
2. **Indefinite IP Address Retention:**
   `public.ai_usage` holds 684 rows with raw `web:<ip>` identifiers dating back to March 2026 (>6 months old). SOC 2 and GDPR data minimization principles require either pseudonymizing IP identifiers (e.g. salted SHA-256 hash) or establishing an automated rolling retention purge job via `pg_cron` (currently only `demo-reset-nightly` exists).
3. **Legacy Public `cv` Bucket:**
   `resumes` bucket is private (T488), but the legacy `cv` storage bucket is still declared `PUBLIC`. Any candidate documents lingering in `cv` expose personal data publicly.

## Acceptance criteria

- [x] AC1 — Backfill & Cutover: Encrypt all plaintext tokens in `connections`, `social_integrations`, and `upwork_auth_tokens` into `*_ciphertext` with `token_key_version = 1` using the AES-256-GCM key from Infisical, verify decryption round-trips in all readers, and drop or null out the plaintext token columns.
- [x] AC2 — Token writers & readers update: ensure all edge functions and API connectors (`supabase/functions/_shared/`, `wom7func`) write and read exclusively via ciphertext columns with zero plaintext fallback.
- [x] AC3 — IP minimization in `ai_usage`: update web visitor tracking to hash client IP addresses (`web:<sha256(ip + salt)>`), preventing indefinite plain IP storage.
- [x] AC4 — Retention schedule: add a `pg_cron` job (e.g. `retention-purge-nightly`) that purges or truncates IP logs older than 90 days.
- [x] AC5 — Storage bucket audit: verify all member CVs are in the private `resumes` bucket with signed URLs (via `just resumes-upload-live`), and unpublish or restrict the legacy `cv` bucket.

## Definition of Done

- 0 plaintext rows exist in `connections.access_token` and `social_integrations.access_token`.
- No raw IP addresses older than 90 days are retained in `ai_usage`.
- No personal resume with contact info is accessible via an unauthenticated public bucket URL.
