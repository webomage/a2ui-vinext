# T493 — "Aleksei's CP" should hold everything that is his; admin CP should hold only w0m system management

## Summary

Owner 2026-09-29: transition every admin-CP view and function that is not w0m-internal management into the member profile, keep
admin CP **untouched** as the reference until the owner confirms, and migrate the data/functions the profile needs. First symptom:
*"I can't see my todo now in user cp."*

**Measured 2026-09-29 (live DB, read-only; `docs/CP-FEATURE-INDEX.md` = the per-feature map, regenerate with `just cp-feature-index`):**

- **Why the to-dos were empty:** all **19** `admin_todos` rows (7 open) are owned by the `w0m@webomage.com` profile; none by
  `aleksei@webomage.com`. `admin-todos-api` correctly returns each person only their own (T361 AC2). Confirmed by simulating both
  identities under RLS: Aleksei sees **0**, `w0m@` sees 19. Fix = data migration (below), not a code bug.
- **Already on Aleksei's profile:** 95 contracts, 1,782 proposals, 55 Upwork rooms, 170 messages, 21 resumes, 95 experience rows
  (T440). **Not attributed to anyone:** 3 contracts and 3 connections (`profile_id` null).
- **The data was there, the views were not:** Upwork rooms and messages were read by **no page at all**; proposals showed only as
  sync counts on Account. Built: `/me/upwork/proposals` and `/me/upwork/messages` (read-only, through the user session, so RLS
  decides). A flaw found and fixed while testing: admin RLS lets an admin read **everyone's** rows, so a "my" page that trusts RLS
  shows an admin every member's proposals (`w0m@` read all 1,782). Every `/me` data page now filters `profile_id` explicitly, and a
  test (`me-pages-own-rows.test.ts`) fails if a query on those pages omits it.
- **"Proven facts" has no code by that name.** The nearest is Resume Studio's experience-by-source breakdown (Upwork / resume /
  manual counts, `upworkFactsCount`). Needs the owner to say what the old admin CP showed.
