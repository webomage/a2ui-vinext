# T587 — Per-Profile Shared Primary CV Links (`/u/[slug]/cv`, `/u/[slug]`, `/team`, `/cv`, `/resume`, and Resume Studio)

## Context
When a w0m team member sets a CV or synthesized variant as their Primary ("Main") CV in Resume Studio (`job.webomage.com/me/resume`) and enables **Public resume**:
1. Setting a `.md` synthesized variant as Primary set `is_primary = true` on the Markdown row (`mime_type = 'text/markdown'`), which caused `public.published_resumes` (`mime_type = 'application/pdf'`) to return 0 rows and flipped `public_team_members.has_public_resume` to `false`. Additionally, `pdf-generator.ts` always inserted rendered PDFs with `is_primary: false`.
2. Each w0m team member needs a canonical **per-profile shared Primary CV URL** (`/u/<slug>/cv` + `/u/<slug>` + `cv-pdf?member=<member_id>`) listed on their public profile, Team card, and inside Resume Studio / Public Settings, while keeping `/cv` and `/resume` as extra aliases for Aleksei's profile (with prominent top-header & footer links to his Primary CV PDF and `/u/aleksei/cv`).
