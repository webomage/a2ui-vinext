# T709 — Evaluate tablinux (linuxontab) claw Package to Replace zeroclaw Functions Across w0m

## Summary

Audit the `claw` package in `tablinux` (`w0m-pr/linuxontab`) against all `zeroclaw` functions and references across `@wom` (`w0m-cf`, `w0m-api`, `w0m-web`, and `project/policies/`). Produce a capability-by-capability parity matrix, security/runtime footprint comparison, and weighted decision (AgDR) on replacing our `zeroclaw` functions with `tablinux`'s `claw` package, followed by clean cutover or scoped migration tasks.

## Acceptance criteria

- [ ] AC1 — **Inventory All `zeroclaw` Functions & Callers Across `@wom`:** Catalog every `zeroclaw` function, worker binding, endpoint, test suite, and policy entry across `w0m-cf`, `w0m-api`, `w0m-web`, and root scripts (`just search "zeroclaw"`).
- [ ] AC2 — **Inspect `tablinux` (`w0m-pr/linuxontab`) `claw` Package Architecture & Capabilities:** Analyze the `claw` package in `linuxontab` (interfaces, runtime dependencies, sandboxing, IPC/RPC transport, resource overhead, and license/security posture).
- [ ] AC3 — **Capability Parity Matrix & Weighted Replacement Decision:** Compare `tablinux` `claw` vs `zeroclaw` across latency, Cloudflare Free-Tier / edge compatibility (`AgDR-0055`), security isolation, and maintenance burden, and record a weighted decision in `.agents/reports/` (`w0m-web/docs/reports/`).
- [ ] AC4 — **Cutover Specification or Replacement Execution:** If `claw` satisfies parity and safety gates, execute or spec the clean cutover (`AgDR-0025` zero shims / zero dual SSOT) replacing `zeroclaw` callers atomically.

## Definition of Done

Per [`w0m-web/openspec/SPEC-AUTHORING-STANDARD.md`](../w0m-web/openspec/SPEC-AUTHORING-STANDARD.md):
- Acceptance criteria AC1–AC4 verified with grounded code/package evidence and report mirrored to `.agents/reports/` and `w0m-web/docs/reports/`.
