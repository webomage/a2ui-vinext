# T554 — release record under a multi-agent beta

## Summary

Owner, 2026-10-07 after the deploy: "we have to make it working stable with multiagent env". The deploy of release `2026.10.07-1791355037` shipped and published its tags, then failed at the last step. `release.py record_release` wrote `releases/<v>.json` and the regenerated `CHANGELOG.md` into the owner's LIVE checkout, committed them on the local `beta`, and ran one `git push origin beta`. agy had landed on `beta` in the meantime, so the push was rejected (`! [rejected] beta -> beta (non-fast-forward)`), the message said "push it later" (no command existed), and the commit stayed on the live branch: ahead 1, behind 1. A diverged live branch also defeats the owner's standard catch-up (`git merge --ff-only origin/beta`).

Three more weaknesses of the same shape, all fixed here:

1. `deploy_from` copied the release worktree's `CHANGELOG.md` over the live checkout's file before recording, dirtying the shared tree.
2. `last_deployed()` (the "previous release" a cut compares against), the release list, and the prune that protects deployed releases all read `releases/` from the **working tree**. A record that landed from another tree is invisible to the next cut until the live checkout happens to be fast-forwarded, so apps could be redeployed (or a deployed release's worktree pruned) on a stale view.
3. The deploy exit code stayed 0 even when the record push failed, so the audit said "clean".

The stranded commit of this deploy was landed unchanged (byte-identical blobs) from an agent tree as `a881ade`; the owner's local copy drops out on `git rebase origin/beta`.

## What was built

- `release.land_release_record(estate, v, files, message)`: the record is a single commit built with git plumbing (`read-tree` into a private index, `hash-object`, `update-index`, `write-tree`, `commit-tree`) directly on the freshly fetched `origin/beta`, then pushed. No working tree, index, checkout or local-branch change, so nothing can be stranded. A non-fast-forward refetches and rebuilds on the new tip (bounded attempts, backoff); any other refusal is not retried. When it cannot land, the payload is parked in `~/.w0m/state/pending-release-records/<v>/` and the message names the exact command: `just release-record <v>`. The push still runs the repository's pre-push hook (`--no-verify` stays prohibited).
- Only `releases/<v>.json` and `CHANGELOG.md` are accepted; a record that already exists with different content is refused, never overwritten; landing twice adds one commit.
- `committed_records()` reads `origin/beta`; `last_deployed`, the release list and the prune use it; no `origin/beta` fails closed.
- `fast_forward_estate()` best-effort catch-up of the live branch, never forced.
- `deploy_from` returns exit code 2 ("deployed, record NOT landed") instead of 0 when the record cannot land; `release.py record <v>` and `just release-record` re-land a parked or missing record.
