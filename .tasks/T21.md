## ⚠️ 2026-08-15 — THE SPECCED API NAME IS DEPRECATED. Fix before building.

This ticket is written against **`navigator.modelContext`**. That name is **deprecated as of
Chrome 150** in favour of **`document.modelContext`** — the 21-July spec draft moved the API from
`navigator` to `document`, to reflect that tools belong to a **page**, not the browser. Chrome's own
docs say plainly: *"navigator.modelContext is deprecated as of Chrome 150 … use
document.modelContext instead."* `navigator.` survives only as a backward-compatible alias that
returns the same instance and logs a one-time deprecation warning.

**⇒ Build against `document.modelContext`**, with the documented feature-detect for the transition:
`const modelContext = document.modelContext || navigator.modelContext;`
The API itself is unchanged — this is a namespace move, and the third one: `window.agent` →
`navigator.modelContext` → `document.modelContext` in under a year. Whatever `@webomage/webmcp`
wraps, it should own that detection in ONE place so the next rename is a one-line change.

**Reach, measured the same day:** Chrome 146+ is the **only** browser shipping it (origin trial;
Firefox/Safari/Edge are in the W3C Web Machine Learning WG but have not shipped). So the
progressive-enhancement framing in the summary is not optional polish — it is the majority path.
Polyfill/types exist as `@mcp-b/webmcp-polyfill` and `@mcp-b/webmcp-types` under `WebMCP-org`.
⚠️ Note for [[T219]]: that is the **same `@mcp-b` namespace** wom7mcp was abandoned over — it is now
the WebMCP standard's tooling, so the earlier "fork was unreliable" judgement is worth re-testing
against the current packages rather than carried forward as settled.

## Definition of Done

1. `@webomage/webmcp` package provides progressive-enhancement feature detection for `document.modelContext` with `navigator.modelContext` backwards compatibility, returning a safe no-op on unsupported browsers with zero console errors or layout shifts.
2. Universal tool manifest is defined once in `@webomage/webmcp` and shared directly with server-side `chat-core.ts` (`SUBMIT_SERVICE_REQUEST_OPENAI_TOOL`), verified by cross-surface unit tests in both Vitest and Deno.
3. Role-gated tool catalogs are exposed across all apps (`web` public tools, `cp` member/admin/client tools, `join`/`job` recruit tools), cleanly deregistering on role downgrade or sign-out.
4. `validate_mermaid` runs client-side deterministically via browser `mermaid.parse` without server round-trips for syntax; non-admin sessions cannot discover or invoke it.
5. Invocation audit trail records `{ ts, user_id, role, tool, args_hash, result }` with deterministic SHA-256 argument hashes (no raw parameters logged), and write tools require explicit user confirmation before execution.
6. Monorepo typechecks, edge function `deno-check`, and all unit test suites pass cleanly with 0 errors.
