# T201 — replace hCaptcha with Turnstile

## Summary

Owner ask, 2026-08-11: *"create a ticket for later to review and replace hcaptcha with turnstile."*
🔴 **Filed P3/backlog on 2026-08-11 and RAISED TO P1 the same day**, because AC1's open question was
answered and it is a live finding: **`DEBUG_BYPASS_KEY` is set in the deployed runtime and skips
hCaptcha entirely.** The vendor swap is still consolidation rather than a defect; the bypass is the
defect, and it is fixed here regardless of whether the swap ever happens. The estate is already on Cloudflare for DNS, Workers, Pages and Workflows; Turnstile is the
same-vendor equivalent with no per-visitor puzzle.

⚠️ **Review first, replace second.** The AC order matters: the current implementation has three things
worth deciding about *before* a swap, and one of them is a live question.

## 📍 Where hCaptcha is today, measured

**Frontend — 2 distinct site keys, hardcoded in 6 files** (`apps/web` and `apps/cp` each carry a copy;
the two apps' components are duplicated, not shared):

```
apps/web/src/components/templates/sections/ContactFormSection.astro:107  data-sitekey="7f2fb4c2-…f1ad"
apps/web/src/components/templates/sections/ContactFormSection.astro:155  <script src="https://js.hcaptcha.com/1/api.js">
apps/web/src/components/forms/ApplicationForm.svelte:268                 data-sitekey="e8b4c002-…c836c"
apps/web/src/pages/careers.astro:33                                      <script src="https://js.hcaptcha.com/1/api.js">
apps/cp/src/components/templates/sections/ContactFormSection.astro:107   data-sitekey="7f2fb4c2-…f1ad"  (same key)
apps/cp/src/components/forms/ApplicationForm.svelte:272                  data-sitekey="e8b4c002-…c836c"  (same key)
```

**Backend — 1 shared secret, 2 verifiers:**

```
wom7api/supabase/functions/contact-submit/index.ts   HCAPTCHA_SECRET · verifyHCaptcha(token, remoteip)
wom7api/supabase/functions/apply-submit/index.ts     HCAPTCHA_SECRET
```

⚠️ **A site key is public by design** — it is meant to be in the page, so this is not a leaked
secret. It *is* a config smell: two keys hardcoded in four component files across two apps means a key
rotation is a code change in two repositories' worth of build output.

🔑 **hCaptcha is the reason `contact-submit` is not a finding in [[T199]] F3.** That function is
`verify_jwt = false` and holds the service-role key; the captcha check is the only thing standing in
front of an unauthenticated service-role insert into `leads`. **Whatever replaces it inherits that
job** — this is not a cosmetic swap.

## 🔴 Three things to review before swapping

1. **`DEBUG_BYPASS_KEY` is read by `contact-submit` in production.** The function reads a
   `DEBUG_BYPASS_KEY` env var alongside `HCAPTCHA_SECRET`. **Unreviewed** — whether it is set in prod,
   what it bypasses, and whether it is constant-time compared are all unknown as of filing. ⚠️ **If it
   is set and it skips the captcha, the captcha is optional.** Establish this *before* any migration,
   because a swap would carry the bypass across unexamined. Sibling shape: [[T175]] (a service key
   compared with `!==`).
2. **The two apps' forms are duplicated, not shared.** `ContactFormSection.astro` and
   `ApplicationForm.svelte` exist in both `apps/web` and `apps/cp` with the same keys. ⇒ **A swap
   touches four component files, or one shared component in `packages/ui` and then two.** This is the
   same cross-app duplication [[T197]] found in the stylesheet layer and D6/T104c found in tsconfig —
   fixing it here is optional, but doing the swap without noticing means doing it twice.
3. **A Gauge spec asserts the current behaviour and will fail on a swap.**
   `apps/cp/specs/api/010-contact-secure.spec` (and the `apps/web` copy) assert *"the response data
   should contain `Invalid captcha`"* on a tokenless POST. ✅ **That is a red probe that already
   exists** — it is the acceptance test for the migration, and it must be updated in the same change,
   not after.

## 🔴 Found in the same pass — six edge-function secrets are set to the EMPTY STRING

`supabase secrets list` returns `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`
for six entries. That is `sha256("")` — verified, not guessed:

```
GOOGLE_API_KEY   HONEYCOMB_API_KEY   UPWORK_AGENCY_API_KEY   UPWORK_AGENCY_API_SECRET
UPWORK_CLIENT_API_KEY   UPWORK_CLIENT_API_SECRET
```

⚠️ **"Set" and "has a value" are different things, and only one of them is what a guard usually
tests.** `Deno.env.get("X")` returns `""`, which is falsy — so a `if (!secret) → fail closed` guard
still works, but any code that treats *presence* as configuration will believe the integration is
configured. Which of the two shapes each of the six sits behind is **unmeasured**; it is a separate
finding from the captcha bypass and shares only the method that found it.

⇪ Not this ticket's job to fix — recorded here because the pass that answered AC1 produced it, and
an unrecorded observation is one nobody re-derives. Belongs with [[T199]]'s secret-surface work.
