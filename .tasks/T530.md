# T530 — Org model S9: retire Axis-1 account classes and network.member

## Summary

Split from [[T458]] AC7 (step S9 in T458 design / [[AgDR-0028]]).
Retire legacy Axis-1 account-class switcher and `network.member` role. Unify access control around:
1. The single root admin identity (`w0m@webomage.com` / `aleksei@webomage.com`);
2. Engagement hats (`pm`, `tl`, `client`, etc.) worn one at a time for all project, client, and company activities;
3. Retire `abilities.ts`, `portal-policy.ts`, and middleware account-class branches in favor of engagement hats + capability checks (pairs with [[T453]]);
4. Update CP context switcher to navigate engagements and roles rather than legacy account classes.

## Acceptance criteria

- [ ] AC1 — Retire Axis-1 account-class switcher from CP navigation and shell components.
- [ ] AC2 — Remove `network.member` role enum and references across middleware, abilities, and RLS policies.
- [ ] AC3 — Update CP context switcher to group and switch context by engagement (`<contractor>.<engagement>.<client>`) and active worn hat.
- [ ] AC4 — Refactor `abilities.ts`, `portal-policy.ts`, and route guards to enforce engagement hats and capability permissions directly.
- [ ] AC5 — Verify admin permissions strictly check root admin identity, eliminating legacy multi-admin role possession fallbacks.
- [ ] AC6 — Automated test suite verifying seamless switching across contractor, client, and team hats with 0 regressions.

## Definition of Done

Per [`../../openspec/SPEC-AUTHORING-STANDARD.md`](../../openspec/SPEC-AUTHORING-STANDARD.md):
- CP Context Switcher updated to present and switch engagement hats cleanly.
- Legacy account classes and `network.member` completely retired from codebase.
- Route guards and ability checks verified test-first against the new permission model.
- Quality gates pass cleanly (`just test`, `just lint`, `just typecheck`).
- Changes committed referencing T530 with TASKS.md updated in sync.
