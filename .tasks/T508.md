# T508 — Skills catalogue measures every governed surface

## Summary

`wom7web/project/scripts/skills_catalogue.py` measures the `w0m` project from `<registry root>/.w0m/skills.json`. The
registry root is the workspace root `.`, which holds **25 skills and no `exclude` list**. The estate's largest manifest,
`wom7web/.w0m/skills.json` (**99 skills, 10 excluded**), and `wom7api/.w0m/skills.json` (9) are never measured. Two tools
now give two answers for one project: the catalogue says 25 installed, `client_inventory` says 99 declared. `k7` has the
same blind spot (catalogue 0, its canonical repo `k7d` holds 4). Research: 2026-09-30, read-only, full report kept in the
session scratchpad (`research-skills-catalogue.md`).

**Correction to the first diagnosis:** this began on **2026-09-07 (T232, `e506674`)**, which created the root manifest
and removed the `@wom/.agents` symlink, **not** with T414 on 2026-09-20/21. T385 already listed `skills-catalogue-test`
as red on 2026-09-18, and the test keeps sliding (17/18, then 15/18, now 13/18).

## Evidence (measured 2026-09-30)

- `skills_catalogue.py:242` resolves `ROOT / p["root"]`; `:141,144,150-151` read `<root>/.w0m/skills.{json,lock.json}`,
  `.agents/skills` and `.claude/skills`. It ignores `canonical_repo` and `repos` in `clients-policy.json`.
  `state_bounds.py:100` and `client_inventory.py:397-411` honour `canonical_repo`.
- Calling its own `catalogue_project` on the three real surfaces gives root 25/25/0/0, wom7web 109 installed / 99
  managed / 10 excluded, wom7api 9/9/0/0. The machinery is right; only the root selection is wrong.
- Several manifests are **intentional per-consumer selection** (T127, T149, T232, owner decision 2026-08-17 at
  `.w0m/sdlc.json:652+`). The content source is one place, `wom7skills/skills/`. The defect is propagation, which is
  split to [[T512]].
- Of the 5 red test assertions, 2 are this shrink and 3 are client drift in `artemio`: `justfile:215` is now `:267`,
  and `mmd-validate` runs by an absolute path into w0m's own `wom7skills` checkout. The w0m override
  `w0m:webapp-testing` has silently matched nothing for 23 days.
- Measuring every repo exposes two bugs in the tool: `ships_executable` does an unfiltered `rglob` and counts 8,144
  `node_modules` files under `wom7web/.agents/skills/mmd-validate/` as runnable, and `host_invocations` counts comment
  lines as host calls (3 of 5 hits for that skill are false). It would also add one real finding: wom7web
  `mmd-validate` runs on the host at `justfile:1266` and `:1274` while inheriting `sandboxed: true`.

## Acceptance criteria

- [ ] AC1 — **Scope is every manifest.** For project `w0m`, `just skills-catalogue --json` lists surfaces `.`, `wom7web`
  and `wom7api` (registry `root` plus each `repos` member, de-duplicated by realpath) with counts derived from the
  manifests, never hardcoded. Probe: the test asserts the catalogued surface roots equal `git ls-files '*/.w0m/skills.json'`
  per declared repo plus the root; red probe adds a fixture repo with a manifest and the row count rises.
- [ ] AC2 — **The canonical-repo blind spot is closed.** `k7` reports the 4 skills of its canonical repo. Probe: live
  assertion plus a fixture with `canonical_repo` different from `root`.
- [ ] AC3 — **A shrink cannot be silent.** A declared repo missing on disk exits 2 naming it; a corpus smaller than the
  manifests found exits 2. Probe: fixture registries for both.
- [ ] AC4 — **Excluded counts are derived.** Per surface, `excluded == len(manifest.exclude)` (wom7web is 10). Red probe:
  delete one exclude entry in a fixture and the unmanaged count rises by one.
- [ ] AC5 — **Executables are real files.** `ships_executable` ignores `node_modules` and untracked output; wom7web
  `mmd-validate` is exactly `{test.mjs, validate.mjs}`. Run time before and after is recorded.
- [ ] AC6 — **A host invocation is a real invocation.** Comment-only mentions do not count and a symlinked justfile is
  scanned once. Probe on fixtures; the live `mmd-validate` hits are asserted by recipe name, not line number.
- [ ] AC7 — **Orphan overrides fail closed.** An override key matching no catalogued skill exits 2 naming the key; the
  live `skills-policy.json` has none.
- [ ] AC8 — **Every runnable skill has an owner-approved decision.** `webapp-testing`, `mmd-validate` (web and artemio)
  and `idea-refine` each carry an override with a reason in `project/policies/skills-policy.json`. The agent proposes;
  the owner approves, because `sandboxed: false` is a policy call.
- [ ] AC9 — **The test asserts properties, not a census.** `just skills-catalogue-test` passes N/N with N reported; no
  assertion pins a line number or a client repo's counts (a grep of the test for `justfile:\d+` is empty); each
  previously failing assertion has a red probe. `project/test-suites.json` reason is rewritten.
- [ ] AC10 — **The two tools agree.** `client_inventory` w0m `skills.declared` equals the catalogue's wom7web
  `project_managed`, asserted in the test.
- [ ] AC11 — **Records reconciled.** TECH-DEBT D53 and D66 re-measured, T385 AC3 wording corrected (overrides live in
  the policy file, not `sdlc.json`), T226 AC1 answered per assertion; `just debt-check` green.
