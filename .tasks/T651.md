# T651 — Fix GitHub ticket mirror fail-closed board resolution, wire `session-complete` close sync, and reconcile 246 stale-open + 119 unmirrored issues

## Summary

Audit of why `webomage/wom7board` (surfaced in Orca Mobile `Tasks -> GitHub -> w0m -> Issues -> Open`) showed `250` open GitHub issues (`T3`–`T531`, including `T140`–`T158`) despite `644` of `649` `.tasks/T*.md` tickets already being `status: done` in git revealed three compounding defects:

1. **Silent `check=False` Fallthrough in `scripts/sync_github.py` (`get_or_create_project()`)**:
   - `get_or_create_project()` called `sh(["gh", "project", "list", "--owner", OWNER, "--format", "json"], check=False)` and discarded non-zero exit codes / stderr. When invoked under `~/.config/gh-w0m` (whose token lacked `read:project` scope), `out` was `""`, `items` became `[]`, and the script mistook an auth/API read error for *"board #2 does not exist"* and fell through to `gh project create --owner webomage --title "w0m Delivery"`, crashing before Phase 2 could close or create a single GitHub issue (and risking a duplicate board if `project` scope were ever granted during a transient read error).
   - `ISSUE_FETCH_LIMIT = 1000` also sat dangerously close to the `650`-ticket corpus, and `ensure_labels()` made unconditional per-label `gh label create` subprocess calls even when labels already matched on GitHub.
2. **No Automatic GitHub Mirror on Ticket Wrap-Up (`scripts/session_complete.py`)**:
   - `w0m-sdlc-new` (`ticket_new.py`) creates an open GitHub issue on `webomage/wom7board` at ticket creation time, while `just session-complete` (`scripts/session_complete.py`, `T640`) flipped `.tasks/T##.md` to `status: done` locally without running targeted GitHub sync (`sync_github.py --tickets <T##>`). Consequently, `w0m-web/project/tickets-sync-index.json` had not been updated since `2026-10-01`: **246** `done` tickets (`T3`–`T531`) remained `OPEN` on GitHub and **118** tickets (`T532`–`T649`, plus `T650`) had never been mirrored at all.
3. **Live `webomage/wom7board` & Project `#2` (`w0m Delivery`) Backlog Drift**:
   - Only **5** tickets in `.tasks/` are genuinely unfinished (`T17` queued; `T290`, `T504`, `T526`, `T537` paused — which deliberately stay `OPEN` per `T141`), yet `250` issues sat `OPEN` on `webomage/wom7board`.

## Acceptance criteria

- [ ] **AC1 — Harden `scripts/sync_github.py` (`get_or_create_project()` fail-closed, `--tickets` subset sync, `--issues-only` explicit flag, `ISSUE_FETCH_LIMIT = 5000`, label preflight & bounded concurrency)**: Make `get_or_create_project()` inspect `RUN(["gh", "project", "list", ...])` exit status and fail closed with an actionable `gh auth refresh -s project,read:project` diagnostic instead of falling through to `gh project create`; add `--tickets T1,T2` / `--ticket T1` targeted subset sync (preserving untouched entries in `tickets-sync-index.json`) and explicit `--issues-only` (updating/closing issues and backfilling `gh_issue:` without falsifying board index hashes); raise `ISSUE_FETCH_LIMIT` to `5000`; skip redundant `gh label create` calls when `gh label list` already matches; and add safe pacing/checkpointing for large sync runs.
- [ ] **AC2 — Wire Automatic Targeted GitHub Ticket Sync into `scripts/session_complete.py`**: Invoke `scripts/sync_github.py --tickets <T## ...>` during live `session_complete.py` runs (prior to final surface refresh & commit, skipped on `--dry-run`, `--skip-land`, or `--skip-gh-sync`; if active `GH_CONFIG_DIR` lacks `read:project` scope, emit a loud warning and run `--issues-only` so closed tickets never remain stale-open on GitHub while keeping `state-doctor` board-mirror accounting honest).
- [ ] **AC3 — Lock Offline RED/GREEN Regression Probes (`scripts/tests/test_ticket_sync.py`, `scripts/tests/test_board_identity.py`, `scripts/tests/test_session_complete.py`)**: Add offline unit probes proving a failed `gh project list` stops immediately with zero `project create` calls, `--tickets` syncs only selected tickets while preserving existing index hashes, `--issues-only` closes `done` issues without calling Projects v2 APIs or marking board hashes clean, and `session_complete.py` invokes targeted GitHub sync cleanly (`just sync-tickets-test`, `just board-identity-test`, `just session-complete-test`, `just py-typecheck`).
- [ ] **AC4 — Reconcile Full Live `webomage/wom7board` Issues + Project `#2` (`w0m Delivery`) & Dogfood `T651`**: Run full live `sync_github.py` (`GH_CONFIG_DIR=$HOME/.config/gh`) to close all `246` completed open issues (`T3`–`T531`), create/close/board-link `T532`–`T650`, backfill `gh_issue:` across `.tasks/`, update `w0m-web/project/tickets.json` + `tickets-sync-index.json`, and complete `T651` via `just session-complete T651` so strictly the `5` genuinely unfinished tickets (`T17`, `T290`, `T504`, `T526`, `T537`) remain `OPEN` on `webomage/wom7board`.
