# T357 — Ingest external project work reports into w0m project progress tracking

## Summary

In multi-project and client delivery engagements (such as `artemioquierocomer.mx`, `bridgeroad`, and `evercred`), autonomous agents and engineers produce rich delivery and session reports documenting shipped tickets, live Cloudflare/Vercel versions, verification metrics, and durable architecture lessons. Currently, these reports are dropped into `@wom/_in/` or client Obsidian vaults as unindexed markdown files, requiring manual review to incorporate lessons and track actual progress.

This ticket builds an automated ingestion pipeline in `w0m`:
1. Parses inbound markdown work/delivery reports from `_in/` or client vaults.
2. Validates metadata (source project, tickets completed, deployment versions, verification gates).
3. Links the work directly to `public.projects` and project progress records in the w0m Control Panel.
4. Automatically extracts and proposes new earned lessons for inclusion in `LESSONS.md`.
5. Automatically archives processed reports to `_arch/` with provenance.

## Acceptance criteria

- [x] AC1 — Schema & Parser Specification: Define an ingestion schema (source project slug, ticket IDs, deployment versions, quality gate results, artifacts, and earned lessons) capable of parsing standard w0m delivery reports (`wom7web/project/report-ingest.schema.json`, `wom7web/project/scripts/report_ingest.py` `parse_delivery_report` & `validate_ingested_report`).
- [x] AC2 — Ingestion CLI Recipe: Author `just project-report-ingest <path>` in `wom7web`/`wom7api/justfile` and root `justfile` that validates report structure, resolves project identity against `wom7web/project/clients-policy.json` and `public.projects`, and dry-run validates payloads (`--dry-run`, `--json`).
- [x] AC3 — Project Progress Sync: Ingested reports idempotently update project milestone/progress records (`wom7web/projects/<project>/vault/mocs/deliverables.md`, `_msg/Progress/<project>-progress.md`, and `public.projects.metadata.progress_reports` when `--sync-db` is passed) with version stamps and completed ticket references (`sync_project_progress` in `wom7web/project/scripts/report_ingest.py`).
- [x] AC4 — Automated Lesson Extraction: Pipeline parses the "Durable Architecture Rules Added" / lessons section of incoming reports and generates formatted candidate rules for `LESSONS.md` with deduplication (`_extract_lessons` and `format_candidate_lessons` in `wom7web/project/scripts/report_ingest.py`).
- [x] AC5 — Automated Archival: Once successfully ingested and recorded, the report is automatically moved from `_in/` to `_arch/` under a project-dated directory (`_arch/<project>_reports_<date>/`) with a SHA-256 `manifest.json` provenance record (`archive_processed_report` in `wom7web/project/scripts/report_ingest.py`).
- [x] AC6 — Regression Suite: Unit and integration tests in `wom7web/project/scripts/tests/test_report_ingest.py` (`6/6` passing via `just project-report-ingest-test`) proving clean ingestion of sample reports (`wom7web/projects/artemio/vault/sources/2026-09-14-artemio-t216-t222-delivery-report.md` and Session 16 `T230`) and fail-closed error handling on malformed reports.
