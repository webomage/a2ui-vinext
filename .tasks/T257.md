# T257 — retiring the emoji protocol

## Summary

[[T256]] made the owner's instruction mechanical for every case where emoji are *decoration*. It
deliberately did not touch the case where they are *protocol*, and this ticket is that case stated
honestly rather than left implied.

The instruction — *prohibit emoji in logs* — is only fully satisfied when script output carries no
pictographs at all. Today **six parsers read emoji as values**, so removing them from producers
without changing the readers does not fail loudly. It fails **green**.

## Why this is dangerous rather than tedious

```python
# project/scripts/run_suites.py:44
CHECK = re.compile(r"^\s*[<pass><fail>]\s", re.M)
```

That is how the estate counts probe results. Convert the producers first and **all 124 registered
suites report zero checks and pass** — an aggregate that has never been greener and measures
nothing. 🔴 **Nothing announces this**, because the observable symptom of the defect is success.

| parser | reads | what breaks |
|---|---|---|
| `run_suites.py` | pass/fail markers **in four dialects** (`✅❌`, `✓✗×`, `ℹ`) | the entire test aggregate silently measures nothing. 🔴 [[T256]] AC8's sweep found three of the four were **undeclared** |
| `tasks_bounds.py` | `STATUS_GLYPH` | a TASKS.md row's status **is** the glyph — needs a row-format migration too, not just a print change |
| `deploy_logged.py` | `STEP` regex | the deploy log stops segmenting into steps |
| `w0m_audit.py` | leading marker, incl. `✗` | probe summaries go blank |
| `debt_register_check.py` | `🔻` in RESOLVED | the down-arrow is **optional** in the pattern, so a resolved TECH-DEBT row silently stops being recognised as resolved |
| `authz_bucket_gate_test.py` | severity markers | finding counts drop to zero, reading as "clean" |
| `authz_grant_gate_test.py` | severity markers | same |

Four of the six fail in the direction that looks like success. That is the whole reason this is a
separate ticket instead of a follow-up commit.

## The only safe order

1. **Teach each parser a text protocol** (`[PASS]` / `[FAIL]` / `[STEP]` / severity words) while it
   still accepts the glyph. Both forms valid, nothing converted yet.
2. **Prove the parser accepts both** — a probe per parser, red first on a text-only fixture.
3. **Convert producers**, in batches small enough that a regression is attributable.
4. **Drop the glyph branch**, and update `emoji-policy.json`'s coupling declaration in the *same
   commit* — `just emoji-check` asserts each declared parser still contains its glyph, so a
   half-finished step fails the gate rather than passing quietly.
5. `tasks_bounds.py` last, because its migration changes **TASKS.md's row format**, not just output.

⚠️ **Do not start by deleting glyphs.** That is the one order in which every intermediate state is
green and wrong.
