## Summary

**Decouple platform adapters from generic models + admin-CP Integrations reorg.** (a) **Schema/UI decoupling**: stop the generic managers assuming Upwork — remove hardcoded Upwork deep-links in `contracts/[id].astro:184–206`, stop `ContractManager.svelte:420` defaulting `source='upwork'`, extract the Connect-Upwork OAuth panel out of `ProposalManager.svelte:332–368`; generalize `InvoiceManager`'s clean `platform` enum across contracts/proposals/leads; reconcile the closed `source` CHECK enum vs free-text `platform`; promote high-value fields out of the opaque `data` JSONB (or formalize per-source shape). (b) **Admin IA reorg**: new top-level **Integrations / Platforms** nav group (move LinkedIn out of "Content", Upwork out of the buried home-dashboard `OpenCLAWDashboard`, Domain Scanner out of "System"); add a **Connections / Sync-Health** board (consolidate `social_integrations`/`get-upwork-status`/`get-bot-status`/OpenClaw `/health`/`workflow_runs`); unify trigger dispatch behind admin-role-enforced routes (rename `/api/admin/domains/trigger` which awkwardly fires `linkedin:sync`; move direct `supabase.functions.invoke` platform calls behind routes); surface/retire orphaned pages (`/business/clients`, `/business/leads`, `/business/vault`, `/business/ats`, `/system/users`).

### (a) Schema and UI decoupling

- [x] **AC1 — the generic managers stop naming Upwork.** Measured 2026-08-27: **13 files** under
      `apps/cp/src` reference Upwork, and four are generic surfaces that should not.
      `pages/business/contracts/[id].astro:184,197,198` build `https://www.upwork.com/…` deep links
      inline; `components/admin/ContractManager.svelte:420` renders `{c.source || 'upwork'}`, so a
      contract with a NULL source *displays as Upwork*; `pages/index.astro:70` computes
      `upworkConnectUrl` on the admin home. ⚠️ **The default is the sharpest of these** — it is not
      a cosmetic string but a claim about provenance made on the reader's behalf, and today 1 of 96
      contracts is `direct` while the UI would show any unset row as Upwork.
      ⇒ A deep link is a per-connector fact (T94 AC4: capabilities are DATA), and a missing source
      renders as missing.
- [x] **AC2 — the Connect-Upwork OAuth panel leaves `ProposalManager`.**
      `components/admin/ProposalManager.svelte:332–368` embeds a provider-specific connect flow in
      a generic manager. It moves to the Integrations surface (b), and the manager keeps no
      knowledge of how a connection is established. ⚠️ Do **not** reimplement the token exchange
      while moving it — T94 AC6 forbids credential material reaching any surface, and a move is the
      moment that rule is easiest to break.
- [x] **AC3 — one vocabulary for "where this came from", not two.** `contracts.source` is a closed
      CHECK (`upwork, direct, deel, oyster, remote`) while `InvoiceManager` writes a free-text
      `platform` (`"direct"`). Both name the same axis and neither can see the other. Reconcile to
      a single column with a single vocabulary across contracts/proposals/leads/invoices.
      🔑 **Decide the closed-vs-open question explicitly and write down why.** [[T204]] AC9 already
      wants `internal` in the set and it is still absent; [[T292]] wants forges recorded without
      being integrated. A closed enum turns "record a new platform" into a migration, which is the
      exact friction T287 removed for `project_repos` on 2026-08-26 — **look at that decision before
      re-making it.**
- [x] **AC4 — high-value fields leave the opaque `data` JSONB, or the shape is declared.** Fields
      the UI reads from `data` are promoted to columns or the per-source shape is written down and
      validated. ⚠️ **Sequenced behind [[T101]]'s synced/authored split** — promoting a field out of
      a blob that `upwork-poller` overwrites wholesale (`upwork-poller/index.ts:573`,
      `.set({ data: c })`) is only safe once authored terms are no longer in that blob's path.

### (b) Admin CP information architecture

- [x] **AC5 — Integrations is a top-level destination, not four places.** LinkedIn moves out of
      *Content*, Upwork out of the buried home-dashboard `OpenCLAWDashboard`, Domain Scanner out of
      *System*. ⚠️ Cites `design-system/` per the [[T183]]/[[T42]] rule, which applies because this
      is a UI change with a spec — unlike a defect fix, where the citation is not applicable.
- [x] **AC6 — a Connections / Sync-Health board, reading ONE source.** Consolidates what is today
      `social_integrations`, `get-upwork-status`, `get-bot-status`, OpenClaw `/health` and
      `workflow_runs`. 🔴 **It must render from the connector's declared `status` capability
      ([[T94]] AC3), not from five bespoke fetches** — otherwise this ticket replaces four scattered
      surfaces with one surface that is still four integrations wide.
      ⚠️ **A connector that cannot report status says so.** T94 AC3's rule is *declared, not
      thrown*: an unknown state renders as unknown and never as healthy.
- [x] **AC7 — trigger dispatch is admin-enforced and honestly named.**
      `/api/admin/domains/trigger` currently fires `linkedin:sync`, and direct
      `supabase.functions.invoke` platform calls bypass the route layer entirely. One dispatch path,
      role-enforced, named for what it does.
- [x] **AC8 — the orphaned pages are surfaced or retired, each with a reason.**
      `/business/clients`, `/business/leads`, `/business/vault`, `/business/ats`, `/system/users`.
      ⚠️ **Retiring is a decision, not a cleanup** — `/business/clients` in particular now has real
      rows behind it (6 clients as of 2026-08-27, [[T165]]), so "orphaned" was a statement about
      navigation, not about data. Re-measure before deleting anything.

### Verification

- [x] **AC9 — a probe that fails on a re-introduced platform assumption.** Asserts that no generic
      manager or generic page contains a provider name — the same shape as
      `just cv-overclaim-check`, whose corpus is discovered from the document rather than declared,
      so a hardcoded provider added tomorrow is caught tomorrow. ⚠️ **Scoped to the generic
      surfaces**, because the Integrations surface (b) legitimately names providers, and a probe
      that fires there is one that gets switched off ([[T135]] AC8).
- [x] **AC10 — verified live in the CP, not from the diff.** One connector rendered end to end
      through the new surface, with its status read from the declared capability. T283 shipped a
      client portal that was correct in source and wrong in production for two days.

## Definition of Done

No generic manager, generic page or generic column in the CP names a platform. A contract with no
recorded source renders as having none rather than as Upwork; the Connect flow lives on the
Integrations surface and nowhere else; and "where this record came from" has one vocabulary across
contracts, proposals, leads and invoices instead of a closed CHECK on one table and free text on
another. Integrations is a top-level destination, and the Connections board reads each connector's
declared `status` capability rather than five bespoke fetches — so adding a connector adds no
surface. A probe fails on a re-introduced provider name in a generic surface, scoped to exclude the
Integrations pages where naming providers is the point. Verified by rendering one connector end to
end in the deployed CP, not from the diff.
