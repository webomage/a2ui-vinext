# T536 — Gate Guild To-dos to platform unit members via capability and restrict /me/todos and todos API

## Summary

Owner direction (2026-10-02): Guild to-dos are an internal operational checklist for w0m unit members, not a generic public member feature or client tool.
Previously, `/me/todos` was declared in `apps/cp/src/lib/context/nav.ts` with `capability: "self"`, which allowed any authenticated user (including external client personas like Carol and candidates like Ravi) to reach the page and call `admin-todos-api`.
This ticket gates to-dos strictly to platform unit members using the capability system:
1. Defines `platform.unit` capability in `@webomage/lib/auth/capability` held only by platform admin or users with an active hat / unit slot in org `w0m` / platform org (`org_kind === "platform"`).
2. Restricts `/me/todos` in `nav.ts` to `capability: "platform.unit"`.
3. Restricts `admin-todos-api` to callers holding a w0m unit membership or platform admin role.
4. Adds explicit boundary verification in `specs/personas/class_reach.spec` proving Carol the client is denied `/me/todos` and Ada the admin reaches `/me/todos`.

## Acceptance criteria

- [x] AC1 — Define `platform.unit` capability in `@webomage/lib/auth/capability` held strictly by platform admin or users homed in a platform/w0m unit or holding an active hat in org `w0m`.
- [x] AC2 — Update `apps/cp/src/lib/context/nav.ts` so `todos` requires `capability: "platform.unit"`, hiding it from clients and refusing unauthorized access in the context gate (`just cp-nav-check` passed with 0 drift).
- [x] AC3 — Enforce platform unit check in `wom7api/supabase/functions/admin-todos-api/index.ts`, returning `403 Forbidden` if caller lacks a w0m unit membership or platform admin role (tested with Deno and verified against local Supabase).
- [x] AC4 — Add persona assertion to `specs/personas/class_reach.spec`: `"Carol" is denied "/me/todos" on "cp"`, passing green, and verify `"Ada" reaches "/me/todos" on "cp"`.
- [x] AC5 — Reconcile `specs/web/admin_todos.spec` and `specs/api/072-admin-todos-api.spec` to use valid test credentials with platform unit capability (both suites pass 100% green).
