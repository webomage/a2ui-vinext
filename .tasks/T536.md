# T536 — Gate Guild To-dos to w0m unit members via capability and restrict /me/todos and todos API

## Summary

Owner direction (2026-10-02): Guild to-dos are an internal operational checklist for w0m unit members, not a generic public member feature or client tool.
Currently, `/me/todos` is declared in `apps/cp/src/lib/context/nav.ts` with `capability: "self"`, which allows any authenticated user (including external client personas like Carol and candidates like Ravi) to reach the page and call `admin-todos-api`.
This ticket gates to-dos strictly to w0m unit members using the capability system:
1. Defines `w0m.unit` capability in `@webomage/lib/auth/capability` held only by platform admin or users with an active hat / unit slot in org `w0m`.
2. Restricts `/me/todos` in `nav.ts` to `capability: "w0m.unit"` and `sides: CONTRACTOR`.
3. Restricts `admin-todos-api` to callers holding a w0m unit membership or platform admin role.
4. Adds explicit boundary verification in `specs/personas/class_reach.spec` proving Carol the client is denied `/me/todos`.

## Acceptance criteria

- [ ] AC1 — Define `w0m.unit` capability in `@webomage/lib/auth/capability` held strictly by platform admin or users homed in a w0m unit (`admin`, `system`, `talent`) or holding an active hat in org `w0m`.
- [ ] AC2 — Update `apps/cp/src/lib/context/nav.ts` so `todos` requires `capability: "w0m.unit"` and `sides: CONTRACTOR`, hiding it from clients and refusing unauthorized access in the context gate.
- [ ] AC3 — Enforce w0m unit check in `wom7api/supabase/functions/admin-todos-api/index.ts`, returning `403 Forbidden` if caller lacks a w0m unit membership or platform admin role.
- [ ] AC4 — Add persona assertion to `specs/personas/class_reach.spec`: `"Carol" is denied "/me/todos" on "cp"`, passing green.
- [ ] AC5 — Reconcile `specs/web/admin_todos.spec` and `specs/api/072-admin-todos-api.spec` to use valid test credentials with w0m unit capability.
