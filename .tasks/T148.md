# T148 — Branch hygiene and main↔beta consolidation

## Summary

**Owner ask, 2026-07-26:** *"sdlc should monitor stale branches and keep everything preserved and
consolidated carefully per stages branches - main and beta"*.

Nothing in the SDLC looks at branches today. All work happens on `beta`, `main` is assumed to trail
it, and no gate verifies that assumption. Measured, the assumption is **false in at least one repo**.

## 🔴 Measured 2026-07-26 — `wom7api`'s branches have DIVERGED

| Repo | `beta` ahead of `main` | `main` ahead of `beta` | Verdict |
|---|---|---|---|
| `wom7web` | **675** | 0 | clean — `main` strictly trails, promotable |
| **`wom7api`** | **447** | **🔴 180** | **DIVERGED — 180 commits exist on `main` that are NOT on `beta`** |
| `wom7ext` | 27 | 0 | clean |
| `wom7sec` | 15 | 0 | clean |
| `wom7cfworkers` | — | — | **no `main` branch at all** |
| `wom7md` | — | — | **no `main` branch at all** |
| `wom7skills` | — | — | **no `main` branch at all** |

Two distinct problems, and the first is the dangerous one:

1. 🔴 **`wom7api` is genuinely diverged, not merely behind.** 180 commits are reachable from `main`
   and not from `beta`. Any "promote beta to main" performed as a fast-forward or a force-update
   would **discard them**, and a plain merge will be non-trivial. **Nobody should touch that pair
   until the 180 are classified** — are they real work, an old release line, or history that was
   rewritten on one side? ⚠️ `STATE.md` already carries a standing warning that force-pushing local
   pre-rewrite branches can **resurrect leaked objects** (see the 2026-07-12 credential leak), so
   force is not an available shortcut here.
2. **Branch topology is inconsistent** — three of seven repos have no `main` at all. A per-stage
   branch model that only exists in four repos is not a model, it is a habit.

## Acceptance criteria

- [x] AC1 A **read-only** branch report: per repo, per branch — ahead/behind vs the stage branch, last
      commit date, whether an upstream is configured, and whether it is merged. Read-only first;
      nothing about this ticket should mutate a branch before the picture is agreed.
      ⚠️ It must use explicit remote refs — `git log @{u}..` returns **0 spuriously** when no upstream
      is set, which is exactly how `wom7mlx` has been reading as "0 unpushed" while holding 3.
- [x] AC2 **Classify `wom7api`'s 180 `main`-only commits** and write the finding down. This is
      analysis, not a merge. Output: are they wanted, and what is the safe consolidation path?
- [x] AC3 Decide and record the **stage-branch model** (which branches exist, what promotes to what,
      who may fast-forward) in `.w0m/sdlc.json`, then make it uniform — including a decision for the
      three repos with no `main`: create one, or state that they are single-branch by design.
- [x] AC4 **Stale-branch monitoring:** flag branches with no commits for N days and no open PR.
      **Report only — never delete.** A branch is cheap; a deleted branch someone needed is not.
- [x] AC5 Wire the report into the SDLC as a **non-blocking** surface (the `deploy`/`archive` gates are
      the natural readers, since promotion is a release-time concern).
      🔴 **Do not make this blocking.** It would fail on day one because of AC2's divergence, and
      per [[T135]] AC8 a gate that starts red is not a gate — it is a thing people bypass.
- [x] AC6 🔴 **AC7 discipline:** prove the report RED (a planted stale branch and a planted divergence
      both appear) and prove it **fails rather than reports "all clean" when it enumerates zero
      branches** — a branch report over an empty ref set is the vacuous pass this estate keeps
      shipping.
- [x] AC7 **Preservation is the priority, per the owner's wording.** No AC in this ticket may
      fast-forward, force-push, prune or delete anything. Consolidation actions are proposed to the
      owner and executed only on explicit approval, one repo at a time.

## Status notes

- **2026-10-22 — Implemented and verified (AC1–AC7):**
  - **AC1 & AC4 (`scripts/branch_hygiene.py`, `just branch-hygiene`):** Built a strictly read-only branch hygiene monitor that inspects explicit refs (`refs/heads/*`, `refs/remotes/origin/*`) via `git for-each-ref` and `git rev-list --left-right --count` (never `@{u}`). Reports per-repo, per-branch ahead/behind vs `refs/remotes/origin/beta`, ISO commit date, upstream configuration, merged status, and staleness (`>= 14` days).
  - **AC2 (Forensic classification of `wom7api`'s 180 `main`-only commits):** Grounded report written to `.agents/reports/T148-branch-hygiene-and-wom7api-main-classification.md` (and mirrored to `wom7web/docs/reports/T148-branch-hygiene-and-wom7api-main-classification.md`). Proven that `origin/main` (`1fbcb1c`, 2026-03-16) and `origin/beta` share merge-base `dfd3d4b240dbbc4f3073030f3e13114b841d3f9d` (2025-12-21), that all 180 commits on `origin/main` have a 1-to-1 positional counterpart in the first 180 commits on `origin/beta` (`dfd3d4b..f70d0ca`, 180/180 matching commit subjects), and that the tip tree SHA of `1fbcb1c` (`origin/main`) and `f70d0ca` (`origin/beta`) is **byte-identical** (`1b6bf2ffb84abaa697263e78e7422e5027d7b587`). Commits `#1..#52` on `origin/main` retain the pre-rewrite `.env` file scrubbed from `beta` during the 2026-07-12 credential-leak history rewrite; commits `#53..#180` have byte-identical trees whose commit SHAs differ solely due to Merkle parent-hash propagation. Therefore **zero unique work exists on `wom7api` `origin/main`**, and merging `origin/main` into `beta` is forbidden because it would resurrect the 52 pre-rewrite `.env` commits.
  - **AC3 (`.w0m/sdlc.json` -> `branch_model`):** Recorded the stage-branch contract per [[AgDR-0032]]: `canonical_branch: "beta"`, `agent_branch_prefix: "agent/"`, `release_tag_prefix: "release/"`, `stale_days: 14`, `single_branch_by_design: ["@wom", "wom7func", "wom7skills"]`, `legacy_main_repos: ["wom7web", "wom7api", "wom7ext", "wom7sec"]` (with `wom7api` marked `diverged_pre_rewrite_do_not_merge: true`), and `excluded_repos: ["wom7mlx/wom7mlx"]`.
  - **AC5, AC6 & AC7 (`wom7web/project/scripts/tests/test_branch_hygiene.py`, `just branch-hygiene-test`):** Wired `branch-hygiene` and `branch-hygiene-test` in both root `justfile` and `wom7api/justfile`. Verified 5/5 probes pass: contract verification, RED probe on planted stale branch with no upstream, RED probe on planted `main↔beta` divergence, vacuity guard failing closed (exit 2) on 0-branch repository, and read-only subcommand whitelist + live-estate non-mutation check.
