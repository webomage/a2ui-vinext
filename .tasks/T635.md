# T635 — Batch Orca Mobile 4-side edge arrows, 4-tap `Alt+M` gesture, smooth `SIGWINCH`/`?2026` resize repaint hold, and `overlay/*` adaptation into single `v1.4.249-w0m.2` release

## Summary

1. **4-Side Edge Arrows Missing from `v1.4.249-w0m.1`**: `feat/mobile-four-side-edge-arrows` (`Edge Pills`, `Edge Strips`, `Floating Orbs`, `Off`, `EdgeNavigationSettingsSection`, and `EdgeNavigationModeSheet`) remained local-only and was not yet pushed to `webomage/orca` or listed in `config/w0m-overlay-branches.json`.
2. **Separate 4-Tap `Alt+M` Gesture Alias**: Alongside `Triple-tap for Enter`, mobile terminal sessions need a separate, independently toggleable **`4-tap for Alt+M`** (`\x1bm`, mode switch in terminal CLI agents) gesture and upstream PR candidate (`feat/mobile-terminal-4-tap-alt-m`), with clean 3-tap vs 4-tap settle disambiguation when both gestures are enabled.
3. **Smooth Terminal Resize & `?2026` Repaint Hold (`fix/terminal-smooth-resize-and-replay`)**: Eliminate the visible top-to-bottom long-scrolling waterfall when CLI agents (`claude`, `codex`, `agy` in xterm's normal scrollback buffer) re-stream conversation history across layout/window resizes (`SIGWINCH`) or multi-chunk synchronized output (`\x1b[?2026h...\x1b[?2026l`) on both Desktop and Mobile.
4. **Inter-Branch Overlay Stacking (`overlay/<branch>`) & GitHub Actions Quota Discipline**: Independent upstream PR branches (`feat/mobile-terminal-triple-tap-enter`, `feat/mobile-terminal-4-tap-alt-m`, `feat/mobile-four-side-edge-arrows`, `fix/mobile-live-input-prompt-backload`, `fix/terminal-smooth-resize-and-replay`) must stay single-concern branches off `upstream/main` for upstream PRs while assembling cleanly together via `origin/overlay/<branch>`, and `w0m-overlay-release.yml` must drop its `17 */6 * * *` cron so overlay releases only run on explicit `workflow_dispatch` after full local verification.
