# T112 — Cross-repo dependency and toolchain alignment

## Summary

>
> **Why it was missing, and why its case differs from the other three restorations:** T38, T39 and

Four TypeScript repos drifted independently: each had its own lockfile, its own floors, and no
shared statement of what a version *must* be. Dependabot and Renovate were evaluated and rejected as
the mechanism — `docs/DEPS-ALIGNMENT.md` records why: they open **per-repo update PRs** and neither
enforces cross-repo floors or lockstep, which is the actual requirement here.

The delivered shape is **one canonical policy plus a lockfile-aware checker**, wired into pre-push so
drift cannot land silently. It grew two categories beyond dependencies during the same day:
a `toolchain` category (pinning the package manager itself) and a host **CLI-tool monitor** with a
smoke-gated auto-updater.

🔑 **The design decision worth preserving:** the auto-updater upgrades *only* a declared-safe subset
and **judges success by whether the version advanced, not by the package manager's exit code** —
`brew` returns non-zero on a spurious *"already linked"*. A gate trusting the exit code would have
reported failure on a successful upgrade.

- [x] **AC1** — one canonical cross-repo dependency policy exists, expressing floors, lockstep,
      documented exceptions and advisories. Evidence: `project/deps-policy.json`.
- [x] **AC2** — a lockfile-aware checker enforces it, with an apply path.
      Evidence: `project/scripts/deps_sync.py` (`--check` / `--apply`), surfaced as `just deps-check`
      and `just deps-apply` (both present in the justfile, verified 2026-08-21).
- [x] **AC3** — the gate runs automatically, not on request. Evidence: wired into **pre-push**.
- [x] **AC4** — real drift was fixed, and the checker **found more than it was pointed at**.
      Evidence: fixed live drift in `undici` and `@hono/node-server`; caught **3 advisories in
      `wom7cfworkers` that no override covered** (`sharp`, `fast-uri`, `@hono/node-server`), ending
      with all 3 TS lockfiles osv-clean. 🔑 The advisories were the finding — the policy was written
      for version skew and surfaced unpatched vulnerabilities.
- [x] **AC5** — the decision not to adopt Dependabot/Renovate is **documented with its reasoning**,
      not left implicit. Evidence: `docs/DEPS-ALIGNMENT.md`, which also records Renovate
      shared-preset pairing as a possible future.
- [x] **AC6** — the package manager itself is pinned across all four repos.
      Evidence: a `toolchain` category added to the policy; **`pnpm@10.32.0`** in every repo's
      `packageManager` (verified 2026-08-21) where previously only `wom7web` was pinned and api,
      cfworkers and ext floated on whatever PATH `pnpm` happened to be (10.17). `deps-check`
      enforces the pin.
- [x] **AC7** — host CLI tooling is inventoried against a policy with minimums and known-good
      versions. Evidence: `project/tools-policy.json` + `project/scripts/tools_check.py` +
      `just tools-check [--strict|--update-known-good]`, covering 16 tools (just, gh, aws, az,
      gcloud, infisical, supabase, terraform, deno, node, python3, osv-scanner, semgrep, gitleaks,
      codegraph, graphify) — all 16 present and at or above minimum. Advisory by design because it
      is per-machine; `--strict` gates the required set for `just audit --deep`.
- [x] **AC8** — the updater is **smoke-gated and scope-limited**, and its risk tiers are explicit.
      Evidence: `just tools-outdated` / `just tools-upgrade [--apply]` upgrade only the safe subset
      (brew, `auto:minor`, non-prod), run each tool's smoke, then promote `known_good` on pass or
      hold on fail. Prod-gating (infisical, supabase, deno), cloud (aws, az) and non-brew default to
      `auto:none` — report-only, manual bump plus deploy smoke, explicitly *"the 2026-07-10 outage
      lesson"*. Ran live: `just` 1.46→1.57, `osv-scanner` 2.3.8→2.4.0, `semgrep` 1.157→1.170 all
      smoke-passed and promoted; 4 held for manual.
- [x] **AC9** — it runs on a schedule and warns at push time without blocking.
      Evidence: `just tools-weekly` (refresh cache + apply the auto subset) for local launchd;
      pre-push warns **non-blocking** from the cache — instant, no brew call — when updates are
      pending or the cache is over 10 days stale.
- [x] **AC10** — the hardening pass on the updater, each item with its own guard:
      **(a)** `infisical` moved `auto:none` → **`auto:patch`** — patch bumps of the prod-gating
      secrets CLI auto-apply *only if* a real injection smoke passes
      (`infisical run --env=dev --silent -- printenv PUBLIC_SUPABASE_URL`); minor and major stay
      manual. ⚠️ That smoke names `--env=dev`; `dev` has since been **renamed `beta`**, and it
      resolves to the **live** database — see [[infisical-dev-env-is-live-db]] before re-running it.
      **(b)** `gcloud` auto-updates as a non-brew SDK — version resolved from the
      `gcloud components list` header, upgrader dispatches by `source`, smoke `gcloud version`, set
      `auto:major` because rolling versions are not semver so the level cap is nominal. Ran live
      **573 → 577**.
      **(c)** `just tools-upgrade --force` escape hatch — also considers `auto:none` **brew** tools
      and lifts the level cap, still smoke-gated; a tool with no smoke is upgraded but flagged
      **UNVERIFIED**, and non-brew tools are listed with their real update command, never
      brew-touched.
- [x] **AC11** — a mislabelled tool source was corrected rather than left to break something:
      `python3` was recorded as brew-sourced and is actually **pyenv** — it must never be
      `brew upgrade`d.
