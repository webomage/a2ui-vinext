# T178 — the lessons skill is installed, unenforced, and w0m-hardcoded; the client uses it and we don't

## Summary

`w0m-lessons` is a canonical skill, installed in `wom7web/.agents/skills/` and declared in
`.w0m/skills.json`. It instructs every agent to append durable findings to `LESSONS.md`. Measured
2026-08-07:

| | `LESSONS.md` | last touched |
|---|---|---|
| **w0m** (`wom7web/.agent/LESSONS.md`) | **827 B** | **2026-06-16** |
| **1945** (client, repo root) | **130,947 B** | 2026-08-07 |

**The client project runs the skill properly. The estate that authored it does not** — and has not
for ~7 weeks.

🔑 **Why, and it is not discipline:** `LESSONS.md` is referenced in **`CLAUDE.md` — no**,
**`.w0m/sdlc.json` — no**, and **`w0m-sdlc-archive` — no**, despite that gate's own description
claiming it *"captures lessons so the ecosystem learns"*. Every other durable surface in this estate
is declared in config and gated (`state_surface` → `state-check` at pre-push; tickets → `sdlc-trace`
at pre-push since [[T110]] AC4). This one is declared nowhere and gated by nothing, so it decayed —
the identical *instruction-without-enforcement* defect T110 AC4 was filed to fix, one level over.

🔴 **And it cannot travel as written: the skill hardcodes `wom7web/.agent/LESSONS.md`.** A w0m
repo path, in a skill shipped to client projects. `1945`'s lessons went to its **repo root** instead,
so an agent had to improvise a path — `CLAUDE.md` explicitly forbids exactly this
(*"project-agnostic skills read the command from `.w0m/sdlc.json` rather than hardcode it"*, the
rule that made the `{secrets.run}` indirection necessary in [[T135]] AC10).

⚠️ **It is also a gap in [[T174]]'s own split.** T174 established *one fact, one home* across three
homes — auto-memory for facts, `CLAUDE.md` for standing rules, the archive for dated history.
`LESSONS.md` is a **fourth** home that the split never mentions, so there is currently no rule
saying which findings belong there rather than in a ticket body. This session is the evidence: its
cross-cutting lessons (*"absence of a DETECTED licence is not absence of a licence"*, *"a gate that
only speaks when it blocks you is one people route around"*) went into ticket bodies and commit
messages, where they are correct but unfindable.

## Acceptance criteria

- [ ] AC1 — **The path is declared, not hardcoded.** `w0m-lessons` reads its target from
      `.w0m/sdlc.json` (a `lessons` key beside `state_surface`), with a documented fallback for a
      project that has no `.w0m/`. No repo name appears in the skill body.
- [ ] AC2 — **Decide where `LESSONS.md` LIVES in w0m and record why.** Today it is
      `wom7web/.agent/` — the **singular** directory, whose `skills` subdir was retired under
      [[T127]] R4. ⚠️ **Verify before acting: the retirement was scoped to `.agent/skills`, not to
      `.agent/` wholesale** (checked 2026-08-07; the directory holds `deployments/`, `rules/`,
      `specs/`, `workflows/` and is live). So this is a *decision*, not an obvious cleanup — do not
      "fix" it by moving the file because the name looks retired.
- [ ] AC3 — 🔴 **Say which findings belong here and which do not**, extending [[T174]]'s
      *one fact, one home* to a fourth home. Without this the skill competes with auto-memory,
      `CLAUDE.md` and the ticket body, and the ambiguity is why nobody used it. Proposed split to
      argue with: **`CLAUDE.md`** = standing rules an agent must follow · **auto-memory** = durable
      facts about this estate · **ticket body** = evidence for one ticket's ACs · **`LESSONS.md`** =
      *transferable* engineering lessons whose value outlives the ticket and is not w0m-specific.
- [ ] AC4 — **Something checks it, or this recurs.** At minimum, `w0m-sdlc-archive` must not be able
      to close a ticket claiming it captured lessons while `LESSONS.md` is untouched — the gate
      currently says it does this and does not. ⚠️ **A per-ticket mandatory-lesson rule is the wrong
      shape**: most tickets have no transferable lesson, and a gate that demands one every time
      trains people to write filler. Prefer a prompt/report over a block, and say which was chosen.
- [ ] AC5 — **Backfill is explicitly OUT of scope, and that is a decision not an omission.**
      Reconstructing 7 weeks of lessons from commit messages would produce plausible prose nobody
      verified — the *confident-sounding wrong handoff* failure `w0m-state-save` warns about. Start
      the file from the fix forward.
- [ ] AC6 — **Proven red** ([[T135]] AC7): whatever check AC4 lands, show it firing on a fixture
      where the condition it names is true, and green on the real tree.

⚪ **Filed 2026-08-07**, from an owner question during a **read-only** review of `1945`:
*"why don't we use w0m-lessons here?"* — a fair question with a measurable answer. Grounded before
filing, **do not re-derive:**

**✅ Installed and declared** — `wom7web/.agents/skills/w0m-lessons` exists and appears in
`.w0m/skills.json`. This is not a missing-install problem.

**✅ Required by nothing** — grep for `LESSONS.md` across `CLAUDE.md`, `.w0m/sdlc.json` and
`w0m-sdlc-archive/SKILL.md` returns **zero**.

**✅ The asymmetry is real and measured**, not an impression: 827 B / 2026-06-16 here against
130,947 B / 2026-08-07 at the client.

**✅ The hardcoded path is in the skill body** — one match for `wom7web|\.agent/` in
`w0m-lessons/SKILL.md`.

⚠️ **I nearly filed a wrong finding here and it is worth recording.** My first read was that the
skill pointed at a **dangling** path. It does not — `wom7web/.agent/LESSONS.md` exists. The defect
is that the path is **w0m-specific in a portable skill**, which is a different and smaller claim.
Checking cost one `ls`; asserting it would have sent this ticket after the wrong thing.
