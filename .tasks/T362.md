# T362 — Resolve conflict between owner request to revoke casualuser@gmail.com admin and the recorded w0m principal-identity decision

## Summary

Requested directly in conversation 2026-09-15: revoke `casualuser@gmail.com`'s admin status,
consolidate admin identity onto `w0m@webomage.com`, and relink `casualuser@gmail.com` to
`aleksei@webomage.com` as a secondary email.

**This directly contradicts a recorded, explicit owner decision.** Per the `wom-principal-identity-model`
memory and the auth-hardening record: `casualuser@gmail.com` is the deliberate, institutional "w0m"
persona (not a personal account standing in for one), `aleksei@webomage.com` is the public person, both
are admin **by design**, and revoking `casualuser@gmail.com`'s admin status was **explicitly declined
by the owner**. The literal request, taken as-is, reverses that decision without saying so.

The target account also does not exist as any kind of verified identity in this project.
`w0m@webomage.com` has **zero matches** anywhere in the tracked repo (`.md`/`.sql`/`.ts`/`.astro`,
verified 2026-09-15) — no `profiles` row, no `connections` row, no prior mention in any ticket, spec,
or migration. And per ROADMAP §14's own named **"Lockout trap"**: the member-CP `@webomage.com`-only
login gate cannot safely enable until every active member has a **verified** `@webomage.com` mailbox —
which depends on [[T28]] (still 🟡 P2, owner-gated, mailboxes not provisioned — `@webomage.com`
addresses "CANNOT RECEIVE MAIL until this lands") — and explicitly requires **"Break-glass admin
required"** before any such cutover. Executing this request today would mean revoking the one
confirmed-working admin identity (`casualuser@gmail.com`) in favor of a mailbox nobody has verified
can receive mail, with no break-glass path in place — the exact lockout ROADMAP §14 was written to
prevent.

This ticket does not execute the swap. It files the request for a grounded decision: either the owner
reconfirms revocation with full awareness of the prior decision and the lockout risk (and the plan is
built safely), or the request is retracted/revised now that the conflict is visible.
