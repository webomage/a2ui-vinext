# T656 — Unify AuthWidget across web and sidebar, consolidate ContextSwitcher + SidebarHatSwitcher into one sidebar control, expose full Me tools on cp, and fix web CTA link contrast

## Summary

Owner live UI review on `webomage.com/careers` and `cp.webomage.com/me/account?mfa_required=1` (2026-11-06) surfaced five interconnected identity, hat-switching, `Me` navigation, and header styling defects:

1. **Redundant Legacy `SWITCH HAT` in `AuthWidget.svelte` (`T54 AC1` & `T530 AC1` drift)**:
   - `T54 AC1` mandated scoping `AuthWidget.svelte` strictly to account identity, workspace launcher links, AI agent entry, and Sign Out — moving hat switching out of `AuthWidget` — and `T530 AC1` (`AgDR-0028`) retired Axis-1 account-class switching (`Member`, `Manager`, `Client`, `Recruit`). However, `AuthWidget.svelte` never deleted `switchRole()` or the `Switch Hat` block (`L327–L349`), still rendered raw emoji icons and a stale `MANAGER`/`MEMBER` subtitle in the sidebar footer, and `openspec/specs/identity-surface/spec.md` + `openspec/specs/web/header_ui.md` still documented `Switch Hat` inside `AuthWidget`.
2. **Four Competing Role/Hat Surfaces in `CpShell.svelte`**:
   - `CpShell.svelte` simultaneously rendered top-left `ContextSwitcher.svelte`, a second stacked `SidebarHatSwitcher.svelte` dropdown below it on `/o/<org>`, a main-pane `HatToolsAvailabilityBar.svelte` card, and bottom-left `AuthWidget.svelte` with `SWITCH HAT` — displaying contradictory role labels (`Tech Lead +5` vs `Unscoped Org Unit Member` vs `MANAGER`) on the same screen.
3. **Nonsensical `HatToolsAvailabilityBar` (`Unscoped Org Unit Member`) on `Me` & `Admin` Pages**:
   - `CpShell.svelte` mounted `HatToolsAvailabilityBar.svelte` unconditionally on `Me` and `Admin` routes where org/project hats do not apply, falling back to `member` (`"Unscoped Org Unit Member"`) and advertising `To-dos & Lists` from pre-`T646` `hat-visibility-policy.json` entries.
4. **Stranded 3-Item `Me` Sidebar on `cp.webomage.com` (`AgDR-0056` / `T646` follow-up)**:
   - `unifiedSwitcherEntries("cp", ...)` hardcoded `Me` to relative `"/me"` (`cp.webomage.com/me`) instead of `https://me.webomage.com/me`, and `unifiedSidebarSections("cp", "me", ...)` rendered only the 3-item Crew stub (`Home`, `My work`, `Account`), hiding all 17 personal & Talent Cloud `Me` UI tools whenever a user entered `/me/account?mfa_required=1` or `/me/work` on `cp`.
5. **Blank Cyan-on-Cyan `Start With Free Audit` CTA Pill on `webomage.com`**:
   - Unlayered `a { color: var(--brand-color); }` in `w0m-web/apps/web/src/styles/global.css` overrode Tailwind v4 `@layer utilities` (`text-slate-950`, `no-underline`), rendering `#nav-free-audit-cta` (`Header.astro`) and solid-fill CTA links across `apps/web` unreadable.

## Acceptance criteria

- [x] AC1 — **Synchronized Account-Only `AuthWidget` Across Header & Sidebar (`AuthWidget.svelte`, `identity-surface.ts`)**: Remove `Switch Hat` and `switchRole()` from `AuthWidget.svelte`, drop the legacy Axis-1 role subtitle (`MANAGER` / `MEMBER`) from the sidebar footer trigger, replace raw emoji icons and hardcoded hex surfaces with accessible SVG icons and design-system CSS tokens, add a direct `Account & security` link, and unify `Your Workspaces` portal labels (`Control Panel (CP)`, `Personal & Talent (Me)`, and `Webomage.com` when inside portals) identically across top-right (`placement="header"`) and bottom-left (`placement="sidebar"`).
- [x] AC2 — **Single Top-Left Sidebar Context + Hat/Side Switcher (`ContextSwitcher.svelte`, `SidebarHatSwitcher.svelte`, `CpShell.svelte`)**: Consolidate `SidebarHatSwitcher.svelte` directly into `ContextSwitcher.svelte` (`hatControls` snippet + active hat summary) so switching Workspace Context (`Me`, `Organizations`, `Admin console`), Engagement/Project Hat (`<contractor>.<engagement>.<client>`), and Delivery/Client side lives in one top-left sidebar control (expanded and collapsed 60px rail modes), with zero second stacked switcher in the sidebar.
- [x] AC3 — **Scope `HatToolsAvailabilityBar` Strictly to Active Narrowing Org/Project Hats (`CpShell.svelte`)**: Render `HatToolsAvailabilityBar.svelte` only inside `org` or `project` contexts when a narrowing engagement/project hat is worn (`Boolean(liveActiveProject?.roleSlug) || liveHatAvailability.narrowCatalog`), never on `Me`, `Admin`, or unscoped default states (`Unscoped Org Unit Member`).
- [x] AC4 — **Unified `Me` Context Target & Full `Me` Tool Sections Across `cp` and `me` (`shared-sidebar.ts`)**: Point `unifiedSwitcherEntries("cp", ...)` `Me` entry to `https://me.webomage.com/me`, and update `unifiedSidebarSections` so `Me` context on `cp` renders all 5 `Me` tool sections (`Personal Hub`, `Profile & Public Identity`, `Talent Cloud & Vetting`, `Freelance & Outreach`, `Economy & Account`), keeping `My work` (`/me/work`) and `Account & security` (`/me/account`) local on `cp` for MFA/`cp.w0m.xyz` while linking personal/talent tools to `me.webomage.com/me/*` (and surfacing `My work` cross-portal on `me` for delivery members).
- [x] AC5 — **Fix `apps/web` Unlayered Anchor CSS Override & Reconcile OpenSpec Docs (`apps/web/src/styles/global.css`, `openspec/specs/identity-surface/spec.md`, `openspec/specs/web/header_ui.md`)**: Move base `a { ... }` styling in `apps/web/src/styles/global.css` into `@layer base` (preserving brand link defaults while honoring `text-slate-950` / `no-underline` utilities on `#nav-free-audit-cta` and solid CTA links), update visual goldens if affected via `just goldens-regen`, reconcile `openspec/specs/identity-surface/spec.md` and `openspec/specs/web/header_ui.md`, and pass unit/conformance/golden suites.
