# T471 — Cross-device human presence confirmation gate

## Summary

Owner direction (2026-09-27):
> "another thing - I tried to do migration and deploy from mobile Orca app and it looks like TouchID was requested correctly at host machine
> but I want to enhance w0m system and let Orca support this across devices - use TouchID/TOTP/Key across any devices working with the w0m development sessions"

Currently:
`confirm_step.py` invokes `human_presence.swift`, which binds strictly to the host macOS LocalAuthentication framework (`LAPolicy.deviceOwnerAuthentication`). When working remotely through the mobile Orca app, remote development sessions, or non-macOS thin clients, the biometric prompt appears on the desk Mac rather than the user's active device in hand.

Objective:
Enhance `confirm_step.py` to support cross-device confirmation:
1. **Orca Mobile Biometric Bridge**: If connected via Orca IDE / mobile client, dispatch an interactive confirmation push to the mobile device requesting local TouchID / FaceID.
2. **TOTP Fallback**: When working from a terminal without local macOS biometrics, allow entering an authenticator code (verified against the admin's enrolled TOTP secret) to confirm.
3. **WebAuthn / Passkey / Security Key**: Support FIDO2 / Passkey challenge responses over WebAuthn.

## Acceptance criteria

- [x] AC1 — **Cross-Device Confirmation Protocol Spec**: Define architecture for remote human presence challenge/response between `confirm_step.py` and Orca client sessions.
- [x] AC2 — **TOTP Terminal Fallback in confirm_step.py**: When LocalAuthentication is unavailable or running in a verified remote/mobile interactive session, offer 6-digit TOTP verification against the admin secret.
- [x] AC3 — **Orca Mobile Client Relay**: Author protocol integration allowing Orca mobile app to trigger native iOS FaceID/TouchID and return signed assertion to mint `$TMPDIR/w0m-confirm-consent.json`.
- [x] AC4 — **Security Invariants Preservation**: Ensure agent sessions remain strictly refused (Layer 1 agent detection unchanged); remote consent must be cryptographically signed and bound to the specific git HEAD.
