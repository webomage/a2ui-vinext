# T275 — the half of T261 that was accepted rather than fixed

## Summary

Owner decision 2026-08-24: *"for now we do non-blocking warning for T261 remainings and let's do
followup P2 ticket to review and complete this fully."*

[[T261]] took the responsive layout from **94 violations to 9** across 33 measured rows and shipped
it — verified against production on 2026-08-23, every figure matching local. The remaining 9 were
**accepted as debt, not fixed**: [[D60]] and [[D61]]. This ticket is that debt, plus the gate change
the acceptance implies.

## What is actually still red

Measured across 11 viewport/orientation pairs x 3 pages, and confirmed against `https://webomage.com`:

| rule | rows | measurement |
|---|---:|---|
| **`content-window`** ([[D60]]) | 6 | at **812x375** the clear reading window is **207px / 55%**; at **844x390** it is **222px / 57%** — against a **60%** threshold |
| **`h1-wrap`** ([[D61]]) | 3 | `/blueprints` needs **1167.63px** at 68px against a **1152px** measure — short by **16px / 1.4%**, at 1280, 1440 and 1920 |

Everything else is green: 0 clipped text, 0 orphans, 0 horizontal overflow, 0 oversized type, H1 on
one line on every page except `/blueprints`.

⚠️ **D60 is not a small gap that was nearly closed.** It went 27% → 55% because the
`max-height: 600px` compact footer did most of the work. The remaining 5 points are a 72px header
plus a footer on a 375px-tall screen, and reaching 60% means restructuring the shell — which the
**T221 note in `BaseLayout`** explicitly calls delicate. Treat "just shrink the header" as a
hypothesis to test, not a plan.

## The gate change, which is the more reusable half

`just layout-matrix-check` stays **non-blocking / warning-only**, and its promotion trigger was
retargeted on 2026-08-24 to point at **D60 and D61 being resolved** rather than at T261 closing.

🔴 **Why the old trigger had to go, because the same mistake is easy to repeat.** It read *"flip to
blocking when that finding is resolved **or accepted as debt**"* — and the finding **was** accepted
as debt, while the very next sentences argued that flipping it would redden the aggregate for a
decision already made ([[T135]] AC8). **A trigger whose condition has fired and whose reasoning says
do not act on it is a dead instruction.** The next reader either flips it (permanent red) or ignores
it (governance text nobody obeys), and neither is a decision. ⇒ Promotion conditions must be states
of the **product**, never of the **paperwork**.

🔑 **The end state this ticket should reach is a VALUE ratchet, not a flip.** Record 55% / 57% / 16px
as a baseline and fail on any regression below it, while keeping **60% as the stated goal**. That is
strictly better than either option available on 2026-08-24:

- it **fires the moment anything gets worse**, which the current warning-only state does not;
- it **can only ever be tightened**, so it cannot become a quiet weakening;
- and it does **not** lower the threshold — the estate's standing rule is that weakening a minimum
  to clear it is the same act as raising a ratchet baseline.

It is also a known shape here, not an invention: `emoji-check` already ratchets this way.

## Acceptance criteria

- [ ] AC1 — **Re-measure before changing anything.** `just layout-matrix` against production and
      against local. The numbers above are from 2026-08-23 and are a claim with a date ([[T67]]);
      the site has shipped since.
- [ ] AC2 — **[[D61]] is resolved or re-accepted with a reason.** 16px on one heading at three
      desktop widths. ⚠️ **Shrinking type to fit is the treadmill the debt row names** — the options
      worth pricing are a wider measure on that page, a shorter heading, or an explicit per-page
      override with a recorded decision. **Not** a quiet global reduction.
- [ ] AC3 — **[[D60]] is resolved, re-scoped, or re-accepted with the shell question answered.**
      Reaching 60% at 375px tall means the header/footer restructure that [[T221]] calls delicate.
      A recorded *"we are not doing this, here is why"* satisfies this AC fully — the point is that
      the decision is made deliberately rather than inherited.
- [ ] AC4 — 🔑 **The gate ratchets on measured VALUES.** Baseline 55% / 57% / 16px (or whatever AC1
      re-measures), fail on regression, 60% retained as the goal in the message. The threshold is
      not lowered.
- [ ] AC5 — **A red probe proves the ratchet fires.** Feed it a synthetic measurement one point
      worse than baseline and observe it fail. Following [[T261]] AC6's own standard: that detector
      reported **0 clipped elements on a page clipped on purpose**, and it passed all 33 rows while
      every H1 rendered at 16px. **A gate here has been wrong three times; assume the fourth.**
- [ ] AC6 — **The suite is promoted to blocking only when it can pass**, and the registration's
      `reason` is rewritten to say what it now measures. A blocking suite that is red on arrival
      teaches people to route around the aggregate.
- [ ] AC7 — **The debt rows are deleted, not edited to look resolved.** Per CLAUDE.md: *"delete rows
      the ticket pays down"*. If a row survives, it survives with a NEW measurement and a new date,
      never with the old numbers and a tick.

## Definition of Done

Per [`../../openspec/SPEC-AUTHORING-STANDARD.md`](../../openspec/SPEC-AUTHORING-STANDARD.md):
the layout is re-measured, D60 and D61 are each resolved or deliberately re-accepted with reasons,
the gate ratchets on measured values with a probe observed failing, and the suite is blocking only
if it can actually pass.
