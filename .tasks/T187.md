# T187 — automate the union refresh, without merging a half-built graph

## Summary

Owner ask 2026-08-08: *"we can update on after_push?"* — after [[T186]] required **two** manual
`just graph-global` runs to keep the union current.

🔴 **There is no `post-push` hook in git.** Client-side you get `pre-push` (fires with the commits
already local) and `post-commit`. The ask is sound; the named mechanism does not exist.

## 📍 The gap, measured 2026-08-08

**Two artifacts, one automated:**

| artifact | built by | automated? |
|---|---|---|
| per-repo graph (`graphify-out/graph.json`) | `_rebuild_code()` in `.husky/post-commit` | ✅ every commit, **backgrounded** |
| **cross-repo union** (`~/.graphify/global-graph.json`) | `just graph-global` | 🔴 **nothing — manual only** |

`CLAUDE.md` makes `just ask` the **default first action**, and `just ask` reads the **union**. So the
one artifact the estate is told to consult first is the one nothing maintains. It reached **5 stale
repos** before this session, and `preflight` *detects* that without fixing it.

**Cost of the fix:** a no-op union refresh measures **1,448 ms**, against a pre-push already running
a dozen checks.

## 🔴 The race — why "just run it at pre-push" is not sufficient

`post-commit` launches the per-repo rebuild **in the background**. A union refresh moments later can
merge a graph that is still being written. And the manifest makes that invisible:

```python
commit = built_at(repo)                    # graphify-out/graph.json → built_at_commit
rc_h, head = run(["git", …, "rev-parse", "HEAD"])
manifest[tag] = {"built_at_commit": commit, "head_at_merge": head,
                 "basis": "built_at_commit" if commit else "head_at_merge", …}
```

🔑 **`graphify extract` does not stamp `built_at_commit` — only `graphify update` does, so 6 of 7
repos have no stamp** (already recorded in the code's own comment). For those, the manifest falls
back to **repo HEAD at merge time**. ⇒ **A mid-rebuild graph is recorded as being at HEAD.** The
union then reports *current* while holding older content — the estate's signature failure, in the
artifact `just ask` trusts most.

⚠️ **The existing `basis` label is honest about WHICH field it used; it is silent about whether the
graph was FINISHED.** Those are different claims and only the second one matters here.

## Acceptance criteria

- [x] **AC1 — a settle check exists**: before merging repo R, the refresh confirms R's
      `graphify-out/graph.json` is not being written (mtime stable across a bounded wait), and
      merges only then.
- [x] **AC2 — an unsettled repo is reported, never silently recorded as current.** If R does not
      settle within the budget, R is **skipped** and named, and the manifest keeps its previous
      entry rather than stamping `head_at_merge`. 🔴 **A skip must be visible in the summary line**,
      per the [[T96]] AC3 lesson — a skipped member folded into a green is the defect, not the skip.
- [x] **AC3 — wired at `pre-push`, after the blocking gates.** A push must not be gated on graph
      freshness: the union is a **writer**, not a correctness gate. Non-zero from the refresh must
      not fail the push.
- [x] **AC4 — declared in `stacks-policy.json → stacks.web.gates`** so `hooks-check` enforces
      declared ⇒ wired. An automation that only *exists* in a hook file is one nothing verifies.
- [x] **AC5 — proven RED and GREEN.** RED: with a rebuild simulated in flight, the refresh skips
      that repo, says so, and does **not** advance its manifest entry. GREEN: a stale union is
      current after one push, and `just preflight` goes from `union STALE` to `union current`
      without a manual run.
- [x] **AC6 — the added wall-clock is measured and recorded**, not estimated. If it exceeds ~3 s on
      a no-op, reconsider the phase rather than shipping a tax on every push.

## Definition of Done

- The union is current after a push, with no manual `graph-global`.
- An in-flight rebuild produces a visible skip, never a false "current".
- `hooks-check` sees the role as declared and wired; `preflight` green.

## 🔴 Found while proving AC5 — the staleness signal has a BLIND WINDOW (filed as D40)

Immediately after `git commit`, `preflight` reported **`union current`** — while the union was in
fact a commit behind. `graph_health` compares the manifest against the **per-repo graph's**
`built_at_commit`, not against repo **HEAD**. During the window in which `post-commit`'s background
rebuild has not yet re-stamped the graph, *manifest == graph* and the check reports current — while
**both are behind HEAD**. Minutes later, once the rebuild landed, the same command correctly said
`STALE`.

🔑 **Two artifacts can agree with each other and both be wrong.** The comparison is between two
derived things; neither is the source of truth. ⚠️ **This does not undermine T187** — the pre-push
refresh runs regardless of what the staleness check believes, and `--settle` covers the same window
from the writing side. But anyone reading `union current` inside that window is being told something
false, so it is filed rather than absorbed.
