# T516 — Group A: convert 12 useful scripts into regular tools

## Summary

Split from [[T509]]. The root-migration research listed 37 scripts as "no caller" and recommended deleting them. The owner
(2026-09-30) said many are useful and should become regular tools, so each was re-read and weighted. Twelve earn conversion.
"Regular tool" means the estate's standard shape: a `just` recipe, `--help`, a test registered in
`wom7web/project/test-suites.json` (the drift gate blocks otherwise), secrets only by `infisical run` injection, and any
mutating mode behind an explicit flag with a dry run as the default.

Scores are 1 to 5 for Value (answers a recurring need), Reuse (generic, not ticket-specific) and Ready (arguments, guards,
size), measured 2026-09-30 by reading each file.

## Acceptance criteria

- [ ] AC1 — **Each tool has a recipe, a `--help` and a one-line purpose.** The recipe appears in `just --list`. Where a script
  lives is decided by [[T509]]'s placement rule: estate-wide tools at the root `scripts/`, tools that touch one repo's code
  or schema in that repo (see Q1).
- [ ] AC2 — **Each tool has a test that runs offline,** with at least one red probe (a mutation that must flip the result),
  registered in `test-suites.json`. `suites-drift` stays at 0 undeclared.
- [ ] AC3 — **No tool prints a secret.** `keys-verify` outputs key name, type and hash only (the api-keys `hash` field is a
  base64url SHA-256, enough to show a leaked key is still live without showing it). A test feeds a known fake key and
  asserts it appears nowhere in stdout or stderr.
- [ ] AC4 — **Secrets only by injection.** No tool reads a `.env` or a literal. A missing secret fails closed with a clear
  message. `grep` for `.env` and for long token-shaped literals in the converted files is empty.
- [ ] AC5 — **Mutating tools default to dry run.** `secrets-push` and `hygiene-docs` change nothing without an explicit
  flag; `secrets-push` is also behind `_confirm`.
- [ ] AC6 — **`secrets-push` target is verified before it is trusted.** The script writes to an Infisical environment named
  `prod`. The session notes say `prod` and `production` did not resolve (only `beta` does); re-test read-only and either
  fix the environment name or record that the tool has no valid target yet.
- [ ] AC7 — **`tinybird-init` waits for [[T515]].** It is converted only after the token literal is gone and rotated.
- [ ] AC8 — **Old paths are not left behind.** Each script is moved with `git mv`, every caller updated in the same commit,
  and the stale-path probe from [[T509]] (when it exists) or a manual search for the old path returns nothing.

## Open questions (recommended answer first, with weight)

1. **Placement.** *Recommend root `scripts/` for `zeroclaw_manage`, `status_truth`, `write_hygiene_docs`,
   `zc_compression_measure`, `graph_callsites`, `infisical_set_prod`, `get_keys`; keep `ds_inventory` in wom7web, and
   `ai-eval`, `resume-assist-eval`, `get_upwork_auth`, `init_tinybird_schemas` in wom7api.* Weight: follows the A/B rule in
   [[T509]] (estate input goes to the root, one repo's code or schema stays); wrong placement means moving twice.
2. **Order.** *Recommend `keys-verify` first (it is a live hazard), then `zeroclaw-*` and `status-truth`, then the rest.*
   Weight: the key printer is the only item that can leak something today.
3. **`secrets-push` if `prod` has no valid target.** *Recommend not shipping it until a target exists.* Weight: a tool that
   writes to a nonexistent environment gives false assurance.
