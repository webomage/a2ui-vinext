# T490 — the extension cannot receive the admin broadcast it was built for

## Summary

Split from [[T453]] AC4 (private `extension_commands` channel). Measured 2026-09-29 while trying to verify AC4 with a real
extension: **no extension build can receive a hosted admin broadcast today.**

- `wom7ext/extension/src/background.ts` subscribes to `extension_commands` **only** inside `if (EXT_MODE === 'local')`.
- In local mode `supabaseService.ts` points at `http://127.0.0.1:54321` (the local stack) and signs in as a mock
  `local-dev@webomage.com` user, while the CP/web `broadcast-extension.ts` routes send to the HOSTED project.
- A release (`normal`) build has no subscription at all.

So the channel had no live subscriber to break when it went private, and AC4's "extension receives an admin broadcast" cannot
be shown with the current extension. T453 verifies AC4 by other means (an anonymous client is refused; an admin session
receives); this ticket is the feature that makes the extension a real subscriber.

## Acceptance criteria

- [x] AC1 — A **normal-mode** build subscribes to `extension_commands` with `config: { private: true }` **as the signed-in
  admin** (the member's real hosted session via `supabaseService.getAuthenticatedSession`, rejecting mock `local-dev@webomage.com` sessions in `normal` mode); no subscription when signed out (`commandChannelStatus: 'unauthenticated'`).
- [x] AC2 — A non-admin session's subscribe is refused by RLS (`CHANNEL_ERROR` / `TIMED_OUT` / `UNAUTHORIZED`) and the extension records `commandChannelStatus: 'unauthorized_or_refused'`, unsubscribes, and removes the channel instead of retrying forever.
- [x] AC3 — `RUN_SPEC` and `PING` payloads are validated (`validateRemoteCommandPayload` against `ALLOWED_REMOTE_COMMANDS` and `ALLOWED_REMOTE_SPEC_ACTIONS`) before `handleMessage` acts on them; unknown events or disallowed action IDs are dropped and logged.
- [x] AC4 — Proven in `wom7ext/extension/src/__tests__/backgroundCommands.test.ts`: authenticated admin normal-mode build subscribes to private `extension_commands` and receives allowlisted `RUN_SPEC` broadcasts, while signed-out, mock `local-dev`, and non-admin RLS-refused profiles do not receive broadcasts.
