## Summary

**Gemma 4 Rust port (`wom7-mlx-rs`)** — port the Rust MLX server off the retired GLM-4.6V path to Gemma 4: a gemma4 loader + dense Gemma decoder + SigLIP vision (+ audio) on `mlx-rs`. mlx-vlm (Python) gemma4 serving is live as the reference; GLM logit-mismatch diagnostic parked.

## Acceptance criteria

- [ ] AC1 — **Gemma 4 weight and config loader**: Implement a dedicated checkpoint loader in `wom7mlx/wom7mlx/src/loader.rs` to ingest Gemma 4 safetensors tensors and JSON model configurations into MLX arrays.
- [ ] AC2 — **Dense Gemma decoder implementation**: Implement the core Gemma 4 transformer decoder blocks (RMSNorm, rotary position embeddings with scaling, GeGLU MLP activations, and grouped-query attention) in `wom7mlx/wom7mlx/src/model/` using `mlx-rs`.
- [ ] AC3 — **SigLIP vision encoder integration**: Implement the SigLIP vision transformer encoder and multimodal projection layer in `wom7mlx/wom7mlx/src/vision.rs` to encode image inputs into prefix tokens.
- [ ] AC4 — **Logit parity against mlx-vlm reference**: Validate generated tokens and next-token logits against the Python reference `mlx-vlm` runner on standard vision/text prompt inputs, verifying parity within numerical tolerance.
- [ ] AC5 — **Diagnostic and benchmark tool verification**: Update `wom7mlx/wom7mlx/src/bin/diagnose.rs` and `wom7mlx/wom7mlx/src/bin/benchmark.rs` to benchmark Gemma 4 inference latency, token throughput (tok/s), and Metal memory footprint.
- [ ] AC6 — **P3 consolidation alignment**: Ensure implementation is bounded strictly to the `wom7mlx/wom7mlx` workspace and documented under [[T184]], with no failing gates introduced to other repos.
