# T648 — Fix rollout friction: multi-platform Terraform locks & retired Worker domain handoff, root secret-sync workspace paths, and first-deploy `webomage-me` secret bootstrap

## Summary

Remediate three infrastructure and secret-sync defects surfaced during the owner's `T646` (`me.webomage.com` + `cp.webomage.com`) production rollout on the Linux host (`HP`):

1. **Cross-OS Terraform `.terraform.lock.hcl` `h1:` mismatch + uninitialized stacks + retired `join`/`job` Worker custom-domain collision**: All three Terraform stacks (`w0m-api/{cloudflare,supabase-settings,monitoring}`) carried only macOS `darwin_arm64` `h1:` directory hashes, causing `terraform apply` on Linux (`linux_amd64` with `~/.terraformrc` `plugin_cache_dir`) to fail provider checksum verification; `cf-apply` and `supabase-settings-apply` did not run idempotent `terraform init -input=false` first; and `join.webomage.com` / `job.webomage.com` still held read-only Worker Custom Domain `AAAA 100::` records (`webomage-join`, `webomage-job`) that must be detached before `cloudflare_record.{join,job}_redirect_edge` creates replacement `AAAA 100::` records.
2. **Root `sync-*-secrets` recipes running `pnpm exec wrangler` outside workspace roots**: Six `sync-*-secrets` recipes in `just/estate.just` ran from `@wom` root (where no `node_modules/.bin/wrangler` exists), failing with `ERR_PNPM_RECURSIVE_EXEC_FIRST_FAIL: Command "wrangler" not found`.
3. **First-deploy `webomage-me` secret bootstrap chicken-and-egg**: Because `webomage-me` does not exist on Cloudflare until `deploy-me` runs (`code: 10007`), `sync-me-secrets` cannot run before first deploy while `smoke-live` inside `deploy-all` needs `PUBLIC_SUPABASE_URL` / `PUBLIC_SUPABASE_ANON_KEY` immediately after `deploy-me`.

## Acceptance criteria

- [x] **AC1 — Multi-platform `.terraform.lock.hcl` (`darwin_arm64`, `darwin_amd64`, `linux_amd64`, `linux_arm64`), self-initializing `cf-apply` / `supabase-settings-apply`, & retired Worker domain handoff**: Lock multi-platform provider hashes across `w0m-api/{cloudflare,supabase-settings,monitoring}/.terraform.lock.hcl`, add `scripts/retire_cf_worker_domains.py` (+ `scripts/tests/test_retire_cf_worker_domains.py`) to detach retired `join.webomage.com` / `job.webomage.com` Worker custom domains idempotently during `cf-apply`, wire `terraform init -input=false` + `-auto-approve -lock=false` in `cf-apply` and `supabase-settings-apply`, and verify read-only `just tf-plan` and `just supabase-settings-plan` exit `0` with zero `.terraform.lock.hcl` drift.
- [x] **AC2 — Workspace-scoped `sync-*-secrets` recipes & first-deploy `webomage-me` secret bootstrap**: Prefix all six `sync-*-secrets` recipes in `just/estate.just` with their owning workspace directory (`cd w0m-web`, `cd w0m-cf`, `cd w0m-api`), handle pre-creation `10007` gracefully in `sync-me-secrets`, bootstrap missing `webomage-me` secrets automatically inside `deploy-me` right after `wrangler deploy` before `smoke-live`, and pin workspace scoping + multi-platform Terraform locks in `scripts/tests/test_deploy_elevation.py`.
