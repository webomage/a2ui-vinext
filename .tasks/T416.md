# T416 — Add Area Column to HOT, SDLC, and EPIC Tasks Tables

## Summary

The task boards rendered by `tasks_query.py` (`just tasks`) display three core tables: `HOT` (actionability), `SDLC` (completeness), and `EPIC` (the declared active plan). While tickets carry a closed `area:` vocabulary (`sdlc`, `product`, `security`, `tools`, `ai`, `infra`, `schemas`, `knowledge`, `skills`, `mcp`, `data`) and GitHub Projects v2 models `Area` as a primary single-select field, none of the three default boards displayed this axis.

This ticket adds an `Area` column to:
1. `markdown_hot` (`HOT` board)
2. `markdown_sdlc` (`SDLC` board)
3. `plan_summary` (`EPIC` / canonical plan board)

The position is uniformly placed after `Status` (`| Prio | Status | Area | ...`), maintaining consistent alignment and clean terminal presentation across all three views.

## Acceptance criteria

- [x] AC1 — `markdown_hot(rows)` renders an `Area` column between `Status` and `Score` (`| # | Ticket | Issue | Prio | Status | Area | Score | Title |`).
- [x] AC2 — `markdown_sdlc(rows)` renders an `Area` column between `Status` and `ACs` (`| # | Ticket | Issue | Prio | Status | Area | ACs | Done | Blocked by | Title |`).
- [x] AC3 — `plan_summary(tickets, plan=None)` renders an `Area` column between `Status` and `ACs` (`| Stage | Ticket | Issue | Prio | Status | Area | ACs | Done | Title |`).
- [x] AC4 — `terminalise()` formats all three tables cleanly without column overflow, misalignment, or broken link escapes.
- [x] AC5 — `just tasks-render-test` asserts presence and alignment of the `Area` column in all three boards and passes cleanly.

## Definition of Done

1. `just tasks` renders the `Area` column across HOT, SDLC, and EPIC tables.
2. `just tasks-render-test` passes (100% green).
