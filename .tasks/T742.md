# T742 — Auto-heal degraded Cloudflare WARP IPv6 tunnel on PMTU drop below 1280 and ensure check-warp runs before db-drift-check in _deploy-preflight

## Summary

During release `2026.11.14-1794666347` (`deploy-logs/run-2026.11.14-1794666347.log`), `just deploy-all` failed at `check-warp` (`line 805`) on `db.pqbbjgeapylcengbuvee.supabase.co:5432` TCP timeout (`5s`), right after `_deploy-preflight` had already printed `db-drift-check: psql failed` and incremented `other_trouble` (`0 -> 2 (+2)`) in `deploy-audit-latest.json`.

Forensic analysis (`journalctl -u warp-svc -b`) uncovered two defects:
1. **Zombie IPv4-only `Connected` WARP state after QUIC PMTU dropped below `1280` (`IPV6_MIN_MTU`):** At `2026-11-14 06:36:21`, `quiche::pmtud` adjusted `CloudflareWARP` MTU to `1222`. Because Linux deletes global IPv6 addresses and flushes all IPv6 routes on interfaces whose MTU falls below `1280`, `table 65743` lost all IPv6 routes (`DelRoute`) while IPv4 stayed up and `warp-cli status` continued reporting `Connected`. Because `check-warp` only called `warp-cli connect` when `status` lacked `"Connected"`, it skipped recovery even though the IPv6-only Supabase Postgres host was unreachable.
2. **Pre-WARP `db-drift-check` ordering in `_deploy-preflight`:** `_deploy-preflight` ran `just db-drift-check` before `check-warp` had connected or healed WARP, causing spurious `db-drift-check: psql failed` warnings before Touch ID confirmation.

## Acceptance criteria

- [x] AC1 — `check-warp` in `justfile` detects when `warp-cli status` reports `Connected` (or IPv4 endpoints succeed) while `scripts/check_db_host.py --host db.{{ project_ref }}.supabase.co` fails on the first probe, performs one automatic `warp-cli --accept-tos disconnect && sleep 2 && warp-cli --accept-tos connect` recovery cycle (waiting up to 30s for `Connected`), and retries `scripts/check_db_host.py` before failing closed.
- [x] AC2 — `_deploy-preflight` in `justfile` invokes `@if command -v warp-cli >/dev/null 2>&1; then just check-warp; fi` before `@just db-drift-check` so `just deploy` / `just deploy-all` connect or self-heal WARP before `db-drift-check` runs `psql` and before prompting for Touch ID.
- [x] AC3 — Add regression tests in `scripts/tests/test_deploy_chain_order.py` asserting `_deploy-preflight` runs `just check-warp` before `just db-drift-check` and that `check-warp` includes self-healing reconnect logic (`warp-cli --accept-tos disconnect` + `connect` + retry of `check_db_host.py`).
