# T640 — Audit connected services & pgvector vs ClickHouse, retire leaky browser OTel, enable native Worker observability, and batch WarpScene WebGL draw calls

## Summary

Post-`T636` live verification of `https://webomage.com` (`release/2026.11.04-1793824626`, passive security `89/100 Grade B`, Accessibility `100`, SEO `100`, `0` third-party cold cookies) alongside a full Triangulated SSOT audit of Honeycomb, PostHog, Tinybird, Cloudflare, Supabase `pgvector`, and all connected services exposed four concrete gaps:

1. **Honeycomb Browser OTel Leak & CSP Console Failure (`Tracing.svelte`) + Dead SSR OTel (`otel-server.ts`) + Unwired CP Tinybird Worker Env (`observability.ts`)**:
   - `apps/{web,cp}/src/components/Tracing.svelte` bundled `@opentelemetry/sdk-trace-web` (~91 KB), exposed `PUBLIC_HONEYCOMB_API_KEY` (`X-Honeycomb-Team`) in public client JS, and posted spans to `https://api.honeycomb.io/v1/traces`, which our `T636` CSP `connect-src` blocked (`errors-in-console = 0`, `inspector-issues = 0`, holding Lighthouse Best Practices at `73/100`).
   - `apps/{web,cp}/src/lib/otel-server.ts` had zero importers across the monorepo and checked `typeof XMLHttpRequest === "undefined"`, returning early on every Cloudflare Worker invocation.
   - `apps/{web,cp,job,join,demo}/wrangler.jsonc` left Cloudflare Workers native `"observability": { "enabled": true }` off (unlike `wom7api` and `wom7func`).
   - `apps/cp/src/lib/observability.ts` read `process.env.TINYBIRD_TOKEN` and `TINYBIRD_API_URL`, both empty in Astro Cloudflare Workers (`AgDR-0023` requires `import.meta.env` and Infisical defines `TINYBIRD_URL`), causing `/admin/services` to report `configured: false` in production.
2. **`ThreeBackground.svelte` & `WarpScene.ts` WebGL Draw-Call Storm (`60.2s` Lighthouse CPU)**:
   - `WarpScene.ts` created `2,000` separate `THREE.Line` meshes (`2,000` `BufferGeometry` + `2,000` `LineBasicMaterial` = `2,000` WebGL draw calls per frame), and `ThreeBackground.svelte` statically imported and instantiated all 17 Three.js scenes on mount (16 deprecated in `T452`), burning `60,245 ms` (`67.5%`) of main-thread CPU in headless/throttled Lighthouse runs (`bootup-time = 0`, `mainthread-work-breakdown = 0`).
3. **`ChatApp.svelte` `#chat-toggle` Accessible Label Mismatch & `just smoke-live` Flag**:
   - `<button id="chat-toggle" aria-label="Open chat (1 unread)">` rendered an unhidden `<span class="notification-badge">1</span>` (`nodeLabel: "1"`), failing `label-content-name-mismatch`.
   - `justfile` `smoke-live` invoked `scripts/live_verify_helper.py crawler-smoke --url {{ url }}`, an unrecognized CLI flag (`crawler-smoke` uses `--crawler-url` with a built-in default).
4. **Connected Services Inventory & `pgvector` vs ClickHouse Free Tier + Keep-Warm Decision**:
   - Live Supabase Postgres measured `148.60 MB` / `500 MB` (`29.7%` used, `351.40 MB` free) with `5,943` total `vector(1024)` rows across 2 tables (`public.documents`: `104` rows / `7.6 MB`; `public.upwork_evidence_passages`: `5,839` rows / `47 MB` = `54.6 MB` combined), while Tinybird already provides always-on serverless ClickHouse (`MergeTree`) for `observability_logs`, `agent_evaluations`, `linkedin_analytics`, and `onboarding_funnel`, and `w0m-cf` is at the `5/5` Cloudflare Free cron trigger ceiling (`AgDR-0043`).
