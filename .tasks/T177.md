# T177 — the retention fix never propagated to a consuming project, and that project is now worse than w0m ever was

## Summary

[[T174]] bounded `wom7web/STATE.md` — 339,508 B → 43,931 B, budgeted and gated at pre-push, with the
combined two-surface cost down 80.8%. **That fix stops at the estate boundary.** The `1945` project
adopted the full w0m pipeline (`.w0m/sdlc.json` present, 15 `w0m-*` skills installed) and carries,
measured read-only 2026-08-07:

| surface | bytes | note |
|---|---|---|
| `STATE.md` | **349,414** | larger than w0m's **peak** of 339,508 |
| `.w0m/BOARD.md` | **391,804** | 156 lines; longest line **28,270 chars** |
| `LESSONS.md` | 130,947 | |
| `SESSIONS.md` | 59,424 | |
| **total** | **931,589 B ≈ 233k tokens** | agent-maintained markdown |

**Nothing there can bound it.** `state_surface` is **not declared** in its `sdlc.json`; `retention`
is not declared; `state-check` / `state-save` / `state-rotate` are **absent from its justfile** (0
of 3); and `w0m-state-save` / `w0m-state-load` are **0 of 2 installed**. The cure is three commits
old and has no delivery mechanism.

🔑 **The general defect, which is the reason this is P1 and not housekeeping:** the estate has no
way to ship a fix to a project that consumes it. Skills sync (`just skills-sync`) propagates skill
*bodies*; nothing propagates the **config keys, justfile recipes and gates** those skills depend on.
So a consumer can hold a skill that names `just state-rotate` while having no such recipe — which is
exactly the *declared ≠ wired* class [[T149]] and [[T135]] AC4 gate **inside** the estate and nobody
gates **across** it.

## Acceptance criteria

- [ ] AC1 — **Measure every consuming project before changing one.** `1945` is the only one found,
      but "the only one I looked at" is not a denominator. Enumerate projects carrying a
      `.w0m/sdlc.json` outside this estate and record the list, with each one's surface sizes. A
      remediation whose scope was never counted is the vacuous-fix shape this estate keeps hitting.
- [ ] AC2 — **A consumer can adopt retention in one documented step**, and that step is *performed*
      against `1945`, not described ([[T110]] AC5's standard). It must carry: the `state_surface`
      + `retention` config block, the three recipes, and the two state skills.
- [ ] AC3 — **`1945`'s surfaces are bounded**, with the before/after recorded the way T174 recorded
      its own (bytes, lines, and the token cost of *every* surface — `STATE.md` **and** `BOARD.md`,
      since T174's lesson is that halving one surface while growing another is not a saving).
      ⚠️ Rotation must be **verbatim**, and here that matters more than it did in w0m: `BOARD.md`
      has 28,270-character lines and `LESSONS.md` is a client's incident record.
- [ ] AC4 — 🔴 **A gate that catches the NEXT one.** The specific 931 KB is a symptom; the defect is
      that a consumer can drift from the estate's own governance with nothing noticing. Add a check
      that a project declaring `.w0m/sdlc.json` has the config keys and recipes its installed skills
      actually reference — the cross-estate half of [[T149]]'s *declared ⇒ wired*.
- [ ] AC5 — **Proven red**, per [[T135]] AC7: a fixture consumer with a skill naming a recipe it
      does not have → exit 1 naming both. And **starts green** on the real consumer set once AC2/AC3
      land, or it is not installed (T135 AC8).
- [ ] AC6 — **`1945` is a CLIENT project — every change to it is the owner's call.** Record explicit
      authorisation before writing to that repo. This ticket's investigation was read-only by
      instruction and the remediation must not quietly become read-write.
