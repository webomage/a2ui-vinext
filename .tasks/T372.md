# T372 — Retire .claude/skills symlink shims across the estate

## Summary

When Claude Code introduced skill discovery (July 2026 / T127), it only scanned `.claude/skills/`. The w0m governance standard established `.agents/skills/` as the canonical location, so `skills.ts` generated compatibility symlinks (`.claude/skills/<name> -> ../../.agents/skills/<name>`).

In recent releases (Claude Code v2.1.275), Anthropic added native support for `.agents/skills/`. Because Claude Code does not deduplicate across `.agents/skills` and `.claude/skills`, every skill is indexed twice within each repo, and up to 5 times when Claude Code is opened at the `@wom` umbrella root (which also scans `wom7web` and `wom7skills`).

This ticket retires the legacy `.claude/skills/` symlink shims, updates `wom7skills/skills.ts` and test suites to treat `.agents/skills/` as the sole active skill directory, and removes the redundant symlink directories.
