# T158 — a missing mirror must be visible, not absent

## Summary

STATE.md's **TOP 10 HOT** and **TOP 10 SDLC** tables render each row through
`tasks_query._links()`, which already emits **both** surfaces:

```
[`T154`](project/tickets/T154.md) · [#151](https://github.com/casualuser/webomage.com/issues/151)
      ^ local ticket file                    ^ GitHub issue
```

The defect is the **failure path**. When a ticket has no GitHub issue, the link is silently
dropped and the row simply renders shorter — nothing says the ticket is unmirrored:

```python
gh = str(t.get("gh_issue") or "0")
slug = _repo_slug()
if gh.isdigit() and gh != "0" and slug:
    link += f" · [#{gh}](…/issues/{gh})"
# else: nothing. The row looks normal.
```

An absent link is indistinguishable from a link that was never expected. The table already knows
how to flag a missing surface loudly — `⚠️ **no TASKS.md row**` — and this is the same class of
fact about the same ticket, reported two different ways.

## Evidence — it was live for hours today

Measured 2026-08-01: **0 of 123** open tickets are currently unmirrored, so this is latent rather
than burning. But it was real earlier the same day: [[T156]] was filed with `gh_issue: 0`, ranked
**#2 in TOP 10 HOT at P0**, and rendered with only a local link until the pre-push mirror assigned
it `#153`. Nothing in the table indicated the P0 at position 2 had no issue behind it.

**Every newly-filed ticket passes through that window**, because the mirror only runs on pre-push.
The higher the ticket ranks, the more likely someone reads the row before the mirror catches up.

## The second, wider failure mode

`_repo_slug()` returns `""` on any `OSError`/`ValueError` reading `.w0m/sdlc.json`, and `_links()`
then drops the GitHub link from **every row in both tables at once** — silently. A malformed or
moved config would make the whole forge column vanish and still render two clean-looking tables.
That is the estate's recurring vacuity shape: absence of a signal presented as a normal result.

## Acceptance criteria

- [x] AC1 — a row whose ticket has no GitHub issue renders an explicit marker (e.g.
      `⚠️ not mirrored`) in place of the issue link, in **both** `markdown_hot` and `markdown_sdlc`
- [x] AC2 — when `_repo_slug()` is unavailable, the tables say so **once, visibly** (a note under
      the table), rather than every row quietly losing its second link
- [x] AC3 — the local ticket-file link is always present; a row can never render with neither
      surface
- [x] AC4 — unit tests in `project/scripts/tests/` cover all four combinations: issue+slug,
      issue-no-slug, no-issue+slug, neither. **Proven RED** by reverting the fix, per the estate's
      convention that a green suite is a hypothesis until a mutant has died
- [x] AC5 — `just state-save` regenerates STATE.md with the new rendering and `just state-check`
      passes
- [x] AC6 — the count of unmirrored open tickets appears in the mechanical block, so the condition
      is measurable rather than only visible row-by-row
