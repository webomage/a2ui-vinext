# T398 — Eliminate legacy npx invocations in favor of native pnpm exec and pnpm dlx

## Summary

Eliminate lingering legacy `npx` invocations across scripts, package.json files, skills tooling, and justfiles in favor of native `pnpm exec` (for installed binaries) and `pnpm dlx` (for on-demand remote package execution). This aligns with estate stack governance (`project/stacks-policy.json`, T130) and eliminates `npm warn Unknown project config "enable-pre-post-scripts"` / `"verify-deps-before-run"` warnings caused by npm parsing pnpm-specific `.npmrc` flags.

## Acceptance Criteria

- [x] AC1 — Update `apps/cp/package.json` and `apps/web/package.json` `build:search` scripts from `npx -y pagefind` to `pnpm dlx pagefind`.
- [x] AC2 — Update `wom7skills/w0m_skill.ts` delegation from `spawnSync("npx", ["--yes", "skills", ...])` and `spawnSync("npx", ["--yes", "tsx", ...])` to use `pnpm dlx` and `pnpm exec`.
- [x] AC3 — Update MCP helper scripts (`project/scripts/upwork_mcp_sync.py`, `probe_upwork_mcp.py`, `test_upwork_mcp.mjs`) from `npx -y mcp-remote` to `pnpm dlx mcp-remote`.
- [x] AC4 — Update legacy recipes in `wom7ext/justfile` and `wom7api/justfile` to use `pnpm exec` / `pnpm dlx` instead of raw `npx`.
- [x] AC5 — Author automated test suite or verification check ensuring zero active `npx` invocations remain in tracked runnable scripts and package manifests.
- [x] AC6 — Verify `just discovery --enforce` and estate test suites pass cleanly with zero npm warnings.

## Definition of Done

Per [`../../openspec/SPEC-AUTHORING-STANDARD.md`](../../openspec/SPEC-AUTHORING-STANDARD.md):
- All identified `npx` invocations replaced with native `pnpm dlx` or `pnpm exec`.
- Automated check confirms zero unauthorized `npx` invocations in tracked automation.
- All stack and skills test suites pass cleanly without npm config warnings.
- Changes committed referencing T398, with TASKS.md and GitHub issue #398 synchronized.
