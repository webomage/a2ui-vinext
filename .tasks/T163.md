# T163 — Make graph-first context and Headroom-routed delegation the default task workflow

## Summary

Owner ask 2026-08-04: *"I want to make the P0 task to process all tasks via Headroom proxied
wrapper and also use our knowledge graphs and indexes — that should be first default way to do
tasks."*

Two halves, and they are **not** equally supported by evidence — which is the point of writing
them into one ticket rather than assuming both are wins.

**Half 1 — graph-first. Strongly supported.** `headroom audit-reads` over **317 real sessions**
measured where agent context actually goes: **Bash 57.7%** of `tool_result` bytes, **Read 34.2%**
(13.0 MB / ~3,261K tok). Inside Read, the single biggest class is **"stale (edit after read)" —
1,139 calls / 6.1 MB / ~1,524K tok = 46.7% of all Read bytes**. That is an agent re-reading a file
it already edited. No compression layer can touch it; it is a *workflow* defect, and consulting an
index instead of re-reading source is exactly the fix.

**Half 2 — Headroom-routed delegation. Weakly supported, adopted by owner decision.** Recorded
honestly here so this ticket is not built on a flattering premise (see [[T162]] for the full
measurement): Headroom **compression is 0 tokens over every request ever made**; its headline
savings figure is **Anthropic's prompt-cache discount re-badged**; measured overhead is **+341 ms
average per request** and **+57% wall clock** in the A/B. The one real saving is **tool-schema
deferral at ~11k tok/request marginal** on top of Claude Code's native `ENABLE_TOOL_SEARCH`, which
is free and already on. Routing also puts a **Pro subscription OAuth token through a third-party
local binary**. The owner has chosen this direction knowing all of it; this ticket's job is to
implement it well, not to relitigate it.

## 🔴 Scope constraint — measured, non-negotiable

**"All tasks via Headroom" is not achievable for in-app work, and no AC here pretends otherwise.**
The desktop app spawns its Claude Code engine with a pinned
`ANTHROPIC_BASE_URL=https://api.anthropic.com`, overriding both `settings.json` and the shell
export. **In-app subagents inherit that bypass: a subagent that burned 48,499 tokens moved the
proxy request counter by ZERO.** Only a **subprocess** (`claude -p`, i.e. `just headroom-task`) is
a fresh process that can take the proxy URL.

⇒ **Routable = delegated/subprocess tasks only. Interactive in-app work gets Half 1 only.**
Writing an AC for "every task routes" would be an AC that can never go green — the exact vacuous
gate this estate keeps producing.

## 🔴 Blocking finding from the research pass — the graphs are STALE right now

`just graph-health --strict` **exits 1 today**, and the union is stale for **all 7 in-union repos**:

```
wom7web  STALE(merged@91b596a now@d6237ce)   wom7api  STALE(merged@2dd88c5 now@87955c8)
wom7cfworkers STALE(...)  wom7skills STALE(...)  wom7ext STALE(...)  wom7sec STALE(...)  wom7mlx STALE(...)
```

**Root cause is structural:** the git hooks refresh a repo's **own** graph on `post-commit` but
**never re-merge the union** — that only happens on a manual `just graph-global`. So the united
graph drifts behind every commit, including the ones made while filing this ticket.

⚠️ **This inverts the ticket's own premise if left unfixed.** Mandating "graph before grep" against
a stale index makes the default path *confidently wrong* — worse than grep, which at least reads
current bytes. **AC2 is therefore a hard prerequisite for AC1**, not a nice-to-have.

Also noted: `wom7md` is excluded from the union by design (markdown vault, 0 code files) and
`graphify-out/` at the estate root is **empty**.

## Acceptance criteria

- [x] AC1 ✅ **Graph-first is the executed default, not just documented.** `just ask` (codegraph +
      graphify) is the first context step for any task that asks *where/what/who-calls*. The three
      SDLC gates that already mention it (`w0m-sdlc-research`, `-start`, `-build`) state it as the
      **default first action** with an explicit "grep/Read only after the graph misses" rule.
      **DONE 2026-08-04 — index fixed AND the gates rewired.** `w0m-sdlc-start`, `-research` and
      `-build` now state `just ask` as the FIRST action with grep as the stated fallback, and
      `CLAUDE.md` carries the same rule as a non-negotiable. Both findings below are written into
      all four surfaces so neither can be rediscovered.
      🔴 **The index was 56.9% vendored junk.** First real `just ask` under this ticket answered
      *"what does graph_fresh do"* with **Obsidian plugin internals**. Cause: `.obsidian/` and
      `.smart-env/` were untracked **but not gitignored**, and codegraph follows `.gitignore` — so
      **10 files out of 848 produced 11,940 of 20,977 nodes**. graphify had already excluded
      `.obsidian` for exactly this (26% of the union); codegraph never did. Ignoring them
      (`.gitignore`) + reindex (5s) → **9,038 nodes, 100% real source**, and the same query then
      resolved `STALE_COMMITS_FAIL` at `graph_fresh.py:45` with `probe → HEALTH`, `main → GLOBAL`.
      ⚠️ **Second finding, still open: prose questions match loose tokens.** *"what does graph_fresh
      do and what calls it"* matched `callLlm`/`callGuild`/`call_llm` off the word **"calls"**, even
      on the clean index. Naming symbols (`graph_fresh probe STALE_COMMITS_FAIL`) resolved exactly.
      **Graph-first therefore needs query discipline written into the gates — name symbols, don't
      ask prose** — or the default hands back confident noise.
- [x] AC2 ✅ **DONE 2026-08-04 — `project/scripts/graph_fresh.py`, gating `just ask`.** Checks
      (~1.4s), auto-re-merges only when stale (~13s), then **re-checks and fails if still behind**
      rather than trusting the merge's exit code. Bypass requires typing `W0M_SKIP_GRAPH_FRESH=1`,
      so the safe path is the default.
      🔴 **The first cut of this script was itself a vacuous green, caught within minutes.** It
      checked only `union_matches` — but that field compares the union to the graph's **built_at**
      commit, *not* to HEAD. So `union_matches: True` coexisted with **`wom7api` +13 commits behind
      HEAD**: the union faithfully carried a graph that was itself out of date, and the script
      called it "current". **There are two independent staleness axes and only checking one is the
      defect:**
      · `union_behind` — union lacks the repo's current graph. Fix `graph-global`, **~13s** → auto-fixed.
      · `graph_behind` — the repo's own graph predates HEAD by N commits. Fix = re-extract,
        **minutes** → reported and refused past `STALE_COMMITS_FAIL = 10`, never silently run
        inside someone's question.
      ⚠️ The fail threshold is **10**, deliberately tighter than `graph_health`'s
      `STALE_COMMITS_WARN = 25`: that governs a dashboard a human skims, this governs whether an
      agent may answer *from the index instead of the file*.
      **Proven both directions, live:** RED → `wom7web` union behind + `wom7api` +13 → rc=1 naming
      both remedies; targeted `graph-global --only wom7api --rebuild` (15s) cleared +13 → 0; GREEN →
      rc=0 with `wom7sec +1`/`wom7mlx +1` still *warned* but under the limit — graduated, not binary.
- [x] AC3 ✅ **DONE 2026-08-04 — `just headroom-task` is the documented default for delegated work**, replacing
      "spawn a subagent" wherever the gates and `CLAUDE.md` describe delegation. The reason is
      recorded inline (subagents structurally cannot route — measured, a 48,499-token subagent moved
      the proxy counter by zero), so a future reader does not "simplify" it back to the Agent tool.
      Written into `CLAUDE.md`'s non-negotiables, where delegation decisions are actually made.
- [x] AC4 ✅ **DONE 2026-08-04 — the routing claim stays honest.** Any surface asserting a task was Headroom-routed
      must show *observed* evidence, never configuration. `just headroom-task` already prints the
      proxy counter before → after and warns when it did not route ([[T162]] AC10), and the
      `CLAUDE.md` entry states that behaviour rather than asserting "tasks are routed". No surface
      added under this ticket claims routing from configuration — the defect that produced
      [[T162]] AC9, where `routing ✅` was printed while the proxy had served zero of this
      session's requests.
- [x] AC5 ✅ **DONE 2026-08-05 — measured, and the result is ADVERSE. Recorded as measured.**
      Re-ran `just headroom-audit` (read-only, no API cost). **326 sessions** (baseline: 317, so
      **9 sessions** under the new workflow).

      | metric | 2026-08-04 | 2026-08-05 | delta |
      |---|---|---|---|
      | Read % of all tool bytes | 34.2% | **33.5%** | **−0.7 pp** |
      | stale (edit after read) calls | 1,139 | **1,207** | **+68** |
      | **stale % of Read bytes** | **46.7%** | **47.4%** | 🔴 **+0.7 pp** |
      | stale tokens | ~1,524K | **~1,593K** | **+69K** |

      **AC5 is satisfied on its own terms** — it closes on *"a measured movement in the stale-read
      share, in either direction, with the number written down"*. The movement is **+0.7 pp**, and
      it is written down. **The intervention did not reduce stale reads.** Recording that plainly
      is the point of an AC worded this way; a version that closed only on improvement would have
      been unfalsifiable.

      🔴 **The marginal rate is the sharp number, and it is worse than the headline.** Of the
      **~97K** Read tokens added since the baseline, **~69K were stale** — a **~71% marginal rate**
      against a **46.7% cumulative average**. Sensitivity band from 1-dp rounding in the source
      percentages: **66–76%**, so the direction is robust even though the point estimate is not
      precise. The 9 sessions since the workflow landed were **materially worse** than the running
      average on the exact metric the change targets.

      ⚠️ **Three caveats, all of which weaken this as evidence and none of which rescue it:**
      1. **n = 9 sessions**, against a 326-session cumulative aggregate. The audit reports a
         *lifetime* figure, not a post-change window, so this is inference from a delta, not a
         cohort comparison. A per-window mode would measure it directly and does not exist.
      2. **This session is a large share of that delta** and was Read/Edit-heavy (tickets, the CV,
         `bake_pdfs.py`). Self-implicating, and stated rather than omitted.
      3. 🔴 **The metric may be measuring relabeling, not reduction.** Read fell **−0.7 pp** while
         **Bash rose +0.9 pp** (57.5% → 58.4%) — near-symmetric. `headroom audit-reads` audits
         **"Read-tool traffic"** only (its own `--help`), so a file read via `sed`/`grep`/`cat`
         inside Bash is **invisible to it** — the bytes move out of the audited surface without the
         waste going anywhere. **The gate cannot see the thing it exists to measure once the work
         routes around it.** This estate's signature defect, in the measurement layer this time.

      ⇒ **Do not read this as "graph-first failed."** It is one thin, confounded window on a
      Read-only metric that a workload can escape by using Bash. What it does establish is that
      **the claimed benefit is not yet visible**, and per AC6 that is what gets stated.

- [x] AC6 ✅ **DONE 2026-08-04 — cost side reported with the benefit.** Whatever this saves is stated next to what it
      costs. `CLAUDE.md` states both in the same breath: **~11k tok/request** of tool-schema
      deferral *marginal* over native free tool search, against **~341 ms/request**, **+57% wall
      clock**, and a Pro-subscription OAuth token traversing a third-party binary — plus the fact
      that compression has removed **0 tokens, ever**, and that Headroom's headline savings figure
      is Anthropic's prompt-cache discount re-badged and must never be quoted. The default is
