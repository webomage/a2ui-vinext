# T241 — `--scope-diff` reaches one check and not the one three lines below it

## Summary

Hit live on 2026-08-20 while pushing an unrelated ticket fix ([[T239]] AC7). The push was blocked
**twice, ~20 minutes apart**, by a defect in a **different agent's untracked, half-written OpenSpec
change** — a directory that was **not part of the push at all**. The error named a change the pusher
had never touched.

### 🔴 The hook advertises the scope. The code applies it to one check only.

`.husky/pre-push:47-53` says, in its own words, *"w0m audit (**scoped drift + openspec**)"*, and
passes the scope:

```sh
python3 project/scripts/w0m_audit.py --quick --no-report --scope-diff origin/beta
```

Inside `check_drift(scope_diff=…)` that argument reaches the **first** check and is then dropped:

```python
if scope_diff:
    sd_cmd += ["--scope-diff", scope_diff]     # ✅ spec-drift IS scoped
...
ov = subprocess.run(["openspec", "validate", "--all", "--strict"], …)   # 🔴 --all, unconditionally
```

⇒ **The scoping mechanism already exists in the same function, three lines above the call that
needs it.** This is not a missing capability; it is a capability not wired to its second consumer —
and the hook's comment asserts otherwise, so reading the hook tells you the opposite of what runs.

**What the unscoped call actually judges:** `--all` validates **24 changes + 43 specs = 67 items**
on every push, and `openspec` reads the tree from **disk**, so **untracked** directories are in
scope. It also accepts a bare `[item-name]`, so per-change validation is a CLI argument away
(`openspec validate <change> --strict` is what diagnosed this).

### Why it matters more here than it would elsewhere

This estate **deliberately runs parallel agents** ([[T235]] added a hook to refuse committing
another agent's in-flight work, so the concurrency is a designed condition, not an accident). Under
that design, an unscoped disk-wide validation means **any agent mid-authoring halts every other
agent's push indefinitely**, with an error naming work the blocked agent cannot fix without taking
ownership of someone else's file. On 2026-08-20 that is exactly what happened, and it was resolved
only by the owner transferring ownership of the change.

⚠️ **`mmd-validate` is NOT an instance and must not be swept in.** It failed in the same session,
but `.pre-commit-config.yaml:154` scopes it with `files: \.(mmd|md|mdx)$` and its comment says
*"Runs on staged files only"* — it fired because the `.mmd` **was staged**, which is correct. Naming
it here would be the over-match this ticket is about.

## Acceptance criteria

- [ ] AC1 — **The openspec check honours the scope the hook already passes.** Validate the changes
      reachable from the push (the same `--scope-diff` basis `spec-drift` uses), or at minimum only
      **tracked** ones. ⚠️ Fix the WIRING, not the CLI call: `--all` is correct for a full sweep, so
      the answer is to pass a scope, never to weaken strictness.
- [ ] AC2 — 🔴 **The hook's comment and its behaviour agree, in whichever direction is chosen.** It
      currently claims *"scoped drift + openspec"* while openspec is unscoped. A comment asserting a
      guarantee the code does not implement is the defect shape this estate keeps paying for
      ([[T228]], [[T240]]) — and here it would have told a reader the blocker was impossible.
- [ ] AC3 — **What was SKIPPED is printed, never silently narrowed.** A scoped gate that says
      nothing about its scope is how coverage is lost: today's output *"67 items"* at least tells you
      it looked everywhere. State the count validated **and** the count skipped, per the estate's
      no-silent-caps rule.
- [ ] AC4 — **The unscoped sweep still exists somewhere deliberate.** `just audit` must keep
      validating everything, so scoping the *hook* narrows a push gate without reducing total
      coverage. Name where the full check runs.
- [ ] AC5 — 🔴 **A red probe: an invalid change OUTSIDE the push does not block the push, and an
      invalid change INSIDE it still does.** Both directions, because a scope that blocks nothing is
      worse than the over-broad gate it replaced. Today's corpus produced a real block from an
      untracked directory, so the fixture is a measured case rather than an invented one.
- [ ] AC6 — **Audit the other pre-push checks for the same shape.** `--scope-diff` exists for
      `check_drift`; verify no other check in the quick tier judges the whole tree while the hook
      implies otherwise. ⚠️ Report the ones that are correctly whole-tree (some should be) rather
      than scoping everything reflexively.
