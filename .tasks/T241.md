# T241 — `--scope-diff` reaches one check and not the one three lines below it

## Summary

Hit live on 2026-08-20 while pushing an unrelated ticket fix ([[T239]] AC7). The push was blocked
**twice, ~20 minutes apart**, by a defect in a **different agent's untracked, half-written OpenSpec
change** — a directory that was **not part of the push at all**. The error named a change the pusher
had never touched.

### 🔴 The hook advertises the scope. The code applies it to one check only.

`.husky/pre-push:47-53` says, in its own words, *"w0m audit (**scoped drift + openspec**)"*, and
passes the scope:

```sh
python3 project/scripts/w0m_audit.py --quick --no-report --scope-diff origin/beta
```

Inside `check_drift(scope_diff=…)` that argument reaches the **first** check and is then dropped:

```python
if scope_diff:
    sd_cmd += ["--scope-diff", scope_diff]     # ✅ spec-drift IS scoped
...
ov = subprocess.run(["openspec", "validate", "--all", "--strict"], …)   # 🔴 --all, unconditionally
```

⇒ **The scoping mechanism already exists in the same function, three lines above the call that
needs it.** This is not a missing capability; it is a capability not wired to its second consumer —
and the hook's comment asserts otherwise, so reading the hook tells you the opposite of what runs.

**What the unscoped call actually judges:** `--all` validates **24 changes + 43 specs = 67 items**
on every push, and `openspec` reads the tree from **disk**, so **untracked** directories are in
scope. It also accepts a bare `[item-name]`, so per-change validation is a CLI argument away
(`openspec validate <change> --strict` is what diagnosed this).

### Why it matters more here than it would elsewhere

This estate **deliberately runs parallel agents** ([[T235]] added a hook to refuse committing
another agent's in-flight work, so the concurrency is a designed condition, not an accident). Under
that design, an unscoped disk-wide validation means **any agent mid-authoring halts every other
agent's push indefinitely**, with an error naming work the blocked agent cannot fix without taking
ownership of someone else's file. On 2026-08-20 that is exactly what happened, and it was resolved
only by the owner transferring ownership of the change.

⚠️ **`mmd-validate` is NOT an instance and must not be swept in.** It failed in the same session,
but `.pre-commit-config.yaml:154` scopes it with `files: \.(mmd|md|mdx)$` and its comment says
*"Runs on staged files only"* — it fired because the `.mmd` **was staged**, which is correct. Naming
it here would be the over-match this ticket is about.

## Acceptance criteria

- [x] AC1 — **The openspec check honours the scope the hook already passes.** Validate the changes
      reachable from the push (the same `--scope-diff` basis `spec-drift` uses), or at minimum only
      **tracked** ones. ⚠️ Fix the WIRING, not the CLI call: `--all` is correct for a full sweep, so
      the answer is to pass a scope, never to weaken strictness.
      - *Evidence:* `_openspec_scope_plan(scope_diff)` and `check_drift(scope_diff=...)` in `scripts/w0m_audit.py` compute tracked `openspec/changes/<id>` (excluding `archive/`) and `openspec/specs/<id>` via `git ls-files`, intersect them with paths touched in `git diff --name-only <scope_diff>...HEAD`, `git diff --name-only <scope_diff> HEAD`, `--cached`, and `spec:` links from `.tasks/T*.md` touched in `MONO_ROOT`, and run `openspec validate <id> --strict` only on touched tracked items while ignoring untracked directories.
- [x] AC2 — 🔴 **The hook's comment and its behaviour agree, in whichever direction is chosen.** It
      currently claims *"scoped drift + openspec"* while openspec is unscoped. A comment asserting a
      guarantee the code does not implement is the defect shape this estate keeps paying for
      ([[T228]], [[T240]]) — and here it would have told a reader the blocker was impossible.
      - *Evidence:* `wom7web/.husky/pre-push` (`step_begin "w0m-audit" "w0m audit (scoped drift + openspec) — T96/T23"`) invokes `python3 ../scripts/w0m_audit.py --quick --no-report --scope-diff origin/beta`, and `scripts/w0m_audit.py` `--scope-diff` CLI help (`scope spec-drift and openspec validate to changes vs REF`) and `check_drift()` wire `scope_diff` to both `spec_drift_gate.py` and `openspec validate`.
- [x] AC3 — **What was SKIPPED is printed, never silently narrowed.** A scoped gate that says
      nothing about its scope is how coverage is lost: today's output *"67 items"* at least tells you
      it looked everywhere. State the count validated **and** the count skipped, per the estate's
      no-silent-caps rule.
      - *Evidence:* In scoped mode, `scripts/w0m_audit.py` always emits `validated K touched item(s), skipped M untouched item(s) (scope: <scope_diff>); N untracked ignored` (measured live at `HEAD`: `validated 0 touched item(s), skipped 160 untouched item(s) (scope: origin/beta); 0 untracked ignored`).
- [x] AC4 — **The unscoped sweep still exists somewhere deliberate.** `just audit` must keep
      validating everything, so scoping the *hook* narrows a push gate without reducing total
      coverage. Name where the full check runs.
      - *Evidence:* `just audit` (`python3 scripts/w0m_audit.py` without `--scope-diff`) executes `openspec validate --all --strict` across all 160 items (11 active changes + 149 specs) plus any untracked OpenSpec directories on disk, reporting `all valid (Totals: 160 passed, 0 failed (160 items))`.
- [x] AC5 — 🔴 **A red probe: an invalid change OUTSIDE the push does not block the push, and an
      invalid change INSIDE it still does.** Both directions, because a scope that blocks nothing is
      worse than the over-broad gate it replaced. Today's corpus produced a real block from an
      untracked directory, so the fixture is a measured case rather than an invented one.
      - *Evidence:* `wom7web/project/scripts/tests/test_t241_scoped_openspec.py` (6 tests) proves: (1) an untracked invalid OpenSpec directory outside the push diff passes `check_drift(scope_diff="base-ref")` with `1 untracked ignored` while failing unscoped `check_drift(scope_diff=None)`; (2) an untouched tracked invalid OpenSpec change committed before `base-ref` is skipped in scoped mode; (3) a tracked invalid OpenSpec change or spec touched inside `base-ref...HEAD` fails `check_drift(scope_diff="base-ref")`; (4) a valid change touched directly or via its owning `.tasks/T*.md` ticket is validated and passes.
- [x] AC6 — **Audit the other pre-push checks for the same shape.** `--scope-diff` exists for
      `check_drift`; verify no other check in the quick tier judges the whole tree while the hook
      implies otherwise. ⚠️ Report the ones that are correctly whole-tree (some should be) rather
      than scoping everything reflexively.
      - *Evidence:* Complete audit of `scripts/w0m_audit.py --quick` and `wom7web/.husky/pre-push` recorded below.

## Definition of Done

- `scripts/w0m_audit.py` (`check_drift` and `_openspec_scope_plan`) wires `--scope-diff <ref>` to OpenSpec validation so only tracked `openspec/changes/<id>` and `openspec/specs/<id>` items touched in `<ref>...HEAD` / `<ref> HEAD` / staged index or linked from touched `.tasks/T*.md` tickets are validated during pre-push, never untracked directories.
- Scoped OpenSpec validation prints the exact counts validated, untouched tracked items skipped, and untracked directories ignored (`validated K touched item(s), skipped M untouched item(s) (scope: <ref>); N untracked ignored`), while unscoped `just audit` continues running `openspec validate --all --strict`.
- `wom7web/project/scripts/tests/test_t241_scoped_openspec.py` passes all 6 red/green probes covering untracked invalid changes, untouched tracked invalid changes, in-push invalid changes, in-push invalid specs, ticket-linked valid changes, and hook/script agreement.
- All other checks in `scripts/w0m_audit.py --quick` and `wom7web/.husky/pre-push` are audited and documented in the AC6 scope table.
