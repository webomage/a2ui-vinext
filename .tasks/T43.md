## Summary

**Full-observability logging strategy** — one structured JSON log shape across all surfaces (apps SSR web/cp/join/job, wom7api edge fns, wom7cfworkers) via `@wom/logger`; **cross-surface trace correlation** (`x-wom-trace-id`, reuses OTel trace id) so one request = one trace app→edge-fn→worker; **central queryable sink** (CF Logpush + Supabase log drain → Tinybird) with retention; **secret/PII redaction** in the logger (the logging analogue of the gitleaks guard); error-rate/`/health` **alerting**; **CP Observability dashboard** (trace lookup + per-service error rate, extends System→Services). Complements OTel (doesn't replace). Spec: OpenSpec `2026-07-15-observability-logging`.

## Acceptance criteria

- [x] AC1 — `@wom/logger` secret & PII redaction: `@wom/logger` implements an automated redaction pass that strips/masks known sensitive keys (`token`, `password`, `secret`, `authorization`, `cookie`), connection strings (`postgres://`, `redis://`), and hashes email addresses before emit, with unit tests proving secret/PII values are never emitted in logs.
- [x] AC2 — `@wom/logger` base fields & async trace context: `@wom/logger` automatically attaches base fields (`service`, `env`, `deploy_version`) and supports trace propagation via `withTrace(traceId, fn)` (using `AsyncLocalStorage`) and helpers to read/write `x-wom-trace-id`, reusing active OpenTelemetry span/trace context when present.
- [x] AC3 — Ingress and egress trace correlation in app middleware: App ingress middleware (`apps/web`, `apps/cp`, `apps/join`, `apps/job`) mints or propagates `x-wom-trace-id`, sets it in request context/locals, adds it to outbound fetch calls to backend services, and echoes `x-wom-trace-id` in response headers.
- [x] AC4 — Edge functions and Cloudflare Workers structured logging: Edge functions (`wom7api/supabase/functions`) and Cloudflare Workers (`wom7cfworkers`) adopt structured `@wom/logger` logging and extract/propagate `x-wom-trace-id`, replacing raw `console.*` calls containing unredacted PII/secrets.
- [x] AC5 — Central queryable sink in Tinybird with retention: Central log sink configured (Cloudflare Logpush + Supabase log drain to Tinybird `observability_logs`), queryable by `traceId`, `service`, `userId`, `level`, and timestamp, with documented retention window.
- [x] AC6 — Error-rate spike & `/health` alerting: Automated monitoring triggers alert notifications (via Telegram/webhook) when service error rates exceed configured thresholds or `/health` checks fail.
- [x] AC7 — CP Observability dashboard: Control Panel (`apps/cp/src/pages/admin/services.astro`, canonical target of `/system/services` per T439 C1) provides an admin-gated observability view displaying service `/health`, deploy version, error rates, and end-to-end log trace lookup by `traceId`.

## Definition of Done

T43 is done when: a single request traced app→edge-fn→worker resolves to one
`x-wom-trace-id` queryable end-to-end in the Tinybird `observability_logs` sink; a
`@wom/logger` unit test proves a token/password/secret/connection-string/email value
submitted to it never reaches the emitted line; `console.*` calls carrying unredacted
PII are gone from `wom7api/supabase/functions` and `wom7cfworkers`; an error-rate spike
or failed `/health` fires a Telegram/webhook alert without a human polling a dashboard;
and `apps/cp/src/pages/admin/services.astro` (moved from `apps/cp/src/pages/system/services.astro`
in T439 C1 with a live 301 redirect) renders that trace lookup + per-service error rate live.
