## Summary

**F4 — Origin check on state-changing auth POSTs** — add Origin/Referer allowlist on `switch-role`/`impersonate` as defense-in-depth beyond `SameSite=Lax` (from F1 Phase-6 review; overlaps T78 G6).

## Acceptance criteria


- [ ] AC1 — `switch-role` and `impersonate` both reject a state-changing POST whose `Origin` (or
      `Referer` when Origin is absent) is not on the allowlist.
- [ ] AC2 — **Proven RED and GREEN against the live endpoints**, not reasoned about: a request with
      a foreign Origin is refused, and a legitimate same-origin request still succeeds. A check
      that has only ever been seen passing proves nothing.
- [ ] AC3 — ⚠️ **The cross-domain SSO handoff still works.** These apps span registrable domains and
      hand sessions between them; an Origin allowlist is exactly the control that breaks that flow.
      The admin→client cross-registrable-domain path is re-verified after the change.
- [ ] AC4 — The allowlist is configuration, not a hardcoded literal, so adding a domain does not
      require a code change — and absent/empty config **fails closed**, never open.
- [ ] AC5 — Recorded as defense-in-depth ON TOP of `SameSite=Lax`, not as a replacement: the ticket
      states what it does and does not add, so nobody later removes the cookie attribute believing
      this covers it. Overlap with T78 G6 reconciled rather than duplicated.
