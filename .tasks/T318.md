# T318 — Transition Upwork integration to MCP flows, Member profile service connections & CP Business Contracts/Proposals dual-view

## Summary

Owner ask 2026-09-05:
1. *"investigate and review current state of syncing from Upwork — in user/admin CP I can see that it display nothing and it looks like still working on auth session extracted from response page or something like that"*
2. *"we have to move from Upwork Api Key to Upwork MCP flows"*
3. *"I want to be able to connect in Member/Unit profile to Upwork via mcp and also map/connect GH and some other services"*
4. *"the current Proposals and Contracts for casualuser@gmail.com should be visible in CP independent or stacked under global abstract contracts (direct, upwork, internal, etc) in Business part"*

### Grounding & Root Causes (verified against live code & DB)

- **Why CP Shows 0 Contracts (`apps/cp/src/pages/business/contracts/index.astro`):**
  Imports `supabase` from `@webomage/lib/supabase` (unauthenticated `anon` singleton). Under PostgreSQL RLS policy `contracts_admin_hat` (`wom_acting_is('admin')`), unauthenticated requests return **0 rows**.
  Postgres actually holds **98 real contracts** (`95 upwork`, `3 direct`).
- **Why CP Shows 0 Proposals (`apps/cp/src/pages/business/proposals/index.astro`):**
  Line 9 executes `.order('created_at', { ascending: false })`. The `proposals` table has **no `created_at` column** (it has `updated_at`, while attributes are in `data` JSONB). PostgREST queries fail with `column "created_at" does not exist`, throwing 500 / empty result.
  Postgres actually holds **539 real proposals** (`source: upwork`).
- **Why Sync Buttons Fail:**
  - `ContractManager.svelte` calls edge function `upwork-poller`, which requires `WORKERS_WEBHOOK_SECRET` or `SUPABASE_SERVICE_ROLE_KEY`. Calling from the browser client fails with **401 Unauthorized**.
  - `ProposalManager.svelte` calls `trigger-hatchet-workflow` with `{ workflowId: "upwork-poller" }` — a workflow **retired 2026-07-20** (debt [[D9]]).
  - `ProposalManager.svelte` contains a legacy popup OAuth flow (`UPWORK_AUTH_URL`) that intercepted callback URLs and wrote to a single hardcoded `freelancer` row in `upwork_auth_tokens`.
- **Upwork MCP Status:**
  The official Upwork MCP server (`https://mcp.upwork.com/mcp`) is authenticated and live with 48 tools. Probe calls to `upwork__list_accounts`, `upwork__list_contracts`, and `upwork__list_freelancer_proposals` succeed cleanly. Furthermore, an MCP sync script already exists at `project/scripts/upwork_mcp_sync.py`.

This ticket pivots the integration from legacy API keys/popups to Upwork MCP flows, adds the Member/Unit Profile connected services interface, fixes CP SSR data fetching, and delivers the dual-mode viewing (Stacked by Channel vs Unified Stream) for contracts and proposals.
