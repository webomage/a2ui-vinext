# T469 — Auth widget suppression during MFA challenge

## Summary

Owner report & screenshot (2026-09-27):
> "and here I think we shouldn't display anything at the auth widget until totp passed"
> Screenshot on `cp.webomage.com/mfa/challenge?next=%2Fme`: The user clicked the top-right avatar menu during the AAL2 two-factor challenge, revealing the full dropdown with email ("Signed in as w0m@webomage.com"), "Your Apps" (Manager CP, Interviews, Job Board), "Switch Hat" (Admin, Manager, Member, Client, Recruit), and agent links.

This leaks internal application routes and role-switching capabilities to an unverified AAL1 session before the required second factor (TOTP) has been verified. The MFA challenge page already provides self-contained navigation (`← Return to Account & security` and `Sign Out`).

## Acceptance criteria

- [x] AC1 — **HeaderActions & Header Route Guard**: When on `/mfa/challenge` (or any `startsWith("/mfa/challenge")` route), `HeaderActions.astro` suppresses the `AuthWidget` completely, ensuring no avatar, identity dropdown, app links, or hat switcher are rendered.
- [x] AC2 — **Client-Side Svelte Guard**: In `AuthWidget.svelte`, fail-closed when `window.location.pathname.startsWith("/mfa/challenge")` or when the user session is at unverified AAL1, rendering nothing.
- [x] AC3 — **Sign Out Access**: Verify that a user stuck on the challenge screen retains the ability to cleanly sign out via the challenge card's existing `Sign Out` button without needing the header widget.
- [x] AC4 — **Automated Component & Page Tests**: Add test assertions in `packages/ui` and `apps/cp` verifying that the auth widget is not rendered on `/mfa/challenge` and renders normally once elevated to AAL2.

## Definition of Done

- OpenSpec spec authored in `wom7web/openspec/changes/2026-09-27-mfa-challenge-auth-widget-suppression` and validated.
- Component tests pass.
- Verified on `/mfa/challenge`.
