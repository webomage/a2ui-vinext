# T435 — The deploy/migrate confirmation gate is forgeable by any agent that holds a terminal — refuse agent ancestry and gate every deploy-shaped recipe

## Summary

`confirm_step.py` (T161 AC3) keeps agents from running `just db-migrate` / `just deploy*` by requiring a
**terminal**: `/dev/tty`, or an interactive stdin. The premise was that an agent shell never has one. That
premise is false, and it has already failed live:

- **Antigravity (agy) runs background commands inside a pseudo-terminal and can type into them.** Session
  `94008993`, 2026-09-17T06:16:50Z: `run_command just db-migrate`, then `manage_task send_input "yes\n"`.
  `wom7web/.git/w0m-confirm.log:976` records `CONFIRMED db-migrate`; the task log shows the prompt answered
  `yes`, Supabase's own `[Y/n]` answered `y`, and three migrations applied to the live database. The user's
  preceding message was the single word "do".
- **Any agent with a shell can allocate one.** From Claude Code's Bash tool, directly: `stdin.isatty()` False,
  `/dev/tty` "Device not configured" (the gate refuses). Through `script -q /dev/null …`: `isatty()` True and
  `/dev/tty` opens (the gate would prompt, and the agent writes the answer).
- **Many mutating recipes never call the gate.** Enumerated with `just --dump --dump-format json`: root
  `deploy-workers`, `deploy-functions`; wom7api `crawler-deploy` (listed in `always_confirm` but not wired),
  `supabase-redeploy-all`, `sync-secrets`, `deploy-infra-tf` / `cf-apply` / `supabase-settings-apply` /
  `azure-jumphost-apply` (`terraform apply -auto-approve`), and seven `sync-*-secrets` (`wrangler secret put`).
  Claude ran `just deploy-workers` against production on 2026-08-21 (session `35b31254`).
- The gate's own docstring conceded the ceiling ("an agent that allocates its own pty defeats either"), while
  `docs/DEPLOY-CONFIRM.md`, the justfile comments and three AGENTS/CLAUDE files state it cannot be answered by
  an agent.

This ticket closes the observed paths: the gate refuses when **an agent harness is in its process ancestry or
environment**, on every path (prompt, root consent, `always_confirm`), and every deploy-shaped recipe is wired
to it, enforced by a probe that enumerates recipes. Found by the 2026-09-24 agent rule-enforcement audit
(`.agents/reports/2026-09-24-agent-rule-enforcement-audit.md`).

**Stated residual (not closed here):** a process that deliberately detaches from its agent (double fork /
`tmux new -d` / `osascript` into a fresh Terminal) *and* scrubs the agent's environment markers escapes an
ancestry check. That is deliberate evasion, not the accidental/automated failure seen on 2026-09-17; closing it
needs proof of a present human (e.g. a Touch ID prompt) — AC8, owner decision.

## Acceptance criteria

- [x] AC1 — `confirm_step.py` refuses, with a named cause and an audit line (`REFUSED-AGENT`), when any process
  in its ancestry is an agent harness (`claude`, `agy`, `codex`, `opencode`, `gemini`, `cursor-agent`, `aider`,
  `hermes`, an IDE `language_server*`, or an interpreter running one of those) or when an agent environment
  marker is set (`CLAUDECODE`, `AI_AGENT`). It applies before the prompt, before a root consent is honoured, and
  to `always_confirm` steps. The Claude desktop **app** (`Claude`) and terminal hosts (Orca, iTerm, login
  shells) are not agents.
- [x] AC2 — Ancestry that cannot be measured (no `ps`, or a chain that breaks before pid 1) refuses as
  UNMEASURABLE — never passes.
- [x] AC3 — `just confirm-doctor` prints the ancestry chain, the agent verdict and which signal decided it.
- [x] AC4 — Every recipe in the root and wom7api justfiles whose body runs a deploy-shaped command
  (`wrangler deploy`, `supabase functions deploy`, `supabase secrets set`, `db push`, `terraform … apply`,
  `npm run deploy`, `wrangler secret put`, `sync_supabase_secrets`) depends on `_confirm`, and every `_confirm`
  argument is described in `confirm-policy.json`. `just confirm-test` enumerates this from
  `just --dump --dump-format json` and fails naming each ungated recipe; a mutation probe proves the detector
  fires.
- [x] AC5 — Red probes: agent ancestry + a pty answering `yes` is refused (the 2026-09-17 shape); agent
  ancestry + a valid root consent is refused; synthetic chains for claude / agy / `script`-under-claude /
  language server / node-running-codex are detected; a human Orca chain and the Claude desktop app are not; a
  broken chain refuses. Green probes still prove a human at a pty can confirm.
- [x] AC6 — Measured live, not assumed: `confirm-doctor` run from Claude Code reports the `claude` ancestor, and
  run by agy (one bounded headless call) reports agy — or the ticket records why agy could not be measured.
- [x] AC7 — The prose describing the gate (module docstring, `docs/DEPLOY-CONFIRM.md`, justfile comments above
  `_confirm`, root + wom7web `AGENTS.md`, wom7web `CLAUDE.md`) no longer claims an agent cannot answer it; it
  states what is refused, how, and the residual. T407's prose-vs-policy probe stays green.
- [x] AC8 — Human-presence factor: **owner decided 2026-09-24 — "macOS Touch ID prompt is great here"**. Built:
  every confirmed prompt is followed by the macOS device-owner dialog (`human_presence.swift`,
  LocalAuthentication `.deviceOwnerAuthentication`: Touch ID, Watch or login password), compiled from source into a
  temp dir on each use. A cancelled / timed-out / unavailable dialog refuses, and a refused root writes no consent.
