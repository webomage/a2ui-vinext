# T477 — Pre-push: fix the slow scans, then parallel gate groups

## Summary

Owner, 2026-09-28, while preparing a deploy: *"can we do parallel execution of different tests in
prepush hooks?"*, then *"go"* on the two-step plan. The wom7web push that landed `33d5d29d` took
**1122s (about 19 min)**, every gate strictly one after another (`wom7web/.husky/pre-push`):

| Step | During the push | Standalone |
|---|---|---|
| typecheck (`astro check`, 5 apps in series) | 488s | 15–37s per app |
| emoji-check | 221s | 28.7s |
| license-check | 163s | 30.6s |
| dep-licenses-check | 56s | 3.4s (all of it `pnpm licenses`) |
| 17 other gates | 194s combined | none over 25s |

Two findings:

1. **emoji-check and license-check walked every `node_modules`.** Both were 95%+ `pathlib` glob
   time (cProfile): `ESTATE.glob("*/**/*.md")` in `scripts/emoji_policy_check.py` and
   `repo.rglob("package.json")` in `scripts/repo_hygiene.py` descended into trees the code then
   discarded. license-check even had git's tracked list in hand and used it only as a filter.
2. **Push time is mostly contention, not work.** Standalone numbers are 5–15× lower than in-push
   ones; the gates do not depend on each other, so a push should cost about its slowest gate.

## Acceptance criteria

- [x] AC1 — **The two slow scans stop entering excluded trees, with identical results.**
  `emoji_policy_check._pruned_glob` walks with `os.walk`, pruning `exclude_paths` dirs, and
  matches `Path.glob`'s symlink rule (followed at the prefix, not inside `**`).
  `repo_hygiene.discover_manifests` iterates `git ls-files` instead of `rglob`. Measured
  equivalence, file for file, against the pre-change code: md 6070 = 6070, scripts-py 274 = 274;
  `check_license` problems and stats equal (23 manifests). Standalone: emoji-check 28.7s → 3s,
  license-check 30.6s → 1s; `emoji-check-test` and `license-check-test` green.
- [x] AC2 — **Independent pre-push gates run in parallel groups.** typecheck's 5 apps with bounded
  concurrency (3–4: each `astro check` holds 1–2 GB), the read-only gates as a second group,
  order-dependent or writing gates (`state-check`, anything regenerating files) serial after.
  Keeps: per-step pass/fail records (resume after failure), each gate's output buffered and
  printed in a fixed order with the ✅/❌ lines byte-identical (parsed downstream), every failing
  gate named, push blocked on any failure.
  → **DONE 2026-10-19:** added `run-typecheck` subcommand (`discover_typecheck_apps` +
  `cmd_run_typecheck`, bounded concurrency 3) and `fcntl.flock` checkpoint locking + per-step
  `why_not(cp, commit_hash, from_step, step_id)` in `scripts/prepush_runner.py`, wired `typecheck:`
  in `wom7api/justfile`, and grouped the 22 read-only pre-push gates (`3. w0m-audit` through
  `20. version-check`) into `run_parallel_readonly_gates` (`PREPUSH_JOBS=6`) in
  `wom7web/.husky/pre-push` with buffered deterministic output order, per-step pass/fail checkpoints,
  and serial execution of `17. state-check` and `graph-global` after the parallel group. Probed in
  `wom7web/project/scripts/tests/test_prepush_runner.py` (16/16 passing).
- [x] AC3 — **Measured:** a full wom7web push with AC1 + AC2 lands in under 5 minutes, timings
  recorded here.
  → **DONE 2026-10-19:** idle full wom7web push measured **60s** end-to-end (vs **1,122s** before
  AC1); under concurrent load, `run-typecheck --concurrency 3` across all 5 apps (`web`, `cp`,
  `demo`, `job`, `join`) reduced cumulative serial app time **912.4s → 337.3s wall-clock** (2.7×
  speedup, ~28s when uncontended), and the 22 read-only gates run in a 6-worker parallel pool in
  **~14s wall-clock** (vs ~65s serial).
