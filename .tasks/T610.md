# T610 — Parallelize `w0m-prs` GitHub delta precheck under 10s, fix Orca `run-use` CLI flag, and harden Linux Orca binary resolution

## Summary

Eliminate 60-second precheck timeouts and CLI/binary resolution mismatches in the scheduled Orca automation `w0m Upstream PRs & Fork Branches Monitor` (`5cc35a43-05f5-45d1-a366-13dcd4ae6e97`):

1. **Parallelize `search_prs` and `audit_pr` fan-out (`AC1`)**: `discover_new_prs_and_branches()` previously ran 13 sequential `gh pr list` subprocesses followed by 21 sequential `gh pr view` subprocesses (~54–60.05s total), causing 10 of 16 scheduled Orca precheck runs on 2026-11-02 to hit Orca's 60s precheck timeout (`skipped_precheck`). Execute preset repo searches and PR audits concurrently via bounded `ThreadPoolExecutor` while preserving deterministic output order and `unittest.mock.patch` compatibility so `check-delta`, `prs-discover`, and `prs-open` complete in `<10s`.
2. **Fix `orca orchestration run-use --id` flag in `sync_prs_to_orca` (`AC2`)**: `sync_prs_to_orca()` passed `--run <run_id>` instead of `--id <run_id>` to `orca orchestration run-use`, silently fencing subsequent `task-create` calls (`consumer_fenced`) when re-syncing an existing Run. Fix `--id <run_id>` and keep existing monitor tasks synced.
3. **Harden `resolve_orca_bin` on Linux (`AC3`)**: Honor `ORCA_CLI_COMMAND` first in live environments, check Orca's user/app shim paths (`~/.config/orca/linux-orca-cli-shim/orca`, `~/.local/bin/orca`, `/Applications/Orca.app/Contents/Resources/bin/orca`) and `orca-ide` before `shutil.which("orca")`, and explicitly skip `/usr/bin/orca` and `/bin/orca` (the GNOME screen reader binary on Linux desktops).

## Acceptance criteria

- [ ] **AC1 — Concurrent `search_prs` & `audit_pr` execution under 10s (`scripts/w0m_prs.py`)**: Fan out per-repo `gh pr list` in `search_prs` and per-PR `audit_pr` calls in `discover_new_prs_and_branches`, `cmd_table`, and `cmd_audit` using a bounded `ThreadPoolExecutor` with deterministic result ordering and bounded subprocess timeouts; verify live `w0m_prs.py check-delta --preset w0m-pr` completes in `<10s`.
- [ ] **AC2 — Valid `orca orchestration run-use --id` binding in `sync_prs_to_orca` (`scripts/w0m_prs.py`)**: Replace `--run` with `--id` on `orca orchestration run-use` in `sync_prs_to_orca` and verify with unit tests in `scripts/tests/test_w0m_prs.py`.
- [ ] **AC3 — Linux-safe `resolve_orca_bin` priority & screen-reader guard (`scripts/agent_provider.py`)**: Honor `ORCA_CLI_COMMAND`, prioritize Orca IDE shims and `orca-ide`, and reject `/usr/bin/orca` + `/bin/orca` screen-reader paths, verified by unit tests in `scripts/tests/test_agent_provider.py`.
