# T374 — Unified oMLX process management: multi-mode daemon/GUI/CLI detection, port arbitration, and lifecycle recipes

## Summary

Owner directive, 2026-09-18:
> *"ok, it looks like we have to fix issue with detecting already running service started manually for omlx and also ability to stop/restart/start it in this case"*

Currently, oMLX on macOS can be started through three disjoint mechanisms:
1. Homebrew LaunchAgent background daemon (`brew services start omlx`, running `omlx-server` as PID under launchd).
2. Desktop GUI application (`/Applications/oMLX.app/Contents/MacOS/oMLX`).
3. Foreground CLI or Python runner (`omlx server` or `python -m omlx.server`).

When an instance is started manually or via the GUI app, Homebrew does not detect it, reporting the service as `stopped` or `error`. Attempting to run `brew services start omlx` or `brew services restart omlx` fails with `OSError: [Errno 48] Address already in use` because port 8888 is already bound. Conversely, running `brew services stop omlx` leaves the manually started or GUI process running.

This ticket delivers a robust, cross-mode oMLX process detector and lifecycle manager script (`scripts/omlx_service.py`) exposed via standard `just` recipes (`just omlx-status`, `just omlx-start`, `just omlx-stop`, `just omlx-restart`), arbitrating port 8888 cleanly across all launch modes.

## Acceptance criteria

- [x] AC1 — **Multi-Mode oMLX Process Detection**: `scripts/omlx_service.py status` accurately inspects port 8888, detecting running PIDs, identifying whether the process was launched via Homebrew daemon (`sh.brew.omlx`), macOS GUI app (`oMLX.app`), or standalone CLI, and printing active model, liveness, and memory consumption.
- [x] AC2 — **Graceful Cross-Mode Process Termination**: `omlx_service.py stop` identifies all processes binding port 8888 or matching `omlx`, stops Homebrew services if loaded, issues graceful SIGTERM to any manual/GUI PIDs, and escalates to SIGKILL if the process fails to release port 8888 within a 5-second deadline.
- [x] AC3 — **Clean Start and Restart with Port Arbitration**: `omlx_service.py start` and `restart` inspect port 8888 prior to launching, safely terminating rogue or conflicting instances before starting the managed service, preventing `[Errno 48] Address already in use`.
- [x] AC4 — **Estate Justfile Integration**: Expose `just omlx-status`, `just omlx-start`, `just omlx-stop`, and `just omlx-restart` across `wom7web/justfile` and the workspace root `justfile`.

## Definition of Done

T374 is done when:
1. `just omlx-status` accurately reports whether oMLX is running, its PID, port 8888 status, and launch mode (Brew, App, or CLI).
2. `just omlx-stop` cleanly frees port 8888 regardless of how oMLX was started.
3. `just omlx-restart` cleanly restarts oMLX without encountering port address conflicts.
4. All quality gates (`just dod-check --ticket T374`) pass cleanly.
