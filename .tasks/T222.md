# T222 — Golden coverage exists, but nothing compares it

> **Owner ask, 2026-08-15:** *"any good golden/baseline for UI you can recommend to embed with Gauge
> UI/UX specs?"* and *"I'm looking to make goldens full page captured, but since our main page
> infinitely adds/loads posts at the end, not sure if it will work on main."*

## Summary — the tooling is fine; the wiring and the capture UNIT are not

The estate already has a competent harness — **do not replace it**. `tests/steps/ui.steps.ts`
implements `pixelmatch` + `pngjs`, per-viewport goldens (`en-<viewport>-<name>.png`), a
`GAUGE_UPDATE_GOLDENS=true` re-baseline path, and diff/current artefacts written to
`screenshots/reports/`. **95 goldens are committed**, including `en-desktop-home.png`. Percy /
Chromatic / Argos would add a vendor and solve nothing that is actually broken here.

Three real defects, in descending order of consequence:

**① The gate is not wired to anything.** `specs/web/goldens.spec` covers `/ → home`, but it is
**absent from `project/test-suites.json`**, has **no `just` recipe**, and runs in no hook. So the
homepage baseline exists and **nothing ever compares against it** — which is precisely how
[[T221]] (hero overlapping its CTAs, service cards stuck at `opacity: 0`) reached production
unnoticed. A baseline nobody diffs is a screenshot, not a gate.

**② A missing golden silently PASSES.** `ui.steps.ts` writes the current frame as the new baseline
and `return`s when no golden exists. A page added with no baseline therefore goes green on its
first run **and enshrines whatever it looked like, including broken**. This is the estate's
signature failure — the same shape as an empty corpus reporting clean ([[T169]]) — and it must fail
(or demand `GAUGE_UPDATE_GOLDENS=true`) instead.

**③ Full-page capture cannot work on the main page — the owner is right.** Capture is
`screenshot({ fullPage: true })`, and the comparator **throws on any dimension mismatch**. An
infinite/lazy-loading feed makes page height non-deterministic ⇒ the check fails **every run for
the wrong reason**, which trains people to ignore it. A gate that cries wolf is worse than no gate.

### The recommendation: scope the capture, don't scope out the page

**Section-scoped goldens, not whole-page**, for any page with dynamic tails:
- `locator.screenshot()` clips to one element — stable regardless of what loads below it. The
  [[T221]] bug lives in the `What we help with` section; a golden of **that block** would have
  caught it exactly, and would be immune to the post feed entirely.
- Playwright **`mask: [locator]`** paints over genuinely volatile sub-regions (the live
  `WARP | 2000 STARS | SPEED` telemetry overlay, timestamps, counters) so they cannot flap a diff.
- **Freeze the data** if a full-page shot is genuinely wanted: stub/limit the posts endpoint under
  test so height is deterministic. Full-page then becomes legitimate — but it is still a blunt unit,
  because one copy edit re-baselines the entire page.
- Keep **full-page only for short, static pages** (contact, team) where it is cheap and meaningful.

## 2026-08-15 — research corrections BEFORE work starts

Run through `w0m-sdlc-research`. The ticket's diagnosis mostly held — `goldens.spec` really is
absent from `test-suites.json`, has no recipe and is in no hook; a missing golden really does write
the frame and `return` (`ui.steps.ts:66-70`); `fullPage: true` + a throw on dimension mismatch are
real; 31 desktop / 9 mobile / **0 tablet** confirmed. Three things it got wrong:

1. 🔴 **"Nothing ever compares them" is too strong.** `env/default/default.properties` sets
   `gauge_specs_dir = specs`, so **`just e2e` DOES execute `goldens.spec`** across all 30 pages.
   What is true is that nothing *automated* invokes it — no hook, and `e2e` is not in the suite
   registry. That changes AC1 from "build a runner" to "wire the one that exists".

2. 🔴 **AC7's "this is coverage, not plumbing" is WRONG.** `ui.steps.ts:23-27` picks dimensions with
   a binary `if`: `mobile` → 390×844, **everything else** → 1440×900. Naming a viewport `tablet`
   would produce a **desktop-sized capture saved under a tablet filename** — a silently wrong
   baseline, the estate's signature failure. AC7 needs a viewport→dimensions table first.

3. 🔴 **55 of the 95 goldens are unreachable by the current code.** The path is
   `` `en-${viewport}-${name}.png` `` (`ui.steps.ts:49`) with the language **hardcoded to `en`**, so
   all 20 `ru-`/`es-` goldens can never be read, and 35 more use an older no-viewport name. One file
   is literally named **`en-<name>.png`** — a fossil from a run where the parameter never
   substituted. Any "N goldens committed" figure must say *reachable*, or it measures nothing.

## 2026-08-15 — AC2, AC3, AC7 landed. AC1/AC4/AC5/AC6 still open.

**AC7 — the viewport matrix, and it WAS plumbing.** Replaced the binary
`if (viewport === "mobile") … else 1440×900` with a `VIEWPORTS` table: desktop 1440×900 ·
tablet-portrait 768×1024 · tablet-landscape 1024×768 · mobile-portrait 390×844 ·
**mobile-landscape 844×390** · plus `mobile` retained as an alias, since 9 committed goldens still
use that name. An **unknown viewport now throws** instead of falling back to desktop — the old
default is how a typo would have produced a confidently-named golden of the wrong size.
`isMobile` is carried per row because `setViewportSize` alone does not make a browser mobile.

**AC2 — a missing golden now FAILS.** It used to write the current frame as the baseline and
`return`, so a page with no golden went green on its first run and enshrined whatever it looked
like, broken included. It now throws, writes the frame to `reports/missing-*.png` for inspection,
and names `GAUGE_UPDATE_GOLDENS=true` as the deliberate opt-in. Verified both directions: the throw
is present **and** the auto-write is gone.

**AC3 — section-scoped step**, `the <selector> should match the <viewport> golden snapshot <name>`,
via `locator.screenshot()`. A selector matching nothing **fails** (`waitFor visible`) rather than
screenshotting emptiness into a stable image that would pass forever. The comparison logic was
extracted so the page-level and section-level steps share **one** path.
`specs/web/goldens.spec` now captures the homepage as hero · services · CTA, with `services` across
all five viewports — leaving the post feed out entirely.

### AC6 + AC5 — 2026-08-15, run against a served build

**AC6 — baselines created deliberately.** 7 new section goldens via `GAUGE_UPDATE_GOLDENS=true`
against **only** the new scenario (`goldens.spec:40`), so the 30 page-level goldens were *not*
mass-re-baselined. The dimensions prove the AC7 table is real rather than nominal:

| golden | size |
|---|---|
| `en-desktop-home_services.png` | 1140×461 |
| `en-tablet-portrait-home_services.png` | 708×649 |
| `en-tablet-landscape-home_services.png` | 964×513 |
| `en-mobile-portrait-home_services.png` | **330×1248** |
| `en-mobile-landscape-home_services.png` | **784×597** |

Under the old binary `if`, every one of those would have been captured at desktop width.

**AC5 — PROVEN RED against the real regression.** Reintroduced T221's `min-height` in
`global.css`, re-ran, restored:

| viewport | with the defect | restored |
|---|---|---|
| `mobile-portrait` | ✘ **25,978** mismatched px | ✔ |
| `mobile-landscape` | ✘ **26,140** mismatched px | ✔ |
| `desktop` · `tablet-portrait` · `tablet-landscape` | ✔ (did not catch it) | ✔ |

🔴 **The headline: the pre-existing DESKTOP-ONLY coverage would NOT have caught T221.** Only the
mobile viewports detect it — the clip needs a short viewport to bite, which is exactly the argument
AC7 made and this is the evidence for it. A gate wired before AC7 would have shipped the regression
and reported green.

**A flaky gate was found and fixed on the way — worth more than the AC.** The first AC5 attempt had
`tablet-portrait` failing in BOTH directions with *different* counts (6,259 then 9,017) on identical
code. Cause: the capture raced **T221's own 1500ms fail-open backstop** — a section below the fold
stays hidden until the backstop reveals it, so timing, not correctness, decided what was
photographed. The step now waits for `.animate-on-scroll:not(.is-visible)` to reach zero inside the
target before capturing, and passes `animations: "disabled"` to Playwright.
**Verified stable: three consecutive runs on unchanged code, all green.** Had this shipped
unfixed it would have been the "cries wolf" gate this ticket was written to avoid.

### AC4 + AC1 — 2026-08-15

**AC4 — volatile regions masked.** `.metrics-overlay` is a per-frame Three.js readout
(`WARP | ${numStars} STARS | SPEED ${speed}`), and it is baked into the committed
`en-desktop-home.png`, so that baseline encodes one arbitrary frame of a counter. Both capture
paths now pass Playwright `mask:`. ⚠️ Masking is **not** exclusion — the region's position and size
are still compared, so a layout break that moves or resizes the overlay is still caught; only the
churning text is neutralised.

**AC1 — PARTIALLY done. `just goldens` exists, is registered, and runs on the deploy path.**
New recipe: boots a dev server (or **reuses** one already on `:4321`), warms it, runs the section
scenario, tears down. Declared in `project/test-suites.json` as tier **live** — `just suites-drift`
green, 90 declared / 0 undeclared. Wired into `just deploy` between `test` and `deploy-api`, the
same insertion point [[T224]] used.

Three defects found by running it repeatedly rather than once:
- 🔴 **It leaked a dev server.** `infisical run -- pnpm dev` puts astro two levels down, so neither
  `kill $DEV_PID` nor `pkill -P $DEV_PID` reached it — **both were tried and both leaked**. Now
  killed **by port**. This matters more than it sounds: a leaked server is silently *reused* by the
  next run, so the gate would test a build nobody remembers starting. (One orphan from this
  session's earlier preview was still listening **2h43m** later, reparented to launchd.)
- 🔴 **Cold-start flake.** The boot path failed while the reuse path was green 3/3 — a cold Astro
  dev server compiles on first request and serves assets unwarmed, so the first capture measures
  the compiler, not the page. Two throwaway loads before capturing. **Verified: 3 cold-boot runs,
  all pass, 0 listeners left behind each time.**
- ⚠️ A first "stray processes: 4" reading was my own bad measurement — taken while runs were in
  flight. Re-measured at rest: **0**.

⚠️ **What AC1 does NOT yet do, and it is the half the AC cared most about:** it gates the **dev
server**, not the **built artifact**. `deploy-web` builds and wrangler-deploys in a single recipe,
so there is no seam between "artifact exists" and "artifact ships" to insert a check into without
restructuring the deploy path — which is not something to do late, on the command that already
failed once today. **② post-deploy smoke against live** and **③ scope-by-changed-paths** are also
still unbuilt. AC1 stays unticked.

### AC1 ② + ③ — 2026-08-15

**② Post-deploy live smoke — BUILT and PROVEN.** `just smoke-live [url]`, wired into `just deploy`
after the apps ship and **non-blocking by design**: it runs once the artifact is already public, so
failing the command could not un-ship anything. Its job is to tell you, loudly.

**Structural, deliberately NOT a pixel diff.** Comparing live against baselines captured on a dev
server would flag font loading, CDN image transforms and cache variance as regressions — noise on
the exact surface this is meant to watch. It asserts the three invariants [[T221]] broke, each
resolution-independent:
1. nothing overflows the `overflow:hidden` clipping parent
2. every `.animate-on-scroll` reached `.is-visible` (read as the **cascade target**, not the
   animated value — a frozen timeline reports the START value forever)
3. the hero paragraph does not collide with the CTA row

**Proven both directions.** Against production: `overflow=0 reveals=7 hidden=0 gap=16` — matching
the manual verification exactly. Against a local build with T221's `min-height` reintroduced:
**FAILED with `content overflows its clipping parent by 136px`** — the same figure measured by hand
when the bug was first diagnosed, on **both** pages, because the shell defect is site-wide.

⚠️ **Two of my own mistakes, caught by running it rather than reading it.** The first version
asserted immediately on page-load and reported *"6 of 7 reveal elements stuck invisible"* **against
a production page that is demonstrably correct** — the same reveal race that made the section
goldens flaky, repeated. And it treated "0 reveal elements" as a failure everywhere, which is right
for the homepage and wrong for `/contact/`. The expected count is now **declared per page in the
spec**, because inferring it makes *"this page has none"* indistinguishable from *"the selector
stopped matching"*.

**③ Scope-by-changed-paths — DECLINED, with the evidence.** The AC asked to run the gate only when
the diff touches `apps/*/src` or `packages/ui`. **[[T224]] is the counter-example:** its `ac-trace`
failure was caused by a **ticket markdown** edit, and a code-scoped gate would have skipped it. A
gate that decides not to run based on a path heuristic is a vacuous green waiting to happen — the
estate's cardinal failure. The cost it was meant to avoid is **~45s on a command that already takes
minutes and is run a few times a day**, which is not worth buying with a blind spot. Recorded as a
decision, not an omission.

### 2026-08-16 — the gate BLOCKED a real deploy, for the wrong reason

The owner's `just deploy-all` reached `goldens` and failed:
`page.goto: net::ERR_ABORTED at http://localhost:4321/` on the **first two rows**, with the
remaining five passing. **Not a visual regression — the gate crying wolf**, which is precisely the
outcome this ticket was written to prevent, shipped by this ticket.

**Cause:** a dev server re-optimizes its dependency graph the first time a real **browser** pulls
it, and that reload aborts whatever navigation is in flight. **`curl` cannot warm this** — it never
fetches the client modules that trigger the re-optimize — so the two warm-up requests already in the
recipe proved nothing, and each of them could itself *be* the request that triggered the reload.

**Two fixes, and BOTH were needed** (the first alone still failed, measured):
1. `just goldens` now warms until **three consecutive successful loads two seconds apart**; a
   restart resets the streak, so the loop exits only once the server has stopped reloading.
2. `ai.steps.ts` retries a navigation **once**, and only on
   `ERR_ABORTED`/`ERR_CONNECTION_*`/`ERR_EMPTY_RESPONSE`. A genuinely missing page still fails, and
   a real 4xx/5xx is a `Response` rather than a throw, so it is untouched.

**Reproduced and verified on the exact failing condition** — cold server with `node_modules/.vite`
deleted, which is what forces the re-optimize:

| | rows passing |
|---|---|
| before | **6 of 7** — `desktop-home_hero` aborted, deploy blocked |
| after warm-up fix only | **6 of 7** — still aborted |
| after both | **7 of 7** |

⚠️ **My earlier "3 cold-boot runs, all pass" was not the cold condition.** Those runs reused a warm
`node_modules/.vite`, so no re-optimize occurred. The genuinely cold case — a fresh cache, which is
what a teammate or a new checkout gets — was never exercised until the owner's deploy hit it.

### 2026-08-16 — AC1 closed: ② built, ③ declined, ① split out as [[T227]]

**② post-deploy live smoke — BUILT and proven both directions** (see above): production reports
`overflow=0 reveals=7 hidden=0 gap=16`, and a local build with T221's `min-height` reintroduced
fails with `content overflows its clipping parent by 136px`.

**③ scope-by-changed-paths — DECLINED with evidence.** [[T224]]'s `ac-trace` failure came from a
**ticket markdown** edit, so a code-scoped gate would have skipped it. Buying ~45s on an infrequent
command with a blind spot is a bad trade.

**① gate the BUILT artifact — SPLIT OUT as [[T227]]** (owner decision 2026-08-16: *"let's separate
built of local wrangler dev with --remote for goldens as a separate independent ticket and complete
T222"*). Measured why it is its own piece of work: `apps/web/dist/server/wrangler.json` declares
**`services: WOM7API, CF_WORKERS`** — bindings to other *deployed* Workers that `wrangler dev`
cannot fulfil locally, forcing `--remote` — plus `kv_namespaces` with real ids, `r2_buckets`,
`d1_databases` and `durable_objects`. Standing that up on every deploy is slow and adds a failure
mode to a path that broke **four times** on 2026-08-16.

⇒ **T222 closes at 7/7.** One AC built, one declined with evidence, one delegated with its own
acceptance criteria — including [[T227]] AC5, which requires proving the built-artifact gate catches
something the dev-server gate cannot, *or* being closed as not worth shipping.

### Still open, deliberately

**Only AC1 ① remains, and precisely one thing is missing from it:** the pre-deploy gate runs against
a **dev server**, not the **built artifact**. `deploy-web` builds and wrangler-deploys inside one
recipe, so there is no seam between *artifact exists* and *artifact ships* to insert a check into.
Closing it means either splitting that recipe or serving `dist/server` under `wrangler dev` and
pointing the gate at it — a change to the deploy path, which deserves its own decision rather than
being tacked onto a long session. Everything else in AC1 is built and proven.
