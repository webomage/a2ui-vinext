# T234 — trial ai-memory, and measure what it could actually replace

## Summary

**Owner, 2026-08-19:** *"let's plan to add ai-memory and test/evaluate if we can then deprecate
something."*

[[AgDR-0007]] deferred every memory framework and named **auto-memory** — Claude-only, unversioned,
per-machine, 62 files / 297 KB — as the one surface a framework could legitimately replace.
**ai-memory** is the only evaluated candidate whose store is **markdown in git**
(`wiki/<workspace>/<project>/*.md` + YAML frontmatter, SQLite FTS5 as an *index*, not the store),
MIT/Rust, 3.2k ★, and it names **Antigravity, opencode, Gemini CLI and Claude Code** explicitly —
[[T232]]'s exact agent set. `memory_handoff_accept` is literally the handoff problem T232 exists for.

## 🔴 Measuring first changed the question

Of the 62 memories: **42 reference a ticket by id** — so the ticket is the record and the memory is
a *pointer* — and **32 carry rule-shaped markers** (`⇒` / `⚠️` / `🔴`), overlapping `LESSONS.md`'s job.

⇒ **The question is not "does ai-memory work". It is "how much of auto-memory is RECALL, and how
much is a duplicate register?"** If most of it duplicates tickets and LESSONS, then **the
deprecation is available without adopting anything**, and adopting would move a duplicate rather
than remove it.

## Acceptance criteria

- [x] AC1 — ✅ **DONE 2026-08-19 — classified by reading: 34 pointer · 24 recall · 4 duplicate.**: `recall` (fast per-session
      lookup that exists nowhere else) · `pointer` (a ticket/debt/lesson is the real record) ·
      `duplicate` (the content is already in a git-tracked register). ⚠️ **By reading, not by
      pattern** — the 42/32 counts above are *shape* matches, and this estate has repeatedly found a
      count that meant something other than it appeared to.
- [x] AC2 — ✅ **DONE — and the trial stops, for a REASON AC2 did not anticipate.** If `recall` turns
      out to be a small minority, say so and stop — 🔴 **that outcome closes this ticket without
      installing ai-memory**, and it is a success, not a failure.
- [ ] AC3 — **Install ai-memory scoped to ONE repo**, never globally, with the uninstall command
      recorded in the ticket before install. ⚠️ It installs **lifecycle hooks**; a trial that cannot
      be cleanly reverted is an adoption.
- [ ] AC4 — 🔴 **A PRE-REGISTERED KILL CRITERION, written before the trial starts.** A trial with no
      failure condition is an adoption with extra steps. It must name what would make us remove it —
      e.g. *"a memory written by Claude is not readable by a second agent"*, *"the wiki and the
      tickets disagree and nothing detects it"*, *"it costs more session tokens than auto-memory"*.
- [ ] AC5 — **Prove the cross-agent claim, or record that it is unproven.** The entire reason to
      adopt is portability. ⚠️ Verifying it needs a **second agent actually reading a memory the
      first wrote** — and Gemini/opencode are not yet configured ([[T232]] AC2/AC3), so this AC may
      legitimately end as **NOT MEASURABLE**, which must be stated rather than assumed away.
- [~] AC6 — 🔬 **RESPECIFIED 2026-08-19 — locking EXISTS; test the known mechanism, do not probe for a missing one.** A parallel Antigravity agent
      commits into this estate today, and ai-memory's conflict semantics for simultaneous edits are
      **undescribed**. Two agents writing the same page must be tried deliberately.
- [ ] AC7 — **Token cost measured both ways.** `MEMORY.md` currently loads **~4.2k tokens every
      session**. If ai-memory's retrieval costs more per session than the index it replaces, the
      trial fails on its own terms.
- [ ] AC8 — **Deprecate exactly one thing, or nothing.** ⚠️ Adding a memory layer *beside*
      auto-memory makes a **ninth register** — the failure this estate keeps finding. The trial ends
      with a surface removed or the tool removed; **"both, for now" is not an allowed outcome.**
- [x] AC9 — ✅ **DONE — [[AgDR-0008]] supersedes [[AgDR-0007]]**, whichever way this goes. It is
      `proposed` today; the trial's result makes it accepted or rejected, and the record of what was
      argued must survive either way.

## Adoption — 2026-08-19 (owner decision)

**Owner:** *"let's embed ai-memory and stick to validated version, do not auto-update it without
revalidating changes"*, then *"nope, let's stick to clear tagged version 1.29.0 preferrable"*.

✅ **ADOPTED, pinned to `v1.29.0`.** Not the first build: that was `v1.28.1-55-g4de744a`, an
**untagged mid-stream commit**. Moving to the tag was the owner's call and it is the better pin.
🔬 **It also corrected a measurement error of mine**: I had reported the first build as sitting
"exactly on v1.29.0", from `git rev-list v1.29.0..HEAD == 0` — which is **equally true when HEAD is
BEHIND the tag**. `git tag --points-at HEAD` was empty. *Verify a tag by what points at the commit,
never by a zero rev-list count.*

**Revalidated at the tag, not carried over:** the 3 commits taken on touch **0 `.rs` files** (a
changelog CI script, a merge, the version bump); rebuild clean in **2m43s / 11 crates** (the rest
cached, consistent with no source change); binary reports **1.29.0**.

| pinned | value |
|---|---|
| commit | `805fa4b17d575dadcd9cc9064aad42975e59e04e` (`v1.29.0`) |
| binary sha256 | `281266dde5423bf69d54ea8ce506d188341c54dac7a2dbcaa9f68eed73039a78` |
| local freeze tag | `w0m-validated-2026-08-19` |
| auto-update | **false — by decision, not by default** |

⚠️ `v1.29.0` is an **annotated** tag, so `git rev-parse v1.29.0` yields the **tag object**
(`fef1f694…`), not the commit. My first verification compared tag-object to tag-object and proved
nothing; dereferenced with `^{commit}`, all four (tag, freeze tag, HEAD, pin) agree.

**Enforcement — `just ai-memory-check`** (`project/scripts/ai_memory_pin_check.py`), registered as a
suite. Verifies **three** things because each drifts alone: checkout commit (someone pulled), binary
SHA-256 (rebuilt from other sources, or replaced), reported version (a prebuilt dropped in).
Commit-only would pass a binary from anywhere — the exact supply-chain risk that made
build-from-source the condition of adoption. Red-proven on all three, plus a missing pin exiting
**2 = unknown, not clean**.

🔴 **Withdrawn during implementation: a `tools-policy.json` entry.** I declared `ai-memory` there and
`tools-check` immediately reported `✗ MISSING` — because it resolves tools by `which(<key>)` and this
binary is deliberately **not on PATH** (a note I had written into that very entry). It could never
pass. Withdrawn: **a permanently-red check is what [[T135]] AC8 forbids**, and the pin check already
governs the artefact properly.

⚠️ **Still open, and adoption does not settle them:** AC8's *"one surface goes or the tool does"* —
**nothing has been deprecated yet**; the 34 pointer memories are still live. And AC6's concurrency
test against the parallel Antigravity agent stands (locking exists, it was never exercised here).

## 2026-08-19 — evaluated, and NOT adopted: the reason to want it was not real

Owner: *"go research ai-memory deep and proceed with adding it if evaluated."* Researched; the
evaluation says no, and **the decisive fact is that a claim I made in [[AgDR-0007]] was wrong**.

### 🔴 The correction

AgDR-0007 called ai-memory *"the only candidate whose store is markdown in git"* and made that the
deciding advantage. The docs place the wiki at
**`~/.local/share/ai-memory/wiki/<workspace>/<project>/`** — git-versioned **in its own repo**, not
inside `wom7web`. ⇒ **It does not clone with the project.** A teammate, a second machine or CI gets
nothing — **exactly like the 62 auto-memory files it would replace**.

The portability it actually buys is **across agents on one machine**. That is real, and it is a much
smaller claim than the one that motivated the trial.

### AC1 — classified by reading all 62

| Class | Count | |
|---|---|---|
| **pointer** | **34 (55%)** | a live ticket already carries the record |
| **recall** | **24 (39%)** | exists nowhere else — `openspec-cli`, `gh-identity-isolation`, `scheduler-surface-split`, `upwork-graphql-contract`, … |
| **duplicate** | 4 | the rule is already in `CLAUDE.md`/`AGENTS.md`/`LESSONS.md` |

⚠️ **AC2's stop condition did NOT fire.** It said *stop if recall is a small minority*; 39% is not.
**The trial stops for a different reason than the one pre-registered**, which is worth stating
rather than retrofitting: the kill criterion I wrote anticipated the wrong failure.

### What adoption would have cost — from the docs, not assumption

A **daemon** on `:49374` (Docker or systemd) on a host the audit already found running **five
container runtimes**; a **prebuilt binary** and **lifecycle hooks** installed into agent runtimes on
a machine holding production credentials, with [[fake-interview-malware-2026-06]] in this estate's
history; **no documented locking** while a parallel **Antigravity** agent writes here (AC6's exact
risk); and consolidation that calls an **LLM provider** per session.

### ✅ The deprecation is available anyway — with no tool

**34 of 62 memories are pointers to tickets that already hold the record.** Pruning them to one-line
hooks removes the duplication immediately. That was T234's real question, and the answer did not
need a purchase.

### Remaining

**AC3–AC8 are moot** — there is nothing to install, no kill criterion to run, no concurrency to
test. ⚠️ **AC5 stands as the honest residue**: the 24 recall memories remain Claude-only, and this
decision **declines a fix that would not have fixed it**. If they must be cross-agent, the route is
moving them into a git-tracked register **inside the repo** — work, not a purchase.


## 2026-08-19 — REOPENED: the rejection rested on a false premise

Owner forked ai-memory (intent — the repo does not exist yet, measured across **1,791** owned repos)
to explore enhancing it. Re-reading upstream to answer *what would we change* found that
**[[AgDR-0008]]'s decisive reason was wrong**, so [[AgDR-0009]] supersedes it.

### 🔴 The correction

`docs/ARCHITECTURE.md`, read directly:

> `<data_dir>/wiki/` — markdown **source of truth**. Owned by a `git2` repo so every consolidation
> pass + every session-end produces a durable commit. … Backups: … **Or: `git push` the wiki dir**.
> `<data_dir>/db/memory.sqlite` — **derived index**.

⇒ The wiki **is a pushable git repo** and SQLite is derived. AgDR-0008 said the store *"does not
travel"* — it does not travel with `wom7web`, which is what I checked, but **that is not the same as
not travelling**, and I asserted the stronger claim.

⚠️ **`--data-dir` is a first-class flag**, so the store location was always configurable. **No fork
is needed for repo-locality** — which was the enhancement this exploration set out to find.

📌 **The error pattern, twice in one day** (also AgDR-0001 → 0002): **I verified a location and
inferred a consequence, instead of reading the two lines that state the consequence.**

### What a fork IS still worth

**Supply-chain control.** Upstream ships **prebuilt binaries** and installs **lifecycle hooks** into
agent runtimes on a machine holding production credentials. Given
[[fake-interview-malware-2026-06]], **building from a fork the owner controls answers that
objection outright** — independent of any code change. That is the strongest argument for forking,
and it needs no feature work.

### What has NOT changed

- **AC1's classification stands**: 34 pointer · 24 recall · 4 duplicate. **34 memories duplicate a
  ticket whether or not any tool is adopted**, so that deprecation remains available today.
- The daemon on `:49374`, the lifecycle hooks, the **undocumented locking** while a parallel
  Antigravity agent writes here — all unchanged. ⚠️ **None of these was the stated reason for
  rejection, and none has improved**; they are now the actual decision basis.
- Every remaining AC still gates the install. **AC4's kill criterion must be rewritten** — the
  original anticipated the wrong failure once already.

📌 **The GitHub code-search API returned 0 hits for `lock`, `Mutex` and `advisory`** on the fresh
fork. Uniformly zero across three terms — the *too-extreme-to-be-true* signal, hit for the **fourth**
time this session. Cloning gave the real answer: **a search index is not the code.**

### ⇒ The remaining decision is not technical

**No enhancement is required to adopt.** The fork's value is build-from-source. What is left is one
owner question: *is cross-agent recall for **24** memories worth a daemon and an owned Rust
dependency?* ⚠️ And it does **not** change AC1: **34 of 62 memories duplicate a ticket**, and pruning
those is available today with no tool at all.


### 🔬 The concurrency hazard fired — on me, in this very commit

While writing the paragraph above about two agents writing concurrently, **`git add -A` swept a file
I did not create into my commit**: `project/scripts/upwork_mcp_sync.py`, mtime 15:50, produced by
the parallel **Antigravity** agent mid-work. It was caught only because `version-check` blocked the
push on a `"version": "1.0"` string inside it.

⇒ Backed out with `git rm --cached` + `--amend`; the file is untracked again, left for its author.

📌 **The lesson is not about ai-memory at all.** The estate's multi-agent hazard is **not** a memory
tool's locking — that turned out to exist and be tested. It is **`git add -A` in a working tree two
agents share**, which no MCP server can protect against. ⚠️ A gate caught it *by accident*: the file
happened to contain a version-shaped string. Nothing checks *"am I committing work I did not do?"*
