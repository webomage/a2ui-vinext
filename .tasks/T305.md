# T305 — declare and govern the cloud compute that runs as us

## Why

Owner 2026-09-02, on seeing a Claude Code **cloud environment named `w0m`** in the claude.ai/code
picker: *"let's own that cloud env config for security and management reasons."*

It is compute that runs agents on our behalf. It can hold secrets, and it is granted access to
repositories. **Nothing in this estate declares it, nothing probes it, and no gate would notice if it
changed.** That is the same shape as the undeclared MCP listeners ([[T154]]) and the `.w0m/` config
left inside the client's repository — a capability that exists, is used, and is accounted for
nowhere.

🔑 **The security argument is not hypothetical, it is structural.** Every other place the estate lets
something act as us is declared and checked: `vcs.gh_account` names the acting principal, `mcp`
declares each server and `just mcp-exposure` measures what is actually listening, `secrets` names
where credentials live. A cloud environment is the one surface with credentials **and** repository
access that has no row anywhere.

## What was measured, 2026-09-02

| check | result |
|---|---|
| `casualuser/w0m` exists | yes — created **2026-09-02T12:10:34Z** |
| clone traffic on it | **0 clones / 0 uniques** |
| webhooks · deploy keys · GH deployment environments | 0 · 0 · 0 |
| traffic API control (`webomage.com` views) | **3 views / 1 unique** — the API works, so the zeros are real |
| any `cloud`/`compute`/`sandbox` key in `.w0m/sdlc.json` | **NONE** |
| local record of the environment | none — no config, no memory, no transcript |

⇒ **If that environment is tied to `casualuser/w0m` and has ever run, it would have cloned the repo,
and nothing has.** That rules out *use*, not *configuration*.

🔴 **Two measurement walls, stated so nobody reads them as absence:**
`GET /user/installations` returns **403** and `GET /repos/:r/installation` returns **401** — both need
a GitHub-App-authorized token, so **which App installations exist and which repos they can reach is
unmeasured, not zero.** And the environment's own contents live server-side on claude.ai with no
CLI read path, so its linked repo, setup script and secrets cannot be enumerated from here.

## Acceptance criteria

- [ ] **AC1** — every cloud/agent compute surface is declared in `.w0m/sdlc.json`: name, provider,
      linked repository, what secrets it carries, which principal it acts as, and **why it exists**.
      A surface without a reason becomes a standing grant nobody can question — the same rule
      `tier_reason` already enforces for client tiers.
- [ ] **AC2** — a probe compares the declaration against what is actually reachable, and reports
      **UNMEASURABLE rather than green** for the parts that are not (the App-installation endpoints,
      the environment's server-side config). [[T304]] just established that vocabulary; use it.
- [ ] **AC3** — the credentials question is answered explicitly: what the environment holds, whether
      any of it overlaps the live estate secrets, and whether anything needs rotating. Presence is
      not content — see the empty-secret digest trap.
- [ ] **AC4** — a disposition is recorded per environment: **kept and governed, or deleted.** An
      environment nobody can account for is a standing grant of repo access, and "we are not sure
      what it does" is a reason to close it, not to leave it.
- [ ] **AC5** — the GitHub side is measured once with a token that can see it: which App
      installations exist on the account and which repositories each may reach. Until then AC2 must
      keep reporting that as unmeasured.
- [ ] **AC6** — generalises beyond this one. Any cloud environment, remote agent runner or hosted
      sandbox that can act as us is covered by the same declaration and the same probe.

## Definition of Done

No compute can act as this estate without a row that says what it is, what it reaches, whose identity
it borrows and why it exists. The declaration is checked by something that runs unattended, and where
a fact cannot be reached the check says so instead of passing — a surface that is merely hard to
inspect must not read the same as one that is clean. Every environment carries a disposition somebody
chose, so an unaccounted grant of repository access is a finding rather than a default. And the
question that started this — *when was it created and what is inside* — has an answer written down
where the next person will find it, instead of being re-derived from a screenshot.

## Notes, traps and dependencies

⚠️ **Do not infer the linkage from the name.** The environment is called `w0m` and a repo called
`w0m` was created the same day; that is suggestive and it is not evidence. The repo did not exist
before 2026-09-02T12:10Z, so an environment older than that **cannot** be tied to it.

The fastest path to AC1 is the environment's own settings pane in claude.ai/code, which names the
linked repository directly — an owner read, not a probe. Related: [[T154]] (undeclared listeners, same
shape), [[T300]] (which identity acts on a project), [[T304]] (unmeasurable vs violating).
