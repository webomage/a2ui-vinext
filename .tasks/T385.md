# T385 — Remediate failing client profile and inventory test suites, and promote drop-callers gate to blocking

## Summary

Research across the estate quality gates (`project/test-suites.json`) revealed **22 test suites marked `"blocking": false`** (10.8% of the 203 registered suites).

Four suites are actively failing RED:
1. `client-profile-check` fails with 2 contract keys (`lessons_surface`, `milestones`) in no profile tier in `client_profile_gate.py`.
2. `client-profile-test` fails 8/31 assertions due to untiered contract keys and profile drift.
3. `client-inventory-test` crashes with `KeyError: 'w0m'` in `test_client_inventory.py` because the umbrella workspace root is not a client repo.
4. `skills-catalogue-test` fails 5/18 assertions on runnable skills decisions and host invocations.

Furthermore, `drop-callers` was originally marked advisory because 7 orphaned callers referenced `public.linkedin_tokens`. The promotion trigger specified in `test-suites.json` was: *"flip to blocking the moment `just drop-callers` exits 0"*. Audit confirms `just drop-callers` now exits 0 with 0 orphaned callers across 21 dropped relations, but the gate was never promoted to blocking.

This ticket fixes the 4 RED suites, updates client profile contracts and test assertions to reflect reality, promotes `drop-callers` to `"blocking": true`, and wires `--enforce` into pre-push.

## Acceptance criteria

- [ ] AC1 — **Fix client-profile-check & client-profile-test**: Classify `lessons_surface` and `milestones` into their correct tier (required/optional/excluded) in `project/scripts/client_profile_gate.py` so both suites pass 100% green.
- [ ] AC2 — **Fix client-inventory-test**: Fix `test_client_inventory.py` handling of `w0m` workspace root so it correctly scopes to client projects and passes without `KeyError`.
- [ ] AC3 — **Fix skills-catalogue-test**: Update runnable skills declarations and decisions in `.w0m/sdlc.json` so `skills-catalogue-test` passes 18/18 green.
- [ ] AC4 — **Promote drop-callers Gate to Blocking**: Update `project/test-suites.json` to set `"blocking": true` on `drop-callers`, verifying pre-push enforcement runs and prevents reintroduced dropped relation callers.
- [ ] AC5 — **Non-Blocking Suites Triage**: Audit the remaining non-blocking suites in `project/test-suites.json` (including stage-exit gates and license check), documenting promotion triggers or retiring obsolete checks.
