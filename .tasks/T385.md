# T385 — Remediate failing client profile and inventory test suites, and promote drop-callers gate to blocking

## Summary

Research across the estate quality gates (`project/test-suites.json`) revealed **22 test suites marked `"blocking": false`** (10.8% of the 203 registered suites).

Four suites were failing RED:
1. `client-profile-check` failed with 2 contract keys (`lessons_surface`, `milestones`) in no profile tier (subsequently tiered into `excluded` in `client-profile.json` on 2026-09-30).
2. `client-profile-test` failed assertions due to `$schema` resolution on `w0m` (T301), `profile` joining `required` (install-time gate), and an undefined `ROOT` constant in `test_client_profile.py`.
3. `client-inventory-test` crashed with `KeyError: 'w0m'` in `test_client_inventory.py` when `client_inventory.py` exited 2 on Linux hosts lacking the macOS `tart` CLI binary or uncloned multi-repo portfolio stubs (`k7`, `mob`), plus skill count drift on `artemio` (55 → 56).
4. `skills-catalogue-test` failed 5/18 assertions due to `elif` branch suppression of `not r["sandboxed_declared"]` in `skills_catalogue.py`, host-dependent `~/.claude/skills` assumption, `w0m` root excluded count (0 vs 10), and `artemio` `justfile:267` line number.

Furthermore, `drop-callers` was originally marked advisory because 7 orphaned callers referenced `public.linkedin_tokens`. The promotion trigger specified in `test-suites.json` was: *"flip to blocking the moment `just drop-callers` exits 0"*. Audit confirms `just drop-callers` now exits 0 with 0 orphaned callers across 23 dropped relations, so the gate is promoted to blocking alongside `client-profile-gate`, `client-profile`, `client-inventory`, and `skills-catalogue`.
