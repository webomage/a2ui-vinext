# T406 — Searching the estate

## Summary

Filed 2026-09-20 from an owner observation: an agent's `git grep` **paused the session for several
minutes and then buried the console in output**. Measuring that symptom found two independent
defects, and neither is the one the generic speedup advice addresses.

**The working tree is not slow.** wom7web — 6,900 tracked files — answers a `git grep` in **0.282s**.
There is no performance problem to fix there.

**1. A search at the estate root sees almost nothing, and says so cheerfully.**
`@wom/.git/info/exclude` lists every `wom7*/` directory, so the root repo excludes its own members.
Measured:

| search, at `/Users/proto/Projects/@self/@wom` | hits | time |
|---|---|---|
| `rg -n supabase` (default) | **64** | 0.06s |
| `git grep -nI supabase` | **71** | 0.06s |
| the same pattern summed per repo | **5,268** | — |
| `rg --no-ignore-vcs` | **462,277** | 5.8s |

⇒ an agent that greps the root concludes the symbol does not exist anywhere. Exit 0, sub-second,
plausible-looking output. 🔴 And `.git/info/exclude` is **unversioned**, so no diff can ever explain
it. This is [[T135]]/[[T149]]'s vacuity shape with a search engine attached.

**2. History — not the working tree — is what costs minutes.** Measured on wom7web (2,877 commits):

| scope | time | output |
|---|---|---|
| working tree | 0.28s | 3,836 lines |
| `git grep` over 20 commits | 4.06s | 76,330 lines |
| `git grep` over 100 commits | 17.50s | 378,665 lines |
| all 2,877 commits (extrapolated) | **~8 min** | **~11M lines** |

`git grep <pat> $(git rev-list --all)` is the exact shape the owner saw: minutes of silence, then a
console nobody can read. The estate already reaches for it — [[T121]] and [[T124]] both record
`git grep eyJ` as a verification step, and [[T32]] is open on a value that is "still in git history".

## What the attached speedup guide is worth here — measured, not assumed

| technique | wom7web working tree | verdict |
|---|---|---|
| bare `git grep` | 0.282s | baseline |
| `LC_ALL=C git grep` | 0.123s | ✅ **2.3× — the only one that pays.** Adopted |
| `+ -F` fixed strings | 0.121s | ➖ no measurable gain at this size; adopt for *correctness* |
| `rg` | 0.098s | ➖ ~20% over `LC_ALL=C git grep`, not the order of magnitude claimed |
| `--threads=N` | — | ❌ git ≥ 2.26 auto-threads (measured 344% CPU with it unset) |

🔴 **`git config --global grep.patternType fixed` REJECTED** — not on performance grounds. It
changes what every unflagged `git grep` *means*, in every repo on this machine, and a broken ad-hoc
regex would then fail by **matching nothing**, silently. Same reasoning as the root `CLAUDE.md`
rule against machine-wide settings for project-specific tools.

## Definition of Done

T406 is done when:
1. `just search "<pattern>"` returns hits from every owned repo for a symbol that exists in more
   than one of them — proving the per-repo unit, which a root `git grep`/`rg` cannot do.
2. `just search` over a repo whose `.git` is absent exits **non-zero** and prints
   `COULD NOT BE SEARCHED`, and a genuine no-match exits 0 and says `real zero`. The two cases are
   distinguishable from the output alone.
3. `just search-test` is green (10 probes) and is registered in `project/test-suites.json`, so
   `just test` runs it and `just suites-drift` reports zero undeclared recipes.
4. No tracked `just` recipe or script invokes `git grep` without `--no-pager`; `tech-debt` and
   `check-guardrails` both carry it.
5. `AGENTS.md` §Searching the estate states the measured numbers (not adjectives) for both traps,
   and the Non-negotiables list points at it.
6. `mypy` is clean over `project/scripts/estate_search.py`.

## Status notes

**2026-09-20 — AC1-AC4 built and verified; AC5-AC7 filed.**

🔬 **The tool reproduced the defect it was written to catch, twice, before it was right.** ① The
first benchmark had no per-command timeout and no unbuffered output: it ran past 600s and left an
**empty** output file — a measurement with no bound and no visible progress, which is the symptom
itself. ② The first version of `estate_search.py` applied its generated-file exclusions to the
working-tree search and **not** to the history search, so history results grew with the depth bound
rather than with the code. Both are now probes.

⚠️ **A third trap, hit while registering the suite.** `project/test-suites.json` is **mixed** —
some `reason` strings carry a raw em dash, others a `—` escape. `json.dumps(ensure_ascii=False)`
rewrote 94 unrelated lines; `ensure_ascii=True` rewrote 48 different ones. No dumper flag reproduces
the file. It was inserted as **text**, parse-checked before writing — the rule
`tickets_frontmatter_sync.py` already records for ticket frontmatter, now known to apply here too.
