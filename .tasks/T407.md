# T407 — The deploy gate's own documentation describes a rule it stopped enforcing 34 days ago

## Summary

During the 2026-09-19 `deploy-all` that restored production, the gate printed:

    ✅ confirm: db-migrate — covered by `deploy-all` (expires in 2697s, HEAD 51e28ad5)

`db-migrate` did not re-prompt. It passed on the root consent granted for `deploy-all`.

`confirm_step.py`'s docstring says that cannot happen, and attributes the rule to an explicit owner
requirement — *"option to confirm only specific steps like migrations"* — naming `db-migrate` as
**the** motivating example for the `always_confirm` carve-out.

🔑 **The prose is the drifted side, not the data.** `confirm-policy.json` →
`_notes.one_yes_is_the_decision` records an owner decision dated **2026-08-16**, six days *after*
the docstring's 2026-08-10 spec: *"one yes from human should be enough here."* It states the owner
was shown the trade-off, was **offered the chance to put `db-migrate` and `sync-secrets` back and
declined**, and it instructs readers **not to "restore" the carve-out as a fix for something else**.
`test_confirm_step.py` already pins that behaviour, with a comment saying the assertion was
deliberately inverted and that re-adding the step "reverses a decision rather than fixing a bug".

⇒ So the fix is to correct the prose, not the policy ([[AgDR-0024]]).

## Why this is the estate's signature defect class, turned inward

Every behavioural probe was green throughout. The gate did exactly what it was configured to do.
What was wrong was its **description of itself** — and that is worse than a red test, because a
reader with no reason to doubt the docstring concludes a schema write is gated when it is not.
This is the gate-that-reads-as-protection shape (cf. [[T161]]), applied to the module written to
prevent it, and it is the measurement-trap pattern: the audit tool commits the defect it hunts.

Tonight was benign only by luck: `db-migrate` reported `0 pending / Remote database is up to date`,
so one root `yes` authorised a live schema write that happened to write nothing.

## It is a PATTERN, not a one-off — 10 claims, 4 surfaces, 2 repos

All trace to the 2026-08-16 change, which updated the JSON's own `_notes` and the test, and
**nothing else**.

## Acceptance criteria

- [x] AC1 — The decision is recorded rather than silently taken: [[AgDR-0024]], naming the rejected
      option (a) and why. ⚠️ **The owner was asked in-session and did not answer**; the recorded
      2026-08-16 decision was therefore treated as standing, and the AgDR says so explicitly rather
      than implying fresh sign-off. Option (a) — re-adding `db-migrate` to `always_confirm` —
      remains available as an owner call and is **not** closed by this ticket.
- [x] AC2 — All 10 claims corrected across the 4 surfaces, in both repos. The corrections state the
      superseding decision and point at `_notes.one_yes_is_the_decision`, so the next reader finds
      the reasoning rather than just a changed sentence.
- [x] AC3 — A **derived** check pins prose to data, in BOTH directions: a step described as
      re-prompting must be in `always_confirm`; a step described as riding the root consent must
      not be. Plus the consent TTL and the advertised probe count. One-way checks pass the day the
      policy flips, which is exactly the flip that happened here.
- [x] AC4 — Proven RED by mutation, not assumed: the checker is shown to flag each exact sentence
      this ticket removed (the carve-out claim, the table row with no sentence punctuation, the
      15-minute TTL), to flag the **inverse** drift, and to stay SILENT on the replacements. A
      detector that also flags the fix is unusable; one that flags nothing is decorative.
- [x] AC5 — **Unmeasurable is its own state, and it fails.** A surface that cannot be read, or
      whose extractor matches no prose region, reports `UNMEASURABLE` and FAILS rather than
      returning "agrees" on zero bytes. 🔴 Not hypothetical: `justfile` is a symlink into the
      `wom7api` repo, so in a detached worktree it resolves to nothing — the first version of this
      check went green there having read no bytes at all, and two probes now guard that branch.
      ⚠️ Consequence accepted: the suite is RED in any checkout where that symlink does not
      resolve. Fail closed beats a green that means nothing.
- [x] AC6 — **30/30 green**, proven against the REAL `wom7api/justfile`. Landed in `beta` under
      `6cf968dfa` (`wom7web`) and `52f90a0` (`wom7api`). Verified in the canonical checkout with
      all 30/30 green probes passing.

## Definition of Done

T407 is done when:
1. `python3 project/scripts/tests/test_confirm_step.py` reports **30 passed, 0 failed**, run against
   the real `wom7api/justfile` and `project/confirm-policy.json` — not a fixture.
2. Every surface describing the gate agrees with `confirm-policy.json` as DATA: the TTL reads 45 min
   (`ttl_seconds: 2700`), `always_confirm` is listed from the file rather than from memory, and no
   surface claims `db-migrate` re-prompts inside an agreed root.
3. The prose↔data check fails in **both** directions when mutated — a corrected sentence put back
   reddens it, and a surface that cannot be read is reported `UNMEASURABLE` and **fails** rather
   than passing on zero bytes.
4. The decision is recorded as [[AgDR-0024]] with the rejected option named (change the policy to
   match the prose), and `docs/DECISIONS.md` indexes it.
5. The change touches prose and checks only: `confirm-policy.json`'s `always_confirm` and `roots`
   lists are byte-identical to their pre-T407 values, because the gate's behaviour was never wrong.
