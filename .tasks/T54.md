## Summary

**Smart identity "Me" widget — multi-role + project-scoped hats** (UI/UX research + plan — owner 2026-07-16) — the flat role string can't express "same role scoped to many resources" (PM/**Questmaster** on projects A/B/C). Target IA (owner): the global **Me/Auth widget = logout + role-scoped portal links ONLY**; the **in-portal side menu = the roles/hats/mappings list** (incl. project-scoped hats + active-hat switch, context-local). Needs `resource_grants` (rbac-capability-model change) + extend active-hat to `role@resource`; deep UI/UX pass (workspace-switcher patterns) + DS-conformant component (RoleSwitcher is a T42 native-`<select>` offender). Supersedes the ad-hoc "remove logout from widget" thread.

## Acceptance criteria

- [x] AC1 — Header "Me" / AuthWidget IA separation: The global header `AuthWidget` dropdown is scoped strictly to account identity info, logout, and role-scoped portal launcher links, decoupling global header chrome from in-portal hat-switching.
- [x] AC2 — Portal Sidebar Hat Switcher with project scoping: The CP portal sidebar provides the primary context-local hat switcher, displaying both global roles and project-scoped delivery roles (`role@project` from `project_roles` and `public.hats`).
- [x] AC3 — Multi-project role resolution & switching API: Backend API (`/api/auth/switch-role` and `/api/project/hats`) supports activating a project-scoped hat (`project_role_id` + `project_id`), minting the session context so `wom_active_role` and active project context are reflected in JWT claims and locals.
- [x] AC4 — Ambient active-hat & project indicator: When acting under a project-scoped or non-admin hat, the portal viewport renders a persistent ambient status indicator stating the active role and project title, with an immediate 1-click exit control.
- [x] AC5 — Native `<select>` elimination in AdminLayout: The legacy native `<select>` `RoleSwitcher.svelte` is removed from the `AdminLayout.astro` header, replaced by unified design-system conformant identity and hat controls.
- [x] AC6 — E2E multi-role switching verification: Verified in a real browser session that a user holding multiple project roles (e.g. PM/Questmaster on Project A, Tech Lead on Project B) can switch between project scopes in the sidebar, observe the ambient indicator update, and have access properly scoped.

## Definition of Done

T54 is done when: the header `AuthWidget` shows only identity/logout/portal-launcher
links (no hat-switching), the portal sidebar is the one place a project-scoped hat
(`role@project` from `project_roles`/`public.hats`) is switched, `/api/auth/switch-role`
and `/api/project/hats` mint a session whose JWT claims and locals carry the new
`wom_active_role` + project context, an ambient indicator names the active role/project
with a 1-click exit whenever it isn't the default admin hat, `RoleSwitcher.svelte`'s
native `<select>` is gone from `AdminLayout.astro`, and a real multi-project user (e.g.
PM on Project A, Tech Lead on Project B) is observed switching between them in a browser
with access scoped correctly both times.
