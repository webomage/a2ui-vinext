# T185 — spec backfill for the 144 ticketed changes that have none

## Summary

Owner direction, 2026-08-08: *"let's restore specs for tickets without it"*, scoped explicitly to
**all 144, including the 37 done**.

⚠️ **"Restore" is the wrong verb and the ticket should say so once, plainly: nothing was lost.**
No rule ever required a spec, so this is **authoring 144 new specs**, not recovering them. That
matters for how the work is judged — there is no prior artifact to compare against, and a spec
written from shipped code cannot be validated by asking whether the code matches it.

## 🔴 The finding underneath the ask

Surfaced at [[T96]]'s archive gate. **There is no rule stating when a ticket requires a spec** —
verified absent from `.w0m/sdlc.json`, `openspec/SPEC-AUTHORING-STANDARD.md` (which governs *how* to
write a requirement block, not *whether* one is owed) and the `w0m-sdlc-spec` skill. The lifecycle
lists `spec` as a stage with no applicability criterion.

Meanwhile `project/templates/ticket.md` ships *"spec verified (`openspec-verify-change`)"* in the
Definition of Done of **every** ticket. ⇒ **144 tickets carry a DoD clause they have never met**,
and 37 of them were archived anyway. Filed as **D38**.

🔑 **The backfill and the rule are separable, and only one of them is durable.** Backfilling makes
the clause true *today*; without a rule, ticket 181 reopens the gap. Both are in scope here.

## ⚠️ The honesty constraint (non-negotiable, and the reason this is not a bulk job)

A retroactive spec **records** a contract; it did not govern one. Two failure modes to refuse:

1. **Generated filler.** [[T96]]'s own header warns that a generated *"observable outcome 1"* reads
   as though someone thought about it. A spec whose scenarios restate the AC in different words adds
   a file and no information.
2. **False provenance.** An archived change implies it was proposed, validated, then built. Each
   backfilled proposal MUST state its real dates up front — capability shipped, ticket filed, spec
   authored — as T96's does.

⇒ **Batches with real authoring, not a generator.** The 144 are not equal: a tooling ticket may
warrant 3 requirements, an RBAC redesign 15.


## 🔬 AC coverage measured 2026-08-13 (owner: *"we should master all our tickets to have ACs"*)

The board's *"N open tickets have NO acceptance criteria"* was **27**. Decomposed, it is almost
entirely honest — and the one error was in the board's favour, not against it.

| | count | what it actually is |
|---|---:|---|
| 🟡 **false negative — real ACs, wrong naming** | **1** | **T66** carried **7 well-formed criteria** that were simply not prefixed `AC<n>`. The counter's regex is `^\s*-\s*\[[ xX~]\]\s*\*{0,2}AC\d`, so a criterion must literally begin `AC1`. **Fixed** — prefixed `AC1..AC7`; the board moved **27 → 26** and measurable **122 → 123**. |
| 🔵 **honest placeholder** | **21** | each carries the template's literal `- [ ] **Not yet written.** Derive them from the Summary above via w0m-sdlc-spec`. ⇒ **These are not missing criteria hidden by a bad count — they are missing criteria DECLARING themselves.** The convention is working. |
| 🔴 **nothing at all** | **5** | `T69` `T70` `T72` `T74` `T76` — no checkbox of any kind, 7-13 lines each |

⇒ **26 tickets genuinely need acceptance criteria authored, and that is real work, not a renaming
pass.** My first scan counted *any* checkbox and reported **5**, which would have understated the
job by 5×; the board was right and the naive measurement was wrong.

🔑 **The 21 placeholders are the useful finding.** They are not a backlog of neglect — they are
tickets filed correctly by `w0m-sdlc-new`, which writes that line deliberately so an unspecced
ticket cannot masquerade as a specced one. The declared path to close them is **`w0m-sdlc-spec`**,
one ticket at a time, which is the same gate this ticket exists to run.
⚠️ **Do not bulk-generate ACs to make the number go down.** An AC that was invented to satisfy a
counter is worse than a placeholder that admits nothing is there — the placeholder at least fails
honestly, which is the whole reason the count was nearly right.

## Acceptance criteria

- [ ] **AC1 — a written rule for when a spec is required**, recorded in `.w0m/sdlc.json` (not only
      in prose), naming the change classes that owe one (e.g. external behaviour, UI surface,
      schema/RLS, public contract) and those that do not (internal tooling, doc-only, chores).
      🔴 **This AC is what stops the gap reopening** and must land before the backfill is called done,
      or T186 will have no spec for the same reason T96 had none.
- [ ] **AC2 — the DoD clause becomes conditional or verifiable.** `project/templates/ticket.md` stops
      asserting `spec verified` unconditionally; it either cites AC1's rule or the gate enforces it.
      Pays down **D38**.
- [ ] **AC3 — all 144 tickets carry a `spec:` pointing at a real change directory**, each validating
      `openspec validate <name> --type change --strict` clean.
- [ ] **AC4 — every backfilled proposal states its provenance dates** (shipped / filed / authored) in
      its first paragraph. A spot-check of any 10 finds 10 compliant.
- [ ] **AC5 — no spec is filler.** Every requirement traces to ≥1 ticket AC and every ticket AC is
      covered by ≥1 requirement, per the `w0m-sdlc-spec` cross-check. 🔴 **Measured by sampling, not
      asserted:** a review of 10 random backfilled specs finds none whose scenarios merely restate
      their AC.
- [ ] **AC6 — progress is visible while the programme runs.** A count of specced-vs-total is
      reported by an existing surface (`just tasks` or the audit sweep), so a half-finished backfill
      is not indistinguishable from a finished one.
- [ ] **AC7 — the `done` 37 are marked as retroactive records**, distinguishable from specs that
      governed their build — otherwise the archive silently gains 37 documents implying a design
      gate that never ran.

## Definition of Done

- AC1's rule exists and is machine-readable; AC2 has paid down D38.
- 144 tickets carry validating specs; the 37 retroactive ones are labelled as such.
- A sampled review finds no filler.
