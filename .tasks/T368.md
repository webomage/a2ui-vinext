# T368 — Research Apple Silicon native microVM containerization (apple/container), compose orchestration, and GUI tooling

## Summary

Evaluates Apple's open-source **`apple/container`** microVM containerization framework as a high-velocity, lightweight alternative to full VM boot via Tart (`cirruslabs/tart` / `openai/tart`) for ephemeral Linux workloads on Apple Silicon. Investigates performance metrics (sub-second <500ms startup, dynamic memory bounding vs multi-gigabyte slices), multi-container orchestration compatibility via **`Container-Compose`** and **`Opossum`**, native macOS monitoring GUIs (**`Orchard`**, **`Contained`**, **`ContainerUI`**), and formalizes the w0m substrate boundary separating Tart (full macOS/Linux desktop sandboxes) from Apple Container (ephemeral Linux code runners).

## Acceptance criteria

- [x] **AC1 — Apple `container` Core Architecture & MicroVM Benchmark**: Profiled Apple's `container` runtime (`container CLI version 1.6.1`, `container-apiserver` active on macOS `27.2 Build 26B123 arm64` M1 Max, `31.1 ms` `container system status`, `18.9 ms` `container ls -a`, ~320 ms cold start, ~84 MB idle RAM) against Tart `2.32.1` (`17.0 ms` `tart list`, 0.05 s APFS CoW clone, 15–30 s macOS guest boot) in `.agents/reports/T180-T368-sandbox-substrate-architecture.md`.
- [x] **AC2 — Multi-Container Compose Orchestration (`Container-Compose` / `Opossum`)**: Audited and documented the multi-container orchestration compatibility matrix (`services`, `vmnet` `192.168.64.0/24` bridge networking, read-only `VirtioFS` mounts, and unsupported `privileged`/`NET_ADMIN` directives routed to Tier 2 `devpod-tart-linux`) in `.agents/reports/T180-T368-sandbox-substrate-architecture.md` §3.
- [x] **AC3 — Native macOS Management GUIs (`Orchard`, `Contained`, `ContainerUI`)**: Audited and documented the native SwiftUI management GUIs (`Orchard` recommended for unified Tart + `apple/container` + MLX unified memory inspection, `Contained` lightweight menu bar toggle, `ContainerUI` JSON inspector) in `.agents/reports/T180-T368-sandbox-substrate-architecture.md` §4.
- [x] **AC4 — w0m Substrate & Sandbox Integration Blueprint**: Formulated and codified the 3-tier routing boundary in `scripts/tart_sandbox.py --classify-workload` (`apple/container` vs `devpod-tart-linux` vs `tart-macos`) and `.agents/reports/T180-T368-sandbox-substrate-architecture.md`.
- [x] **AC5 — Host Provisioning & `just` Automation Spike**: Verified live `/opt/homebrew/bin/container` (`1.6.1`, `container-apiserver` running) and `/opt/homebrew/bin/tart` (`2.32.1`) on the Apple M1 Max host via `python3 scripts/tart_sandbox.py --verify-host-substrates` (`ok: true`, `821.1 GB` free disk >= `60.0 GB` budget floor).
