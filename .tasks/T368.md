# T368 — Research Apple Silicon native microVM containerization (apple/container), compose orchestration, and GUI tooling

## Summary

Evaluates Apple's open-source **`apple/container`** microVM containerization framework as a high-velocity, lightweight alternative to full VM boot via Tart (`cirruslabs/tart` / `openai/tart`) for ephemeral Linux workloads on Apple Silicon. Investigates performance metrics (sub-second <500ms startup, dynamic memory bounding vs multi-gigabyte slices), multi-container orchestration compatibility via **`Container-Compose`** and **`Opossum`**, native macOS monitoring GUIs (**`Orchard`**, **`Contained`**, **`ContainerUI`**), and formalizes the w0m substrate boundary separating Tart (full macOS/Linux desktop sandboxes) from Apple Container (ephemeral Linux code runners).

## Acceptance criteria

- [ ] **AC1 — Apple `container` Core Architecture & MicroVM Benchmark**: Profile Apple's `container` runtime (`apple/container`) against Tart VM execution (`w0m-bridgeroad` / Ubuntu baseline). Measure cold-start spinup latency (<500ms target), idle RAM consumption (~60–120MB vs multi-GB Tart slice), VirtioFS throughput, and Linux-only constraint boundary.
- [ ] **AC2 — Multi-Container Compose Orchestration (`Container-Compose` / `Opossum`)**: Evaluate `Container-Compose` (by Mcrich23) and `Opossum` for parsing `docker-compose.yml` topologies on top of Apple's microVM-per-container model. Document service networking (`vmnet`), port mapping, volume binding parity, and unsupported compose directives.
- [ ] **AC3 — Native macOS Management GUIs (`Orchard`, `Contained`, `ContainerUI`)**: Audit and test native macOS menu bar and windowed management applications (`Orchard`, `Contained`, `ContainerUI`) for container lifecycle observation, live log streaming, image inspection, and Apple Silicon MLX GPU bridge integration.
- [ ] **AC4 — w0m Substrate & Sandbox Integration Blueprint**: Formulate the architectural boundary defining when w0m tasks route to Apple `container` (ephemeral single-run Linux code execution, polyglot SAST, test jobs) vs Tart VMs (full macOS sandboxes, Xcode/iOS simulators, persistent GUI workspaces per [[T296]], [[T297]]).
- [ ] **AC5 — Host Provisioning & `just` Automation Spike**: Specify host installation recipes (`brew install container`, launchd daemon lifecycle), verify sandbox isolation against host file tampering, and evaluate potential `just container` or `just sandbox-run` wrappers for `project/stacks-policy.json`.
