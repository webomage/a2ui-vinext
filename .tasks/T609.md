# T609 — Declarative hat/role permissions & UI visibility schema, PM Knowledge Hub Worker bundling, Linux obsidian:// handler, and multi-agent provider abstraction

## Summary

Resolves live Control Plane, Knowledge Hub, Obsidian URI, and Orca multi-agent automation regressions surfaced on `cp.webomage.com` and the Linux primary workstation:

1. **Worn-Hat Capability Scoping & Real-Time `SideNav` Sync (`AC1`)**: Wearing `Tech Lead` (`tl`), `PM` (`pm`), or `Dev` (`dev`) on `/o/webomage` previously leaked `MONEY → Invoices` (`invoice.view`) and `SALES → Blueprints` (`blueprint.publish`) because `wom_context_capabilities` unions all active hats held by the profile. Narrow `Held.catalog` in `org` and `project` contexts by intersecting DB-verified `row.capabilities` with the worn hat's allowed capability set, and sync `SideNav` sections in real time in `CpShell.svelte` when switching hats.
2. **PM-Side Knowledge Hub Documentation on Cloudflare Workers & Project Routes (`AC2`)**:
   - Replaced `(import.meta as any).glob(...)` in `apps/cp/src/lib/vault-reader.ts` with literal `import.meta.glob(...)` so Vite statically bundles all `projects/*/vault/**/*.md` files into the Cloudflare Worker chunk (`workerd`).
   - Updated the PM (`!clientSide`) branch of `apps/cp/src/pages/o/[org]/projects/vault.astro` to query Supabase `project_vaults` + `vault_notes` merged with bundled local notes via `loadStaffProjectVaultAndNotes()`, and mounted `<KnowledgeHub />` on `apps/cp/src/pages/o/[org]/p/[project]/vault.astro`.
3. **Cross-Platform `open_vault.py`, Linux `obsidian://` URI Handler & Shell TTY Auto-Repair (`AC3`)**:
   - Updated `w0m-api/scripts/open_vault.py` to support Linux (`~/.config/obsidian/obsidian.json` + `xdg-open`) alongside macOS, and create named vault symlinks (`~/.w0m/vaults/<slug>`) so `obsidian://open?vault=<slug>&file=<note>` resolves by `<slug>` (`w0m`, `1945`, `artemio`, `servicios777`, `personaje0`) instead of folder basename `vault`.
   - Installed `~/.local/share/applications/obsidian.desktop` + `~/.local/bin/w0m-obsidian-uri` on the Linux workstation and added `_repair_tty_state` `PROMPT_COMMAND` recovery to `~/.bashrc`.
4. **JSON-Schema-Governed Hat/Role Permissions & UI Feature Visibility SSOT (`AC4`)**:
   - Authored `packages/lib/src/auth/hat-visibility-policy.schema.json`, `hat-visibility-policy.json`, and `hat-visibility.ts` (`canSeeUiFeature`, `canSeeCommercialAmounts`, `visibleFeaturesForHat`) covering all 14 platform, unit office (`finance`, `growth`, `recruiting`), delivery (`pm`, `tl`, `dev`, `devops`, `qa`, `design`, `client`), and training (`trainer`, `trainee`) hats (`AgDR-0028`, `AgDR-0020`), with automated parity tests against `apps/cp/src/lib/context/nav.ts`.
   - Wired `canSeeUiFeature` into `KnowledgeHub.svelte` and both `vault.astro` routes (`vault.open_in_obsidian`, `vault.r2_mobile_sync`, `vault.r2_push`, `vault.staff_search`).
5. **Multi-Agent CLI & Orca Provider Abstraction (`AC5`)**:
   - Created `scripts/agent_provider.py` (`resolve_agent_provider`, `resolve_orca_bin`, `build_agent_resume_command`) and eliminated hardcoded `provider="claude"` / `agy` assumptions in `scripts/w0m_prs.py`, `scripts/t171_sandbox_cohort_runner.py`, and `scripts/orca_sessions.py`, updating the live `w0m Upstream PRs & Fork Branches Monitor` Orca automation to `antigravity`.
