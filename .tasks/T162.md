# T162 — Headroom: measured, deployed, and governed

## Summary

Owner ask 2026-08-03: *"can we add this solution to use it in Claude Code App we are using now?"*
— [headroomlabs-ai/headroom](https://github.com/headroomlabs-ai/headroom), `headroom-ai` 0.33.0, a
context-compression proxy for Claude Code.

**It was measured before it was adopted, and the measurement did not support the claim.** A
warm-vs-warm A/B (same prompt, same repo, `claude -p --output-format json`) showed Headroom's own
counters reporting `total_tokens_removed: 0` and `tokens_saved_by_strategy: {}` across 11 real
requests, while imposing +57% wall clock, ~2× turns and +36% output tokens. The apparent −6.7% cost
delta is agent nondeterminism at n=1/arm (the two arms took 6 vs 11 turns), not compression.

🔴 **The headline savings figure is Anthropic's prompt cache re-badged.** `headroom savings`
reported `savings_total_tokens: 99864`, which is exactly `cache_read_tokens: 324562 × the 90% read
discount it reports itself` — a discount that accrues with or without the proxy. Anyone running
`headroom savings` after a session and reading "99,864 tokens saved" would conclude it was working.

**Root cause is structural, not a misconfiguration.** `--mode cache` is documented as "delta-only
compression at ~0 prefix-cache busts". On Claude Code work the bulk of input *is* the cacheable
prefix (442k of 508k input tokens were cache reads, already 90% discounted), so cache-safe mode has
almost nothing left to compress — and raising aggression destroys the 90% discount instead. The two
mechanisms fight each other, and Anthropic's native cache already captures the win being sold.

**Owner deployed it anyway on 2026-08-03 after seeing the above.** That is a legitimate call — this
ticket's job is not to relitigate it but to make sure the thing is *governed*: provisioned
reproducibly, gated, and unable to flatter itself in a report.

## 🎯 The actual value is the two read-only analyzers, not the proxy

`headroom audit-reads` over **309 real sessions** found **Bash is 57.5% of tool_result bytes vs
Read's 34.3%** — so a Read-compressor targets the minority. The biggest single class is
**"stale (edit after read)" = 1120 calls / 6.0 MB / ~1.49M tokens = 46.4% of Read bytes**, which is
a *workflow* defect, not a compression one. `headroom learn` over 133 sessions / 15,884 calls /
1,011 failures (6.4%) produced 7 grounded recommendations and independently rediscovered the pyenv
`timeout` shim trap — a good credibility signal for the analyzer even though the proxy did not earn
its keep.

## Acceptance criteria

- [x] AC1 ✅ **Measured before adopting, and the measurement was allowed to say no.** Warm-vs-warm
      A/B recorded in full (direct 508,015 input / 40.1s / $0.559 vs headroom 456,409 / 62.8s /
      $0.522), plus Headroom's self-contradicting counters (`summary.requests_compressed: 0` vs
      `compressions_by_strategy: {"tabular":1,"text":1}`). Scope caveat kept with the result: one
      task, one repo, one sample per arm — enough to show the claimed win did not appear and the
      overhead did, not a broad benchmark.
- [x] AC2 ✅ **The status surface refuses to launder the prompt-cache discount.**
      `just headroom-status` prints the two numbers as distinct facts —
      `headroom compression: 0 tok over 2 req | anthropic prefix cache: 13,386 read tok (NOT
      headroom's)`. This is the anti-flattery requirement: the tool's own dashboard conflates them,
      so ours must not.
- [x] AC3 ✅ **Provisioning is a script encoding all four traps, not a justfile blob.**
      `project/scripts/headroom_bootstrap.py` (279 lines), house three-mode convention matching
      `discovery.py` / `deps_sync.py`: advisory (exit 0) · `--enforce` (exit 1 on FAIL) · `--apply`
      (provision then re-check) · `--json`. The four traps, each hit once the hard way:
      1. `install apply --providers auto` **aborts the whole deployment** on the retired **openclaw**
         binary still at `/opt/homebrew/bin` → must be `--providers manual --target claude`.
      2. `--memory` leaves the backend `initialized: false` → pins `/readyz` at **503** → makes
         `install apply` fail outright. Never passed.
      3. Headroom **silently installs serena** as its code-memory MCP, and serena refuses to boot
         without a `projects` key in `~/.serena/serena_config.yml`.
      4. A custom `ANTHROPIC_BASE_URL` silently disables on-demand tool loading (#746) **and** the
         1M context window (#1158).
- [x] AC4 ✅ **Proven RED, live, not asserted.** Re-verified 2026-08-04 by mutating the real
      `~/.claude/settings.json` and restoring it:
      · 🔴 **RED** — routed with `ENABLE_TOOL_SEARCH` removed → **rc=1**,
        `❌ tool-search  ENABLE_TOOL_SEARCH=<unset> — every tool schema will eager-load (#746)`.
      · 🟢 **GREEN** — restored → rc=0.
      ⚠️ **Routing-unset is a WARN, not a FAIL, and that is deliberate** — `required: false` means
      "no routing" is a safe state, not a broken one; the `#746` check is nested under `if routed`
      because eager-loading cannot happen when nothing is routed. Missing `settings.json` entirely
      *is* a FAIL (`headroom_bootstrap.py:186`).
- [x] AC5 ✅ **`just` surface, per the [[T130]] contract** — `headroom-status`, `headroom-bootstrap`
      (idempotent, mirrors the `gh-w0m` provision-then-prove pattern), `headroom-audit`,
      `headroom-learn`, `headroom-learn-apply`, `headroom-doctor` (raw upstream escape hatch).
      `just discovery` stays green — 8 stacks, every declared command binds a real recipe.
- [x] AC6 ✅ **`learn --apply` is pinned to `CLAUDE.local.md`.** A bare `headroom learn --apply`
      also targets the agent memory index (`~/.claude/projects/*/memory/MEMORY.md`) and would
      **rewrite it wholesale**. The recipe hardcodes `--target CLAUDE.local.md`; the reason is
      written above the recipe so it cannot be "simplified" away.
- [x] AC7 ✅ **Declared `required: false` on purpose** in `project/tools-policy.json`, with the
      measurement and all four traps in the `note`. `just tools-check` → `headroom [opt] ✓ 0.33.0`.
      Declaring it `required` would make a tool that demonstrably saves nothing into a gate on
      everyone else's work.
- [x] AC8 ✅ **`/headroom` slash command** (`.claude/commands/headroom.md`, 85 lines) routing
      `status|bootstrap|audit|learn` to the matching recipe, with a writes?/costs-tokens? table —
      two of the four surfaces write and two cost tokens, so blind pass-through was not acceptable.
      Carries the AC2 warning inline: **never quote the headline figure as a compression saving.**

- [x] AC9 ✅ **`observed` — the check that the rest of this ticket was missing.** Added 2026-08-04
      after the owner asked *"are we working via headroom?"* and the honest answer turned out to be
      **no**, while `just headroom-status` and `headroom doctor` both showed routing green.
      🔴 **AC2 policed the savings NUMBER and never questioned the routing CLAIM.** `routing` proved
      only that `ANTHROPIC_BASE_URL` was written into `settings.json` — a check that looks where it
      already knows to look, the estate's most-repeated defect, shipped fresh in the very script
      whose docstring says "NO VACUOUS GREEN".
      **The evidence that broke it:** the proxy had served **27 lifetime requests, all
      `claude-sonnet-5`**, while the live session was **Opus 5** — so not one request had ever come
      from it. Root cause: the caller's own environment carried
      `ANTHROPIC_BASE_URL=https://api.anthropic.com`, which **wins over `settings.json`**. Config
      and behaviour disagreed and nothing in the tool could tell.
      **Fix:** `routing` → **`routing cfg`** (labelled config-only), plus two real checks —
      **`caller env`** (does *this* process's env actually point at the proxy?) and **`observed`**
      (has the proxy ever served a request, and for which models?).
      **Proven both directions:** `caller env` flips PASS when run with the var pointed at the proxy;
      `observed` returns **FAIL** on zero-lifetime-traffic *and* on an unreachable `/stats`, PASS on
      real traffic. ⚠️ **Unreachable is a FAIL, not a WARN** — "cannot confirm" is not "fine".
      **Independently confirmed the proxy itself works**: two live `claude -p` calls moved the
      counter 2→3 (explicit env) and 3→4 (`settings.json` alone, harness var unset), so the config
      is genuinely effective for any client that does not override it.

- [x] AC10 ✅ **`just headroom-task` — the only Headroom-routed agent obtainable from the desktop
      app.** Added 2026-08-04 answering *"can we spawn Claude Code tasks with Headroom integrated?"*
      🔴 **Subagents do NOT route, and this is the trap worth writing down.** The in-app `Agent`
      tool runs inside the app's own engine, which is spawned with a pinned
      `ANTHROPIC_BASE_URL=https://api.anthropic.com` — so a subagent inherits the bypass. **Measured:
      a subagent that burned 48,499 tokens moved the proxy counter by ZERO (29 → 29).** A subprocess
      `claude -p` is a *fresh process* and therefore can take the proxy URL; that is the whole
      mechanism.
      **Measured benefit — tool-schema deferral, and it is the first non-zero saving Headroom has
      produced here:** in `@wom` (~200 MCP tools), **~11k tokens/request** on top of Claude Code's
      own `ENABLE_TOOL_SEARCH`, and **~103k tokens/request** when the client has no tool search
      (`tool_search` layer went 55,480 → 158,367 on a single `ENABLE_TOOL_SEARCH=0` run). ⚠️ The
      honest marginal figure is **~11k**, not 103k — Claude Code already defers natively for free,
      so 103k is the saving versus a *misconfigured* client, not versus a correct one. Compression
      remains **0 tokens** and always has been.
      **Anti-vacuous-green by construction:** the recipe prints the proxy request counter
      **before → after** and states whether the task routed, so a run that silently bypassed the
      proxy is visible instead of assumed. Both branches proven (`before == after` → warn;
      `before != after` → ok), plus a health guard that exits 1 **before spending tokens** if the
      proxy is down.
      ⚠️ Runs from the **workspace root (`@wom`)**, not `wom7api/` — the first version inherited
      `just`'s justfile-directory cwd and answered a question about `TECH-DEBT.md` with "it doesn't
      exist", which is true in `wom7api/` and useless as an answer.

## Deployed state (verified 2026-08-04)

launchd daemon `com.headroom.default` (`KeepAlive` + `RunAtLoad`, so a dead port cannot brick the
app) + routing in `~/.claude/settings.json` `env`. `just headroom-status` → **0 failures, 2
warnings**, both warnings intentional and reported rather than silently accepted.

## ⚠️ Open / accepted, NOT closed by this ticket

- 🔴 **`--memory` never initializes** (`backend: local, initialized: false` → `/readyz` 503) —
  likely the missing `sentence_transformers` semantic vector store. **Persistent / cross-agent
  memory is therefore NOT working**, and passing `--memory` fails the install outright.
- ⚠️ **1M context window is disabled behind the custom base URL** unless opted in (#1158). Reported
  as a WARN, not auto-enabled — it is the owner's call, and the fix (`--1m`) is printed with it.
- ⚠️ **`headroom init claude --global` exported the proxy URL machine-wide** into `~/.zshrc`,
  `~/.profile` **and** `~/.bashrc` — every shell, not just Claude Code. w0m blast radius checked at
  the time (only 3 files reference the Anthropic API, 2 of them Obsidian plugins → effectively nil),
  but **re-check before adding any shell-launched Anthropic caller.** `headroom-status` reports this
  every run so it cannot be forgotten.
- ⚠️ It also **registered and auto-enabled a plugin marketplace** pointing at `chopratejas/headroom`
  (redirects to headroomlabs-ai — transferred repo, same project) and added a Bash `PreToolUse` +
  `SessionStart` hook that re-assert its config. Unasked-for, left in place, recorded here.
- ⬜ **The 7 `learn` recommendations are not applied.** Top items: grep/sed `STATE.md`+`TASKS.md`
  instead of a full Read (~40k tok/session), `infisical run` instead of grep/cut/tr on `.env`
  (~25k tok/session), fresh-shell-per-Bash-call, and `w0m-sdlc-*` skills needing the
  directory-scoped prefix. Worth a follow-up ticket — and note the audit says the **stale
  (edit-after-read)** class is the single biggest win, which no proxy can fix.
