# T743 — Fix Stripe secret sync allowlist and Client Portal Stripe checkout headers/payloads

## Summary

End-to-end audit of Stripe keys and all five checkout flows uncovered four production blockers preventing Stripe checkout and billing portal sessions from succeeding reliably in Client Portal (`/o/[org]`) and Supabase Edge Functions:

1. `w0m-api/scripts/sync_supabase_secrets.py` omitted `STRIPE_SECRET_KEY` (already present in Infisical `beta`, `sk_test_…`, 107 chars) and `STRIPE_WEBHOOK_SECRET` from `keys_to_sync`, leaving Supabase Cloud (`pqbbjgeapylcengbuvee`) without `STRIPE_SECRET_KEY` (`500 Server missing environment configuration` / `503 Billing is not available`).
2. `w0m-web/apps/cp/src/components/client/ClientDashboard.svelte` (`triggerPortalPackageCheckout`) called `${supabaseUrl}/functions/v1/stripe-checkout` without `apikey` / `Authorization` headers (rejected `401` by Kong because `verify_jwt = true`), omitted `contact_email` and `service_title`, and silently swallowed non-OK HTTP responses without surfacing `wizardError`.
3. `w0m-api/supabase/functions/stripe-checkout/index.ts` and `_shared/stripe-billing.ts` did not fall back `contact_email`, `company_name`, or `repo_url` to the authenticated client's `orgs` record (`email`, `company_name`, `name`, `website`) or `authUser.email` when `type: "audit"` omitted those fields from the payload.
4. `w0m-web/apps/cp/src/components/client/SubscriptionManager.svelte` and `InvoiceList.svelte` omitted the `apikey` header on Supabase Edge Function payment requests.
