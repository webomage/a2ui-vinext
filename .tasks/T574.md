# T574 — Extension: auto-sync Webomage/Google browser session from `.webomage.com` cookies and wire Antigravity Bridge status to HTTPS/Realtime transport

## Summary

Observed 2026-10-26 while clipping a job posting (`https://builtin.com/job/senior-software-engineer-developer-experience/11853960`) with the Webomage Agent Chrome extension:
1. **Existing Google/Webomage login in another tab is not caught, and popup has no Google SSO action**:
   - Webomage web apps (`webomage.com`, `cp.webomage.com`, `job.webomage.com`) store the authenticated Supabase session in `httpOnly: true` `@supabase/ssr` chunked cookies (`sb-<ref>-auth-token`, `.0`, `.1`, … and `sb-access-token` / `sb-refresh-token`) on `.webomage.com`.
   - The extension's `supabaseService.ts` only checks `chrome.storage.local` (`ChromeStorageAdapter`), which is isolated inside `chrome-extension://<id>`, and `popup.html` only renders email + password inputs (`supabase.auth.signInWithPassword`).
2. **`"Anitgravity Bridge"` popup card is misspelled and stuck on `"Connecting..."`**:
   - `T220` / `AgDR-0039` retired the legacy `ws://localhost:8008` WebSocket relay (`mcp-bridge.js`) in favor of Layer 2 authenticated HTTPS (`POST /functions/v1/outreach-clip-ingest`) and the `T490` Supabase Realtime private `extension_commands` channel.
   - However, `popup.html` still displays `"Anitgravity Bridge"` (typo) and `popup.ts` sends `MCP_CONNECT`, which has no handler in `background.ts`, leaving the UI permanently stuck on orange `Connecting...` (`...`).

## Acceptance criteria

- [x] **AC1 — `.webomage.com` Cookie Session Auto-Sync (`manifestGenerator.ts`, `supabaseService.ts`)**:
  - Add `"cookies"` to `permissions` and `"https://webomage.com/*"`, `"https://*.webomage.com/*"` to `host_permissions` in `manifestGenerator.ts`.
  - Implement `parseSupabaseCookiesToSession(cookies)` and `syncSessionFromWebomageCookies()` in `supabaseService.ts` to reassemble chunked `@supabase/ssr` `sb-*-auth-token(.0..N)` (`base64-...`) cookies (and fallback `sb-access-token` / `sb-refresh-token` cookies), validate non-expired JWTs, persist to `chrome.storage.local` (`wom_supabase_session`), and hydrate the extension Supabase client automatically inside `getAuthenticatedSession()`.
- [x] **AC2 — Google / Webomage SSO Button & Live Cookie Listener (`popup.html`, `popup.ts`, `background.ts`, `messages.ts`)**:
  - Add a **"Continue with Google / Sync Webomage Login"** button (`#btn-login-google-sso`) in `popup.html` / `popup.ts` and handle `SUPABASE_SYNC_BROWSER_SESSION` in `background.ts`: if a `.webomage.com` cookie session exists, sign in immediately; otherwise open `https://cp.webomage.com/login` and auto-sync when `chrome.cookies.onChanged` detects `sb-*-auth-token*`.
  - Pass `Authorization: Bearer <session.access_token>` explicitly in `clipActiveTabToOutreachVault` (`outreach-clip-ingest`) so cookie-synced sessions authenticate edge function calls reliably.
- [x] **AC3 — Fix `"Antigravity Bridge"` Spelling & Wire Live HTTPS/Realtime Status (`popup.html`, `popup.ts`, `background.ts`, `mcpService.ts`)**:
  - Fix `"Anitgravity Bridge"` → `"Antigravity Bridge"` in `popup.html`.
  - Handle `MCP_GET_STATUS`, `MCP_CONNECT`, and `MCP_DISCONNECT` in `background.ts` / `mcpService.ts` so the Bridge card reflects the real Layer 2 HTTPS Cloud + `extension_commands` Realtime channel state (`status: "connected" | "disconnected" | "error"`) and clicking Connect/Sync refreshes the session & Realtime subscription instead of hanging on `Connecting...`.
- [x] **AC4 — Unit Tests & Built Extension Bundle**:
  - Add unit tests in `extension/src/__tests__/backgroundCommands.test.ts` and `extension/src/__tests__/crossBrowserManifest.test.ts` covering chunked `@supabase/ssr` cookie decoding, `SUPABASE_SYNC_BROWSER_SESSION`, `MCP_GET_STATUS` / `MCP_CONNECT` / `MCP_DISCONNECT`, and manifest permissions.
  - Rebuild `extension/dist/` (`pnpm run build:chrome`) and pass `pnpm test`, `pnpm run type-check`, and `oxlint` in `w0m-ext/extension`.
