# T64 — w0m + Dagger + Backstage Synergy Integration

## Summary

Draft and implement the integration architecture linking the w0m orchestrator (`wom7api`), TypeScript-based Dagger pipelines, and Backstage-modeled developer portal dashboard interfaces.

## Decision — 2026-07-24 (framework direction resolved)

**Decision record:** `../../docs/design/T64-sdlc-devops-framework-decision-2026-07-24.md`. Owner
reviewed the 30-platform research and chose: **Model B stays the baseline interface; Dagger and a
Backstage-*style* catalog are implementations *behind* `just`** — no CI/CD server, no Backstage
framework, no self-hosted forge. This **re-scopes the ACs below** and orders them **after [[T130]]**
(whose per-stack `stacks-policy.json` registry is the catalog's data model):

## Acceptance criteria

- [x] **AC1 — Dagger SDK (folds into AC3).** Install/configure `@dagger.io/dagger` in `wom7api`.
- [x] **AC3 (do first) — Dagger execution behind `just`.** A type-safe TypeScript Dagger pipeline
      replaces the **fragile bash** inside `deploy-all`, invoked by the existing `just deploy-all`
      recipe (`tsx dagger/…`, not bash) — Dagger is a recipe *implementation*, not a competing
      interface (compatible with [[T130]]'s "everything via `just`" rule + no-fragile-bash). Prove
      local-first parity + caching. **Start with the smallest fragile-bash blocks.**
- [x] **AC2 (do second) — Catalog in Backstage's entity standard, NOT the framework ([AgDR-0026]).** Every
      catalog item is a Backstage entity (`catalog-info.yaml`): repos and stacks → `Component`/`System`, MCP servers →
      `API` `spec.type: mcp-server`, skills → `AiResource` (or a `w0m.dev` custom kind), owners → `Group`/`User`;
      w0m facts as `w0m.dev/` annotations. Generated one-way from the existing registers ([[T130]] `stacks-policy.json`,
      `.w0m/sdlc.json`, `.w0m/skills.json`), with a drift gate. Validated by typed Python models against the pinned
      `@backstage/catalog-model` JSON Schemas ([[T448]]). Served read-only to the CP catalog view (Svelte) and over
      MCP from the same entity set.
- **Rejected/deferred:** self-hosted forge/CI (GitLab/Gitea/Drone/Argo) — rejected at this
      scale; Gitpod `.gitpod.yml` cloud dev-envs — deferred (optional onboarding polish).
