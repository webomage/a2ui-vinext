# T627 — Replace Bash `orca-overlay-update` with stdlib Python `scripts/orca_overlay_update.py` (fixing `EXIT` trap crash) and clean up `webomage` GitHub Actions workflows and run history

## Summary

1. **First live `webomage/orca@v1.4.249-w0m.1` release & replacement of Bash `orca-overlay-update` with Python**: After `webomage/orca` Actions was re-enabled and two first-run cloud quirks were fixed (`9d3acca4757` declaring `ORCA_RELEASE_REPO` in `src/shared/release-channel.ts` for `tsconfig.build.cli.json`, and `a1581002ad7` creating release tags via `gh release create --target beta` instead of `git push refs/tags/$TAG`), run `#41764577088` published `webomage/orca@v1.4.249-w0m.1`. Running `just orca-apply` verified SHA-512, backed up `orca-linux.AppImage.stock.bak`, and installed `orca-linux.AppImage`, then exited `1` (`line 1: workdir: unbound variable`) because the Bash script glued `gh` + `jq` + `local workdir` + `trap 'rm -rf "$workdir"' EXIT` + an embedded `python3 <<'PY'` snippet together under `set -euo pipefail`.
2. **Organization-wide `webomage/*` GitHub Actions noise & history cleanup**: Across all 33 `webomage` repositories, 10 repositories held `71` noisy/broken active `.github/workflows/*` workflows (inherited upstream fork crons/PR checks and broken cross-repo private CI checkouts) and `1,707` legacy/failed/cancelled runs.
