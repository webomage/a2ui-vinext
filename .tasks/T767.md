# T767 — Assert pinned security-hook revs == gate-binary versions

## Summary

T766 cost two failed deploys (releases 2026.11.17-1794956925 and
2026.11.17-1794964464) to a silent tool-version drift: each repo's
`.pre-commit-config.yaml` pinned `osv-scanner` at `rev: v2.4.0`, while
`check-guardrails` (`scripts/deploy_cert.py:358`) runs
`shutil.which("osv-scanner")` — the PATH binary, at that time v2.7.0.
The two disagreed on the SAME lockfile: v2.4.0 flagged the fixed
`webomage/picomatch` 2.x fork (advisory range `[0, last_affected 4.0.7]`
matches any 2.x declaration), v2.7.0 did not. The drift was invisible
to every gate until an owner deploy attempt failed on it, twice.

A pin is part of the vulnerability surface: whatever verdict the gate
binary renders must be reproducible by the hook pin, or commits pass on
different evidence than deploys fail on.

Fix: a small checker (`scripts/hook_pin_drift_check.py` at the root
repo) that for every security-scanner hook pinned estate-wide
(osv-scanner; optionally gitleaks) parses each
`.pre-commit-config.yaml` rev and compares it to the gate binary's
`--version` (major.minor; patch-level lag allowed, declared). Wire it
into `check-guardrails`' guardrails step (`deploy_cert.py`) so drifted
pins fail closed at pre-push and deploy time, with a per-repo mismatch
report. Do NOT auto-bump pins from the gate — the gate reports, the
human commits the bump (T112's raise-the-floor discipline).

## Acceptance criteria

- [ ] AC1 — `just hook-pin-check` (root) exits 0 with all pins aligned
      (post-T766 state: 7 repos at v2.7.0 == brew binary 2.7.0), and a
      red test proves exit non-zero when a pin is reverted to v2.4.0
      (fixture-based, no repo files touched).
- [ ] AC2 — The check runs inside `check-guardrails` (via
      `deploy_cert.py`), so `_deploy-all-chain` fails closed on drift
      before a release is cut; transcript output is zero-finding-clean
      for `audit_transcript`/`rx_harmless_trouble` (T734 lesson).
- [ ] AC3 — gitleaks (pinned `rev: v8.30.0`) covered by the same
      checker where a local binary is resolvable; repos without a
      resolvable gate binary for a hook are reported UNMEASURABLE, not
      silently passing.
- [ ] AC4 — `scripts/tests/test_hook_pin_drift_check.py` unit tests
      green; checker style aligned with `scripts/hooks_check.py`
      (same exit vocabulary: 0 conformant, 1 findings, 2 unmeasurable).

## Definition of Done

- Drift between any repo's security-hook pin and the actual gate
  binary now fails the pre-push guardrails gate with a named repo +
  rev; T766's failure mode (2 wasted owner deploys) is structurally
  impossible without an explicit UNMEASURABLE disclosure; ticket +
  TASKS.md in sync; tree landed; state-check green.
