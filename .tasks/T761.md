# T761 — Let an imported design system provide its own mono type specimen

## Summary

OpenDesign hardcodes the mono type specimen for every design-system kit view as
`'const brand = await extract(url);'`
(`apps/web/src/components/DesignKitView.tsx:1367`,
`{label === 'Mono' ? 'const brand = await extract(url);' : kit.name}`), measured
2026-11-17 on `webomage/open-design` branch
`fix/local-import-palette-fonts-logo` (verified identical on `upstream/main`).
Display/body specimens use `kit.name`, so mono is the only specimen a design
system cannot influence. The owner wants kit-authored, meaningful text instead
(filed as a follow-up to [[T759]] / upstream PR
`nexu-io/open-design#9500` — deliberately kept out of that PR's scope).

Fix in two halves:

- (**Upstream fork** → PR) Let the kit bundle declare its mono specimen:
  `import.ts` (`renderDesignMd`) copies an optional
  `mono_specimen:` frontmatter line from the source package's `DESIGN.md` into the
  synthesized DESIGN.md; `parseDesignMd` reads it; `parsedToKit` exposes
  `kit.monoSpecimen`; `DesignKitView` renders
  `kit.monoSpecimen ?? 'const brand = await extract(url);'` (default unchanged
  for systems that declare nothing).
- (**Estate** → registry sync) `w0m-web/design-system/DESIGN.md` gains
  `mono_specimen: "w0m deploy --prod && smoke-live green"` (owner-quote pending;
  final text to be confirmed during build) so the imported Webomage kit shows it.

Branch: `feat/kit-mono-specimen` on `webomage/open-design`, GPG-signed, body
Why / What users will see / Surface area / Validation, registered in
`scripts/w0m_prs.py` `CONTRIBUTION_PROPOSALS`, submitted via `just pr-auto`
(`AgDR-0058`).
