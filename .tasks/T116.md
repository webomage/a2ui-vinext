# T116 — Consolidate duplicated schemas/models into packages/lib

## Summary

The app-facing schema layer is **duplicated per-app** instead of shared. The DB itself is fine —
Supabase migrations (`wom7api/supabase/migrations`, 185 files) are the single source of truth, and
the generated `Database` types live in `packages/lib/src/supabase.ts`. But above that:

- **Zod models are byte-identical copies**: `apps/web/src/lib/models/{project,tech,unit}.ts` ===
  `apps/cp/src/lib/models/{project,tech,unit}.ts` (verified with `diff`). `packages/lib` has **no
  `models/` dir**, so there's no shared home — each app carries its own copy.
- **The Supabase type client is copied too**: `packages/lib/src/supabase.ts` (canonical) is also
  duplicated into `apps/web/src/lib/supabase.ts` + `apps/cp/src/lib/supabase.ts`.
- **Drizzle schema exists in two places**: `supabase/migrations/drizzle/schema.ts` +
  `supabase/functions/_shared/database/schema.ts`.

**Evidence it bites:** T115's Zod-v4 migration had to edit the *same three model files twice* (web +
cp). Miss one and they drift silently.

## Acceptance criteria

- [ ] AC1 — Shared Zod models live in `packages/lib` (e.g. `packages/lib/src/models/`), exported once
- [ ] AC2 — `apps/{web,cp}` import the shared models; the duplicated per-app copies are deleted
- [ ] AC3 — The Supabase `Database` type client is imported from `packages/lib`, not copied per app
- [ ] AC4 — Decide on the Drizzle schema duplication (single source or documented why two)
- [ ] AC5 — `astro check` clean for web+cp after the move; no behavior change (schemas are identical today)

## Notes

- Pure refactor — schemas are identical *today*, so this is a move+import, not a redesign. Do it
