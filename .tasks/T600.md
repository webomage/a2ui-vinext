# T600 — Fix CP SidebarHatSwitcher no-op dropdown, stop Project Hats resetting to Artemio, and compact ContextSwitcher multi-role subtitle

## Summary

Owner live UI review on `cp.webomage.com/o/webomage/projects` (2026-11-01) surfaced three UX and state-synchronization defects in the CP project hats and context switching surfaces:

1. **Sidebar `Project Hats ▼` Displays and Does Nothing When Clicked (`SidebarHatSwitcher.svelte` & `/api/project/hats`)**:
   - `GET /api/project/hats` (without `projectId`) returned `project_id: p.id` (no `id` field) and `assigned_roles: string[]` (role names only, no `project_role_id` or `role_slug`).
   - `SidebarHatSwitcher.svelte` accessed `proj.id` (`undefined` on every project), causing `selectedProject` to evaluate to `null` (always displaying `"Project Hats"`) and throwing a Svelte 5 `each_key_duplicate` error on `{#each scopedProjects as proj (proj.id)}` and `{#each availableProjectHats as hat (hat.project_role_id)}` when clicked.
2. **Project Hats Switcher Resets All the Time to `Artemio, quiero comer!` (`MyProjectHats.svelte`, `HatSwitcher.svelte`, `SidebarHatSwitcher.svelte`)**:
   - `MyProjectHats.svelte` (`onMount`) hardcoded `selectedProjectId = projects[0].project_id` (alphabetically always `"Artemio, quiero comer!"`), ignoring `activeProject?.projectId`, persisted user selection (`localStorage`), and current org context (`/o/webomage/projects`, where `w0m Platform` is `webomage → webomage`).
   - `SidebarHatSwitcher.svelte` ran `scopedProjects.find((p) => p.worn_role)` on mount; because `worn_hats` stores one worn hat per `(profile_id, project_id)` across all assigned projects, `.find((p) => p.worn_role)` always returned `scopedProjects[0]` (`"Artemio, quiero comer!"`), overwriting `activeProject?.projectId`.
   - `HatSwitcher.svelte` updated `worn_hats` via `POST /api/project/hats` without syncing `/api/auth/switch-role` or notifying `MyProjectHats` / `SidebarHatSwitcher` via event, leaving project card `"Wearing: ..."` badges stale and resetting the switcher to Artemio on reload.
3. **`ContextSwitcher` (`Webomage` vs `Me`) Overflowing with Extra Role Text (`ContextSwitcher.svelte`)**:
   - `public.wom_my_contexts()` concatenates all active office titles with `' · '`, producing `"Client · Developer · Member · Tech Lead · Tech Ops · Tech QA · Technical Program Manager"` for multi-hat users in `Webomage`.
   - `ContextSwitcher.svelte` rendered the entire raw string inside `<small>` without summarizing multiple roles or truncating to a single line, wrapping across 4–5 lines in the sidebar header and menu.

## Acceptance criteria

- [x] **AC1 — Fix `SidebarHatSwitcher` ("Project Hats") dropdown and `/api/project/hats` payload contract**:
  - Enriched `GET /api/project/hats` (`apps/cp/src/pages/api/project/hats.ts`) so each project entry includes `id: p.id` alongside `project_id: p.id`, structured `assigned_hats` (`{ hat_id, project_role_id, unit_id, role_slug, role_name, is_worn }[]`) alongside `assigned_roles: string[]`, and normalized `worn_role`.
  - Updated `SidebarHatSwitcher.svelte` to normalize `proj.project_id ?? proj.id`, merge per-project hats via `/api/project/hats?projectId=...` with `assigned_roles`, display the active project and worn role in the trigger button (`Hat: <Project> · <Role>`), and open/switch hats cleanly without key collisions (`just test`).
- [x] **AC2 — Persist selected hat project and stop resetting to `Artemio, quiero comer!` (`MyProjectHats.svelte`, `HatSwitcher.svelte`, `SidebarHatSwitcher.svelte`)**:
  - Persisted `wom_selected_hat_project_id` in `localStorage` and broadcast `wom:project-hat-changed` across `MyProjectHats.svelte`, `HatSwitcher.svelte`, and `SidebarHatSwitcher.svelte` whenever a project or hat is selected.
  - Resolved initial project selection with deterministic precedence: (1) explicit `initialProjectId` / `activeProject?.projectId` or persisted `wom_selected_hat_project_id`, (2) current route/org match (`client_org_slug === currentOrgSlug` first so `/o/webomage/projects` defaults to `w0m Platform` (`webomage → webomage`) rather than client `Artemio, quiero comer!`), (3) first project with `worn_role`, (4) `projects[0]`.
  - Synced `HatSwitcher.svelte` role wear/take-off with `/api/auth/switch-role` and refreshed `MyProjectHats` card `"Wearing: ..."` badges in place without resetting the selected project (`just test`).
- [x] **AC3 — Compact `ContextSwitcher` multi-role subtitle (`packages/ui/src/lib/components/layout/ContextSwitcher.svelte`)**:
  - Added `compactContextRole(role?: string)` in `ContextSwitcher.svelte` so `role` strings with `> 2` `' · '`-separated roles summarize to `<primary role> +<N-1>` (e.g. `"Tech Lead +6"` instead of `"Client · Developer · Member · Tech Lead · Tech Ops · Tech QA · Technical Program Manager"`), keeping full roles in the `title` tooltip and leaving 1–2 role strings unchanged.
  - Enforced single-line truncation (`white-space: nowrap; overflow: hidden; text-overflow: ellipsis`) on `<small>` and `.role-text` in `ContextSwitcher.svelte` (`just test`).
- [x] **AC4 — Unit & Regression Verification**:
  - Added unit tests in `packages/ui/src/lib/components/layout/__tests__/ContextSwitcher.test.ts`, `apps/cp/src/components/admin/__tests__/ProjectManager.test.ts`, and `packages/lib/src/auth/unified-identity-surface.spec.ts` verifying AC1–AC3 (`41/41` passing across 4 suites).
