# T570 — Upstream PR to Graphify-Labs/graphify: commit-provenance manifest, settle guard, and global status/sync subcommands

## Summary

Our multi-repo Graphify union (`wom7web/project/scripts/graph_global.py`, `graph_health.py`, and `graph_fresh.py`, built under `T151`, `T163`, and `T187`) works around three upstream gaps in `Graphify-Labs/graphify` (`graphify/global_graph.py` and `graphify/cli.py`):
1. `~/.graphify/global-manifest.json` records `added_at`, `source_path`, `node_count`, `edge_count`, and `source_hash`, but **never records git commit provenance** (`built_at_commit` or `head_at_merge` + explicit `commit_basis`) — so `graphify global` cannot tell when a registered repository's local graph or git `HEAD` has advanced ahead of the merged union.
2. `graphify hook install` (`post-commit`) launches incremental rebuilds of `graphify-out/graph.json` in the background, and `global_add` has no settle guard (`--settle <seconds>`) to avoid reading or stamping a `graph.json` while a background rebuild is mid-write (`T187`).
3. `graphify global` only provides `add`, `remove`, `list`, and `path` — there is no `graphify global status [--strict] [--json]` to audit per-repo commit lag and union hash drift, and no `graphify global sync [--only <substr>] [--settle <sec>]` to re-merge all registered repositories in `~/.graphify/global-manifest.json` in one pass.

Owner direction (2026-10-23): check `Graphify-Labs/graphify` PR requirements (`CONTRIBUTING.md`, `v8` base branch, `pytest`, `ruff`, `pyright`, `skillgen --check`) and prepare the upstream PR on `github.com/webomage/graphify` (`wom7pr/graphify`).
