# T704 — Harden Client Portal Audit Result Preservation, Multi-Target Report Maps, & Service-Role RLS Persistence Across All Diagnostic Surfaces

## Why

1. **Silent RLS Update Drop on `public.orgs.service_usage` for Client Members & Client Hats**:
   - `public.orgs` has a single `UPDATE` RLS policy (`"Admins update orgs"` requiring `public.wom_acting_is('admin')`).
   - When a client member (`org_members` / `client_users`) or an admin wearing a Client Hat (e.g., `Hat: Solar Mobile`) executes an audit in Client Portal (`/o/[org]/projects/security-audit`), `/api/client/security-audit.ts` and `/api/client/lighthouse-audit.ts` verify org membership via `verifyOrgMembershipIfProvided(supabase, orgId)` (`SELECT` on `orgs`), and then call `supabase.from("orgs").update({ service_usage })` using the user-scoped SSR client (`getSupabaseServerClient`).
   - Under PostgREST RLS, `UPDATE` with `USING (false)` silently updates `0` rows without throwing an error, so reloading `/o/[org]/projects/security-audit` drops all newly generated audit reports, Mistral patches, and diagnostic sessions.
2. **Incomplete Persistence Across Audit Actions (`verify_domain`, `lighthouse-audit` KV hits, `k7_infra_migration`, `order_works`, `GET /api/client/security-audit`)**:
   - `verify_domain` did not append a `DiagnosticSessionRecord` to `service_usage.diagnostic_sessions` or return `diagnosticSessions` to the UI.
   - `lighthouse-audit.ts` returned early on `AUDIT_CACHE_KV` URL hits (`w0m:lhr:v1:<url>`) before calling `persistOrgDiagnosticUpdate`, so cached Lighthouse runs were never saved to `orgs.service_usage`.
   - `k7_infra_migration` and `order_works` computed `k7Report` without persisting `latest_k7_report` or a `k7_migration` session to `orgs.service_usage`.
3. **Single-Slot Overwrite Across Multiple Domains & Repositories**:
   - Storing only a single `latest_security_audit`, `latest_lighthouse_report`, and `latest_level2_report` on `orgs.service_usage` overwrote the previous target's report whenever an org audited a second domain (`webomage.com` -> `cp.webomage.com`) or switched between the 7 `@wom` estate repositories.

## Acceptance Criteria

- [x] **AC1 — 3-Layer Org Audit State Persistence (`client-audit-persistence.ts`, `security-audit.ts`, `lighthouse-audit.ts`)**: `persistOrgDiagnosticUpdate` and `loadMergedOrgAuditUsage` persist and merge org audit state across Cloudflare `AUDIT_CACHE_KV` (`w0m:org-audit-state:v1:<orgId>`) + isolate memory and `public.orgs.service_usage`, surviving Client Hat RLS `0-row` `UPDATE` drops without adding `adminClient()` importers.
- [x] **AC2 — Complete Session & Multi-Target Map Persistence Across All Audit Actions (`security-audit.ts`, `lighthouse-audit.ts`)**: `level1` (`POST` & `GET`), `verify_domain`, `lighthouse-audit` (both fresh and KV-cached runs), `level2_trial`, `level3_cloud`, `k7_infra_migration`, `order_works`, `mistral_remediate`, and `save_diagnostic_session` persist their latest report, per-target report map (`security_reports_by_target`, `lighthouse_reports_by_target`, `level2_reports_by_repo`), and a `DiagnosticSessionRecord` with full combined snapshot.
- [x] **AC3 — Multi-Target Report Restoration & Per-Org LocalStorage Hydration (`security-audit.astro`, `SecurityAuditReportViewer.svelte`)**: `security-audit.astro` merges `orgs.service_usage` with `AUDIT_CACHE_KV` via `loadMergedOrgAuditUsage` and passes `initialSecurityReportsByTarget`, `initialLighthouseReportsByTarget`, and `initialLevel2ReportsByRepo` into `SecurityAuditReportViewer.svelte`; switching domains/repos or restoring a diagnostic session restores all saved reports without losing prior target runs.
- [x] **AC4 — Automated Unit & Contract Verification (`lighthouse-audit.test.ts`, `test_t336_security_audit.py`)**: Unit and contract tests (`8/8` Vitest node+dom tests in `lighthouse-audit.test.ts` and `7/7` in `test_t336_security_audit.py`) verify multi-target preservation and KV + isolate fallback when `orgs` UPDATE returns 0 rows.
