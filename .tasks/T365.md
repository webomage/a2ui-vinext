# T365 — GUI sandbox browser & extension bundling: pre-provisioned Chromium with managed enterprise policies for Jam.dev, Obsidian Web Clipper, and w0m extension

## Summary

Interactive GUI client sandboxes (`var.gui == true`, established in [[T296]]) provide XFCE and user-level session agent plumbing, but have no pre-installed browser or extension toolchain. When an engineer or autonomous agent needs to record proof-of-fix walkthroughs (meeting DoD requirements), clip documentation and architecture into client Obsidian vaults (`_msg/` / `vault/`), or interface with w0m governance directly inside the isolated VM, they currently have to rely on host-side browser relays or ad-hoc manual installations.

Host-relayed recording breaks the client persona boundary: host-level credentials (e.g. `aleksei@webomage.com`) leak into client-facing deliverables on projects managed by other profiles (such as BridgeRoad where `.w0m/sdlc.json` specifies `developer: Elena Shatalova`).

This ticket provisions Chromium in the GUI sandbox image alongside declarative Linux Chromium Managed Enterprise Policies (`/etc/chromium/policies/managed/extensions.json`), force-installing and enabling:
1. **Jam.dev Extension** (`jpbeimfedmonkgnmfchpilaapbdcgodn`) for guest-side visual proof recordings, network captures, and console telemetry.
2. **Obsidian Web Clipper** (`mphjhdfgofbhojkhfnoipmhmcnedafeb`) for structured clipping into local mounted vaults.
3. **w0m Extension** unpacked from `/opt/w0m/extension` to bridge in-VM activity to the w0m Control Panel.

## Acceptance criteria

- [ ] **AC1 — Clean Chromium installation in GUI profile only**: When `var.gui = true`, Packer provisions `chromium-browser` (or `chromium` arm64) on Ubuntu 26.04 LTS. The installation is verified in the build gate by `chromium --version`. Headless profile (`var.gui = false`) remains untouched and carries zero browser footprint.
- [ ] **AC2 — Declarative managed enterprise policies**: Provision `/etc/chromium/policies/managed/extensions.json` containing an `ExtensionInstallForcelist` that automatically installs:
  - Jam.dev extension: `jpbeimfedmonkgnmfchpilaapbdcgodn;https://clients2.google.com/service/update2/crx`
  - Obsidian Web Clipper: `mphjhdfgofbhojkhfnoipmhmcnedafeb;https://clients2.google.com/service/update2/crx`
  Policy validates via standard Chromium JSON schema with `ExtensionInstallAllowlist: ["*"]`.
- [ ] **AC3 — w0m enterprise extension unpack & load**: Package/unpack the w0m extension asset into `/opt/w0m/extension` and register via managed policies (`ExtensionInstallSources` or local unpack policy) so that the w0m toolbar and SDLC bridge are loaded by default.
- [ ] **AC4 — Headless/first-run suppression & default profile settings**: Seed default master preferences (`/etc/chromium/master_preferences` or `/home/ubuntu/.config/chromium/Default/Preferences`) to disable first-run dialogs, default browser prompts, and telemetry popups (`--no-first-run`, `--no-default-browser-check`).
- [ ] **AC5 — Headless smoke & policy verification gate**: In `bridgeroad.pkr.hcl`, add a verification assertion that checks `/etc/chromium/policies/managed/extensions.json` exists, is valid JSON, and contains the required extension IDs.
- [ ] **AC6 — Documentation & boundary update**: Update `vm-seed/README.md` and `image-policy.json` to record the GUI browser capabilities, extension list, and disk footprint delta.

## Definition of Done

A GUI image built via `bridgeroad.pkr.hcl` with `-var=gui=true` boots into XFCE with Chromium installed. Launching Chromium requires no first-run prompts, and `/etc/chromium/policies/managed/extensions.json` is validated with Jam.dev and Obsidian Web Clipper in the force-install list. The headless build profile remains completely free of Chromium packages. Image sizing and policy updates are recorded in `image-policy.json` and `vm-seed/README.md`.

## Notes, traps and dependencies

- ⚠️ **Ubuntu arm64 package name**: Ubuntu 26.04 arm64 uses `chromium` (transitional dummy) or `chromium-browser`. If snap is disabled or purged on minimal cloud images, install Chromium via PPA or Debian/Ubuntu apt repo without snapd dependencies (`--no-install-recommends`).
- ⚠️ **Zero host leakage**: Do not copy host Chrome profiles or extensions into the guest; installation must be entirely declarative via enterprise policies.
