# T676 — Rename `Guild & Cohorts` to `Guild`, activate CP `/o/[org]/people/quests` page, fix expired JWT in CP islands, and add Admin Corporate/RPG naming & Live User Sessions dashboards

## Summary

Addresses five CP UX, authentication, and Admin governance capabilities surfaced on `https://cp.webomage.com/o/webomage/people/technologies` and `/admin`:
1. **Simplify RPG Gamification Label (`Guild & Cohorts` → `Guild`)**: In `apps/cp/src/lib/context/nav.ts`, `GAMIFIED_NAV_LABELS.Team` rendered `"Guild & Cohorts"` when Gamification Mode (`mage`) was active. Shorten this to `"Guild"` and map `guild: Users` in `@webomage/ui` `SideNav.svelte`.
2. **Activate CP `Quests` (`/o/[org]/people/quests`)**: `people/quests` (`capability: "quest.master"`) was unlocked in `hat-visibility-policy.json` (`Unlocked tools: Quests`) for `Product Manager` and `Questmaster` roles, but remained marked `reserved: true` (`Soon`) in `apps/cp/src/lib/context/nav.ts` with no `apps/cp/src/pages/o/[org]/people/quests.astro` route — even though `RaidBoard.svelte`, `AgentQuestTracksBoard.svelte`, and `QuestBoard.svelte` were already implemented in `apps/cp/src/components/admin/`.
3. **Fix `Error: JWT expired` in `TechnologyManager` and CP Admin Islands (`createAdminClient.ts` + `.astro` pages)**:
   - `technologies.astro` (and sibling CP `.astro` pages) read `Astro.cookies.get("sb-access-token")?.value` (the incoming request cookie before SSR session refresh) instead of `Astro.locals.accessToken` (the freshly rotated token set by `@webomage/lib/auth/middleware.ts`).
   - `createAdminClient.ts` attached `Authorization: Bearer ${accessToken}` without checking whether the JWT's `exp` claim had already expired, causing PostgREST to reject queries (including public-readable `technologies` and `tech_categories`) with `HTTP 401 {"code":"PGRST301","message":"JWT expired"}`.
4. **Admin Corporate (`Web`) ↔ RPG Guild (`Mage`) Naming & Vocabulary Studio (`/admin/settings`)**: Add a live terminology switcher and customizable Corporate (`Web`) ↔ RPG (`Mage`) dictionary editor in `CoreSettingsManager.svelte` (`packages/lib/src/terminology.ts`, `packages/lib/src/site-links.ts`, `/api/system/settings.ts`).
5. **Admin Live User Sessions & Actions Dashboard (`/admin/users` & `/admin`)**: Add `LiveUserSessionsDashboard.svelte` mounted on `/admin/users` and linked from `/admin` showing active user identities, system ranks, active role (`user_active_role`), worn project delivery hats (`worn_hats`), verified device sessions (`user_devices`, `devices`, `device_sessions`), and 1-click admin session actions (**Impersonate**, **Clear Worn Hat**, **Reset Active Role**, **Revoke Device Session**) with audit logging (`impersonation_audit`, `admin_activity_logs`).
