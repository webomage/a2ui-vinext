## ✅ Resolved by reading the source — the husky worry is unfounded

A reasonable first objection is that `graphify hook install` would collide with husky, or write into
`.husky/_` and be clobbered when husky regenerates it. **It does not.** `graphify/hooks.py`:

- `_hooks_dir()` reads `core.hooksPath` (wom7web: `.husky/_`) and validates the path stays inside the
  repo root;
- `_user_hooks_dir()` returns the **parent** when the resolved dir ends in `_`, explicitly for
  Husky 9 — so it installs to **`.husky/post-commit`**, the tracked user-editable location.

⚠️ **This is exactly the trap this repo already documents in three places** (`CONTRIBUTING.md:96`,
`.pre-commit-config.yaml:137`, `STATE.md` gate matrix): `wom7web` redirects `core.hooksPath`, so
`.git/hooks/pre-commit` there is **inert**. graphify happens to handle it correctly — **verify this
per repo anyway**, because `wom7api`/`wom7cfworkers` use the default hooks path and the resolution
differs.

## 🔴 The one risky part — the codegraph succession

**Do not treat "graphify is primary" as "delete codegraph".** The constraint that makes this
delicate:

- The **global `~/.claude/CLAUDE.md` instructs every agent** to reach for codegraph *before*
  grep/find, in any repo with a `.codegraph/` directory. That instruction is live in every session.
- codegraph is indexed in **6 repos** and re-syncs on **every commit** (visible in the pre-commit
  output as `codegraph sync (incremental)`).
- graphify's graph is **stale by 274 commits** and covers one repo.
- 🔴 **AC1 sharpened this:** codegraph's reach is not just an instruction in a doc — it is a **live
  MCP server registered in `~/.claude.json`**, available in every session in every directory.
  graphify has **no MCP registration at all**. The succession therefore needs AC8 (a graphify MCP
  surface) *before* AC9 can even be attempted; editing instructions would not transfer the surface.

⇒ **Right now, switching the instruction would point agents at the less current index.** The
succession must be ordered: *graphify reaches parity (coverage + freshness + a query surface) →
then* the instruction changes. Flipping the doc first would degrade every agent session in the
estate, silently — a count/coverage claim outrunning reality, which is [[T149]]'s organising failure
mode wearing new clothes.

⚠️ [[T150]] AC9 already set the rule for this: **measure what calls each tool before changing
anything.** That measurement is AC1 here.
