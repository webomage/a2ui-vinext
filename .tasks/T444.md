# T444 — Configurable public website external links via Admin CP w0m Core Settings

## Summary

Owner direction (2026-09-24):
> "we have to have all the external links on public side of website to be tweakable/setable via admin CP w0m core settings"

Currently, all external outbound links across the public website (`apps/web`):
- Footer social links (GitHub, LinkedIn, Upwork, Telegram) in `Footer.astro`
- Booking/Calendly URL in `Header.astro`
- Contact section links (LinkedIn, Upwork) in `ContactFormSection.astro`
- Resume and CV page contact/profile links in `resume.astro` and `CVPage.astro`
- Portal links (Job Board, Join Network)

are hardcoded strings directly in the Astro components. Modifying any public link requires a source code edit and full redeploy.

To make external links dynamically configurable:
1. Store external link configurations under key `external_links` in `public.site_settings` (with typed fallback defaults).
2. Provide an Admin CP settings manager under `/system/settings` ("Core Settings") with Svelte UI and API endpoints (`GET /api/system/settings`, `PATCH /api/system/settings`) to view and update link URLs.
3. Expose a unified helper `getSiteLinks()` in `apps/web` (SSR-safe, caching with fallback defaults) and wire all public components (`Footer.astro`, `Header.astro`, `ContactFormSection.astro`, `resume.astro`, `CVPage.astro`) to read from it.
4. Provide immediate validation and preview in CP before saving.

## Acceptance criteria

- [ ] AC1 — **Schema & Default Settings**. Migration or initial seed in `site_settings` under key `external_links` with canonical link keys: `github_url`, `linkedin_url`, `upwork_url`, `telegram_url`, `calendly_url`, `job_board_url`, `join_network_url`, and custom external links array.
- [ ] AC2 — **Admin CP Core Settings Page & API**. Create `/system/settings` page in Admin CP (and link in `AdminLayout.astro` under System -> "Core Settings") with `/api/system/settings` endpoint allowing authorized admins to view and update links.
- [ ] AC3 — **Public Web Site-Links Provider**. Create `apps/web/src/lib/site-links.ts` that fetches `external_links` from `site_settings` with robust fallbacks to existing URLs if DB is unreachable or unset.
- [ ] AC4 — **Public Component Wiring**. Refactor `Footer.astro`, `Header.astro`, `ContactFormSection.astro`, `resume.astro`, and `CVPage.astro` to consume dynamic links from `getSiteLinks()`.
- [ ] AC5 — **Verification & Tests**. Vitest tests verifying settings API, unit tests for `getSiteLinks` fallback behavior, and E2E verification that changing a link in CP reflects on the public site.
