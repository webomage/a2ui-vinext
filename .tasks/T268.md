# T268 — two project shapes, one of them undeclarable

## Summary

Owner direction 2026-08-23: *"we have to have simple mode for project config when root of project is
git repo, and more advanced like workspace with repos folders under the parent folder which is the
root of project"*.

🔑 **The asymmetry is already in the estate's own files, and it has been paying for it all day.**

| | how it is declared today | supports |
|---|---|---|
| **w0m itself** | `.w0m/sdlc.json` → `root: ".."` + `repos: {web: wom7web, api: wom7api, cf: …}` — **seven repos under one parent** | **workspace** |
| **every client** | `project/clients-policy.json` → one `root` per project, and `client_inventory.py` **hard-fails** if it is not a git repo ROOT | **simple only** |

⇒ **The estate models itself as a workspace and can only register a client as a single repo.**
Every workspace-shaped client has to be squeezed into the simple shape by declaring one repo inside
it and leaving the rest of the project undeclared.

## What it has already cost, measured today

**1. [[T265]] — BridgeRoad had to be declared wrong to be declarable.** Its project root is
`_proj/bridgeroad/`, which is **not a git repo**; the code lives in `_proj/bridgeroad/BridgeMvp`
(remote `BridgeRoad/bridgeroad-app`), and beside it sit `client_message_2026.07.11.md`,
`client_roadmap_proposals.md`, `coverage_report.md`, `_report/`, `_state/`. T265 AC1 therefore
declares the root as **`BridgeMvp`** — the repo — and T265 AC8 has to invent a disposition for the
delivery artefacts as *"out-of-repo, handle them somehow"*.

🟢 **Under workspace mode both problems dissolve**: the project root is `_proj/bridgeroad`, `BridgeMvp`
is a repo under it, and the delivery files are **workspace-level artefacts** — a legitimate place to
live, not an anomaly needing a special ruling. ⇒ **T265 AC1 and AC8 are re-scoped by this ticket.**

**2. [[T267]] — the deploy hook could not express "same project".** A `just deploy-*` running in
`wom7api/` must block a commit in `wom7web/` because consent binds to `wom7web`'s HEAD, while 1945's
deploy must not. There is no repo-level rule that gets both right; the correct predicate is *"is this
process inside the same **workspace**"*, which only exists because `.w0m/sdlc.json` happens to
declare `root` + `repos` for w0m. **A client workspace has no such declaration to consult.**

**3. The 1945 trap, already documented in `clients-policy.json`.** Its note warns that the root is
`_self/1945`, **not** `_self/1945/1945socialclub.com`, because `git -C` on a subdirectory silently
reports the enclosing repo. That warning exists because the schema has one slot for a concept that
sometimes has two levels.

**4. Artemio has two design-system trees** (`design-system/` and `docs/design-system/`, [[T183]]
AC11) and a 29 MB zip outside the repo. "Which repo is the DS in" is the wrong question for a
project whose artefacts are not all in one repo.

## Design notes, not decisions

- **Simple stays the default and must not get harder.** Four of five declared projects are
  simple (`1945`, `artemio`, `servicios777`, `personaje0`). A schema change that makes those
  declare a one-entry `repos` map to say what they already say is a regression in ergonomics.
- **The estate's own `root` + `repos` is the obvious prior art** and is already read by
  `coverage_scan.py:176` and others. Reusing that vocabulary for clients means one concept, not two.
- 🔴 **The hard-fail must be kept, just moved.** `clients-policy.json` refusing a root that is not a
  git repo root is a *good* rule that caught real errors; under workspace mode the equivalent rule
  is *"every declared repo under the workspace root resolves to a git repo root"*. Relaxing it into
  nothing is the failure mode here.
- ⚠️ **A workspace root that is not a git repo means the project's own governance files are
  unversioned.** `@wom` is exactly this and it is already recorded debt (**D32**), and
  `_proj/bridgeroad` is the same. Workspace mode must say where a workspace's `.w0m/` lives and
  whether it is tracked — otherwise it legitimises the D32 shape by silence.

## Acceptance criteria

- [x] AC1 — **`clients-policy.json` accepts both shapes, and the schema says which is which.**
      A simple project keeps today's single `root`. A workspace project declares a `root` plus a
      `repos` map, in the same vocabulary as `.w0m/sdlc.json`. The mode is **derivable from the
      declaration** rather than a separate flag that can disagree with it.
      ✅ **2026-08-23** — `clients-policy.schema.json` gains `repos` (object, min 1) and `canonical_repo`, with an `allOf`/`if`-`then`-`else` making `canonical_repo` REQUIRED when `repos` is present and FORBIDDEN when it is absent. Verified: the live registry validates, a workspace entry validates, and `repos` without `canonical_repo` is rejected. The mode is derived from the presence of `repos` — there is no `mode` field to disagree with the shape.
- [x] AC2 — 🔴 **The git-root check is preserved, not relaxed.** Simple: `root` must be a git repo
      root, as today. Workspace: **every declared repo** must be a git repo root, and a `repos` entry
      pointing at a non-repo is a hard failure. A workspace whose root happens to be a repo too is
      allowed and must not double-count.
      ✅ **2026-08-23** — `client_inventory.py` branches on `repos`. Simple: unchanged. Workspace: `root` may be a non-repo, and EVERY entry in `repos` must be a git repo root. Held by four red probes — a repo that is a subdirectory, a repo that does not exist, a `canonical_repo` outside `repos`, and the CONTROL proving the same root with no `repos` still hard-fails as simple. That control is what makes this a move rather than a relaxation.
- [x] AC3 — **A red probe for the exact 1945 trap.** Declaring a workspace root that is a
      *subdirectory* of a git repo must FAIL, not silently adopt the enclosing repo — `git -C`
      reports it happily, which is why the warning is already written in the registry's note.
      ✅ **2026-08-23** — `WORKSPACE: a declared repo that is a SUBDIRECTORY hard-fails`, using `wom7web/project` as the fixture. Observed red before the branch existed.
- [x] AC4 — **`just client-inventory` and `just client-check` report a workspace correctly** — per
      repo where the question is per-repo (stacks, branch, dirty), once where it is per-project
      (`.w0m/sdlc.json`, agent memory, skills). ⚠️ State which is which; today every column is
      implicitly per-repo because a project *is* a repo.
      ✅ **2026-08-23** — the split is now stated in the code and printed in the report: **per-repo** = branch / remote / dirty (each repo listed, so a dirty non-canonical repo cannot hide behind a clean canonical one); **per-project** = declaration, CLAUDE.md, skills, agent memory, read from the canonical repo. ⚠️ The probes assert the STRUCTURE, not the rendering — the first version did `"wom7api" in out` where `out` is a parsed dict, which silently checks top-level keys instead of contents.

      `BridgeMvp` — and [[T265]] AC1/AC8 are updated to match. Its loose delivery files become
      workspace-level artefacts with a declared home, which is AC8's answer rather than a special case.
      🟡 **HALF — the capability is built and proven, the declaration is [[T265]]'s act.** T265 AC1 and AC8 were rewritten to the workspace shape on 2026-08-23 (done). - [x] AC7 — **Workspace-level `.w0m/` placement is declared**, including whether it is git-tracked,

      ✅ **2026-08-23** — answered structurally rather than by a new rule: `canonical_repo` requires the contract to live **inside a declared repo**, so it is always git-tracked.       `canonical_repo` now also accepts **`"."`**, meaning the workspace root — **but only when that
      root is itself a git repo root**. 🔑 The distinction this AC exists to protect is preserved
      exactly: *"the root is a repo we own, with history and hooks"* is a different claim from *"an
      untracked parent is fine"*, and `client_inventory` hard-fails the latter **by name** —
      *"that is D32 (configuration versioned nowhere), which T268 AC7 exists to keep inexpressible"*.
      Red-tested against a real non-repo workspace root. ⇒ D32 remains inexpressible; it is simply no
      longer the case that avoiding it requires writing into someone else's repository.
- [x] AC8 — **[[T267]] can ask "same workspace?" of a client project.** Once a client declares
