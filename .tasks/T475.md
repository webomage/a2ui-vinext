# T475 — Biometric hardware anchor for @wom/kyc and compliance profiles

## Summary

Owner ask, 2026-09-28: *"actually if we can do biometrics for auth then it's the bridge into kyc"*.

Traditional KYC verifies identity statically (document scan, CURP/RFC standing), leaving accounts vulnerable to session hijacking, credential stuffing, and account resale (Sybil/puppet accounts). Conversely, biometric authentication (WebAuthn / Passkeys / Touch ID / Face ID) backed by device hardware enclaves (Apple Secure Enclave, Android StrongBox, FIDO2 tokens) proves physical human presence with unexportable asymmetric cryptography.

This ticket delivers the **Biometric-to-KYC Bridge**: cryptographically binding hardware-anchored biometric credentials to verified KYC records in `@wom/kyc` and `gamification.compliance_profiles`. High-assurance operations (treasury withdrawals, contract signatures, outstaffing compliance) can then be authorized via a 1-second biometric challenge (NIST AAL3), proving continuous live presence of the verified legal individual while maintaining privacy-by-design (zero raw biometric templates leave the user device).

## Acceptance criteria

- [x] AC1 — **BiometricAnchor & KycAssuranceLevel in `@wom/kyc`:** Extend `packages/kyc/src/types.ts` with `BiometricAnchor` (`credentialId`, `publicKey`, `authenticatorType`, `aaguid`, `enrolledAt`, `attestationFormat`, `counter`) and `KycAssuranceLevel` (`none`, `tier1_basic`, `tier2_full`, `tier3_biometric_anchored`, `corporate_mx_anchored`). Unit tests in `packages/kyc/tests/` verify schema conformance and payload validation.
- [x] AC2 — **Durable database migration for compliance profiles:** A Supabase migration adds `biometric_credential_id text`, `biometric_public_key text`, `biometric_authenticator_type text`, `biometric_enrolled_at timestamptz`, `biometric_bound_at timestamptz`, and `kyc_assurance_level text DEFAULT 'tier1_basic'` to `gamification.compliance_profiles` with a strict check constraint enforcing valid assurance levels.
- [x] AC3 — **Cryptographic binding ceremony helper:** Implement `bindBiometricToKyc()` in `@wom/kyc` that generates a deterministic HMAC-SHA256 / SHA-256 binding digest over `(userId, credentialId, legalIdentifier, verifiedAt)`, returning an updated `UnifiedKycScorecard` with `tier3_biometric_anchored` status when both valid legal identity and hardware attestation are present.
- [x] AC4 — **Privacy-by-design & raw template rejection:** Architectural test / static probe verifies that API endpoints and data schemas reject raw biometric data (pixel arrays, minutiae templates) and accept exclusively W3C WebAuthn public keys, client data JSON, and authenticator data.
- [x] AC5 — **Automated verification probe (`just kyc-bio-probe`):** Live database test probe verifies columns, constraints, and end-to-end binding between a WebAuthn biometric anchor and an active KYC compliance profile.
