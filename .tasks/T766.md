# T766 — Fix picomatch ReDoS via webomage fork instead of osv ignores

## Summary

Owner direction (2026-11-18): ignoring unfixable advisories is not a
long-term policy — fork, fix, and install from `webomage/*` instead
(AgDR-0058 fork discipline). Background: `GHSA-fc5q-39xc-vjpf` (CVSS 8.7)
is a ReDoS in picomatch `analyzeRepeatedExtglob`
(`lib/parse.js`): single-branch repeated extglobs like `+(*)` / `+(*a)`
skip the risk analysis and backtrack exponentially. Affects `<= 4.0.7`
(no upstream release since 2026-08-27; `first_patched_version: null`).
Upstream already carries 10+ open, unreviewed fix PRs (#257–#266, none
merged, no CI) — an elevent would be a duplicate by `just pr-auto` rules.

Plan:

- Fork `micromatch/picomatch` to `webomage/picomatch`.
- Port the collapsible-single-branch approach (PR `micromatch/picomatch#266`,
  credited): a single-branch repeated extglob whose body is only `*`
  literals and `?` collapses (`+(X)` -> `@(X)`, `*(X)` -> `?(X)`); anything
  else stays marked risky. Regression tests from the advisory PoC
  (`+(*a)` vs `'a'.repeat(28) + 'b'`, etc.).
- Two branches/tags because the estate consumes two majors:
  `v4` based on upstream master (tags `v4.0.8-wom.1`) and
  `v2` based on the 2.x line (tag `v2.3.3-wom.1`).
- Estate consumption via `pnpm.overrides` in the 4 repo lockfile holders:
  `w0m-web`, `w0m-api`, `w0m-cf` (picomatch 4.0.x) and
  `w0m-ext/extension` (2.3.2), then reinstall; drop the T765 osv ignore
  entries only where scans stay clean afterwards (git deps may fall outside
  osv version ranges — verify before removing, unused-ignore gate is strict).
- Upstream: optionally comment/review on `#266` (no new PR — duplicates
  rejected).
