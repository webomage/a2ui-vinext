# T142 — Gherkin → Gauge migration inside w0m

## Summary

**Owner directive, 2026-07-26:** *"we should not use Gherkin as a primary tool but Gauge"*, *"we can
keep Gherkin support as an sdlc tool for customers project in our w0m skills and tools"*, and then
explicitly: *"if we see gherkin somewhere at w0m now then it should be converted and migrated to
Gauge completely"*.

So this is a **migration**, not a precedence rule. Gherkin remains a supported **offering for
customer/client projects** (`wom7skills/GENERIC-SDLC-SET.md`) — it is intentional capability there
and must not be stripped out.

`wom7mlx/wom7mlx/specs/`: `003-mlx-rs-upgrade.feature`, `multimodal_serving.feature`.

⚠️ **This is not a file rename.** Each `.feature` has a Cucumber step implementation
(`extension/tests/e2e/steps/*.steps.js`) that must be **re-written as Gauge step implementations**,
and the runner + CI/`just` recipe must move with it. Count the step files, not the feature files,
when sizing this.
