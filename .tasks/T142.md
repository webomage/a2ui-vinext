# T142 — Gherkin → Gauge migration inside w0m

## Summary

**Owner directive, 2026-07-26:** *"we should not use Gherkin as a primary tool but Gauge"*, *"we can
keep Gherkin support as an sdlc tool for customers project in our w0m skills and tools"*, and then
explicitly: *"if we see gherkin somewhere at w0m now then it should be converted and migrated to
Gauge completely"*.

So this is a **migration**, not a precedence rule. Gherkin remains a supported **offering for
customer/client projects** (`wom7skills/GENERIC-SDLC-SET.md`) — it is intentional capability there
and must not be stripped out.

`wom7mlx/wom7mlx/specs/`: `003-mlx-rs-upgrade.feature`, `multimodal_serving.feature`.

⚠️ **This is not a file rename.** Each `.feature` has a Cucumber step implementation
(`extension/tests/e2e/steps/*.steps.js`) that must be **re-written as Gauge step implementations**,
and the runner + CI/`just` recipe must move with it. Count the step files, not the feature files,
when sizing this.

## Acceptance criteria

- [ ] AC1 `wom7ext`'s 7 `.feature` files are expressed as Gauge `.spec` files, with their Cucumber
      `*.steps.js` re-implemented as Gauge steps. The old Cucumber runner/deps are removed, not left
      dormant beside the new one.
- [ ] AC2 `wom7mlx/wom7mlx`'s 2 tracked `.feature` files are migrated to Gauge.
      🔴 **Coordinate first** — see the conflict note below.
- [ ] AC3 The migrated suites **run and pass**, invoked through a `just` recipe declared in
      `project/stacks-policy.json` (T130's `commands` contract). A migration that cannot be run is
      not a migration.
- [ ] AC4 🔴 **RED proof required (AC7 discipline):** deliberately break one migrated scenario and
      observe the Gauge suite fail. A suite that collects **zero** specs also "passes" — prove it
      can fail before believing it green. This is the exact trap that made `just test` in `wom7web`
      report success while collecting 0 files (see [[T140]]).
- [ ] AC5 `wom7skills/skills/w0m/w0m-spec/SKILL.md` teaches **Gauge** as the w0m default. Its
      current worked example is a Gherkin `Scenario:` block.
- [ ] AC6 Gherkin remains available and documented **for customer projects** in
      `wom7skills/GENERIC-SDLC-SET.md` — verify it is not collaterally deleted by AC5.
- [ ] AC7 No `.feature` file remains tracked in any w0m repo. Add a gate/check so a new one is
      caught, rather than relying on this ticket having been done.

## 🔴 Conflict note — `wom7mlx/wom7mlx` has a parallel agent in it

That repo holds a **third**, untracked `specs/004-logits-mismatch.feature` belonging to another
agent's in-flight logits-mismatch work, alongside ~10 dirty paths that `STATE.md` records as
**"do not touch, do not reformat"**. Migrating specs there mid-flight will collide. Either wait for
that work to land, or migrate only the 2 tracked files and leave `004` to whoever owns it.
