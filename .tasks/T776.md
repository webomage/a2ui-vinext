# T776 — Add direct local folder import button with workspace ownership scoping on OpenDesign Design Systems page

## Summary

On OpenDesign's `/design-systems` page, clicking `+ Create` and selecting a local folder opens the AI agent brand-creation wizard (`DesignSystemCreationFlow`), which falls back to `buildFallbackDesignMdFromState()` (`Product`, default `#ffffff`/`#111111`/`#1677ff` palette, `Inter 400/700`, `No logo yet`) instead of calling OpenDesign's deterministic local package importer (`POST /api/design-systems/import/local`). Meanwhile, `importLocalDesignSystem`, `importGitHubDesignSystem`, and `importShadcnDesignSystem` in `apps/web/src/providers/registry.ts` do not forward `workspaceProjectHeaders(workspaceContext)` (needed to claim ownership in signed-in workspaces), and `importLocalDesignSystemProject` in `apps/daemon/src/design-systems/import.ts` ignores `DESIGN.md` frontmatter `name:` when deriving the imported display name and slug.

Expose a direct `Import folder` button alongside `+ Create` in `DesignSystemsTab`, thread `workspaceContext` through the registry import helpers and callers, read optional YAML `name:` from `DESIGN.md` / `design.md` frontmatter in `import.ts`, verify across daemon/web Vitest + `typecheck`/`guard`/`i18n:check` and live `:7456`, register the upstream PR in `scripts/w0m_prs.py`, and close out cleanly.

## Acceptance criteria

- [x] AC1 — Upstream web client & Settings (`registry.ts`, `DesignSystemsSection.tsx`): `importLocalDesignSystem`, `importGitHubDesignSystem`, and `importShadcnDesignSystem` accept optional `workspaceContext` and attach `workspaceProjectHeaders(workspaceContext)` when present; `DesignSystemsSection` forwards its active `workspaceContext`.
- [x] AC2 — Upstream Design Systems UI & i18n (`DesignSystemsTab.tsx`, `DesignSystemsTab.module.css`, `i18n`): header exposes an `Import folder` button next to `+ Create` that invokes `openFolderDialog({ throwOnError: true })`, calls `importLocalDesignSystem({ baseDir }, workspaceContext)`, refreshes the catalog into **Your systems**, selects the imported system, and surfaces clean loading/error feedback across all 19 locales.
- [x] AC3 — Upstream daemon importer (`import.ts`): `scanProject` reads frontmatter `name:` from source `DESIGN.md` / `design.md` (`sourceDesignName`) so omitted `options.name` resolves `options.name ?? scan.sourceDesignName ?? scan.packageName ?? options.fallbackName ?? path.basename(sourceRoot)`.
- [x] AC4 — Verification, integration & PR registration: Node v24.22.3 `pnpm typecheck`, `pnpm guard`, `pnpm i18n:check`, `import.test.ts`, `DesignSystemsTab.test.tsx`, and `DesignSystemsSection.test.tsx` pass with zero public-leak strings; `feat/design-system-local-import` is GPG-signed & pushed to `webomage/open-design`, merged into `local/sdlc-integration` and live-verified on `:7456`, and registered in `scripts/w0m_prs.py` (`AgDR-0058` owner gate respected).
