# T174 — STATE.md retention: rotate dated history out, split durable facts to their proper home, budget both surfaces

## Summary

`STATE.md` is the estate's cross-session memory and **it grows without bound**. Measured
2026-08-07 at `9696cfbf`:

| | |
|---|---|
| size | **332,615 B · 4,130 lines · ~83k tokens** |
| dated history | **93.9%** of the bytes — 19 superseded pickup blocks, 59 `###` sections |
| growth | **5 KB → 333 KB in 16 days** (2026-07-22 → 2026-08-07, ~20 KB/day) |
| auto-memory `MEMORY.md` | 15,990 B (~4k tok) **auto-loaded every session**, 56 fact files |

`w0m-state-load` instructs the next agent to read `STATE.md`, so **orientation costs ~87k tokens
before any work starts**, and the ratio is getting worse every session. At the observed rate the
file passes 1 MB in early September.

[[T145]] is **done** and fixed a *different* problem: the **mechanical** block (repo/dirty/unpushed
table, gate codes, counts) is generated and gated at pre-push. It deliberately never touches the
editorial prose — which is where all 93.9% lives. **§0q of `STATE.md` named this exact gap as its
deliverable 3 — *"retention/pruning of resolved sections"* — and it was never ticketed.** This is
that ticket.

**Root cause, stated as a design fault rather than a housekeeping backlog:** `STATE.md` is doing
**three** jobs at once, and only one of them is bounded by nature.

| Job | Belongs | Bounded? |
|---|---|---|
| (a) mechanical snapshot of the estate | the generated block ([[T145]]) | ✅ regenerated, so self-limiting |
| (b) **what is next / what is uncommitted** — the actual handoff | `STATE.md` prose | ✅ ~200 lines, replaced each session |
| (c) accumulated gotchas, lessons, resolved records | **auto-memory** (durable facts) / **`CLAUDE.md`** (standing rules) / archive (history) | 🔴 **append-only, unbounded** |

Job (c) is the whole problem, and `CLAUDE.md` already states the rule it violates: *"One fact, one
home: durable facts go to auto-memory, rules go here."* So the fix is not "trim the file" — it is
**send job (c) to the homes the estate already declared**, then hold the result with a budget so it
cannot silently regrow. Owner decision 2026-08-07: do **both** halves (rotate **and** split), and
run it through the SDLC gates.

## Acceptance criteria

- [x] AC1 — **Rotation mechanism.** `just state-rotate` moves every superseded pickup block and
      resolved dated section out of `STATE.md` into `project/state-archive/YYYY-MM-DD-<slug>.md`
      (one file per block, matching the established `openspec/changes/archive/` date-slug
      convention), and writes a one-line-per-archive **index table** back into `STATE.md`. Idempotent:
      a second run moves nothing and exits 0.
- [x] AC2 — **Lossless, and provably so.** Rotation emits a **disposition record** accounting for
      **every one of the 63 editorial sections** (66 headings − 3 generated; see the start-gate
      bucket table in the status notes) — archived / promoted-to-auto-memory /
      promoted-to-`CLAUDE.md` / kept-live — committed as a versioned file. A section with no recorded
      disposition is a **hard failure**, not a default-archive. ⚠️ Byte-accounting must reconcile:
      `sum(archive files) + new STATE.md ≥ old STATE.md` minus only the index/header text added.
- [x] AC3 — **Split by purpose, per the `CLAUDE.md` rule.** Each durable fact in job (c) lands in
      exactly one home: **auto-memory** for facts, **`CLAUDE.md`** for standing rules, **archive** for
      dated history. No fact is duplicated across two homes (that is the failure the rule exists to
      prevent), and each promoted item names its origin section.
- [x] AC4 — **Budget on `STATE.md`, enforced.** `state-check` fails when `STATE.md` exceeds a budget
      declared in `.w0m/sdlc.json → state_surface` (lines **and** bytes). Starts **GREEN** on the
      rotated tree with real headroom — a budget set at the post-rotation size blocks the very next
      session's writing ([[T135]] AC8: never install a gate that starts red).
- [x] AC5 — **Budget on the OTHER surface too.** `MEMORY.md` is auto-loaded **every** session, so
      draining `STATE.md` into it can make the always-on cost *worse than the file it drained*.
      Record the pre/post token cost of **both** surfaces, and budget `MEMORY.md`'s index as well.
      🔴 This AC is the reason AC3 cannot be "move it all to memory".
- [x] AC6 — **Proven RED, and proven against the empty set.** Per [[T135]] AC7: a hand-grown
      `STATE.md` over budget → exit 1 naming the overage; **and** rotation over a file with **zero**
      rotatable sections must not report success-over-nothing, nor must a budget check pass on an
      absent or empty file. Extend `just state-doctor-test` (currently 9 checks) rather than adding a
      parallel harness — it already retargets via `W0M_STATE_MD`, which is exactly the fixture hook
      this needs.
- [x] AC7 — **The skills carry it.** `w0m-state-save` rotates as part of saving; `w0m-state-load`
      reads the **bounded** file plus the archive index instead of 4,130 lines, and can still reach a
      named archive on demand. Both are governed ([[T127]]) — **stamp → sync → relock**, and
      `relock-all` for any NEW declaration ([[T145]]'s recorded trap).
- [x] AC8 — **Config + docs.** `.w0m/sdlc.json → state_surface` gains the retention settings §0q
      deliverable 3 asked for (archive dir, budget, what rotates, what is never rotated);
      `CLAUDE.md`'s `STATE.md` workflow line covers `state-rotate`.
- [x] AC9 — **Record what leaves git.** 🔴 Auto-memory lives at
      `~/.claude/projects/-Users-proto-Projects--self--wom/memory/` — **unversioned, per-machine, and
      invisible to every gate**, the same class of blind spot as the estate-root `.mcp.json` found on
      2026-08-07. Every fact promoted there must leave a **versioned** pointer behind, so a fact
      moving out of git still produces a diff someone can review.

**Design decisions taken at this gate:**
1. **AC4 and AC5 share one requirement, deliberately.** They are one behaviour — *a surface is
   bounded* — applied to two surfaces. Splitting them would have produced a second requirement whose
   scenarios duplicated its sibling's, and duplication in a spec is the same defect the change is
   fixing in the file.
2. **The empty/absent case is a first-class SCENARIO in three requirements, not a review item.**
   A retention gate's natural failure mode (a small file) is **indistinguishable from its success
   condition**, which makes it unusually prone to the vacuous pass this estate has shipped four
   times. So *"the budget cannot certify an absent or empty file"* and *"nothing to rotate is not
   success-over-nothing"* are written as behaviour the spec demands.
3. **Rotation must copy VERBATIM, and that is a security clause, not a style one.** Several sections
   are the only record of credential incidents; a tool that "helpfully" rewrote one would be an
   unreviewed edit to a security record.
4. **`archived` is the DEFAULT disposition in the triage; promotion is the exception** (`tasks.md`
   §3.2). This falls straight out of AC5's cost inversion — promoting to auto-memory moves a cost
   from occasional to permanent, so it has to earn its place.
5. **`tasks.md` carries paired evidence slots with BLANK exit-code fields**, so a missing proof is
   visible at review time instead of assumed — T135's practice, which is why its AC7 held.
6. **§4.3 has an explicit STOP condition:** if the *combined* token cost of both surfaces goes **up**,
   the split is wrong and §3.2 gets re-triaged rather than shipped. An AC that can only be measured
   after the work is done needs a stated abort, or it becomes a rationalisation.

## 2026-08-19 — the rotation could NEVER fire, and the cap was nominal

`state-rotate` reported an empty candidate set while `STATE.md` sat at **94% of its enforced byte
cap** with **four pickup blocks, two of them both claiming "(LATEST)"**.

🔴 **The policy depended on a rename step nobody performs.** `rotate_patterns` expect
`### ⭐ (was) PICK UP HERE` — a heading something used to write (**17 archived files carry it;
STATE.md carried zero**) — while `never_rotate` protects `^## ⭐ PICK UP HERE`, which shielded the
*superseded* blocks along with the current one. ⇒ **Two rules that could only both hold if a human
renamed the old block, and nobody did** — including me: I wrote a new pickup block earlier the same
day and left the previous three untouched, then read the empty rotate output as *"nothing to
archive"* rather than as *"the matcher is dead"*.

✅ **Fixed mechanically.** A superseded pickup block is now identified **by the date in its
heading**: the newest is current, every older one is dead *by definition*, because writing a new one
is what supersedes it. No rename, no discipline, no human step. ⚠️ Ordering is by **date, not file
position**, so a block appended out of order cannot silently become "current".

**Result: 3 sections archived · 24,864 B out · 94% → 64% · idempotent on re-run**, and the archive
index still names them so history stays reachable.

⚠️ **Two of the seven new probes were wrong first** — they asserted the rotated section's *title*
was gone, but a rotated section deliberately leaves an index row naming it. **Assert on the body.**
Same shape as the day's other probe failures: a substring standing in for the thing it represents.

📌 **The lesson is about the empty result, not the regex.** `state-rotate` printed *"candidate set
was EMPTY … Nothing to rotate is a valid no-op, NOT evidence the file is bounded"* — the tool
**said** it could not prove boundedness, and that warning was read as reassurance for days.
