# T430 — Repair the T411/T414/T418/T419 elevation fallout that turned 8 deploy-blocking suites red

## Summary

`just deploy-all` (owner, 2026-09-23, HEAD `f95963aa`) passed check-infisical ([[T429]]) and db-migrate
(0 pending). It then stopped at `test`: **8 blocking suites red** (`py-test`, `coverage-scan`, `decisions`,
`decisions-index-fresh`, `skills`, `tickets-frontmatter`, `push-cadence`, `ds-conformance-selftest`).
Nothing was deployed.

Root causes, each verified:

| Suite(s) | Cause | Came from |
|---|---|---|
| coverage-scan, tickets-frontmatter | bare `import discovery` / `import tasks_query` from the script's own directory; those modules only exist in the estate `scripts/` | T419 cutover (2026-09-22) deleted the wom7web copies |
| push-cadence, and 10 more production scripts | read the dead `wom7web/project/tickets/` instead of the estate `.tasks/` | T411 (2026-09-20) |
| decisions, decisions-index-fresh, py-test | `decisions_index.py` read 3 of its 6 sources at dead wom7web paths (tickets, TECH-DEBT, ROADMAP) and **skipped missing ones silently** (`if not p.exists(): continue`). The index shrank without an error | T411 / T414 |
| tickets-frontmatter (after the import fix) | 56 tickets' derived `x_*` fields drifted, because the refresh hook lived in wom7web and watched `project/tickets/`, so it could never fire | T411 |
| skills | 3 skills legitimately updated by T418 (`w0m-sdlc-start`, `w0m-tasks`, `w0m-ticket-audit`, byte-identical to canonical) but wom7web was never relocked | T418 |
| ds-conformance-selftest | a **real regression**: T165's `ResumeStudio.svelte` added 11 native `<button>`s (ratchet 392 → 398) | T165 (`89fac6f3`) |

Also found while fixing (the same class of silent failure):
- `gen_status_dashboard.py` epic roll-up had `except ImportError: return ""`. The whole section had
  vanished silently since T419.
- `tickets_frontmatter_sync.py` compared full text, including the daily `x_synced` stamp, so the first
  run of each day rewrote **all ~430 tickets**. That is a collision on every file for parallel agents.
- `--porcelain` printed paths relative to `TICKETS.parents[1]` (`@self`), not the repo root.
- `test_ticket_schema_check.py` globbed the live corpus at `project/tickets`, so it passed vacuously on
  0 tickets.
