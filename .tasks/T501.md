# T501 — `w0m-personnel`: the Resume Studio assistant

## Summary

Split from [[T499]] AC3 (owner, 2026-09-30: enhance the members' AI bot to help parse and rewrite positions and other texts in Resume Studio; agents are `w0m-` prefixed; name `w0m-personnel`, spelling to confirm). Replaces T499's earlier "rule-based parser first" plan.

Measured 2026-09-30:
- No agent knows about CVs. Personas are `agent-admin`, `agent-architect`, `agent-consultant` only.
- `parse-resume` extracts PDF text with a regex (first 6,000 characters) and sends it to **Google** `gemma-4-31b-it`: member resume text leaves Cloudflare. It also marks EVERY parsed upload `is_primary: true`, and writes AI-authored descriptions to `profile_experience` with no review.
- CF chat usage is unmetered: the `/ai/chat` proxy returns `usage: 0`, so `ai_usage` shows 9 consultant calls with 0 tokens (30 days). No per-member cap is possible until that is fixed.

## Design

1. Persona `w0m-personnel` (`ai_personas`) + alias `w0m-llm-personnel` (`ai_models`, Cloudflare, with a fallback) + edge function `w0m-personnel` with four one-shot actions: `parse`, `rewrite`, `summarize`, `tailor`. Authenticated members only, per-member daily quota from `ai_usage`.
2. **Suggestion-only.** The model returns a proposal; Studio shows a diff; nothing is stored until the member accepts. Keeps T498's rule: no claim the member did not author.
3. **Deterministic no-invention check** on every rewrite: numbers, company names, and technology names in the output must be a subset of the input's; otherwise the suggestion is rejected and the reason shown. No second model.
4. Resume text stays on Cloudflare: `parse-resume` moves to the CF alias (and stops forcing `is_primary`).
5. Model chosen by measurement: `scripts/ai-eval.ts` on a task set built from the owner's real bullets and resumes; candidates from the Workers AI catalogue (mistral-small-3.1-24b, llama-3.3-70b, glm-4.7-flash, kimi-k2.6). Catalogue pages do not state tool or JSON support for most models, so each is tested, not assumed.
6. Raw-upload gate before any model call: type, size, text layer present, language detected. Deterministic.

## Status notes

- 2026-09-30 build, test-first. **Scope decision:** T500 (renaming the EXISTING agents) is not Resume Studio work and the new names collide with nothing, so T501 was built with its final names (`w0m-personnel`, `w0m-llm-personnel`) and no longer waits for T500.
- **What exists (all committed, none deployed):**
  - `_shared/resume-assist.ts` (+ 22 Deno tests): the no-invention check (numbers by value, capitalised names, digits/symbols in names, a technology lexicon so a lowercase "terraform" is caught, spelled-out figures), the upload gate, language detection, grounded parse validation, tailor id validation, prompts.
  - `w0m-personnel/` edge function (+ 19 handler tests): authenticate, own profile (`current_profile_id()`), quota, validate, ownership of the file, gate, THEN the model, THEN the checks; a rejected suggestion is not returned in any field; usage logged against `user:<id>` and ESTIMATED (marked) when the proxy reports zero.
  - Migration `20260930100000`: alias `w0m-llm-personnel` (Cloudflare, provisional model), persona `w0m-personnel`, member INSERT/DELETE on `profile_cv_facts` (RLS, column grant, 200-row cap, length checks); proven on scratch Postgres incl. cross-member insert, ungranted column, cap.
  - wom7func `/ai/chat` now passes Workers AI token usage through (it always said 0). 3 tests.
  - Studio: Suggest rewrite (accept or discard), Suggest summary, Tailor to a job (pins ids; synthesis `pinnedHighlightIds`), Extract highlights + Add selected to my facts. 14 new component tests; 70 in the resume suite.
- **Findings the tests caught:** (1) the first no-invention check let a lowercase invented technology and a spelled-out number through: a lexicon and number words now close both; (2) a summary that names the member's own role needs the job titles as allowed context; (3) an employer already in the facts was not detected because loader keys and upload keys differ (`x:2025-11` vs `upload:x:2025-11`): the check compares the identity, not the key.
- **Known limits:** the check is a subset test on numbers, names and a technology list, not a semantic one (a bullet can be re-worded into a claim that reads stronger while adding no token); Spanish and Russian numerals are not recognised; PDF text extraction is the crude text-object scan the estate always used (a scanned PDF is refused with a message); Word files are refused.

## AC6 evaluation (2026-09-30, `scripts/resume-assist-eval.ts`)

Run through the production path (`/ai/chat`), with the function's own prompts and chunking, on the owner's own text: 12 English bullets, 2 Spanish and 2 Russian, 2 full resumes, one tailoring task. Scored by the same deterministic checks the function uses, so no model grades a model.

| model | rewrite accepted | language kept | parse: every chunk readable | employers | ungrounded dropped | tailor | p50 / p95 ms |
|---|---|---|---|---|---|---|---|
| **llama-4-scout-17b-16e-instruct** | 92% (11/12) | 4/4 | **2/2** | 21 | **0** | top-1 ok | **707 / 9,855** |
| llama-3.3-70b-instruct-fp8-fast | 92% (11/12) | 4/4 | 1/2 | 21 | 0 | top-1 ok | 752 / 10,511 |
| mistral-small-3.1-24b-instruct | 83% (10/12) | 4/4 | 2/2 | 21 | 5 | top-1 ok | 1,038 / 17,944 |
| qwen3-30b-a3b-fp8 | 100% (12/12) | 4/4 | 1/2 | 8 | 5 | top-1 ok | 10,487 / 20,677 |
| gpt-oss-120b | 67% (8/12) | 4/4 | 1/2 | 8 | 5 | top-1 ok | 4,642 / 34,356 |

**Chosen: llama-4-scout (primary), llama-3.3-70b (fallback).** Migration `20260930100000` was edited to say so before it was applied (it had not been applied live).

What the first run got wrong, kept as the reasons the numbers can be trusted now: (1) my harness printed Cloudflare's already-parsed JSON object as `[object Object]`, which made tailoring look broken for four models (the router's normaliser handles it; the harness now does too); (2) the output cap made whole-resume parsing fail for every model, because one 17k-character CV needs about 12.5k characters of JSON in one answer while the router caps a reply at 4,096 tokens. Parsing now runs in bounded chunks and merges (a real product fix, not just an eval fix); (3) the upload gate collapsed newlines, which hurt both the model and the chunker; (4) the no-invention check rejected `DApps` for `DApp` and `HP-UX` for `HPUX` (plural and hyphen variants of a name the text already had); it now compares names ignoring case, hyphens, dots and a trailing plural, while `C` vs `C++` and a new technology are still refused.

Limits: 12 bullets and 2 resumes is a small sample, single run, temperature 0.3, on one member's text; English bullets are the bulk of it. Re-run it when a model is swapped.

## Definition of Done

- A member uploads a resume and reaches tagged, editable highlights without any repo file changing.
- No suggestion the member accepted contains a claim absent from what they wrote.
- Resume text never leaves Cloudflare and Supabase.
