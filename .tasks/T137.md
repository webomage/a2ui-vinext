# T137 — Register and Offer the 4-Tier Audit Service

## Summary

Commercial packaging, SKU definition, pricing, intake workflows, and legal authorization architecture for Webomage's audit services, powered by the `wom7sec` toolchain ([[T111]]).

Structures the offering into **4 Progressive Access Tiers**:

1. **Tier 1 — Free Fast Public Audit (URL Only)**: Zero-credential, instantaneous self-serve web scan. Evaluates SSL/TLS, HTTP security headers (CSP, HSTS, CORS), DNSSEC, exposed public sensitive files (`.git`, `.env`), and cookie banner compliance. Functions as a high-conversion lead generation tool and front-door diagnostic.
2. **Tier 2 — Authenticated App Audit (Authorized Account on URL)**: DAST assessment of private web applications using test credentials, magic links, or session tokens. Tests IDOR/BOLA, RBAC role boundary enforcement, CSRF, authenticated XSS, session invalidation, and business logic flaws in client portals.
3. **Tier 3 — Code & Architecture Audit (Repo / Docs Access)**: Whitebox SAST, SCA, and software license review. Inspects source code in an air-gapped sandbox for vulnerabilities, secret leaks (Gitleaks), Open Source license cleanliness (GPL/AGPL viral copyleft risks), Web3 smart contract security (Solidity/Slither), and generates enterprise SBOMs.
4. **Tier 4 — Full Infrastructure & Cloud Audit (Cloud / DB / IAM Access)**: Deep posture assessment across cloud providers (AWS, GCP, Cloudflare, Supabase) and Kubernetes/container runtimes. Audits Supabase RLS policies, IAM least-privilege, network exposure, and FinOps cost optimization via `@k7` integration.

### Legal Authorization & Sandboxing Boundary

- **Proof of Ownership**: Tiers 2–4 require explicit, cryptographically signed or domain-verified Proof of Authorization before initiating scans, preventing illegal unauthorized testing.
- **Zero Exposure Guarantee**: All scans execute inside hardened, ephemeral sandboxes with zero exposure of internal Webomage credentials or databases, even when interacting with hostile target URLs or untrusted code containing malicious hacker agents or prompt injection traps.

## Acceptance criteria

- [ ] AC1 — **Tier 1 Free Fast Public Scan SKU & Self-Serve Landing**: Define the zero-friction public audit workflow (URL input → instant 60s scan → interactive web scorecard + lead capture gate for full report). Requires zero customer credentials and operates completely unauthenticated.
- [ ] AC2 — **Tier 2 Authenticated App Audit SKU & Safe Intake**: Define the intake workflow for providing test credentials / magic links. Includes safe credential handling (single-use / ephemeral test accounts only, encrypted transit) and automated boundary-checking to ensure tests remain within customer-owned domains.
- [ ] AC3 — **Tier 3 Code & Repo Audit SKU**: Specify private repo intake mechanisms (GitHub App OAuth with fine-grained read-only permissions, temporary deploy keys, or zip upload), language coverage, turnaround SLAs, and delivered artifacts (Executive Audit Report, License Cleanliness Matrix, SBOM).
- [ ] AC4 — **Tier 4 Full Infrastructure Audit SKU & Legal Scope Artifact**: Design the legally binding **Scope and Authorization Agreement (Letter of Attestation & Rules of Engagement)** detailing exact assets in scope, read-only guarantees, test windows, and zero-exploitation boundaries.
- [ ] AC5 — **Pricing & Packaging Matrix**: Define transparent pricing across all tiers (e.g., Free Tier 1; Fixed-price Tier 2/3 packages; Custom enterprise Tier 4 retainers), delta re-audit discounts, and subscription models.
- [ ] AC6 — **Client Intake & Registration Surface on Webomage Portal**: Build the client intake flow inside `apps/web` and `apps/join`, allowing prospective clients to request or initiate audits, sign engagement scopes, and view live report deliverables.
- [ ] AC7 — **Report Deliverable Standard & Remediation Punchlists**: Standardize executive summaries, technical vulnerability findings (CVSS/CWE), code-diff remediation patches, and compliance mappings (SOC 2, GDPR, HIPAA alignment).
- [ ] AC8 — **Dogfood Verification**: Execute all 4 audit tiers end-to-end against internal/test assets (`@k7`, demo staging apps) before opening public intake.
