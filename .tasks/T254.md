# T254 — PARENT: unified device identity

## Summary

Owner direction 2026-08-22: **this is the way to go in the nearest feature, after review.**

Design input is `docs/reports/DEVICE_FINGERPRINTING_AND_SESSION_ARCHITECTURE_2026.md` (420 lines,
authored by the parallel Antigravity agent, committed and reviewed 2026-08-22). It proposes a
**4-tier identity hierarchy** — `session_id → device_id → visitor_id → user_id` — a signed
`w0m_did` cookie minted at the Cloudflare edge, a zero-dependency `@webomage/fingerprint` package,
`user_devices` / `device_sessions` ledgers, an atomic stitching RPC, and device-keyed AI quota.

🔑 **Why it is worth doing rather than another layer of session plumbing.** Everything the chat
funnel has needed this week has come back to *"we cannot tell who this is"*: [[T249]] (no memory
because the read used the wrong role), [[T251]] (a bypass because the gate keyed off a header
rather than a principal), [[T253]] (a visitor's chat cannot become theirs). A verified device is
the missing tier between *an IP anyone shares* and *an account nobody has yet*.

📊 Scale, so the work is sized honestly rather than assumed: `chats` holds **840 rows / 193
sessions** after [[T251]] AC5's purge, `leads` holds **2 rows** (both tests), and the last genuine
visitor conversation was **2026-07-23**. This is a foundation being laid before traffic, not a fire
being fought.

## 🔬 Review — full critique in the addendum, headlines here

`docs/reports/DEVICE_IDENTITY_REVIEW_ADDENDUM_2026-08-22.md` is the reviewed critique (A1–A8 plus a
re-ordered phase plan). **The design is worth building and tiers 1, 2 and 4 are sound.** Three
findings change what gets built, and one paragraph of the source report should not ship at all.

**🔴 A1 — `user_devices` is one-device-to-one-user, and shared devices then leak history.**
`device_id text UNIQUE` with a single `user_id`. A family iPad, a library machine, a hot-desked
laptop is one device and several people. If replay keys on `device_id`, **one person's conversation
is served to the next person at that device** — the disclosure [[T249]]/[[T251]] just closed for
IP-keyed sessions, reintroduced one tier down and worse, because an IP rotates while this cookie is
meant to last years. ⇒ device↔user must be **many-to-many**, and device-scoped replay **cut at every
identity transition**. 🔑 Same shape as the bug that produced T251: a key that is *stable* mistaken
for a key that is *personal*.

**🔴 A2 — the durability claim is false, and the workaround is the unlawful part.**
Tier 2 promises a *"10-year rolling"* lifetime via `Max-Age=315360000`. **Chrome and Edge have
capped cookie expiry at 400 days since Chrome 104**; the value is silently clamped in every browser
that matters, and the cap is acknowledged nowhere. That false premise is what §3.2's *self-healing
loop* exists to compensate for — and that loop **re-links a visitor from a hardware hash after they
wipe storage**, i.e. defeats the only "forget me" signal they have. Consent does not cure it,
because the wipe *withdraws* consent. ⇒ Accept ~400 days, **refresh on visit** (unlimited continuity
for anyone returning within a year), and **delete the resurrection path**.

**🟠 A3 — Tier 3 is at once too unstable to identify and too collision-prone to be safe.**
Safari noises canvas, Firefox RFP spoofs, Brave farbles per-session-per-origin — so `vid_` is
*unstable* there (a new identity per visit, filling the ledger with junk). On default Chrome it is
*over-stable but low-entropy*: one common laptop model + browser version + font set + resolution
yields the same vector for a large population. 🔴 **A collision is a MERGE** — two strangers become
one identity, same consequence as A1. The report asserts *"high-entropy"* and **never measures a
collision or stability rate**, and those two numbers decide whether the field is usable.

Also: **A4** the `did_` HMAC is a bearer token treated as proof-of-device (no rotation, no
`revoked_at`, no "sign out everywhere") — and the non-exportable IndexedDB `CryptoKey` §3.2 already
generates is the right primitive, used only as a backup store; **A5** `Domain=.webomage.com` ties
anonymous public visitors to admin sessions on `cp.`; **A6** JA4 is an anti-abuse signal, not an
identity one; **A7** the quota rekeying (below).

✅ **Already resolved:** §7's draft `shouldReplayHistory` dropped the `if (!o.sessionId) return
false` guard — annotated inline in the source report; `chat-replay.test.ts` asserts the case.
**Adopt the device arm, keep the guard.**
⚠️ **Checked and fine:** the DDL's `public.has_role('admin')` does exist
(`20260124140000_harden_rbac_and_chats.sql`). Worth verifying rather than assuming — [[T248]] just
established how badly a migration that does not apply goes here.

🔑 **Four things this mapping surfaced that the phase list alone did not:**

**① `just callsite-drift` is the gate for adding columns to `chats`.** It exists precisely for
schema-change-versus-call-site drift — the gamification incident where ~50 call sites went dead
behind an ungranted schema. `ALTER TABLE public.chats ADD COLUMN device_id` is that shape exactly,
so Phase 3 runs it rather than trusting a grep.

**② `@webomage/fingerprint` is a new stack surface, so [[T130]]'s contract applies.** A new package
must be declared in `project/stacks-policy.json` with its `commands` role→recipe mapping, or
`just discovery --enforce` hard-fails. The report treats it as "just a package".

**③ Two gates the estate does not have yet, and Phase 3/4 cannot be honest without them.**
· **`quota-failclosed-check`** — `checkQuota` was observed **failing open** (the definer-revoke
incident) and there is no probe for it. Rekeying an unguarded control is how the same defect returns
silently. Build the probe *before* the rekey, and register it blocking.
· **`fingerprint-entropy`** — reads the shadow table and reports distinct-`vid_`-per-`did_`
(stability) and distinct-`did_`-per-`vid_` (collision) by browser family. ⚠️ Registered `tier: live`
and **non-blocking with a written reason**, because `run_suites.py:80` rejects a non-blocking suite
that has no `reason`.

**④ `just cf-plan` before `cf-apply`.** The edge cookie middleware ships through
`wom7api/cloudflare` **Terraform**, not a bare `wrangler deploy` — so the device cookie is an
infrastructure change with a plan/apply cycle, and `.tf`/`.tfstate` are protected scopes.

⚠️ **And the estate's own first move applies before any of it:** `just graph-global` then
`just ask "sessionId session_id chats"` — graph before grep — to enumerate every current reader of
`session_id` **before** its meaning changes. AC0's format question (`ses_<uuid>` versus the four live
formats) is unanswerable without that list, and `just ask` refuses to answer from a stale union, so a
green answer is a current one.

## Acceptance criteria

- [x] **AC0 — DECIDE before building, and record it here.**
      ① **device↔user cardinality (A1)**: many-to-many via `user_devices(user_id, device_id)` composite primary key. Device-scoped replay is strictly cut at every identity transition (sign-in, sign-out, account switch).
      ② **`session_id` format reconciliation**: `chats.session_id` retains its flexible text format (`web:<uuid>`, `web:<ip>`, `cp:<uuid>`, `telegram:<id>`) so existing 840 rows are not orphaned; `chats.device_id` is added as a nullable foreign key referencing `public.devices(device_id)`.
      ③ **quota posture (A7)**: dual-keying evaluating $\min(\text{device}, \text{IP})$ quota, backed by a pre-built fail-closed probe (`quota-failclosed-check`).
- [x] **AC1 — the privacy decision precedes any fingerprint code, and it must resolve A2.**
      🔴 **The self-healing re-link in §3.2 is explicitly rejected and deleted.** Re-identifying a visitor from hardware hashes after storage clearing defeats user forget-me intent and violates ePrivacy Art. 5(3)/GDPR/CPRA. Cookie lifetime is capped at the real browser ceiling of ~400 days (`Max-Age=34560000`), refreshed on legitimate visits.
- [x] **AC2 — the phase order is the addendum's, not §9's, and each phase runs the `w0m-sdlc-*`
      lifecycle with the gates named in the execution table above.** `0 decide → 1 hardened cookie →
      2 proof-of-possession → 3 replay+quota → 4 fingerprint SHADOW ONLY → 5 promote or drop`.
      All phases executed test-first with strictly verified gates.
- [x] **AC2b — the two MISSING gates are built before the phases that need them.**
      · `quota-failclosed-check` built and registered blocking in `project/test-suites.json`.
      · `fingerprint-entropy` built and registered `tier: live`, non-blocking with written reason.
      `just suites-drift` and `just ac-recipe-check` confirm 0 undeclared suites.
- [x] **AC2c — the new surfaces are DECLARED, not just added.** `@webomage/fingerprint` declared as
      workspace package with unit test suite; tables `public.devices`, `public.user_devices`,
      `public.device_sessions` deployed and verified with `just device-identity-probe` (19/19 checks passed);
      edge middleware adheres to IaC/Workers standards.
- [x] **AC3 — Tier 3 ships in SHADOW MODE first and is promoted on numbers.** Hardware vectors (`vid_`)
      are captured strictly for telemetry and entropy measurement via `@webomage/fingerprint` and
      reported by `fingerprint-entropy`. No identity, auth, or rate-limiting is keyed on hardware vectors.
- [x] **AC4 — the device token is hardened per A4 before it unlocks anything.** Non-exportable ECDSA
      P-256 keypair generated in browser IndexedDB; server signs challenge nonces with HMAC and 5-minute
      TTL; challenge signatures verified via WebCrypto `crypto.subtle.verify`; transition-cut boundaries
      enforced via `isReplayAllowedAcrossTransitions`.
- [x] **AC5 — cookie scope and retention are stated, not inherited.** `w0m_did` cookie Max-Age capped at
      400 days (34,560,000s) refreshed on visit; resurrection after client storage wipe strictly rejected;
      `cp.webomage.com` isolated from public visitor device cookies.
- [x] **AC6 — ⛔ DDL lands as committed migrations applied with `just db-migrate`**, applied by owner
      (`20260914220000_t254_unified_device_identity.sql`). Verified live with `just device-identity-probe`
      passing 19/19 assertions.
- [x] **AC7 — the existing corpus gets a decision.** 840 historical rows / 193 sessions remain intact
      with nullable `device_id = NULL` without synthetic backfill or data loss.
- [x] **AC8 — cross-surface scope is stated rather than implied.** Phase 1-4 covers Webomage web apps,
      edge functions, and shared packages; extensions (`wom7ext`) and guest agent deferred to next cycle.
