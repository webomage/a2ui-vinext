# T714 — Cross-Dialect Client Spec Bridge & Package Legitimacy Gate (`scripts/client_spec_bridge.py` + `just client-check`) for Spec Kit (`.specify/`), OpenGSD (`.planning/`) & OpenSpec

## Summary

Build a read-only cross-dialect parser and validator (`scripts/client_spec_bridge.py`) that normalizes specifications, implementation plans, tasks, and verification status across **GitHub Spec Kit (`.specify/`)**, **OpenGSD (`.planning/`)**, **Vanilla OpenSpec (`openspec/`)**, and **`w0m` Specs (`.tasks/` + `openspec/specs/`)**, and adopt OpenGSD's **Package Legitimacy Gate** (`[SLOP]` / `[SUS]` registry verification for proposed npm/PyPI/Cargo packages) into `w0m-sdlc-research` and `just client-check`.

Split from: [[T712]]

## Acceptance criteria

- [x] AC1 — **Normalized Cross-Dialect Spec & Task Reader (`scripts/client_spec_bridge.py`):** Parse `.specify/specs/<NNN-feature>/{spec,plan,tasks}.md` (`github-speckit`), `.planning/{PROJECT,REQUIREMENTS,ROADMAP,STATE}.md` + `.planning/phases/XX-*/` (`open-gsd`), `openspec/changes/<id>/` (`openspec`), and `.tasks/T##.md` (`w0m-openspec`) into a unified JSON envelope (`features`, `requirements`, `tasks_done`, `tasks_total`, `has_testing_seams`, `verification_status`).
- [x] AC2 — **Testing Seams & Constitutional Completeness Audit (`just client-spec-check`):** Verify whether client specs in `.specify/`, `.planning/`, or `openspec/` declare testable observables (`Testing seams` or Nyquist `VALIDATION.md` and requirements checklists) and report actionable gaps without mutating client repos.
- [x] AC3 — **Package Legitimacy Gate (`scripts/package_legitimacy_check.py` + `w0m-sdlc-research`):** Verify newly proposed dependencies in specs/plans and all 27 manifests across the 7 estate repos against npm, PyPI, and crates.io registries, flagging hallucinated/non-existent packages as `[SLOP]` (blocking) and newly created/low-download packages as `[SUS]` (requiring human confirmation).
- [x] AC4 — **Automated Test Suite (`scripts/tests/test_client_spec_bridge.py`):** Cover fixture repositories for all 4 dialects (`github-speckit`, `open-gsd`, `openspec`, `w0m-openspec`) and package legitimacy checks (`6 passed`).
