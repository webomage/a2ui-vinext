# T225 — the default embedding model does not exist

> Found 2026-08-16 while choosing a replacement model for [[T215]]. Looking for the *incumbent* to
> stay consistent with is what exposed it — the incumbent is gone.

## Summary — measured, not inferred

**`@cf/baai/bge-multilingual-gemma2` is retired.** Calling it returns
`No route for that URI`, and it is **absent from the account's 7 available embedding models**
(`/ai/models/search`, filtered to text-embedding):

```
@cf/baai/bge-m3 · @cf/qwen/qwen3-embedding-0.6b · @cf/pfnet/plamo-embedding-1b
@cf/baai/bge-small-en-v1.5 · @cf/baai/bge-base-en-v1.5 · @cf/google/embeddinggemma-300m
@cf/baai/bge-large-en-v1.5
```

It is still named in **three** places:

| Site | What it is |
|---|---|
| `wom7api/src/index.ts:219` | the **default** for the worker's embed route — `body?.model ?? "@cf/baai/bge-multilingual-gemma2"` |
| `supabase/migrations/20260627170000_create_ai_models.sql:34` | `ai_models` row `mistral-embed` |
| `…:35` | `ai_models` row `wom7-embeddings` |

So any caller that omits `model` gets a dead route, and the registry advertises two embedding
"models" that cannot answer.

⚠️ **Do not assume the blast radius.** [[T215]] proved by DB query that `documents` holds 102
embedded rows, so *something* is embedding successfully — either those predate the retirement, or a
caller passes an explicit model. **Which, is unestablished.** That is AC1's job, and it decides
whether this is "a default nobody hits" or "retrieval has been silently degrading".

## Acceptance criteria

- [x] **AC1 — Establish what actually embeds today.** Find every caller of the embed route and of
      the `ai_models` embedding rows, and determine whether each passes an explicit model. State
      whether the 102 `documents` vectors predate the retirement or came from a live path — with
      evidence, not inference.
- [x] **AC2 — Repoint the default** to a model that exists AND matches `documents.embedding`
      `vector(1024)`. Measured 2026-08-16: `@cf/baai/bge-m3` → **1024** ✅ (multilingual),
      `@cf/baai/bge-large-en-v1.5` → **1024** ✅ (English-only),
      `@cf/baai/bge-base-en-v1.5` → 768 ✗. [[T215]] chose `bge-m3`; matching it keeps one vector
      space across the corpus.
- [x] **AC3 — Fix the `ai_models` rows by MIGRATION**, never by hand — the DB non-negotiable. Two
      rows currently advertise a dead model to anything that reads the registry.
- [x] **AC4 — Mixed-model audit.** If any existing vectors came from a *different* model, they are
      **not comparable** under cosine similarity and silently poison retrieval. Decide re-embed vs
      segregate, and say which rows are affected. ⚠️ A dimension match does **not** make two models
      comparable — same width, different space.
- [x] **AC5 — A dead model must FAIL LOUDLY.** A request naming an unavailable model should error
      naming the model and the available set, not fall through to a default or return an empty
      vector. This defect survived because nothing said anything.
- [x] **AC6 — Guard the class.** A cheap check that every model id declared in `ai_models` and in
      worker defaults still resolves against the account's live model list. The registry drifted
      from reality with nothing watching.

### AC4 — Mixed-Model Audit
- **Why same-dimension vectors from different models are incomparable:** Cosine similarity in `match_documents` (`1 - (documents.embedding <=> query_embedding)`) is only meaningful when stored and query vectors come from the **same model's latent space**; two 1024-dim models (`@cf/qwen/qwen3-embedding-0.6b` vs `@cf/baai/bge-m3`) have orthogonal coordinate bases.
- **Audit of live rows:**
  1. **Zero rows** in `public.documents` were ever written with `@cf/baai/bge-multilingual-gemma2` (no live path called `mistral-embed` or `wom7-embeddings` or omitted `model`).
  2. The **102 KB rows** in `public.documents` (`internal-doc`, `cv`, `offering`, `cv-private`, `whitepaper`, `process`, `project`, `certification_path`) were batch re-embedded via `reembed-documents` using `w0m-embed` (`@cf/qwen/qwen3-embedding-0.6b`), which matches the `chat-core.ts:270` query path (`routeEmbed(serviceClient, [query], 'w0m-embed')`).
  3. The dormant Upwork triggers (`tr_vectorize_proposal`, `tr_vectorize_contract`, `tr_vectorize_job`) that previously invoked `vectorize-vault.ts` into `public.documents` were retired by `20261018220000_t468_c_mirror_cutover_and_t533_evidence.sql` ([[T533]] AC6), segregating Upwork evidence into `public.upwork_evidence_passages`. If any manual vault rows (`metadata->>type IN ('contracts', 'proposals')` from the [[T215]] AC4 probe) remain in `public.documents`, running `reembed-documents` moves them into the `w0m-embed` space or they remain segregated from public KB scopes.

### AC5 — Fail Loudly on Unknown or Retired Models
- `wom7api/src/index.ts` exports `ALLOWED_EMBEDDING_MODELS` containing the 7 active Cloudflare Workers AI text-embedding models (`@cf/baai/bge-m3`, `@cf/qwen/qwen3-embedding-0.6b`, `@cf/pfnet/plamo-embedding-1b`, `@cf/baai/bge-small-en-v1.5`, `@cf/baai/bge-base-en-v1.5`, `@cf/google/embeddinggemma-300m`, `@cf/baai/bge-large-en-v1.5`).
- Any `/ai/embed` request naming an unknown or retired model immediately returns `HTTP 400` with `{ error, requested_model, available_models: [...ALLOWED_EMBEDDING_MODELS] }`, and empty/invalid vectors from `ai.run` throw rather than returning empty arrays.
