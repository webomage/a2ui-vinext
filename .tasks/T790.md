# T790 — Sidebar collapsible role selector dropdown, default highest available role active, and offices catalog RLS policy

## Why

In `SidebarHatSwitcher.svelte`, selecting a project previously rendered all roles as an open, expanded list, and `sortProjectHats` placed `Client Stakeholder` first (rank 0), often defaulting users down to `client` or unstaffed mode even when senior contractor roles (`tech-lead`, `pm`, `dev`) were held. Furthermore, the Project Delivery Roles modal in CP displayed "Offices / Capability Bundles: No offices loaded." because the RLS policy on `public.offices` only allowed `is_admin()`, locking out w0m Co-Owners and managers.

## Scope

- **In:**
  - In `SidebarHatSwitcher.svelte`, collapse the project roles list by default under an interactive dropdown selector with chevron (`isRolesOpen = false`).
  - Introduce role seniority ranking (`getRoleSeniority`): `admin`/`root`/`super_pm` (100) > `tech-lead`/`architect`/`lead-engineer` (90) > `pm`/`project-lead` (85) > `devops`/`sre` (80) > `dev`/`engineer` (70) > `qa-engineer` (60) > `designer` (55) > `client` (10).
  - Update `sortProjectHats` to order hats by seniority descending.
  - Automatically make the highest available role active by default (`availableProjectHats[0]`) when a project is selected or loaded without an explicitly chosen role.
  - Author SQL migration in `w0m-api/supabase/migrations` granting scoped SELECT on `public.offices` to authenticated users with `is_admin() OR is_manager() OR is_w0m_owner() OR is_capable('engagement.staff')`, and add defensive fallback in `apps/cp/src/pages/api/project/roles.ts`.
  - Update unit and component tests in `apps/cp/src/components/admin/__tests__/ProjectManager.test.ts`.
- **Out:**
  - Changing underlying Postgres schema tables.

## Acceptance Criteria

- [x] **AC1 — Collapsible Role Selector:** In `SidebarHatSwitcher.svelte`, the roles list under a selected project is placed inside a by-default collapsed dropdown selector with a toggle button displaying the active role name and chevron.
- [x] **AC2 — Role Seniority Hierarchy:** Export `getRoleSeniority(roleSlug, category)` ranking roles from `super_pm` (100), `tech-lead` (90), `pm` (85), `devops` (80), `dev` (70), `qa` (60), `designer` (55) down to `client` (10).
- [x] **AC3 — Seniority-First Ordering:** `sortProjectHats` sorts available project hats by seniority descending so senior delivery roles appear first.
- [x] **AC4 — Default Highest Active Role:** When switching or initializing a project, if no explicit role has been chosen in the session, automatically activate `availableProjectHats[0]`.
- [x] **AC5 — Offices Catalog Scoped RLS Policy:** Author migration in `w0m-api/supabase/migrations` permitting managers, co-owners, and staff to SELECT `public.offices`, and update `apps/cp/src/pages/api/project/roles.ts`.
- [x] **AC6 — Vitest & Typecheck Gates:** Update `ProjectManager.test.ts` to assert the collapsible dropdown and highest role default, passing all Vitest suites and Svelte typecheck ratchets.
