# T476 — /me/account: privacy, PKCE identity linking, one identity section

## Summary

Owner, 2026-09-27, with a screenshot of `/me/account` whose address bar held `#access_token=…`:
*"what this 2 parts do different way and intended to do initially? why there are two parts with
similar functions after all?"*, then *"go"* on the proposed fix order.

The page carries two sections that grew up separately:

- **Connected Identities** (`ConnectedIdentities.svelte`) — Supabase Auth identities: which
  providers can SIGN IN as this person. Real, server-backed (`auth.identities`).
- **External Service Mapping** (`ConnectedServices.svelte`) — handles on outside services
  (GitHub, Upwork, …) used for attribution and sync. Stored in the browser's `localStorage`, with
  the founder's own handles as defaults.

Measured defects, in the order they are fixed:

1. **Privacy.** Every person saw the founder's data. `ConnectedServices` defaulted handles to the
   founder's, and rendered three hardcoded Upwork accounts (the founder's org ids).
   `ResumeStudio` showed the founder's CV files to anyone with no documents, on any load error.
   The localStorage keys were not scoped per person, so a shared browser crossed people.
2. **Token in the URL.** "Link" called `linkIdentity` in the browser with the implicit flow, so
   the provider returned `#access_token=…&refresh_token=…` to the page: visible in the address
   bar, in history, and to any screenshot (the owner's was one).
3. **Two sections, one concept.** Service mapping belongs in `social_integrations` (server-side,
   per person), and the Upwork card reads the [[T468]] mirror instead of a hardcoded list.

## Acceptance criteria

- [x] AC1 — **No person sees another person's data on `/me/account` or the resume studio.**
  `ConnectedServices` handles default to empty, storage keys are `member_mapping_<sub>_<service>`,
  the hardcoded Upwork cards are gone, and the MCP status starts "unknown" rather than a claimed
  state. `ResumeStudio` shows only the person's `profile_resumes` rows, and an error shows an
  error, not someone else's files. Guard: `apps/cp/src/lib/__tests__/no-personal-data-in-components.test.ts`
  fails on the founder's handle, slug or Upwork org ids in any CP component or page (public footer
  brand links reviewed and allowed). `ResumeStudio.test.ts` asserts the empty state.
- [x] AC2 — **Identity linking is server-side PKCE.** `GET /api/auth/link?provider=…`
  (`handleLinkIdentityStart` in `packages/lib/src/auth/handlers.ts`) starts `linkIdentity` on
  the SSR client with `skipBrowserRedirect`, so the provider returns a code to
  `/api/auth/callback`, never a token in the URL. A failure comes back as `?link_error=` and is
  shown. The page also strips any leftover `access_token`/`refresh_token` fragment on load.
- [ ] AC3 — **Verified live after deploy:** linking a second Google account from `/me/account`
  ends on `/me/account` with no `#access_token` in the URL and the new identity listed; a signed-in
  non-founder sees no founder handles, Upwork cards or CV files.
- [ ] AC4 — **One identity section.** Service handles move from `localStorage` to
  `social_integrations` (migration + RLS: owner-only read/write), rendered inside the identities
  section; `ConnectedServices` is deleted, not kept beside it.
- [ ] AC5 — **The Upwork card reads the [[T468]] mirror** (`upwork` schema via its RPCs), showing
  the person's own synced accounts, or nothing.
