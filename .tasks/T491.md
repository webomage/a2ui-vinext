# T491 — `wom7func` was chosen on 2026-09-18; is it the right name, and what does the third rename cost?

## Summary

Owner 2026-09-29: consider renaming `wom7func` again (`wom7fn` / `wom7edge`), choosing the suffix from its content and from the
fact that it is the Cloudflare stack while `wom7api` holds Supabase. **Measured today** (`just name-refs`, `git`, file counts):

- **What `wom7func` is:** 28 source files. 2 Workflows (`document-generator`, `job-scanner`), an AI proxy (`/ai/chat`, `/ai/embed`),
  an ATS service (`services/ats`: huntflow, factory, merge), a Browser binding, and `scheduled()` cron (5 triggers, the account's
  whole cron budget). Deployed as the `wom7func` script; `https://wom7func.webomage.workers.dev/health` answers 200.
- **The stack split is NOT clean today.** `wom7api` holds Supabase (65 edge functions, 309 migrations) AND the larger Cloudflare
  worker (`src/`: 22 workflows, 20 Durable Object class bindings, deployed as `wom7api`). `wom7func` is the smaller CF repo.
  A suffix cannot honestly say "the CF stack" while the biggest CF worker sits in the Supabase repo.
- **The estate's own vocabulary already spends the obvious words:** `edge` = Supabase Edge Functions (`stacks-policy.json` stack `edge`
  -> wom7api, recipes `edge-local`, 65 functions); `func`/`fn` = Supabase `functions/` (`deploy-functions`, `supabase/functions`);
  `worker` = wom7api's `src/` (`typecheck-worker`, `deploy-workers`). The word already registered for THIS repo is **`cf`**:
  `stacks-policy.json` stack `cf` -> wom7func, recipes `cf-test` / `cf-typecheck` / `cf-plan` / `cf-apply`, and the `TASKS.md`
  legend "`cf` = …".
- **Cost of any rename:** `just name-refs wom7func` = **199 live references** in 11 repos (50 code, 56 config, 29 spec, 58 docs,
  3 paths, 2 remotes, 1 env-default), 12 generated, 220 allowed to keep. The previous rename left 144 live references behind after
  being recorded as complete (LESSONS: *A name lives in eleven places*).
- **Two things a repo rename must NOT be confused with:** the deployed Worker script name (`wrangler.jsonc` `name`, its
  `workers.dev` host, cron triggers, bound Workflows) and the value of the `WORKERS_WEBHOOK_URL` secret, which is a URL of it.
  The 2026-08-01 script-name collision (two repos, one script, 19 orphaned Workflows) is why those are separate decisions.

## Weighted decision (owner picks; scores 1-5, higher is better)

| Option | Ambiguity vs estate vocabulary (x3) | Fits registry / recipes / ticket tags (x3) | Rename cost (x2) | Says what it is (x1) | Total /45 |
|---|---|---|---|---|---|
| A. keep `wom7func` | 2 ("func" = Supabase functions) | 3 | 5 (0 refs) | 2 | **6+9+10+2 = 27** |
| **B. `wom7cf`** | **5** (no collision) | **5** (`cf` stack, `cf-*` recipes, ticket alias) | 2 (~200 refs) | 3 (names the platform, not the role) | **15+15+4+3 = 37** |
| C. `wom7edge` | 1 (collides with Supabase Edge Functions) | 1 | 2 | 2 | 3+3+4+2 = 12 |
| D. `wom7fn` | 2 (same collision as func, shorter) | 2 | 2 | 2 | 6+6+4+2 = 18 |
| E. role name (`wom7cron`, `wom7jobs`) | 3 (`jobs` collides with the job board app) | 1 | 2 | 4 (only true if the repo stays this small) | 9+3+4+4 = 20 |

**Recommendation: B, `wom7cf`, done once, and after T492 (so paths move once).** Rejected: C (would make "edge" mean two things in
one estate) and D (same collision as today, plus churn). Not recommended: renaming AGAIN for a marginal gain — A is a legitimate
answer if the owner values zero churn; the loss is a permanent "is `func` Supabase or Cloudflare?" question.
**Sub-decision:** repo/folder/remote rename does NOT require renaming the deployed script. Recommend keeping the deployed script
`wom7func` until the secret values are changed in the same window, and recording why in `wrangler.jsonc`.
**Larger question, separate ticket if wanted:** move `wom7api/src` (the CF Workflow host) into the CF repo so that "CF = one repo,
Supabase = the other" becomes true. High risk (script identity, 20 DO classes, 22 Workflows); do not fold it into a rename.
