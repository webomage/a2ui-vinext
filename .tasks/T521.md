# T521 — mmd-validate as a portable tool for client projects

## Summary

Owner direction, 2026-10-01: *"mmd-validate should become a w0m skills tool and be available via it for client projects as well."*
This replaces the narrower plan in [[T508]] (record `sandboxed: false` for it in the w0m policy and leave it at that).

Today it is the opposite: `wom7skills/GENERIC-SDLC-SET.md` classes `mmd-validate` as **w0m-bound** and the generic installer
**withholds** it from clients. `wom7skills/portability.jsonc` records the reason and the way out:
`"why": "instructions hardcode wom7skills/skills/mmd-validate and --root ../../../wom7web"`, `"fixable": true`. Nothing in the
tool itself needs w0m: `validate.mjs` uses `mermaid` and `jsdom` and reads files, with no network call, child process or file
write (read 2026-09-30). The doc says plainly that fixing those instructions is "separate work", and this is that work.

## Measured state (2026-09-30 and 2026-10-01)

- Canonical source `wom7skills/skills/mmd-validate/`: `validate.mjs`, `test.mjs`, `package.json` (`mermaid ^11`, `jsdom ^25`), `SKILL.md`.
  Its `node_modules` (about 8,100 files) is gitignored, so dependencies are installed per consumer, not shipped.
- Invoked in the estate by `just mmd-validate` and `mmd-validate-test` (`node ../wom7skills/skills/mmd-validate/validate.mjs`) and by a
  pre-commit hook on staged files.
- The client `artemio` already carries a vendored copy and a `lint-mmd` recipe that runs **w0m's** `wom7skills` checkout by absolute
  path, so the vendored copy never runs there and the recipe breaks on any other machine. Client repos are owner-write-only, so this
  ticket records it and the owner repoints it.
- The skills catalogue ([[T508]]) flags it as `sandboxed: true` (inherited default) while it runs on the host: the label question is
  settled by this ticket's AC6.

## Acceptance criteria

- [x] AC1 — **Measure the binding exactly.** List every line of the skill (`SKILL.md`, `validate.mjs`, `test.mjs`, `package.json`) that
  names a w0m path, repo or file, and which installer marker (`.w0m/config`, `wom7-repo-path`, `TASKS.md`, ...) each trips. The fix list
  comes from this measurement, not from the one-line note in `portability.jsonc`.
- [x] AC2 — **The skill locates itself.** Its instructions and `just` snippets resolve the script from the skill's own installed
  directory and take the scan root as an argument, with no `wom7skills/...` or `../../../wom7web` path left. Verified by running it from a
  scratch directory that contains no `wom7*` folder.
- [x] AC3 — **Classification flips and the installer ships it.** `portability.jsonc` moves it from `fixable` to portable, the
  installer's drift probe agrees (it classifies by content, so the probe must pass without a manual override), and the GENERIC-SDLC-SET
  counts and lists are updated in the same change.
- [x] AC4 — **It works in a client-shaped project.** A fixture project with `.mmd` files and a Markdown file with a `mermaid` fence:
  a valid diagram passes, a broken one fails with a useful message, and a missing `jsdom` or `mermaid` exits non-zero rather than
  skipping (the existing `mmd-validate-test` already requires this; keep it). Registered in `test-suites.json`.
- [x] AC5 — **Dependencies are handled, not assumed.** The install path states how `mermaid` and `jsdom` reach a client (declared in
  `package.json`, installed by the client's package manager, or provisioned by the installer) and fails with a clear message when they
  are absent.
- [x] AC6 — **The sandbox label is a recorded decision.** `project/policies/skills-policy.json` gets an override with a reason for
  `mmd-validate` (and `artemio:mmd-validate`), proposed by the agent and approved by the owner: it reads files and runs on the host in a
  hook, so `sandboxed: false` with the reason "read-only, offline, hook-invoked" is the honest value. The skills catalogue stops
  flagging it.
- [x] AC7 — **Canonical edit procedure is followed.** Changes are made once in `wom7skills/skills/`, version-stamped before the sync,
  synced to every consumer and re-locked (`relock`, not `update`), per the skills governance rule. The estate's three consumers
  (root, wom7web, wom7api) are checked afterwards ([[T512]] makes this one command).
- [x] AC8 — **Clients are told, not written to.** The `artemio` absolute-path recipe is reported to the owner as a finding with the
  one-line repair (use the vendored copy). Nothing is written to any client repository by this ticket.

### AC8 — One-Line `artemio` Repair (Owner-Only Client Repo Action)
In `artemio`'s `justfile` (after running `cd .agents/skills/mmd-validate && npm install` once in `artemio`), replace the absolute-path `lint-mmd` recipe with:
```just
lint-mmd *files:
    node .agents/skills/mmd-validate/validate.mjs {{ if files == "" { "--root ." } else { files } }}
```
*(No client repository was modified by this ticket.)*
