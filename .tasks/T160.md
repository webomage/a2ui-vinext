# T160 — the verify gate's own command does not run the gates

## Summary

`.w0m/sdlc.json → commands.test` is `just test`, which runs **vitest only — 1 test**. Every
Python gate suite in the estate runs *only when someone names it by hand*:

| suite | checks | run by `just test`? |
|---|---|---|
| `just ac-progress-test` | 14 | ❌ |
| `just ac-trace-check` | 155 tickets | ❌ |
| `just mcp-declared-test` | 30 | ❌ |
| `just mcp-ratchet-test` | 35 | ❌ |
| `just discovery-test` | 28 | ❌ |
| `just sync-tickets-test` | call-count assertions | ❌ |
| `just test` (vitest) | **1** | ✅ |

**The w0m-sdlc-verify gate instructs the agent to "run `commands.test`".** Following that
instruction literally produces a green verification while none of ~110 checks execute. The gate
that exists to stop false greens is itself the source of one.

Found 2026-08-01 at [[T154]]'s verify gate — the change under verification had 30 checks, and the
prescribed command ran none of them. Recorded as **D25** in `TECH-DEBT.md`; filed as a ticket
because it is not debt to be tolerated, it is a broken gate.

## Why P0

Not for blast radius today — nothing is on fire. It is P0 because **it silently degrades every
future ticket's verification**, and this estate's recurring defect is precisely a green check over
an unasked question. Every gate built after this one inherits the flaw: writing a new suite and
adding a `just` recipe is *not enough* for it to ever run.

## Acceptance criteria

- [x] AC1 — `just test` runs **every** gate suite, not just vitest. Composition, not replacement:
      the JS and Python suites both run and a failure in either fails the whole command.
- [x] AC2 — the aggregate reports **how many checks ran**, per suite. A total is the only thing
      that makes "it passed" falsifiable — "0 checks passed" must be distinguishable from
      "110 checks passed".
- [x] AC3 — **fails closed on a missing suite.** If a declared suite's script is absent or
      unrunnable, `just test` FAILS rather than skipping it quietly. A skipped suite that reports
      green is the exact defect this ticket exists to remove.
- [x] AC4 — the suite list is **declared, not hardcoded in a shell loop** — a registry
      (`project/*.json` or `.w0m/sdlc.json`) so adding a gate means adding an entry, and a
      declared-but-missing entry trips AC3.
- [x] AC5 — a **drift check**: any `*-test`/`*-check` recipe in the justfile that is not in the
      registry is reported. This is the [[T130]] `discovery` pattern applied to test suites, and it
      is what stops the registry going stale the way this gap did.
- [x] AC6 — **proven RED**: with one suite deliberately broken, `just test` fails and names it.
      Verifying only the green path is how this was missed.
- [x] AC7 — `w0m-sdlc-verify` documentation updated so the gate's instruction and its effect agree.

## Delivered 2026-08-02

`just test` is now the aggregate: **146 checks across 19 suites**, up from 1.

| | |
|---|---|
| registry | `project/test-suites.json` — 21 recipes declared, 1 excluded with a reason |
| runner | `project/scripts/run_suites.py` |
| tiers | `just test` = **offline** (no secrets, bare checkout) · `just test-all` adds live |
| drift | `just suites-drift` — found **2 undeclared** on its first run (`model-test`, `skill-test`) |
| self-proof | `just run-suites-test` — 10 checks, in the registry itself |

**AC7 needed no doc change, which is the point.** `.w0m/sdlc.json → commands.test` still says
`just test`; the fix made the instruction *true* rather than rewording it. A gate whose
documentation has to explain that its command does not do what it says is not fixed.

⚠️ **`license` is registered `blocking: false` with a written reason** — 209 findings, tracked
under T135 §license. Blocking on it would make `just test` permanently red, and a permanently red
gate gets muted; that is the same reasoning that split `mcp-ratchet` from `mcp-exposure`. The
runner **refuses a registry** where a non-blocking suite carries no reason.

**Proven RED twice.** Nine unit cases cover every false-green path (empty registry, missing
recipe, advisory-without-reason, excluded-without-reason, tier with no suites). Then a live
mutant: a declared suite whose recipe does not exist made `just test` exit **1** and name
`planted-mutant`, with the restore verified.

## Notes

⚠️ Consider the runtime. Adding ~110 checks to `just test` is fine; adding a network-dependent
one is not — `ac-trace-check` and the ratchet tests are offline and fast, but anything needing
`DATABASE_URL` or a live socket belongs behind a flag, or the aggregate becomes something people
skip. A gate that is slow enough to route around is a gate that gets routed around.
