# T762 — Trigger overlay CI build when the latest release is older than beta

## Summary

`scripts/orca_overlay_update.py` only dispatches a fresh overlay CI build when
*no* GitHub release exists at all (`_gh_json(.../releases/latest) is None`).
When a stale release predates the `beta` HEAD (the common case after any
push), `apply_overlay --wait-for-ci` silently applies the outdated overlay
instead of refreshing it. Additionally, `trigger_overlay_build` never reports
the id of the run it just dispatched, so the wait path can attach only by a
coincidental discovery race (5x3s polling after dispatch).

Fix (single file, working-tree change already staged in `/tmp/t762-orca-overlay.patch`,
recovered from an unticketed live-root edit):

- `trigger_overlay_build`: after a successful dispatch, poll up to ~12s
  (6x2s) for the run to appear and report it, so callers wait on the *actual*
  run.
- New `_is_latest_release_older_than_beta()`: compares `releases/latest`
  `published_at` against `commits/beta` commit date; a missing release counts
  as stale.
- `apply_overlay`: triggers a fresh build whenever the latest release is
  older than `beta` HEAD, not only when no release exists; per-dispatch
  run-id discovery collapses into `trigger_overlay_build`.

## Acceptance criteria

- [ ] AC1 — With a release older than `beta` HEAD, `apply_overlay --wait-for-ci`

- [ ] AC2 — `trigger_overlay_build` polls for the dispatched run id (up to
