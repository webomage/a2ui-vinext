# T478 — Local full regression with a provisioned test team

## Summary

Owner, 2026-09-28, after [[T476]]'s live check could not sign in as anyone but the founder:
*"let's go do fixes with test account provisioning for member for full regression tests while we
have master all of them at local side first"*, then *"for local tests we can create full team and
emulate client hats well and do not afraid to hit live free tier limits"*.

Measured 2026-09-28:

- The local stack exists ([[T238]]: `just db-local-up`, `db-local-seed`, `e2e-local`), but its
  schema is `supabase/baseline/schema.sql` from **2026-08-19**; **80 migrations** have landed since,
  including all of [[T458]]'s org model. Specs touching those tables fail on schema, not on product.
- No test accounts exist anywhere. `TEST_USER_EMAIL`/`TEST_USER_PASSWORD` and `DEMO_*_PASSWORD` are
  absent from Infisical `beta`; `ADMIN_EMAIL` there is a Google-only login, so the **17** specs that
  "Login as test Administrator" cannot sign in, and the **2** member specs have no account.
  `tests/helpers/auth.ts` fails closed on both (correct since `adc1fd7b`), and must stay env-only.
- The seed restores today's backup rows (`backup_20260928_081512.sql`), real users included.
- 193 Gauge specs.

Owner decisions, 2026-09-28: Docker.app as the runtime; **replay the post-baseline migrations**
rather than regenerate the baseline from live; the public static CV (`/cv/*.pdf`) is decided later.

## Acceptance criteria

- [ ] AC1 — **The local schema is current.** `just db-local-up` applies the baseline, then every
  migration newer than it, in order, and fails on the first error (no `ON_ERROR_STOP=0` for this
  part). Measured: local ledger count equals `ls supabase/migrations/*.sql`, and a migration that
  does not replay is fixed in a new migration, never skipped.
- [ ] AC2 — **`just test-team-local` provisions a full team on the LOCAL stack only.** Refuses any
  non-loopback Supabase URL. Accounts on `@test.webomage.com`, random passwords per run, written
  only to the gitignored `env/local/generated.properties`. Roster follows [[AgDR-0027]] /
  [[AgDR-0028]] as the schema stands: platform root (the one admin), operator company owner and
  member, client company main person wearing the client hat, an engagement with its minimum hats,
  a recruit, a person with only a personal org. Idempotent; re-running converges.
- [ ] AC3 — **`just e2e-local` signs in as the test team**, not beta's `ADMIN_EMAIL`: the admin,
  member and client credentials come from the generated file, and every Supabase pointer stays on
  loopback (the teardown safety of [[T238]] unchanged).
- [ ] AC4 — **Full corpus run locally, every failure triaged** as product defect, test defect, or
  environment, with counts recorded here; product and test defects fixed or split into tickets.
- [ ] AC5 — **Uploaded resumes link by signed URL.** `ResumeStudio` calls `getPublicUrl` on the
  private `resumes` bucket for any `storage_path` outside `cv/`, which cannot resolve.
- [ ] AC6 — **Open: is `/cv/Aleksei_CV_2025.pdf` meant to be public?** Served 200 without auth on
  `cp.w0m.xyz`, `cp.webomage.com` and `webomage.com`. Owner decides later.
- [ ] AC7 — **Live provisioning is a separate, owner-run step:** the same roster against `beta`
  behind the Touch ID confirm gate, secrets set in Infisical by the owner. Split into its own ticket
  if it is not done here.
