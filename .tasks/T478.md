# T478 — Local full regression with a provisioned test team

## Summary

Owner, 2026-09-28, after [[T476]]'s live check could not sign in as anyone but the founder:
*"let's go do fixes with test account provisioning for member for full regression tests while we
have master all of them at local side first"*, then *"for local tests we can create full team and
emulate client hats well and do not afraid to hit live free tier limits"*.

Measured 2026-09-28:

- The local stack exists ([[T238]]: `just db-local-up`, `db-local-seed`, `e2e-local`), but its
  schema is `supabase/baseline/schema.sql` from **2026-08-19**; **80 migrations** have landed since,
  including all of [[T458]]'s org model. Specs touching those tables fail on schema, not on product.
- No test accounts exist anywhere. `TEST_USER_EMAIL`/`TEST_USER_PASSWORD` and `DEMO_*_PASSWORD` are
  absent from Infisical `beta`; `ADMIN_EMAIL` there is a Google-only login, so the **17** specs that
  "Login as test Administrator" cannot sign in, and the **2** member specs have no account.
  `tests/helpers/auth.ts` fails closed on both (correct since `adc1fd7b`), and must stay env-only.
- The seed restores today's backup rows (`backup_20260928_081512.sql`), real users included.
- 193 Gauge specs.

Owner decisions, 2026-09-28: Docker.app as the runtime; **replay the post-baseline migrations**
rather than regenerate the baseline from live; the public static CV (`/cv/*.pdf`) is decided later.

## Status notes

- 2026-09-28 — **AC1 and AC2 met locally; replay was not viable, baseline regenerated (owner's call).**
  Replaying the 78 post-baseline migrations stopped at 22/78: a schema-only baseline has no catalogue
  rows (`offices`, `capabilities`) and later migrations insert against them; no backup from
  2026-08-19 exists to supply them (oldest is 2026-09-20). Owner chose to regenerate. Found and fixed
  on the way: the schema list was hand-kept in four places and missed T468's `upwork` (now
  `db_baseline.OWNED_SCHEMAS`); T206's 7 `svc_*` roles are cluster objects no schema dump carries (48
  policy errors; now derived from the dump's policies, attributes read from live, written as an
  idempotent prerequisite); the empty-DB check lacked gotrue's `auth.jwt()` (created in the throwaway
  container only); the replay boundary is live's own ledger written into the baseline header, not
  "the commit that last changed schema.sql" (which replayed 78 migrations onto a schema that had them).
  Measured: `db_baseline --verify` 134/134 tables, 0 errors; `db-local-up` ledger 304 = 304;
  `db-local-seed` 136 tables of rows, 0 errors. `just test-team-local`: 7 accounts, every non-admin
  with a personal home, client hat from the `client_users` trigger, 3 project hats; re-run converges;
  all 7 sign in (GoTrue password grant 200). **Nobody is a webomage team member**:
  `wom_operator_home_gate` admits only @webomage.com and tests live on @test.webomage.com, so the team
  are contractors on a test engagement rather than weakening the gate.

- 2026-09-28 — **Run 1 (148 local specs, edge functions served): 271/435 scenarios passed, 164
  failed, 38m47s.** 45 of 193 specs excluded because they target live (6 `specs/live`, 33 name a
  live host in the spec text, 6 whose steps hardcode a live URL). Triage found four environment
  defects before any product one, all fixed:
  1. **Test sign-in never produced a session CP reads.** `signInViaRestApi` injected
     `sb-access-token` on the E2E_BASE_URL host; the server reads only the @supabase/ssr cookie
     (F1) and CP loads from PUBLIC_CP_URL. Every CP page bounced to `/login` "Session expired" for
     every persona — the largest single cause. Now it signs in through each app's own
     `/api/auth/signin`.
  2. **No role claims locally.** The local auth server had no custom access-token hook (live has
     `pg-functions://postgres/public/wom_access_token_hook`), so JWTs carried no `wom_roles` and the
     admin landed on `/me` as VIEWER. `config.toml` now carries live's hook and TOTP settings.
  3. **Admin without MFA.** Live requires TOTP for admin and manager (T463/T465); with roles fixed
     the admin landed on `/me/account?mfa_required=1`. `test-team-local` enrolls a verified TOTP
     factor through the real GoTrue flow; the helper answers `/api/auth/mfa/challenge-verify`.
  4. **The teardown deleted the team.** `@AfterSuite` purges `@test.webomage.com`, which is the
     provisioned team; it now skips accounts marked `test_fixture = "T478 test team"`.
  Also found: the baseline was dumped `--no-privileges`, so local grants were the image defaults
  (service_role denied on `ai_models`, 14/136 tables with no ACL); it now carries live's grants.
  Verified by probe after the fixes: admin reaches the Admin Console; member is kept on `/me`;
  all 6 classed personas get the right `wom_roles`. Run 2 measures what is left.
- 2026-09-28 — **🔴 Run 2: 237/435; and the local runs WROTE TO LIVE.** 31 of run 2's 34 new failures
  were the helper signing in a second time on the web origin, replacing CP's aal2 cookie (cookies are
  host-scoped, not port-scoped; prod scopes them to `.webomage.com`) — fixed, `27f02f11`. Triage of
  the 71 failures common to both runs then found the incident: ~25 step implementations hardcoded
  `https://<ref>.functions.supabase.co/<fn>`, and the exclusion scan matched `<ref>.supabase.co` but
  not the functions host. Read-only on live: **12 rows in `public.contact_messages` (ids 819–830),
  3 per session at 10:08, 10:26, 17:23, 17:51 UTC**, all synthetic (`test@example.com`, one with no
  email, one "bypass"). No other table gained a row (`job_applications`, `scraped_jobs`,
  `profile_snapshots`, `crawl_queue`, test-domain `auth.users`: 0). Every other live call carried a
  local credential and was refused. Two live `contact-submit` defects surfaced by it: a row stored
  with **no email** (the spec expects a rejection), and "bypass" accepted — probably via the
  `E2E_ACCESS_SECRET` bypass header, a beta secret the gauge process receives.
  **Fixed so it cannot recur:** `tests/support/liveGuard.ts` refuses live hosts in-process (Node
  fetch, `page.request`, browser) whenever the run's Supabase is loopback; `liveGuard.probe.mts`
  (10/10) runs first in `e2e-local`, which refuses to start if it fails; 42 hardcoded live URLs and
  `env || live` fallbacks replaced with fail-closed `urls.ts` `SUPABASE()`/`fnUrl()`, evaluated lazily
  (`d51f83c5`, `46d2af8`). Run 3 proved it: the guard refused 3 live calls (2 × contact-submit from a
  spec whose TEXT names the functions host — the spec-level scan had the same regex bug — and one
  browser GET of webomage.com), and live gained **0** rows after 18:04 UTC.
  **Run 3 stopped, not measured:** another session's uncommitted `tests/helpers/auth.ts` imports a
  `./mailpit` stub that re-exports an unresolvable `@webomage/lib/mailpit`, so every step file using
  the sign-in helper fails to compile (TS2305/TS2307). Left untouched — not this ticket's file.
  **Owner decisions open:** delete live `contact_messages` 819–830; the two contact-submit defects.
