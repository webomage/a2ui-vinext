# T227 — run gates against the built artifact, not the dev server

> Split out of [[T222]] AC1 ① at owner request, 2026-08-16: *"let's separate built of local wrangler
> dev with --remote for goldens as a separate independent ticket."* T222 closes without it.

## Summary — the gap, stated precisely

Every gate that drives a browser today runs against **`astro dev`**. That is a different artifact
from the one that ships:

| | dev server | built worker |
|---|---|---|
| bundling | on-demand, unminified | rolled up, minified, hashed |
| adapter | dev shim | `@astrojs/cloudflare` entry |
| bindings | none | KV · R2 · D1 · services · DOs |

So a defect introduced by the **build** — a broken asset hash, an adapter-only code path, a
minifier changing behaviour — passes every gate and reaches production. [[T216]] is the worked
example: the icon-routing bug lived in code that only executes in a real render, and typecheck,
build and the golden gate were all green while the page downloaded **3× the bytes**.

## Why it was split out rather than done inside T222

Measured on the current build (`apps/web/dist/server/wrangler.json`):

- **`services`: `WOM7API`, `CF_WORKERS`** — bindings to *other deployed Workers*. `wrangler dev` in
  local mode cannot fulfil them; it needs `--remote`, which then touches **real** infrastructure.
- **`kv_namespaces`: `SESSION`, `SETTINGS`** with real ids · plus `r2_buckets`, `d1_databases`,
  `durable_objects`.

Standing that up on **every deploy** is slow and adds a new failure mode to a path that broke four
times on 2026-08-16 alone. That is a piece of infrastructure with its own design, not a line in
another ticket's AC.

## Acceptance criteria

- [x] **AC1 — Decide the mode, with the trade-off written down.** `--remote` touches live KV/R2/D1
      and real service bindings — a *test* that can mutate production state. Either scope it to
      read-only surfaces, or use throwaway namespaces. ⚠️ Do not hand-wave this: the estate has
      already had a test delete a live deploy's consent and bury 32 of 33 deploy transcripts
      ([[T224]]) — a probe writing where the product writes is a known, repeated failure here.
      **Decided & implemented (`2026-10-26`):** `wrangler dev --remote` is rejected for automated
      gates because `apps/web/dist/server/wrangler.json` binds to live production KV (`SESSION`,
      `SETTINGS`), R2 (`wom-public-assets`), and live Workers (`wom7func`, `wom7api`). Instead,
      `w0m-web/project/scripts/serve_built_artifact.py` generates a sanitized local config
      (`wrangler.local-gate.json` next to `apps/web/dist/server/wrangler.json`) that preserves
      `main: "entry.mjs"`, `assets: {"binding": "ASSETS", "directory": "../client"}`,
      `compatibility_date`, `compatibility_flags`, `kv_namespaces`, and `r2_buckets`, while
      stripping remote-only `services`, `routes`, and `triggers`, and boots
      `wrangler dev --local --persist-to <tempdir>` so local state is ephemeral and production
      mutation risk is zero. Documented in the OpenSpec proposal
      (`w0m-web/openspec/changes/2026-10-26-t227-serve-built-artifact-goldens/proposal.md`)
      and `serve_built_artifact.py` module docstring.
- [x] **AC2 — One command serves the built artifact** and reports the URL, with teardown that
      releases the port on every exit path. ⚠️ [[T222]] learned this the hard way: `kill $PID` left
      an orphan holding `:4321` for **2h43m** because the process was a grandchild — kill by PORT.
      **Verified (`2026-10-26`):** `just serve-built-web` (`w0m-web/project/scripts/serve_built_artifact.py`)
      boots the built worker, prints the URL, and executes port-scoped teardown (`kill_port(port)`
      via `lsof -ti tcp:<port> -sTCP:LISTEN` -> `SIGTERM`/`SIGKILL` + process group termination +
      ephemeral `--persist-to` and `wrangler.local-gate.json` cleanup) across `try/finally`,
      `atexit`, `SIGINT`, and `SIGTERM`. Proven in
      `test_serve_and_run_kills_grandchild_listener_by_port_on_exec_failure`.
- [x] **AC3 — Warm before measuring.** A cold server re-optimises and aborts the first navigation;
      [[T222]] measured that as a spurious deploy-blocking failure. Require N consecutive stable
      loads, not one 200.
      **Verified (`2026-10-26`):** `wait_until_warm()` requires `required_streak=3` consecutive HTTP
      `200 OK` responses with non-empty body and resets `streak = 0` on any non-200 or network error.
      Live run on `:4329` recorded `history: ["ERR", "ERR", "ERR", "ERR", 200, 200, 200]` (`probes=7`,
      `streak=3`). Unit-tested in `test_wait_until_warm_requires_consecutive_200_streak_and_resets_on_failure`.
- [x] **AC4 — Run the golden matrix against it** and record how the numbers differ from the
      dev-server run. If they are identical, say so — that is the measurement that decides whether
      this gate earns its place at all, and a null result is a real answer.
      **Measured (`2026-10-26`):** Built `apps/web` under Infisical `beta` (`1m32s`) and ran
      `just goldens-built 4329` (`specs/web/goldens.spec:40` across all 7 viewport/section rows:
      `desktop-home_hero`, `desktop-home_services`, `desktop-home_cta`,
      `tablet-portrait-home_services`, `tablet-landscape-home_services`,
      `mobile-portrait-home_services`, `mobile-landscape-home_services`). All 7 rows passed (`1/1`
      spec, `7/7` table rows green in `1m55.3s`), matching the dev-server baselines within the
      2,000px threshold (`<2000` mismatched pixels on every row). The built-worker run additionally
      surfaced two runtime differences invisible or different in `astro dev`: (1) `/cdn/*` post-image
      requests return `503 Service Unavailable` against the empty local R2 bucket (confirming zero
      production R2 coupling, while section-scoped goldens remain immune), and (2)
      (2) `pagefind-component-ui.{js,css}` returns `404` when `pagefind` has not been indexed
      into the client output directory.
- [x] **AC5 — Prove it catches something the dev server cannot.** A build-only defect: a mangled
      asset hash, or an adapter-only path. **If no such case can be constructed, this ticket should
      be closed as not-worth-it rather than shipped as ceremony.**
      **Proven (`2026-10-26`):** Implemented `--check-assets` (`verify_built_assets()`) and
      [[T404]] bundle-provisioning verification (`check_bundle_provisioning()`) inside
      `serve_built_artifact.py`. On a clean build, all 4 root `_astro` assets
      (`ClientRouter...Bcn-gyid.js` 16,327B, `Layout.C1tvxOzt.css` 194,931B,
      `src.I3oobE8M.css` 18,297B, `WebMCP...Dgi0QNqz.js` 14,655B) verified `200 OK` on disk and over
      HTTP. When `apps/web/dist/client/_astro/src.I3oobE8M.css` was mangled — a
      build-only defect `astro dev` never sees because `astro dev` serves unbundled source CSS —
      `serve_built_artifact.py --check-assets` failed closed with `EXIT_CODE=1`
      (`MISSING_CLIENT_ASSET_ON_DISK` + `ASSET_HTTP_ERROR` HTTP 404 from built worker).
- [x] **AC6 — Decide where it runs.** Blocking pre-deploy costs minutes per deploy; a scheduled or
      on-demand run costs nothing until invoked. [[T224]] AC4's constraint applies — most deploys
      are unaffected by a UI regression, and a gate that makes shipping painful gets bypassed.
      **Decided & wired (`2026-10-26`):** Wired as on-demand recipes `just serve-built-web` and
      `just goldens-built` in the root `justfile` (not in blocking `_deploy-gates`, matching [[T224]]
      AC4 and `justfile` host memory constraints). Offline unit/lifecycle tests (`9 passed in 4.34s`)
      live in `w0m-web/project/scripts/tests/test_serve_built_artifact.py`.

## Definition of Done

The built `apps/web` Cloudflare Worker (`apps/web/dist/server/entry.mjs` + `apps/web/dist/client`) can be booted locally in one command (`just serve-built-web` / `just goldens-built`) using a sanitized local Wrangler config and ephemeral persistence without touching live production bindings, waits for 3 consecutive `200 OK` probes before measuring, fails closed on build-only asset or [[T404]] provisioning defects invisible to `astro dev`, and releases its TCP port on every exit path.
