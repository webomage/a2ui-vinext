## 2026-08-18 — research: is `LESSONS.md` a standard? No. Is the PATTERN real? Yes.

**Owner ask:** *"browse and check how people use LESSONS.md, and if there is any popular tool/skill
to look at before implementing this in w0m."* Done — and the honest answer splits in two.

**🔴 The filename is not a standard.** There is no spec and no cross-vendor adoption. The standard
that *does* exist is **`AGENTS.md`** — GitHub studied **2,500+ repositories** of it. The community's
name for the self-learning file is **`LEARNINGS.md`** (also `.learnings/` directories), not
`LESSONS.md`. ⇒ **AC1's decision to make `AGENTS.md` the source is the right one**, and this ticket
should not claim standards status for `LESSONS.md`.

**✅ The pattern is real and has earned mechanics**, chiefly from the `LEARNINGS.md` write-up:
read **first** at session start, write **last** before ending, *unconditionally*; a dated entry
carrying **Observation / Action / Confidence(high|medium|low)**; **promotion** of low→high once
repeat runs confirm; **archival at 80–100 lines**; one file per skill to stop cross-contamination.
A **"Lessons Learned" Claude Code skill** exists on mcpmarket doing roughly what `w0m-lessons` does
(writes `LESSONS.md`, optionally updates `CLAUDE.md`, enforces a bar against *"generic platitudes"*)
— ⚠️ its page returned **HTTP 429**, so this is from search summaries, **not read directly**.

**📌 The most useful comparison is where w0m is already ahead.** `TerminalSkills/agent-memory`
proposes `memory/MEMORY.md` + `entities/` + daily logs — **which is what w0m's auto-memory already
is** — and then states the unsolved problem outright: *"without pruning, memory grows until it
overwhelms context windows"*, **with no pruning mechanism specified**. w0m solved that for `STATE.md`
(900-line/80 KiB bound, `state-rotate`, `DISPOSITION.md` requiring a disposition before archiving).
⇒ **The gap is not knowledge, it is application: `LESSONS.md` has no bound and no reader.**

⚠️ **Caveat on the underlying claim.** Eric Ma's *self-improving coding agents* argues improvement
comes from **changing the environment, not the weights** — sound, and the framing behind all of
this. But his own post demonstrates **one** concrete win (a 2s vs 40s code search) and marks the
rest as future work. **The pattern is plausible and lightly evidenced, not proven** — which is the
right posture for adopting it here.

## 2026-08-19 — AC8: the ADR value, without an ADR store

**Owner asked about applying ADRs.** Measured first, and the measurement changed the design.

🔴 **Decisions are already recorded — 151 of them, across 68 files:** **137 in ticket bodies**,
6 in `.w0m/sdlc.json`, 3 in `TECH-DEBT.md`, 2 in `ROADMAP.md`, 2 in `cv/resolutions.json`, 1 in
`confirm-policy.json`. ⇒ **The gap was never the record. It was the INDEX** — no way to answer
*"was this decided, or did it just happen?"* without grepping.

⇒ A `docs/adr/NNNN-*.md` series would have created a **ninth register** and left all 151 behind,
which is this estate's signature failure: a new surface accumulating beside the ones people actually
write in. **Decisions stay where they were made.** `just decisions` generates
**`docs/DECISIONS.md`** pointing at them — 112 dated, 39 undated — and `AGENTS.md`'s routing table
now names it.

### ⚠️ A correction I had to make mid-proposal

I first suggested making **`resolutions.json`** the estate's decision record. **It is CV-scoped** —
it lives in `project/data/cv/` and only `cv_import.py` reads it. Calling it estate-wide would have
been wrong, and the design only survived because the next step was to measure rather than build.

### Why generated, and why staleness is a failure

⚠️ **A hand-maintained index is accurate the day it is written and decays in silence** — precisely
the shape of `AGENTS.md`'s dangling `LESSONS.md` pointer, which sent agents to a non-existent file
for weeks. So: nothing is retyped, `just decisions` rebuilds it, and **`just decisions-check` fails
when the committed copy drifts**, making staleness a push-time fact rather than a discovery months
later.

🔴 **It refuses an empty sweep.** Zero decisions exits 1 — the corpus is known to hold dozens, so
empty means *the matcher broke*, not that nobody decided anything.

**12 probes** (`just decisions-test`), plus the freshness gate registered separately: one proves the
generator cannot lie, the other proves the artefact in git still matches the corpus. Two different
claims, so two suites.


## 2026-08-19 — adopted AgDR, and the field I argued against is the one that mattered

**Owner: *"it looks like we should lead to AgDR."*** Correct, and it overrode my recommendation.

I had proposed taking **only** `superseded_by` and skipping the agent frontmatter, on the grounds
that `agent`/`model` is *"traceability for teams where it's unclear who decided; here it's one owner
and one agent."* 🔴 **That was wrong, and it contradicted this very ticket.** A parallel
**Antigravity** agent commits into this estate today, and T232 exists to add **Gemini and opencode**.
Multi-agent attribution is the estate's declared direction.

**Measured, which settles it:** all **667 commits since 2026-08-01 carry one git author**. At least
two agents and a human wrote them and **nothing on the commit says which**.

### What shipped

- **`project/templates/decision.md`** — AgDR: `id · timestamp · agent · model · trigger · status ·
  superseded_by · supersedes · ticket`, then Y-statement, Context, **Options considered** (with the
  rejected ones named), Decision, Consequences, and *What this does NOT decide*.
- **`docs/decisions/AgDR-0001`** — the decision to adopt AgDR, **recorded as an AgDR**. It names all
  four formats considered and why each lost, and states the negative consequences plainly: newest
  and least proven, ceremony that will be skipped, a corpus mixed for a long time.
- **The index reads them first-class** — structured records in their own table above the 151
  unstructured ones, **and a superseded record renders struck through with its replacement named**.
- **`AGENTS.md` routes to it**, including the instruction that overturning a decision means setting
  `superseded_by` on the OLD record.

**23 probes**, including that supersession renders and that restoring clears it (no sticky state).

### ⚠️ The honest risk, written into AgDR-0001 itself

**A format nobody writes in is worse than none.** If `docs/decisions/` still holds only AgDR-0001 in
a month, that is the finding — and the right response is to drop the format, not defend it.


## 2026-08-19 — backfilled the load-bearing decisions, and superseded my own record to do it

**Owner: *"review decisions to fulfil AgDRs."*** [[AgDR-0001]] had said *"the 151 existing decisions
are not migrated."* This reverses that in part — so it was recorded as **AgDR-0002 superseding
AgDR-0001**, not as an edit. ⚠️ **Quietly rewriting AgDR-0001 would have erased the record that
argued against this**, which is precisely the in-place correction the format was adopted to stop.
The mechanism's first real use was on itself.

### The index's 151 is a ceiling, not a count

Triaged before writing anything: **110 rows carry a strong marker** (`OWNER DECISION`/`RULING`/
`DECIDED`), **41 matched only `owner, <date>`**. 🔴 And some rows are **mentions**, not decisions —
*"the scope question was ALREADY DECIDED, in writing, on 2026-07-16"* records that a decision exists
elsewhere. **A line matcher cannot tell a decision from a reference to one.** Migrating all 151
would have produced 151 records of uneven worth.

⇒ The bar is **load-bearing**: something still depends on it, and not knowing it would change what
the next person builds.

### Backfilled

| | Decision | Why it binds |
|---|---|---|
| **AgDR-0003** | Stay on Supabase **Free** | shapes every capacity and backup choice; **egress is unmeasurable** |
| **AgDR-0004** | Pause `solar_flares` by **deactivating**, not unscheduling | reversible in one statement; 🔴 records that a **plaintext `service_role` JWT** survives the pause |
| **AgDR-0005** | **This machine** produces backups; R2 stores them — **no Worker** | a Worker cannot reach a laptop file, so there was nothing to mirror *from* |
| **AgDR-0006** | **`AGENTS.md`** is the control plane; others point at it | its own Consequences section records that **a dangling pointer already happened** |

Each states its **negative** consequences and a *What this does NOT decide* boundary. Contexts are
**recovered from what survives** — so where a consideration was never written down, it is absent
rather than reconstructed.

### Three probe bugs, all from the corpus changing under the tests

1. **`model` was required of every record** — AgDR-0003 is `agent: human`, and a person has no model.
   The probe would have pushed a **fake model id into a human's judgement**. Now required only when
   `agent != human`.
2. **The strike-through probe mutated `recs[0]`** — which became the genuinely-superseded AgDR-0001
   the moment supersession existed, so *"restoring clears it"* could never pass again.
3. **The line-picker matched any row containing the id** — and a superseded row **names its
   replacement**, so asserting on "AgDR-0002" hit AgDR-0001's row first and tested the wrong record.

📌 All three are the same shape as the day's earlier ones: **a matcher standing in for a concept.**
