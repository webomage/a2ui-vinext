# T319 — Dedup project delivery-role slugs (tpm/tech-lead, fullstack-dev/dev) and complete the pm/tl/dev triad

## Summary

Inbound report `_in/2026-09-05-project-roles-hats-offices-and-resource-access-architecture.md`
(AGY, 2026-09-05) proposed retiring the empty `tpm` office into `tech.lead` and standardizing
every project on 3 delivery seats (`pm`/`tl`/`dev`). Verified live against the actual database
(read-only, `infisical run --env=beta -- psql`) before touching anything:

- **`public.offices`**: 11 rows; `tpm` (Technical Program Manager, `is_management=true`) carries
  **0 rows in `office_capabilities`** — confirmed empty, matching the report. No code, RLS policy,
  or CASL check reads `offices`/`office_capabilities` at all (T117's own migration comment says so
  and a repo-wide grep confirms it) — the office catalog is declared-only today, so retiring `tpm`
  is pure cleanup with no live consumer to break.
- **`public.project_roles`** has **no `office` column** — the Axis3→Axis4 "backed by" link the
  report describes as already wired is **conceptual only**, not a schema relationship. That's a
  bigger gap than this ticket fixes; it stays out of scope (see Links).
- **The real, measured problem is at the `project_roles`/`hats` layer, not the `offices` layer.**
  Artemio (`a7e31002-…`) carries **7** role rows where 3 seats are actually needed: `dev` AND
  `fullstack-dev` (same `min_unit_id`, both "Developer"-ish), `tech-lead` AND `tpm` (same
  `min_unit_id`, same Lead Engineer unit). Both of Aleksei's profiles
  (`aleksei@webomage.com`, `casualuser@gmail.com`) hold **all four** of those hats simultaneously —
  pure seeding duplication from T313/T315, not a deliberate distinction anything reads.
- **BridgeRoad MVP (`b7100002-…`) has no `pm` role row at all** — the project has zero PM seat,
  vs. Artemio's 7-role catalog. The triad is incomplete there, not merely duplicated.
- `public.resource_grants` exists (T205's "not yet migrated" claim is stale — it's live with 2
  rows), but neither row references `office`, so it's unaffected by the `tpm` retirement.
- The report's item 2 ("auto-seed pm/tl/dev on project creation") has no code to update yet —
  `apps/cp/src/pages/api/project/` has no project-creation endpoint at all today. Out of scope
  until that endpoint exists; noting it rather than inventing one.
