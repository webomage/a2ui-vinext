# T497 — the hat stopped narrowing on 2026-09-26 21:00

## Summary

Found when a routine push ran the authz probes in full (they are scoped to pushes that touch `authz-`/migration paths, so nothing
had run them since **2026-09-26 09:16, the last 0-RED run**). `D2-hat-narrows` was RED with **98 violations**: an admin wearing the
`member` hat (AAL2) reads all 98 contracts.

**Cause (measured, live `pg_policies`):** migration `20260926210000_t465_manager_requires_aal2.sql` re-created FOUR policies as
**possession** tests, `wom_jwt_is_aal2() and (is_admin() or exists(user_roles ... role in ('admin','manager')))`: `contracts`
"Admins and managers can manage contracts" (FOR ALL), `projects` "Managers can manage projects" (FOR ALL) and
`managers_can_update_github_fields` (UPDATE), `project_roles` "Elevated manage project roles" (FOR ALL). Possession is true whatever
hat the person wears and policies are OR-ed, so the possession arm defeats `contracts_admin_hat`. It is the exact shape T198 D2
removed. The **same T465 migration got `client_milestones` right** (`wom_jwt_is_aal2() and wom_acting_in('admin','manager')`), which
is the template used for the fix. Only `contracts` has a probe, so the other three regressed silently.

**Also found and closed in the same run (`G3-views-security-invoker`, 1 violation, RED):** `public.public_team_members` (T470) is a
deliberate definer view (T198 dropped anonymous SELECT on `team_members` to stop email scraping; an invoker view would return an empty
roster). The probe had no way to express a deliberate exception and its message named a different view (`player_xp_totals`, which is
`security_invoker=true` live). Now `project/authz-public-views.jsonc` records the decision with a reason; G3 reads it (no second copy),
`G3b` fails on a stale declaration, `G3c` fails if a declared view ever exposes an email/phone/token/secret-shaped column.
