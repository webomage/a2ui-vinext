# T463 — Admin MFA enforced in the database, not only in the CP middleware

## Summary

Owner screencast, 2026-09-26: `w0m@webomage.com` signs in with Google and gets the Two-Factor Challenge; "Return to
Account & security" lands on `/me/account` (exempt so a factor can be enrolled) without entering a code. That page
hands the AAL1 access token to browser components (`apps/cp/src/pages/me/account.astro:17,35`), and no database
function or policy reads `aal`: `public.is_admin()` checks only `user_roles`. Measured live with a simulated AAL1
admin token (`just admin-aal-verify`): `is_admin`, `has_role('admin')`, `get_user_roles`, `wom_role_set`,
`wom_acting_is('admin')` all true, the admin's own `user_roles` row visible, and `upwork_auth_tokens` readable
(7 of 8 admin checks; `admin_secrets` held only because it is empty). The exposure: 22 policies via `is_admin()`,
21 functions calling it, 108 policies checking `user_roles` inline or via `wom_acting_is('admin')`, and edge
functions that check admin with the service role. One admin account exists (`w0m@`, 1 verified factor).

## Acceptance criteria

- [ ] AC1 — Migration `20260926170000_t463_admin_requires_aal2.sql`: `wom_jwt_is_aal2()`; a restrictive
  `user_roles` policy hides admin rows below AAL2 (covers the 108 inline policies); `is_admin`, `has_role`,
  `get_user_roles`, `wom_role_set`, `wom_acting_role`, `check_member_cp_lockout_blockers` drop admin below AAL2.
  Applied by the owner.
- [ ] AC2 — Edge functions: `requireAdminAuth` refuses below AAL2 with `MFA_REQUIRED`; the service-role admin
  checks in `client-api` and `lead-api` call `hasAal2(req)`; lead-api red probes for an AAL1 admin. Deployed.
- [ ] AC3 — `just admin-aal-verify` 16/16 on the live database (AAL1 refused everything admin, AAL2 keeps it).
- [ ] AC4 — Browser: the screencast flow (challenge → Return to Account & security) then a direct PostgREST read of
  `upwork_auth_tokens` with the page's token returns no rows.
- [ ] AC5 — Probes that simulate the admin carry `aal2` (authz suite, write probes, T439 verify, member probe) and
  stay green after apply.

## Definition of Done

T463 is done when an admin token without a verified second factor reaches nothing admin in the database or the edge
functions, the admin keeps full rights at AAL2, and both are proved on the live system by a recipe and a browser run.
