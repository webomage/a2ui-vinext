# T57 — Implement w0m Open Routing Layer

## Summary

Build and deploy the w0m Open Routing layer to dynamically allocate tasks between commoditized local SLMs (or Cloudflare Workers AI) and flagship frontier model APIs (Claude 3.5 Sonnet / Gemini 1.5 Pro). Establish complexity heuristics (intent-routing classification) and integrate Gemini context caching to lower API overhead.

## Acceptance criteria

- [x] AC1 — Implement Intent Router logic in `wom7api` / `wom7cfworkers` classifying incoming prompts (Routine/Simple vs. Complex).
- [x] AC2 — Route Routine queries to local SLM/CF-Workers-AI endpoints, and Complex queries to flagship models.
- [x] AC3 — Integrate Gemini context caching for repeated input sequences.
- [x] AC4 — Log token routing allocations to audit blended cost metrics.

## Status

- **2026-10-23 — Completed & Verified**:
  - **AC1 (Intent Router Classification)**: Implemented `classifyPromptIntent()` and `routeModelByIntent()` in `wom7api/supabase/functions/_shared/intent-router.ts`, classifying incoming messages into `routine` (greetings, FAQ, status checks, short conversational turns) vs `complex` (multi-step system architecture, security/threat modeling, code/SQL/Mermaid generation, deep debugging) with optional System One (`@cf/cloudflare/clef-flash`) classifier hook.
  - **AC2 (Tiered Model Allocation)**: Routine prompts on heavy 70B aliases (`w0m-llm-architect`, `w0m-llm-admin`) dynamically down-route to `@cf/mistralai/mistral-small-3.1-24b-instruct` (`~68%` neuron reduction per output token), while complex architectural prompts on `w0m-llm-consultant` escalate to `@cf/meta/llama-3.3-70b-instruct-fp8-fast`.
  - **AC3 (Gemini Context Caching)**: Implemented `computeGeminiContextCacheMetadata()` (`fnv1a64` deterministic digest + `cachedContent` key reuse across repeated system prompts >= 1,024 chars) and wired `providerOptions.google.cachedContent` into `GoogleGeminiAdapter` in `wom7api/supabase/functions/_shared/ai-router.ts`.
  - **AC4 (Blended Cost & Routing Telemetry)**: Wired `routingDecision` + `costAccounting` into `ai-router.ts`, `chat-core.ts`, and `agent-runtime.ts` so every `logAIUsage` call persists `intent_tier`, `requested_alias`, `selected_model_id`, `estimated_cost_savings_pct`, and `context_cache` metadata in `public.ai_usage.metadata`. Verified with 6 unit tests in `wom7api/supabase/functions/_shared/intent-router.test.ts` (`deno test --no-config --allow-env` green).
