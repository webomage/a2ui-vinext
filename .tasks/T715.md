# T715 — Client Portal (`apps/cp`) Onboarding Wizard & Project Settings: Selectable SDD Spec Dialect (`GitHub Spec Kit`, `OpenGSD`, `OpenSpec`, `Webomage SDLC`)

## Summary

Expose a **Spec-Driven Development (SDD) Methodology & Dialect Selector** inside the Client Portal Onboarding Service Wizard (`T703`) and Project Settings (`apps/cp`) so clients can select **`GitHub Spec Kit (.specify/)`**, **`OpenGSD Phase Loop (.planning/)`**, **`OpenSpec Delta (openspec/)`**, or **`Webomage Full SDLC`**, persist the preference in `orgs.service_usage.onboarding_service_wizard` and project metadata, and render normalized spec/phase progress in the Client Portal dashboard.

Split from: [[T712]]

## Acceptance criteria

- [ ] AC1 — **SDD Dialect Catalog & Recommendation Engine (`packages/lib/src/security/order-form-state.ts`):** Define the 4 selectable client SDD dialects (`github-speckit`, `open-gsd`, `openspec`, `w0m-openspec`) with clear trade-off descriptions (Constitutional Enterprise Contracts vs Fresh-Context Phase/Wave Execution vs Lightweight Brownfield Deltas vs Full Managed Webomage SDLC) and automatic recommendation based on engagement type.
- [ ] AC2 — **Onboarding Service Wizard & Project Settings UI (`apps/cp`):** Add the SDD Dialect selector using `@webomage/ui` primitives (`Card`, `Badge`, `Button`, `Select`) with zero internal ticket/AgDR leakage (`just ui-ticket-leak-check` + `just ds-conformance --enforce`).
- [ ] AC3 — **Normalized Spec/Phase Progress Card in `ClientDashboard.svelte`:** Render spec, phase, and task completion metrics hydrated from `client_spec_bridge` / `orgs.service_usage` regardless of whether the client project uses `.specify/`, `.planning/`, `openspec/`, or `.tasks/`.
- [ ] AC4 — **Automated Vitest Regression Suite (`apps/web/src/tests/`):** Verify dialect selection, recommendation defaults, payload serialization, and dashboard progress rendering.

## Definition of Done

Per [`w0m-web/openspec/SPEC-AUTHORING-STANDARD.md`](../w0m-web/openspec/SPEC-AUTHORING-STANDARD.md):
- Acceptance criteria AC1–AC4 verified by Vitest unit tests, `just ds-conformance --enforce`, and `just ui-ticket-leak-check`.
