# T415 — Embed Area-Grouped Tasks Renderer into tasks_query and w0m-tasks Skill

## Summary

The task queue currently renders ranked lists (`hot`, `sdlc`) and high-level rollup counts (`overview`). However, when triaging estate work by functional domain (e.g. `product`, `sdlc`, `tools`, `infra`, `security`, `ai`, `knowledge`, `schemas`, `data`, `skills`, `mcp`, `sec`), developers and agents need a structured, full-fidelity table of open tickets partitioned by area.

This ticket adds an `area` mode to `tasks_query.py` (`just tasks area`) and embeds the capability into the `w0m-tasks` skill.
By default, `just tasks` remains untouched (displaying the standard `hot` and `sdlc` ranking boards). When the `area` option is explicitly invoked (`just tasks area` or `just tasks area --area <name>`), it renders an Area Breakdown Summary statistics table followed by detailed markdown tables for each area sorted by status (`in-progress` first), priority (`P0` > `P1` > `P2` > `P3`), and score.

## Acceptance criteria

- [x] AC1 — `scripts/tasks_query.py` accepts `area` mode in CLI choices and implements `cmd_area(tickets, area_filter=None)`.
- [x] AC2 — `just tasks area` renders an overall Area Breakdown Summary table (Open, WIP, Done, Total, % Complete) and formatted markdown tables for each thematic area.
- [x] AC3 — Optional `--area <name>` argument filters output to a specific area (e.g. `just tasks area --area tools`).
- [x] AC4 — Default invocation of `just tasks` remains strictly unmodified (hot and sdlc boards only; area view is not posted by default).
- [x] AC5 — `wom7skills/skills/w0m-tasks/SKILL.md` is updated to document the `area` subcommand and option, and synced to `.agents/skills/w0m-tasks/SKILL.md` via `just skills-sync`.
