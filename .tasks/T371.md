# T371 — Incorporate claude-obsidian ecosystem, per-project vaults for clients & managers, and CP knowledge embedding

## Summary

Owner directive, 2026-09-17:
> *"we have to incorporate into our w0m ecosystem this - https://github.com/AgriciDaniel/claude-obsidian*
> *and also we have to have obsidian vault per project accessible by client and w0m managers*
> *also it will be nice to understand if we can embedd obsidian into w0m user cp panel"*

This ticket unifies three tightly coupled knowledge capabilities across the w0m estate:
1. **claude-obsidian Integration**: Ingest and govern [`AgriciDaniel/claude-obsidian`](https://github.com/AgriciDaniel/claude-obsidian) (v2.2.0, MIT) within w0m. Adopt its 15 Agent Skills (Karpathy LLM Wiki pattern: `wiki`, `save`, `wiki-ingest`, `wiki-query`, `wiki-lint`, `autoresearch`) into canonical `wom7skills`, governed by `.w0m/skills.json`.
2. **Per-Project Obsidian Vault Standard**: Define a standardized, multi-tenant vault topology for all client projects declared in `project/clients-policy.json` (`1945`, `artemio`, `servicios777`, `personaje0`, etc.), giving every project its own structured knowledge base (`inbox/`, `sources/`, `claims/`, `notes/`, `mocs/`).
3. **Dual Access Model & CP Panel Knowledge Embedding (Blueprint A)**:
   - **w0m Managers & Internal Admins**: Access via local Obsidian Desktop application (`scripts/open_vault.py`), git synchronization, and Agent Skills / MCP bridge (`obsidian-mcp-bridge.py`). Estate-wide administrative vault controls live exclusively on `cp.w0m.xyz` (admin-only domain).
   - **Clients & Project Stakeholders**: Zero-install, responsive browser access embedded directly within the Client Portal at `cp.webomage.com` (e.g. `/client/vault` and `/client/projects/[id]/docs`), rendering project markdown, Mermaid diagrams, bidirectional wikilinks, and an interactive 2D/3D graph view, paired with an "Open in Obsidian" desktop deep-link affordance (`obsidian://open?vault=...`).

## Technical Assessment: Embedding Obsidian into CP Panel (Blueprint A Approved)

Directly running the native Obsidian Desktop application inside a web browser iframe is technically not viable without streaming a heavy virtualized desktop container (e.g. `obsidian-remote` via noVNC/Kasm in Docker), which is resource-intensive, laggy, insecure across multi-tenant boundaries, and poor on mobile devices.

Instead, the approved production solution (Blueprint A — Native Svelte Knowledge Hub + Embedded Graph, adhering to `HOSTED_OBSIDIAN_VAULTS_AND_COMMUNITY_PLUGINS_RESEARCH_2026.md` and Webomage Design System) is:
- **Client Portal on `cp.webomage.com`**: Svelte 5 / Astro SSR component in `apps/cp` rendering the client's project vault notes, frontmatter, and Mermaid diagrams with strict tenant isolation (`client_id` RLS).
- **Admin Control Panel on `cp.w0m.xyz`**: Admin-only control panel for cross-project vault oversight, sync status, and internal documentation.
- **Interactive Web Graph View**: Client-side interactive canvas/graph visualization component (using D3.js or Cosmograph) providing the signature Obsidian interconnected node graph directly in the browser.
- **Desktop Deep-Link**: Native `obsidian://open?vault=<project>&file=<path>` links for users who have the Obsidian app installed.
