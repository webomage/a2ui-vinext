## Summary

**Astro 6 → 7 upgrade (security-driven)** — `GHSA-4g3v-8h47-v7g6` (reflected XSS via unescaped View Transition animation properties) has **no 6.x fix**; minimal fix is **Astro 7.1.0**, a MAJOR upgrade across all 5 apps (web/cp/join/job/demo, currently `^6.4.8`). Suppressed in `osv-scanner.toml` 2026-07-20 to unblock commits — suppression is a deferral, not a fix. Exposure is limited to places where view-transition animation props derive from untrusted input (audit those first — it may be zero, which would downgrade urgency). **✅ EXPOSURE AUDIT 2026-07-21: effectively ZERO** — `transition:animate` (the direct vector) is used **nowhere** across all apps+packages; the only dynamic transition value is `transition:name={\`…-${blueprint.blueprint_id}\`}` (apps/web/blueprints/[...slug].astro) which derives from a **guarded** DB lookup (`if (!blueprint) redirect`) → a w0m-controlled id, never the raw request slug. Fold in the three older `Astro 6 unfixable` suppressions, which this upgrade also clears.

## 🔴 THE BLOCKER FOUND 2026-08-13 — an EMPTY patch file, and it is two lines to remove

Owner asked *"why don't we use astro7 — there was something missed in packages compatibility some
time ago"*. **There is no package-compatibility problem. There is a no-op patch pinning the adapter.**

```
pnpm-workspace.yaml:23-24
  patchedDependencies:
    '@astrojs/cloudflare@13.3.0': patches/@astrojs__cloudflare@13.3.0.patch
```

🔴 **That patch file is 0 bytes.** It was created empty in a single commit — `79ab2e30`
*"fix(build): resolve Astro v6 content collection id vs slug migration bug causing prerender crash"*
— and **never had content** (verified by object size at every commit that touched it, not by
`git log --follow`, which chases unrelated renames here and gives a misleading history).

⇒ Because pnpm hard-fails with **`ERR_PNPM_UNUSED_PATCH`** when a declared patch goes unused, the
declaration **pins `@astrojs/cloudflare` to exactly 13.3.0** — and that package is the *adapter*, so
Astro cannot move either. **A patch that patches nothing has been holding the major upgrade.**

✅ **Proven: removing those two lines lets Astro 7 resolve.** `pnpm install --lockfile-only`
completed with no errors.

### Every peer requirement is ALREADY satisfied — measured, not assumed

| Astro 7 / adapter needs | we have | |
|---|---|:--:|
| `node >= 22.12.0` | **v24.17.0** | ✅ |
| `wrangler ^4.83.0` (`@astrojs/cloudflare@14`) | **4.112.0** | ✅ |
| `svelte ^5.43.6` (`@astrojs/svelte@9`) | **5.56.4** | ✅ |
| `typescript ^5.3.3 \|\| ^6.0.0` | **6.0.3** | ✅ |

🔑 **The upgrade FIXES an existing unmet peer rather than creating one.** `@astrojs/svelte@8.1.0`
demands `typescript ^5.3.3` and we run **6.0.3** — that warning is printed on every install today.
`@astrojs/svelte@9` accepts `^6.0.0`. ⇒ We are already on a TypeScript the *current* integration
does not support.

The other six `astro*` packages (`sitemap`, `partytown`, `check`, `astro-icon`, `astro-compress`,
`prettier-plugin-astro`) declare **no `astro` peer at all**, so they do not constrain the version.

### ⚠️ What this does NOT prove

The dry run bumped only **3 of the 6** manifests that carry astro deps, so it resolved a **mixed
tree** — `astro@6.2.1` and `astro@7.2.1` side by side. **That demonstrates the patch was the
blocker; it does not demonstrate the estate upgrades cleanly.** A real attempt must bump all six
(`package.json`, `apps/{web,cp,job,join,demo}`) and then prove **all 5 apps build**, which is where
Astro 7's own breaking changes across **220 `.astro` files** will actually show up.
⚠️ **`wrangler` is a cross-repo lockstep dep** (`deps-policy.json`: wom7web + wom7api +
wom7cfworkers at `^4.112.0`). A residual peer wanted `^4.122.0`, so the bump is a **three-repo**
coordination, not a one-repo edit.

### What it clears

`GHSA-8hv8-536x-4wqp`, `GHSA-jrpj-wcv7-9fh9`, `GHSA-4g3v-8h47-v7g6`, `GHSA-7pw4-f3q4-r2p2`,

## ✅ UPGRADED 2026-08-13 — astro 6.4.8 → 7.2.1, all five apps building

**One astro major in the lockfile** (the thing the dry run could not show), `extract-zip` still

deleted**.

### What actually broke, in the order it broke

1. 🔴 **`astro-compress` held the tree on astro 6.** It declares **`"astro": "*"` as a regular
   DEPENDENCY, not a peer**, so it installs its own copy — which is why the earlier dry run kept
   resolving a mixed tree no matter what the manifests said. `2.3.8 → 2.4.3` resolved it.
   ⚠️ **This is why "it resolved" was never evidence**: pnpm will happily seat two astro majors.
2. 🔴 **`wrangler` became a HARD failure, not a warning.** Astro 7's cloudflare adapter pulls
   `@cloudflare/vite-plugin@1.52.0`, which **asserts `wrangler ^4.122.0` at config-load time and
   throws**. Under Astro 6 the same mismatch was a peer *warning* printed on every install and
   ignored for months. ⇒ Raised **once** in `deps-policy.json` (`^4.112.0 → ^4.123.0`) and applied
   across **wom7web + wom7api + wom7cfworkers** — exactly what that lockstep entry exists for.
3. 🔴 **A pre-existing import-path defect that Astro 6 tolerated.** `packages/ui` is reached two
   ways that disagree: a **vite alias** maps `@webomage/ui → packages/ui/src`, while the package's
   **exports map** says `"./*": "./src/lib/*"`. So `@webomage/ui/lib/…` satisfies the alias (18
   imports) and `@webomage/ui/…` satisfies the exports map (9 imports) — **both spellings were in
   use.** Astro 6 resolved either; **vite 8/rolldown lets the alias win**, so the 9 short-form
   imports broke. Normalised to `lib/` across 5 files.
   🔑 **Not an Astro bug — Astro 7 is what made the ambiguity fatal.** Two resolution mechanisms
   pointing at different roots is the same class as the two whitelists in [[T207]] AC1.
   🔬 **And my first fix was half right, which the typecheck ratchet caught.** Normalising the 9
   imports to `lib/` satisfied vite and **broke TypeScript**, because *tsc reads the package exports
   map* (which wanted the SHORT form) while *vite reads the alias* (which wanted `lib/`) — **the two
   resolvers wanted OPPOSITE spellings.** `join` went **12 → 16 errors** and the ratchet refused the
   push with *"Fix the new errors — do NOT raise the baseline"*.
   ✅ **Real fix: make all THREE agree**, rather than choosing a side.
   `packages/ui` exports `"./*"` changed `./src/lib/*` → **`./src/*`**, so exports + vite alias +
   tsconfig all resolve `@webomage/ui/lib/…` to the same file. ⚠️ **`apps/join/tsconfig.json` also
   pointed at `packages/ui/*` with no `src` at all** — wrong under *either* spelling, and only
   visible once the other two agreed. **join is back to its 12-error baseline; ratchet green.**
4. 🔴 **Astro 7 changed the default Markdown processor.** `markdown.remarkPlugins` /
   `rehypePlugins` now need **`@astrojs/markdown-remark`** installed explicitly; it is no longer
   bundled. Added at **`7.2.2`** — astro 7.2.1's exact declared peer — to `web` and `cp`, the two
   apps using the legacy config.

⚠️ **`wom7api` and `wom7cfworkers` have the wrangler bump in `package.json` but still need
`pnpm install` in their own trees** to move their lockfiles.
