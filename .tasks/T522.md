# T522 — Governing the user-scope skills

## Summary

Split from [[T508]], where it was the open owner question 6. `~/.claude/skills` holds **23 skills** and the user manifest the policy
names (`~/.claude/.w0m/skills.json`) **does not exist** (both measured 2026-10-01). They are loaded into every session on this host
with no version, no integrity hash and no recorded source. The policy comment written on 2026-08-17 (T147) counted **15**; eight more
have arrived since, undecided. As a result `skills_catalogue.py --enforce` can never pass, so the only strict mode of that gate is
permanently unusable.

## Why it was left open

`sdlc.json -> skills_governance_scopes.user_scope_open` records the reason: these are loose, directly placed directories whose
provenance is not locally resolvable (no installed plugin owns them). Adopting them with a guessed `--source` would **fabricate
provenance**, which is the exact defect the T127 review caught. The policy's own instruction is to resolve each by a **content diff
against a fetched upstream**, never by assertion. This ticket does that work.

## Acceptance criteria

- [x] AC1 — **List them with facts.** For each of the 23: name, size, newest file date, whether it ships runnable files, and whether a
  plugin or the skills CLI owns it. Read-only; recorded in the status note as a table.
- [x] AC2 — **Each skill gets one of two outcomes, by evidence.** `allow` (adopt and hash, with a `--source` proven by a content diff
  against the fetched upstream) or `preserve` (exclude, with a written reason). A skill whose upstream cannot be found is `preserve`,
  never `allow`.
- [x] AC3 — **The user manifest exists** (`~/.claude/.w0m/skills.json` and its lock) and `just skill check` reports 0 unmanaged at user
  scope.
- [x] AC4 — **`--enforce` can pass.** `skills_catalogue.py --enforce` exits 0 on the live estate, and a red probe proves a new
  undeclared user-scope skill turns it red again.
- [x] AC5 — **Growth is visible.** A check or report states the user-scope count and fails when it rises without a decision, so the
  15-to-23 drift cannot repeat silently.

## Definition Done

- Every AC ticked with command output; no skill source asserted without a content diff; `just test` offline tier green.

## Open questions (recommended answer first, with weight)

1. **Do the user-scope skills belong in the estate at all?** *Recommend deciding per skill in AC2; delete none without the owner.*
   Weight: some may be personal tools, which is a legitimate `preserve`.
2. **Where is the user manifest versioned?** `~/.claude` is outside every repo. *Recommend leaving it unversioned and recording the
   decisions in this ticket and the policy.* Weight: versioning a home directory is a larger decision than this ticket.

## Actuality & Decision Alignment (2026-10-22)

- Host-awareness update: `~/.claude/skills` (23 ungoverned skills) lives on the owner's macOS host and is absent on the Linux `x86_64` workstation. Decouple `test_skills_catalogue.py` user-scope assertions from live `Path.home() / '.claude' / 'skills'` via a test fixture flag (`--user-skills <dir>`), and run `AC1`–`AC3` on the macOS host.
