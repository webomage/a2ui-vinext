# T436 — Public-safe automated CHANGELOG: Conventional Commits, ticket synthesis & disclosure guardrail gate

## Summary

Owner direction (2026-09-24): Start automated `CHANGELOG.md` generation (Option A: Conventional Commits & ticket synthesis), with the foundational architectural invariant that `CHANGELOG.md` — unlike internal `STATE.md` — is a **public-facing artifact** and must be strictly gated against public info sharing rules and guardrails in the w0m ecosystem.

Currently, `scripts/gen_changelog.py` dumps raw `deploy_log` rows (`Service | Commit | Actor | Deployed at`), publishing raw personal/admin emails (`casualuser@gmail.com`) and omitting readable feature/fix descriptions. Moreover, it completely overwrites `CHANGELOG.md` on every run.

This ticket upgrades `scripts/gen_changelog.py` to:
1. Determine git commit ranges between successive deploy commits.
2. Extract and classify user-facing Conventional Commits (`feat:`, `fix:`, user-facing `perf:`) while filtering out internal plumbing noise (`chore:`, `ci:`, `test:`).
3. Associate commits with their ticket metadata (`.tasks/T*.md`), rendering clean public titles and links.
4. Enforce strict public disclosure guardrails: redact personal actor emails/PII, sanitize sensitive ticket tags (`security`, `p0`, confidential client codes), and verify the output against a dedicated guardrail gate (`just changelog-check`).

## Acceptance criteria

- [x] AC1 — Conventional Commits & Ticket Range Synthesis: `scripts/gen_changelog.py` resolves commit ranges between successive deploy commits (`git log <prev_commit>..<curr_commit>`), groups commits into `### Features` (`feat:`) and `### Fixes` (`fix:`), links to tickets ([`T###`]), and renders readable release notes under each version heading alongside deployment metadata.
- [x] AC2 — PII & Actor Email Redaction Invariant: The generator never publishes personal or employee email addresses (`@gmail.com`, internal staff emails). Actor identities are normalized to neutral public release identities (or the actor column is removed from public tables).
- [x] AC3 — Public Scope & Internal Noise Filtering: Commits without user-facing impact (`chore:`, `ci:`, `test:`, internal refactors) are omitted from the public changelog by default, keeping the document high-signal.
- [x] AC4 — Security & Confidentiality Guardrail Gate: Tickets tagged `security`, `p0`, or containing confidential client project identifiers are sanitized/redacted to prevent disclosure of vulnerability mechanics or client privacy data.
- [x] AC5 — Offline Guardrail Linter Recipe (`just changelog-check`): A dedicated verification script scans `CHANGELOG.md` for forbidden patterns (emails, credentials, confidential client codes, unsanitized security disclosures) and fails closed; covered by unit test suite in offline tier.
- [x] AC6 — Regeneration Invariant & Drift Parity: `just changelog-drift` and `deploy_logged.py` integration remain green, ensuring automated changelog generation after successful deploys preserves guardrail compliance without manual intervention.

## Definition of Done

Per `SPEC-AUTHORING-STANDARD.md`: implementation test-covered in offline tier, red probes proving disclosure gate fails on PII/sensitive tokens, `just changelog` producing clean sanitized output, `just changelog-drift` passing, and tracked surfaces in sync.
