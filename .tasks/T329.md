# T329 — Bind the authz probe's actor to one real client, not two unrelated rows

## Summary

`project/scripts/authz_probe_suite.py:78-127`. The `actor()` helper builds a client principal by
selecting the user id and the organisation id in **two separate `LIMIT 1` subqueries**, with no
join and no ordering guaranteeing they describe the same client. Nothing forces the uid it picks to
belong to the org it picks.

Today that is harmless by accident: `client_users` has exactly **2 rows**, so the pairing is very
likely coherent and the suite reads 18/18 green. **The moment [[T325]] links the other 8 client orgs
the accident stops holding** — and this is the probe whose job is proving cross-tenant isolation. It
would go on printing GREEN while testing a principal that does not exist.

That matters more than a P3 normally would, because of what the two affected cases assert:

- **A1** — `SELECT CASE WHEN count(*) > 0 THEN 0 ELSE 1 END FROM contracts;` — the positive control.
  It proves the harness can see *something*, so a green A2 means isolation rather than a broken
  connection. A mismatched actor can make the control pass for the wrong reason.
- **A2** — `SELECT count(*) FROM clients WHERE id <> '{client_org}'::uuid;` — the isolation
  assertion itself. If `client_org` is not the org the JWT actually belongs to, this counts rows
  the principal was never scoped to, and a pass says nothing.

⇒ This is the estate's recurring shape: **the audit tool commits the defect it hunts**, and every
metric has a degenerate solution. A probe with a self-inconsistent fixture is a green light wired to
nothing.

## Acceptance criteria

- [x] AC1 — `actor()` derives the client uid and org id from **one row of `client_users`** (a single
      query or an explicit join), so they are the same client by construction rather than by luck.
- [x] AC2 — The probe FAILS with a clear message when no coherent client actor exists, instead of
      running with a half-populated principal. An unusable fixture is unmeasurable, not passing
      (T242).
- [x] AC3 — The chosen actor's uid and org are printed in the probe output, so a reader can see
      which client was tested rather than inferring it.
- [x] AC4 — A red probe proves the fix: construct a deliberately mismatched uid/org pair and show
      the suite refuses it. Per the estate's rule, a check with no test case that makes it fire is
      not proven to work.
- [x] AC5 — `just authz-probe` still reports 18/18 after the change, with A1 as the positive
      control and A2 green for the reason intended.

## Definition of Done

T329 is done when:
1. `authz_probe_suite.py` resolves the client actor's `user_id` and `client_id` from a single atomic row in `client_users` rather than two independent queries.
2. The probe suite refuses to run with a half-populated or non-existent client principal, failing closed with a clear unmeasurable diagnosis.
3. The resolved client principal (`user_id` and `client_org`) is explicitly emitted in stdout during execution.
4. Offline unit probes in `test_authz_probe_suite.py` prove the suite rejects missing or mismatched client fixtures.
5. `just authz-probe` runs cleanly with 18/18 green probes and zero unmeasured/red probes against the live database.
