# T465 — Mandatory step-up MFA (TOTP / Touch ID / AAL2) for manager-level actions and responsibilities

## Summary

Owner directive 2026-09-26: "make it mandatory to confirm with totp or TouchId all manager level responsibilities actions". Following the hardening of admin privileges to AAL2 in [[T463]], tactical delivery management roles (`manager` / PM / Centurion / Tribune) hold sensitive operational capabilities: approving milestones, modifying budgets/billing circles, staffing project roles, managing client contracts, and accessing external integrations. This ticket extends the database, edge function, and middleware MFA assurance requirements from `admin` to all `manager` responsibilities, ensuring that any session exercising managerial powers must be verified via a second factor (TOTP authenticator app or WebAuthn/Touch ID Passkey at AAL2).

## Acceptance criteria

- [ ] AC1 — Middleware & Route Policy: `mfa-policy.ts` and CP middleware evaluate `isElevatedMfaContext` to require `aal2` for users wearing the `manager` hat, holding the `manager` role, or accessing manager-level management routes. Sessions at `aal1` with enrolled factors redirect to `/mfa/challenge`; sessions without factors redirect to `/me/account?mfa_required=1`.
- [ ] AC2 — Database Migration: Create migration `20260926180000_t465_manager_requires_aal2.sql` adding restrictive RLS on `user_roles` for `manager` below AAL2, dropping `manager` from `has_role('manager')`, `get_user_roles()`, `wom_role_set()`, and `wom_acting_role()` below AAL2.
- [ ] AC3 — Database Mutation Gates: Mutating policies on core manager responsibility relations (`projects`, `project_roles`, `client_milestones`, `billing_circles`, `contracts`) require `public.wom_jwt_is_aal2()`.
- [ ] AC4 — Edge Functions: `wom7api/supabase/functions/_shared/requireAuth.ts` adds `requireManagerAuth(req)` requiring `hasAal2(req)` (refusing AAL1 with `403 MFA_REQUIRED`). Edge endpoints for milestone approvals, billing circle mutations, and lead/contract operations enforce `requireManagerAuth`.
- [ ] AC5 — Verification Suite: Provide `just manager-aal-verify` with exhaustive probes verifying that a manager at AAL1 is refused for all manager-level operations and functions, while an AAL2 manager retains full operational capabilities.
- [ ] AC6 — Unit & Integration Probes: Update `mfa-policy.spec.ts` and authz test suites to verify that manager contexts require AAL2 and pass cleanly.

## Definition of Done

T465 is done when an authenticated user with the `manager` role cannot access manager routes, call manager edge functions, or mutate manager database entities without an AAL2 token verified via TOTP or Touch ID/WebAuthn, and both AAL1 refusal and AAL2 acceptance are proven by automated probes and test suites.
