# T787 — Terraform drift detection with Telegram alerts, DNS cleanup, AgDR-0060, and TabLinux WASM client domain audit

## Why

Cloudflare infrastructure drift (e.g. manual dashboard edits, unmanaged duplicate SPF records, or out-of-band rule modifications) must be detected automatically and alerted to the operator before it breaks production mail delivery or routing. Furthermore, legacy Pages domain resources must be retired in favor of Wrangler Worker Custom Domains, and the same perimeter/DNS drift detection capability must be extended to client connected/audited domains running directly in WASM inside the TabLinux Control Panel console without backend compute costs.

## Scope

- **In:**
  - Automated Cloudflare Terraform drift detection script (`scripts/tf_drift_check.py`) and recipes (`just tf-drift-alert`, `just tf-drift-check`).
  - Telegram alert dispatch to `TELEGRAM_ADMIN_ID` (275104413) via `TELEGRAM_BOT_TOKEN` on detected drift.
  - Python test suite `scripts/tests/test_tf_drift.py`.
  - DNS cleanup: remove dead `cloudflare_pages_domain` resources from `w0m-api/cloudflare/records.tf`; align `email_routing.tf` (MX untracked/delegated to Email Routing, rule metadata aligned).
  - Decision record: `docs/decisions/AgDR-0060-edge-dns-email-routing-drift-and-wasm-domain-audit.md` and index regeneration (`just decisions`).
  - Client domain drift monitoring library (`w0m-web/packages/lib/src/security/domain-drift.ts`) running in WASM / browser sandbox via Cloudflare DoH.
  - TabLinux module registration in `w0m-web/packages/lib/src/security/seo-geo-scanner.ts` (`TABLINUX_CREW_MODULES`).
  - Unit tests in `w0m-web/packages/lib/src/security/__tests__/domain-drift.spec.ts`.
- **Out:**
  - Modifying third-party DNS provider APIs or sending external non-Telegram alerts.
