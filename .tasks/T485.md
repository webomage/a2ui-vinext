# T485 — Align workerd runtime binary versions across estate and refresh worker types

## Summary

Audit and unify `workerd` package versions across all estate repositories. Currently `wom7web` and `wom7api` resolve `workerd@1.20260811.1` via `wrangler@4.123.0`, but `wom7func` carries two parallel versions in its lockfile (`1.20260616.1` via `@cloudflare/vitest-pool-workers@0.16.16` and `1.20260811.1` via `wrangler`). Additionally, `wom7func/worker-configuration.d.ts` carries types generated against an older build (`1.20260504.1`).

## Acceptance criteria

- [x] AC1 — In `wom7func/package.json`, pin `workerd` in `pnpm.overrides` to `1.20260811.1` (or upgrade `@cloudflare/vitest-pool-workers` to align with Miniflare 5 / workerd 1.20260811.1) so `pnpm-lock.yaml` resolves exactly one unified `workerd` version.
- [x] AC2 — Run `pnpm install` in `wom7func` and verify that `pnpm why workerd` reports `Found 1 version of workerd: workerd@1.20260811.1`.
- [x] AC3 — Run `cf-typegen` (`pnpm exec wrangler types`) in `wom7func` to refresh `worker-configuration.d.ts` against the aligned runtime.
- [x] AC4 — All test suites pass: `pnpm exec vitest run` in `wom7func` passes with 100% test files passing, and estate offline test suites pass.
