## Summary

**Align deployed runtimes — CF `compatibility_date` + Node build pin** — surfaced 2026-07-21 answering "what runtimes do we actually deploy?". **CF workerd `compatibility_date` is split**: the 5 Astro apps (web/cp/join/job/demo) are on **`2024-11-18`** (~18 months old) while the 2 Hono workers (api/cfworkers) are on **`2026-05-06`**. Bump the Astro apps to a current date — but it's a **runtime-semantics change**, so per-app build + smoke (SSR + `/api/health`) before deploy, not a blind sync. Also: **Node is unpinned** (no .nvmrc/engines; build ran on local v24.17.0) — add a repo-level Node pin for reproducible builds. Deno (Supabase edge) is Supabase-managed (not ours); we already pin npm specifiers in `deno.json` (correct). Doc: `docs/DEPS-ALIGNMENT.md` §Deployed runtimes.

## Acceptance criteria

- [ ] AC1 — **Node runtime build pin**: Establish a canonical Node.js version pin across the repository using an `.nvmrc` configuration and an `engines` declaration in `package.json` matching the active build environment.
- [ ] AC2 — **Astro apps compatibility_date upgrade**: Advance `compatibility_date` in `apps/web/wrangler.jsonc`, `apps/cp/wrangler.jsonc`, `apps/join/wrangler.jsonc`, `apps/job/wrangler.jsonc`, and `apps/demo/wrangler.jsonc` to match the current worker baseline (`2026-05-06`).
- [ ] AC3 — **Per-app build verification**: Run complete compilation across all 5 workspace applications (`pnpm build`) verifying that Astro Cloudflare adapters, Vite bundling, and worker shims compile cleanly.
- [ ] AC4 — **SSR and runtime smoke testing**: Validate local/preview SSR execution across apps, ensuring session KV bindings, Cloudflare services (`CF_WORKERS`, `WOM7API`), and `/api/health` endpoints function without workerd semantic regressions.
- [ ] AC5 — **Cross-repo runtime alignment verification**: Verify that worker runtimes and `nodejs_compat` compatibility flags across `wom7web`, `wom7api`, and `wom7cfworkers` are aligned without unrecognized drift.
- [ ] AC6 — **Documentation update in DEPS-ALIGNMENT.md**: Update the "Deployed runtimes" matrix in `docs/DEPS-ALIGNMENT.md` to reflect the updated `compatibility_date` stamps and the pinned Node runtime.
