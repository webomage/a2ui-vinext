## Summary

**Align deployed runtimes — CF `compatibility_date` + Node build pin** — surfaced 2026-07-21 answering "what runtimes do we actually deploy?". **CF workerd `compatibility_date` is split**: the 5 Astro apps (web/cp/join/job/demo) are on **`2024-11-18`** (~18 months old) while the 2 Hono workers (api/cfworkers) are on **`2026-05-06`**. Bump the Astro apps to a current date — but it's a **runtime-semantics change**, so per-app build + smoke (SSR + `/api/health`) before deploy, not a blind sync. Also: **Node is unpinned** (no .nvmrc/engines; build ran on local v24.17.0) — add a repo-level Node pin for reproducible builds. Deno (Supabase edge) is Supabase-managed (not ours); we already pin npm specifiers in `deno.json` (correct). Doc: `docs/DEPS-ALIGNMENT.md` §Deployed runtimes.
