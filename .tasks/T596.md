# T596 — Multi-host Orca instance and agent session orchestration across macOS and Linux boxes

## Summary

Enable discovering, inspecting, attaching, and controlling Orca instances (`orcad` / `orca serve`) and live or dormant agent sessions (`agy`, `claude`, `codex`, `opencode`) across local (`darwin-arm64` MacBook Pro) and remote (`linux-x86_64` / `HP` via SSH `linux-host`) hosts from a unified CLI and UI control plane.

Grounded in live inspection of `Orca 1.4.245`:
- Local agent state is split across `orca terminal list --json`, `~/Library/Application Support/orca/agent-hooks/last-status.json` (`paneKey`, `tabId`, `worktreeId`, `providerSession.id`, `payload.state`, `payload.prompt`), `agent-session-journal.db`, and `~/.gemini/antigravity-cli/brain/<uuid>/` (`transcript.jsonl`).
- When sessions start in the Floating Workspace (`global-floating-terminal`), detach after a restart, or run on a second host (`linux-host`), operators need a single command and workflow to list all sessions across hosts, inspect their active ticket/worktree, and safely reattach or consolidate them into the right workspace tab without dual-writer transcript corruption.

## Acceptance criteria

- [ ] **AC1 — Unified Cross-Host Session Discovery & Status Inventory (`scripts/orca_sessions.py` / `just orca-sessions`)**: Discover and tabulate all live and dormant agent sessions (`agy`, `claude`, `codex`, `opencode`) across the local macOS host and configured remote SSH hosts (`linux-host`), correlating `orca terminal list --json`, `last-status.json`, live process trees (`--conversation=<uuid>`), and `.gemini/antigravity-cli/brain/<uuid>/` transcripts (`conversation_id`, `state`, `worktreePath`, `tabId`, `paneKey`, `host`, last user prompt, and active `.w0m/work/<tree>`).
- [ ] **AC2 — Safe Programmatic Session Reattachment & Consolidation (`just orca-attach`)**: Implement deterministic session reattachment into any target Orca worktree tab (`orca terminal create/send --worktree <path> --command "agy --conversation=<uuid> ..."`) with a single-writer PID guard (refusing to attach a second `agy` process to a `transcript.jsonl` that still has an active writer PID, and supporting graceful stop + rebind from `global-floating-terminal` into a project worktree tab when `tui-idle`).
- [ ] **AC3 — Cross-Host Orca Daemon & Remote Environment Management (`macOS` ↔ `linux-host`)**: Configure and verify multi-host connectivity between macOS (`darwin-arm64`) and Linux (`linux-host` `x86_64`) in Orca and `w0m` tooling so remote terminals, worktrees, and agent sessions on `linux-host` can be inspected, launched, and supervised from the primary macOS Orca desktop and mobile control plane.
- [ ] **AC4 — Unit Tests & Quality Gates (`scripts/tests/test_orca_sessions.py`)**: Add deterministic unit tests for session discovery, transcript/hook correlation, single-writer PID lock verification, and cross-host inventory formatting, passing all pre-commit and pre-push gates without `--no-verify`.
