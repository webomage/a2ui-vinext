# T396 — Client Delivery Readiness: End-to-end client functions security and authz audit

## Summary

Audit and verify the end-to-end authorization floor for client-facing capabilities (client CP, onboarding, guest portals, and API routes). Ensures active-hat enforcement, tenant isolation, and prevents unauthenticated data leakage across all client functions.

## Acceptance Criteria

- [ ] AC1 — Audit all client-facing Edge Functions and API endpoints to verify strict session and tenant isolation.
- [ ] AC2 — Enforce active-hat validation across client onboarding and workspace invite flows.
- [ ] AC3 — Verify that client data queries evaluate authenticated RLS policies and fail closed on anon access.
- [ ] AC4 — Author automated security verification probes in `wom7sec` testing cross-tenant access denial.
- [ ] AC5 — Run `just security-check` and confirm 0 high/critical findings across client surfaces.

## Definition of Done

Per [`../../openspec/SPEC-AUTHORING-STANDARD.md`](../../openspec/SPEC-AUTHORING-STANDARD.md):
- Security audit matrix documented across client edge functions and API endpoints.
- All 5 acceptance criteria verified with red-probe authz and tenant-isolation test cases.
- Automated security verification passes cleanly via `just security-check` with 0 high/critical findings.
- Changes committed referencing T396 with TASKS.md and GitHub issue #396 updated in sync.
