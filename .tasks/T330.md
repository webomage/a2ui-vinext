# T330 — Reconcile or remove stray top-level repo content

## Summary

Session audit (2026-09-08) of `wom7web`'s top-level directories/files, triggered by a design-system
placement review, surfaced several git-tracked items that don't fit the repo's own documented
conventions or look like accidental commits. **Ground-checked via `w0m-sdlc-research` before filing**
— that pass found and corrected two draft claims: (a) the skills-governance saga (`T127`/`T128`/`T182`/
`T313`) only ever documents the *dotted* `.agent/skills` (confirmed 0 files, still correctly retired
empty), never the *undotted* `agent/skills` found here, so this is genuinely new ground, not a
regression of an already-fixed problem; (b) `lib/tinybird.ts` is already claimed by `[[T43]]`
(observability/log-sink work, "deep research... `lib/tinybird.ts`", SPECIFIED) and independently noted
by `[[T155]]` ("Tinybird is NOT wired" as of that ticket's writing) — it is forward-looking scaffolding
for T43, not an orphan, and is explicitly **excluded** from this ticket (see AC5).

## Acceptance criteria

- [ ] AC1 — **`agent/skills/`** (undotted, 207 tracked files / 46 skill dirs) is a THIRD skills
      location, distinct from the governed pair `.agent/skills` (dotted singular, retired, confirmed
      **0 files** — T127's fix held) and `.agents/skills` (dotted plural, canonical, 377 tracked
      files). By name it is a strict subset of `.agents/skills` (`comm -23` between sorted dir
      listings returns empty) but has **not** been content-diffed file-by-file. Diff every one of
      the 46 shared-name dirs against its `.agents/skills` counterpart. If all are byte-identical,
      delete `agent/skills/` entirely. Any directory that differs is either reconciled or listed
      here with an explicit disposition — not silently dropped either way. It is currently invisible
      to `.w0m/skills.json` / `just skill check`; confirm the gate sees the outcome (absence or a
      declared+excluded entry).
- [ ] AC2 — **`db/activity_logs_schema.sql`, `db/technologies_schema.sql`, `db/technologies_seed.sql`**
      predate the migrations-only rule (first committed 2026-01-13 and 2026-02-16). The tables they
      define (`admin_activity_logs`, `tech_categories`) are referenced by several later, real
      migrations. For each file, confirm read-only against the live schema whether its DDL/seed is
      already fully represented by committed migrations. Fully superseded → delete the file. Any
      statement that never reached a migration → write that migration first (per the CLAUDE.md
      non-negotiable), then delete the loose file. `db/` does not exist at repo root when this
      closes.
- [ ] AC3 — **`scratch/`** (5 files) is not uniform, treat per-file:
      - `login_error.html`, `test_login.ts` (added 2026-05-08 in an unrelated SSR/auth bugfix
        commit) are ad-hoc debug artifacts. Confirm zero references anywhere in the repo, then
        delete both.
      - `Someone_Awesome_CV.md`, `Someone_Awesome_CV.pdf`, `generate_cv_pdf.py` (added 2026-05-22)
        look like a CV-rendering demo/test fixture set. Grep `apps/`, `packages/`, `specs/` for any
        reference. If referenced, relocate to a proper fixtures path with a one-line note of what
        uses it. If not, delete.
- [ ] AC4 — Tool-cache accidents: `.home/.npm/_update-notifier-last-checked`,
      `.home/Library/Preferences/astro/config.json`, and `.sitepins/config.json` (263 B, purpose
      unconfirmed as of filing). Confirm each is non-product — auto-generated by a tool via a
      stray `$HOME`, not read by any build/config path — and remove. If `.sitepins/config.json`
      turns out to be load-bearing, document what reads it instead of deleting it.
- [ ] AC5 — Closing note records what was investigated and explicitly **excluded** from this
      ticket's scope, so a future audit doesn't re-open it: `env/` (structured per-environment
      `.properties` config — legitimate), `screenshots/` (30M, `audit`/`goldens`/`reports`
      subdirs — looks like an intentional visual-regression golden-image setup; confirm it's wired
      to a real suite before ever touching it, don't assume bloat), `specs-resilience/` (deliberately
      placed outside `specs/` per its own header, actively referenced by
      `openspec/specs/site-resilience/spec.md`), `lib/tinybird.ts` (claimed by `[[T43]]`, not
      orphaned — see Summary), and the `@wom` workspace-root underscore folders (`_ds_arc`,
      `_ds_arc_pack`, `_ext`, `_in`, `_msg`, `_t99_arc` — already deliberately `.gitignore`d with
      documented rationale, reviewed 2026-09-08, no action needed).
