# T664 — Per-client tech mailboxes on `w0m.xyz` (Cloudflare Email Routing) and dedicated client Infisical org bootstrap workflow

## Summary

Bootstrapping client infrastructure (such as `pandatransfer.io` in [[T665]]) before the client registers in the portal—or when vendor accounts (Cloudflare, R2, license cabinets, VPS panels) sit behind client inbox OTPs or phone/SMS MFA—blocks autonomous delivery and mixes client credentials into agency-global tenants if handled ad hoc.

Grounding against live estate DNS (`2026-11-06`):
- `webomage.com` MX points to Google Workspace (`smtp.google.com`), so Cloudflare Email Routing cannot take over `webomage.com` root mail without disrupting Workspace delivery.
- **`w0m.xyz`** (`zone_id: 6ef3055469ff713dc17c5ce6b461b69e`) is active in the Webomage Cloudflare account (`bc601016b37b7d59e75bdb7e33b7f74d`) with **zero MX records**, making it ready for declarative **Cloudflare Email Routing** (`<client-slug>@w0m.xyz` -> operator inbox, plus post-DNS `ops@<client-domain>` forwarding).
- **Interim state for `pandatransfer` ([[T665]])**: Until `w0m.xyz` Email Routing is enabled and Cloudflare Admin delegation for `pandatransfer.io` lands, third-party vendor delegation uses `casualuser@gmail.com` and secrets are vaulted in `Webomage` Infisical project `pandatransfer` (`b2313889-594b-45de-9885-f241b8686f4d`). Once `pandatransfer@w0m.xyz` is live, a dedicated Infisical account/organization will be registered on `pandatransfer@w0m.xyz` and bound to `/home/aleksei/Projects/!proj/pandatransfer`.

This ticket delivers the reusable `w0m.xyz` tech-mailbox IaC, vaulted TOTP standard, dedicated per-client Infisical org bootstrap CLI/runbook, and the `pandatransfer@w0m.xyz` cutover.

## Acceptance criteria

- [ ] AC1 — **Declarative `w0m.xyz` Cloudflare Email Routing IaC (`w0m-api/cloudflare/`):** Enable Cloudflare Email Routing MX/SPF records on `w0m.xyz` via OpenTofu/Terraform (without altering `w0m.xyz` HTTP redirects in `redirects.tf`) and support per-client routing rules (`<client-slug>@w0m.xyz` -> verified operator destination, initially `casualuser@gmail.com`).
- [ ] AC2 — **Dedicated Per-Client Infisical Org + Vaulted TOTP Bootstrap Standard (`docs/CLIENT-IMPORT-PATH.md` & CLI helper):** Document and codify the two-stage client tech-identity workflow: (a) Day-0 `<slug>@w0m.xyz` tech mailbox, (b) dedicated Infisical account/org registered per client (`infisical login --save-as <slug>@w0m.xyz--<slug>` + `infisical profile bind`), (c) mandatory Authenticator TOTP (never SMS) with base32 seeds/recovery codes stored in Infisical `prod` (`*_TOTP_SEED`), and (d) post-DNS `ops@<client-domain>` Email Routing for zero-friction client handover.
- [ ] AC3 — **Cut Over `pandatransfer` Tech Identity (`pandatransfer@w0m.xyz` & `ops@pandatransfer.io`):** Provision `pandatransfer@w0m.xyz` Email Routing -> `casualuser@gmail.com`, register the dedicated `pandatransfer@w0m.xyz` Infisical account/org, migrate the `pandatransfer` `prod` secrets from `Webomage` workspace `b2313889-594b-45de-9885-f241b8686f4d` (`/` + `/backend` + `/frontend`), update `.infisical.yaml` + `clients-policy.json`, and configure `ops@pandatransfer.io` + Cloudflare R2 off-site Restic backups once `pandatransfer.io` Cloudflare Admin delegation is accepted.
- [ ] AC4 — **Verification & Quota Guards:** Add offline regression checks verifying `w0m.xyz` DNS/Email Routing Terraform resources coexist cleanly with `T653` redirect-ruleset quotas and `clients-policy.json` schema validation (`just schema-check`, `just client-inventory`).
