# T331 — make a debt citation checkable, not just a debt row

## Summary

`project/scripts/debt_register_check.py` runs five checks and **all five point the same way** —
from a row in `TECH-DEBT.md` outward to reality (DUPLICATE ID · DEAD PATH · DEAD TICKET ·
STALE TRACKING · RESOLVED-NOT-DELETED · UNOWNED). Nothing runs the other direction: from a
**citation** of a debt id in live prose back to the register. So a paid-down debt keeps its claim
alive in every file that cites it, and every gate stays green.

🔴 **This is not hypothetical — it shipped, and it shipped into the skill built to catch it.**
[[D32]] (*"the `@wom` workspace root is not a git repo, so its configs are unversioned"*) was
**closed 2026-09-02** by [[T312]], when `@wom/` became `casualuser/w0m` and its configs became
tracked. Its row was deleted, as `CLAUDE.md:33` instructs (*"delete rows the ticket pays down"*).
On **2026-09-07 — five days later — six live surfaces still asserted the false claim**, one of them
`.agents/skills/fact-checker/SKILL.md`, which cited *"see debt row D15"* for a file whose location
it also got wrong. The skill whose entire job is verifying claims against current state was
carrying a stale claim about a debt row that no longer existed. Repaired by hand the same day;
**nothing stops the next one.**

🔑 **The root cause is that the register has no memory.** Because a paid-down row is *deleted*,
there is nowhere to look up "was there ever a D32, and what stopped being true?" A rowless citation
is therefore genuinely ambiguous today, which is why a naive rule would be wrong — see AC3.

## Acceptance criteria

- [x] AC1 — **A closed-debt ledger exists and is append-only.** One entry per paid-down id:
      `id`, close date (absolute), the ticket that paid it, and **one line naming what was true and
      is not any more**. Backfill the 10 real ids above (`D2`, `D5`, `D9`, `D15`, `D18`, `D22`, `D25`,
      `D32`, `D37`, `D42`, plus `D1`, `D27`, `D33`, `D35`, `D38`, `D48`, `D50`, `D53`, `D61`, `D63`,
      `D66` = 21 closed-ledger rows total in `TECH-DEBT.md` `## Closed-Debt Ledger`). 🔑 The last field is the load-bearing one —
      without it a reviewer can see that `D32` closed but not that *"@wom is not a git repo"* is the
      sentence to stop repeating.
- [x] AC2 — **A new check runs citation → register.** Every debt id cited in a declared live surface
      must resolve to either an open row or an AC1 ledger entry; an id resolving to neither is a
      finding. 🔴 Must be wired into `--enforce` and reachable from `just`, alongside the five
      existing checks — a check nothing invokes is [[T22]] AC3's gap, not a gate.
- [x] AC3 — **The grammar for "asserts" vs "mentions" is written down before it is coded.** A
      rowless id is the *designed* end state of a paid-down debt, so "no row" alone cannot be the
      finding. The finding is a citation that **asserts a closed debt as live** (`see debt row D15`,
      `blocked by D32`) — not a dated historical reference (`D15 closed 2026-08-31`), of which
      `TECH-DEBT.md`'s own `D36` row and the repaired fact-checker skill are both legitimate
      examples. ⚠️ Of D15's 17 citations, at least two are correct history; a rule that reddens
      those trains the avoidance [[T135]] AC8 warns about.
- [x] AC4 — **The report prints its denominator and its precision.** Name the surfaces scanned and
      the id-matching rule, and exclude the `D0` artefact class by construction rather than by a
      hardcoded skip. An unmeasurable citation gets **its own state**, not a silent pass and not a
      violation ([[T242]]).
- [x] AC5 — **Both directions proven RED** in `project/scripts/tests/test_debt_register_check.py`
      (131 lines today), per [[T135]] AC7/AC8: injecting a citation of a nonexistent id must make
      `--enforce` exit non-zero, and closing a row without a ledger entry must be named. A gate
      observed only passing is a hypothesis.
- [x] AC6 — **The D32 sweep is not re-done by hand.** Once AC2 runs, the 10 backfilled ids are
      re-checked mechanically and any surviving live assertion is either fixed or recorded.
      🔴 **Three hand sweeps for ONE claim, three wrong answers — this AC is the whole ticket in
      miniature:** (1) a positive pathspec mixed with `:!` exclusions matched nothing and reported
      **0** live citations; (2) re-measured as *"six surfaces"*, which was six **assertions** out of
      41 files citing the id; (3) after repairing those six I stated only the fact-checker skill
      still restated it — **wrong again**, five more files asserted it in the present tense
      (`T161`×2, `T166`×2, `T199`, `T255`, `emoji_policy_check.py:169`), annotated 2026-09-08.
      ⚠️ **And the pattern that finally found them also matches every correction that QUOTES the
      claim** — including this ticket's own row. A sweep cannot separate assertion from mention,
      which is precisely why AC3 comes before AC2.
