# T315 — Bridge w0m units to project delivery roles and enable member staffing in CP

## Summary

Owner direction 2026-09-04:
*"here I also can't see w0m units assignment to project roles"* and *"do, and find related tickets to update it as well"*

While [[T311]] created `public.project_roles` with `min_unit_id uuid references public.units(id)` and supported `minUnitId` in the API, the frontend CP experience was left incomplete:
1. `ProjectRolesModal.svelte` does not fetch `public.units`, does not display the backing w0m unit on configured role cards, and lacks a `Backing w0m Unit` dropdown in the role creation/edit form.
2. `ProjectRolesModal.svelte` only lists wearers who are actively wearing the hat, with no direct UI mechanism (`+ Assign Member`) to assign a team member to a project role (writing a `public.hats(profile_id, project_id, project_role_id)` row).
3. In `ProjectManager.svelte:566`, the Groups view omitted the `Roles` action button from project rows (it was present in List view only).
4. In `ClientManager.svelte:381`, the `no portal access` marker and `grant access` button are suppressed for clients with 0 memberships due to a count check evaluating `undefined` as `false`.

This ticket bridges w0m units to project delivery roles in the CP, implements direct member staffing in the modal, restores the missing Roles button in Groups view, and fixes the portal access marker.

## Acceptance criteria

- [x] **AC1 — Backend API joins backing w0m units and supports member assignment.** `GET /api/project/roles?projectId=...` joins `units(id, title, squad)` to return `unit_title` and `unit_squad` alongside `min_unit_id`. `POST /api/project/roles` (or assignment action) allows assigning/unassigning a team member's profile to a project role by creating/deactivating `public.hats` rows.
- [x] **AC2 — Backing w0m Unit selector and badge in `ProjectRolesModal`.** `ProjectRolesModal.svelte` fetches `public.units` on mount. Each role card renders a visible badge indicating its backing unit (e.g. `🏛️ Backing Unit: Senior Architect` or `None`). The role creation/edit form provides a `Backing w0m Unit` dropdown selector binding `min_unit_id`.
- [x] **AC3 — Direct member staffing in `ProjectRolesModal`.** Under each role card in `ProjectRolesModal.svelte`, show assigned team members with an inline `+ Assign Member` button (with team member picker) to assign team members to delivery seats directly.
- [x] **AC4 — Groups view parity in `ProjectManager`.** Add the `Roles` button to project rows in Groups view (`viewMode === "groups"`) in `ProjectManager.svelte`.
- [x] **AC5 — Fix "no portal access" marker in `ClientManager`.** Correct `memberCounts` evaluation in `ClientManager.svelte:381` so clients without linked accounts display the `no portal access` badge and actionable `grant access` button.
- [x] **AC6 — End-to-end verification.** Verify on *Artemio, quiero comer!* that: (1) w0m units can be linked to delivery roles; (2) Aleksei (`aleksei@webomage.com`) can be assigned to `PM`, `TPM`, and `Dev` roles; (3) Groups view has the Roles button; and (4) unlinked clients on `/business/clients` show portal status.
