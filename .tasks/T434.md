# T434 — Typed-decision capability: System One contract with Jev, Kev and Laya providers, the Laya adapter contributed upstream

## Summary

Many w0m call sites ask a **bounded question** — a label, a yes/no, a score, pick one of N — but answer it
with a generative LLM whose text is then string-parsed, or with a regex/threshold that is really a semantic
judgement. A typed-decision model answers those directly, with a calibrated probability, in one forward pass.

This ticket adopts **TypeSafe's System One HTTP contract** as the one interface, with three providers behind it,
selected by `base_url`:

| Provider | What it is | Contract | Runs where |
|---|---|---|---|
| **Jev** | TypeSafe hosted SaaS (`jev-latest`) | native `POST /v1/systemone` | hosted — reachable from edge |
| **Kev** ([`jaredpalmer/kev`](https://github.com/jaredpalmer/kev), Apache-2.0) | Qwen3.5 0.8B/4B/9B LoRA + pointer head, "Jev-like", no Jev outputs in training | native `/v1/systemone` (+ `/permute`, `/separate`, `/v1/models`); `KEV_API_KEY` → Bearer | Mac via MLX (Kev-4B ~136 ms cached / ~721 ms new state on M5), or GPU on Modal (`modal deploy kev_serve.py` → HTTPS, reachable from edge) |
| **Laya** ([`mizorewww/laya-mlx`](https://github.com/mizorewww/laya-mlx), Apache-2.0) | MLX port of Convai's Laya (ModernBERT 421M / mmBERT 322M, 512–1024 ctx) | **none** — Python library (`laya.load`, `agent.predict`, `system_one` alias) + CLI only | Apple Silicon only — ~7–14 ms P50 on M3 Max; local tooling only, never edge |

Laya's `predict(state, questions)` already takes System One's shape (`type` ∈ `noul`/`choice`/`score`,
`instructions`, `criteria`), so the missing piece is a **thin HTTP serve mode**. That adapter is built as an
**upstream contribution** to `laya-mlx` (fork under the `webomage` org into `wom7pr/`, commits authored as
`casualuser@gmail.com`, tracked with `w0m-prs`), so every System One client — Switchboard, SystemOneHarness,
the TypeSafe SDK — gains Laya, not only w0m.

### Call-site inventory (2026-09-24, adversarially verified)

A 3-finder + verifier sweep found **70 candidate sites**. The verifier confirmed/corrected most and refuted 10
(deterministic questions — `validate-mermaid`, `emoji-script-output-emit`, `authz-failure-cause` — or duplicates).
They split by where they run, which decides which providers can serve them:

- **Local-capable** (Laya, Kev-MLX; Jev optional where data is not sensitive) — SDLC tooling: `type_backfill.py`
  (ticket type), `ticket_duplicate_check.py` (ticket-dups), `tasks_query.py` blocker inference, `ticket_audit.py`
  AC verdicts, `ticket_schema_check.py` unbuilt-claim detector, `spec_reality_check.py`, `dod_check.py`,
  `debt_register_check.py`, `ac_recipe_check.py`, `decommission_check.py`, `lessons_query.py`,
  `reports_ticket_check.py`, `sdlc_trace.py`, `wom7skills/skill_audit.ts`, `wom7api/scripts/ai-eval.ts` grader,
  `wom7web/tests/bot_security_steps.ts` judge; planned: T432 AC7, T357, T118 AC6, T101, T152 AC5, coding-agent
  task routing (T171), ZeroClaw escalation (T153).
- **Local-only** (sensitive input, or a TTY-less hook that cannot fetch hosted credentials): `repo_hygiene.py`
  secrets prose-vs-consume, `auto_memory_check.py`, `cv_overclaim_check.py`, `db_restore_verify.py`,
  `deploy_logged.py` trouble detection, `attribution_drift_check.py`; wom7sec injection screen/triage (T111).
- **Hosted-only** (Supabase edge fns, CF Workers/Workflows, CP SSR): chat safety guard (`guardrails.ts`, llama-guard
  3-8b, 2 calls/public turn), prompt-injection gate, lead-intake readiness, non-replayable-turn detection and RAG
  relevance (`chat-core.ts`), `proposal-seed.ts` blueprint match, `contact-submit` lead qualification,
  `manage-document` KB scope, `daily-news-scheduler` relevance, `grade-challenge`, `analyze-interview`,
  `cert-evaluator`, `job-scorer.ts` (wom7api) + `scorer.ts` (wom7func), `hn-jobs.ts` remote-type, KYC DENUE entity
  match, `parse-resume` seniority, `verify-credential` name match, `agent-architect` scope gate.

🔴 **Every hosted-only site conflicts with [[T36]] AC2** ("provider set limited to `cloudflare` + `google`; no
third-party gateways, no new keys") and ROADMAP §17 (a provider plugs in behind `routeChat` as an `ai_models`
adapter). Jev and Kev-on-Modal are both new third-party hosts with new keys. **No edge site moves until an AgDR
records the exception** — which is why the pilot is local.

### Pilot — `type_backfill.py`

`wom7web/project/scripts/type_backfill.py` (`just type-backfill`) is the strongest measured baseline in the estate
and has no production blast radius. It is a 3-way `choice` {bug, feature, task}. Its own docstring (measured
2026-08-25) records why rules failed: 84% on 19 decided at first pass; "tightened" 100% but abstaining on 76%;
~75% real precision on transfer (T195 and T239 misread as `bug`). The rules were derived from the first 37
labels, and `.tasks/` now holds more human-typed tickets, so the rest form a held-out set. Title + first 900
characters fit Laya's context, so all three providers run through one harness on the Mac.

## Acceptance criteria

- [ ] AC1 — **Contract spec.** An OpenSpec change pins the System One request/response shape w0m depends on
  (`model`, `state`, `questions{<id>: {type, instructions?, criteria}}` → `answers`, `usage`, `latency_ms`;
  `noul` = P(yes), `choice` = `{choice, confidence, probabilities}`, `score` = `{score, confidence, legend,
  probabilities}`; `422` on invalid). Fields confirmed against Kev's implementation and TypeSafe's `/api` docs;
  every field only one provider returns is marked as such.
- [ ] AC2 — **Provider terms verified.** Licence, weight source and data terms recorded for each provider: Jev
  (TypeSafe ToS, data retention, pricing, auth), Kev (Apache-2.0; training-data licences per dataset), Laya
  (Apache-2.0 + NOTICE; Convai weight licence on Hugging Face). A provider whose terms forbid a use is
  excluded from that use.
- [ ] AC3 — **One client + provider registry.** A single client selects the provider by `base_url` from one
  registry. An unreachable, unauthenticated or malformed provider is an explicit error — **no silent fallback
  to another provider or to the old regex/LLM path** (AgDR-0025). Offline tests cover success, `422`,
  connection refused and malformed answers.
- [ ] AC4 — **Laya serve mode, upstream.** `laya-mlx` forked under the `webomage` org into `wom7pr/laya-mlx`;
  a thin HTTP serve mode exposes `POST /v1/systemone` and `GET /v1/models` over `laya.predict`, binds
  `127.0.0.1` by default, and has upstream-style tests. The PR is opened **only after the owner approves it**,
  and it is tracked with `w0m-prs` / `just forks-check`.
- [ ] AC5 — **Pilot benchmark.** The pilot harness runs `type_backfill.py`'s question through Laya, Kev-MLX
  (0.8B and 4B) and Jev against the held-out human-typed tickets, reporting per provider: accuracy and
  macro-F1, risk–coverage (selective accuracy at each confidence threshold), calibration (Brier / ECE), and
  P50/P95 latency. The rule classifier is scored at the same coverage. Results live in the ticket, not only
  in a report.
- [ ] AC6 — **Pilot decision.** The owner decides adopt / reject for `type_backfill.py` from AC5, against the
  bar ≥80% accuracy at ≥60% coverage. The decision is recorded in `docs/DECISIONS.md`. `--apply` stays unwired
  until the owner decides.
- [ ] AC7 — **Hook posture.** Any site adopted inside a pre-commit or pre-push hook reports **UNMEASURABLE**
  when its model is down or unreachable. It never silently reverts to the regex, and it never blocks as if a
  violation were found (T242).
- [ ] AC8 — **Edge gate.** An AgDR decides whether a hosted provider (Jev, or Kev on Modal) may serve edge
  sites despite T36 AC2, and on what terms (data leaving the estate, keys, a sibling `/v1/systemone` route
  beside `/ai/chat`). No hosted-only site is changed before that AgDR exists.
