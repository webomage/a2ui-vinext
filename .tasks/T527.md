# T527 — state-check is blind at push, so the first place it fails is the deploy

## Summary

Found 2026-10-01 when `just deploy-all` failed at its preflight: `state-check` reported T525 and T526 as "newly invisible", because the rendered board `TASKS.md` had no row for them. I had created both tickets and pushed three repos; every push passed.
Why: `wom7web/.husky/pre-push` step 17 runs `just state-check` only when the push range touches `STATE.md`, `TASKS.md`, `.tasks/` or `ROADMAP.md`, and it looks for them inside **wom7web's** range. Those files moved to the root repo ([[T414]]), so in wom7web they can never appear:
the step prints "tracking surfaces untouched in push range; state-check advisory/skipped" on every push, forever. The root repo's own pre-push has no `state-check` step. So the gate exists, is declared and passes, and no push can ever trigger it. The deploy preflight is the only place it runs. Same family as the stale-path trap [[T509]] is built to catch.

## Acceptance criteria

- [x] AC1 — **The root repo's push runs `state-check` when its range touches `STATE.md`, `TASKS.md`, `.tasks/` or `ROADMAP.md`**, and fails the push on drift. Red probe: a root push range that adds a ticket with no board row is refused.
- [x] AC2 — **wom7web's step is removed or repointed**, not left as a dead branch (AgDR-0025: no shim, no fallback). Whatever remains names the repo it actually inspects.
- [x] AC3 — **A probe pins the scope against the real layout:** it fails if the paths a hook greps for do not exist in the repo whose range it reads (the check that would have caught this one).
- [x] AC4 — **Creating a ticket re-renders the board.** Either the ticket-creating path runs `just tasks-render`, or a commit hook refuses a new `.tasks/T*.md` with no `TASKS.md` row, so the drift is caught at commit and not at deploy.
