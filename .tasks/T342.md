# T342 — manage .superpowers tooling and add code annotations doctor for overrides, hacks, and ignores

## Summary

Manage the `.superpowers` tooling directory so agent subagent-driven development runs do not
cause gitignore-audit failures or leave untracked dirt in workspaces, and introduce a
comprehensive code annotations doctor to audit and report debt markers across the estate
including overrides, hacks, ignores, todos, hotfixes, and lintexcludes.

## Acceptance criteria

- [x] AC1 — `.superpowers` tooling directories are registered in `project/ignore-policy.json` under `generated.dirs`, and ignored across git roots (`.gitignore`), allowing superpowers agent subagents/planning workflows to run cleanly without tripping `just ignore-audit`.
- [x] AC2 — A dedicated code annotations doctor (`project/scripts/annotations_doctor.py`) is implemented, accessible via `just annotations-doctor` / `just overrides-check`, and integrated into `just hygiene-check` (`repo_hygiene.py all`).
- [x] AC3 — The scanner covers all six requested categories across the 7 estate repos:
      1. Overrides: `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`
      2. Hacks: `HACK`, `WORKAROUND`, `XXX`, `TEMP`, `TEMPORARY`
      3. Ignores: `eslint-disable`, `prettier-ignore`, `biome-ignore`, `noqa`, `type: ignore`
      4. Todos: `TODO`, `FIXME`
      5. Hotfixes: `HOTFIX`, `PATCH`
      6. Lintexclude: linter exclusions and suppression directives
- [x] AC4 — The scanner implements the empty-input-set failure contract (fails if 0 files scanned) and excludes vendored, build, and generated directories (`node_modules`, `dist`, `target`, `.quartz-engine`, etc.).
- [x] AC5 — Offline regression test suite (`project/scripts/tests/test_annotations_doctor.py`) proves detection of each annotation category on synthetic fixtures and proves empty-set failure.

## Definition of Done

Per [`../../openspec/SPEC-AUTHORING-STANDARD.md`](../../openspec/SPEC-AUTHORING-STANDARD.md):
`.superpowers` is declared in `ignore-policy.json` and `.gitignore`, `annotations_doctor.py` accurately identifies debt markers across all 7 governed estate repos with exit-0 report and exit-1 enforce modes, unit tests in `project/scripts/tests/test_annotations_doctor.py` verify detection and empty-corpus rejection, and all gates pass cleanly.
