# T785 — Fix OpenDesign PR #9500 bundle font/logo probing when packageInfo.availableFiles is absent

## Summary

In `nexu-io/open-design` PR `#9500` (`fix/local-import-palette-fonts-logo`, [[T759]]), `parsedToKit` in `design-kit.ts` called `firstAvailablePackageFile(opts.packageInfo, ['fonts/manifest.json'])` without checking `Boolean(staticUrl && Array.isArray(opts.packageInfo?.availableFiles))`. Because `hasAvailablePackageFile` defaults to `true` whenever `packageInfo?.availableFiles` is not an array, prose-only or mock design systems without `packageInfo` received a synthetic `fontsManifestUrl`, causing `useBrandFonts` in `DesignKitView.tsx` to fire an unexpected `fetch('/api/design-systems/.../static?path=fonts%2Fmanifest.json')` on mount and fail 3 fetch-count assertions in `DesignSystemsTab.sync-to-team.test.tsx`.

Gate bundle logo and `fonts/manifest.json` resolution in `parsedToKit` on `Boolean(staticUrl && Array.isArray(opts.packageInfo?.availableFiles))`, verify `DesignSystemsTab.sync-to-team.test.tsx` (13/13) + `import.test.ts` (4/4) + `pnpm typecheck` + `pnpm guard`, push GPG-signed to `webomage/open-design`, and merge into `local/sdlc-integration`.
