# T375 — Commit-bound pre-push checkpoints: skip unchanged commits, auto-continue from last failed step, and arbitrary step restart

## Summary

Owner directive, 2026-09-18:
> *"we have to midify prepush steps to run against commit hash, do not run if commit not changes and be able to continue/restart from any step, auto continue should take place from last failed step if commit hash is the same"*

Currently, `.husky/pre-push` runs a sequential chain of ~20 quality, security, and integrity gates (`check_git_identity`, `typecheck` across Astro apps, `w0m_audit`, `sdlc-trace`, `authz-probe`, `deps_sync`, `docs-check`, `license-check`, `dep-licenses-check`, `cv-leak-check`, `dod-check`, `client-page-tenancy-test`, `suites-drift`, `debt-check`, `drop-callers`, `state-check`, etc.) taking 3–6 minutes per run.

When a gate fails near the end of the sequence (e.g. `drop-callers` or `client-page-tenancy-test` at minute 4), or when an identical commit is re-pushed, the entire pre-push sequence currently restarts from the beginning, repeating expensive checks (`astro check` ~30s, `dod-check` ~70s) that already passed.

This ticket introduces a commit-bound checkpoint runner for pre-push hooks:
1. **Commit-Hash Bound**: All step results are tracked against `HEAD` commit hash in `~/.cache/w0m/prepush/<hash>.json`.
2. **Zero-Cost Push on Unchanged Certified Commits**: If all steps already passed for `HEAD`, pre-push exits 0 in <1s.
3. **Auto-Continue**: If step N fails, fixing the environment or external issue without changing the commit re-runs only from step N forward, skipping steps 1..N-1.
4. **Step Control**: CLI/env overrides (`PREPUSH_FROM=<step>`, `PREPUSH_RESET=1`) allow resetting or resuming from any step.
5. **Fail-Closed Invalidation**: A new commit hash automatically invalidates old checkpoints, requiring a full run for new code.

## Acceptance criteria

- [x] AC1 — **Commit-Hash Bound Checkpoint State**: Pre-push gates record step execution status (step ID, name, status, timestamp) keyed by `HEAD` commit hash in a persistent cache directory (`~/.cache/w0m/prepush/<commit-hash>.json`), out of the git working tree.
- [x] AC2 — **Skip Unchanged Certified Commits**: If all pre-push gates have already succeeded for the current commit hash, subsequent push attempts report instant pass (`All N pre-push gates certified for <hash>`) and exit 0 without re-executing steps.
- [x] AC3 — **Auto-Continue from Last Failed Step**: If a pre-push run fails at step N on commit hash X, a subsequent run on commit hash X reuses cached passes for steps 1..N-1 and automatically resumes execution from step N.
- [x] AC4 — **Arbitrary Step Restart & Control**: Provide flexible restart controls via environment variables and CLI (`PREPUSH_FROM=<step_id>`, `PREPUSH_RESET=1`, `just prepush-reset`, `just prepush-status`) allowing developers to restart from step 1, skip to a specific step, or inspect checkpoint progress.
- [x] AC5 — **Fail-Closed Safety on Commit Change & Corruption**: Any change in commit hash (`HEAD`) initiates a fresh check sequence; unparseable or corrupted checkpoint files trigger a clean fallback to a full run.

## Definition of Done

T375 is done when:
1. Re-pushing an already-certified commit hash skips all steps and exits 0 in <1 second.
2. A failed pre-push step records failure in the checkpoint file and subsequent push on the same hash resumes from that failed step.
3. Changing `HEAD` commit hash automatically starts a fresh run from step 1.
4. `just prepush-status` and `just prepush-reset` recipes are operational.
5. Automated test suite proves skip, auto-continue, step override, and invalidation semantics.
