# T432 — Delivery & DevEx measurement: DORA 5-metric cockpit, Agent-DevEx signals, DX Core 4 scorecard, SPACE charter

## Summary

Research (2026-09-23, owner request) into DORA, SPACE, DevEx and DX Core 4, and how w0m can use them
internally and as a client offering. Full report and diagram:
[`2026-09-23-t432-research-dora-space-devex-for-w0m.md`](../.agents/reports/2026-09-23-t432-research-dora-space-devex-for-w0m.md)
· [`.mmd`](../.agents/reports/2026-09-23-t432-research-dora-space-devex-for-w0m.mmd).

What each framework is for:
- **DORA** measures the delivery pipeline. It now has 5 metrics: throughput (lead time, deploy frequency, failed-deployment
  recovery time) and instability (change fail rate, and the new *deployment rework rate*). The 2025 report dropped the
  elite/high/medium/low tiers in favour of 7 team profiles.
- **DevEx** measures friction (feedback loops, cognitive load, flow).
- **SPACE** is the rulebook (≥3 dimensions, ≥1 perceptual, never a single metric).
- **DX Core 4** is the one-page scorecard that combines the other three (speed · effectiveness · quality · impact).

The w0m position, measured read-only:
- `deploy_log` + git already give deploy frequency and lead time.
- **Nothing records whether a deploy failed or was unplanned**, so change fail rate and rework rate are unmeasurable.
  That needs one migration.
- Activity metrics are degenerate here: 967 agent commits in 30 days in wom7web (the T261 lesson). DevEx is adapted to
  **agent friction** (hook time, gate failures, permission prompts) plus a weekly 3-question owner pulse.
- A first Core 4 *Impact* reading from `.tasks/` `area:` puts ~24% of tickets in product and ~49% in w0m's own delivery
  platform. That is the ratio this work makes visible.

The same extractor can later back a client SKU, the *"Delivery & Developer-Experience Baseline"* (2–4 weeks). The name
avoids "DORA", which in the EU usually means the Digital Operational Resilience Act.

## Acceptance criteria

- [x] AC1 — A measurement-charter AgDR is recorded in `docs/DECISIONS.md`. It requires ≥3 SPACE dimensions and team or
  system level only; activity (commits, PRs, tokens, agent-task counts) is shown as context, never as a target; and
  *could not measure* is its own state and never reads as success (T242 lesson).
- [x] AC2 — Audit whether every deploy path (`just deploy`, `just deploy-all`, `just deploy-function` from [[T431]]) writes
  a `deploy_log` row, with evidence recorded in Status notes. Any path that doesn't is fixed before any metric is published.
- [x] AC3 — A migration adds `deploy_log.outcome` (success · failed · rolled_back · hotfixed), `trigger` (planned ·
  incident) and `incident_ref`. Deploy recipes write them, and a missing value fails closed. The agent prepares the
  migration; **the human runs `just db-migrate`**.
- [x] AC4 — A structured incident record exists, with detected_at, recovered_at and cause-deploy fields. The owner decides
  where it lives: a table, or `.incidents/*.md` mirroring the `.tasks/` pattern.
- [x] AC5 — `just dora [--since N] [--service X]` emits the 5 DORA metrics as JSONL, marking each one `unmeasurable` (with
  the reason) when its inputs are missing. It has a test suite registered in the stack registry.
- [x] AC6 — Agent-DevEx signals (hook duration, gate failures per commit, permission prompts per session) and a weekly
  3-question owner pulse (1–5) are logged to JSONL.
- [x] AC7 — `just dora` also emits a DX Core 4 scorecard (Speed · Effectiveness · Quality · Impact). Impact starts as the
  done-ticket share by `area`. The 80 tickets whose `area:` is marked *inferred* are confirmed before the first reading is
  published.
- [x] AC8 — A DORA AI Capabilities Model (v2025.2, 7 capabilities) self-assessment is committed to `.agents/reports/`.
- [x] AC9 — The owner decides on a CP "Delivery" panel and a Tinybird dual-write (fits [[T43]]): adopt now, later, or never.
- [x] AC10 — The owner decides whether to productize the client offering. If yes, a one-page outline (scope, phases, price
  hypothesis) is committed; if no, the decision is recorded with its reason.
