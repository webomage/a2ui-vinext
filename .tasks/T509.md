# T509 — Root-first layout: finish the T414 move, staged

## Summary

Owner direction, 2026-09-30: *"we have to operate from the w0m workspace by default, with folders like wom7web inside"*, and
review whether more helper commands should move **up** from `wom7web` and `wom7api`. Deep research was done read-only the
same day (full report in the session scratchpad, `research-root-migration.md`). Its conclusion: **the estate is half-moved,
and the half-move is what keeps breaking things.** T414 (2026-09-21) lifted 64 scripts and ~19 policy files to the root but
left 76 more estate-wide scripts, 26 of their tests, one justfile that really lives in `wom7api` and 24 shadow symlinks
behind. The leftovers failed quietly as missing files. This session alone found and fixed about 20 of them in advisory
suites ([[T414]] leftovers in `client-profile`, `client_check`, profile gates and two recipes).

**Recommendation: staged by area (O2), starting with the stale-path probe as unit U0**, in 10 one-session units, each a clean
cutover with no shim. Rejected: a single big-bang cutover (294 reference sites, 120 tests and 5 host agents in one change on
a shared tree), probe-only (it moves nothing, so it fails the owner's direction), and a forwarding facade (the shim that
AgDR-0025 forbids, and the cause of today's dangling recipes).

Verified by hand while writing this ticket: `just sdlc-start` at the root fails with *"justfile does not contain recipe
`sdlc-start`"*; the root forwarder `just --justfile wom7web/justfile sdlc-start` points at nothing. `justfile-calls-check`

`sdlc-archive`) are dangling.

**No existing gate checks that a script file exists.** Five gates check "the recipe exists"; none checks "the file this
recipe, hook or profile runs exists". A prototype scan found 8 stale recipes, about 20 stale JSON references (some probably
functional: the emoji-policy `discovery_exempt` keys are keyed by old `file:line` paths) and 50+ usage docstrings naming old
paths.

## Findings carried over from the T508 research

Readers that share the same root-anchored shrink (not fixed by [[T508]]): `client_check.py` and `client_profile_check.py`
report `k7` as 0 declared, `w0m skill estate` and `gaps` run from wom7web report every repo missing, and

## Design

- **Layout L2.** One flat recipe namespace at the root, split by area with `import` (not `mod`, not forwarders), per-repo
  justfiles removed. `just` resolves the nearest justfile upward, so with the symlinks gone `just tasks` works from inside any
  repo and runs with the root as its working directory. This was verified in a scratchpad with `just` 1.58.0.
- **Stale-path probe** `just stale-path-check` (exit 0 clean, 1 stale, 2 could not measure, the convention of
  `justfile-calls-check`). It scans five carriers: recipe bodies (via `just --dump --dump-format json`), JSON/JSONC policy
  and profile files (keys too), hook configs, test-runner config, and host-level launch agents. It is extended from
  `justfile_calls_check.py` (so there is one tool, not two) to resolve `--justfile` targets and reject duplicate recipe
  names. Exemptions require a written reason, and a stale exemption is itself reported.
- **Every unit** runs in an isolated worktree, moves files with `git mv`, updates 100% of the area's callers in the same
  commit pair, keeps the old symlink deletion as its last commit so a revert restores it, and leaves no shim.

## Risks

1. **Shared tree.** Moving 76 files and rewriting about 294 reference sites while another agent edits the same scripts loses
   work. Mitigation: a worktree per unit and `git status` before and after. Known traps are in memory (pre-commit stash drops
   unstaged work when a dashboard regenerates; `git mv` followed by a failed commit and reset can drop the new tree).
2. **The root is invisible to `just search` and `just ask`** (no `.codegraph/`, not in the graph union), so each moved script
   leaves the code graph. Re-indexing is a step of every unit; creating the root index needs the owner's approval.
3. **Secrets handling.** Root recipes pin `infisical --projectId`; wom7api recipes rely on a `.infisical.json` in their own
   directory. A recipe moved to root without `--projectId` breaks silently (T421 did this once). Probe candidate: every root
   `infisical run` carries `--projectId`.
4. **Host references outside git:** 5 launchd plists and `.claude/settings.local.json` (globally gitignored). Only the probe's
   host mode finds them.
5. **Not atomic across repos.** Root and wom7web are separate repos, so a unit lands as two commits; verify locally, then push
   together.
6. **Two hardcoded absolute paths** (`tech-debt` recipe, `.mcp.json`) break on any other checkout.
