# T417 — Add Review Feedback and Comments Inspection Column to w0m-prs Table

## Summary

`w0m-prs` (`just prs`, `just prs-open`, `cmd_table()`) audits and displays active pull requests across the `w0m7pr` upstream dependency set (`oraios/serena`, `stablyai/orca`, `openai/tart-guest-agent`, `jundot/omlx`, `cirruslabs/tart`, etc.).

Currently, `cmd_table()` displays:
`| Repository | PR | Title | State | Mergeable | Review | CI | URL |`

While `Review` shows the top-level GitHub review status (`APPROVED`, `CHANGES_REQUESTED`, `REVIEW_REQUIRED`, `NONE`), it provides zero visibility into:
1. Reviewer or maintainer questions (`?` in discussion comments or review comments).
2. Review suggestions (e.g. GitHub suggestion blocks ```` ```suggestion ````).
3. Review activity or unaddressed feedback threads (inline diff comments and review comments from non-author contributors).

As seen on `oraios/serena#2085`, maintainers frequently leave critical questions (e.g., architectural questions on companion servers) or inline review comments that require contributor action, but `just prs-open` simply shows `Review: NONE` or `COMMENTED` without indicating pending questions or suggestions.

This ticket adds a dedicated `Feedback` column to the `w0m-prs` table (both terminal aligned table and Markdown table) that inspects comments and reviews, detects questions (`?`), suggestions, and comments from non-author contributors, and displays high-signal visual badges/counters (e.g. `❓ 1 question`, `💡 suggestion`, `💬 2 comments`, `clean`).

## Acceptance criteria

- [x] AC1 — `audit_pr()` parses and aggregates non-author comments, questions (`?`), and suggestions (```` ```suggestion ````, suggested changes, or review threads) from GitHub PR comments and reviews.
- [x] AC2 — `cmd_table()` adds a `Feedback` column positioned after `Review` across both Markdown (`--markdown`) and terminal aligned table views.
- [x] AC3 — Non-author questions display an indicator (e.g. `❓ <n> q`), suggestions display `💡 <n> sugg`, external comments display `💬 <n>`, and clean/idle PRs display `-` or `clean`.
- [x] AC4 — `test_w0m_prs.py` includes tests asserting feedback extraction, question/suggestion parsing, and table header/data alignment with the new column.
- [x] AC5 — Zero `--no-verify` used and all pre-commit hooks / existing PR tests pass.

## Definition of Done

1. `just prs-open` and `just prs table --preset wom7pr` render the `Feedback` column with clear question and suggestion indicators.
2. `test_w0m_prs.py` passes 100% green.
3. No `--no-verify` flag used.
