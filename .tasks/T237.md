# T237 — the specs validate. That is not the same as testing anything.

## Summary

Owner 2026-08-19: *"it looks it's time to revalidate our specs against reality"*.

🔬 **`gauge validate specs` reports `No errors found` across all 190 specs.** That check is real and
it answers *"does every step have an implementation?"* — **not** *"would any of this fail if the
product broke."* A step implemented as `// Visual check` validates perfectly.

Measured 2026-08-19 by `just spec-reality` (`project/scripts/spec_reality_check.py`):
**190 specs · 585 scenarios · 461 implemented steps.**

### 🔴 1. Four authorization tests pass for the wrong reason

`candidate user is logged in` is a **stub** — `// Stub — candidate login not yet implemented`, empty
body. There is **no candidate login helper anywhere in the harness**. So these four scenarios run
with *nobody* logged in:

| spec | scenario |
|---|---|
| `specs/web/admin_ai_simulator.spec` | CP AI Simulator page is blocked for candidate users |
| `specs/web/admin_cp_personas.spec` | CP AI Personas page is blocked for candidate users |
| `specs/web/admin_system_domains.spec` | Domain Scanner page is blocked for candidate users |
| `specs/web/admin_system_tasks.spec` | CP System Tasks page is blocked for candidate users |

Each then asserts `user is redirected away from the CP` — which **an anonymous user satisfies**. ⇒
The tests are green, and would stay green **if candidates had full CP access**. This is worse than
an absent test: an absent test is visibly absent. 📌 It is also the shape [[T202]] AC7 just dealt
with — a conclusion true for a reason unrelated to what it claims to prove.

### 🔴 2. Ten scenarios where not one step verifies anything

Setup/teardown excluded (they legitimately assert nothing).

| spec | scenario | steps |
|---|---|---|
| `specs/api/006-dsl-models.spec` | Core tracks and at least one codemap are defined | 11 |
| `specs/api/063-openspec-models.spec` | Core tracks and at least one codemap are defined | 11 |
| `specs/api/008-visual-identity.spec` | Footer Gradient Mask and Opaque Background Preserved | 4 |
| `specs/api/008-visual-identity.spec` | Static Hero Content (Visual Identity) | 4 |
| `specs/api/008-visual-identity.spec` | Static Features List | 3 |
| `specs/api/011-openspec-integration.spec` | Upwork Integration Codemap and Track | 2 |
| `specs/web/goldens.spec` | Page matches visual golden snapshot | 1 |
| `specs/web/goldens.spec` | Homepage sections match their goldens across viewports | 2 |
| `specs/web/navigation_main.spec` | Main Navigation Links Work | 1 |
| `specs/web/navigation_mobile.spec` | Mobile Navigation Menu Works | 3 |

📌 `goldens.spec` independently reproduces [[T222]] (*"Goldens exist and NOTHING compares them"*)
from the opposite direction — that ticket found it from the registry, this from the assertions.
⚠️ Two specs carry an **identical** 11-step scenario name — `006-dsl-models` and `063-openspec-models`.

### 🔴 3. Twenty-three claim-shaped steps whose body verifies nothing

The step **name** is the lie, not the body: `the "Footer" should be visible` → `// Visual check`.
`Verify database table <t> contains user email` → a `console.log` and a comment saying it skips the
check. Others read `// Basic check passed` — a comment asserting success.

## AC6 — the routes 404, and it compounds the authorization finding

Measured 2026-08-19 against a running stack:

| target | result |
|---|---|
| `web:4321/cp/interviews` · `/cp/system/users` · `/cp/ai/personas` | **404** |
| **production `webomage.com/cp/interviews`** | **404** |
| `cp:4325/cp/interviews` | 401 — the route exists, auth-gated |

`apps/web` has **zero** `/cp` pages; `apps/cp` has **58**. The CP moved on **2026-05-14**
(`12dade3e`), and `E2E_BASE_URL` still points at the web app. ⇒ **40 spec files · 102 scenarios ·
105 navigation steps have been driving a browser to 404 pages for three months.**

🔴 **This makes the four candidate-authorization scenarios TRIPLE-vacuous**, not merely stubbed.
`admin_ai_simulator`, `admin_cp_personas`, `admin_system_domains` and `admin_system_tasks` are all
in the 404 set, so each passes for three independent and compounding reasons:

1. `candidate user is logged in` is an **empty stub** — nobody is logged in;
2. the `/cp/*` route **404s** — the browser never reaches the CP at all;
3. *"user is redirected away from the CP"* is **trivially true** for someone who was never on it.

⇒ Fixing only the stub (AC1) would leave the test green and still meaningless. **AC1 and AC6 must
land together, and the fix must be red-proven against a real candidate on a real CP route** — which
is only possible now that a local stack exists ([[T238]]).

this ticket exists to prevent.** By cause:

| cause | scenarios | verdict |
|---|---|---|
| `ADMIN_EMAIL and ADMIN_PASSWORD must be set` | **102** | 🔴 **harness gap — mine.** `just e2e-local` wrapped the DEV SERVER in `infisical run` and not `gauge`, so the runner had no credentials |

Failing specs by area: `web` 54 · `api` 34 · `ui`/`visual` 6 · `live`/`ai`/`demo` 2 each · rest 1.

⇒ **~37% of the failures were my own misconfiguration.** The honest baseline needs a re-run with

injection deliberately**, so a new Supabase-shaped secret appearing in beta cannot silently redirect
the purge.

## AC6 — implemented 2026-08-20 (⚠️ awaiting the owner's corpus run to verify)

`tests/support/urls.ts` resolves a spec path to the app that actually serves it, and both navigate
steps now use it — including `"I am on the Admin CP at <path>"`, which was **named for the CP and
still resolved to the web origin**.

The CP is a **subdomain** (`PUBLIC_CP_URL`, production `cp.webomage.com`), so its paths carry no
`/cp` prefix: `apps/cp/src/pages/` has `ai/`, `business/`, `system/` at top level and **no `cp/`
directory**. A spec saying `/cp/system/users` means `system/users` **on the CP origin**.

🔬 **The corpus encodes a URL structure that is TWO refactors out of date.** Census of the 42
distinct `/cp/*` paths:

| | count | handling |
|---|---|---|
| resolve once the origin is corrected | **30** | ✅ fixed by the resolver |
| **moved** into a `/business/` namespace | **4** (`blueprints`, `contracts`, `projects`, `proposals`) | ✅ **corrected in the specs**, not in a redirect table |
| **exist nowhere** | **8** — `/cp/ai`, `/cp/ai/interviews`, `/cp/ai/personas`, `/cp/ai/simulator`, `/cp/managers`, `/cp/resources`, `/cp/slides`, `/cp/system/settings` | 🔴 **reported, not fixed** |

🔑 **The moved paths were corrected in the specs deliberately.** A resolver that silently rewrote
them would have made these specs pass while hiding the very staleness this ticket exists to find —
and would hide the next reorganisation too.

- [x] **AC6b — decide the 8 paths that exist nowhere.** Resolved 2026-10-01 directly in the specs:

      All 194 specs validate with 0 errors via `gauge validate specs`.
