# T626 — Fix `/me/account` `403 Forbidden` on MFA/PAT/Identities proxy APIs, unblock first-factor `/api/me/mfa` enrollment, and enforce explicit CP API route-table coverage

## Summary

Live owner inspection on `cp.webomage.com/me/account` (`TECH-LEAD` session) revealed red `⚠ Forbidden` alerts in both **Multi-Factor Authentication (TOTP / MFA)** and **Personal Access Tokens (PAT)**:

1. **Missing `ME_APIS` & Self-Auth Route Declarations in `cp-routes.ts`**: When `T479` moved `MfaEnrollment.svelte`, `PersonalAccessTokens.svelte`, and `ConnectedIdentities.svelte` onto same-origin cookie proxy routes (`w0m-web/apps/cp/src/pages/api/me/mfa.ts`, `w0m-web/apps/cp/src/pages/api/me/tokens.ts`, `w0m-web/apps/cp/src/pages/api/me/identities.ts`), none of those routes (nor `w0m-web/apps/cp/src/pages/api/profile/self-accounting-kyc.ts`, `w0m-web/apps/cp/src/pages/api/project/release-approval.ts`, `w0m-web/apps/cp/src/pages/api/payments/mercadopago-checkout.ts`, or self-authenticating webhook/extension endpoints) were registered in `w0m-web/apps/cp/src/lib/cp-routes.ts`. Because `cpRoutes()` ends with `{ test: () => true, subject: "admin-console" }`, `w0m-web/packages/lib/src/auth/route-inventory.spec.ts` treated every unlisted CP API file as declared while `w0m-web/packages/lib/src/auth/middleware.ts` rejected non-`admin` callers with `403 {"error": "Forbidden"}`.
2. **First-Factor `/api/me/mfa` Enrollment Deadlock in `mfa-policy.ts`**: `isMfaExemptRoute` exempted `/me/account` so an elevated user (`admin`/`manager`) with `0` enrolled factors (`currentLevel === "aal1"`, `nextLevel === "aal1"`) is sent to `/me/account?mfa_required=1`, yet `evaluateMfaRequirement` (`w0m-web/packages/lib/src/auth/mfa-policy.ts`) still blocked `/api/me/mfa` at `aal1` with `403 MFA_REQUIRED`.

## Acceptance criteria

- [x] **AC1 — Register Member/Client Proxy APIs in `ME_APIS` (`w0m-web/apps/cp/src/lib/cp-routes.ts`)**: Added `/api/me/mfa`, `/api/me/tokens`, `/api/me/identities`, `/api/profile/self-accounting-kyc`, `/api/project/release-approval`, and `/api/payments/mercadopago-checkout` to `ME_APIS` (`subject: "profile"`), plus AAL2 unlock notices and `w0m:mfa-verified` auto-reload across `w0m-web/apps/cp/src/components/profile/MfaEnrollment.svelte`, `w0m-web/apps/cp/src/components/profile/PersonalAccessTokens.svelte`, and `w0m-web/apps/cp/src/components/profile/ConnectedIdentities.svelte`.
- [x] **AC2 — Declare Self-Authenticating Webhook, Extension & Board APIs (`w0m-web/apps/cp/src/lib/cp-routes.ts`)**: Explicitly classified `PUBLIC_SELF_AUTH_APIS` (`w0m-web/apps/cp/src/pages/api/payments/mercadopago-webhook.ts`, `w0m-web/apps/cp/src/pages/api/webhooks/linkedin.ts`, `w0m-web/apps/cp/src/pages/api/sync/vault.ts`) + `isBoardApi` (`subject: "public"`), and `ADMIN_CONSOLE_APIS` + `isPostsApi` (`subject: "admin-console"`).
- [x] **AC3 — Allow First-Factor `/api/me/mfa` Enrollment at `aal1` Only When Unenrolled (`w0m-web/packages/lib/src/auth/mfa-policy.ts`)**: Allowed `/api/me/mfa` in `evaluateMfaRequirement` strictly when `!hasEnrolledFactor` (`nextLevel !== "aal2"` and `currentLevel !== "aal2"`), while preserving `403 MFA_REQUIRED` at `aal1` whenever `hasEnrolledFactor === true`.
- [x] **AC4 — Exhaustive CP API Disk-Parity Ratchet & Unit Regression Suite**: Added `isExplicitCpApi` filesystem parity ratchet + red mutation probe in `w0m-web/apps/cp/src/lib/__tests__/cp-routes.test.ts` (`55/55` pass), unenrolled/enrolled probes in `w0m-web/packages/lib/src/auth/mfa-policy.spec.ts` (`60/60` pass), and `TECH-LEAD` end-to-end AAL1/AAL2 lifecycle probe in `w0m-web/packages/lib/src/auth/middleware.spec.ts` (`17/17` pass; `180/180` total across 7 Vitest suites).

## Definition of Done

- All `/me/account` proxy APIs resolve to `subject: "profile"` in `cpRoutes()`.
- Unenrolled elevated users (`!hasEnrolledFactor`) can reach `/api/me/mfa` at `aal1`, while already-enrolled users (`hasEnrolledFactor`) at `aal1` continue to receive `403 MFA_REQUIRED` on `/api/me/mfa`.
- Every file under `w0m-web/apps/cp/src/pages/api` is explicitly covered by a named set/predicate in `w0m-web/apps/cp/src/lib/cp-routes.ts` (`55/55` in `cp-routes.test.ts`), and `route-inventory.spec.ts` (`21/21`), `mfa-policy.spec.ts` (`60/60`), `cp_nav_policy_test.py`, and `ticket_audit.py` exit `0`.
