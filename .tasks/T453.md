# T453 — One access foundation for every web app

## Summary

Owner, 2026-09-25: *"job app, and in general all of our web apps should use same foundation with solid
middleware and auth/rbac/access policies"*.

**Measured 2026-09-25 (state before any change):**
- 4 of 5 apps mount the shared `createAuthMiddleware` (`@webomage/lib/auth`): `cp`, `web`, `join`, `job`.
  **`demo` has no middleware**, yet `api/demo/enter.ts` uses the admin client.
- Each app declares route policy its own way: `cp` a subject table (`lib/cp-routes.ts`) plus the T439 context
  gate that exists only in cp; `web` a DB-driven `resolveSubject` that returns **public for every `/api/*`**;
  `join` one inline rule; `job` `routes: []`.
- So API authorisation is per-file. `web/api/admin/broadcast-extension.ts` says "Require admin session" and checks
  only `locals.user`, so **any signed-in account** can send `RUN_SPEC` with an arbitrary payload to the extension's
  `extension_commands` channel, over a service-role client. Mitigations measured: the extension subscribes only
  in `EXT_MODE === 'local'` (`wom7ext/extension/src/background.ts:47`). But it is a **public** Realtime broadcast
  channel, which anyone holding the public anon key can send to without calling this route at all.
- The sign-in, OAuth, magic-link, callback and sign-out endpoints are already thin wrappers over the shared
  handlers in every app. The exception is `job/api/auth/me.ts` (113 lines against ~22 elsewhere): it resolves identity
  and roles a second time instead of projecting `locals`, the way `cp/api/auth/me.ts` does.
- The MFA admin context (T100 AC8, `isAdminMfaContext`) and the admin/member domain rules are configured only in
  cp's middleware call.

## Acceptance criteria

- [ ] AC1 — **Every app mounts the shared middleware**, `demo` included; `just` gate fails on an app with no
  `src/middleware.ts` that calls `createAuthMiddleware`.
- [ ] AC2 — **One route-policy model** in `@webomage/lib/auth`: each app declares `{ path → subject/capability }`
  rules in one shape (pages AND `/api/*`); no app returns "public" for a whole prefix by default. Default for an
  undeclared `/api/*` path is **deny** (fail closed, AgDR-0025); public endpoints are listed explicitly.
- [x] AC3 — **`/api/admin/*` requires the held admin role in every app**, enforced by the middleware, with a red
  probe per app (signed-in non-admin → 403). `broadcast-extension.ts` fixed as the first case.
- [ ] AC4 — **`extension_commands` becomes a private Realtime channel** (RLS on `realtime.messages`, admin-only
  send), by migration; the extension subscribes with `config: { private: true }`. Owner applies the migration.
- [ ] AC5 — **`/api/auth/me` is one shared handler** projecting `locals`; job's bespoke re-resolution removed.
- [ ] AC6 — **The capability/context gate is shared**: the T439 gate model moves into the lib so any app can
  declare capability-gated routes; cp keeps working unchanged (its tests stay green).
- [ ] AC7 — **A cross-app policy check** (`just` recipe, in pre-push) lists every page and API route per app with
  its resolved policy, and fails on an undeclared route; red probes included.

## Definition of Done

T453 is done when every app in `wom7web/apps/` resolves identity, role and capability through the shared
middleware and one route-policy model, an undeclared API route is denied rather than public, `/api/admin/*`
refuses a signed-in non-admin in every app (red probe per app), the extension command channel is private, and the
cross-app policy check runs in pre-push. Quality gates clean; migration and deploy run by the owner (T435 gate).

  resolver is not consulted, so web skips a DB lookup). The existing portal policy then requires a held admin role and
  a @webomage.com email (403). Red probes per app (web, job, join, cp): a signed-in member is refused, a held admin in
  the manager hat is allowed; a permissive config cannot open the prefix. Auth suite 122/122, cp + lib 448/448,

  **Found and fixed on the way:** `stop-impersonate` sat under `/api/admin/`, but during impersonation the session is
  the target's (non-admin), so cp's catch-all admin gate answered 403 on "exit impersonation". It moved to
  `/api/auth/stop-impersonate`, which is always reachable (it only clears cookies and restores the httpOnly admin
  stash). All 5 callers were updated in one cutover.
  ⚠️ Semantics, unchanged from cp's existing behaviour: the ability check is hat-based, so an admin wearing the
  **member** or **client** hat is refused on admin APIs (the manager hat passes). `impersonate.ts`'s comment
  ("an admin viewing as member can still impersonate") has not been true under the middleware. Decide in AC2 whether
  admin APIs follow the held role, as T100 AC8 did for MFA.
