# T659 — Close Backstage and skills catalog drift loops across `skills-sync`, `w0m` CLI worktrees, root git hooks, and `session-complete`

## Summary

Measured on `2026-11-06` (`aleksei@HP`), `python3 scripts/w0m_cli.py catalog check` and `just catalog-check` (`guardrails` blocking suite) exited `1` (`2 finding(s)`), and `just skills-catalog-check` exited `1` (`1 finding(s)`):

1. **Live catalog drift on `origin/beta` (`a4bee84`)**:
   - `catalog-info.yaml` and `w0m-web/project/catalog-entities.json` held stale `w0m.dev/skill-observed-version: 2026.10.28-1793220550` on `AiResource` `skill-w0m-prs` vs `2026.11.06-1793946619` in `.w0m/skills.json` after `T655` updated `w0m-prs` via `just skills-sync`. This is the third consecutive skill-sync commit (`2635b66`, `6ea1835`, `a4bee84`) to leave Backstage catalog outputs drifted on `beta`.
   - `w0m-web/docs/SKILLS-CATALOG.md` drifted both from `w0m-prs` version/lockfile updates in `T655` (`2abda8ac8`) and from `oxfmt` table reformatting in `T646` (`36b14dabf`) because `docs/SKILLS-CATALOG.md` and `project/catalog-entities.json` were omitted from `w0m-web/.oxfmtrc.json` `ignorePatterns`.
2. **Asymmetric sync & `w0m_cli.py` worktree blindness (`AgDR-0032` violation)**:
   - `just skills-sync` in `justfile` ran `tsx skills.ts` (which calls `relockAll()` and mutates `.w0m/skills.json` across estate consumers) without invoking `w0m-web/project/scripts/catalog_sync.py --write` or `w0m-web/project/scripts/skills_catalog_gen.py --write`, unlike `w0m skill sync`.
   - `scripts/w0m_cli.py` hardcoded `ESTATE_ROOT = HERE.parents[1]` (the canonical live checkout) inside `handle_catalog`, `_run_catalog_sync`, and `handle_skill`, ignoring `--project` and `cwd`. Running `~/.local/bin/w0m catalog sync` or `w0m catalog check` from inside an `AgDR-0032` `agent-tree` mutated or inspected the shared live checkout instead of the caller's worktree, and unconditionally spawned `uv run --with pyyaml --with jsonschema` (~6–27s cold overhead) even when `sys.executable` already imports `yaml` and `jsonschema` natively (~0.2s).
3. **Missing commit, pre-push, and `session-complete` enforcement**:
   - `@wom/.pre-commit-config.yaml` and `scripts/root_pre_push.py` had no `catalog-fresh` / `catalog_sync.py --check` gate when `.w0m/sdlc.json`, `.w0m/skills.json`, `project/policies/stacks-policy.json`, or `catalog-info.yaml` changed in `@wom`.
   - `scripts/session_complete.py` (`harvest_and_refresh_surfaces` and `sync_worktree_onto_origin_beta`) omitted `catalog_sync.py --write` and `skills_catalog_gen.py --write`, and `.w0m/sdlc.json -> session_wrapup.verification_gates` omitted `just catalog-check` and `just skills-catalog-check`.

## Acceptance criteria

- [x] **AC1 — Regenerate Backstage & skills catalog surfaces and exclude generated catalogs from `oxfmt`**: Regenerate `catalog-info.yaml`, `w0m-web/project/catalog-entities.json`, and `w0m-web/docs/SKILLS-CATALOG.md` (`just catalog-sync` and `just skills-catalog`), make `write_catalog_artifacts` / `skills_catalog_gen.py --write` skip disk writes when rendered content is already byte-identical, and add `docs/SKILLS-CATALOG.md` and `project/catalog-entities.json` to `w0m-web/.oxfmtrc.json` `ignorePatterns` so `oxfmt` never reformats Python-generated catalog artifacts.
- [x] **AC2 — Wire `just skills-sync` to regenerate estate catalogs while keeping `check` read-only**: Update `skills-sync` in `justfile` so write runs (`mode == ""` or `mode == "--all"`) automatically run `w0m-web/project/scripts/catalog_sync.py --write` and `w0m-web/project/scripts/skills_catalog_gen.py --write` after `tsx skills.ts`, while `just skills-sync check` remains strictly read-only.
- [x] **AC3 — Make `scripts/w0m_cli.py` `AgDR-0032` worktree-aware with native Python fast path**: Resolve the target estate root from `--project` / `cwd` (walking up for `.w0m/sdlc.json` + `w0m-web/project/scripts/catalog_sync.py` before falling back to `HERE.parents[1]`) across `w0m catalog` (`check`, `sync`, `list`) and `w0m skill` (`sync`, `add`, `remove`, `update`, `relock`), use `sys.executable` directly when `yaml` and `jsonschema` are importable (falling back to `uv run` only when absent), and prove worktree isolation + fast-path execution in `scripts/tests/test_w0m_cli.py`.
- [x] **AC4 — Enforce `catalog-fresh` at `@wom` pre-commit and `root_pre_push.py`**: Add check-only `catalog-fresh` (`python3 w0m-web/project/scripts/catalog_sync.py --check`) to `.pre-commit-config.yaml` scoped to `^(\.w0m/sdlc\.json|\.w0m/skills\.json|project/policies/stacks-policy\.json|catalog-info\.yaml)$`, extend `scripts/root_pre_push.py` (`CATALOG_SCOPE_RE`) and `scripts/hooks_check.py` to block `@wom` pushes when catalog inputs/outputs drift, and pin both invariants with unit + red-probe tests in `w0m-web/project/scripts/catalog_sync_test.py` (`just catalog-check-test`) and `scripts/tests/test_t527_state_check_push.py`.
- [x] **AC5 — Wire catalog refresh & verification into `session_complete.py` and `.w0m/sdlc.json`**: Refresh `catalog_sync.py --write` and `skills_catalog_gen.py --write` in `scripts/session_complete.py:harvest_and_refresh_surfaces()` (and reset derived catalog files cleanly in `sync_worktree_onto_origin_beta()`), add `just catalog-check` and `just skills-catalog-check` to `.w0m/sdlc.json -> session_wrapup.verification_gates`, refresh `docs/DECISIONS.md`, and verify in `scripts/tests/test_session_complete.py` (`just session-complete-test`).
