# T78 — Auth session-hygiene hardening (residual G-items from T39)

## Summary

[[T39]] closed the security-critical Auth/RBAC scope (active-hat RLS enforcement, posts-INSERT
hole, minted-session impersonation, and moving policy authority off `app_metadata` — all verified
live 2026-07-18). Per T39's own plan, the **residual session-hygiene gaps** are spun off here so
T39 can archive cleanly. These are hardening items, not active exploits (authority already lives in
`user_roles` + the JWT hook; RLS is active-hat).

## Acceptance criteria

- [x] AC1 — **G1/G2/G7 (Med)** — unify the session path: kill the dual-cookie split-brain (cp reads the
      chunked SSR cookie, web/join read legacy `sb-access-token`); stop resolving roles via the
      **service-role** client (RLS-disabled) in web/join; make signout clear the **chunked SSR
      cookie** + `sb-active-role`/`sb-sudo-token` (cp currently stays authed after "sign out").
- [x] AC2 — **G4/G5/G6 (Low)** — `sb-active-role` → `httpOnly`; fix web private-page cookie parse (G5);
      add a CSRF token to the impersonation POST (G6, currently lax+JSON only).
- [x] AC3 — **G9/G10 (Low/Info)** — cp "member view" is display-only (impersonation gate re-reads
      `roles.includes('admin')`); `verifyToken` HMAC compare → constant-time.
- [x] AC4 — **app_metadata cleanup** — `wom7api/supabase/functions/admin-todos-api/index.ts:36` still
      writes a now-dead `app_metadata:{role:"admin"}` (nothing reads it for authority) — remove it.
- [x] AC5 — `docs/backend/AUTH-RBAC.md` G-table updated as each is resolved.
