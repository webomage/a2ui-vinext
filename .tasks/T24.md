# T24 — Skills expansion — import + survey

## Summary

Add [`kepano/obsidian-skills`](https://github.com/kepano/obsidian-skills) (Agent-Skills
spec: Obsidian markdown/wikilinks, Bases, JSON Canvas, Obsidian CLI, clean web-content
extraction) into `wom7skills`; survey the top skills on [skills.sh](https://skills.sh) and
decide per skill: **import/connect** vs **master & craft ourselves**; produce a skills
catalog (what we use, what we build).

## 🔗 Reconciliation with [[T127]] — recorded 2026-07-29 (T127 AC9)

**Decision: T24 stays a SEPARATE ticket; it was NOT folded into [[T127]].** T127's start gate
raised the option explicitly (*"If the owner prefers, T127 folds into T24 as its build phase"*) and
this is the answer.

**Why separate:** they are different kinds of work on the same subject. **T127 is the machinery**
(manifest · lockfile · integrity hash · provenance gate · updater). **T24 is the curation** — which
skills we adopt, which we author, and the catalog that records it. Machinery can be finished and
verified without a single curation decision, and a curation decision is worthless without machinery
to land it without drift. Merging them would have produced one ticket that could never be closed.

**Build order: T127 first, T24 consumes it.** Every T24 outcome lands *through* the manager:
- `kepano/obsidian-skills` is imported with **`w0m skill add <owner/repo@skill>`** — fully-qualified
  provenance, because a **bare name is rejected** (three different owners publish
  `playwright-best-practices`; resolving by name could substitute another author's executable
  instructions).
- Every surveyed skill that is adopted lands in `.w0m/skills.json` + `.w0m/skills.lock.json` with an
  integrity hash, so the catalog is **generated from the manifest**, never hand-maintained.
- "Import vs master ourselves" maps onto the manager's existing provenance classes:
  `skills.sh` (adopted) · `w0m-native` (authored) · `local` (vendored).

⚠️ **What T24 must NOT do:** hand-copy a skill into `wom7skills/skills/`. That is the exact drift
that got the `openspec-*` family removed on 2026-07-21, and it is what T127 exists to prevent.

⚠️ **Reachability is a two-repo rule** ([[T149]] AC5): adding a skill to the canonical library does
**not** install it anywhere — the consumer's `.w0m/skills.json` entry does. A T24 import that skips
the manifest entry reaches nobody, silently.

⇒ **Read [[T127]]'s AC5 (stack/policy-matched install) before starting the survey** — it decides
which skills a project gets automatically, which changes what the survey is choosing between.
