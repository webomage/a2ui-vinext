# T603 — Declare w0m UI mobile-first with tablet portrait/landscape and well-wrapped desktop support (AgDR-0054), retire VIEW SIDE switcher, smooth real-time sidebar hat re-rendering, and master UI/UX design skills

## Summary

Owner UI/UX review (`2026-11-01`) identified four high-priority improvements across `@webomage/ui`, `apps/cp`, `apps/web`, and `w0m-skills`:
1. **Mobile-first multi-orientation responsive declaration (`AgDR-0054`)**: Declare `w0m` UI (`@webomage/ui`, `w0m-web/design-system`, `apps/web`, `apps/cp`, `apps/join`, `apps/job`) **mobile-first** (`0px–767px` portrait & landscape) while explicitly supporting **Tablet Portrait (`768×1024`)**, **Tablet Landscape (`1024×768`)**, and **Well-Wrapped Desktop (`1200px–1440px+`)**.
2. **Retire manual `VIEW SIDE` switcher (`SidebarHatSwitcher.svelte`)**: Selecting a project hat already determines whether the user is operating on the `client` side (`client` / `Client Stakeholder`) or `contractor` side (`pm`, `developer`, `architect`, `qa`, `devops`, `security`, etc.). The separate manual `VIEW SIDE` (`w0m PM` / `Client View`) toggle box is redundant and causes contradictory states (`Project: 1945 -> Client` while `VIEW SIDE = w0m PM`).
3. **Client hat first ordering & smooth real-time panel re-rendering without sidebar collapse**:
   - Sort project hats so the **Client hat** (`client` / `Client Stakeholder`) appears first when available, followed by other client-side hats and the user's other assigned hats on that project.
   - Selecting or resetting a hat must NOT collapse the hat switcher popover (`isOpen`) or the sidebar (`AppShell.svelte`), and must smoothly re-render the main panel (`#main`) and sidebar navigation (`SideNav`) in real time (`wom:project-hat-changed`) without a jarring full-page reload.
4. **Master UI/UX & design skills (`webomage-design`, `figma-designer`, `landing-page-design`, `w0m-ui-expert`, `steve-jobs`, `w0m-pixel-clone`)**: Fork `elayadesign/ai-design-skills` to `github.com/webomage/ai-design-skills`, vendor `webomage-design`, `figma-designer`, and `landing-page-design` into `w0m-skills`, wire them into `project/policies/stacks-policy.json` (`astro`, `svelte`, `tailwindcss`), and produce a comprehensive UI/UX & behavior audit report in `.agents/reports/CP-SIDEBAR-HAT-UX-AUDIT-2026-11-01.md` (mirrored to `w0m-web/docs/reports/`).

## Acceptance criteria

- [x] **AC1 — Mobile-First Multi-Orientation Responsive UI Standard (`AgDR-0054` + `@webomage/ui` + `design-system`)**: Record `docs/decisions/AgDR-0054-mobile-first-multi-orientation-responsive-ui.md` (indexed in `docs/DECISIONS.md` via `just decisions`), update `w0m-web/design-system/readme.md`, `w0m-web/design-system/SKILL.md`, and `w0m-web/packages/ui/src/lib/components/layout/AppShell.svelte` so base styles are mobile-first with explicit media/orientation support for Tablet Portrait (`768×1024`), Tablet Landscape (`1024×768`), and Well-Wrapped Desktop (`1200px–1440px+`), preserving `localStorage` sidebar state across viewports.
