# T457 — Inline service-role clients escape the admin-client ratchet

## Summary

Found verifying T439 C3 in the owner's session (2026-09-25). The admin-client ratchet (T327, sharpened by [[T450]])
counts importers of the shared singleton (`supabase` / `staffAdminClient`). It does **not** count a page that builds
its own service-role client from the key, nor the named `adminClient()` factory.

**Measured 2026-09-25:** 13 source files under `apps/` read `SUPABASE_SERVICE_ROLE_KEY` and call `createClient(` —
cp: `components/pages/BlueprintsPage.astro`, `api/admin/integrations/trigger.ts`, `api/auth/linkedin-callback.ts`,
`api/auth/switch-role.ts`, `api/sync/upwork-mcp.ts`, `api/sync/vault.ts`, `sso.ts`; web: `api/auth/linkedin-callback.ts`,
`api/auth/sso-cp.ts`, `api/auth/switch-role.ts`, `api/sync/vault.ts`; demo: `api/demo/enter.ts` (plus 2 scripts). Several
use the shape `if (isAdmin && serviceKey) client = createClient(...)`, a **silent fallback** to the user client when the
key is missing (AgDR-0025). The two money list pages had it and caused a live defect: list via service role, detail via
RLS, so every contract detail bounced for an admin in the member hat (fixed under T439, wom7web `6d228a8c`, by
`adminClient()`).

## Acceptance criteria

- [x] AC1 — The ratchet counts every service-role client construction: singleton imports, `adminClient()` calls and
  inline `createClient(<url>, <service key>)`, each as a named set with its own limit; red probes per shape.
- [x] AC2 — Every inline construction moves to `adminClient()` (throws without the key) or to the user client; no
  `serviceKey &&` fallback remains (red probe: an `&& serviceKey` branch is a finding).
- [x] AC3 — Baseline re-measured with a reason per file; limits only go down afterwards.

## Definition of Done

T457 is done when no app source builds a service-role client by hand, every service-role read is counted by the
ratchet with a recorded reason, and no page silently downgrades to the anon/user client when the key is missing.
