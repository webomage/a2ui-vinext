# T580 — Per-Engagement Cloudflare R2 Obsidian Vaults & Mobile App Gateway

## Goal

Enable per-engagement Obsidian vault storage and synchronization on Cloudflare R2 (`r2://wom-engagement-vaults/engagements/<engagement_public_id>/...`) with an authenticated WebDAV/R2 gateway (`/api/vault/r2/[engagement]/[...path]`) so the native Obsidian Mobile app (via `Remotely Save`) and CP web portal can connect, authenticate, and sync per engagement:
1. **Per-Engagement Vault Schema & Policy (`clients-policy.json` + Supabase migration)**:
   - Extend `knowledge_hub` in `project/policies/clients-policy.schema.json` and `project/policies/clients-policy.json` with `engagement_public_id`, `r2_bucket`, and `r2_prefix`, and declare `knowledge_hub` boundaries for `servicios777` (`eg-servicios777`) and `personaje0` (`eg-personaje0`) alongside `artemio` (`eg-artemio-quiero-comer`) and `1945` (`eg-1945`).
   - Add `engagement_id uuid REFERENCES public.engagements(id)`, `r2_bucket text`, and `r2_prefix text` to `public.project_vaults` (`20261028190000_t580_per_engagement_r2_vaults.sql`), backfill existing vaults and seed `servicios777` + `personaje0` engagement vaults, and scope RLS policies by active `public.hats` on `engagement_id` / `client_id`.
2. **Cloudflare R2 Bucket (`wom-engagement-vaults`) & Sync Tooling (`just vault-push-r2`)**:
   - Create and configure `r2://wom-engagement-vaults` (including mobile CORS for `app://obsidian.md`, `capacitor://localhost`, `http://localhost`, `https://cp.webomage.com`, `https://cp.w0m.xyz`).
   - Bind `VAULT_R2 -> wom-engagement-vaults` in `w0m-web/apps/cp/wrangler.jsonc` (`apps/cp/src/env.d.ts`).
   - Implement `scripts/vault_push_r2.py` (`just vault-push-r2 [--engagement <id>] [--dry-run] [--verify]`) to push client-safe engagement vaults (`artemio`, `1945`, `servicios777`, `personaje0`) + mobile-safe `.obsidian/{app,graph}.json` to `r2://wom-engagement-vaults/engagements/<engagement_public_id>/...` with SHA-256 round-trip verification.
3. **Authenticated Per-Engagement R2 WebDAV / Mobile Sync Gateway (`/api/vault/r2/[engagement]`)**:
   - Implement `/api/vault/r2/[engagement]/index.ts` and `/api/vault/r2/[engagement]/[...path].ts` in `apps/cp` supporting WebDAV (`OPTIONS`, `PROPFIND`, `GET`, `HEAD`, `PUT`, `MKCOL`, `DELETE`) and JSON manifest/sync (`GET`/`POST`) backed by `VAULT_R2` (with transparent fallback to `vault_notes` / bundled vault notes).
   - Enforce Bearer or HTTP Basic Auth (email + Supabase JWT access token for Obsidian Mobile `Remotely Save`) and verify the caller holds an active hat on the target engagement (`public.hats` / `public.engagements`) or `admin` before serving or writing any note, while blocking denied prefixes (`inbox/`, `.obsidian/plugins/`, `internal/`).
4. **Multi-Engagement Switcher & Mobile Connection UI (`KnowledgeHub.svelte` & `/admin/vaults`)**:
   - Update `orgVault` / `getProjectVaults` so organizations with multiple engagements (e.g. `maksim-kulikov` holding `eg-servicios777` and `eg-personaje0`) resolve all engagement vaults cleanly and can switch between them in `/o/[org]/projects/vault`.
   - Add a **"Connect Mobile App (CF R2)"** panel in `KnowledgeHub.svelte` and `VaultSyncPanel.svelte` (`/admin/vaults`) displaying the per-engagement WebDAV/R2 URL (`https://cp.webomage.com/api/vault/r2/<engagement_public_id>`), R2 prefix (`r2://wom-engagement-vaults/engagements/<engagement_public_id>/`), 1-click copy buttons, and a "Sync Engagement to R2" action.
