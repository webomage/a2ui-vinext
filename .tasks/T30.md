# T30 — Portal access control (identity barrier)

## Summary

Member CP = `@webomage.com`-login only; client/job/join = whitelisted addresses; admin =
domain+role; deny-by-default, audited. 🔴 Ships behind a flag and refuses to enable until
all members have `@webomage.com` logins (lockout trap) → depends on T28 mailboxes. Gate on
auth email, not `work_email`.

## Acceptance criteria

- [x] AC1 — Member CP restricted to `@webomage.com` login only
- [x] AC2 — client/job/join restricted to whitelisted addresses; admin = domain+role
- [x] AC3 — Deny-by-default, audited
- [x] AC4 — Ships behind a flag; refuses to enable until all members have `@webomage.com` logins
- [x] AC5 — Gate keyed on auth email, not `work_email`

## Definition of Done

This ticket is done when:
1. `public.access_allowlist` exists in Postgres with RLS restricting maintenance to admins and reads to authenticated allowlisted subjects.
2. The shared auth middleware enforces the per-portal identity barrier:
   - On Member CP (`cp`), requests require an authenticated email domain ending in `@webomage.com` (ignoring `profiles.work_email`) when the barrier flag is active.
   - On client, job, and join portals, access is denied unless the authenticated email is present in `public.access_allowlist` for that portal (or added via self-registration on join).
   - Admin access on any portal requires an `@webomage.com` authenticated email in addition to holding the `admin` role in `user_roles`.
3. The lockout prevention mechanism is in place: the hard domain gate ships behind a flag (defaulting to off/advisory mode) and refuses to hard-block active members unless all active team accounts have `@webomage.com` logins or an explicit break-glass admin exception is provided.
4. Every portal access decision produces structured audit logs `{ portal, email, allow, reason }`.
5. Vitest test suite covers: `@webomage.com` admission, non-org email rejection on Member CP, allowlist verification on client/join, work_email-only rejection, and the flag-disabled fallback.
6. `just typecheck` passes with zero errors, and all tracking surfaces (`TASKS.md`, `project/tickets/T30.md`) are synced.
