# T523 — Golden run browser errors and audit noise

## Summary

Found while reviewing the last deploy (`2026.09.30-1790816882`, audit exit 0, golden check passed). The deploy audit that
[[T507]] added classifies the transcript, and for this deploy it reports **288 browser errors** and **70 "other trouble"** lines. The
golden check still says `Golden check passed: desktop-home_hero`, so a page that fails to load images in the test browser does not fail
the deploy. Nothing is known to be broken in production from this; it is the signal that is unexplained and being ignored.

**Correction to my own earlier report:** I compared this deploy's "70" with an earlier "12" and called it a rise. That was wrong: the
earlier run was the failed deploy that stopped at the test gate, before the goldens ran, so the two numbers are not comparable. No earlier
deploy has an audit file (the audit was added the same day), so whether 288 is new is **not measured**.

## Measured (2026-10-01, by re-running the audit classifier on the real transcript)

Browser errors, 288 lines in 17 distinct shapes:

| Count | Shape |
|---|---|
| 90 + 90 | `Failed to load resource: the server responded with a status of 503 (Service Unavailable)`, logged twice (as an ERROR and as a console message) |
| 15 each, 5 images | `[Browser HTTP 4xx]` on `http://localhost:4321/cdn/news/<id>.png` |
| 13 | `[Browser HTTP 4xx]` on `/cdn/post-images/welcome-bg-DaVinci.png` |
| rest | smaller variants of the same |

"Other trouble", 70 lines in 30 shapes: about 35 are `[Browser WARNING]` WebGL GPU driver performance messages
(`GL Driver Message ... GL_CLOSE_PATH_NV`); several are Gauge summary lines such as `Specifications: 2 executed 2 passed 0 failed`, matched
only because the word "failed" appears in `0 failed`; a few are console format strings containing the word `Error`; one is the known advisory
`forks-check` failure. These come from the classifier's keyword regex
`\b(error|failed|failure|warn|warning|deprecat|...)\b` in `wom7web/project/scripts/deploy_logged.py`, which matches words, not meaning.

## What is not known

- Which service answers 503 for `/cdn/*` under the golden run's dev server, and why. A plausible but **unverified** cause is that the local
  stack's storage buckets hold none of the news and post images the home page requests. That would be a test-environment gap, not a
  production fault. The `/cdn/news` images belong to the news pipeline, whose status is an open question in [[T518]].
- Whether the same images load in production.
