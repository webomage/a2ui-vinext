# T658 — Tinybird ClickHouse Free-Tier Unification: canonicalize 8 datasources + 6 pipes in Forward SSOT, fix EU host & marketJobs drift, wire non-blocking worker telemetry, and gate schema sync

## Summary

Our connected hosted ClickHouse workspace (`gcp/northamerica-northeast2/w0m`, `https://api.northamerica-northeast2.gcp.tinybird.co`, 10 GB Free Tier storage + 1,000 req/day) sits at `364 B` (`1` row) because:
1. **Fragmented Forward SSOT (`w0m-web/lib/tinybird.ts`)**: `w0m-web/tinybird.config.mjs` points `@tinybirdco/sdk` strictly at `lib/tinybird.ts`, which only declared the original 3 datasources (`linkedin_analytics`, `market_jobs`, `worker_logs`) and 1 pipe (`top_linkedin_posts`). Five later datasources (`observability_logs`, `agent_evaluations`, `onboarding_funnel`, `upwork_telemetry`, `gamification_events`) and five SQL endpoint pipes were scattered across `w0m-api` and `w0m-cf` copies—and `observability_logs_query` (called by `TinybirdObservabilitySink.queryLogs()` in `packages/logger/src/tinybird.ts`) was never defined in any schema file.
2. **Hardcoded EU Host, Wrong Datasource Name & Missing Worker Bindings**: `w0m-api/src/index.ts` (`/health`) and `w0m-cf/src/index.ts` (`/health`) hardcoded `https://api.tinybird.co`; `w0m-api/src/workflows/job-aggregator.ts` posted to `https://api.tinybird.co/v0/events?name=marketJobs` (wrong region + camelCase datasource + unchecked HTTP status); and `w0m-api`/`w0m-cf` lacked `TINYBIRD_URL` in `wrangler.jsonc` `vars` and `TINYBIRD_TOKEN` in `sync-api-secrets` / `sync-cfworkers-secrets` / `sync-cp-secrets`.
3. **Unwired Edge Telemetry & Ungated Schema Provisioning**: `w0m-cf` logged request lifecycle and `/health` anomalies only to stdout instead of shipping redacted `observability_logs` / `worker_logs` via `executionCtx.waitUntil`, and `init_tinybird_schemas.py` (`just tinybird-init`) only knew 3 CSV datasources and 0 pipes and was absent from `deploy-all`.
