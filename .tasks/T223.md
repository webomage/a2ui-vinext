# T223 — The status dashboard stamped a date nothing could refresh

> Found 2026-08-15 while updating the published **w0m Delivery Status** artifact at the owner's
> request. Not a filed request — a defect noticed on the way to something else.

## Summary — the half that regenerates sat under a header that never could

`docs/STATUS-DASHBOARD.html` is rebuilt from `TASKS.md` by
`project/scripts/gen_status_dashboard.py`, wired into pre-commit as *"Refresh w0m status dashboard"*.
The generator only rewrites its marked `<!-- AUTOGEN:* -->` regions — `STATS`, `BOARD`, and
optionally `GATES` / `SCOPE`.

The masthead stamp read **`Snapshot 2026-07-16`** and was **outside every one of them**. So for a
month the page reported a fresh, correct delivery board under a header asserting it was a
month-old snapshot. **A page that dates itself wrongly is worse than one carrying no date**,
because a reader trusts the stamp over the content and discounts everything below it.

The same masthead carries a **hand-maintained** stat strip, and 3 of its 6 numbers were stale:

| Stat | Claimed | Actual 2026-08-15 |
|---|---|---|
| apps | `4+1` (web/cp/join/job + console) | **5** — `demo` was missing entirely |
| Supabase edge functions | `~55` | **59** |
| memory facts | `25` | **61** — more than doubled |
| DB tables · RLS | 98 | **not re-verified** (needs live DB) |
| RAG documents | 102 | **not re-verified** (needs live DB) |
| OAuth providers | 3 | **not re-verified** (needs live DB) |

## Acceptance criteria

- [x] **AC1 — The stamp is generated, not written.** Added an `AUTOGEN:STAMP` region; the generator
      injects `Snapshot <today> · <n> tracked · <n> done`.
- [x] **AC2 — A missing stamp marker FAILS.** Injected unconditionally like `STATS`/`BOARD`, not
      optionally like `GATES`/`SCOPE`. **Proven red:** deleting the marker exits `1` naming
      `AUTOGEN:STAMP`, verified on a copy with the original restored.
- [x] **AC3 — Correct the verifiable hand-written stats** (apps, edge functions, memory facts).
- [x] **AC4 — Do NOT let unverified stats borrow a fresh date.** The three needing a live database
      keep an explicit `(2026-07-16)` as-of label, and a note states which half of the page is
      hand-maintained. Re-stamping the page while silently carrying month-old numbers would have
      made it *more* misleading, not less.

- [x] **AC5 — Ticket links must resolve where the page is PUBLISHED, not only in the repo.**
      Owner report 2026-08-15: *"links to local .md tickets ... now it says not found."* `TASKS.md`
      links are repo-relative (`project/tickets/T196.md`), which resolves when the markdown is read
      in the repo or Obsidian and **404s on the published page, which has no repo underneath it**.
      The generator now rewrites relative hrefs to absolute GitHub blob URLs
      (`.../blob/beta/...`); absolute hrefs (the `#123` issue links) pass through untouched.
      **289 links, 0 relative remaining.**
      ⚠️ **Two href sites, not one.** The first fix covered `links()` only; a second builder at
      `gen_status_dashboard.py:202` (the scope table) still emitted relative paths, and the
      verification step is what caught it — the "all links absolute" claim was false when first
      written. Both go through `portable()` now.
      ⚠️ **The repo is PRIVATE.** An unauthenticated fetch of a blob URL returns **404**, which
      looks identical to a wrong path — confirmed via `gh api` that the paths are real
      (`T222.md`, 8091 bytes, on `beta`). So the links work for anyone signed in with repo access,
      and will read as broken to anyone the artifact is shared with who lacks it.

- [x] **AC6 — Ticket links must open the LOCAL `.md` where a local file makes sense.**
      Owner ask 2026-08-15: *"in both just generated or /tasks command generated reports I want to
      have local .md tasks files to be opened on local"* — and *"and html report artifact as well"*.
      Two renderers, two different fixes:
      · **`just tasks`** emitted `project/tickets/T2.md`, relative to the *script's* cwd. The recipe
        does `cd ../wom7web`, so that path never resolved from the estate root where the terminal
        actually sits — the link rendered, looked right, opened nothing. `Path.cwd()` cannot fix it
        (the `cd` already happened), so the justfile now passes just's `invocation_directory()` as
        `W0M_LINK_BASE` and the script resolves against it. **Verified from both cwds:** estate root
        → `wom7web/project/tickets/T2.md`, from `wom7web` → `project/tickets/T2.md`, each confirmed
        with a real file test.
      · **The HTML dashboard** carries both targets per anchor — `href` = GitHub blob URL,
        `data-local` = `../project/tickets/T###.md` — and a script picks by `location.protocol`,
        with a visible toggle. **289 anchors carry both; the 113 GitHub-issue links correctly carry
        neither** (no local twin). Paths are relative to `docs/`, so nothing machine-specific is
        baked in: **0 occurrences of an absolute home directory** in the generated file.
      🔴 **The hard limit, stated rather than papered over:** a published page **cannot** open a
      local file. `file:` navigation from an `https:` page is blocked by the browser — no flag,
      header or permission changes it. So in the artifact the local mode is inert by construction;
      the toggle exists so that is *visible* instead of a silent dead link.
      ⚠️ **Unverified:** the `file:` default could not be exercised — the in-app browser refuses
      `file://` URLs (static snapshot, no scriptable document). The swap mechanism and the `https:`
      default were verified on the real published page; the `file:` branch is the same code path
      with the opposite boolean.

- [x] **AC7 — The terminal table must not wrap.** Owner 2026-08-15: *"the table malformed."*
      Measured, not guessed: rows ran to a **median 262 / max 280 characters**, so every row wrapped
      and a wrapped row *is* a broken table on screen. Markdown link syntax puts the whole target in
      the visible line, and AC6's correctness fix made it worse — an absolute path is longer than a
      relative one, so **correctness and legibility were pulling in opposite directions**.
      Resolved with **OSC 8 hyperlinks** when stdout is a TTY: the terminal shows only the label
      (`T2`, `#3`) and carries the target invisibly, so the link gets *shorter* as it gets more
      correct. Non-TTY output (a pipe, a redirect, embedding into `STATE.md`, pasting into a ticket)
      keeps the markdown form, which is what those readers need.
      **Measured after: median 262 → 138, max 280 → 157**, escape sequences stripped so it is what
      the eye actually sees.
      ⚠️ `W0M_LINK_BASE` and the `invocation_directory()` plumbing from AC6 were **removed** — dead
      once the href became absolute. Kept the absolute path: it survives the output being copied
      somewhere else, which a relative one does not.
      ⚠️ **OSC 8 needs terminal support** (iTerm2, WezTerm, Ghostty, Kitty, VS Code have it;
      Apple Terminal does not). An unsupporting terminal shows the escape bytes rather than a link,
      so the guard also requires a real `TERM` — an unset or `dumb` TERM falls back to markdown.
