# T661 — Deploy side-by-side `~/Apps/orca-linux-w0m.AppImage` and harden parallel ticket allocation & `session-complete` wrap-up against collisions

## Summary

Two operational gaps surfaced while auditing the last 48 hours of multi-agent Orca sessions and deploying `orca-linux-w0m.AppImage` alongside `orca-linux-main.AppImage`:

1. **Missing side-by-side `~/Apps/orca-linux-w0m.AppImage` target & `.desktop` launchers**: After upstream `stablyai/orca` (`v1.4.251`) moved to `~/Apps/orca-linux-main.AppImage`, `scripts/orca_overlay_update.py` (`just orca-apply`) still targeted the removed `~/Apps/orca-linux.AppImage` path and `~/.local/share/applications/orca.desktop` pointed to a missing binary.
2. **Parallel ticket ID collisions, concurrent `vitest` starvation, and GitHub `#N` overwrites during `session-complete`**:
   - `scripts/ticket_new.py` only inspected its own `repo_dir/.tasks/` via `O_EXCL`, ignoring sibling linked `git worktree` checkouts (`~/.w0m/work/*/w0m`), so concurrent sessions cut from the same `origin/beta` tip allocated duplicate `T##` IDs.
   - `scripts/session_complete.py` only waited on `.land.lock` (held for the final push), leaving ~90% of `run_session_complete()` unlocked: sibling sessions ran `sync_tickets_to_github()` and `deploy_cert.py` (`vitest` fork pools) simultaneously on a 5 GiB RAM host (`load > 23`), overwrote the same GitHub Issue `#N`, failed to clear inherited `gh_issue:` frontmatter on renumber, failed `--dry-run` on colliding tickets, could not compact early-finisher gaps (`T661 -> T659` when `T659` is still coding in another tree), and held idle SSH `git-receive-pack` sockets open across ~10-minute `w0m-web` `.husky/pre-push` runs.

## Acceptance criteria

- [x] AC1 — **Target `~/Apps/orca-linux-w0m.AppImage` by default (`scripts/orca_overlay_update.py`, `project/policies/tools-policy.json`)**: Change `_default_appimage_path()` in `scripts/orca_overlay_update.py` to `~/Apps/orca-linux-w0m.AppImage`, surface both `orca-linux-w0m.AppImage` and `orca-linux-main.AppImage` in `just orca-status`, sync `~/.local/bin/orca-overlay-update`, and update `project/policies/tools-policy.json`.
- [x] AC2 — **Sync Linux `.desktop` launchers for both Orca builds (`scripts/orca_overlay_update.py`)**: Keep `~/.local/share/applications/orca.desktop` (`Orca (w0m)`) pointed at `~/Apps/orca-linux-w0m.AppImage` and emit `~/.local/share/applications/orca-main.desktop` (`Orca (Main)`) whenever `~/Apps/orca-linux-main.AppImage` exists, verified in `scripts/tests/test_orca_overlay_update.py` (`just orca-overlay-test`).
- [x] AC3 — **Deploy verified `~/Apps/orca-linux-w0m.AppImage` live on `HP`**: Run `just orca-apply` to SHA-512 verify and install `~/Apps/orca-linux-w0m.AppImage` (`webomage/orca@v1.4.251-w0m.2`, `0755`) alongside `~/Apps/orca-linux-main.AppImage` without interrupting the active `orca-linux-main.AppImage` GUI process.
- [x] AC4 — **Cross-worktree atomic ticket allocation (`scripts/ticket_new.py`)**: Serialize `allocate_ticket()` across linked git worktrees via `fcntl.flock` on `<git-common-dir>/w0m-ticket-seq.lock` and scan `git worktree list --porcelain` (`.tasks/T*.md`) so parallel `agent-tree` sessions allocate distinct sequential `T##` IDs up front while keeping standalone test repositories hermetic.
- [x] AC5 — **Serialized `session-complete` wrap-up, bidirectional contiguous ID compaction, `gh_issue:` scrub, local `w0m-web` pre-push pre-certification & `LESSONS.md` rule (`scripts/session_complete.py`, `scripts/tests/test_session_complete.py`, `LESSONS.md`)**: Hold an exclusive `fcntl.flock` mutex (`<git-common-dir>/w0m-session-complete.lock`) across live `run_session_complete()`, compact branch-added tickets onto `[max(origin/beta)+1, ...]` (handling both collisions and early-finisher gaps via two-phase renames), strip inherited `gh_issue:` frontmatter on renumbered tickets, fix `--dry-run` renumbering, pre-certify `w0m-web` `.husky/pre-push` locally before opening SSH, record the earned rule in `LESSONS.md`, and verify with hermetic unit & red-probe tests (`just session-complete-test`, `just t531-layers-test`).
