# T442 — Connector framework: one OAuth connect flow, MCP-first transport, encrypted tokens

## Summary

Owner, 2026-09-24: *"we should start implementing real oauth connections and integration with services also as
planned"* and *"Upwork and other services should be with prio connected via — 1. mcp, 2. api/app"*.

"As planned" is the connector architecture: [[T94]]/[[T95]]/[[T134]] (done) built the registry, and
`wom7web/docs/backend/CONNECTOR-RESEARCH-MATRIX.md` set a depth ladder (0 link → 1 verified link → 2 read sync →
3 read+write). What was never built is the shared machinery every level-1–3 connector needs. Each provider has
its own half-flow today:
- **Upwork:** a member callback exists, but nothing starts it (0 member connections live, [[T441]]).
- **LinkedIn:** 1 member connection, on its own routes.
- **GitHub:** only a Supabase *login* identity ([[T53]]), which stores no token usable for sync.
- **Tokens at rest:** encryption is paused in [[T99]].

**Transport rule (owner, 2026-09-24).** Consistent with the recorded deployed-code ladder "MCP if it can
authenticate without a human → SDK → API" (wom7web `CLAUDE.md`, 2026-08-28):
1. **MCP**, when the provider's MCP server can keep a session going without a human, i.e. its OAuth
   server issues a refresh token our backend can use.
2. **API / App** (GitHub App, OAuth app, API key) otherwise, and for scheduled sync wherever the MCP session
   cannot be kept going.

The choice is recorded per provider in the registry from a **measurement**, never assumed. [[T218]] found
Upwork's MCP OAuth 2.1 "per interactive session" and concluded it cannot serve a cron. That was recorded but never
tested against the refresh-token path (AC1).

## Acceptance criteria

- [x] AC1 — **Upwork MCP headless spike.** Complete OAuth 2.1 (DCR + PKCE) against `https://mcp.upwork.com/mcp`
  once interactively, then prove or disprove that a server-side MCP client can refresh and call a tool with no
  human present (after the access token expires). Result recorded in the registry (`wom7web/project/services-policy.json`) and `docs/DECISIONS.md` (`docs/decisions/AgDR-0034-connector-framework-and-transport-ssot.md`, measured by `wom7web/project/scripts/upwork_mcp_spike.py` under [[T537]]). It
  decides T441's sync transport: local interactive MCP (`headless: false`), as Upwork DCR rejects non-localhost `https://` redirect URIs (`HTTP 400 invalid_redirect_uri`) and the legacy GraphQL API is deprecated.
- [x] AC2 — **One connect flow.**
  - `start` (`wom7web/apps/cp/src/pages/api/connections/[provider]/start.ts` + `wom7web/packages/lib/src/connectors/flow.ts`) writes an `oauth_states` row bound to the session's profile/org/estate owner with RFC 7636 S256 PKCE (`wom7web/packages/lib/src/connectors/pkce.ts`).
  - `callback` (`wom7web/apps/cp/src/pages/api/connections/[provider]/callback.ts` and `wom7api/supabase/functions/upwork-callback/index.ts`) validates state (`consumed_at`, expiry, owner binding) and uses one exact redirect URI (no variant ladder, AgDR-0025).
  - Tokens are exchanged and stored; `auth.identities` is never touched.
  - Refresh (`POST /api/connections/[id]`) runs and updates tokens; a refresh failure marks the connection `expired`, never silently `connected`.
  - Disconnect (`DELETE /api/connections/[id]`) revokes at the provider where supported, then deletes.
- [x] AC3 — **Tokens encrypted at rest** (aligns with [[T99]] via Owner Decision D1/D4 in `AgDR-0034`). Access/refresh tokens are encrypted using application-level AES-256-GCM (`wom7api/supabase/functions/_shared/crypto.ts` and `wom7web/packages/lib/src/connectors/crypto.ts`, keyed by Infisical `CONNECTOR_TOKEN_KEY_VERSION` + `CONNECTOR_TOKEN_KEY_V<n>`), decrypted only server-side, and never selected into the browser (`20261020160000_t442_connector_framework.sql` column-level `GRANT SELECT` + in-transaction `has_column_privilege` verification for `connections` and `oauth_states.code_verifier`).
- [x] AC4 — **Transport adapters.** Each provider is an adapter (`wom7web/packages/lib/src/connectors/adapters.ts` + `wom7web/project/services-policy.json`) declaring its auth kind, its transport (`mcp` | `api`) with the measurement behind it (`ProviderEvidence`), `scope_catalog`, and its sync capabilities by depth level (`capabilities`). An adapter that cannot authenticate or has not synced reports `never_synced` / `unmeasurable`, never `connected`.
- [x] AC5 — **Measured status everywhere.** Every `connections` row carries `last_attempt_at`, `last_success_at`, `last_error`, and derived `status` (`connected` / `expired` / `error` / `never_synced`, computed by `deriveConnectionStatus` in `wom7web/packages/lib/src/connectors/status.ts`). Hardcoded `mcpStatus = "connected"` was already deleted with `ConnectedServices.svelte` in [[T210]].
- [x] AC6 — **First adapters.** GitHub App (`github`, `GITHUB_APP_CLIENT_ID` / `GITHUB_APP_CLIENT_SECRET`) and LinkedIn (`linkedin`, `LINKEDIN_APP_ID` / `LINKEDIN_APP_SECRET`) live on the unified `/api/connections/[provider]/*` framework (with `wom7api/supabase/functions/linkedin-oauth/index.ts` updated for AES-256-GCM dual-write and scope/capability persistence); Upwork (`upwork`) is registered on the framework as capability-gated (`headless: false`, awaiting [[T537]] ToS sign-off) and `wom7api/supabase/functions/upwork-callback/index.ts` enforces single-URI exchange (`AgDR-0025`).
- [x] AC7 — **UI in the [[T439]] shell:** Me → Profile → Connected accounts (`wom7web/apps/cp/src/components/profile/ConnectedIdentities.svelte`); Org → Settings → Integrations (`wom7web/apps/cp/src/pages/o/[org]/settings/integrations.astro` + `wom7web/apps/cp/src/components/org/OrgIntegrationsManager.svelte`); Admin console → Connections (`wom7web/apps/cp/src/components/admin/ConnectionsManager.svelte`).
- [x] AC8 — Tests: `wom7web/packages/lib/src/connectors/__tests__/connector-framework.spec.ts` (PKCE S256 round-trip, AES-256-GCM round-trip + tamper rejection, state expiry/replay/foreign-owner/redirect-URI mismatch refusal, `auth.identities` invariant, refresh-failure → `expired`, capability derivation) + `wom7web/packages/lib/src/system-registry/providers.spec.ts` + `wom7web/packages/lib/src/system-registry/sources.spec.ts` + `wom7web/apps/cp/src/lib/__tests__/cp-routes.test.ts` + migration column-privilege verification in `wom7api/supabase/migrations/20261020160000_t442_connector_framework.sql`.
