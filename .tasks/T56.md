# T56 — Close the supabase-js version spread and give dependency currency an owner

## Summary

[[T112]] built cross-repo dependency **enforcement** (floors, lockstep, a pre-push gate) and left two
items open that were never picked up: the lagging `@supabase/supabase-js` in `wom7ext`, and whether
to adopt Renovate for **discovery**. Restoring `T112.md` on 2026-08-21 recorded both as unowned. This
ticket owns them — and measuring them first turned up something neither was about.

🔴 **The gate's scope is narrower than the sentence it prints.** `just deps-check` reports
*"deps aligned across 4 repos … 1 advisory warning"*. It compares **repo-root `package.json` files
only**. Measured 2026-08-21 — declared versions at 10 sites, 5 distinct specifiers:

| site | declared | resolved (lockfile) |
|---|---|---|
| `wom7web` root · `wom7api` · `wom7cfworkers` | `^2.110.7` | **2.110.7** |
| `wom7web/packages/lib` | `^2.90.1` | **2.105.1** |
| `wom7web/apps/web` · `cp` · `job` · `demo` | `^2.89.0` | **2.105.1** |
| `wom7web/apps/join` | `^2.99.2` | **2.105.1** |
| `wom7ext/extension` | `^2.87.1` | **2.98.0** |

So **three different versions of the Supabase client are actually installed** across the estate
(2.110.7, 2.105.1, 2.98.0) against a registry latest of **2.112.3** — and **two of them live inside
`wom7web`, under one lockfile**, where the gate reports alignment. Six of ten declarations sit below
the policy target and the policy's `lagging` map records exactly **one**.

⚠️ **The recorded exception is itself stale.** `deps-policy.json → aligned_advisory` says
*"wom7ext: ^2.87.1 — 23 minors behind"*. The **declared** floor is indeed `^2.87.1`, but the
**installed** version is `2.98.0`, and against today's latest the declared floor is **25** minors
behind, not 23. The advisory has been carrying a hand-written number that drifts on its own.

🔑 **Why this is the same defect this estate keeps shipping, not just old dependencies:** the gate is
not wrong about what it measured — the four roots *are* aligned. It is wrong about what it appears to
certify. A reader sees *"deps aligned"* and concludes the estate is on one version. Nothing lied;
the scope was simply never stated.

## Acceptance criteria

- [ ] **AC1** — `deps_sync.py` reads **every** `package.json` in each repo's pnpm workspace, not just
      the root. Its output must name the unit it checked (*"N package.json across M repos"*), so the
      claim can never again be broader than the measurement.
- [ ] **AC2** — the estate converges on **one** installed `@supabase/supabase-js`, or every remaining
      exception is recorded **per site** with a reason and a re-check date. 🔴 `wom7ext` is the one
      real blocker and the reason is unchanged since 2026-07-21: **the bump needs an extension test
      that does not exist.** Either write the smoke that unblocks it or record explicitly that
      `wom7ext` is pinned pending [[T55]]-style coverage — but stop carrying it as a one-line note
      that silently goes stale.
- [ ] **AC3** — the policy's `lagging` entries stop hand-carrying a minor-count. Derive
      *"N minors behind"* at check time from the registry, or drop the number and state the
      versions. A hard-coded distance is wrong the day after it is written.
- [ ] **AC4** — the policy can express **intra-repo** exceptions. Today `lagging` is keyed by *repo*
      (`wom7ext`), so there is no way to declare `wom7web/apps/join` as a known exception even after
      AC1 makes it visible. Widen the key to a workspace path.
- [ ] **AC5** — a gate asserts the estate holds **at most one resolved version** of the packages
      under lockstep, read from the **lockfiles** rather than the declared ranges. 🔴 The current
      check reads specifiers; `^2.89.0` and `^2.99.2` both resolved to `2.105.1`, so *declared* drift
      and *installed* drift are different questions and this ticket exists because only the first was
      ever asked. Register it in `project/test-suites.json` ([[T240]]).
- [ ] **AC6** — the gate is demonstrated **failing first** against the current tree: with today's
      three installed versions it must go red before any bump lands. A gate first seen green proves
      nothing.
- [ ] **AC7** — the Renovate question from [[T112]] is **decided and recorded**, either way.
      `docs/DEPS-ALIGNMENT.md` already establishes that neither Dependabot nor Renovate enforces
      cross-repo floors or lockstep — that is why T112 built enforcement locally. What is still
      undecided is **discovery**: being told a new version exists. Note that `just tools-outdated`
      already solves this for *host CLI tools* and nothing equivalent exists for packages, which is
      the actual gap. Record the decision in `docs/DEPS-ALIGNMENT.md`; *"declined, because X"* closes
      this AC as validly as adoption.
