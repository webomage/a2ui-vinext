# T542 — The preflight does not check what db-migrate needs

## Summary

2026-10-03, third deploy attempt of the day (log `deploy-logs/run-2026.10.03-1791070263.log`): preflight passed, the blocking test tier ran for about 19 minutes and passed, then `db-migrate` failed with `psql: could not translate host name "db.<ref>.supabase.co" to address`. Nothing was pushed (the step fails closed), but the owner lost 19 minutes and a Touch ID consent window.

Cause, measured the same day (see `LESSONS.md`, "The database host is IPv6-only"): the database host has an AAAA record and no A record. The machine's resolver stopped answering IPv6-only names (`getaddrinfo` fails for it and for any other AAAA-only name; `dig` still answers; a TCP connect to the IPv6 address still works; `scutil --nwi` shows `en0` with `IPv4,DNS` and no IPv6 state; WARP still says Connected). It recurred about 2.7 hours after a WARP reconnect had fixed it.

Why the preflight missed it: `check-warp` (`wom7api/justfile`) tests `curl -6 https://cloudflare.com`, which is a dual-stack name and a connection test, not a name-resolution test of the database host, and when it fails it prints "no IPv6 — advisory only, the deploy path is IPv4", which is false for the database. So the one check that mentions IPv6 cannot see this failure and tells the operator not to worry about it.
