# T764 — Segmented 6-box OTP input on auth surfaces

## Summary

The MFA one-time-code field is one wide `<input maxlength=6>` with placeholder
`123456` on both auth surfaces:

- inline challenge step in `packages/ui/src/lib/components/ui/AuthForm.astro`
  (`#mfa-code-input`, used by cp/me/web login pages), and
- the shared standalone challenge page
  `packages/ui/src/lib/components/mfa/MfaChallenge.svelte` (`#totp-input`,
  mounted by cp/web/join/job/demo `/mfa/challenge`).

Owner request (2026-11-17): replace the `123456` placeholder with `010-101`
and render the code as 6 separate one-character boxes (3+3 grouped by a dash)
that accept pasted codes in different formats (`123456`, `123-456`,
`123 456`).

Fix: add a canonical `InputOtp` primitive to `@webomage/ui`
(`Svelte 5` runes, DS tokens, mobile-first per AgDR-0054), then:

- `MfaChallenge.svelte` swaps its `Input` for `InputOtp` (binds `code`).
- `AuthForm.astro` mounts `InputOtp` (Svelte island) in the inline MFA form,
  syncing the code into a hidden `#mfa-code-input` so the existing submit
  handler and its 6-digit validation keep working unchanged.

Behavior: digit-only entry with auto-advance, backspace to previous box,
arrow-key navigation, paste redistribution stripping separators/spaces via a
shared `otpDigits()` util, `aria-label`/`role=group` a11y, dash separator
between boxes 3 and 4 with per-box placeholder digits `0 1 0 | 1 0 1`.
