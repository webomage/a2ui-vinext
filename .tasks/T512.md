# T512 — Skill propagation across every consumer

## Summary

Split from [[T508]]. Each repo that loads skills carries its own manifest and lock by design (T127, T149, T232). That is
fine for *selection*. The defect is *propagation*: the same declaration ("skill X at version V, hash H") is copied into up
to three manifests, with a single-target sync, a drift hook for wom7web only and no gate for the other two.

## Measured state (2026-09-30, read-only)

- `skills.ts --check ../wom7api` reports drift: `w0m-ticket-audit/SKILL.md` differs from canonical. The api copy is
  version `2026.09.19-1789854184` against canonical `2026.09.22-1790054019`, and it still points at the retired
  `project/tickets/` path (T418 moved tickets to `.tasks`).
- `w0m skill check` on the workspace root reports 2 blocking findings: `w0m-tasks` integrity drift (installed
  `sha256-fcb319cd...` against locked `sha256-0521d11d...`) and version drift. Cause: canonical commit `fd3a232`
  (2026-09-28) was synced to root and wom7web but relocked only in wom7web.
- Nothing automated runs either check. The only drift hook is `wom7web/.pre-commit-config.yaml:135`;
  the root and wom7api pre-commit configs have no skills hook; `toolset_status.py` runs `just skill check` from wom7web.
- `just skills-sync` has no multi-target form (`wom7api/justfile:3284-3285`, root `justfile:797-798`); both resolve to
  the default target `../wom7web`, so root and api need a manual `tsx skills.ts <dir>`. Commit `207b58c` is literally
  titled "hand-copy ... to the umbrella; relock".
- `just skill estate` and `gaps`, run from wom7web, resolve `repos` against the wrong root since T412 and report all 10
  repos "missing on disk" and "8 canonical skills installed nowhere" (false). The same command with `--project <@wom root>`
  works. See `w0m_skill.ts:1746-1760`.

## Acceptance criteria

- [ ] AC1 — **One recipe checks every consumer.** `skills.ts --check` runs for root, wom7web and wom7api in one
  recipe and exits non-zero on any drift. Today it is red for root and api; the ticket fixes those two copies first.
- [ ] AC2 — **One recipe syncs and relocks every declared consumer.** The consumer list comes from the registry, not a
  second hardcoded list. Verified by editing a canonical skill, running it, and seeing all manifests and locks agree.
- [ ] AC3 — **The gate actually runs.** The aggregate check is wired into `just test` and into pre-commit for the root and
  wom7api. Red probe: edit one canonical skill, skip the relock, and the aggregate fails.
- [ ] AC4 — **`estate` and `gaps` resolve the right root.** From wom7web they report zero "missing on disk" for repos
  that exist. Probe against the live workspace.
- [ ] AC5 — **The current drift is cleared.** The api `w0m-ticket-audit` copy and the root `w0m-tasks` lock are brought
  to canonical by the new recipe, not by hand.
