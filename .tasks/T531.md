# T531 — Several agents, one estate

## Summary

Owner, 2026-10-01: *"can we somehow make shared worktree comfortable for simultaneous mindful edits by different agents? ... what we can do for commits and pushes go success while worktree is dirty with changes already?"* Answer, after measuring one day of two agents in one tree: stop sharing it.

**Measured 2026-10-01 (two sessions, one tree):**
1. **One index.** A failed commit left my files staged and the next commit would have swept them in (T235's stage guard exists for exactly this); the same holds for another agent's staged files.
2. **Every commit stashes everyone's unstaged work** (`~/.cache/pre-commit/patch*`). It restored cleanly this time (the other session's 6 files hashed byte-identical before and after), but a hook that regenerates a file mid-commit makes the restore skip, and the memory note `precommit-stash-drops-unstaged-work` records two cases of lost files.
3. **Generated files read the whole tree.** `STATE.md`, `TASKS.md`, `docs/DECISIONS.md` and the epic vocabulary are rebuilt from everything on disk, so my commit needs the other agent's tickets to be consistent and carries or blocks on them. Two of my commits were blocked until I regenerated; the deploy preflight failed on a missing board row ([[T527]]).
4. **Push gates test the working tree, not the commit.** The 26-step pre-push has no step that runs against a snapshot of what is being pushed, so an unrelated half-written file can fail it, and an uncommitted file can make a bad commit pass.
5. **A plain git worktree of the root is not enough.** The root repo excludes its member repos, so a worktree of it holds no code. `orca worktree create` has the same limit (it manages worktrees of one repo). A usable set is one worktree per member repo, which is what the release tooling already builds (about 3 GB each).

## Acceptance criteria

Order is the owner's decision of 2026-10-01 (design: `.agents/reports/2026-10-01-t531-multi-agent-landing-design.md`). Each layer removes one measured incident class and does not depend on the later ones.

- [x] AC1 — **Commit by path (L1).** `just commit -m <msg> -- <paths>` (`scripts/commit_by_path.py`) refuses to run without named paths, resets the index to `HEAD` and stages only the named paths while snapshotting all non-target index entries and working-tree bytes, runs `git commit -m <msg>` on the real index so pre-commit formatters (`oxfmt`'s `git add` inside the hook) commit cleanly without leaving `MM` residue, and restores another agent's staged and unstaged files byte-identically (SHA-256 and `git status --porcelain` before and after are equal).
- [x] AC2 — **Atomic identifiers and one source per fact (L4).** `just ticket-new` (`scripts/ticket_new.py`) allocates the next id by exclusive create (`os.open(..., os.O_CREAT | os.O_EXCL | os.O_WRONLY)`) in a loop from `origin/beta` + `.tasks/` and renders the board row (`scripts/tasks_render.py`) in the same step, so a ticket cannot be rowless ([[T527]]). The hand-kept `SECTION_SLUGS` dictionary in `wom7web/project/scripts/sync_epic_vocabulary.py` is deleted and epic slugs are read directly from the `> **Epic slug:**` lines of `ROADMAP.md` (`sync_epic_vocabulary.py`, `epic_completeness.py`, `tasks_query.py`, `ticket_schema_check.py`). `scripts/lessons_query.py` supports keyed per-lesson files (`project/lessons/<key>.md` via `record_lesson()` + `parse_lessons()`) so two appends do not share an EOF anchor.
- [x] AC3 — **Derived files are produced at landing, not at every commit (L2).** `_refresh_derived_at_landing()` in `wom7web/project/scripts/agent_tree.py` regenerates derived root surfaces (`TASKS.md`, `docs/DECISIONS.md`, `STATE.md`) after rebase at landing time and commits them as `chore(derived): regenerate landing surfaces (T531)` even when two agents only committed `.tasks/T<N>.md` without editing `TASKS.md`. Red probe verified in `test_t531_layers.py`: two agents each add a ticket and land sequentially; `origin/beta:TASKS.md` holds both rows.
- [x] AC4 — **Gates evaluate a snapshot of the commit, not the working tree (L3).** `commit_snapshot()` and `verify_commit_snapshot()` in `wom7web/project/scripts/agent_tree.py` extract `git archive HEAD` to an isolated temporary directory with read-only cache symlinks (`node_modules`, `.venv`). Red probes verified in `test_t531_layers.py`: (1) committing a valid module and breaking an unstaged line in the working tree passes the snapshot gate; (2) committing a module that imports an untracked helper sitting on disk fails the snapshot gate.
- [x] AC5 — **Landing lock.** `just land` / `just agent-tree-land` (`wom7web/project/scripts/agent_tree.py`) acquires `~/.w0m/work/.land.lock` (`O_CREAT | os.O_EXCL` with `{pid, set_name, started_at, epoch}`, dead-PID and 30-min stale-TTL eviction, ordered waiting queue), fetches `origin/beta`, rebases, regenerates derived files (`_refresh_derived_at_landing`), runs the commit snapshot gate (`verify_commit_snapshot`), and fast-forward pushes without `--force`.
- [x] AC6 — **Workspace sets, only if a need remains after AC1 to AC5.** `just agent-tree <name>` (`wom7web/project/scripts/agent_tree.py`) provisions a complete private estate worktree set on `agent/<name>` reusing `release.py` (AgDR-0032), enforces the 3-set cap (`MAX_SETS = 3`), and provides `prune_merged_sets()` (`just agent-tree-prune`) which automatically removes clean merged sets (`ahead == 0` and `not dirty` across all repos) to free slots while never pruning sets with unpushed commits or dirty files. Measured: `just ask` queries the root `.codegraph/` and `graphify-out/` across the estate without requiring a duplicate per-tree index.
