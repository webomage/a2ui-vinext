# T212 — Portable w0m Core CLI Toolchain & just Recipe Distribution via wom7skills Claude Plugin

## Summary

Owner ask, 2026-08-14: *"reviewing how we can install just commands and tools and also make it portable with wom7skills Claude plugin file (specifically `/tasks`, `sync_github.py`, and core task lifecycle tooling across client repos)"*.

Currently, while `wom7skills` packages agent prompt skills, core CLI utilities such as `tasks_query.py` (`just tasks`), `sync_github.py` (`just sync-tickets`), and ticket lifecycle helpers remain tightly coupled to `wom7web/project/scripts/` with monorepo-specific paths and assumptions. Client repositories (such as `artemioquierocomer.mx`, `1945`, `evercred`) adopt these tools through ad-hoc manual file copying.

This ticket designs and implements the portable distribution mechanism for w0m CLI tools and `just` command recipes, bridging them directly into the `wom7skills` Claude Plugin architecture.

---

## 📍 Problem Statement & Gaps

1. **Decoupling Tools from Monorepo Paths**:
   `tasks_query.py` and `sync_github.py` in `wom7web` assume fixed relative directory depths (`parents[2]`), Infisical wrappers, and hardcoded repository names (`casualuser/webomage.com`).
2. **Missing Portable Recipe Export / Installer**:
   `justfile` in `wom7web` has 206 recipes. A client project needs a clean, standalone bundle of core w0m recipes:
   - `just tasks` (queue ranking & score breakdown)
   - `just sync-tickets` (GitHub Issues bidirectional mirror)
   - `just skill-check` (two-layer lockfile validation)
   - `just state-bounds` (STATE.md boundary enforcement)
3. **Claude Plugin Command Integration**:
   Under the Claude Plugin specification (`.claude-plugin/plugin.json`), custom slash commands (`/tasks`, `/sync-tickets`, `/w0m:status`) and MCP tools should be declared such that an agent in any client workspace can execute them seamlessly without requiring bespoke local shell configurations.

---

## 🎯 Requirements & Acceptance Criteria (ACs)

- [ ] **AC1 (Portable CLI Module & Config Discovery)**:
  Extract `tasks_query` and `sync_github` into portable Python/Node modules (or CLI binary `w0m-cli`) that automatically discover repo root, `.w0m/sdlc.json`, and git remote origin dynamically rather than using hardcoded paths.
- [ ] **AC2 (Canonical Client Recipe Module)**:
  Publish a standardized `w0m.just` (or modular include `!include .w0m/justfile`) containing the clean standalone task and lifecycle recipes (`tasks`, `sync-tickets`, `skill-check`, `state-bounds`) that client repos can include in 1 line.
- [ ] **AC3 (wom7skills Claude Plugin Tool & Command Declarations)**:
  Declare `/tasks` and ticket sync tools in `wom7skills` plugin manifest (`.claude-plugin/plugin.json` / MCP server tool definitions) so Claude Desktop, Claude Code, AGY, and OpenCode can invoke task queries and syncs natively.
- [ ] **AC4 (Single-Command Client Installer / Sync)**:
  Provide a single setup command (e.g. `w0m init --tools` or `pnpm dlx wom7skills init`) that writes `.w0m/`, installs the portable script runners, and wires the `justfile` recipes into any client repository in seconds.
- [ ] **AC5 (Validation across Client Repositories)**:
  Prove the portable toolchain and recipes work cleanly on external client repos (validated against `artemioquierocomer.mx` and clean fixture projects) with zero monorepo path assumptions.
