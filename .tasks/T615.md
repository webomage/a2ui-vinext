# T615 — Extend PRs & forks monitor with post-rebase obsolete PR management, cgroup-safe completed-session auto-close, and collapsed launch reports UI

## Summary

Extend and harden the scheduled `w0m Upstream PRs & Fork Branches Monitor` pipeline (`scripts/w0m_prs.py`, `scripts/orca_sessions.py`, `w0m-web/project/scripts/agent_tree.py`, and Control Panel `/admin/forks`) across four end-to-end capabilities:

1. **Upstream Update Alignment & Post-Rebase Obsolete PR Management (`AC1`)**: Fetch and align clean `w0m-pr/*` base branches (`beta`/`main`) with `upstream`, evaluate every open PR head branch and candidate fork branch via `git cherry`, `git rev-list`, and 100% read-only index 3-way merge (`git read-tree --aggressive -i -m` + `git merge-file -p` + `git diff-index --quiet --cached`), classify `UP_TO_DATE`, `CLEAN_REBASEABLE`, `CONFLICTING_NEEDS_REBASE`, `OBSOLETE_PATCH_EQUIVALENT`, `OBSOLETE_EMPTY_AFTER_REBASE`, `OBSOLETE_UPSTREAM_MERGED`, and `OBSOLETE_SUPERSEDED`, prune obsolete entries from local discovery and Orca workspace references, emit `OBSOLETE_PR` deltas, and generate human-confirmed `gh pr close` proposals (`T435`).
2. **Safe Completed Agent Session Auto-Close After Alignment (`AC2`)**: Replace `archive_host_sessions`'s indiscriminate `w0m` terminal close with `close_completed_sessions` (`orca_sessions.py close-completed` / `just orca-close-completed`) so post-sweep cleanup closes **only** finished Orca automation run terminals (`status` in final states with saved `outputSnapshot`) and settled `done`/`idle` `w0m` sessions whose `agent/<name>` worktree is clean and `0 ahead` (pruning merged sets via `agent_tree.py prune`) while never disturbing active `working`/`permission` agents, client workspaces, or unlanded worktrees; also align `agent_tree.py` `MAX_SETS` with `.w0m/sdlc.json -> release.keep_worktrees` (`5`) and Linux-safe Orca CLI resolution.
3. **Collapsed-by-Default Launch Reports in PRs Updates Tasks & CP UI (`AC3`)**: Persist bounded `launch_history` in `~/.w0m/state/prs-watch-state.json`, emit launch reports wrapped in collapsed-by-default `<details>` disclosures for Orca `AutomationRun` and `orca orchestration task-update --result`, complete the missing `Upstream PRs` tab in `w0m-web/apps/cp/src/components/system/ForksManager.svelte`, and render a **PRs Updates Task — Launch Reports** panel in `/admin/forks` (`/api/admin/forks.ts` `launch_reports` + enriched `prs` actions) using `@webomage/ui` primitives and CSS tokens.
4. **Cgroup-Safe Detached Self-Closer, `--fresh-session` Isolation & PR-Only Precheck Filtering (`AC4`)**: Fix three live automation failure modes observed during Runs #42–#47: (a) add `close-run-when-settled --daemon` spawning via `systemd-run --user --collect` on Linux (falling back to `start_new_session=True`) so Antigravity/Claude tool-runner cgroup/PGID teardown cannot kill the closer before Orca captures `outputSnapshot` (~22s post-turn, `max_wait=60s`) and unwrap `last-status.json` v2 `entries` dicts; (b) switch `sync_prs_to_orca` to `--fresh-session` (preventing conversation hijack/looping) and resolve `precheck` script paths to the canonical host estate root (never ephemeral `~/.w0m/work*` paths); and (c) add `--ignore-worktrees` + `--close-settled` + `pending_deltas` handoff to `check-delta` so unrelated `~/.w0m/work/*` edits stop waking the PR monitor and precheck deltas survive into `reconcile`.
