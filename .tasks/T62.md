# T62 — Cohort Staffing Units Schema & UI

## Summary

Implement database schema tables for cohort unit templates and project team memberships, and build the role-switching interface inside the Member Control Panel to handle dynamic staffing hats.

## 🔴 RE-SCOPED 2026-08-11 ([[T203]] AC4) — two of these three are already owned elsewhere

Read against [[T200]] and [[T117]] as they stand today. **AC1 and AC2 are `resource_grants` and the
scoped hat under different names.** Building them here would produce a second, competing
implementation of the authorization core — and [[T200]] exists precisely because that work must land
as ONE migration series.

| was | verdict |
|---|---|
| **AC1** `unit_templates`, `project_teams`, `project_team_members` | 🔴 **= `resource_grants`** (user × office × scope). T200 AC4 / [[T117]] AC4. **Do not build a parallel table set.** |
| **AC2** active-hat resolution in CP middleware, `role@project` | 🔴 **= the scoped hat** ([[T117]], owner decision 2026-08-11) resolved by `is_capable(cap, scope_type, scope_id)`. ⚠️ **And `role@project` is a STRING-ENCODED SCOPE** — the exact trap the office-vocabulary research names: this estate has already been bitten twice by structure carried in a string ([[T198]] C1). Scope must be `scope_type` + `scope_id` columns. |
| **AC3** the hat switcher in the nav header | ✅ **SURVIVES — and it is the only part this ticket uniquely owns.** |

🔑 **What T62 becomes: the UI half of the hat model.** That is a real and unclaimed job —
[[T117]] AC6 names a CP management surface but the *switcher* itself (choose your active hat, see
which scope you are acting in) is not built anywhere. **Keep the ticket, shrink it to that.**
⚠️ **It cannot start before [[T200]] step 3/4**: a switcher needs something to switch between, and
`resource_grants` is what supplies the list.

## Acceptance criteria

- [ ] AC1 — ⛔ **WITHDRAWN — duplicates [[T200]] AC4 / [[T117]] AC4 (`resource_grants`).** Recorded
      rather than deleted so the duplication is visible if someone re-proposes it.
- [ ] AC2 — ⛔ **WITHDRAWN — duplicates the [[T117]] hat model.** 🔴 Its `role@project` encoding is
      additionally the string-as-structure anti-pattern; if any part of it is revived, the scope must
      be columns, not a parsed key.
- [ ] AC3 — **Build the hat switcher in the CP navigation header** — toggle between project-scoped
      hats, and make the ACTIVE hat unmissable. 🔑 **The second half matters as much as the first:**
      hats are EXCLUSIVE (owner, 2026-08-11), so a user wearing the wrong one sees an empty page that
      looks like a bug. The UI is what stops "the CP is broken" being the first support ticket.
- [ ] AC4 — **Reads its options from `resource_grants`, not from a second source of truth.** ⚠️ Blocked
      on [[T200]] step 4; starting before then means inventing the list it should be reading.

## Definition of Done


Per [`../../openspec/SPEC-AUTHORING-STANDARD.md`](../../openspec/SPEC-AUTHORING-STANDARD.md):
the CP navigation header carries a working hat switcher that reads its options from `resource_grants` and **nowhere else**. ⛔ AC1 and AC2 are WITHDRAWN as duplicates of [[T200]] AC4 / [[T117]] — so this ticket is now only the UI half, and closing it must not quietly re-introduce the schema half it gave away. 🔑 The clause that decides it: a second source of truth for what hats exist is the defect, not the switcher.
