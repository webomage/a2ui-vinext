# T441 — Upwork for every member: connect from Me, one sync engine, and CP UI

## Summary

Split from [[T439]] / [[T440]]. Owner, 2026-09-24: *"we have to rework upwork poller to be possible to activate for
members profiles and do UI for everything"*.

**Measured 2026-09-24:**
- **The OAuth callback already supports members.** `wom7api/supabase/functions/upwork-callback/index.ts` reads
  `oauth_states.profile_id` and upserts `connections(owner_kind='member', profile_id, provider='upwork')`.
- **Nothing starts that flow.** [[T318]] retired the popup OAuth, and live there are **0 member Upwork
  connections**, only 3 `estate` ones.
- **The cron poller only reads estate tokens.** `upwork-poller/index.ts:295` loops `upwork_auth_tokens`, never
  member `connections`, and `:287` falls back to a hardcoded `profiles.email = 'casualuser@gmail.com'` owner.
- **A second, separate sync path exists.** `apps/cp/src/pages/api/profile/upwork-sync.ts` is on-demand, pulls
  `vendorContracts` (50) and nothing else: no proposals, rooms or messages.
- **The CP reports statuses it never measured.** `ConnectedServices.svelte:20` hardcodes
  `mcpStatus = "connected"`.
- **A banned fallback ladder.** `upwork-callback` retries four redirect-URI variants (AgDR-0025).

## Acceptance criteria

- [ ] AC1 — **Connect from Me.** Me → Account & security → Connected accounts (the [[T439]] shell) has "Connect
  Upwork": it writes an `oauth_states` row bound to the session's profile and redirects to Upwork. The callback
  stores a member connection for that profile. Disconnect revokes and deletes it. One redirect URI, exact; no
  variant ladder.
- [ ] AC2 — **One sync engine.** The poller iterates estate tokens **and** member connections, and every row it
  writes is attributed to that connection's `profile_id`. The on-demand endpoint only enqueues a run for the
  caller's own connection; there is no second fetch path. The `casualuser@gmail.com` fallback is deleted: a
  connection with no owner is skipped with a logged error (moved here from [[T440]] AC2).
- [ ] AC3 — **Same coverage for members.** A member sync pulls what the estate sync pulls (contracts, proposals,
  rooms, messages), within the member's granted Upwork scopes; anything a scope forbids is reported as not
  granted, not as zero.
- [ ] AC4 — **Tokens protected at rest** before any member other than the owner connects: member access/refresh
  tokens are encrypted (Supabase Vault or equivalent) and never sent to the browser. Reconciles with the paused
  [[T99]] (connector credential hardening).
- [ ] AC5 — **Member UI** (Me): connection status measured from the last run (connected / expired / error / never
  synced), last and next sync, per-type counts, "Sync now", pause/resume, reconnect. Synced contracts appear in
  **Work history** ([[T440]] AC4).
- [ ] AC6 — **Org/Admin UI**: Org → Integrations → Sync health lists each member's connection and last result for
  that org; the Admin console shows all connections. `SyncHealthBoard` is reused, and `ConnectedServices`'
  hardcoded status is replaced by a measured one.
- [ ] AC7 — **Owner check of Upwork's API terms** for syncing members' data through the w0m app (scopes, app
  approval, data retention). Recorded in `docs/DECISIONS.md` before AC1 ships to non-owner members.
- [ ] AC8 — Tests: a member-connection sync writes rows only under that member's `profile_id`; an ownerless
  connection is skipped with an error; RLS shows a member only their own synced rows (checked with `SET LOCAL ROLE`
  inside a transaction).
