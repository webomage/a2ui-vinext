# T220 — Choose the agent transport stack per layer

> **Owner ask, 2026-08-15.** *"Look for current MCP and ACP protocol options we can use to talk
> between browser, w0m ext and our services and other APIs."*

## Summary — four layers, four protocols, and they are complements

The estate has been treating "MCP" as one decision. It is four, and conflating them is why the
`:8008` bridge could die without anyone being able to say what should replace it. Researched
against current sources 2026-08-15 (not recall — the field moved under us):

| Layer | Protocol | w0m today |
|---|---|---|
| **Page ↔ agent** (own sites) | **WebMCP** — `document.modelContext` | 🔴 [[T21]] specced on the **deprecated** `navigator.` name |
| **Extension ↔ agent** (third-party sites) | **MCP**, extension as server | transport was WebSocket → `:8008`, host repo deprecated |
| **Agent ↔ our services/APIs** | **MCP Streamable HTTP** | 🔴 **no `/api/mcp` exists anywhere** |
| **Host ↔ agent** | **ACP** (JSON-RPC 2.0 / stdio) | ZeroClaw's `acp` command; pairing unbuilt ([[T153]]) |

### What changed under us, and why the old judgement needs re-testing

- **The WebMCP API renamed twice**: `window.agent` → `navigator.modelContext` → **`document.modelContext`**
  (21-July draft; tools belong to a **page**, not the browser). Chrome **150 deprecates**
  `navigator.*`, keeping it only as an alias that logs a warning. Recorded on [[T21]].
- **Reach is one browser.** Chrome 146+ only, via origin trial; Firefox/Safari/Edge are in the W3C
  Web Machine Learning WG and have **not** shipped ⇒ progressive enhancement is the majority path,
  not a nicety.
- **MCP dropped HTTP+SSE**; **Streamable HTTP** is the transport, and 2026-07-28 added
  `Mcp-Method`/`Mcp-Name` headers so gateways can route without reading the body.
- **`@mcp-b` is now the WebMCP standard's tooling** (`@mcp-b/webmcp-polyfill`, `@mcp-b/webmcp-types`
  under `WebMCP-org`) — the same namespace `wom7mcp` was abandoned over, because *"mcp-b was not
  providing what we need and managing a fork was not reliable"* (owner, 2026-08-15). **That
  judgement predates this shift and must be re-tested, not inherited.**
- ⚠️ **"ACP" is two protocols.** Zed's **Agent Client Protocol** (editor/host ↔ agent, JSON-RPC over
  stdio) is the live one and what ZeroClaw speaks. IBM's **Agent Communication Protocol** merged
  into **A2A** and its repo is archived. Searching one returns the other; do not conflate them.

**This ticket supersedes [[T219]] AC2** — "resolve the `:8008` bridge host" was the wrong question.
`wom7mcp` was deliberately deprecated; the open question is not *where is the host* but *what
carries extension↔agent traffic now*, which is a layer choice, not a repo hunt.

## Acceptance criteria

- [ ] **AC1 — One written decision per layer**, in `docs/` (not a ticket comment), naming the
      protocol, the transport, and **what it is NOT for**. The four rows above are the starting
      point, not the answer — each needs a yes/no with a reason.
- [ ] **AC2 — Re-test the `@mcp-b` judgement against current packages.** Either "still unsuitable,
      because X" or "suitable now; the 2026-03 assessment predated WebMCP-org." **Do not carry the
      old verdict forward silently** — it was made about a different codebase.
- [ ] **AC3 — Decide extension↔agent transport** now that `:8008`'s host is retired: WebMCP shrinks
      this to **third-party sites only** (our own pages can expose tools directly), so state whether
      the extension still needs an MCP transport at all, and if so which.
- [ ] **AC4 — Decide whether we expose `/api/mcp`.** The estate has **zero** MCP server endpoints
      despite "MCP-first transport" being the stated posture — a gap [[T154]] measures but no ticket
      owns. Either commit to Streamable HTTP endpoints (naming auth + which apps) or record that we
      deliberately do not.
- [ ] **AC5 — Version-pin the volatile bits.** The WebMCP namespace moved three times in a year;
      whatever ships must isolate that in **one** place (`@webomage/webmcp`) with the documented
      feature-detect, so the next rename is a one-line change rather than a sweep.
- [ ] **AC6 — Prove each chosen path with one working call**, not a config entry. `just mcp-exposure`
      (T154) re-run afterwards so declared-vs-listening-vs-connected stays measured — the estate has
      already been bitten by "declared ≠ connected" ([[T154]], Obsidian 3-of-4 for 12 days).
