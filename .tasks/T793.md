# T793 — Segregate security audit workbench by archetype, banner sample fixtures, and add interactive message composer on empty client threads

## Why

1. The CP Security Audit page currently bundles Level 1 Web & Edge, Level 2 SAST, Level 3 Cloud Infra, AI Agents, Compliance, and Web3/Crypto smart-contract & tokenomics audits into a single flat feed under Overview, confusing users with mixed domains and synthetic sample fixtures (such as fake hardcoded Stripe keys and public S3 ACLs) without clear labeling.
2. The CP Messages page displays a dead-end "No client communication threads found for this organisation yet" empty box without auto-initializing the client thread for the active organization or providing an active composer to start a conversation across channels.

## Scope

- **In:**
  - **Security Audit Archetype Segregation:**
    - Isolate Web3 / smart-contract audits and tokenomics intelligence into a dedicated `crypto` ("Web3 & Contracts") workbench tab in `SecurityAuditReportViewer.svelte`.
    - Prevent Web3/Crypto panels from polluting the `overview`, `cloud_code`, and `compliance` views for regular web/cloud projects.
    - Keep `overview` focused strictly on real Web & Edge security posture (Passive Security Audit, Cloudflare WAF/TLS/DNS, Verified Domain Status).
    - Add explicit `[DEMO SAMPLE FIXTURE]` notice banners on synthetic Level 2 / Level 3 / Crypto sections explaining they are mock fixtures, with a CTA to scan live targets or connect a private repository.
  - **Client Message Threads Auto-Init & Empty State Composer:**
    - In `messages.astro`: Auto-ensure the organization thread exists via `wom_bind_lead_thread_to_client_org` when `orgId` is present.
    - In `ClientMessageThread.svelte`: Replace the dead-end empty box with an interactive "Start a Conversation" workspace showing connected channel badges and an active message composer input + "Send Message" button.
    - In `ClientMessageThread.svelte`: Auto-bind the thread and send the message seamlessly when sending from an empty initial state.
- **Out:**
  - Altering underlying Supabase RPC security posture or database migration schemas.

## Acceptance Criteria

- [x] **AC1:** Isolate Web3 & smart contracts in Security Audit: Add dedicated `crypto` ("Web3 & Contracts") workbench tab and remove smart contract / tokenomics cards from `overview`, `cloud_code`, and `compliance`.
- [x] **AC2:** Overview focus & sample fixture banners: Refine `overview` to show core Web & Edge posture without synthetic code/cloud card dumping, and banner synthetic Level 2/3/Crypto findings as demo fixtures.
- [x] **AC3:** Messages auto-init for client organizations: In `messages.astro`, ensure `orgId` automatically initializes a client thread if one does not exist yet.
- [x] **AC4:** Interactive composer on empty threads: In `ClientMessageThread.svelte`, replace the empty container message with an interactive message composer and channel capabilities preview allowing immediate communication.
- [x] **AC5:** Conformance & typecheck verification: Pass `astro check` across `apps/cp` and `just state-check`.

- Sample findings are prominently badged as demo fixtures.
- Client messages page allows immediate conversation initiation even on previously uncontacted orgs.
