# T197 — the warnings a successful deploy prints, and nobody triages

## Summary

The 2026-08-10 deploy (`2026.08.10-1786387039`) succeeded: all 6 surfaces live, all `/api/health`
green on commit `e59babcc`. It also printed **20+ build warnings**, and nothing in the pipeline
reads them. Triaged here, because "the deploy went green" is not the same as "the deploy was
clean" — and one of these is a live 404.

## 📍 Findings, measured against production

### 🔴 A. `/noise.png` — a live 404 on a rendered element

`apps/cp/src/components/admin/CharacterSheet.svelte:133` renders
`<div class="absolute inset-0 bg-[url('/noise.png')] …">`. The file exists in **no app's
`public/`**. `https://cp.webomage.com/noise.png` → **404**, confirmed post-deploy.

This one is *applied*, not merely declared, so every render of the admin CharacterSheet requests a
missing texture. Either ship the asset or drop the layer — it is currently doing neither.

### 🟠 B. Twelve `/assets/info{1-4}-web.webp` 404s — latent, and a trap

`join`, `job` and `demo` each return **404** for all four; `web` and `cp` return **200**. Root
cause is a **cross-app import**:

```
apps/join/src/layouts/Layout.astro:5   import "../../../web/src/styles/global.css";
apps/job/src/layouts/Layout.astro:5    import "../../../web/src/styles/global.css";
apps/demo/src/layouts/Layout.astro:6   import "../../../web/src/styles/global.css";
```

Three apps reach across into **`apps/web`'s** stylesheet, inheriting
`--bg-slide-1..4: url("/assets/infoN-web.webp")` — paths only `web` and `cp` can serve, because
only they have the files in `public/assets/`.

⚠️ **Not user-visible today, and the reason matters:** the consuming component
(`LegacyBackground.svelte`) exists only in `cp` and `web`. Verified against production — join's
served CSS *does* carry the `.site-bg-slide` rules, but its rendered HTML contains **zero**
elements with that class, so no browser ever requests the files. **It is dead CSS, not a broken
page.** ⇒ Do not "fix" this by copying 12 files into three `public/` dirs; the defect is the
import, not the assets.

🔑 **This is D6/T104c in CSS form.** That row records join's tsconfig "reaching into `../cp/src/**`
and repo-root files"; this is the same boundary violation in the stylesheet layer, and it is why
the apps drag each other's build graphs around.

### 🟠 C. Hume `ReadStream` — unverified risk on a reachable page

```
[vite] hume/…/expressionMeasurement/streaming/StreamSocket.mjs (46:35):
       "ReadStream" is not exported by "__vite-browser-external"
```

Hume's streaming client imports a Node built-in that vite stubs for the browser/worker target. The
importer is real and reachable: `apps/join/src/components/interviews/InterviewSession.svelte:10`
(`import { HumeClient } from "hume"`), rendered by `apps/join/src/pages/interview/[id].astro`.
⚠️ **Filed as a RISK, not a defect** — proving it needs the interview flow exercised with a live
Hume token, which was not done. If that code path runs, it throws at runtime.

### 🟡 D. Astro deprecation (cp)

`markdown.remarkPlugins`, `markdown.rehypePlugins` and `markdown.remarkRehype` are deprecated —
pass them to `unified({...})` from `@astrojs/markdown-remark` instead. Harmless now; it is removal
in a future major, and [[D3]]/[[T103]] already owe an Astro 6→7 upgrade.

### 🟡 E. Toolchain notices printed into the deploy

- `wrangler 4.112.0 (update available 4.120.1)` — **not** a `tools-policy.json` entry, and
  correctly so: it is a `package.json` devDependency (`^4.112.0`), governed by `deps-policy.json`.
  The caret already allows 4.120.1; the lockfile is just stale. Not a governance gap.
- `A new release of infisical is available: 0.43.114 -> 0.43.121`, printed **6 times**.
  ✅ Already resolved — infisical was upgraded to 0.43.121 at 13:45 while this deploy ran
  13:40–13:42, so it raced the fix. It will not recur.

## The actual gate this is missing

Every one of these was printed, in green, and read by nobody. `just deploy` has no notion of a
warning: a step either exits 0 or fails the deploy. So a live 404 shipped inside a successful run.

## Acceptance criteria

- [ ] **AC1 — ship or remove `/noise.png`.** It is referenced by a rendered element and exists
      nowhere. Decide which, do not leave it 404ing.
- [ ] **AC2 — kill the cross-app stylesheet import.** `join`/`job`/`demo` must not reach into
      `apps/web/src`. Move the shared layer into `packages/ui` (the existing home for shared UI)
      or give each app its own. ⚠️ **Do not fix by copying assets** — that ratifies the boundary
      violation and multiplies the files.
- [ ] **AC3 — decide the Hume question by exercising it**, not by reading the warning. If the
      streaming path runs in join's runtime, it is a defect; if it is never reached, record that
      and move on. An unexercised warning stays a risk, not a finding.
- [ ] **AC4 — a build-warning budget.** Capture warnings per app at deploy and ratchet: the count
      may fall, never rise ([[T149]]'s typecheck-ratchet is the shape to copy). ⚠️ It starts
      non-zero, so per [[T135]] AC8 it goes in advisory with a recorded promotion trigger.
- [ ] **AC5 — asset references are checked at build.** A `url()` or `bg-[url()]` naming a file no
      app serves should fail, not warn. Proven red on `/noise.png` — today's actual case.

## Definition of Done

- No 404 for any asset a rendered element references.
- No app imports another app's `src/`.
- Warning counts are recorded and cannot silently grow.
