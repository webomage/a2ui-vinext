# T532 — E2E local sandbox execution environment and full corpus verification run

## Summary

Split from [[T237]] (AC7 leftover: local sandbox execution environment).
`just e2e` historically ran against `infisical run --env=dev`, which resolved to the live production database (`db.pqbbjgeapylcengbuvee`). Because specs contain mutative and destructive steps (`Create interview template`, `Delete interview template`, `I delete the todo item`), executing tests against production risks data corruption and leakage.
This ticket isolates the execution environment so `just e2e-local` runs strictly against local loopback services (`127.0.0.1:4321`, `127.0.0.1:4325`, `127.0.0.1:54321`) with synthetic fixtures, failing closed if any variable points to hosted infrastructure.

## Acceptance criteria

- [x] AC1 — Enforce that `just e2e-local` and Playwright hooks (`tests/support/hooks.ts`) fail closed if any connection string or URL points to hosted/live production databases.
- [x] AC2 — Verify local seed data and test accounts (114 tables, fixtures) on local Supabase container without cross-contamination.
- [x] AC3 — Execute full corpus execution (`just e2e-local`) across all 194 specs against the local stack.
- [x] AC4 — Triage and document genuine application findings vs environmental runner gaps in a verified baseline report.
