# T387 — Restore remote CI/CD verification workflow and resolve GitHub Actions runner startup failures

## Summary

The estate currently operates with **zero active remote CI/CD enforcement**. GitHub Actions has accumulated **339 consecutive startup failures** across repository history, concentrating 100% of the verification, quality, security, and integrity gates onto local developer workstations (taking ~114s per push).

Local git hooks alone cannot safeguard the repository:
1. Any push executed from a fresh clone without initialized hooks, via web UI, or through external automation completely bypasses pre-push checks.
2. The long local pre-push run time creates heavy friction and tempts developers/agents toward `--no-verify`.
3. GitHub repository branch protection cannot require status checks to pass because no remote status checks ever complete successfully.

This ticket diagnoses and fixes the root cause of the 339 GitHub Actions startup failures, establishes an operational remote CI workflow mirroring critical local quality gates, and configures branch protection.

## Acceptance criteria

- [x] AC1 — **Root Cause Diagnosis & Runner Resolution**: Investigate the 339 consecutive GitHub Actions startup failures (e.g. runner allocation, GitHub Actions billing/plan status, secret access, or concurrency queues) and resolve runner execution.
- [x] AC2 — **Server-Side Verification Workflow**: Implement a streamlined GitHub Actions workflow (`.github/workflows/ci.yml`) executing key offline quality gates: `astro check`, `state-check`, `debt-check`, `emoji-check`, and `spec-drift`.
- [x] AC3 — **Prove Remote CI Green**: Trigger and verify at least 3 consecutive successful green CI workflow runs on commits/PRs to `beta`.
- [x] AC4 — **Branch Protection Integration**: Document or configure GitHub branch protection rules requiring the remote CI check to pass before merging into `beta`.
- [x] AC5 — **Tech Debt Update**: On archive, delete or update row D68 in `TECH-DEBT.md`.
