# T169 — Declare Headroom's MCP server + proxy daemon as governed surfaces, or retire them

## Summary

Headroom runs **two undeclared long-lived surfaces** on this machine — an MCP server and a
network proxy holding a subscription OAuth token — and neither appears in
`.w0m/sdlc.json → mcp.servers`. Found 2026-08-05 while investigating whether Headroom could be
integrated over MCP for [[T163]].

⚠️ **State the gap precisely — it is narrower than "Headroom is ungoverned", which is false.**
Headroom **is** governed as a **CLI tool**, and well: `project/tools-policy.json` carries
`min 0.33.0`, `known_good 0.33.0`, `required: false` (deliberately), a `smoke` command, and a long
note recording four traps. Installed version is **0.33.0** — at floor. `just tools-check` covers it.

**What is missing is the MCP/daemon half.** Measured live 2026-08-05:

| Surface | Process | Declared in `tools-policy.json` | Declared in `sdlc.json → mcp` |
|---|---|---|---|
| `headroom mcp serve` (stdio, 3 tools) | pid 92344 | ✅ as a CLI | 🔴 **no** |
| `headroom.cli proxy` → **listening `127.0.0.1:8787`** | pid 26424 | ✅ as a CLI | 🔴 **no** |
| `serena start-mcp-server` | pid 92522 | 🔴 not present | 🔴 no — owned by [[T166]] AC1 |

The MCP server is **live and answering**: `mcp__headroom__headroom_stats`,
`headroom_compress`, `headroom_retrieve` all responded this session.

🔴 **The consequence is a vacuous gate, which is this estate's signature defect.**
`just mcp-exposure` (T154) printed, verbatim:

> `⚠️ compared NOTHING — no declaration is listening-capable, so this reconcile proves nothing
> about exposure.` · `12 declaration(s) excluded as not listening-capable (stdio/remote)`

All 12 declared servers are stdio or remote, so the declared-vs-listening reconcile compares an
empty set and **exits green**. Meanwhile a real local-http listener (`127.0.0.1:8787`) is up and
undeclared. The one surface the gate was built to reconcile is the one it cannot see — a green run
that is a hypothesis, not a result ([[T154]] AC8 requires every entry to record `transport`, and
`local-http` additionally requires `bind` + `auth`).

**The keep/remove decision is genuinely open, unlike [[T166]]'s.** T166 exists under a standing
owner directive (*"we have to use serena in our sdlc"*), so serena's answer is "declare it".
Headroom has no such directive, and the measurements argue both ways:

- 🔴 **Compression has removed 0 tokens, ever — re-verified twice on 2026-08-05.** Lifetime proxy
  stats: `Tokens saved: 0`. And an MCP-path `headroom_compress` of a 628-token payload returned
  `transforms: ["router:noop"] · tokens_saved: 0`, output **byte-identical** to input. The
  `$1.73` in "savings" is Anthropic's prefix cache, which accrues with or without Headroom.
- 🔴 **The proxy cannot serve this app at all.** The Claude App process carries
  `ANTHROPIC_BASE_URL=https://api.anthropic.com` in its environment (read from `ps eww`), and
  Headroom's own `mcp --help` says automatic compression requires setting that variable. Confirmed
  by its own telemetry: stats report **`claude-sonnet-5`, 15 requests** while the session running
  them is **Opus 5** — the proxy only ever sees `claude -p` subprocesses.
- ✅ **The read-only analyzers are the real, working value** and need no proxy:
  `just headroom-audit` (transcript waste sizing, no API cost) and `just headroom-learn`. This is
  already the recorded position in `tools-policy.json` and `CLAUDE.md`.

⇒ So the honest framing is **"keep the CLI analyzers, decide about the daemon + MCP server"**, not
"keep or remove Headroom". A retire decision here would stop a proxy, not remove a capability.

**Security surface, stated plainly because it is the reason this is P2 and not P3:** the proxy is a
**listening socket** that a Pro-subscription OAuth token traverses, inside a third-party local
binary, running continuously. It binds **loopback only** (`127.0.0.1:8787`, verified — *not*
wildcard, so it is not LAN-reachable) and that is the mitigating fact. But an undeclared listening
daemon holding an auth token is exactly the class of thing `mcp-exposure` was built to surface, and
it is currently invisible to it.

## Acceptance criteria

- [x] AC1 — **Declared or retired — no third state.** Either `.w0m/sdlc.json → mcp.servers` gains a
      `headroom` entry, or the MCP server is removed from `~/.claude.json` and the proxy daemon
      stopped. Record the decision and its reason where the next agent will read it. **DONE 2026-08-05 — DECLARED, not retired.** Reasoning recorded in `TECH-DEBT.md` **D31**: the proxy is the only path for `just headroom-task` (CLI subprocess routing), so stopping it removes a capability while fixing nothing — whereas declaring it makes the OAuth-token-on-a-listening-socket **visible to the gate** instead of implicit. ⚠️ **Reversible**, and D31 names the conditions to revisit.
- [x] AC2 — **If declared, the entry satisfies [[T154]] AC8**: `transport` recorded, and — because
      the proxy is `local-http` — `bind` and `auth` recorded too. `just mcp-exposure` **fails** on
      an entry with no transport, so a malformed entry is caught rather than accepted. **DONE 2026-08-05.** `headroom` → `transport: stdio`. `headroom-proxy` → `transport: local-http`, **`bind: 127.0.0.1:8787`**, **`auth: none (loopback-only)`**, per the T154 AC8 contract.
- [x] AC3 — **The proxy daemon is declared as its own surface, distinct from the MCP server.** They
      are two processes with two transports (stdio vs local-http on 8787) and two risk profiles;
      one entry covering both would hide the listening socket, which is the half that matters. **DONE 2026-08-05 — two entries, deliberately.** Two processes, two transports, two risk profiles; a single entry would have hidden the listening socket, which is the half that matters. Only `headroom-proxy` is `local-http`, so it is the **only** declaration in the whole file the reconcile can actually compare.
- [x] AC4 — 🔴 **`just mcp-exposure` stops comparing an empty set.** After this change the
      declared-vs-listening reconcile must compare **at least one** real listening surface and say
      so. Proven by a red probe: mis-declare the bind or the port and assert the reconcile goes red.
      A green run over zero comparables is the defect, not the baseline. **DONE 2026-08-05 — and this AC earned its wording.** The reconcile went from `compared NOTHING` to **1 comparable declaration**. 🔴 That first real comparison immediately produced a **FALSE NEGATIVE**: *"declared, not listening"* for a proxy that was live on `127.0.0.1:8787` answering **HTTP 200** — because `reconcile()` was passed **confirmed-MCP surfaces only**, so a declared `local-http` entry that is not itself an MCP server could **never** match. Worse, that message reads as benign (its own docstring: *"usually just stopped, does not fail"*). Fixed by separating **presence** (all listening sockets) from **protocol** (MCP-confirmed) — with `undeclared` deliberately left MCP-only, since widening it would report every unrelated socket as a rogue server and that noise is what gets a gate ignored. **Red probes: 6 added**, covering the mis-declared bind, the opposite failure (the fix must not make every declaration look alive), and that a genuinely undeclared MCP surface still fails. **Proven non-vacuous:** the same fixture on the old code path reports the live socket as absent.
- [x] AC5 — **The keep/retire decision is recorded with the measurement next to it** — 0 tokens
      saved lifetime, `router:noop` on the MCP path, and the fact that the analyzers work without
      the proxy. Whichever way it goes, the *reason* survives so this is not re-derived a fourth
      time. **DONE 2026-08-05 — `TECH-DEBT.md` D31**, with the measurements next to the decision: 0 tokens compressed lifetime, `router:noop` on the MCP path, the app cannot route through the proxy (`ANTHROPIC_BASE_URL` pinned), and the analyzers work without it. D29 carries the unproven-benefit half, D30 why the metric cannot settle it.
- [x] AC6 — **If retired:** `tools-policy.json`'s `headroom` entry is updated rather than deleted —
      the CLI analyzers stay governed and `required: false` stays correct. If **kept**: a
      `TECH-DEBT.md` row records that a listening daemon holds a subscription OAuth token, so the
      acceptance is visible rather than implicit. **DONE 2026-08-05 — kept, so the TECH-DEBT branch applies.** **D31** records the accepted exposure explicitly (loopback daemon carrying a subscription OAuth token, `auth: none`) with the condition that makes it acceptable — **the bind staying loopback** — named as the thing to watch. `tools-policy.json`'s `headroom` entry is unchanged and still correctly `required: false`.

  the entire job of codegraph/graphify. `headroom memory import` ingests Headroom's own JSON export
  format, not source. Recorded so the idea is not re-attempted on the same wrong premise.
