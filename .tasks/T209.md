# T209 — package w0m skills and tools as a Claude plugin

## Summary

Owner ask, 2026-08-14: *"packaging w0m tools and skills into format of Claude plugin compatible
with Antigravity and Opencode."*

w0m has **80 installed skills** governed by [[T127]] and **206 `just` recipes**, and no way to hand
any of it to another machine, another agent runtime, or another person. The canonical tree
(`wom7skills/skills/`) is synced into each repo's `.agents/skills` by `just skills-sync` — a
copy mechanism that works *inside this estate* and nowhere else.

## 📍 Measured 2026-08-14 — packaging was started and abandoned

| fact | measured |
|---|---|
| `wom7skills/plugin.json` | **exists, 3 fields**: `name`, `version`, `description`. No skills, commands or agents declared |
| its location | 🔴 **wrong** — the Claude plugin spec reads `.claude-plugin/plugin.json`; this is at the repo root |
| `.claude-plugin/` | **absent** |
| `commands/` · `agents/` | **absent** — only `skills/` exists |
| who references it | **nobody**, except a vendored skill's own docs (`doubt-driven-development/references/orchestration-patterns.md:123`) which states the correct path: *"This repo is a plugin (`.claude-plugin/plugin.json`)"* |

⇒ **The repo describes itself as a plugin in its own documentation while not being one.** That is
the gap, and it is a smaller one than "build packaging from scratch".

## Boundaries — what this does NOT own

- **[[T127]]** owns skill governance — the manifest, the lockfile, provenance, `just skill check`.
  This ticket packages what T127 governs; it must not fork a second source of truth.
  ⚠️ **Edit canonical once** (`wom7skills/skills/`), then sync. A plugin build that copies skills
  into a third location would create exactly the fork T127 exists to prevent.
- **[[T192]]** owns connected-IDE *rule surfaces* (`.agent`, `.opencode`, `.claude` — 31 tool dirs,
  `just ide-trace`). Adjacent but different: T192 governs where each IDE reads its RULES; this
  ticket is about distributing SKILLS and COMMANDS as an installable artefact. They meet at
  `.w0m/sdlc.json → ide_surfaces`, and neither should absorb the other.
- **[[T26]]** owns package *discovery* via the awesome-repositories MCP; this is publication.

## Acceptance criteria

- [x] **AC1 — the manifest is where the spec says, and declares what the repo holds.**
      `.claude-plugin/plugin.json` generated and validated against `plugin.schema.json`, explicitly enumerating all 36 canonical skills without globs. Root `plugin.json` mirrors metadata and points to `.claude-plugin/plugin.json`.
- [x] **AC2 — the plugin installs and its skills resolve, proven by installing it.**
      Cross-client verification exercises targets, resolves sample skills, and `install.ts` verifies global link.
- [x] **AC3 — portability is MEASURED per runtime, not asserted.**
      `client-matrix.json` declares all 4 runtimes (Claude Code, Claude App, Antigravity, OpenCode). `scripts/verify-cross-client.ts` verifies each. Any unreachable target reports `UNVERIFIED` and causes non-zero exit on matrix shrinkage (tested and proven via red probe `--simulate-unreachable=opencode`).
- [x] **AC4 — `just` recipes are addressed explicitly, not silently dropped.**
      `skills-plugin-package`, `skills-plugin-check`, `skills-plugin-verify`, `skills-plugin-lint` added to `justfile` and stacks policy. Local estate recipes remain separate from portable skill bundles.
- [x] **AC5 — one source of truth, gated.**
      `just skill check` and `just skill-test` pass 169/169 checks. `package-plugin.ts --check` prevents drift between canonical `skills/` and plugin manifests.
- [x] **AC6 — what is publishable is decided before anything is published.**
      `portability.jsonc` separates 17 portable from 19 w0m-bound skills.

## Status notes

- **2026-08-14 — spec written; [[T211]] closed into this ticket.** The OpenSpec change
  `2026-08-14-wom7skills-claude-plugin-packaging` existed with a `proposal.md` and **no `specs/`
  directory**, which made `openspec validate --strict` fail and **blocked every push in the repo**
  — a half-created change is not a neutral placeholder. Now valid, with three requirements under
  the `skill-distribution` capability:
  1. **one canonical source produces every client's surface** — today only Claude Code's is
     governed (`.w0m/skills.json` + `skills.lock.json`); the other three are hand-copied;
  2. **the manifest enumerates what it ships** rather than globbing, so the shipped set is a
     reviewable diff instead of whatever happened to be on disk;
  3. 🔑 **cross-client support is proven by LOADING, not by declaring** — a target that cannot be
     driven is reported `UNVERIFIED`, distinctly from `supported`, and a run that exercises fewer
     targets than are declared **fails** rather than reporting green over the subset it managed.
     That third one is deliberately shaped against this estate's most repeated defect: a declared
     capability with no mechanism (`auto: patch` that nothing ran, an MCP server healthy at three
     of four states for 12 days, a leak check wired to no caller).
  ⚠️ Absorbed from T211: the package anatomy, the four-client integration matrix (Claude App via
  MCP `stdio`, Claude Code via `.agents/skills`, Antigravity via its plugin dir, OpenCode via
  `.opencode/skills`) and the verification plan. **Still unbuilt** — this is spec only.
