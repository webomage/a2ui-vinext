# T341 — gate_advance.py id-prefix regex silently mutates the wrong ticket's board row

## Summary

`just gate <id> <status>` (T119 AC5's atomic transition tool) is meant to update a ticket's
frontmatter, `TASKS.md` row and `project/tickets.json` together, precisely so the three surfaces
can never drift apart by hand-editing. `find_tasks_row()`'s regex had no boundary after the ticket
id, so a short id matched as a bare PREFIX of any longer id sharing the same digits — `T7` against
`T70`/`T71`/`T74`/`T75`, `T20` against `T200`+. `re.search` returns the first match in the file, so
`just gate T7 in-progress` silently flipped **T70's** board glyph (⚪ → 🟡) while leaving T7's own
row untouched — a tool built to prevent exactly this kind of drift caused it instead. Caught only
because the diff from `just gate T7 in-progress` (T7's SDLC kickoff) was read before committing.

## Acceptance criteria

- [x] AC1 — `find_tasks_row(tid)` matches only the row whose id equals `tid`, never a row whose id
      merely starts with the same digits — verified against `T7` vs `T70`/`T71`/`T74`/`T75` and
      `T20` vs `T200`, all five now resolving to their own row
- [x] AC2 — `TASKS.md`'s T70 row, corrupted by this bug during T7's 2026-09-11 kickoff, is restored
      to its pre-bug glyph (⚪), and T7's own row is set to the glyph its frontmatter/manifest
      actually carry (🟡)

## Definition of Done

`find_tasks_row` returns the correct row for every id that collides on a shared digit prefix with
another id present in `TASKS.md`, proven by resolving all of `T7`, `T70`, `T71`, `T74`, `T75`,
`T20`, `T200` in one run and confirming each returns its own, distinct row (an id absent from the
board, e.g. `T1`/`T2`, correctly still fails closed — that is the tool's intended refusal, not a
regression). No board row changed except the two named in AC2.

## Status notes

**2026-09-11 — found, fixed and verified same-day, during [[T7]]'s `w0m-sdlc-start` kickoff.**
`just gate T7 in-progress "..."` reported `updated TASKS.md` but the diff showed **T70's** row
changing, not T7's — `find_tasks_row`'s pattern `\[?\s*{tid}\s*\]?` has no assertion that `tid`
ends where the ticket id ends, so `T7` satisfied it against `T70`/`T71`/`T74`/`T75` (whichever
appears first in the file) with zero characters left over to check. Fixed by adding a `(?!\d)`
lookahead immediately after the id in `wom7api/scripts/gate_advance.py`. Regression-checked by
calling `find_tasks_row` directly for `T7`, `T70`, `T71`, `T74`, `T75`, `T2`, `T20`, `T200`, `T1`,
`T10` — the seven with real board rows each returned their own row; `T1`/`T2` correctly failed
closed (no row exists — both are done tickets with no active board entry, unrelated to this bug).
`TASKS.md`'s corrupted T70 glyph reverted to ⚪ and T7's own row hand-corrected to 🟡 to match its
already-correct frontmatter/manifest state before this fix existed.
