# T410 — Enable ast-grep to parse and inspect Astro components via tree-sitter-astro custom language

## Summary

In `wom7web/CLAUDE.md` and `wom7web/project/ast-grep/sgconfig.yml`, an explicit structural blindspot was documented:
> "Cannot parse .astro/.svelte/.vue/.sql. With serena's identical .astro gap, the 210 .astro files have no structural tool at all."

AST-grep (currently `0.45.3`) natively supports 25 languages (TS/TSX/JS/HTML/CSS/Rust/Python, etc.), but `.astro` files (210 git-tracked files across `apps/web` and `apps/cp`) were previously blind to it, leaving the entire UI page and layout layer without structural AST inspection or automated rule enforcement.

AST-grep supports dynamically loaded Tree-sitter grammars via the `customLanguages` configuration in `sgconfig.yml`. By building and registering the `tree-sitter-astro` shared dynamic library (`astro.dylib`), we can unlock full AST matching, pattern rewriting, linting, and structural scanning on `.astro` files across the repository.

This ticket delivers:
1. Automated compilation and setup for `tree-sitter-astro` as a dynamic library under `project/ast-grep/parsers/astro.dylib`.
2. Registration of the `astro` custom language in `project/ast-grep/sgconfig.yml`.
3. AST-grep rule(s) and test fixtures targeting `.astro` files in `project/ast-grep/rules/` and `project/ast-grep/tests/`.
4. Updates to `just sg-scan` and `just sg-test` to include `.astro` files in automated CI/SDLC checks.
5. Retirement of the ".astro is blind to ast-grep" documentation caveat in `CLAUDE.md` and `sgconfig.yml`.
