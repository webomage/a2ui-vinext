## 🔬 The React-DS vs Astro/Svelte-stack question, answered by measurement (2026-08-08)

Owner question: *"the DS is React based and we have to find out how to match this with Astro/Svelte
stack"*. 🔑 **Measured answer: the DS is only React-shaped in ONE of its three layers, and the
common framing — "port the React linter to a Svelte-aware linter" — is the wrong fix.**

`_adherence.oxlintrc.json` (19,514 B) holds **3 rules**, of which `no-restricted-syntax` carries
~28 selectors. They split cleanly:

| layer | what it is | portable to Astro/Svelte? |
|---|---|---|
| **1. Tokens** — `design-system/tokens/*.css`, **186 tokens** in `x-omelette.tokens` | plain CSS custom properties | 🟢 **Already neutral — nothing to port.** Astro, Svelte and plain CSS consume them identically. This is most of the DS's value |
| **2. Token adherence** — **3 selectors**: `Literal[/#[0-9a-fA-F]{3,8}/]` (raw hex), `Literal[/\b\d+px\b/]` (raw px), `Literal[/font-family:(?!Inter)/]` | match **`Literal` nodes, no JSX** | 🟡 **Content portable, TOOL wrong** — see below |
| **3. Component API** — **~25 selectors**, all `JSXOpeningElement[name.name='X']`, over **15 components** (`Badge`, `Button`, `Dialog`, `GlassCard`, `StatusDot`, `TechIcon`, …) encoding declared props + allowed enum values | JSX AST | 🔴 **Structurally untranslatable — Svelte has no JSX AST** |

⚪ The 4th rule, `react/forbid-elements`, is **`{"forbid": []}` — inert**. It forbids nothing today.

### 🔑 The two conclusions that matter

**(a) For layer 2, the blocker is not React — it is that oxlint is a JavaScript linter and the
styling lives where it cannot look.** Measured hex-literal occurrences by surface:

| surface | files with raw hex | oxlint can see it? |
|---|---|---|
| `.ts` / `.js` | **385** | 🟢 yes — these 3 rules would fire **today** |
| `.svelte` | **48** | 🟡 script blocks only, **not `<style>`** |
| `.astro` | **33** | 🟡 script blocks only, **not `<style>`** |
| `.css` | **21** | 🔴 no — not JavaScript |

⇒ **The fix is two tools, because there are two languages: keep oxlint for the script surface, add
a stylesheet linter (stylelint or equivalent) for `<style>` blocks and `.css`.** Porting the JS
linter to be "Svelte-aware" would still never read a `.css` file.

**(b) For layer 3, do not port the selectors at all — express them as TYPES.** The 25 JSX selectors
encode prop names and allowed enum values. In Svelte the native equivalent is **typed props on the
`packages/ui` (`@webomage/ui`) components**, enforced by `svelte-check`/`tsc` at compile time —
**strictly stronger than a lint selector**, and the estate already gates it via the pre-push
`typecheck-ratchet`. 🔑 A lint rule that says *"`<Badge>` size must be `sm|md`"* is a weaker
restatement of `size: 'sm' | 'md'`.

⇒ **"React DS → Svelte" is not one migration.** Tokens need nothing, token-adherence needs a CSS
linter, component contracts need types. **Only layer 3 is genuinely React-shaped, and its
destination is the type system, not a linter.**

keying cheap rather than a per-project bespoke job.

🔴 **Three projects, FOUR shapes** (export · hand-rolled · prose-docs · out-of-repo zip) ⇒ AC1's
`format` enum needs at least `claude-design | custom | docs | none`, and **`docs` is a real
answer** — Artemio's markdown *is* its design system, and declaring it `none` would be false.

⚠️ **Tailwind changes the token question and is unexamined.** Both w0m and Artemio use Tailwind
(w0m at root + `packages/ui`; Artemio v4). A utility-class system and a CSS-custom-property token
system are two sources of truth for the same values, and **nothing here has looked at how they
relate**. Do not design `design_system.tokens` until that is settled.

🔑 **The estate owns a React adherence config it cannot fully use, and the client that could use it
natively does not have it.** Neither project can discover that today, because nothing declares a
design system anywhere.

🔴 **And 1945 rules out the layer-3 answer that works for w0m: it has 72 `.jsx` and ZERO `.tsx`** —
no type system to express prop contracts in. ⇒ For 1945 the **JSX lint selectors are the right and
only enforcement**; for w0m they are the wrong one. **The same DS demands opposite gates on the two
stacks.**

⇒ **`design_system.adherence_gate` must be declared PER PROJECT and keyed to the stack**, resolved
against [[T130]]'s `stacks-policy.json`, which already records each stack's tech:

| stack | correct layer-2 gate | correct layer-3 gate |
|---|---|---|

| React + `.tsx` | same | prop **types**, selectors as backstop |
| Astro + Svelte (**w0m**) | CSS linter (`<style>` + `.css`) + oxlint for scripts | **TS prop types** on `@webomage/ui`, gated by `typecheck-ratchet` |

## Acceptance criteria

- [ ] **AC1 — `design_system` exists in the sdlc schema** with at minimum: `format`
      (`claude-design` | `custom` | `none`), `path`, `tokens`, `adherence_gate`, and an explicit
      `none` that is a *valid, recorded* answer rather than a missing key.
- [ ] **AC2 — detection is a recipe, not a convention.** `just design-system-check` (name TBD)
      reports format + path + drift for the current project. 🔴 **It must FAIL on an undeclared but
      present DS** — a project with `design-system/` on disk and no declaration is precisely the
      case that must not pass silently.
- [ ] **AC3 — the Claude Design export format is pinned by its real markers**, not by directory
      name: `<x-dc>` elements and the `_ds/<slug>-<uuid>/tokens/*.css` layout. 🔑 **Matching on the
      folder being called `design-system` would pass 1945, which is not a Claude Design export** —
      the estate's recorded trap of *never match on a name the inspected thing supplies*.
- [ ] **AC4 — the declaration NAMES its enforcing gate, and records that the gate does not yet
      exist.** `adherence_gate` must point at [[T93]]'s Svelte-aware linter, and until T93 lands,
      the declared value must be explicitly *pending* rather than pointing at
      `_adherence.oxlintrc.json` — which is React/JSX-only and would inspect **zero** files here.
      🔴 **Wiring the React config to make AC4 "pass" is the failure mode**, not the fix.
- [ ] **AC5 — the client cases are covered by the profile, not special-cased**: 1945's `custom`
      format is declarable and passes as `custom`; Artemio's out-of-repo zip is either imported or
      declared `none` with a reason. Ties [[T182]] AC8.
- [ ] **AC6 — the empty-corpus case fails loudly.** If detection finds zero DS files where a DS is
      declared, that is an error, not a green run — the estate's most-repeated defect.
- [ ] **AC8 — `adherence_gate` is keyed to the STACK, not global**, resolved against [[T130]]'s
      `stacks-policy.json`. 🔴 The evidence is that the same DS demands **opposite** gates: JSX
      selectors are correct for 1945 (React, 72 `.jsx`, no types to lean on) and wrong for w0m
      (Astro/Svelte, no JSX AST). A single global gate cannot be right for both.
- [ ] **AC9 — the detector distinguishes "Claude Design export" from "token folder that looks like
      one".** 1945's `tokens/` mirrors the export's file names while being hand-rolled — the AC3
      trap, found in the wild.
- [ ] **AC7 — the `webomage-design` skill and the declaration agree**, so an agent asked to build UI
      reads the same DS the gate enforces. ⚠️ The skill currently hardcodes brand facts in prose
      (`slate-950`, `#38bdf8`); if those drift from `tokens/*.css` nothing notices.

- [ ] **AC10 — 🔴 the surface is invisible to EVERY gate, not merely ungated — remeasured
      2026-08-23 on owner ask** (*"do we have presence and integration level of Design System for
      projects gated/detected/etc?"*). The answer is **no**, and it is stronger than this ticket
      recorded. `design_system` is absent from **all three** places it could be caught:
      **not in the estate's 34-key contract** (`.w0m/sdlc.json`), **not in `client-profile.json`
      keys**, and **not even in its `excluded` block** — so it is not a recorded omission, it is an
      unrecorded one. ⚠️ That distinction is the finding: `client-profile-check` fails on a contract
      key in no tier (it caught six such keys the same day), but it can only see keys that are IN
      the contract. A surface in neither escapes the one gate built to catch exactly this. There is
      also **no recipe** — `just design-system-check` (AC2) and `just ds-conformance` ([[T207]]) are
      both cited only by unticked ACs, which `just ac-recipe-check` correctly classifies as plans.
- [ ] **AC11 — detection is keyed on CONTENT, and BridgeRoad is the proof it must be.** Measured
      2026-08-23 across four projects — **four shapes, and the fourth breaks the obvious detector**:

      | project | artefacts |
      |---|---|
      | `wom7web` | `design-system/` — Claude Design export |
      | `1945` | `design-system/` — hand-rolled |
      | `artemio` | `design-system/` **and** `docs/design-system/` — **two**, plus the 29 MB zip outside the repo |
      | `bridgeroad` ([[T265]]) | 🔴 `design_guidelines.md` + `ds-bundle/` — **neither is named `design-system`** |

      A detector globbing `design-system` returns **zero** for BridgeRoad and would report it as
      *no design system* while a whole bundle sits beside the glob. That is AC6's empty-corpus trap
      arriving through the front door, and it is the estate's standing rule restated: **a surface is
      identified by its CONTENT, never its directory name** — broken four times inside [[T192]],
      twice by that gate itself. Artemio's **two** trees are the second half of the same point: the
      count is not one-per-project, so a detector returning a single path is already wrong.

## Definition of Done


Per [`../../openspec/SPEC-AUTHORING-STANDARD.md`](../../openspec/SPEC-AUTHORING-STANDARD.md):
`design_system` is a declared, schema-validated sdlc.json key with a detection **recipe** — not a convention — whose format is pinned by the Claude Design export's real markers, keyed to the STACK rather than globally, and which **distinguishes an export from a token folder that merely looks like one**. Every project carries a truthful declaration including `none`, and the client cases are covered by the profile rather than special-cased. 🔴 Two clauses carry the weight: the empty corpus must fail LOUDLY (a detector finding zero files where a DS is declared must not read as conformance), and detection is keyed on CONTENT — BridgeRoad is the proof it must be.
