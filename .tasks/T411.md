# T411 — Decouple Task Queue to Root .tasks/ and Establish Contention-Free Multi-Agent Concurrency Architecture

## Summary

As parallel AI agents (Claude Code, Antigravity, OpenCode) execute across the estate, severe cross-pathing bottlenecks and serializations degrade developer velocity and trigger merge collisions:
1. **The Root-Only Worktree Illusion**: Agent CLI tools spawn git worktrees at the root wrapper (`casualuser/w0m`). Because child estate repos (`wom7web`, `wom7api`, `wom7func`) are git-excluded subdirectories, agents in different worktrees actually share the *same* physical working copies on disk in `wom7web` and `wom7api`. Uncommitted work and builds collide in real time.
2. **Monolithic `TASKS.md` Contention**: `wom7web/TASKS.md` is a 268 KB monolithic Markdown table. All agents are required by SDLC rules to update it on every status change, causing frequent git merge conflicts on concurrent commits.
3. **Estate Governance Coupled to Web App**: Governance and task tracking live inside `wom7web`. Updating any ticket triggers `wom7web`'s pre-commit/pre-push hooks (Astro checks, frontend linters, web tests), burdening backend and tooling agents with web app CI overhead.
4. **Global Pre-Push Gate Failures**: Pre-push hooks run `state-check` (which fails if another agent moved the global hot list) and `openspec validate --all` (which fails if another agent has an in-flight draft spec on disk).

This ticket delivers:
1. **Relocate Task Queue to `@wom/.tasks/`**: Promote per-ticket Markdown files (`T##.md`) to the exclusive Source of Truth (SSOT) at the workspace root `@wom/.tasks/`, preserving `wom7web/project/tickets/` backwards-compatibility via symlink/resolver.
2. **Make `TASKS.md` a 100% Generated View**: Convert `TASKS.md` into a purely derived artifact generated via `just tasks-render`. Agents never hand-edit `TASKS.md`.
3. **Update SDLC Gates & Trace**: Update `sdlc_trace.py`, `w0m-sdlc-new`, `w0m-sdlc-start`, and `w0m-sdlc-archive` to operate exclusively on per-ticket files in `.tasks/`.
4. **Scope Pre-Push Validation**: Update `state-check` and `openspec validate` in `.husky/pre-push` to evaluate `--scope-diff origin/beta`, ignoring parallel in-flight draft work.
5. **Coordinated Worktree Orchestrator (`just worktree-agent <id> [repo]`)**: A recipe ensuring parallel agents receive isolated worktree checkouts across both the root union repo and target child repos.

## Acceptance criteria

- [x] AC1 — Establish `@wom/.tasks/` as the canonical ticket directory and configure `.w0m/sdlc.json` to resolve `.tasks/`, preserving `wom7web/project/tickets/` compatibility.
- [x] AC2 — Implement `just tasks-render` in root justfile to compile `TASKS.md` deterministically from `.tasks/T*.md`; update `tasks_query.py` and `sdlc_trace.py` to read/write per-ticket files exclusively.
- [x] AC3 — Update SDLC lifecycle skills (`w0m-sdlc-new`, `w0m-sdlc-start`, `w0m-sdlc-archive`) to eliminate manual `TASKS.md` edits and enforce single-ticket editing.
- [x] AC4 — Scope pre-push gates (`state-check` and `w0m-audit` / `openspec validate`) in `.husky/pre-push` to scoped push diff (`--scope-diff origin/beta`), preventing parallel in-flight work from blocking unrelated pushes.
- [x] AC5 — Implement `just worktree-agent <id> [subrepo]` to coordinate linked git worktrees across root `@wom` and target sub-repos (`wom7web`, `wom7api`), eliminating the shared unbranched filesystem trap.
- [x] AC6 — Add unit test suite `scripts/tests/test_agent_concurrency.py` verifying clean non-conflicting concurrent ticket updates and deterministic `tasks-render` output.

## Definition of Done

This ticket is complete when all of the following are observably true:
- The canonical task queue resides at `@wom/.tasks/` with individual `T##.md` files as the exclusive write surface.
- `just tasks-render` builds `TASKS.md` deterministically from `.tasks/T*.md` files without manual formatting intervention.
- `just sdlc-trace` verifies ticket progress from `.tasks/T##.md` without requiring edits to `TASKS.md`.
- `just worktree-agent <id>` provisions coordinated worktrees across root and targeted sub-repos.
- Pre-push gates `state-check` and `openspec validate` pass cleanly on scoped push diffs while another agent has uncommitted draft changes on disk.
- All pre-commit and pre-push quality gates pass cleanly with zero `--no-verify`.
