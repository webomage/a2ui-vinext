# T284 — give the client their own documentation, not a link to ours

## Summary

Implementation ticket for `docs/reports/HOSTED_OBSIDIAN_VAULTS_AND_COMMUNITY_PLUGINS_RESEARCH_2026.md`
— a 374-line architecture study written by the **Antigravity session** and adopted here on
2026-08-25 at owner direction, together with its two diagrams
(`docs/flows/hosted-obsidian-vault-topology.mmd`, `docs/flows/client-vault-delivery-lifecycle.mmd`).

⚠️ **The research is the input, not the deliverable.** It surveys the Obsidian plugin ecosystem and
proposes **four** hosting blueprints. This ticket scopes the one it calls the recommended core and
leaves the other three as decisions, because a ticket that adopts four architectures at once adopts
none of them.

**Blueprint A — Native CP Knowledge Hub.** Astro SSR renders the client's own markdown and mermaid
inside `cp.webomage.com`, beside their invoices and milestones. No client installation, works on a
phone, updates on git push. Blueprints B (Quartz on CF Pages), C (R2 + Remotely Save) and D (private
GitHub repos) are recorded in the research and are **out of scope here** — they serve
technical clients who want the vault in their own Obsidian app, which is a different audience and a
different security argument.

## 🔴 What the research assumes that is not yet true

The blueprint's multi-tenancy section reads: *"Strict Supabase RLS: authenticated user session maps
to `client_id`. Maksim Kulikov sees only `servicios777` & `personaje0`. Artemio sees only
`artemioquierocomer.mx`."* Measured 2026-08-25, three of those premises are open:

| the research assumes | measured state |
|---|---|
| Maksim is a client with two projects | 🔴 **no `clients` row, no account** — [[T279]] is `queued` |
| RLS tenancy is settled | ⚠️ [[T198]] AC6/AC7 still open; [[T266]] AC8 records them as Artemio's residual risk |
| what the portal shows is the client's data | 🔴 [[T283]] — the dashboard rendered a **$4,200 PAID demo invoice** to a real client while the tenancy probe was green |

🔑 **The third is the one that should shape this ticket.** [[T283]] proved a green tenancy probe says
nothing about whether the page shows real data. A knowledge hub is worse than a dashboard here: a
client reading *architecture and decisions* has no way to tell a placeholder from a fact.

## Acceptance criteria

- [x] AC1 — **A client reads their OWN docs, and the corpus boundary is DATA.** Which paths belong to
      which client is declared (per [[T182]]'s import path / `clients-policy.json`), never inferred
      from a directory name — CLAUDE.md's standing rule, broken four times inside the ticket that
      established it.
- [x] AC2 — 🔴 **A probe that a client session reads ZERO documents belonging to another client**,
      observed red first, following [[T198]] AC8. ⚠️ And **unlike** the tenancy probe, it must assert
      over a **non-empty** corpus for both tenants — "0 rows for the other client" is vacuous when
      the other client has no documents.
- [x] AC3 — 🔴 **Nothing rendered may be a placeholder.** Direct consequence of [[T283]]: no fixture,
      no sample, no demo document reaches a real client's hub. If there is nothing to show, the page
      says so.
- [x] AC4 — **Mermaid renders server-side or is degraded honestly.** The estate already validates 311
      diagrams with `just mmd-validate`; a diagram that fails to render must show that it failed, not
      an empty box.
- [x] AC5 — **Internal-only content cannot leak through the hub.** The KB content policy (auto-memory:
      *projects/client work never in public KB tier*) applies in reverse here — w0m's own specs,
      tech-debt and incident notes must be unreachable from a client session even when they sit in
      the same repository.
- [x] AC6 — **Blueprints B/C/D get a written verdict — adopt, reject, or revisit-when-X — not
      silence.** Each serves a different audience; leaving them undecided means the next person
      re-derives the same four options. ⚠️ C and D hand the client a git remote or an R2 bucket,
      which is a materially larger authorization surface than a rendered page.
- [x] AC7 — **Depends on, and does not duplicate, the client surface work.** [[T283]] must land first
      (a hub that fabricates is worse than none), and [[T279]] before any claim involving Maksim.

## Definition of Done

Per [`../../openspec/SPEC-AUTHORING-STANDARD.md`](../../openspec/SPEC-AUTHORING-STANDARD.md):
a signed-in client reads their own architecture, specs and decisions inside the CP, with the
client↔document boundary declared as data rather than inferred from paths, and a probe — observed
red first, over a non-empty corpus for BOTH tenants — showing they read none of another client's;
nothing rendered is a placeholder; a diagram that fails to render says so; w0m's internal material
is unreachable from a client session; and Blueprints B, C and D each carry a written verdict rather
than being left implicitly deferred.
