# T192 — connected IDEs are an ungoverned surface

## Summary

Owner direction 2026-08-10: *"we had openspec managing connected IDEs and it looks like we chose 3
— Claude Code, OpenCode, Antigravity … let's make it available for setting multiple via openspec
for project configs sdlc … we have to insure also that connected IDEs autostart all the rules and
follow same tooling schemas and flows … there could be also global or local rules/tools/workflows
in different IDEs; in general we should manage and trace all of them for a project."*

🔴 **The finding that defines this ticket: a second IDE is already autoloading rules that
contradict `CLAUDE.md`, and nothing detects it.** `openspec init --tools` writes a *per-IDE*
instruction surface — 31 tools supported, each with its own `skillsDir`. The estate has been
governing exactly one of them.

## Retro — 2026-08-10

**What this ticket actually taught, beyond its own subject.**

🔑 **The rule the ticket was built on, I broke four times.** *Identity is content, never the
directory name.* The filing broke it twice (`.kilocode`, `wom7ext/.agent`). Then the gate's first
marker was too narrow. Then — the one that matters — I **widened** the marker with an `openspec*`
glob and wrote *"the earlier openspec layout"* into four artefacts, having verified nothing. It
was a filename. ⇒ **Recall of a trap does not prevent it.** Only a probe does: the case that pins
this now asserts `openspec*` is NOT in the marker, so re-adding it fails a test rather than a
review.

🔑 **Before "fixing" duplication, check whether it is one file.** `.agent/rules.md` was recorded as
*"byte-identical to wom7api's — one repo's rules copied into the other"*. `wom7api/.agent` is a
**symlink**; same inode, set 2026-02-12, exactly like the shared `justfile`. I discovered it by
writing two per-repo files and watching the second overwrite the first — a diff would never have
shown it, because there was only ever one file to diff.

🔑 **A gate that models the estate wrongly manufactures work.** Scoring five delegating repos at
1/6 would have had someone paste the canonical text into six `CLAUDE.md` files — creating the exact
drift the gate exists to detect. The fix was to teach it delegation, and then to make delegation
honest: the pointer must resolve **and** the target must carry the rules, because wom7mlx's
`CLAUDE.md → AGENTS.md` resolved, carried 1/6, and looked compliant.

🔑 **A red probe bound to a file you intend to repair stops proving anything the moment you
succeed.** Ours did, failed loudly, and said what to do. The 1,646 B original is frozen as a
fixture; the live file gets its own separate probe.

⚠️ **`openspec init` does not touch `AGENTS.md`** — the surface it generates and the surface the
IDE autoloads are not the same thing. That is why declaring `opencode` immediately exposed
wom7api as having no contract at all.
