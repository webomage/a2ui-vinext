# T69 — Schema-qualifier / missing-table query bugs (live)

## Summary

Three live query bugs found against the DB:

- **(a)** `apps/cp/src/components/admin/CharacterSheet.svelte` queries `player_xp_totals` + `wallets` without `.schema('gamification')` → PostgREST resolves against `public` (neither exists there), errors are swallowed → the character sheet **always renders 0 XP / 0 balance**.
- **(b)** interviews `Dashboard.svelte` (web + cp) query `interview_messages`, a table that exists in **no schema** → transcript panel permanently empty.
- **(c)** the `job-ingest` edge fn upserts into non-existent `scraped_jobs` → scraped LinkedIn jobs never persist to Postgres.

Fix or remove each; sweep for other unqualified gamification refs (see T41 WalletPanel).

## 🔬 Re-verified live 2026-08-13 — all three still reproduce

| claim | measured |
|---|---|
| (a) `player_xp_totals` + `wallets` unqualified | 🔴 **confirmed.** Both exist **only in `gamification`**; `CharacterSheet.svelte:55,65` call `.from(...)` with **no `.schema('gamification')`** ⇒ PostgREST resolves against `public`, finds nothing, the error is swallowed, **0 XP / 0 balance renders as if true** |
| (b) `interview_messages` | 🔴 **confirmed — exists in NO schema**, and is queried by `Dashboard.svelte` in **both** web and cp |
| (c) `scraped_jobs` | 🔴 **confirmed — exists in NO schema**; `job-ingest/index.ts:78` upserts into it |

🔑 **New for (c): `public.aggregated_jobs` DOES exist**, and reads like the intended target — so this
may be a rename that one writer never followed. **Check before creating `scraped_jobs`**: creating a
table to satisfy a stale name would fork the job corpus in two.
⚠️ **All three fail SILENTLY**, which is why they survived a month: (a) swallows the error, (b)
renders an empty panel, (c) drops rows. **A visible failure would have been fixed already.**

## 🔴 2026-08-13 build — the root cause is a missing GRANT, and it is much wider than (a)

**`gamification` was never granted to ANY role.** Measured live before the fix:

```
pg_namespace.nspacl  for gamification            = NULL
has_schema_privilege('authenticated', …,'USAGE') = false
has_schema_privilege('service_role',  …,'USAGE') = false   ← even the admin role
rows in role_table_grants for the schema         = 0
GET /rest/v1/wallets (Accept-Profile: gamification, service-role key) → 403 42501
```

The RLS policies for this exact feature have existed since `20260503120000` (*"Players can view own
wallet"* TO `authenticated`) and have been **unreachable the whole time** — RLS filters a grant, it
does not substitute for one. So (a) is one symptom of a schema nobody could read:

- Adding `.schema('gamification')` **alone** converts a silent `0 XP` into a **401**. AC1 would have
  read as met while the panel stayed blank — the exact failure mode this ticket is about.
- The components that *already* qualified — `CampaignBoard`, `QuestBoard`, `UnitsManager` — were
  **already dead** for the same reason, just loudly.
- So were **9 edge functions**: `gamification-economy` (withdrawals, wallet deductions, compliance),
  `process-payout`, `stripe-webhook`, `guild-api`, `telegram-webhook`, `gamification-ingest`,
  `client-api`. **50 call sites in total.**

⚠️ **The sweep found more of (a) than the ticket knew about.** `CharacterSheet.svelte` had **4**
unqualified calls, not 2 (`badge_awards` and `xp_ledger` too), and two further components were
unqualified: `TreasuryManager.svelte` (5 sites) and `WalletPanel.svelte` (1).

🔑 **(c): `aggregated_jobs` is NOT the intended target — the hypothesis was wrong, and acting on it
would have been the damaging option.** `aggregated_jobs` is the **source-agnostic public feed**
(7,375 rows, keyed `(source, external_id)`, filled by `job-aggregator` from
remoteok/remotive/hn/wwr/jooble/adzuna, read by `apps/job`). `scraped_jobs` is a **per-user LinkedIn
inbox** needing `user_id`, `identity_context`, `raw_data`, `ats_state`, `ai_score`, `scored_at` —
none of which `aggregated_jobs` has. Writing per-user scrapes into the public feed would have leaked
one user's `identity_context` into every visitor's job list. Also **4** call sites, not 1:
`job-ingest:78`, `job-scorer:18,88`, `vectorize-job:32`.

🔑 **(b): decided — the panel is removed.** `interview_messages` has no schema **and no writer
anywhere**; `analyze-interview` only touches `public.interviews` (2 rows). Creating the table would
have left the panel permanently empty *and* added dead schema. Restore from git history if a
transcript writer is ever built.

## Acceptance criteria

- [x] **AC1 — (a) `CharacterSheet.svelte` reads the gamification schema, and the sweep is finished.**
      Add `.schema('gamification')` to both calls, then sweep for **every other unqualified
      gamification reference** (T41's `WalletPanel` is the known second site). ⚠️ **The sweep is the
      AC, not the two lines** — the same bug in another component is the same bug.
      ✅ **Done 2026-08-13 — 10 sites, not 2.** `CharacterSheet` **4** (`player_xp_totals`, `wallets`,
      `badge_awards`, `xp_ledger`), `TreasuryManager` **5**, `WalletPanel` **1**.
      `just callsite-drift` reports **UNQUALIFIED: 0**, which is what makes "the sweep is finished" a
      measurement rather than a claim.
- [x] **AC1b — the grant the qualifier depends on.** 🔴 Added during the build: the qualifier alone
      turns the silent `0 XP` into a **401**, because the schema has no `USAGE` for any role (see the
      build section above). Migration
      `20260813120000_t69_ac1_gamification_grants.sql` issues exactly what the existing policies
      assume — `USAGE` to `authenticated`+`service_role`, `SELECT` to `authenticated` on the 13 tables
      with a player-scoped policy, `ALL` to `service_role`, plus `ALTER DEFAULT PRIVILEGES` so the
      next table is not born unreachable. ⚠️ **`billing_circles` and `operations_treasury` are
      deliberately NOT granted to `authenticated`** — they carry a service_role-only policy, so
      `TreasuryManager` still 403s on those two and needs a server route, not a wider grant.
      🔴 **`player_xp_totals` needed `security_invoker = true`** or the grant would have exposed every
      player's XP totals: it aggregates `xp_ledger` and is owned by BYPASSRLS `postgres`.
      ✅ **APPLIED AND VERIFIED LIVE 2026-08-13** (owner ran `just db-migrate`).
      `has_schema_privilege`: `authenticated` **true**, `service_role` **true**, `anon` **false**.
      The exact call that returned `403 42501` before now returns **200**. `anon` still **401**,
      and the *unqualified* path still **404**s — so the qualifier is still load-bearing rather than
      papered over by a wide grant.
      🔬 **The `security_invoker` decision is measured, not argued:** postgres (BYPASSRLS) sees
      **2** rows in `player_xp_totals`, an authenticated player sees **1** — their own.
      Without it that would read 2. `operations_treasury` → **permission denied for authenticated**,
      exactly as intended.
- [x] **AC2 — (b) `interview_messages` is created or the panel is removed.** It exists in no schema,
      so the transcript panel can never populate. **Decide which**, in both web and cp — leaving a
      permanently empty panel is the worst of the three options.
      ✅ **Removed**, in both. No writer exists anywhere, so creating the table would have kept the
      empty panel and added dead schema. Reversible from git history if a writer is ever built.
- [x] **AC3 — (c) `job-ingest` writes somewhere real.** ⚠️ **Establish first whether
      `public.aggregated_jobs` is the intended target**; only create `scraped_jobs` if it genuinely
      is a distinct thing. **Scraped LinkedIn jobs currently never persist.**
      ✅ **Hypothesis checked and rejected** (see the build section) — two different corpora, and
      merging them would have leaked one user's `identity_context` into the public feed. Migration
      `20260813121000_t69_ac3_scraped_jobs.sql` creates `public.scraped_jobs` with RLS, and
      `job-ingest`'s `onConflict` is corrected to the real key `(user_id, job_source_id)` — the
      previous `job_source_id` alone would have let two users' upserts overwrite each other.
      ✅ **APPLIED AND VERIFIED LIVE 2026-08-13.** `public.scraped_jobs` exists, RLS on, 3 policies,
      `anon` SELECT **false**; service-role REST read returns **200**, anon **401**.
      ⚠️ **Still needs a deploy** — the corrected `job-ingest` runs the old code until then.
- [x] **AC4 — errors stop being swallowed at these three call sites.** All three failed silently for
      a month. A caught-and-ignored PostgREST error is what turned a missing table into "the feature
      shows zero".
      ✅ `CharacterSheet` throws on every error and uses `maybeSingle()` so *no rows yet* stays
      distinguishable from *failed*; `TreasuryManager` throws on the first failed read instead of
      rendering `|| []`; `job-ingest` returns **500** instead of `console.warn`-ing and reporting
      success to the extension. The transcript panel's swallow is gone with the panel.
- [x] **AC5 — a check catches the class, not the instances.** `just schema-drift` already flags a
      Drizzle table that does not exist ([[T117]] AC8); extend the same idea to **`.from('<table>')`
      call sites naming a table that exists in no schema, or in a schema the call does not qualify.**
      🔴 **Red-probe it against today's tree** — it must find these three before they are fixed.
      ✅ **`just callsite-drift`** — 492 call sites, 4 classes: GHOST / UNQUALIFIED / MISQUALIFIED /
      **UNREACHABLE** (the fourth was added *because* of the grants finding: a check that only reads
      names would have called this ticket done). Red probe against the pre-fix tree saved at
      `project/authz-probe/T69-callsite-redprobe-2026-08-13.md` — it found all three.
      **`just callsite-drift-test`** holds 10 offline probes, one per class plus the three false
      alarms this checker actually raised: 26 storage buckets read as GHOSTs, and a hoisted
      `const g = supabase.schema(…)` handle read as UNQUALIFIED — i.e. it flagged T69's own fix as
      the bug it fixes.
