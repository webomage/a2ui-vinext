# T771 — Surface components catalog, design tokens matrix, and interactive showcase on OpenDesign Design Systems page and Webomage design system

## Summary

On OpenDesign's Design Systems page (`http://127.0.0.1:7456/design-systems`), imported local kits (such as `user:webomage`) currently render only Identity, Logo, Typography (with Fontsource slug names and no self-hosted font normalization), and Palette — hiding the interactive `components.html` Design System iframe (`parsedToKit` gated `staticUrl` behind `!opts.editable`), hiding the 6 `preview/*.html` tiles (whose relative `../tokens.css` href also 404s when served via `/api/design-systems/:id/static?path=...`), omitting structured `## Typography` / `## Voice & Tone` / `## Imagery` / `## Layout` sections from source `DESIGN.md`, emitting circular `var(--self)` bindings in `tokens.css` when Tailwind v4 `@theme inline` tokens are scanned, and lacking Claude-Design-style native Components catalog and Design Tokens sections.

Fix both halves cleanly: (a) upstream fork (`feat/design-system-components-showcase`) — prevent circular token self-references in `token-contract.ts`, preserve authored `components.html` + structured `DESIGN.md` sections + normalized Fontsource family names + inline preview `tokensCss` in `import.ts`, rewrite relative HTML asset URLs on `/api/design-systems/:id/static`, unlock `kit.system` / `kit.assets` / `designTokensUrl` / `componentsManifestUrl` for non-project imported bundles in `parsedToKit`, and render native Components catalog + structured Design Tokens matrix + new-tab action in `DesignKitView.tsx` (with zero hardcoded CSS colors and full 19-locale i18n parity); (b) estate (`w0m-web/design-system/`) — enrich `DESIGN.md`, `components.html`, and `components.manifest.json`, register the PR proposal in `scripts/w0m_prs.py`, merge into `local/sdlc-integration`, restart `:7456`, re-import `user:webomage`, and verify live.
