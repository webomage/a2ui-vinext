# T738 — Fix /solutions & /services direct package checkout and hats_profile_id_fkey profile ID resolution across w0m-api and w0m-web

## Summary

Submitting the Direct Package Checkout (`$890` / `$1,900` / `$2,200`) form on `/solutions` or `/services` failed with `insert or update on table "hats" violates foreign key constraint "hats_profile_id_fkey"` because `w0m-api/supabase/functions/client-register/index.ts` resolved `public.profiles.id` only inside the optional `domainChallenge` branch while writing raw `auth.users.id` into `public.hats.profile_id` (despite `claim_profile_for_account` minting `gen_random_uuid()` as `public.profiles.id` and storing `auth.users.id` in `profiles.auth_user_id`). Downstream blockers also prevented direct `stripe-checkout` calls from `/solutions`: missing `apikey` / `Authorization` headers when `[functions.stripe-checkout] verify_jwt = true`, rejecting blank optional `Domain or Repo` (`repo_url: ""`), and ignoring `package_price_usd` / `service_slug` in `validateAuditCheckoutPayload`.

## Acceptance criteria

- [x] AC1 — `w0m-api/supabase/functions/client-register/index.ts` resolves/claims `public.profiles.id` unconditionally via `auth_user_id` / `id` / `email` / `claim_profile_for_account` (`_shared/auth.ts` `ensureProfileIdForAuthUser` + `resolveCandidateProfileIds` + `resolvePrimaryProfile`) before inserting/querying `domain_ownership_verifications` and `public.hats`, and `client-api`, `stripe-checkout`, `stripe-portal`, `mercadopago-checkout`, `lead-api`, `seed-demo`, and `verify-credential` consistently resolve `public.profiles.id` alongside `auth.users.id` instead of passing raw `auth.users.id` into `hats.profile_id` or `verified_credentials.profile_id`.
- [x] AC2 — New migration `w0m-api/supabase/migrations/20261113210000_t738_hats_profile_id_normalize_trigger.sql` installs `public.wom_normalize_hat_profile_id()` (`SECURITY DEFINER`) `BEFORE INSERT OR UPDATE OF profile_id` on `public.hats` and `public.worn_hats` so any legacy caller passing `auth.users.id` normalizes cleanly to `public.profiles.id`.
- [x] AC3 — `w0m-api/supabase/functions/_shared/stripe-billing.ts` (`validateAuditCheckoutPayload`) accepts optional `package_price_usd` (`100..50000`), `service_slug`, and `service_title`, normalizes bare-domain `repo_url` values, and allows blank optional `repo_url` (or non-URL organization fallback) when `service_slug` is provided while keeping `"Invalid or missing repo_url"` when both are absent.
- [x] AC4 — `w0m-web/apps/web/src/pages/api/security-audit.ts`, `ServiceOrderSection.astro`, `audit.astro`, `ServiceActionOrderConfigurator.svelte`, and `AuditPricing.svelte` sanitize raw database constraint errors (never leaking `hats_profile_id_fkey` to UI copy), preserve successful `leadId` orders with `provisioningDeferred: true` if `client-register` hits the legacy FK mismatch prior to edge redeploy, pass `supabaseAnonKey` headers (`apikey` + `Authorization: Bearer ...`) + fallback `repo_url` + `service_title` to `stripe-checkout`, surface non-OK `stripe-checkout` errors explicitly (`AgDR-0025`), and adapt error banner actions (`Try Again` + `Refresh Security Check` + `Complete via AI Agent Helper ->`).
- [x] AC5 — Deno type-check (`just deno-check`: 64 entrypoints, 0 errors), Deno tests (`just deno-test`: 395 passed, 0 failed across 34 files), Vitest suites (`security-audit-order.test.ts` + `service-action-order-configurator.test.ts`: 16 passed), `supabase_surface_drift_check.py` (767 calls vs 200 SQL relations: 0 findings), and `just ui-ticket-leak-check` (503 files: 0 leaks) passed.
