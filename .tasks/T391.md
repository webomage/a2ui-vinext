# T391 — Harmonize workspace root and sub-app package manifests under canonical release versioning schema

## Summary

The canonical w0m release versioning standard is `YYYY.MM.DD-<unixtimestamp>` per ROADMAP §4 and [[T131]] ([`.w0m/sdlc.json -> versioning`](file:///Users/proto/Projects/@self/@wom/wom7web/.w0m/sdlc.json#L519)). However, package manifests across the estate have drifted:
- `apps/web/package.json` and `apps/cp/package.json` carry `"2026.02.26-1772088006"` (conforming to the schema, but static and stale since February 2026).
- `apps/demo`, `apps/job`, and `apps/join` carry `"1.0.0"`.
- `wom7web/package.json` carries `"0.0.1"`.
- The root workspace `@wom` (`casualuser/w0m`) lacks any `package.json` or version manifest.

Because all internal apps and monorepos declare `"private": true`, package managers (`pnpm`) do not reject date-timestamp strings during development or build. This ticket harmonizes all app manifests, establishes a root manifest for `@wom`, aligns policy declarations in `.w0m/sdlc.json`, and introduces `just version-sync` to keep manifests aligned.

- [x] AC2 — Establish a root manifest for workspace `@wom` (`/Users/proto/Projects/@self/@wom/package.json` declaring `"name": "@wom/workspace"`, `"private": true`, and canonical versioning).
