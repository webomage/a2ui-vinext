# T697 — Live Edge Lighthouse CWV Engine, Full First-Party Website & Repo Security/Compliance Audits, Saved Diagnostic Sessions, and Dedicated Mistral CP Fix Helper

## Summary

1. **Google PSI Anonymous Pool Quota Exhaustion (`project_number:583797351490`)**:
   - In Client Portal (`/o/[org]/projects/security-audit`), clicking **Run Lighthouse & CWV Audit ->** on verified `webomage.com` returned `Quota exceeded for quota metric 'Queries' and limit 'Queries per day' of service 'pagespeedonline.googleapis.com' for consumer 'project_number:583797351490'`.
   - When `PAGESPEED_API_KEY` is unset (or rate-limited on Cloudflare Worker egress IPs), Google PageSpeed Insights v5 routes requests through Google's shared anonymous consumer project `583797351490`, which hits HTTP `429`.
   - Implemented a live **Cloudflare Edge HTML + CWV/A11y/SEO/Best-Practices Diagnostic Engine (`runEdgeHtmlLighthouseAudit`)** that automatically executes against the live target URL when PSI returns `429`/`403`/`502`, measuring real TTFB, HTML/asset payload, render-blocking scripts/stylesheets, image dimensions/lazy-loading/modern formats, caching, HSTS/CSP, SEO tags, and ARIA/label accessibility across Mobile and Desktop profiles.
2. **All Audit Services Active Out-of-the-Box for First-Party Websites & Repositories (Security & Compliance)**:
   - First-party Webomage websites (`webomage.com`, `www.webomage.com`, `cp.webomage.com`, `me.webomage.com`, `demo.webomage.com`, `w0m.xyz`, `www.w0m.xyz`) are recognized as canonical verified first-party targets across Surface Security, Lighthouse & CWV, and Cloudflare Security Audit Skill checks, with root-zone `_w0m-verify` DNS TXT inheritance.
   - First-party `@wom` estate repositories (`github.com/webomage/w0m-web`, `w0m-api`, `w0m-cf`, `w0m-ext`, `w0m-sec`, `w0m-skills`, `w0m-mlx`) work seamlessly in Level 2 Sandboxed Code Audits without hitting the 1-scan trial demo cap (`TRIAL_QUOTA_EXCEEDED`), with quick-select buttons in Client Portal for our websites and all 7 estate repos.
3. **Saved Diagnostic Sessions in Client Portal**:
   - Every diagnostic run (`level1` surface security, `lighthouse` Mobile+Desktop CWV, `level2_trial` repo SAST/IaC/SCA, `level3_cloud` posture & compliance, and `mistral_remediate` fixes) is saved to `orgs.service_usage.diagnostic_sessions` (and hydrated on SSR load in `security-audit.astro`), with a dedicated **Saved Diagnostic Sessions** panel (`data-testid="cp-diagnostic-sessions-panel"`) supporting snapshot saving and instant session restoration.
4. **Dedicated Mistral Security & Compliance Fix Helper in CP**:
   - Building on `T677` (`MISTRAL_API_KEY_<PROJECT_UPPER>` -> `MISTRAL_API_KEY_W0M` / `MISTRAL_API_KEY`, `mistral-small-latest`), added a dedicated **Mistral CP Fix Helper** (`w0m-web/packages/lib/src/security/mistral-remediation-helper.ts` + `action: "mistral_remediate"` in `/api/client/security-audit.ts` + interactive UI workbench `data-testid="cp-mistral-fix-helper-panel"`) so operators can click **"Fix with Mistral Helper"** on any Surface, Lighthouse/CWV, Cloudflare Security Skill (`[CF-AUD-###]`), Level 2 Repo, or Level 3 Compliance finding.
