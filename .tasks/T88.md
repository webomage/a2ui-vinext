# T88 — Agent framework — first-class streaming + buffered modes w/ real tool loop

## Summary

**Agent framework — first-class streaming + buffered modes w/ real tool loop** — today both paths handle only the terminal `submit_service_request` tool as **canned text** (model never reads tool results); streaming **drops late tool-call frames** once prose starts (`ai-router.ts:~207`). Gap = a genuine **multi-turn tool loop** (model → tool → result fed back → model streams NL answer) identical in streaming **and** buffered, via one `runAgentTurn` runtime + a `TOOL_REGISTRY`, with `tool_call`/`tool_result` SSE status frames. Closes the 🔴 "streaming↔tools don't meet" item.

## Acceptance criteria

- [x] AC1 — A genuine **multi-turn tool loop** exists: model → tool → result fed back → model
      answers from the result. Today the model never reads tool output; a canned-text response is
      the defect, not the feature.
- [x] AC2 — **Streaming and buffered take the SAME path** — one `runAgentTurn` runtime plus a
      `TOOL_REGISTRY` — so the two modes cannot drift apart again.
- [x] AC3 — 🔴 **Late tool-call frames are no longer dropped once prose starts**
      (`ai-router.ts:~207`). Proven with a case that emits a tool call after the first prose token
      — the exact shape that fails today.
- [x] AC4 — `tool_call` and `tool_result` SSE status frames are emitted and consumable by the
      widget, so the UI can show tool activity rather than a silent pause.
- [x] AC5 — Closes the recorded 🔴 **"streaming ↔ tools don't meet"** item: a single live request
      demonstrates streaming AND tool use together, which is the thing that has never worked.

## Definition of Done

Per [`../../openspec/SPEC-AUTHORING-STANDARD.md`](../../openspec/SPEC-AUTHORING-STANDARD.md):
a genuine multi-turn tool loop exists — model → tool → result fed back → model — and streaming and buffered take the **same** `runAgentTurn` path rather than two implementations that drift. 🔴 The specific defect this closes: late `tool_call` frames are no longer dropped once prose has started, and `tool_call`/`tool_result` SSE frames are emitted and consumed by the widget. ⇒ Demonstrated by a single live request in which streaming and tools meet, which is the recorded item this ticket exists to retire.
