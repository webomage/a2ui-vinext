# T565 — OpenSpec backfill batches for non-exempt tickets

## Summary

Split from [[T185]] after [[T185]] landed the machine-readable `.w0m/sdlc.json → spec_policy` contract (AC1), made `project/templates/ticket.md`'s Definition of Done conditional on `spec_policy` paying down **D38** (AC2), wired `N/M specced` reporting into `just tasks` and `STATE.md` (AC6), and added `wom7web/project/scripts/spec_policy_check.py` enforcing backfill provenance (`Shipped`, `Filed`, `Authored` dates, AC4/AC7).

Across 564 tickets in `.tasks/`, **201** carry a `spec:` path today while **362** remain unspecced (many of which fall under `spec_policy.exempt_classes`: `consolidation_decision`, `audit_sweep`, `hygiene_or_cleanup`, `doc_or_registry_sync`, `duplicate_or_superseded`). Per [[T185]]'s honesty constraint, retroactive specs must never be bulk-generated filler — exempt tickets should declare `spec_exempt: <class>` in frontmatter, and remaining non-exempt feature/schema/contract tickets should receive hand-authored, `openspec validate --strict` changes in bounded batches.

## Acceptance criteria

- [x] **AC1** — **Disposition pass on closed unspecced tickets:** classify closed tickets that fall under `.w0m/sdlc.json → spec_policy.exempt_classes` with `spec_exempt: <class>`, verified by `spec_policy_check.py`.
- [x] **AC2** — **Retroactive OpenSpec batch for non-exempt closed feature/contract tickets:** author retroactive OpenSpec changes (with `Shipped`, `Filed`, `Authored` provenance dates in `proposal.md` per [[T185]] AC4/AC7) for closed tickets in `requires_spec` classes (`new_feature`, `schema_or_contract_change`, `cross_repo_behaviour_change`, `security_surface_change`).
- [x] **AC3** — **Every authored backfill change validates `openspec validate <name> --type change --strict` clean** and passes a 10-spec anti-filler spot-check (every requirement traces to >=1 ticket AC and no scenario merely restates an AC).
