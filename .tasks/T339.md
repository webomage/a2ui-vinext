# T339 — Mage/Web terminology-theme toggle

## Summary

Owner, 2026-09-11, mid-turn during T338 work: *"I think we should use gamificated DSL as a 'Mage'
theme, available for all users to activate and 'Web' as normal classic business terminology for
clients and PM/TL/Dev — change in user settings."*

`docs/backend/TERMINOLOGY-MAP.md` already documents that the estate carries two complete,
structurally real vocabularies for the same production work — an agency one (`contract →
client_milestone → revision → closure`) and a gamified one (`project → adventure → raid → quest`)
— and that the schema-level fork was deliberately settled rather than merged ([[T203]] AC6/AC6b,
2026-08-12; [[T239]], 2026-08-21). **This ticket does not reopen that fork.** It adds a
presentation-layer switch that lets either vocabulary be *displayed*, without changing which table
backs which word.

**Grounded 2026-09-11 — the split the owner describes already half-exists in code, by accident,
not by design.** `apps/cp/src/components/client/MilestoneList.svelte` already speaks the classic
business term to clients, while `apps/cp/src/components/admin/RaidBoard.svelte`,
`QuestBoard.svelte` and `CharacterSheet.svelte` already speak the gamified term on the internal/
admin side. Nothing today makes that a *choice* — it is only which component a given page happens
to import, and an admin never sees "milestone" while a client never sees "raid". This ticket turns
the accident into a deliberate, per-user setting: a `terminology_theme` preference (`mage` |
`web`), defaulting to `web` for every role including clients and PM/TL/Dev, and available for
**any** user — including a client, if they want it — to opt into `mage`.

**Home:** the existing "Me" settings page, `apps/cp/src/pages/profile.astro`, which already hosts
per-user CP preferences (`MyProjectHats`, `ConnectedServices`, `CharacterSheet`) and is the natural
place for a fourth.

**Explicitly presentation-only.** The schema fork and its unresolved C1 finding (no FK between
`client_milestones` and `raids`/`quests`) are untouched here — see [[T333]] (records the bridge
equivalence: epic → Raid, milestone → Adventure, ticket → Quest) and [[T27]] (still unbuilt, 0/6
ACs — the ticket that actually writes epics/tickets into the gamified schema). A label swap needs a
term dictionary, not a foreign key.

## Acceptance criteria

- [x] AC1 — A `terminology_theme` preference exists per user (`mage` | `web`), stored durably.
      Grounded: no `user_settings`/`user_preferences` table exists today (checked `packages/lib/src`,
      `apps/cp/src`) — this ticket decides where it lives (new column vs. new table) and migrates it.
      Defaults to `web`.
- [x] AC2 — A toggle to change it is added to the "Me" page (`apps/cp/src/pages/profile.astro`),
      visible and changeable by every role — client, PM, TL, Dev, admin — not gated to internal staff.
- [x] AC3 — A single term dictionary maps each internal noun to its two display strings (`mage` and
      `web`), using [[T333]]'s bridge once recorded (epic ↔ raid, milestone ↔ adventure, ticket ↔
      quest) as the mapping source of truth. `RaidBoard.svelte`, `QuestBoard.svelte`,
      `CharacterSheet.svelte` and `client/MilestoneList.svelte` read their labels from this
      dictionary instead of hardcoding them as literals.
- [x] AC4 — Switching the setting changes displayed labels only — no data, FK, or table changes.
      Verified by toggling as one test user and confirming the same underlying records render under
      both labels.
- [x] AC5 — A client test account and a PM/TL/Dev test account each default to `web` on first login;
      switching either to `mage` persists across a reload and a new session.

## Definition of Done

Both themes render from the same term dictionary and the same underlying rows — no component holds
a hardcoded gamified or business-term literal once this lands. A client and a staff account each
start on `web`, and either can opt into `mage` from `profile.astro`, with the choice surviving a
fresh login. `just ac-trace-check` passes on this ticket; `TASKS.md`, this file, and the GH mirror
agree on status.
