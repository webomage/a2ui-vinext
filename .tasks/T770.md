# T770 — Fix layout-matrix `measureAtBottom()` footer-assumption drift after T754

## Summary

Live QA of webomage.com with `apps/web/scripts/layout-matrix.mjs` reported
11/11 viewport pairs "bottom-unreachable" (footer text under the footer
overlap band at max scroll). On inspection every flagged text node is the
footer's OWN text ("Webomage", "© 2026. All rights reserved.") and
`atBottom=True` wherever the scroller could scroll — the real layout is
healthy. `measureAtBottom()` (layout-matrix.mjs ~L617-654) walks text nodes
inside `.content-scroll-area` and was written for the pre-T754 shell where
the footer was fixed chrome OUTSIDE the scroller (T261 defect 3). T754 moved
the footer in-flow INSIDE `.content-scroll-area`, so the walker now starts
inside the footer and always qualifies the footer's own text as "content
under the footer band". The probe's hidden invariant (footer outside the
scroller) silently rotted in the same change that moved the footer —
verification tooling must track the layout contract it verifies.

Root-cause chain: T261 defined the unreachable-text probe for the old overlap
footer → T754 (AgDR-0054) moved the footer in-flow into the scroll area →
the probe's hidden assumption wasn't updated in the same change → false 11/11
violations on live.
