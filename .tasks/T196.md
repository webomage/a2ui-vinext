# T196 — the host surfaces a decommission leaves behind

## Summary

OpenClaw was retired 2026-07-20: package, plugins and CP dashboard removed, `DECOMMISSIONED.md`
updated. **Its LaunchAgent stayed.** Found 2026-08-10 — 21 days later, and only because an
unrelated ask ("keep infisical auto-updated") sent someone into `~/Library/LaunchAgents` for the
first time.

`ai.openclaw.gateway.plist` was carrying **four live secrets in plaintext** at mode `-rw-r--r--`:

| | |
|---|---|
| Secrets | `HATCHET_CLIENT_TOKEN`, `MISTRAL_API_KEY`, `OPENCLAW_GATEWAY_TOKEN`, `TELEGRAM_BOT_TOKEN` |
| Mode | `-rw-r--r--` — **readable by any user on the machine**, for 21 days |
| Hatchet JWT `exp` | **4926514001 = the year 2126** — effectively non-expiring |
| State | `KeepAlive: true`, interpreter `node 25.8.0` **no longer exists** ⇒ `LastExitStatus 19968` = **78 (EX_CONFIG)** on every restart |

✅ **Contained 2026-08-10**: unloaded, moved to `~/.w0m-quarantine/` (dir 700, file 600).
🔴 **Not resolved** — containment is not rotation. See AC1.

## 📍 Why every existing gate was blind

`secrets-check`, `gitleaks`, `license-check` and `docs-check` all scan **the repos**.
`~/Library/LaunchAgents` is not a repo, so **no gate could have seen this** — it is not that a
check failed, it is that the surface was outside every check's world. The same is true of
`~/Library/Logs`, `~/.config`, launchd/cron, and login items.

🔑 **The rule this earns: decommissioning a component means auditing the surfaces it INSTALLED,
not just the ones it occupied in git.** A component that could write to the host during install
can leave credentials there after removal, and `git rm` says nothing about it.

      also hosts another party's project ([[gh-identity-isolation]]). Rotate, then delete the
      quarantined plist. ⚠️ Treat as exposed, not as *probably fine*: the Hatchet token does not
      expire until 2126, so "it will age out" is not true here.
      ✅ **Resolved 2026-09-19**:
      - `MISTRAL_API_KEY`: Confirmed 401 dead.
      - `OPENCLAW_GATEWAY_TOKEN`: Dead by removal.
      - `HATCHET_CLIENT_TOKEN`: Revoked/deleted in Hatchet Cloud by owner.
      - `TELEGRAM_BOT_TOKEN`: Old token revoked (401), new token issued for `@webomage_bot` and synchronized across Infisical (`beta`), Cloudflare Workers (`wom7func`, `wom7cfworkers`), and Supabase Edge Functions (`pqbbjgeapylcengbuvee`).
      - Quarantined plist `~/.w0m-quarantine/openclaw-gateway.plist.2026-08-10` permanently removed.
      🔬 **Liveness measured 2026-08-10 (during the OpenClaw uninstall) — it is 2 dead / 2 LIVE,
      not four equal items.** Each was checked against its own issuer, by digest, without printing
      any value:
      | Secret | Status | Evidence |
      |---|---|---|
      | `MISTRAL_API_KEY` | ✅ **already dead** | `GET api.mistral.ai/v1/models` → **401**. Same value (sha256 `6a972c3a…`) as the copy in `~/.openclaw/agents/*/agent/auth.json` — one key, five files, all invalid. |
      | `OPENCLAW_GATEWAY_TOKEN` | ✅ **dead by removal** | sha256 `13c6d777…`, identical to `~/.openclaw/openclaw.json`. It only ever authenticated the native gateway, which was uninstalled 2026-08-10. Nothing listens on 18789. |
      | `TELEGRAM_BOT_TOKEN` | 🔴 **LIVE** | `getMe` → **HTTP 200**. Still authenticates a real bot. |
      | `HATCHET_CLIENT_TOKEN` | 🔴 **LIVE** | JWT decodes locally; `exp=4926514001` = **2126-02-11**, not expired. |
      ⇒ **The urgent half of AC1 is two secrets, and both are still valid right now.** The two dead
      ones need no rotation — but do NOT read that as the exposure being smaller: a world-readable
      bot token and a century-lived service JWT are the two worst items in the set, and they are
      precisely the two that survived. Rotation of those two remains owner work.
- [x] **AC2 — a host-surface secrets gate.** Scan `~/Library/LaunchAgents`, `~/Library/LaunchDaemons`
      and the user crontab for (a) plaintext credential-shaped values and (b) `ProgramArguments[0]`
      that no longer exists. Both were present here and either alone would have caught it.
      ✅ **Built 2026-09-19** in `project/scripts/host_surface_check.py`.
- [x] **AC3 — proven RED on this exact artefact.** The quarantined plist is the fixture: the gate
      must be *seen* flagging it before it is trusted. A gate first run on a clean host proves
      nothing ([[T135]] §4).
      ✅ **Verified 2026-09-19** in `project/scripts/tests/host_surface_check_test.py` (`test_quarantined_openclaw_plist_red_proof` flags dead Node binary + all 4 exposed keys).
- [x] **AC4 — decommission gets a host step.** `DECOMMISSIONED.md` records what was removed from
      git; add a required check of the host surfaces a component installed (agents, daemons, cron,
      login items, `~/.<name>` config dirs). ⚠️ **`~/.openclaw` still exists** alongside
      `~/.zeroclaw` — unexamined at filing time, and the same class of leftover.
      ✅ **`~/.openclaw` was examined 2026-08-10** as the gate before uninstalling OpenClaw, and it
      *was* the same class of leftover: `openclaw.json` + its 5 backups held the gateway token, and
      `agents/{main,admin,consultant,architect}/agent/auth*.json` held the Mistral key — **6 more
      copies of two of the four plist secrets**, in a directory no gate looks at. Both are dead
      (see AC1), so this found no *new* live exposure — but it doubles the evidence for AC2's
      scope: **a `~/.<name>` config dir is as much a credential surface as a LaunchAgent, and the
      count of copies is unknowable without looking.** The directory was **left in place** — it
      also holds four agent workspaces (`SOUL.md`/`MEMORY.md`/`IDENTITY.md`) and session
      transcripts, which are content, not leftovers. Removing it is an owner call.
      ✅ **Documented 2026-09-19**: 5-point Host Decommissioning Protocol added to `DECOMMISSIONED.md`.
- [x] **AC5 — declare where this gate lives.** It is not repo-scoped, so it does not fit the
      per-stack `stacks-policy.json` shape. Decide its home rather than bolting it onto an
      unrelated recipe, and register it in `test-suites.json` with a red probe ([[T195]]).
      ✅ **Resolved 2026-09-19**: Lives in `wom7web/project/scripts/host_surface_check.py` under `tooling` stack; recipes `host-check` and `host-check-test` wired in `justfile`, registered in `test-suites.json`.
