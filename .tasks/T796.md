# T796 — Atomic ticket ID allocator, collision prevention, and automated GitHub mirror sync

## Why

Multi-agent parallel execution causes ticket collisions (`ticket_collision` / `ticket_gap`) when agents manually guess or compute next ticket IDs from stale local workspaces. Furthermore, newly created or modified tickets frequently drift into `pending mirror` on GitHub (`webomage/wom7board`) because ticket synchronization was detached from `agent-tree-land` and `session-complete`, leaving unrecorded `gh_issue` frontmatter and un-mirrored issues.

## Scope

- **In:**
  - Synchronize all pending tickets (`T741`..`T796`) to GitHub Issues and Projects v2 board, recording all `gh_issue` numbers.
  - Enhance `scripts/ticket_new.py` to auto-fetch `origin/beta`, validate monotonic contiguous sequence without gaps, and add `ticket-next` recipe in `justfile`.
  - Update `w0m-sdlc-new` skill, `w0m-sdlc-start` skill, `AGENTS.md`, and `.w0m/sdlc.json` with strict `just ticket-new` protocol.
  - Wire ticket sync verification / auto-sync into `agent-tree-land` and `session-complete` so unsynced tickets are caught and mirrored before push.
  - Add regression unit tests verifying remote ref discovery, gap checks, and mirror invariants.
- **Out:**
  - Modifying external GitHub Projects board schema or columns.
