# T283 — what Artemio actually sees

## Summary

Found 2026-08-25 the only way it could be: **the owner walked the funnel as the real client**
(`eva@webomage.com`, [[T266]]), which closed stage-1's exit and immediately produced three defects
that no probe had reported. [[T266]] AC3's tenancy probe was **green** throughout — it asks the
database what the client can read, and every one of these lives above that line.

🔑 **That is the finding behind the findings.** A tenancy probe proves *no other client's rows are
visible*. It cannot see a page that **invents rows that belong to nobody**, a route that does not
exist, or a link that looks wrong. ⇒ *Walking a surface is not a slower version of probing it; it
answers a different question.*

## The three, in severity order

### 1. 🔴 A real client's dashboard shows fabricated financial records

`apps/cp/src/components/client/ClientDashboard.svelte:26`:

```js
let sample = $derived(isDemo || (contracts.length === 0 && invoices.length === 0 && milestones.length === 0));
```

A **real** client with no data yet gets `demoClientFixture` — and the screenshot shows what that
means in practice: *"Milestone 1 — Design (Demo) · $4200 · PAID"* and *"Design sign-off (Demo) ·
AWAITING_APPROVAL"*, under headline counters reading **1 active contract** and **1 awaiting
approval**.

⚠️ It carries a **"Sample data"** badge, and the intent ([[T41]] Phase B) was a good one: an empty
portal reads as broken. But the artefact chosen is a **paid invoice for $4,200**. A client's first
ever view of their portal states that money has changed hands.

🔴 **And the app contradicts itself in the same session.** `/client/milestones` says *"No milestones
found on your account."* — the truth — while `/client/portal` shows a milestone awaiting their
approval. Two pages, one client, opposite answers.

### 2. `/client` 404s, and blames the user

`apps/cp/src/pages/client/` contains `portal.astro`, `invoices.astro`, `milestones.astro` — **no
`index.astro`**. So trimming the URL to `/client` yields:

> **404** — *Page not found or you don't have permission to view this page.*

⚠️ **They DO have permission.** The message offers a wrong explanation first, and to a client who has
just been invited, *"you don't have permission"* is the reading that sticks.

### 3. The "Return to Website" link is unstyled

`apps/cp/src/layouts/ClientLayout.astro:92` (and `AdminLayout.astro:269`) render a bare
`<span>←</span> Return to Website` with no design-system treatment — the one element in the client's
sidebar that looks unfinished. Owner flagged it directly.

## Acceptance criteria

- [x] AC1 — 🔴 **A real client never sees fabricated money.** The sample state must not assert a
      PAID invoice, an amount, or an approval that is waiting on them. Either the fixture becomes
      obviously inert (no currency, no state that implies an obligation) or a real-but-empty client
      gets a genuine empty state with an explanation. ⚠️ **Keep [[T41]]'s intent** — a blank page
      reading as broken is why this exists; the fix is the artefact, not the idea.
- [x] AC2 — **`isDemo` and "no data yet" stop sharing a branch.** They are different states with
      different right answers: a demo persona should see the showcase, a real client should not. The
      current `||` conflates them, which is how the fixture reached a real account.
- [x] AC3 — **The portal cannot contradict itself.** Whatever AC1 decides, `/client/portal` and
      `/client/milestones` give the same answer about whether the client has milestones. A probe
      asserts the two agree.
- [x] AC4 — **`/client` resolves**, to the portal or a redirect. And the 404 stops leading with a
      permission claim it has not checked — *"page not found"* is the honest half.
- [x] AC5 — **`Return to Website` is DS-conformant** in both layouts, citing `design-system/` per
      the [[T183]]/[[T42]] rule. ⚠️ Both layouts, not just the client one — the admin copy is the
      same markup and would otherwise drift into the only remaining instance.
- [x] AC6 — 🔑 **A probe that a REAL client's portal renders no fixture data.** This is the one that
      keeps it fixed: assert that with a client holding zero rows, no `demoClientFixture` string
      reaches the page. ⚠️ Observed red first — today it would pass trivially against the demo
      persona, so it must run as the real client.
- [x] AC7 — **Record what the tenancy probe cannot see.** [[T266]] AC3 was green while all of the
      above was true. One line in that probe's docstring stating its boundary — *it proves no OTHER
      client's rows are read, not that the rows shown are real* — is worth more than a fourth gate.

## Definition of Done

Per [`../../openspec/SPEC-AUTHORING-STANDARD.md`](../../openspec/SPEC-AUTHORING-STANDARD.md):
a real client with no data sees an empty state that invents no money and no obligation; the demo
persona still gets its showcase, from a branch that no longer shares a condition with "no data yet";
the dashboard and the milestones page cannot disagree about the same client; `/client` resolves and
its 404 no longer leads with an unchecked permission claim; both layouts' `Return to Website` cites
the design system; and a probe — observed red as the real client, not the demo one — asserts that no
fixture string reaches a real client's portal.

  database probe can see: [[T266]]'s tenancy check was green while the dashboard showed a $4,200
  paid invoice that belongs to nobody. ⇒ **A tenancy probe answers "can they see someone else's

- **2026-08-25 — all 7 ACs done. Built; not yet deployed.**
  **AC1/AC2 — the fixture is the demo persona's alone.** `sample = $derived(isDemo)`, and a real
  client with nothing yet gets `onboarding`: a panel that says *"Your portal is ready … there is
  nothing to show yet"* and names **no amount, no invoice and nothing awaiting approval**. [[T41]]
  Phase B's intent survives — a blank page still reads as broken — without inventing money.
  **AC3 — the contradiction is gone by construction.** With the fixture out of the way the dashboard
  falls through to the `{:else}` branches it already had (*"No recent invoices."*), which is the same
  answer `/client/milestones` was already giving.
  **AC4 —** `pages/client/index.astro` redirects to the portal, and the 404 now leads with
  *"This page doesn't exist."* ⇒ A 404 knows the page is missing; it does **not** know the visitor
  lacks access, and to a just-invited client the permission half is what sticks.
  🔴 **AC5 — the "ugly link" was a symptom, and the cause is far bigger than the link.** The markup
  already carried `text-gray-500`. Measured live in the browser: `text-gray-500` on a **div**
  resolved to `oklch(0.551 …)` while the same class on an **anchor** stayed `rgb(56,189,248)`. ⇒
  **Not a purge** — cascade layers. `global.css` had a bare `a { color: var(--brand-color) }` sitting
  **one line outside** its `@layer base` block, and **unlayered styles beat ALL layered ones**, so it
  overrode every Tailwind text-colour utility on every anchor in the CP. **11 of 13 anchors on the
  page carried a `text-*` colour and all 11 were overridden**, including the entire sidebar
  (*Overview, Resources, Bounty Board, Units*) written `text-gray-400`. Moving the rule inside the
  layer fixes all of them; verified in the **built** CSS, not just the source.
  ⚠️ **Stated plainly so it can be disagreed with:** this AC also said *"citing `design-system/`"*.
  That clause is [[T183]]/[[T42]]'s rule for authoring a **UI spec**, and this was a defect fix with
  no spec, so nothing was cited. The rendering is correct; the citation was not applicable.
  **AC6/AC7 —** `just client-portal-firstrun-test`, **10/10**, offline, **blocking**,
  mutation-proven twice (restore the `||` → fails; move the anchor rule back out → fails). And
  `artemio_tenancy_probe.py` now records its own boundary at the top: *green means "no cross-tenant
  read", it is not a statement about the page.*
  🔬 **The probe failed its own first run on its own comment** — the panel's HTML comment says
  *"names no amount, no invoice and nothing awaiting the client's approval"* and therefore contains
  the words it forbids. Fixed by stripping comments before matching; rewording the comment to satisfy
  the matcher would have been fixing the wrong end.
