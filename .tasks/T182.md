also asserts required ∪ optional ∪ excluded **== the contract exactly**, so no key can be quietly
dropped, and rejects any required key whose gate fails open.

### 🔴 The method correction — three false-positive classes, each caught by a red probe

I attributed gates by grep three times and was wrong three times. The tool now encodes each lesson:

1. **A quoted word is not a read.** `project` looked like the *best*-gated key in the contract —
   a quoted-word scan reported **19 readers**, `sdlc_doctor.py` alone appearing to read it 5×.
   **Every one is the `project/` DIRECTORY PATH** (`CANONICAL / "project" / "tools-policy.json"`)
   or a table header (`f"{'project':10}"`). ⇒ `project` has **no** reader and is **excluded**.
2. **A dict-read of its own output is not a read of the declaration.** `state_doctor`'s
   `data["tickets"]` is the dict it just built; `sync_github`'s is its hash cache.
3. **A dict-read of a *different* json is not a read of the declaration.** `discovery.py:406`
   reads a **package.json**'s `project`; `repo_hygiene.py:569` reads **hygiene-policy.json**'s
   `root`; `discovery.py:262` reads **stacks-policy.json**'s `commands`.

⇒ **Every tier in the profile carries a `file:line` I opened and read.** The gate verifies the
*necessary* condition mechanically; the recorded line is what makes it sufficient. 🔑 This is the
estate's *never match on a name the inspected thing supplies* trap in a new costume — the string
was real every time; the reading was not.

🔴 **`.w0m/sdlc.json` is largely a POINTER file.** Most gates read a policy file it references
(`stacks-policy.json`, `hygiene-policy.json`, `deps-policy.json`) rather than the declaration
itself. That is why `commands` is excluded despite being genuinely enforced — it is enforced
*through* `stacks`, which is required, and requiring both would declare the same thing twice and
gate it once.

### 🔴 `$schema` is present-and-dangling in w0m AND Artemio

Both declare `"$schema": "./sdlc.schema.json"`. **That file does not exist in either.** So the
baseline's *1945 ❌ / Artemio ✅* contrast is misleading: **nothing has ever validated Artemio's
declaration either** — it just fails the check in a way a presence test cannot see. Same shape as
the retracted 11-byte `CLAUDE.md`. The gate therefore checks **resolution**, not presence, and
reports all three; `--enforce` blocks.

### ⚠️ Correction — the read-only verification was itself a non-firing probe

The AC1 note above claimed *"verified after the run: zero files modified in either"*. **The
command that produced that zero was `find … -newermt '-3 hours'`, which this host's `find` (bfs)
rejects as an invalid timestamp** — and its stderr was routed to `/dev/null`, so an error printed
`0` and the `0` was read as cleanliness. 🔑 **A probe that does not fire is not evidence** — the
estate's own recorded trap, committed in the session that was applying it, and the wrong method
reached a commit message.

**Re-verified with absolute timestamps 2026-08-09, and the conclusion holds:**
- **Artemio — zero files modified since 10:00.** `.w0m/sdlc.json` last touched **2026-07-23**.
- **1945** — many files modified today, all site content (`menu-site/`, `united-site/`,
  `data/menu.json`, `.w0m/BOARD.md`, `.w0m/tickets`) by the **parallel actor** known to work this
  repo; **`.w0m/sdlc.json` last touched 2026-08-04**, `skills.json`/`skills.lock.json` 2026-07-26.
  None of it is a file any read-only inventory can produce.

⇒ AC6 holds on evidence rather than on a broken check. ⚠️ **Relative `-newermt` is not portable
here** — use an absolute timestamp, and never send a verification's stderr to `/dev/null`.

## 🔑 Design principle: import is a PROFILE, not the estate contract

The estate's 23 keys encode w0m's own needs. A client does not necessarily need `iac`, `versioning`
or `mcp`. ⇒ **Define a `client` profile — the minimum that makes a project governable — and make the
remainder explicitly optional.** 🔴 Copying all 23 keys would produce declarations nothing enforces,
which is this estate's most-repeated defect ([[T169]] vacuous green, [[T161]] AC3's non-firing tier,
[[T131]] unmanaged skills). **A key in the profile must have a gate behind it or it does not belong
in the profile.**

## 🪜 Step-by-step path flow (the deliverable)

**Phase 0 — Boundary and consent.** Client repos are **owner-write-only**; every write needs explicit
say-so (standing rule, honoured throughout this ticket's research). Record per client: who may
commit, which branch, and whether the mirror to GitHub is wanted. ⚠️ 1945 is on `beta`, Artemio on
`main` — the path must not assume a branch name.

**Phase 1 — Inventory (read-only).** Run a scripted baseline per project against the contract:
which keys, which surfaces, which skills, which gates, byte sizes of agent-maintained files. Output
is a diff, not a judgement. 🔑 This phase is already prototyped by the table above — make it a
recipe so it is repeatable rather than a one-off measurement.

**Phase 2 — Define the `client` profile.** The minimum key set + the gate behind each. Ship it as a
schema so `$schema` validation is meaningful. **Exit criterion: every key in the profile names its
enforcing gate.**

**Phase 3 — Converge the schema.** Add `$schema` to 1945; map or retire its 5 divergent keys
(`version`, `description`, `runner`, `branches`, `skills`) — `skills` in particular may duplicate
`skills.json`. **Do not silently drop a key that something reads**; check first.

**Phase 4 — Wire the governance surfaces.** `state_surface` + retention (this is [[T177]]'s cure),
`skills.json` + `skills.lock.json` for Artemio's 33 ungoverned skills, `preflight`. Each lands with
its gate, in the same commit.

**Phase 5 — Bound the memory surfaces.** Propagate [[T174]]'s rotation to 1945's 545 KB of
`STATE`/`LESSONS`/`SESSIONS`. ⚠️ **Rotation is lossy if done wrong** — T174 required a disposition
record covering every section, and that discipline transfers.

**Phase 6 — Fill Artemio's `CLAUDE.md`.** 11 bytes is a presence-check pass and a content failure.

**Phase 7 — Prove it with a gate, not a checklist.** A recipe that answers *imported / not imported*
per project and **fails on a missing profile key**. Reuse [[T130]]'s `just discovery --enforce`
rather than inventing a second enforcement path.

**Phase 8 — Run it twice, then a third time cold.** 🔑 **The path is only proven when the second
client needs no bespoke step**, and the acceptance test is a *third* project onboarded from the
written path alone.
