# T486 — Bring the stale admin/web Gauge specs in line with the current UI, or retire each with a reason

## Summary

Split from [[T478]] (owner, 2026-09-29: close T478 at "environment fixed, failures triaged"; leftover scope becomes
its own ticket). T478 run 4 (150 specs, local stack, guard on): 291/442 scenarios passed, 151 failed, 34 min.

## Measured (T478 run 4/5)

Most of the 151 failures are specs written for a UI that has since changed, not environment faults (failure
screenshots now show the page): 51 scenarios in 33 specs fail on "page element not found", 21 on API status,
8 on wrong 403/404/redirect. Examples: `admin_clients_crud` uses test ids `new-client-btn`, `client-name-input`,
`client-contact-input`, `save-client-btn`, which exist nowhere in `apps/` or `packages/` (the page is "Guild Patrons"
with "New Patron"); `admin_contracts` clicks `new-contract-btn` on a page of 98 Upwork-synced contracts with no
create action. 4 of the 17 test ids the specs use are gone. 6 scenarios in 2 specs still name the live functions URL
in their step text (`005-contact-submit-api`, `010-contact-secure`).

## Acceptance criteria

- [ ] AC1 — **Every failing spec is classified** in one table (spec, scenario, cause: stale UI / stale id / product
  defect / live-only), from a fresh full local run, replacing the measured counts above.
- [ ] AC2 — **Each stale spec is updated to the current UI or retired**, and a retirement names its reason in the
  spec and in `spec-reality` output; nothing is deleted silently.
- [ ] AC3 — **Product defects found are filed or fixed**, not papered over in the spec.
- [ ] AC4 — **Steps stop naming live URLs** (`005`, `010`, and the 43 specs `e2e-local` still excludes): built from
  `SUPABASE()`/`fnUrl()`, so they run locally.
- [ ] AC5 — **A full local run passes at least 95% of scenarios**, with the remainder each tagged and explained.
