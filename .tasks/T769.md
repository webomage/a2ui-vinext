# T769 — HOTFIX: T764 dropped the named-input import in AuthForm.astro; every login page renders empty

## Summary

Release 2026.11.18-1794983261 (root 9b3a649, w0m-web 9337fa631) shipped
T764's `AuthForm.astro` refactor, which replaced
`import { Input as InputComponent } from "./input/index"` with
`import InputOtp from "./input-otp/input-otp.svelte"` but left two
`<InputComponent>` usages (email field line 68, password field line 92).
`login.astro` is `prerender: false`, so the build never executed the page;
first SSR render in production throws
`ReferenceError: InputComponent is not defined` (captured via
`wrangler tail webomage-cp`). All three apps (web, cp, me) return
HTTP 200 with a 0-byte body on `/login` — login is down estate-wide.
`/forgot-password` (no AuthForm) still renders, and
`POST /api/auth/signin` works, proving GoTrue is healthy.

## Acceptance Criteria

- AC1: `packages/ui/src/lib/components/ui/AuthForm.astro` restores
  `import { Input as InputComponent } from "./input/index";` alongside the
  T764 `InputOtp` import; email/password fields render again.
- AC2: Regression gate: a test or build-time prerender check catches an
  undefined-component reference inside `@webomage/ui` auth components
  (grep-level AST check acceptable for a hotfix; caught-at-build, not
  caught-in-prod).
- AC3: Post-deploy verification: `GET https://webomage.com/login`,
  `https://cp.webomage.com/login`, `https://me.webomage.com/login` each
  return 200 with non-empty HTML containing the sign-in form; login E2E
  successful (owner browser check).

## Status

- 2026-11-18: Diagnosed live (wrangler tail). Fix applied to
  `packages/ui/src/lib/components/ui/AuthForm.astro` (restore Input
  import), local cp rebuild green, awaiting owner Touch ID deploy +
  live verification. Regression gate (AC2) to follow in-tree.
