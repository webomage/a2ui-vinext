# T161 — Slash-command surface for `just`

## Summary

Owner ask 2026-08-02: *"I want to be able to call `just tasks` with slash command and we can
actually look into creating universal slash command wrapper to call our just commands as well."*

**The gap is real.** `just` is one of the two standard SDLC interfaces (`project/tools-policy.json`
→ `required: true`), it carries **206 recipes**, and it has **no slash-command surface at all**.
The only commands installed are the 10 `opsx/*` files, which are OpenSpec CLI output, not ours.

Related but distinct finding, surfaced in the same conversation: **`w0m-sdlc-start` answers
*"what should I work on"* by hand-reading `TASKS.md`'s NOW/NEXT sections and never calls the
ranking tool.** That means it sees **40 of 119** open tickets (NOW 23 + NEXT 17) — the remaining
79 live in nine other sections it does not read — and it presents them unranked, so the score, the
AC progress and the hot-vs-sdlc disagreement never reach the decision. **T99 tops both ranked
boards and is in none of the sections that skill reads.** Tracked here as AC5.

**Design of record — `just --show` is the safety primitive, not an allowlist.** A wrapper over 206
recipes must not run `deploy-all` or `db-migrate` as casually as `tasks`. The obvious design is a
hand-maintained safe-recipe list; it is the wrong one, because it rots silently against a justfile
that gains recipes every week, and this estate's recurring defect is exactly *"a check that only
looks where it already knows to look."* Instead the wrapper runs **`just --show <recipe>`** first
— ground truth read from the justfile per call, cannot go stale, and errors loudly on an unknown
name so a typo fails closed instead of resolving to a neighbour.
