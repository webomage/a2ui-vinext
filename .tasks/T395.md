# T395 — Migrate estate-universal config/tooling from wom7web into @wom workspace root

## Summary

Filed 2026-09-18 per owner directive: physically relocate content that is genuinely
**estate-universal** (applies across all 8 stacks, not specific to the `web` app) out of
`wom7web` and into the `@wom` workspace root, so `wom7web` holds web-app content and shared
things live in shared space — a real move, not just documenting the existing "canonical
conventions live in `../wom7web/AGENTS.md`" pointer pattern ([[T192]]) in place.

Starting candidates, all currently living inside `wom7web` despite governing every stack:
`project/stacks-policy.json` ([[T130]] — per-stack tech/tools registry, read by
`project/scripts/discovery.py` for `web`/`worker`/`edge`/`skills`/`cf`/`mlx`/`ext`/`sec`),
`project/tools-policy.json` (host CLI tool contract), `project/deps-policy.json` (npm version
floors, pinned across repos). `docs/DECISIONS.md` / `docs/decisions/` / AgDR is explicitly
**out of scope** here — [[T392]] already covers making that estate-wide, and duplicating that
scope in two tickets would just create two plans for the same file.

This is a scoping/survey-and-move ticket, not a mass relocation: not everything that mentions
multiple repos is "universal" (e.g. `.w0m/sdlc.json` itself is wom7web-rooted config that
*describes* the estate but is not itself estate-shared state), and getting the keep/move line
wrong in either direction either leaves `wom7web` cluttered or breaks a gate that resolves a
path relative to `wom7web`'s own root.

## Acceptance criteria

- [x] AC1 — Survey candidates and record a keep/move decision with a one-line reason each,
      starting from `stacks-policy.json` / `tools-policy.json` / `deps-policy.json`, checked
      against: does this file's content apply identically regardless of which stack/repo reads
      it, and does relocating it avoid breaking a path any gate assumes relative to `wom7web`.
- [x] AC2 — For every file the survey marks MOVE: relocate it to the `@wom` root as a real
      move (removed from `wom7web`, added at root — not a duplicated copy), and repoint every
      reader (`discovery.py`, `tools_check.py`, `deps_check.py`, any `just` recipe, and the
      tables in `wom7web/AGENTS.md` / `wom7web/CLAUDE.md` / `@wom/AGENTS.md` that cite the old
      path) at the new location. No stale pointer left claiming ownership `wom7web` no longer has.
- [x] AC3 — `just discovery`, `just discovery --enforce`, and the tools/deps-check gates (plus
      their `-test` regression suites) still pass from their normal invocation point
      (`wom7api`'s justfile) after the move — proves the relocation didn't silently break the
      gates that read these files, rather than just moving files and hoping.
- [x] AC4 — `@wom/AGENTS.md`'s "Fast Project Info & Indexed Data References" table (which today
      implicitly points into `wom7web` for stacks/tasks/debt/decisions) is corrected to state,
      per row, whether the target now lives at the workspace root or still inside `wom7web` —
      so the table stops silently assuming one root for everything it lists.
- [x] AC5 — Explicitly confirmed out of scope: `docs/DECISIONS.md` / `docs/decisions/` / AgDR
      estate-wide reach is [[T392]]'s scope. This ticket does not touch it, to avoid two tickets
      independently planning the same relocation.
