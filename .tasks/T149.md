# T149 — w0m toolset consolidation

## Summary

**Owner decision, 2026-07-26:** *"let's make w0m toolset consolidation top P0 task"*, following
*"w0m skills and tools should be a complete SDLC and management toolset with native skills install
features and detecting any custom skills installed"*.

This is the **top-level epic** for making the w0m skills store, the task/queue surfaces, the SDLC
gates and the MCP transport into **one** toolset rather than several adjacent ones. The measured
baseline is `docs/W0M-TOOLSET-CONSOLIDATION-2026-07-26.md` — read that first; it is the ground truth
this ticket is scoped against, and every figure in it carries a reproduce-command.

⚠️ **A note on the P0.** In this queue P0 has so far meant a production or security emergency
([[T99]] credential hardening, [[T120]] Safe Browsing). This ticket is P0 by **explicit owner
priority**, not because something is on fire. Both readings of P0 now coexist — do not infer urgency
of the security kind from this row, and do not let it displace T99/T120 in triage.

## Why an epic and not more tickets

The toolset is already substantial: **40** canonical skills, **10** `w0m-sdlc-*` gates, **171** `just`
recipes, **8** declared stacks (28/28 registry tests), a 9-stage lifecycle, a TS skills manager with a
manifest + lockfile. Nothing here is missing-from-scratch.

What is missing is **coherence**: the pieces do not know about each other, and their coverage gaps all
share one shape.
