# T404 — Harden the deploy path: an unprovisioned app bundle must not reach production

## Summary

On **2026-09-19** `webomage.com` and `cp.webomage.com` both served 500s with
`Middleware Error: Supabase environment variables are missing`. Nothing was wrong with the code, the
Workers, or the secret store. An agent ran `pnpm --filter web build` **without**
`infisical run --env=beta` and then `wrangler deploy` by hand from `apps/web/dist/server`,
bypassing `just deploy-web` — which exists precisely because it wraps the build in `infisical run`.

`PUBLIC_SUPABASE_URL` / `PUBLIC_SUPABASE_ANON_KEY` are read through `import.meta.env`, which Vite
replaces with a **literal at build time**. A build with an empty environment inlines `undefined`,
and nothing at runtime can repair it: all four app Workers are `compatibility_date 2024-11-18` +
`nodejs_compat`, which predates Workers populating `process.env` from bindings. So the
`|| process.env.X` fallback sitting beside every read had never once executed — 🔬 proven, not
reasoned: the `webomage` Worker **had** the secret set, the deployed code **did** read
`process.env.PUBLIC_SUPABASE_URL`, and it still threw.

That fallback was not neutral. It is what sent the diagnosis to Cloudflare's secret store — where
everything was correctly configured — instead of to the build command. This ticket makes the build
the single source of truth, **proves** it in the artifact before `wrangler` sees it, and deletes the
safety net that was never one ([[AgDR-0023]]).

## The diagnostic reads INVERTED

    grep -rl "Supabase environment variables are missing" apps/<app>/dist/server/

* **a HIT means the build is BROKEN** — the throw branch survived, so `!url || !key` was not
  foldable, so no literal was inlined.
* **no hit means the build is GOOD** — the literals folded the condition to `false` and the minifier
  dropped the dead branch, taking the message with it.

Every instinct says a missing-config error string in a bundle is harmless boilerplate. Here its
presence **is** the defect. That inversion is why this lives in a gate with a docstring rather than
in somebody's head.

## Acceptance criteria

- [x] AC1 — `just deploy-web` · `deploy-cp` · `deploy-join` · `deploy-job` each run
      `_assert-provisioned <app>` **after** the build and **before** `wrangler deploy`, and the
      deploy stops with a named reason when the bundle is unprovisioned. Logic in Python
      (`project/scripts/build_provisioning_gate.py`), not inline shell.
      🧪 Proven end to end 2026-09-19 on `apps/job`, both directions: built bare → **BLOCKED** with
      all three signals (sentinel present, neither literal inlined); rebuilt under `infisical run`
      → `[OK]`.
- [x] AC2 — the gate fails closed and cannot go vacuous. **13 red probes**
      (`project/scripts/tests/test_build_provisioning_gate.py`), proven RED by mutation — stubbing
      the sentinel scan and the missing-bundle branch turns 4 of them red. Covers: a missing
      `dist/server` and an empty one are **blocked, not passed** (unmeasurable ≠ clean); the
      sentinel vanishing from the SOURCE is reported as `GATE IS VACUOUS`; an empty-string secret
      counts as missing; and no failure message ever prints a value.
- [x] AC3 — the `|| process.env.X` question decided and recorded: [[AgDR-0023]] — **delete it**, and
      `docs/DECISIONS.md` regenerated via `just decisions`. The rejected options are named, incl.
      why making it real (`cloudflare:workers` env, or raising `compatibility_date`) is worse: these
      are `PUBLIC_*` values that are **also** inlined into the CLIENT bundle, so a server-side
      runtime read half-fixes an unprovisioned build and converts a loud 500 into a browser-only
      failure nobody sees.
- [x] AC4 — all **23** occurrences of `import.meta.env.X || process.env.X` removed across **14**
      worker-bundled files; `pnpm typecheck` clean (web · cp · demo · job, 0 errors); a provisioned
      build still inlines both literals (re-proved on `apps/job` after the change).
- [x] AC5 — the **11** sole-source worker-bundled `process.env` reads found by the survey are
      dispositioned **one by one**:
      - `packages/lib/src/supabase.ts:19-21`: Removed dead `urlFromProcess` and `keyFromProcess`.
      - `packages/lib/src/supabase-clients.ts:31-36`: Removed dead `urlFromProcess` and `typeof process` branch from `envVar`.
      - `packages/lib/src/auth/handlers.ts:490-493`: Removed dead `process.env.PUBLIC_SUPABASE_URL || process.env.SUPABASE_URL` in `handleSignOut`.
      - `packages/lib/src/auth/middleware.ts:281`: Removed inert `process.env.PORTAL_IDENTITY_BARRIER_ENABLED === "true"`.
      - `apps/cp/src/pages/api/bug-report.ts:84,86`: Switched to `import.meta.env.TELEGRAM_ADMIN_CHAT_ID` and `import.meta.env.SUPABASE_SERVICE_ROLE_KEY`.
      - `packages/kyc/src/mexico/inegi.ts`: Replaced with `(import.meta.env as any)?.INEGI_DENUE_API_TOKEN`.
      - `packages/lib/src/auth/signout.spec.ts:107`: Updated test mock to `import.meta.env.PUBLIC_SUPABASE_URL`.
- [x] AC6 — a repeatable gate stops the pattern returning: `project/scripts/worker_env_gate.py` with

**2026-09-19 — AC1-AC4 built and verified; AC5-AC8 filed from the survey.**

The survey (item 3 of the owner's brief) found the fallback shape was the *smaller* half of the
problem. Every `process.env` read in `apps/` + `packages/` classified by the runtime it executes in:

| runtime | shape | count | verdict |
|---|---|---|---|
| worker-bundled | fallback after `import.meta.env` | 23 | ✅ removed (AC4) |
| worker-bundled | **sole source** | 11 | 🔴 dead reads — AC5 |
| worker-bundled | `typeof`-guarded | 6 | 🔴 silently dead — AC8 |
| worker-bundled | build-time toggle (`NODE_PHASE`) | 2 | ✅ benign, intended false at runtime |
| Node (configs, `apps/*/scripts/*.mjs`, Playwright) | sole source / toggle | 32 | ✅ correct, leave alone |

🔬 **A measurement trap, caught on my own sweep.** The first pass selected files with
`grep -E 'import\.meta\.env\.\w+\s*\|\|\s*process\.env'` and rewrote 18 occurrences. grep matches
**LINES**, so four multi-line pairs (`apps/cp/src/pages/business/{contracts,proposals}/index.astro`,
`content/edit/new.astro`) were never offered to the rewriter. The file LIST was the limiter, not the
regex — and the sweep would have reported "done" over an incomplete job. Re-run with a file list
built from `grep -F process.env`, which is shape-agnostic: 23 total.

🔴 **A second finding the guard produced rather than the sweep.** The rewriter refused any pair whose
two sides name different variables, and that refusal surfaced
`import.meta.env.SERVICE_ROLE_KEY || process.env.SUPABASE_SERVICE_ROLE_KEY` in two CP content
editors — a 4-alternative chain ending in `|| import.meta.env.PUBLIC_SUPABASE_ANON_KEY`, i.e. a
silent fall-through from service-role to anon. Only the inert `process.env` link was removed; the
rest is AC5/AC8 territory and needs a person.

⚠️ **Found in passing, NOT in scope here:** `apps/join` is absent from `pnpm typecheck` — the script
runs `web && cp && demo && job` only (measured 2026-09-19). `join` therefore has no type gate at
all. Filed separately rather than smuggled into this diff.
