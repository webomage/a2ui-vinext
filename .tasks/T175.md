# T175 — `get-admin-metrics` compares the service key with `!==`

## Summary

`wom7api/supabase/functions/get-admin-metrics/index.ts:21` gates the function on

```ts
if (!serviceKey || xServiceKey !== serviceKey) {
```

`!==` on a secret is **not constant-time**, so comparison latency varies with how many leading bytes
match. `_shared/auth.ts` already exports `constantTimeEqual`, which is what the rest of the estate
uses; this call site never adopted it.

**Severity is P2, and the honest reason is the exploit path, not the pattern.** A remote timing
oracle across the public internet against an edge function is noisy and slow, so this is hardening
rather than an open door. It is filed because the fix is three lines and the helper already exists —
not because exploitation is likely.

🔴 **How it survived: it was flagged inside a ticket that then closed.** [[T124]] recorded it as
*"🟡 `get-admin-metrics` compares the service key with `!==` — a non-constant-time comparison"* and
T124's status is now `done`. [[T126]] mentions it in passing (*"the non-constant-time smell already
flagged on `get-admin-metrics`"*) and also closed. So the finding was **noted twice and owned by
nobody**, and the only standing reminder that it was still open was a line in a dated `STATE.md`
gotcha block:

> **Still genuinely open (security, unticketed):** `get-upwork-status` (ungated Upwork read) +
> `get-admin-metrics` (`!==` non-constant-time key compare — reuse `_shared/auth.ts`
> `constantTimeEqual`).

**This ticket exists because [[T174]] tried to archive that block.** The disposition record's rule —
*an unaccounted section is a hard failure, never a default-archive* — is what forced the check, and
the check found a real live gap. That is the rule earning its keep on its first use.
