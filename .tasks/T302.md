# T302 — an estate gate may not depend on a client workspace

## Why

Owner 2026-09-02: *"in general gates for clients projects should not run in w0m workspace."*

Said after two rows — `vm-image` and `vm-disk` — were added to `preflight.py` measuring the
**BridgeRoad** VM image and disk. They reached into `_proj/bridgeroad`, which is wrong on three
counts:

1. it is not w0m's health;
2. the row goes red, or "skipped", for reasons about **someone else's directory** — a client repo
   that may be absent, moved, or deliberately not checked out;
3. a preflight that reports on a client is a preflight that can no longer be read as *"is the estate
   fine"*. The signal that matters gets diluted by one that belongs elsewhere.

Those rows are gone, and the checks live in `bridgeroad-w0m` beside the toolchain they measure
(`just vm-staleness` / `just vm-retention`) — where a client's facts belong.

## Current state — measured 2026-09-02, not assumed

- `preflight.py` is **compliant**. It already distinguishes client mode from estate mode and states
  that "Estate-global checks (graph currency, host tooling) are NOT run for a client". Its only
  remaining `_proj` reference is the comment recording why the two rows were removed.
- `client_inventory.py` **does** emit errors about client-side state ("declared root does not exist",
  "repo … is NOT a git repo root"). That is acceptable and deliberate: it is an inventory **of the
  registry**, invoked explicitly via `just`, not a gate wired into preflight or a hook. It answers
  "is the registry true?", which is w0m's own question.
- So there is no live violation today. What is missing is that the rule is held **only by a comment
  in the file that last broke it**, which will not survive the next person adding a useful-looking row.

## Acceptance criteria

- [x] **AC1** — the principle is written where gate authors will meet it (AGENTS.md / the preflight
      module docstring), stated as a rule with its reasoning, not as an incident note.
- [x] **AC2** — a check fails if any preflight row's command references a path outside the estate —
      `_proj/`, a `clients-policy.json` root, or any absolute path under a client workspace.
- [x] **AC3** — AC2 is red-tested by adding a row that reaches into `_proj/bridgeroad` and watching it
      block, then removing it. A guard nobody has seen fail is not a guard.
- [x] **AC4** — the inverse is stated too: client-side checks belong in the client's own `-w0m`
      workspace, reachable by the same recipe names, so moving a check out of preflight is a
      relocation and not a deletion.

## Status

- **2026-10-22 — Completed (`T302`)**:
  - **AC1 & AC4**: Documented the standing estate-vs-client gate boundary rule and its complementary relocation rule (`<client>-w0m` under the same `just` recipe names) in `@wom/AGENTS.md` and `wom7web/project/scripts/preflight.py` module docstring.
  - **AC2**: Implemented `check_estate_preflight_client_boundary()` and `check_boundary()` (plus `--check-client-boundary`) in `wom7web/project/scripts/preflight.py`, wired into both `FAST_CHECKS` and `run_full()`. Fails closed if any `FULL_CHILDREN` row references `_proj/`, `!proj/`, `_self/`, a non-`w0m` `root` from `project/clients-policy.json`, or an absolute path under a client workspace.
  - **AC3**: Verified with red probes in `wom7web/project/scripts/tests/test_preflight_client_boundary.py` (`5/5` passed) and `wom7web/project/scripts/preflight_test.py` (`14/14` passed), confirming a `vm-image` row reaching into `_proj/bridgeroad` is blocked and live `FULL_CHILDREN` (`5/5` rows) passes.

## Definition of Done

The rule that an estate gate may not depend on a client workspace is written where someone adding a
gate will encounter it, with the reasoning that produced it, and not only in the file that last
violated it. A check enforces the boundary mechanically: a preflight row whose command reaches into
`_proj/`, a registry-declared client root, or an absolute path under a client workspace fails, and
that check has been watched blocking a row deliberately pointed at `_proj/bridgeroad` before being
removed again. The complementary half is equally explicit — a client's own checks live in its `-w0m`
workspace under the same recipe names — so a check moved out of preflight is visibly relocated and
cannot be mistaken for one that was dropped. Reading a green preflight tells you the estate is fine
and nothing about anyone else's directory.

## Notes

The general shape is the one this estate keeps rediscovering: **a measurement is only meaningful
where its subject lives.** Same root as the `authz-probe` trap (a gate labelled `dev` measuring
production) and the workspace-mode gap — the label and the subject drifted apart.
