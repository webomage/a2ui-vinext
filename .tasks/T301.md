# T301 — make a declared `$schema` mean something

## Why

Owner 2026-09-02, while `clients-policy.json` was being extended with a 33-key tier contract:
*"we need to write down this also"* — the file declares a `$schema` and **nothing reads it**.

Measured the same day (`grep` for each schema filename across `*.py`/`*.ts`/`*.sh`/`justfile`,
excluding `.pyc`, with a positive control to prove the search was not vacuous):

| schema | referenced in code | file present |
|---|---|---|
| `client-profile.schema.json` | 1 | yes — **actually validated**, `client_profile_check.py:135` |
| `clients-policy.schema.json` | 0 | yes — authored, never loaded |
| `skills-policy.schema.json` | 0 | yes — authored, never loaded |
| `hygiene-policy.schema.json` | 0 | **missing** |
| `authz-allowlist.schema.json` | 0 | **missing** |
| `sdlc.schema.json` | 1 | **missing** — dangling reference |

One of six is enforced. Two schemas were written and wired to nothing. Three are named by a policy
file that has no schema to be checked against.

This is the estate's own recurring defect applied to itself: the capability exists, the declaration
exists, and nothing connects them. `clients-policy.json` is the worst case, because it is the file
that decides which projects are governed and what a tier obliges — a typo in a tier key silently
un-governs a client, and today the only thing that would notice is a human reading the diff.

`client_profile_check.py` already knows part of this: its own docstring says *"Presence is not
validation: w0m's and Artemio's both point at `./sdlc.schema.json`, which does not exist."* It checks
that references **resolve**, and stops there. Resolution is not validation either — a schema that
exists and is never applied fails exactly like one that is missing.

## Acceptance criteria

- [x] **AC1** — `client_inventory.py` validates the registry against the schema its own `$schema`
      names, **before** reading anything out of it, and `just client-inventory` now fails on a bad
      registry.

      🔑 The schema was not missing — it was 163 lines of draft-07 and, measured, still validated the
      live file with **0 errors**. That is the trap: it looked healthy. Probing it with mutations
      showed the `projects` half caught all five thrown at it while the `tiers` half — the part T265
      had just added, carrying the 33-key contract — caught **none**: an unknown tier name, a tier
      that was a bare string, a missing `definition`, a null surface, and an emptied
      `contract_surfaces` all passed.

      The `tiers` half is now written: `surface` (`status` ∈ in|out, plus a required non-empty
      `reason`), `surface_map` (non-empty, lowercase keys), and `tier`. Tier names `$ref` the **same**
      definition the `role` property uses, so a tier cannot be defined for a role that does not exist
      and a new role cannot arrive with its tier unschema'd. An `allOf` requires that a tier which is
      **used** is also **defined**.

      ⚠️ draft-07 **ignores siblings of `$ref`**, so making `role` a `$ref` would have silently
      dropped its long description; it was moved inside the definition first.

      Verified by 16 mutations, not by reading: 5 previously-caught stayed caught (no regression from
      the `$ref` refactor), 5 previously-missed now caught, 6 newly expressible caught, and a control
      — the real terse reason `"Tools."` — correctly does **not** fire, because the bar rejects
      unexplained decisions and not short ones. End to end, a tier-key typo now prints
      `does not validate at tiers: 'half-mananged' is not valid…` and blocks. A missing `jsonschema`
      is reported as **unmeasurable and fails closed**, verified by blocking the import.
- [x] **AC2** — `skills_catalogue.py` validates the policy it loads, and a bad policy stops the
      catalogue instead of being built from.

      Unlike AC1 this needed **no schema authoring**: probed with 10 mutations, `skills-policy.schema.json`
      caught all 10 — including the mandatory `reason` on an override (`minLength: 30`), the
      `<project>:<skill>` key format, and extra keys inside an override — with the control correctly
      silent. It was complete and loaded by nothing, which is the same as absent.

      The validator is now **one shared module** (`project/scripts/schema_check.py`) rather than a
      second copy: two call sites is where a copied twenty lines starts to drift, and the copy that
      drifts is the one that stops catching things. AC1's local helper was replaced by it, and the
      clients-policy red test was re-run afterwards to prove the refactor did not regress it.

      🔴 **It broke four tests and the fix was NOT to exempt the fixtures.** `skills-policy.json`
      declares a RELATIVE `$schema`, correct only where that file lives; the tests copy the policy
      into a temp dir, where the ref dangles, so validation stopped the tool before any catalogue
      logic ran (14/18 → 10/18). `variant()` now re-points `$schema` on copy, which keeps fixtures
      held to the same schema as the real file. Back to 14/18, and the remaining four failures were
      diffed against a stashed baseline and are byte-identical to it — **pre-existing, not mine**.
- [ ] **AC3** — `hygiene-policy.json` and `authz-allowlist.jsonc` either gain the schema they name or
      stop naming one. A declared-but-absent schema is a lie either way.
- [ ] **AC4** — `sdlc.schema.json` is written, or every `.w0m/sdlc.json` stops pointing at it. This is
      estate-wide, not just w0m's copy — Artemio's has the same dangling reference.
- [ ] **AC5** — one generic check, driven by a list, replaces per-file bespoke wiring: for every
      config declaring a local `$schema`, the schema exists **and** the file validates against it.
      Red-tested by breaking one file, not by reading the code.

## Definition of Done

Every config in the estate that declares a local `$schema` is validated against it by a check that
runs unattended, and the schema it names exists. The count of enforced schemas is derived from the
files themselves rather than from a list someone maintains, so a config added later is covered
without anyone remembering to add it. The check has been observed failing: a deliberately broken
`clients-policy.json` — a tier key outside the contract — blocked, and the failure named the key and
the schema rather than reporting a generic validation error. Where the validator itself cannot run,
the result reads as skipped and never as passed, because a missing validator and a clean validation
must not print the same word. Configs that name a schema which does not exist are resolved in one
direction or the other; none is left declaring a promise nothing can keep.

## Notes

`jsonschema` is already a dependency and already used by `client_profile_check.py`, so AC1–AC2 are
wiring, not new capability. Keep the "skipped, not passed" branch that script already has for when
`jsonschema` is absent — a missing validator must not read as a green validation.
