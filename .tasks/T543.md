# T543 — Enforce manager or admin role for project creation and require assigned PM to hold manager role

## Summary

Owner direction (2026-10-03): expand manager-level scoping (following [[T538]]) to project creation and delivery leadership:
1. Creating a new project requires the user to hold the `manager` or `admin` role (or management capability `project.create`). Non-managers must not be able to create projects via CP UI or direct DB insert.
2. Every project should designate an assigned Project Manager (PM), and the assigned PM must hold the `manager` or `admin` role (or management office `project.manager` / `w0m.delivery.manager`). Unprivileged members/candidates cannot be designated as PM.
3. Align frontend forms in `ProjectManager.svelte` with database RLS policies and/or constraints so unprivileged project creation and invalid PM assignment fail closed.

## Acceptance criteria

- [ ] AC1 — **Project creation authorization gate:** In `ProjectManager.svelte` and CP routing, project creation is accessible only to authenticated users with `role IN ('admin', 'manager')` or holding `project.create` capability. Non-managers are denied both UI access and form submission.
- [ ] AC2 — **PM assignment selector:** In `ProjectManager.svelte` create/edit project modal, add a Project Manager (PM) selector populated strictly with profiles holding the `manager` or `admin` role (or management office `project.manager`), refusing selection of unprivileged members.
- [ ] AC3 — **Delivery role & hat linkage:** Saving a project with an assigned PM creates or updates the project's delivery role (e.g. `public.project_roles` record for PM) and an active hat in `public.hats` associating the PM's profile to the project.
- [ ] AC4 — **Database RLS & validation guardrails:** Update RLS on `public.projects` to allow authenticated users with `role IN ('admin', 'manager')` to INSERT and UPDATE projects (widening the legacy admin-only check while preventing unprivileged user insertion). Validate that an assigned PM possesses manager-level credentials.
- [ ] AC5 — **Automated tests (unit, RLS, and UI):** Add unit tests in `apps/cp` and RLS/API probes verifying: (a) managers and admins can create projects and assign a PM, (b) regular members cannot create projects, and (c) attempting to assign an unprivileged member as PM is rejected.
