# T33 — Spec-authoring standard — verifiable specs

## Summary

Every requirement carries a verification contract: feature description + acceptance
criteria + skill-mapped verification (`test-driven-development`/`playwright`/`verify`/
`code-review`/`security-review`/`openspec-verify-change`/`schema`) + w0m ecosystem &
security checklists + a change-level Definition of Done. The standard shipped
(`openspec/SPEC-AUTHORING-STANDARD.md`, referenced from AGENTS.md). Remaining: **retrofit
the active P1 specs** (client-conversion, webmcp, agency-delivery) to the enriched block;
apply to all new changes by default.

## Acceptance criteria

- [x] AC1 — `openspec/SPEC-AUTHORING-STANDARD.md` shipped and referenced from AGENTS.md
- [x] AC2 ✅ **DONE 2026-08-02 — all 18 requirements across the 3 named specs retrofitted.**
      webmcp 6 · agency-delivery 5 · client-conversion 7. Each gained **Feature** (context, who it
      serves, explicit non-goals), **Acceptance criteria** (binary and testable) and **Verify with**
      (named skills). All three still pass `openspec validate --strict`.
      🔴 **The measured gap was far worse than this AC implied:** it named 3 specs, but the corpus
      is **25 active spec files / 110 requirements**, and **0 of 110 conformed** — not 18. Even the
      single requirement that already had a `Feature:` block was missing Acceptance criteria and
      Verify with. Ratchet moved **110 → 92**.
- [x] AC3 ✅ **DONE 2026-08-02 — enforced MECHANICALLY, not by hope.** `just spec-standard-check`
      (`project/scripts/spec_standard_check.py`) parses every `### Requirement:` in active changes
      and checks the four things the standard mandates. **Ratchet, not a cliff:** the non-conforming
      count may shrink freely; any increase fails. Baseline `project/spec-standard-baseline.json`
      = **92**.
      🔴 **Proven RED and GREEN** — `just spec-standard-test`, 11 checks against a FIXTURE estate
      (`W0M_SPEC_ROOT`), because planting a malformed requirement in a real spec would mean
      committing the defect the gate catches: a conforming requirement passes; a bare one pushes
      the count over the ceiling and exits 1 naming the rise; `--verbose` names the missing parts;
      holding at the ceiling passes; a drop prompts a re-baseline; **an empty corpus FAILS** rather
      than reporting a clean estate; `archive/` is out of scope.
      ⚠️ **The suite earned its keep on first run** — it caught `relative_to(WEB)` raising whenever
      the corpus is outside the repo, i.e. the gate *crashed* instead of reporting. Fixed.
      ⚠️ Deliberately shallow: it checks the block is **present**, not that the prose is good. A
      checker cannot judge that, and pretending it could would be the vacuous-gate trap in a new
      costume.
