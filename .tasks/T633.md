# T633 — `deploy-all` blocking suite failures across `worker-env-check` (`security-audit` `process.env` & `locals.runtime`) and `vitest` (release-worktree obsidian `dist` & `roles` `.in().in()` mock)

## Summary

Running `just deploy-all` (`release 2026.11.03-1793766898`, `deploy-logs/run-2026.11.03-1793766898.log`) passed `codemap-check` and `reality-verify` from `T625`, then failed on 2 blocking suites introduced by `T628–T632` (`ccde9cba7`):
1. **`worker-env-check` (`4` forbidden `process.env` reads + Astro v6/v7 `locals.runtime` crash trap)**:
   - `w0m-web/apps/cp/src/pages/api/client/security-audit.ts:281-283` and `w0m-web/apps/web/src/pages/api/security-audit.ts:102-104,320-328` read `process.env.{TURNSTILE_SECRET_KEY,PUBLIC_SUPABASE_URL,PUBLIC_SUPABASE_ANON_KEY}` AND accessed `(locals as any)?.runtime?.env`, which throws at runtime in Astro v6/v7 (`@astrojs/cloudflare` v14 — `AgDR-0023`).
2. **`vitest` (`4` failed assertions across `2` test files)**:
   - `w0m-web/apps/cp/src/lib/__tests__/vault-r2-gateway.test.ts:700` read `../w0m-ext/obsidian-w0m/dist/manifest.json` directly from disk, which fails with `ENOENT` in clean release worktrees (`~/.w0m/releases/<version>/w0m`) because `dist/` is gitignored in `w0m-ext/.gitignore`.
   - `w0m-web/apps/cp/src/tests/api/project/project-pm-assignment.test.ts` returned a bare `Promise` on `user_roles.in(...)`, throwing `TypeError: supabase.from(...).select(...).in(...).in is not a function` when `apps/cp/src/pages/api/project/roles.ts:557` chained `.in("user_id", ...).in("role", ["admin", "manager"])`.
