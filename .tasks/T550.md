# T550 — Telegram and Threads integration (research and plan)

## Summary

Owner ask 2026-10-06: "research more tight and advanced integration with TG and Threads chats to search, message and manage bots", with a concrete test: search `@it_chats` and the channels it relates to for offers matching the owner's experience, paid in USD, fully remote.

Findings (full report: `.agents/reports/2026-10-06-t550-telegram-and-threads-integration-research.md`):

- **A Telegram Bot API bot cannot search or read history** (Bot API 10.3, 2026-08-24); Business bots see only incoming messages in chats the owner grants; **searching channels and chats needs a user-account (MTProto) client**, which Telegram monitors and whose Terms are silent on personal automation, with a clause (§1.5) against using Telegram data for AI/ML development.
- **Managed bots (Bot API 9.6, 2026-04-03)** are the official way to create and manage child bots: a manager bot, a `t.me/newbot/...` link, `getManagedBotToken`, `replaceManagedBotToken`, access settings.
- **Threads has no messaging or DM API** (checked against the documentation index and the changelog to 2026-08-12); "message" means replies and posts. Keyword search is 2,200 queries per rolling 24 hours per user (a secondary source's "500 per 7 days" was the old figure), needs `threads_keyword_search` and App Review; webhooks (`replies`, `mentions`, `publish`, `delete`) document no payload signature.
- **The live test:** `@it_chats` is a directory, not a feed. Of 15 job channels tried, 2 expose a public preview. From 210 posts (166 were candidate résumés), 4 vacancies were fully remote with a USD figure; one is a strong stack match (SRE, 6,500 to 9,300 USD, Kubernetes, Terraform, AWS, Python or Go), though below principal level. A thin sample, stated as one.
- The estate already has a Telegram bot (webhook, notifier, auth link, status card) and a job pipeline with six sources, but Telegram is only a notification target there and nothing exists for Threads.
