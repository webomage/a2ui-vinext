# T598 — Unified `w0m` CLI tool (`w0m skill`, `w0m project`, `w0m agent`, `w0m tree`, `w0m session`) for skills and multi-project management

## Summary

Provide a single, globally runnable `w0m` CLI (`scripts/w0m_cli.py`, installed at `~/.local/bin/w0m` on both macOS and `linux-host`) that unifies **skills management** (`w0m skill`) and **multi-project / workspace / agent management** (`w0m project`, `w0m agent`, `w0m tree`, `w0m session`, `w0m tasks`, `w0m status`) from any directory on the host.

Previously, these capabilities were fragmented across separate runtimes and directory-relative invocations (`tsx w0m-skills/w0m_skill.ts`, `tsx w0m-skills/skills.ts`, `tsx w0m-skills/src/cli.ts`, `python3 scripts/client_inventory.py`, `python3 scripts/client_check.py`, `python3 w0m-web/project/scripts/agent_identity.py`, `python3 w0m-web/project/scripts/agent_tree.py`, and `python3 scripts/orca_sessions.py`), and `which w0m` returned `w0m not found`.

## Acceptance criteria

- [x] **AC1 — Unified `w0m skill` Subcommands (`list`, `search`, `check`, `sync`, `add`, `remove`, `update`, `relock`, `audit`)**:
  - `w0m skill list [--project <dir>] [--registry] [--json]` inspects `<project>/.w0m/skills.json` + `.w0m/skills.lock.json` (and canonical `w0m-skills/skills-registry.json` with `--registry`) and reports declared skills, providers, versions, lock status, and integrity hashes.
  - `w0m skill search <query> [--json]` searches canonical skills in `w0m-skills/skills-registry.json` by name, description, and category/tags.
  - `w0m skill check`, `sync`, `add`, `remove`, `update`, `relock`, and `audit` delegate cleanly to `w0m-skills` (`w0m_skill.ts`, `skills.ts`, `skill_audit.ts`, and `w0m_portable_cli.py` fallback).
- [x] **AC2 — Unified `w0m project` Subcommands (`list`, `show`, `check`, `init`, `link-remote`)**:
  - `w0m project list [--orca] [--json]` inventories all declared estate and client projects in `project/policies/clients-policy.json` plus local `~/Projects/!proj/*` checkouts (e.g. `pandatransfer`, `bridgeroad`), reporting `id`, `role`, local checkout presence, `git remote`, derived Orca `projectId` (`github:<owner>/<repo>` vs host-local `repo:<uuid>`), `.w0m/skills.json` count, and `.w0m/sdlc.json` status.
  - `w0m project show <id> [--json]` displays detailed project metadata, repos, skills manifest status, and Orca cross-host identity.
  - `w0m project check [<id>]` delegates to `scripts/client_check.py` / `scripts/client_inventory.py`.
  - `w0m project init [<dir>] [--retention]` bootstraps `.w0m/w0m.just` and `.w0m/bin/w0m_portable_cli.py` into any target project.
  - `w0m project link-remote <dir-or-id> <remote-url>` sets/updates `origin` remote URL so host-local Orca projects gain a canonical `github:<owner>/<repo>` or `git:<canonicalKey>` identity and merge across paired Orca hosts.
- [x] **AC3 — Integrated `w0m agent`, `w0m tree`, `w0m session`, `w0m tasks`, `w0m status` & `~/.local/bin/w0m` Installer (`w0m install`)**:
  - Route `w0m agent` (`whoami`, `claim --track`, `rename`, `release`, `tag`, `claims`), `w0m tree` (`new --ticket --track`, `list`, `land`, `remove`, `prune`), `w0m session` (`orca_sessions.py`), `w0m tasks`, `w0m status`, `w0m preflight`, and `w0m prs` through `scripts/w0m_cli.py`.
  - Provide `w0m install [--bin-dir ~/.local/bin]` and install `~/.local/bin/w0m` on both macOS (`local`) and `linux-host`.
- [x] **AC4 — Unit Tests & Suite Registration (`scripts/tests/test_w0m_cli.py`)**:
  - Add comprehensive unit tests in `scripts/tests/test_w0m_cli.py` covering `w0m skill list/search/check`, `w0m project list/show/link-remote/init`, `w0m agent`, `w0m tree`, and `w0m install`, and wire `just w0m` into root `justfile`.
