# T440 — Move Aleksei's casualuser-era work onto the person profile and show it as Me → Work history

## Summary

Split from [[T439]] (CP IA). Owner, 2026-09-24: *"resume part in CP to receive/accumulate all our already fetched
agency projects/contracts because it was made by Aleksei all till now"*, then: *"add to my Aleksei's account also
casualuser@gmail.com as second e-mail since we separated admin to w0m@webomage.com"*.

**Measured live (read-only) 2026-09-24:**
- Three principals: `w0m@webomage.com` = **admin** (institutional, since [[T362]]); `aleksei@webomage.com` =
  member (the person, profile `8d16aff5`); `casualuser@gmail.com` = member (profile `5691add5`).
- casualuser is **already a second login of the Aleksei profile**: `account_profiles(user 5691add5 → profile
  8d16aff5, is_primary=false)` since [[T363]]. `current_profile_id()` resolves `account_profiles` first, so a
  casualuser sign-in already acts as Aleksei.
- **But the data never moved.** Still on the old casualuser profile `5691add5`: `contracts` 95 (all Upwork,
  `CLOSED`, 75 clients, 2012-07 → 2026-04), `proposals` 1,782, `platform_rooms` 55, `platform_messages` 170,
  `upwork_auth_tokens` 3. RLS (`profile_id = current_profile_id()`) scopes by profile, so **neither login can
  see any of it** as its own.
- Contract rows carry only `title`, `client`, `start_date`, `end_date`, `status`: no description, no skills. They
  back up the CV timeline; `project/data/cv/resume.json` (29 curated work entries) stays the CV source.
- 🔴 `upwork-poller/index.ts:287` hardcodes `profiles.email = 'casualuser@gmail.com'` as the fallback owner for
  tokens without a `profile_id`: a silent fallback (AgDR-0025) that points at the old profile.

  asserts the before-counts, fails if any table's count differs from the measured one, and leaves `5691add5`
  holding zero rows in every `profile_id` table. The old profile row is kept, because `profiles.auth_user_id`
  still points at it.

  where it becomes part of the one sync engine.

  1,782 proposals through RLS (not service role).
- [ ] AC4 — **Me → Profile & CV → Work history** (UI lands in the [[T439]] shell; API completed here): a timeline of contracts per

  stay private (KB content policy). Endpoints `GET /api/profile/contracts` and `POST /api/profile/contracts/promote` built and tested.
