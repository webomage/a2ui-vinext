# T564 — Virtual Agent Identity (`agent_id`) & Cross-Worktree Ticket Claim and Tagging System

## Summary

Parallel AI agents working in isolated agent trees (`~/.w0m/work/<name>/w0m`) previously had no canonical virtual identity (`agent_id`), no mechanism to claim or tag tickets with their identity, and no cross-worktree visibility into tickets already claimed or completed in sibling agent trees before push (causing `just tasks hot` in one tree to recommend `T63` or `T29` while another agent had already completed them in its tree).

This ticket introduces:
1. Deterministic **Virtual Agent IDs** (`<harness>:<handle>`, e.g. `agy:ant-ci`, `agy:agy-jobs-cp`, `claude:main`) persisted in `.w0m/agent-id` and `~/.w0m/agents/registry.json`.
2. First-class ticket frontmatter `agent_id:` and namespaced `agent_<harness>_<handle>` tags in `tags: [...]` (conforming to T353 tag families), plus CLI tools (`just agent-id`, `just ticket-claim`, `just ticket-release`, `just ticket-tag`, `just agent-claims`) so agents can claim tickets and assign/remove ticket tags.
3. A **Cross-Worktree Live Radar** in `scripts/tasks_query.py` (`just tasks hot`, `just tasks board`, `just tasks wip`) and `wom7web/project/scripts/agent_tree.py` (`just agent-tree-list`) that inspects `~/.w0m/agents/registry.json` and all sibling `~/.w0m/work/*/w0m` trees so tickets already claimed or completed by another agent are automatically excluded from `just tasks hot` and attributed to their owning virtual agent ID.

## Acceptance criteria

- [x] AC1 — **Virtual Agent Identity Resolution & Registry (`agent_identity.py`)**: Mint and resolve deterministic virtual agent IDs (`<harness>:<handle>`, e.g. `agy:ant-ci`, `agy:agy-jobs-cp`, `claude:main`) from `W0M_AGENT_ID`, `.w0m/agent-id`, or auto-detected harness + `agent/<name>` branch/worktree, and persist active agents in `~/.w0m/agents/registry.json`.
- [x] AC2 — **Ticket Schema & Template Support for `agent_id` and Agent Tags**: Declare optional `agent_id` in `wom7web/project/tickets-schema.jsonc`, `wom7web/project/schemas/meta/ticket-frontmatter.schema.json`, `scripts/ticket_schema_check.py`, and `project/templates/ticket.md`, paired with namespaced `agent_<harness>_<handle>` tags in `tags: [...]`.
- [x] AC3 — **Ticket Claim, Release & Tag Assignment CLI (`just ticket-claim`, `just ticket-tag`, `just ticket-release`, `just agent-claims`)**: Allow agents to claim a ticket (refusing if another virtual agent already claims or completed it unless `--force`), assign or remove arbitrary tags (`+tag`, `-tag`), and release claims, updating both `.tasks/T##.md` frontmatter and `~/.w0m/agents/registry.json`.
- [x] AC4 — **Cross-Worktree Live Radar in `tasks_query.py` & `agent_tree.py`**: Scan sibling `~/.w0m/work/*/w0m` worktrees and `~/.w0m/agents/registry.json` during `just tasks hot` / `just tasks board` / `just agent-tree-list` so tickets claimed or already marked `done` in another agent's tree (e.g. `T29` in `agy:agy-jobs-cp`) are automatically excluded from `hot` and reported in the Virtual Agent Radar banner.
- [x] AC5 — **Unit Tests & Suite Registration**: Add comprehensive unit tests in `wom7web/project/scripts/tests/test_agent_identity.py` covering virtual ID resolution, claim conflict detection, tag mutation, and cross-worktree radar filtering, wired into `wom7web/project/test-suites.json`.
