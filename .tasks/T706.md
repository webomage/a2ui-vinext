# T706 — Orca Desktop: Fix Back Button Not Navigating Embedded Browser Tabs, File Upstream Issue & Open PR

## Summary

In Orca Desktop (`w0m-pr/orca`), pressing the Back button (mouse back button / hardware navigation / browser toolbar back action) does not navigate the active embedded browser tab (`webContents.navigationHistory.goBack()`). Reproduce and isolate the root cause in `w0m-pr/orca`, file a grounded bug issue at upstream `stablyai/orca`, implement and test the fix in our `webomage/orca` fork, and open a compliant GPG-signed upstream PR via `just pr-open`.

## Acceptance criteria

- [ ] AC1 — **Root-Cause Diagnosis & Upstream Issue (`stablyai/orca`):** Trace how mouse back (`app-command` / `browser-backward` / mouse button 3/4 / keyboard `Alt+Left` / `Cmd+[` / toolbar back button) is routed in `w0m-pr/orca` when an embedded browser tab is focused vs workspace pane history, and file an upstream issue on `stablyai/orca` documenting reproduction steps and root cause.
- [ ] AC2 — **Fix Embedded Browser Tab Back/Forward Routing (`w0m-pr/orca`):** Route Back (and Forward) navigation commands to the active embedded browser tab's `webContents` history when a browser tab is focused and `canGoBack()` is true, without breaking terminal/worktree pane navigation.
- [ ] AC3 — **Automated Regression Test & Local Build Verification:** Add unit/integration test coverage in `w0m-pr/orca` verifying embedded browser tab back navigation and verify local Orca build (`just orca-apply` / test suite).
- [ ] AC4 — **Compliant Upstream Fork PR (`webomage/orca` → `stablyai/orca`):** Commit with GPG signature (`-S`) on a dedicated branch in `webomage/orca` and open the upstream PR referencing `Fixes #<issue>` via `scripts/w0m_prs.py` (`just pr-open`).
