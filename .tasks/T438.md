# T438 — Evaluate and prototype WebRTC/WebTorrent transport support in Rust `librqbit` (or Rust/Tauri streaming client)

## Context

Split from `[[T437]]` (`webtorrent-desktop` `arm64` build).

While `webtorrent-desktop` is an Electron + Node.js application, **`rqbit` (`librqbit`)** is the leading modern, high-performance Rust BitTorrent engine and desktop/HTTP streaming server. However, `librqbit` currently implements standard TCP/uTP/DHT BitTorrent (`BEP-03`/`05`/`09`/`10`/`15`/`29`) and **does not yet implement the WebTorrent protocol** (BitTorrent over WebRTC DataChannels + WebSocket `wss://` tracker signaling).

This ticket evaluates and specifies the architecture for adding WebRTC DataChannel peer transport + `wss://` tracker signaling to `librqbit` (`ikatson/rqbit`) and pairing its HTTP range-request streaming server with a native `arm64` Tauri v2 desktop client.

## Acceptance Criteria

- [x] **AC1 (Protocol & codebase audit):** Audited `librqbit`'s peer transport abstraction (`peer_connection.rs`, `stream_connect.rs`) and tracker subsystem (`tracker_comms.rs`) and documented the exact extension points required for `wss://` WebSocket trackers (SDP offer/answer signaling) and WebRTC DataChannel peer streams in [`wom7web/docs/research/oss/2026-10-22-t438-librqbit-webrtc-webtorrent-evaluation.md`](../wom7web/docs/research/oss/2026-10-22-t438-librqbit-webrtc-webtorrent-evaluation.md).
- [x] **AC2 (Architecture decision record):** Recorded [`docs/decisions/AgDR-0041-librqbit-webrtc-transport-architecture.md`](../docs/decisions/AgDR-0041-librqbit-webrtc-transport-architecture.md) comparing Option A (`librqbit` + `str0m` sans-I/O WebRTC), Option B (`librqbit` + `webrtc-rs` async `tokio`), and Option C (`libdatachannel` C++ FFI), settling on a feature-gated pure-Rust `DataChannelByteStream` + `WssTrackerClient` architecture paired with Tauri v2 (`WKWebView`).
- [x] **AC3 (Prototype / PoC specification):** Specified the `DataChannelByteStream` (`AsyncRead + AsyncWrite` over `RTCDataChannel` with 16 KiB SCTP chunk framing) and `wss://` tracker SDP offer/answer sequence in [`wom7web/docs/research/oss/2026-10-22-t438-librqbit-webrtc-webtorrent-evaluation.md`](../wom7web/docs/research/oss/2026-10-22-t438-librqbit-webrtc-webtorrent-evaluation.md).
- [x] **AC4 (Upstream / fork strategy):** Defined the two-step upstream contribution strategy via `github.com/webomage/rqbit` (zero-dependency `PeerStream` trait generalization PR first, opt-in `#[cfg(feature = "webrtc")]` crate second; external PR creation remains owner-gated per `AGENTS.md`).
