# T438 — WebTorrent in Rust: WebRTC peer transport for librqbit (rqbit#71), then a Tauri client and a Rust→WASM core

## Summary

Split from [[T437]] AC5 (owner, 2026-09-24: "Rust will wait and we can separate it to extra ticket"). T437 fixes the
real problem, Rosetta, with a native arm64 Electron build. This ticket holds the larger rewrite question: can
WebTorrent Desktop and its JS library become Rust + WASM?

**Research so far (2026-09-24):** don't start from scratch. [`ikatson/rqbit`](https://github.com/ikatson/rqbit)
(★1.9k, pushed 2026-09-24) is a maintained Rust BitTorrent library (`librqbit`) and already ships a Tauri desktop
app (`rqbit-desktop_9.0.1_universal.dmg`). What it lacks is exactly what makes WebTorrent WebTorrent: WebRTC peers
and WebSocket trackers ([rqbit#71](https://github.com/ikatson/rqbit/issues/71), open). Rust WebRTC stacks:
[`algesten/str0m`](https://github.com/algesten/str0m) (sans-IO, MIT) and
[`webrtc-rs/webrtc`](https://github.com/webrtc-rs/webrtc) (Apache-2.0). Note that `webtorrent` itself is
JavaScript (292k lines of JS on GitHub), not TypeScript.

Ordered by value:
- **A** — WebRTC transport in librqbit, contributed upstream: native clients join browser swarms.
- **B** — a Tauri client on librqbit, replacing Electron. Risks: WKWebView plays fewer formats than Chromium (e.g.
  MKV), and casting needs porting (AirPlay especially).
- **C** — a Rust→WASM browser core sharing A's code. Networking stays browser WebRTC/WebSocket, since browsers
  allow no TCP/UDP/DHT. The win is mostly hashing, against bundle size and JS↔WASM cost.

**Known risk (measured 2026-09-24, T437):** WebTorrent Desktop's engine (webtorrent 1.9.7) drops webtorrent 3.x
peers ~20 ms after TCP connect, so the desktop app is already cut off from current WebTorrent swarms. Any
replacement must interoperate with webtorrent 3.x (the reference) and should be tested against both versions.

`blocked_by: [T437]`: sequencing rather than a technical dependency. The arm64 fork is the working product and the
contributor foothold; this starts once T437 has shipped.

- [ ] AC1 — rqbit measured, not assumed: DHT, magnet links, HTTP streaming, Tauri app features and platform

- [ ] AC2 — Design note for path A: `str0m` vs `webrtc-rs`, WebSocket tracker protocol, signalling, how the
  transport fits librqbit's peer abstraction. Recorded as an AgDR.
- [ ] AC3 — Owner decision: start A (fork `ikatson/rqbit` under `webomage` into `wom7pr/`), or park.
- [ ] AC4 — If A ships: B/C go/no-go, with the WKWebView format gap and casting measured on a real build.
