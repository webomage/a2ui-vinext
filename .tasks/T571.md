# T571 — Portal sidebar separation, Admin full-org/capability access, Client/PM side switcher, and Gamification Mode naming for w0m units

## Summary

Owner live UI review on `cp.webomage.com/o/webomage` and `/o/webomage/projects/milestones` (2026-10-25) surfaced six interconnected UX and RBAC issues:
1. **Toolbar & Dropdown Stacking Overflow**: On `/o/webomage/projects/milestones`, `AdminTableToolbar.svelte` (`sticky top-16 z-30`) collided with `<aside class="w0m-aside">` (`z-index: 30` on narrow viewports, no `z-index` or stacking isolation on desktop) and painted on top of the sidebar and `AuthWidget` popup. Furthermore, `ContextSwitcher.svelte`'s `.menu` had no `max-height` scroll container, causing a browser scrollbar to bisect the screen.
2. **Missing Client Orgs in `ContextSwitcher` for Platform Admin**: `public.wom_my_contexts()` in `w0m-api` filtered `admin_contractors` to `'contractor' = any(public.wom_org_sides(o.id))`, hiding all client `company` orgs from Platform Admin in the `ContextSwitcher` dropdown even though `wom_context_capabilities` grants Admin access to them.
3. **No Way to Switch Between Client Side and w0m PM/Contractor Side on `Webomage` (`BOTH`)**: Because `Webomage` has `sides = ['contractor', 'client']` (`BOTH`), `pureSideAllows("client", held)` / `isPureClientOrg(held)` always returned `false`, locking `/o/webomage` permanently into the Contractor view with no way to preview or operate the Client side.
4. **Confusing `SidebarHatSwitcher` (`ACTIVE PROJECT CONTEXT`) in Sidebar**: Showing an unscoped project hat widget (`ARTEMIO...`) directly under `ContextSwitcher` (`Webomage`) created a competing dual-SSOT project context in the sidebar.
5. **Cross-Portal Link Mixing in `shared-sidebar.ts`**: Merging `cp.webomage.com`, `job.webomage.com`, and `join.webomage.com` links into one sidebar menu caused unexpected cross-domain jumps when clicking sidebar links inside `cp`.
6. **Enterprise vs. Gamification Naming (`Milestones` vs. `Adventures/Quests`)**: Keep `Milestones` and classic enterprise development naming (`Milestones`, `Projects`, `Team`) as the default across orgs/clients, and display RPG gamification names (`Adventures`, `Projects & Raids`, `Guild & Cohorts`, `Quest Bounties`) when Gamification Mode (`mage`) is enabled for `w0m` units (`held.platformUnit`).

## Acceptance criteria

- [x] **AC1 — Fix Sidebar & Sticky Toolbar Z-Index / Horizontal Overflow (`AppShell.svelte`, `AdminTableToolbar.svelte`, `AuthWidget.svelte`, `ContextSwitcher.svelte`)**:
  - Isolated stacking contexts in `AppShell.svelte` (`<aside class="w0m-aside">` `z-index: 40; isolation: isolate`, `.col` `isolation: isolate; z-index: 1; min-width: 0; overflow-x: hidden`, `.scrim` `z-index: 35`).
  - Lowered `AdminTableToolbar.svelte` sticky header from `z-30` to `z-20 min-w-0`.
  - Made `AuthWidget.svelte` dropdown opaque (`bg-[#090d16] z-50`) and constrained `ContextSwitcher.svelte` `.menu` with `max-height: min(70vh, 420px); overflow-y: auto; z-index: 60` (`just test`).
- [x] **AC2 — Display All Active Orgs in `ContextSwitcher` for Platform Admin (`w0m-api` migration)**:
  - Added migration `w0m-api/supabase/migrations/20261025193000_t571_admin_all_orgs_in_wom_my_contexts.sql` updating `public.wom_my_contexts()` so `public.is_admin()` lists all active non-personal orgs (`o.deleted_at is null and o.kind <> 'personal'`), ordered contractor-first then by name (`just test`).
- [x] **AC3 — Unlock All Functional Capabilities & Hats for Admin Without Breaking PII (`capability.ts`)**:
  - Updated `heldFrom()` in `w0m-web/packages/lib/src/auth/capability.ts` so `isAdmin === true` holds `delivery`, `talent`, `platformUnit`, and `admin` across contexts while `public.profile_identity` self-only RLS (`AgDR-0035`) remains untouched (`just test`).
- [x] **AC4 — Client vs. w0m PM/Contractor Side Switcher for `both`-Sided Orgs (`Webomage`) & Admin**:
  - Added `activeSide?: Side`, `terminologyTheme?: "web" | "mage"`, `effectiveSides(held)`, and `hasBothSides(held)` to `Held` (`capability.ts`), and updated `sideAllows()`, `pureSideAllows()`, `isPureClientOrg()`, `resolve.ts`, `gate.ts`, `middleware.ts`, and `shell-model.ts` so `wom_active_side` cookie / `?side=client|contractor` switches a dual-sided (`BOTH`) org cleanly between **w0m PM / Contractor Side** and **Client Side**.
  - Updated `SidebarHatSwitcher.svelte` and `CpShell.svelte` to scope project hats strictly to the current org (`currentOrgSlug`), eliminating foreign-org project bleed (`ARTEMIO...`), and added 1-click **View Side (`w0m PM` ↔ `Client View`)** and **Vocabulary Mode (`Enterprise` ↔ `RPG Guild`)** toggles (`just test`).
- [x] **AC5 — Classic Enterprise Naming (`Milestones`) Default vs. Gamification Mode (`Adventures`, `Quests`) for `w0m` Units**:
  - Kept `Milestones` (`projects/milestones` and `milestones`) in `NAV.org` and `NAV.project` (`apps/cp/src/lib/context/nav.ts`).
  - Added `displayLabelFor(item, held)` in `apps/cp/src/lib/context/nav.ts` so classic enterprise terminology (`Milestones`, `Projects`, `Team`, `Bounty board`) is the default (`web`), and enabling Gamification Mode (`mage`) on a `w0m` unit (`held.platformUnit && held.terminologyTheme === "mage"`) translates delivery labels to the RPG Guild lexicon (`Adventures`, `Projects & Raids`, `Guild & Cohorts`, `Quest Bounties`) (`just test`).
- [x] **AC6 — Separate Sidebar Menus Cleanly Across Portals (`cp` vs `job` vs `join`)**:
  - Updated `shared-sidebar.ts` so `cp` renders only `cp` routes (`cpMenuFor`), `job` renders only `job` routes (`jobMenuFor`), and `join` renders only `join` routes (`Candidate Portal`); cross-portal navigation stays in `Your Apps` (`AuthWidget`) (`just test`).
- [x] **AC7 — Unit & Conformance Verification**:
  - Updated and passed unit tests in `packages/lib/src/auth/capability.spec.ts` and `apps/cp/src/lib/context/__tests__/shared-sidebar.test.ts` (`just test`).
