## Summary

**Contract model: type vs source + synced/authored split** — `contracts.source` currently collapses two orthogonal axes (*what kind of agreement* vs *where the record comes from*), so a member contract via Upwork and a client contract via Upwork are indistinguishable. Add `contract_type`; **separate connector-owned synced data from w0m-authored terms** (🟠 live risk: both `upwork-poller` and `platform-webhook-gateway` do `set: { data: … }`, wholesale-overwriting `contracts.data` every sync — authored terms placed there would be destroyed); generalize the counterparty beyond `client`/`client_id`/`client_user_id` to cover member/vendor contracts; attach satellites (proposals, `platform_rooms`/`platform_messages` ✅ already source-generic, `invoices`, `client_milestones`) to the contract spine; make `source` an FK into the T94 registry.

## Acceptance criteria

> ✍️ **Written 2026-08-27**, replacing the `Not yet written` placeholder. Every claim in the Summary
> was re-measured against production first, and all of them hold: `contracts.source` is a **closed
> CHECK** (`upwork, direct, deel, oyster, remote`) carrying **95 `upwork` and 1 `direct`**; there is
> **no `contract_type` column**; the counterparty is client-shaped throughout (`client` text,
> `client_id`, `client_user_id`); **seven** tables FK to `contracts`; and the wholesale overwrite is
> live at `upwork-poller/index.ts:573` — `.set({ data: c })`.
>
> 🔴 **AC1 is a live data-loss risk and does not wait for the model work.** Everything else here
> reshapes a schema; AC1 stops a running poller from destroying anything a human writes into
> `contracts.data`. Land it first, on its own if need be.

- [ ] **AC1 — 🔴 a sync can no longer overwrite authored terms.** `upwork-poller/index.ts:573` does
      `.set({ data: c })` — the whole JSONB, every poll — and `platform-webhook-gateway` writes the
      same column. **Anything a human authors into `contracts.data` is destroyed on the next sync**,
      which is why the split below is not merely tidier: connector-owned synced data and w0m-authored
      terms live in different places, and the sync writes only its own.
      ⚠️ **Prove it the way the estate proves destructive changes** — write an authored value, run
      the poller against it, and read the value back. A test that asserts the *code shape* would
      have passed on the day this bug shipped.
- [ ] **AC2 — `contract_type` exists and answers a different question from `source`.** Today one
      column collapses *what kind of agreement this is* with *where the record came from*, so a
      member contract via Upwork and a client contract via Upwork are indistinguishable — and 95 of
      96 rows say `upwork`, which is a provenance fact carrying no information about the agreement.
      The two axes are separated, and the existing 96 rows are classified rather than defaulted.
      ⚠️ **A backfill that puts every row in one bucket has not classified anything.** State the
      rule that assigns each row, and how many landed in each type.
- [ ] **AC3 — the counterparty generalises beyond a client.** `client`, `client_id` and
      `client_user_id` presume one shape; member and vendor contracts have none of it. The model
      carries a counterparty that can be a client, a member or a vendor, without a nullable column
      per kind. ⚠️ **Sequenced with [[T210]]** (*detach the person from the account*) — a member
      counterparty is a person, and this AC must not invent a second answer to the keying question
      T210 is already deciding.
- [ ] **AC4 — the satellites hang off the contract spine, and the set is the measured one.** Seven
      tables reference `contracts` today: `client_milestones`, `engagement_closures`, `invoices`,
      `lead_proposals`, `platform_rooms`, `projects`, `proposals`. ✅ `platform_rooms` and
      `platform_messages` are **already source-generic** and need no change — say so rather than
      touching them. Each remaining satellite either works for every `contract_type` or declares
      which types it applies to.
- [ ] **AC5 — `source` becomes an FK into the [[T94]] registry.** ⏳ **Blocked on T94 AC5**, which
      unifies `upwork_auth_tokens` and `social_integrations` into one registry keyed to the person.
      Until that table exists there is nothing to point at, and inventing an interim lookup would
      make a second registry — the outcome T94 AC5 exists to prevent.
      🔑 **Until then `source` stays a CHECK, and the CHECK is kept honest**: [[T204]] AC9 wants
      `internal` in it and it is still absent, so a contract for our own work cannot currently be
      recorded. That is a one-value migration and should not wait for the registry.
- [ ] **AC6 — no consumer reads `source` to mean "kind of agreement" after the split.** The
      contradiction this ticket fixes is only fixed if the call sites move too:
      `ContractManager.svelte:420` renders `{c.source || 'upwork'}` as the contract's identity, and
      [[T90]] AC1 removes that default. Enumerate the readers and show each one asking the axis it
      actually means.
- [ ] **AC7 — a probe that fails if the two axes recollapse.** Asserts that `contract_type` is
      populated for every row, that `source` values are all in the declared set, and that no row
      carries authored terms in a connector-owned blob. ⚠️ **Runs against the LIVE database** — the
      overwrite in AC1 is a property of what the poller does to production, and a scratch restore
      carries the schema without the poller ever having run.
- [ ] **AC8 — the migration is proven on production data before it is trusted.** 96 contracts is
      small enough to check exhaustively and large enough that a silent mis-classification would go
      unnoticed. Apply inside a transaction, read the classification back, roll it back, and report
      the per-type counts — the pattern used for the `projects` dedupe on 2026-08-27.

## Definition of Done

A sync can no longer destroy what a human wrote: connector-owned data and w0m-authored terms occupy
different places, and `upwork-poller` writes only its own — proven by authoring a value, running the
poller, and reading that value back, not by inspecting the code shape. `contracts` answers *what
kind of agreement* and *where the record came from* as two separate questions, with all 96 existing
rows classified by a written rule rather than defaulted into one bucket, and the per-type counts
reported. The counterparty covers members and vendors without a nullable column per kind, keyed
consistently with [[T210]] rather than re-deciding it. Every one of the seven satellites either
works for all contract types or declares which it applies to. A live-measuring probe fails if the
two axes recollapse, and the migration is proven on production data inside a rolled-back transaction
before it is trusted.

🔴 **`source` becoming an FK is explicitly NOT required to close this ticket** — it is blocked on
[[T94]] AC5, and holding this ticket open for it would strand the data-loss fix and the type split
behind a registry that does not exist. What IS required is that the CHECK stays honest in the
meantime.
