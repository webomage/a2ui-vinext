# T334 — Self-update checks and update workflow for w0m skills across estate and client workspaces, and bring Artemio up to canonical

## Summary

Owner 2026-09-11: *"I wandering if we have properly installed current version of w0m skills into artemio workspace and repo"*, followed by *"do, and we actually should have some kind of self-update checks and update process in w0m skills"*.

**Grounding & Drift Audit (measured 2026-09-11):**
1. **Artemio workspace (`artemioquierocomer.mx`) is severely drifted**:
   - Frozen on an August 14, 2026 snapshot (`2026.08.14`).
   - 11 canonical skills drifted (e.g. `w0m-lessons` still pointed agents to non-existent `wom7web/.agent/LESSONS.md`; `w0m` and `w0m-sdlc-start` missing Step 0a preflight and Step 2 coverage scans; `mmd-validate` missing updated lockfile).
   - Missing core skill: `w0m-tasks` is absent from `.w0m/skills.json` and `.agents/skills/`.
   - Legacy residue: `.agents/skills/w0m/` still contains 10 retired unbundled directories (`w0m-build`, `w0m-deploy`, `w0m-e2e`, `w0m-e2e-workspace`, `w0m-monkey`, `w0m-perf`, `w0m-plan`, `w0m-review`, `w0m-spec`, `w0m-test`, `w0m-ui-expert`).
   - Hash divergence: Artemio's local `scripts/verify_skills.mjs` implemented an ad-hoc hash calculation that diverged from canonical `wom7skills/w0m_skill.ts`, generating false-green on its local lock while `w0m skill check` reported 86 blocking findings.
2. **Missing self-update workflow for `w0m-native` skills**:
   - `w0m_skill.ts`'s `cmdUpdate` explicitly refused `w0m-native` skills:
     `w0m-native: canonical — edit it in wom7skills/skills/ and run just skills-sync; it has no skills.sh upstream`.
   - Outside `wom7web` or across client workspaces, there is no automated command to self-update `w0m-native` skills from the canonical store (`wom7skills/skills/`), sync files, update manifest observed versions, and re-lock.

This ticket delivers:
- (Part A) Full synchronization, cleanup, and canonical alignment of Artemio (`artemioquierocomer.mx`).
- (Part B) A first-class self-update check and update command in `wom7skills` supporting canonical updates for managed client projects, with modification guard, diffing, and backport capabilities.
- (Part C) Automated tests proving self-update detection, syncing, and re-locking.

## Acceptance criteria

- [x] AC1 — **Artemio skills synced to canonical**: `artemioquierocomer.mx` has all declared w0m skills updated to current canonical versions; `w0m-tasks` is declared in `.w0m/skills.json` and installed; the 10 retired legacy subdirectories in `.agents/skills/w0m/` are removed.
- [x] AC2 — **Artemio lockfile & integrity aligned**: Artemio's `.w0m/skills.lock.json` is re-locked with canonical directory hashes; `verify_skills.mjs` is aligned or delegates to `w0m skill check`; `skills.ts --check` and `w0m skill check` both pass with 0 errors and 0 warnings.
- [x] AC3 — **Canonical update capability in `wom7skills`**: `w0m_skill.ts` supports updating `w0m-native` skills from canonical source (or via a `--canonical` / `--source-dir` flag or dedicated `w0m skill update --canonical` workflow) so client projects can self-update without manual file copying.
- [x] AC4 — **`just skills-update` recipe**: A recipe is declared in root/wom7web/wom7skills justfiles allowing one-command update of client projects (e.g. `just skills-update /path/to/client`).
- [x] AC5 — **Automated tests for self-update**: Unit and integration tests in `wom7skills/tests/` verify that `w0m-native` update detection and synchronization work cleanly across test fixtures, updating lockfile hashes and observed versions.
- [x] AC6 — **Zero git hooks skipped**: All changes across `wom7skills`, `wom7web`, and `wom7api` pass linters, typechecks, and tests without `--no-verify`, proven via the hook-run ledger. `artemioquierocomer.mx`'s two T334 commits are verified by direct re-run of its own gate (`just skill-check` → 56/56, 0 drift) rather than a pre-commit hook — it has none, by explicit owner policy ([[T265]] AC2, half-managed tier: `quality_gates` is "DECLARED, NOT ENFORCED — we cannot install a hook in a repo we do not control").
