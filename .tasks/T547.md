# T547 — credential-probe red: apps/cp/src/pages/api/profile/services.ts

## Summary

`just credential-probe` (live, read-only; injects secrets and value-scans a snapshot) fails on committed `beta` code, measured 2026-10-06:

    credential-probe FAILED (1):
      apps/cp/src/pages/api/profile/services.ts: exported handler `POST` — the credential surface must have ZERO write routes

The probe treats any cp route whose path matches `(credential|connections|services|system-registry)` (`SURFACE_PATH` in `project/scripts/credential_surface_probe.py`) as part of the admin credential surface, which must be read-only by construction ([[T134]] AC11). `api/profile/services.ts` arrived with commit `b784c45e` ([[T476]], "unify service handles into social_integrations and retire ConnectedServices"). It reads and saves a MEMBER's own service handles (`getMemberServiceHandles` / `saveMemberServiceHandles`), which appear to be profile handles, not credentials: the match is on the word `services` in the path. The other three routes the probe finds (`admin/connections`, `admin/credentials`, `admin/services`) are the real surface and pass. The leak half of the probe is clean (84 injected secrets value-scanned against the snapshot, 0 leaks).

Not a deploy gate: only the probe's own self-test (`credential-probe-test`, offline) is a registered suite, and it passes. It is a real red nobody sees, which is the failure mode this estate keeps repeating, so it needs an owner-visible decision rather than a quiet fix in either direction.

## Acceptance criteria

- [x] AC1 — **Decide and record which it is.** Read `getMemberServiceHandles` / `saveMemberServiceHandles` and `social_integrations`: if the stored values are public handles only (no token, no secret), the route is not a credential route. If anything secret-shaped can be written through it, the probe is right and the route must move or change. Recorded here with the evidence.
- [x] AC2 — **Fix on the right side, test first.** Either narrow the probe (an explicit, reasoned exclusion list for member routes, never a looser regex; a test that a route which really writes a credential still fails it) or change the route. The probe must not go green by being blunted: keep the mutation test that a POST under `admin/credentials` is still caught.
- [x] AC3 — **It stays visible.** `just credential-probe` is green on `beta`, and the live probe is named somewhere a human sees a red (the weekly audit or the pre-push scope), not only the offline self-test.

## Status notes

- 2026-10-25 — **All 3 ACs verified and resolved:**
  - **AC1 (Grounded evidence):** Inspected `wom7web/packages/lib/src/auth/service-handles.ts` (`getMemberServiceHandles` / `saveMemberServiceHandles`) and `wom7web/apps/cp/src/pages/api/profile/services.ts`. The route strictly reads and writes public profile handles (`SUPPORTED_SERVICES = ["github", "linkedin", "telegram", "producthunt"]`), validating regex handle shapes and persisting `urn:handle:<service>:<handle>`, `handle`, and `profile_data: { handle }` into `public.social_integrations` alongside `public.profile_contact` (`github_url`, `linkedin_url`) and `public.profiles.telegram_username`. Zero secrets, OAuth tokens, or API keys are read or written. Similarly, the two OAuth 2.0 PKCE routes added in [[T384]] (`apps/cp/src/pages/api/connections/[id].ts` and `apps/cp/src/pages/api/connections/[provider]/start.ts`) manage connection labels, PKCE `oauth_states` challenges, and server-side token refresh over `SAFE_CONNECTION_COLUMNS` rather than the admin `credential-snapshot.json` surface.
  - **AC2 (Explicit reasoned exclusion, test-first):** Added `NON_CREDENTIAL_MEMBER_ROUTES` in `wom7web/project/scripts/credential_surface_probe.py` with explicit ticket rationale while preserving `SURFACE_PATH` (`(credential|connections|services|system-registry)`) unblunted and enforcing that any route importing `SURFACE_IMPORT` (`credential-snapshot.json` or `system-registry/credentials`) still fails even if listed in `NON_CREDENTIAL_MEMBER_ROUTES`. Added unit tests in `wom7web/project/scripts/tests/test_credential_surface_probe.py` proving (a) `api/profile/services.ts` passes `check_readonly_routes`, (b) `api/profile/services.ts` importing `credential-snapshot.json` fails, and (c) synthetic `POST` handlers in `api/admin/credentials.ts` and `api/admin/services.ts` are caught and fail.
  - **AC3 (Continuous visibility):** Added a live committed-corpus route check (`probe.check_readonly_routes() == []` over the real `apps/cp/src/pages` tree) inside `test_credential_surface_probe.py` (registered in `wom7web/project/test-suites.json` as `credential-probe` / `credential-probe-test`, `tier: "offline"`), so any future non-GET route matching `SURFACE_PATH` immediately fails pre-push and `just test`. Both `python3 project/scripts/credential_surface_probe.py --routes` and `python3 project/scripts/credential_surface_probe.py --test` (18/18 cases) are green.
