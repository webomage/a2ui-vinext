# T636 — Harden first-party web apps and codebase to pass Webomage perimeter, Lighthouse, and codebase audits, and add Lighthouse report service

## Summary

Dogfooding Webomage's own security and performance audit surfaces against live `webomage.com` (`2026-11-04`) exposed concrete first-party audit failures alongside missing productized Lighthouse reporting:

1. **Perimeter Security Audit (`44/100 — Grade F` on `webomage.com`, `cp.webomage.com`, `job.webomage.com`, `join.webomage.com`)**:
   - `apps/web/public/_headers` sets only `Cache-Control` on static asset paths, and `middleware.ts` across `apps/web`, `apps/cp`, `apps/job`, `apps/join`, and `apps/demo` emits only `x-wom-trace-id`. Zero security headers (`Strict-Transport-Security`, `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `X-Frame-Options` / `frame-ancestors`, `Referrer-Policy`, `Permissions-Policy`) are served (`5/35` on HTTP Security Headers, `-30` pts; `-10` pts on HSTS).
   - Cleartext port 80 (`http://webomage.com/`, `http://job.webomage.com/`, `http://join.webomage.com/`) returns `HTTP/1.1 200 OK` instead of `301` redirecting to `https://`, and `http://cp.webomage.com/` returns `302 Location: /login` keeping cleartext `http://` (`-5` pts), because Cloudflare Workers `custom_domain: true` handles port 80 directly when Zone "Always Use HTTPS" is off.
   - DNS anti-spoofing scores `14/25` (`-11` pts): `_dmarc.webomage.com` is in monitoring-only `p=none` (`4/10`) and DNSSEC is unsigned (`0/5`).
2. **Lighthouse 13.4 Web Performance (`64/100`) & Best Practices (`77/100`) Audit (`w0m-web/webomage-lh.json`)**:
   - `https://webomage.com/` measured `FCP: 4.1s`, `LCP: 6.3s`, `Speed Index: 6.1s`, `TTI: 7.6s`, `render-blocking-insight` (`1,980 ms` savings), `image-delivery-insight` (`1,355 KiB` savings + `unsized-images`), `cache-insight` (`776 KiB` savings), `bootup-time` (`4.9s` main-thread JS + `110 KiB` unused JS from eager `client:load` Svelte islands and third-party scripts), `third-party-cookies` (`9` cookies) + `inspector-issues`, and `label-content-name-mismatch` (`0.00`).
3. **Codebase & UI Hygiene on `/audit/`**:
   - `ComplianceAuditCatalogExplorer.svelte` is duplicated across `apps/web/src/components/security/` and `apps/cp/src/components/client/` and renders an internal `<Badge.Root variant="outline">T282</Badge.Root>` ticket badge on the public `/audit/` page.
   - `AuditPricing.svelte` advertises 4-tier SKUs (`Tier 2: $1,490`, `Tier 3: $2,900`, `Tier 4: $5,900`) while `w0m-api/supabase/functions/_shared/stripe-billing.ts` bills Level 3 at `$4,900` and rejects `audit_level: 4` with HTTP `400`.
4. **Lighthouse Test & Remediation Report as a Service (`AgDR-0055` Free-Tier-First)**:
   - Clients ordering a domain-verified website audit in `apps/cp` need an automated Mobile + Desktop Lighthouse & Core Web Vitals report (`Performance`, `Accessibility`, `Best Practices`, `SEO`, `LCP`, `INP`/`TBT`, `CLS`, `FCP`, `TTFB`, plus prioritized asset/script remediation steps) alongside the perimeter security scorecard, backed by Google PageSpeed Insights v5 API (`runPagespeed` — zero-cost edge fetch cached in R2/KV) for instant single-URL diagnostics and Playwright + Lighthouse CI for paid multi-route authenticated web audits.

## Acceptance criteria

- [ ] **AC1 — Shared Perimeter Security Headers & `http -> https` `301` Redirect Across All `w0m-web` Apps (`@webomage/lib/security`, `apps/{web,cp,job,join,demo}/src/middleware.ts`, `public/_headers`)**: Enforce `301` `http://` -> `https://` redirects on non-loopback hosts plus `Strict-Transport-Security` (`max-age=63072000; includeSubDomains; preload`), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`, and a production-safe `Content-Security-Policy` (allowlisting required Cloudflare Turnstile / Supabase origins without `'unsafe-eval'`) across all 5 apps so `evaluatePassiveSecurityPosture` scores `35/35` on HTTP Security Headers and `25/25` on TLS & Transport (`89/100` before DNS changes; `95–100 Grade A` with DMARC + DNSSEC).
- [ ] **AC2 — Remediate Lighthouse Performance (`>= 90`), Best Practices (`>= 95`), Accessibility (`100`), & SEO (`100`) Across Webomage Web Apps**: Eliminate render-blocking head requests, convert below-the-fold `client:load` Svelte islands (e.g. `AuditPricing`, `ComplianceAuditCatalogExplorer`) to `client:visible` / `client:idle`, lazy-load Cloudflare Turnstile only when interactive forms enter viewport or focus (eliminating unprompted third-party cookie / DevTools inspector warnings on initial load), add explicit `width`/`height` and optimized WebP/AVIF + `Cache-Control` headers on images/assets, and fix `label-content-name-mismatch` controls.
- [ ] **AC3 — Productized Lighthouse & Core Web Vitals Audit + Report Service (`@webomage/lib/security/lighthouse-audit.ts`, `apps/cp/src/pages/api/client/lighthouse-audit.ts`, CP Report Viewer)**: Add a domain-ownership-gated (`T623` invariant) Mobile + Desktop Lighthouse & Core Web Vitals runner using Google PageSpeed Insights v5 API (`AgDR-0055` Free-Tier-First edge fetch with KV/R2 snapshot caching, zero database binary blobs) returning category scores, Core Web Vitals (`LCP`, `TBT`/`INP`, `CLS`, `FCP`, `TTFB`), and ranked remediation items inside the Client Portal audit workspace, plus register Lighthouse/CWV multi-route auditing in the commercial catalog.
- [ ] **AC4 — Deduplicate `/audit/` Catalog UI, Remove Leaked Ticket Badges, & Align Checkout SKU Validation**: Consolidate `ComplianceAuditCatalogExplorer.svelte` into a single shared implementation without internal `T282` ticket badges on customer-facing UI, and reconcile `stripe-billing.ts` `AUDIT_PRICES` / `validateAuditCheckoutPayload` with the owner-confirmed commercial catalog SSOT so every advertised tier checks out at its exact displayed price without HTTP `400` or price drift.
- [ ] **AC5 — Continuous Estate Self-Audit Gate (`vitest`, `just audit`, & DNS Runbook)**: Ship automated regression tests asserting every `w0m-web` app's middleware/headers pass `evaluatePassiveSecurityPosture` (`0` critical/high findings, `Grade A` header/TLS posture), built HTML pages enforce image dimensions and non-blocking script rules, `w0m-sec` / `just check-guardrails` codebase gates pass clean, and document the 3 owner-only Cloudflare Zone/DNS switches (`_dmarc.webomage.com` -> `p=quarantine`/`p=reject`, Always Use HTTPS, DNSSEC) to lock in `100/100 (Grade A)` live.
