# T772 — Add oMLX BYOK provider preset and fix keyless local OpenAI-compatible provider requests

## Summary

In OpenDesign (`w0m-pr/open-design`, local sidecar at `127.0.0.1:7456`), `/settings` lists `vLLM` as the only local OpenAI-compatible provider preset (`http://127.0.0.1:8000/v1`), and selecting it or editing a local loopback OpenAI-compatible endpoint fails with `Test failed: baseUrl, apiKey, and model are required` and `Could not fetch models: baseUrl and apiKey are required` because the daemon routes (`/api/provider/models`, `/api/test/connection`, `/api/proxy/openai/stream`), web callers (`InlineModelSwitcher`, `AvatarMenu`, `api-proxy`), and loopback URL detection (`byokProviderRequiresApiKey`, `byok-opencode.ts`) unconditionally require an API key for `openai` protocol.

Add `oMLX` (`jundot/omlx`, default `http://localhost:8000/v1`, `requiresApiKey: false`) to `KNOWN_PROVIDERS` and `BYOK_PROVIDER_PRESETS` (distinct from `vLLM`'s `http://127.0.0.1:8000/v1`), allow keyless loopback `openai` URLs end-to-end across web and daemon (including non-default local ports such as `:8888`) without sending blank `Authorization: Bearer ` headers, prepare GPG-signed upstream PR branch `feat/omlx-provider-keyless-local`, register the proposal in `scripts/w0m_prs.py`, and integrate into `local/sdlc-integration` on `:7456`.
