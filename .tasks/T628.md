# T628 — Build first-party `w0m-obsidian-sync` plugin, native Cloudflare R2 delta-sync protocol, ready-to-open vault bootstrap `.zip`, and revocable device sync tokens

## Summary

Connecting Obsidian Mobile (iOS/Android) to per-engagement vaults (`T580`) via third-party `Remotely Save` + WebDAV suffered from three UX and architectural defects:
1. **1-Hour Expiring JWT Password**: `KnowledgeHub.svelte` instructed users to copy their short-lived browser `sb-access-token` JWT (`1h` TTL) as a static WebDAV password, causing mobile sync to fail with `401 Unauthorized` an hour later.
2. **Chatty WebDAV XML & Manual 6-Step Setup**: Configuring WebDAV URLs, usernames, passwords, and matching local folder names (`T612` guard) inside a third-party plugin on a mobile screen was error-prone, slow over cellular networks, and burned R2 Class A/B operations compared to a single delta manifest (`AgDR-0055`).
3. **Zero Webomage Native Capabilities Inside Obsidian**: `Remotely Save` had no awareness of `obsidian://w0m-connect` 1-tap pairing, multi-engagement hat switching, live project milestones/roadmap telemetry, or Webomage shared todos/checklists.

## Acceptance criteria

- [x] **AC1 — Long-Lived Revocable Vault Sync Tokens & Append-Only Audit Log (`20261103190000_t620_vault_sync_tokens.sql`, `/api/vault/tokens`, `vault-r2-gateway.ts`)**: Created `public.vault_sync_tokens` storing only SHA-256 token digests (`token_sha256 UNIQUE`, `token_prefix`, `profile_id`, `label`, `engagement_public_id`, `expires_at`, `revoked_at`, `last_used_at`) with strict owner/admin RLS and append-only `public.vault_sync_token_audit_log` + `SECURITY DEFINER` trigger (`T613`/`T614`), exposed `/api/vault/tokens` (`GET`, `POST`, `DELETE`) in `ME_APIS`, and authenticated `w0m_vst_...` tokens inside `vault-r2-gateway.ts`.
- [x] **AC2 — Native Cloudflare R2 JSON Delta-Sync & Ready-to-Open Vault Bootstrap `.zip` (`vault-r2-gateway.ts`, `vault-bootstrap-zip.ts`)**: Added single-round-trip JSON delta sync (`POST /api/vault/r2/[engagement]` with `action: "delta_sync"` computing `{ toPull, toPush, unchanged, serverManifest }` by SHA-256/ETag + batch file pull/push directly against `VAULT_R2`) and `GET /api/vault/r2/[engagement]?format=bootstrap-zip` streaming a valid ZIP archive pre-populated with engagement notes, `.obsidian/{app,graph,community-plugins}.json`, and `.obsidian/plugins/w0m-obsidian-sync/{manifest.json,main.js,styles.css}`.
- [x] **AC3 — First-Party `w0m-obsidian-sync` Obsidian Extension (`w0m-ext/obsidian-w0m/`)**: Implemented and bundled mobile-and-desktop compatible (`"isDesktopOnly": false`) Obsidian plugin in `w0m-ext/obsidian-w0m/` featuring: (a) 1-tap `obsidian://w0m-connect` protocol handler pairing endpoint, engagement, and `w0m_vst_` token without manual typing, (b) native R2 JSON delta-sync engine with conflict-safe `.conflict-<ts>.md` preservation and conservative free-tier-friendly sync cadence (`AgDR-0055`), and (c) an integrated **Webomage Engagement, Milestones & Todos** sidebar view inside Obsidian.
- [x] **AC4 — CP Native R2 Pairing & Token Management UI (`KnowledgeHub.svelte`, `VaultSyncPanel.svelte`)**: Upgraded the mobile/desktop connection panel in `KnowledgeHub.svelte` and `/admin/vaults` to lead with **1-Tap Pair in Obsidian (`obsidian://w0m-connect`)**, **Download Ready Vault `.zip` (Plugin Pre-Installed)**, and revocable device token management + live `vault_sync_token_audit_log` timeline (`@webomage/ui` primitives), keeping WebDAV tucked in a legacy compatibility collapsible.
- [x] **AC5 — OpenSpec, Drift Gate & Security/Unit Tests**: Updated `w0m-web/openspec/specs/per-project-vault-topology/spec.md`, built deterministic plugin artifacts (`dist/{main.js,manifest.json,styles.css}`), and passed `supabase_surface_drift_check.py` (`0` findings), `ds_conformance.py --enforce`, `just -f w0m-ext/justfile test-obsidian` (`4/4`), `vault-r2-gateway.test.ts` (`13/13` including expired/revoked token & cross-engagement isolation red-probes), and `pnpm --filter cp build`.

## Definition of Done

Mobile and desktop users can onboard any authorized engagement vault by downloading a pre-configured Vault `.zip` (with `w0m-obsidian-sync` pre-installed and enabled) and tapping a single `obsidian://w0m-connect` deep link backed by a revocable, SHA-256-hashed `w0m_vst_` device token logged in `vault_sync_token_audit_log`; bi-directional vault sync runs natively over the JSON R2 delta-sync endpoint without WebDAV XML or 1-hour JWT expiry, and the Obsidian sidebar renders engagement switching, roadmap milestones, and synced todos, verified by unit/red-team tests across `w0m-ext` and `w0m-web`.
