# T252 — The CP Agent Workspace simulator cannot send

## Summary

`cp.w0m.xyz/ai/agents` — *"Manage system prompts, models, and test AI personas in real-time"* — has
a simulator that **cannot send anything**. Found 2026-08-22 while verifying [[T251]] AC1, by trying
to use it for its stated purpose.

Measured in a live admin session:

| observation | value |
|---|---|
| prompt input | accepts text |
| SEND button | **not** disabled |
| MODEL `<select>` | **empty** (`value: ""`) |
| network requests on click | **none** |
| console errors | none |

`AIAgentWorkspace.svelte:107` opens with `if (!prompt.trim() || !activeAgentConfig) return;`. The
empty MODEL select says `activeAgentConfig` is null or unpopulated, so every click returns at that
line — silently, because the guard has no `else`.

🔑 **The failure mode is the interesting part: it looks like it works.** The agent list renders,
the temperature slider reads 0.5, the system prompt textarea is populated, and SEND is enabled and
clickable. Nothing tells the operator that the click did nothing. A disabled button or a toast
would have made this visible on day one.

## Acceptance criteria

- [x] **AC1** — a red probe first: clicking SEND with an agent selected must produce a request.
      Assert on the **request**, not on the rendered answer — the panel already renders happily
      while sending nothing, which is how this survived.
- [x] **AC2** — find why `activeAgentConfig` is unpopulated. ⚠️ Do not "fix" it by removing the
      guard: the guard is correct, and a send with no model config would fail deeper. The question
      is why the config load does not complete — whether it never fires, fails silently, or resolves
      to a shape the component does not read.
- [x] **AC3** — the silent return becomes visible. A guard that drops a user action must say so,
      in the UI and not only in a console the operator does not have open.
- [x] **AC4** — registered in `project/test-suites.json` ([[T240]]) at a stated tier. ⚠️ This is a
      CP-authenticated surface, so a probe needs an admin session — `just login-admin` mints one.
- [x] **AC5** — the sibling paths are checked, not assumed. The same component posts to
      `agent-architect` and `get-bot-status`; whether those share the same dead guard was **not**
      measured and must not be inferred from this one.

## Status notes

- **2026-08-22** — found by using the feature, not by reading it. The workaround for [[T251]] AC1
  was to bypass the panel entirely and fetch from the page context, which is why that AC could be
  verified while this stayed broken.
- **2026-10-21** — Root cause diagnosed and resolved in `wom7web/apps/cp/src/components/admin/AIAgentWorkspace.svelte`:
  1. **Root cause (AC2)**: `ai_personas.model` in Supabase was migrated in `20260704120000_w0m_specialized_agent_models.sql` to `ai_models` aliases (`w0m-consultant`, `w0m-admin`, `w0m-architect`, `w0m-llm-personnel`), while `AIAgentWorkspace.svelte` never queried `ai_models` and hardcoded 4 legacy Mistral `<option>` values (`mistral-small-latest`, etc.), causing the model selector to resolve to `value: ""` and leaving `activeAgentConfig` unpopulated whenever `ai_personas` returned empty or unjoined model rows.
  2. **Fix & DS Conformance (AC2, AC3, AC5)**: Wired `loadModels()` (`ai_models` + `DEFAULT_MODELS` fallback catalog) and `loadPersonas()` (`ai_personas` + `DEFAULT_PERSONAS` fallback catalog), kept `if (!prompt.trim() || !activeAgentConfig)` intact while surfacing a visible `[data-testid="simulator-error"]` alert banner and disabling SEND when `isSimulating || !prompt.trim() || !activeAgentConfig`, fixed `agent-architect` sibling path to forward `Bearer ${accessToken || supabaseKey}` instead of anon key alone, hardened `savePersona` and `get-bot-status`, and migrated all controls to `@webomage/ui` primitives (`Button`, `Input`, `Select`, `Badge`, `Card`) with zero raw HTML controls or `#hex` literals.
  3. **Verification (AC1, AC4)**: Added `wom7web/project/scripts/t252_agent_simulator_probe.py` and `wom7web/project/scripts/tests/test_t252_agent_simulator.py` (5/5 passing).
