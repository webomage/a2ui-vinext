# T612 — Guard Obsidian URI launches per engagement to prevent mobile last-vault fallback and cross-project vault collisions

## Summary

Opening the Webomage (`w0m` / `eg-w0m`) Knowledge Hub as a `client` on mobile (`/o/webomage/projects/vault`) and tapping `💎 Open in Obsidian` invoked a raw `obsidian://open?vault=w0m&file=index` anchor (`KnowledgeHub.svelte`). Because `obsidian://open?vault=<name>` cannot create a vault or fetch from Cloudflare R2—and Obsidian iOS/Android silently falls back to opening the user's **last active local vault** when `<name>` does not exist on the device—Obsidian iOS opened the user's unrelated empty local vault `Servicios777.mx` (live Supabase `project_vaults`, `vault_notes`, and R2 had zero cross-tenant data leakage).

In addition:
1. Inline `obsidian://` links inside rendered note bodies (`.obsidian-content`) bypassed validation, and `/admin/vaults` exposed raw `obsidian://open?vault=<id>&file=index` links on mobile cards.
2. `preprocessWikilinks` in `w0m-web/apps/cp/src/lib/vault-parser.ts` hardcoded `${baseUrl}?file=${encodedTarget}` and `KnowledgeHub.svelte` omitted `?engagement=<engagementPublicId>` from `effectiveClientBaseUrl`, dropping `?engagement=` or emitting malformed `?engagement=...?file=...` URLs on multi-vault organizations (`maksim-kulikov`: `eg-personaje0` vs `eg-servicios777`).
3. Root `index.md` notes across all 5 declared project vaults (`w0m`, `1945`, `artemio`, `servicios777`, `personaje0`) in `w0m-web/projects/*/vault/index.md` and `w0m-api` (`public.vault_notes`) listed bare `obsidian://open?vault=<slug>` links without documenting the local-vault creation prerequisite or mobile last-vault fallback rule.

This ticket permanently eliminates unguarded `obsidian://open` launches, enforces fail-closed cross-engagement local vault name collision checks against `clients-policy.json`, preserves `?engagement=` across wikilink navigation, synchronizes all 5 vault `index.md` notes across `w0m-web` and `w0m-api`, and provides an inline `@webomage/ui` pre-flight setup & launch guard with 1-tap R2 WebDAV credentials.

- [x] **AC2 — Guarded `KnowledgeHub.svelte` Pre-Flight Modal, Inline `obsidian://` Interception & R2 WebDAV Setup (`@webomage/ui`)**: Replaced the raw `<a href={obsidianUri}>` anchor in `KnowledgeHub.svelte` with `@webomage/ui` `Button` + `Dialog` pre-flight guard (plus a persistent `⚙️` rebind/reset control and `onLaunchObsidianUri` test seam), intercepted inline `a[href^="obsidian://"]` clicks inside `.obsidian-content` via Svelte action `use:interceptContentLinks` (blocking foreign-vault and `path=` URIs fail-closed), warned explicitly about Obsidian iOS/Android's missing-vault fallback to the last active vault, surfaced 1-tap copy for the engagement's R2 WebDAV URL and JWT token alongside validated local vault confirmation (`Checkbox` + `Input` + `Label`), and proved DOM interaction in `KnowledgeHub.test.ts` (`4/4` passing).

## Definition of Done

No client or operator viewing a Knowledge Hub in `cp.webomage.com`—on iOS, Android, or desktop—can trigger an unconfirmed `obsidian://open` deep link or bind a local vault name that collides with another declared engagement or multi-vault organization in `clients-policy.json`, multi-engagement `[[wikilink]]` navigation preserves `?engagement=<public_id>` without malformed query strings, and all five project vault `index.md` notes in both `w0m-web` and `public.vault_notes` (`w0m-api`) document the local-vault creation prerequisite (`spec_policy` compliant via `openspec/changes/archive/2026-11-02-t612-obsidian-vault-launch-guard`).
