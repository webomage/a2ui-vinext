# T612 — Guard Obsidian URI launches per engagement to prevent mobile last-vault fallback and cross-project vault collisions

## Summary

Opening the Webomage (`w0m` / `eg-w0m`) Knowledge Hub as a `client` on mobile (`/o/webomage/projects/vault`) and tapping `💎 Open in Obsidian` invoked a raw `obsidian://open?vault=w0m&file=index` anchor (`KnowledgeHub.svelte`). Because `obsidian://open?vault=<name>` cannot create a vault or fetch from Cloudflare R2—and Obsidian iOS/Android silently falls back to opening the user's **last active local vault** when `<name>` does not exist on the device—Obsidian iOS opened the user's unrelated empty local vault `Servicios777.mx` (live Supabase `project_vaults`, `vault_notes`, and R2 had zero cross-tenant data leakage).

In addition:
1. Inline `obsidian://` links inside rendered note bodies (`.obsidian-content`) bypassed validation, and `/admin/vaults` exposed raw `obsidian://open?vault=<id>&file=index` links on mobile cards.
2. `preprocessWikilinks` in `w0m-web/apps/cp/src/lib/vault-parser.ts` hardcoded `${baseUrl}?file=${encodedTarget}` and `KnowledgeHub.svelte` omitted `?engagement=<engagementPublicId>` from `effectiveClientBaseUrl`, dropping `?engagement=` or emitting malformed `?engagement=...?file=...` URLs on multi-vault organizations (`maksim-kulikov`: `eg-personaje0` vs `eg-servicios777` or staff engagement switcher).

This ticket permanently eliminates unguarded `obsidian://open` launches, enforces fail-closed cross-engagement local vault name collision checks against `clients-policy.json`, preserves `?engagement=` across wikilink navigation, and provides an inline `@webomage/ui` pre-flight setup & launch guard with 1-tap R2 WebDAV credentials.

## Acceptance criteria

- [x] **AC1 — Per-Engagement Obsidian Launch Guard & Fail-Closed Cross-Vault Name Validation (`apps/cp/src/lib/obsidian-launch.ts`)**: Implemented pure, unit-tested helpers (`validateLocalVaultNameForEngagement`, `parseObsidianOpenUri`, `readObsidianVaultBinding`, `saveObsidianVaultBinding`, `clearObsidianVaultBinding`, `resolveObsidianLaunch`, `isMobileObsidianClient`) backed by `getAllDeclaredKnowledgeHubBoundaries()` (`clients-policy.json`) that block cross-engagement local vault names and shared multi-vault org slugs fail-closed (rejecting `Servicios777.mx`, `servicios777`, `personaje0`, `artemio`, `1945`, and generic `vault` when launching `eg-w0m`, and vice versa), parse custom-scheme `obsidian://` URIs identically across WebKit/iOS Safari and Chromium without `new URL()` opaque-pathname bugs, isolate persisted device bindings per `engagementPublicId`, and never fire `obsidian://open` without an explicit per-engagement local vault confirmation (`10/10` tests passing in `obsidian-launch.test.ts`).
- [x] **AC2 — Guarded `KnowledgeHub.svelte` Pre-Flight Modal, Inline `obsidian://` Interception & R2 WebDAV Setup (`@webomage/ui`)**: Replaced the raw `<a href={obsidianUri}>` anchor in `KnowledgeHub.svelte` with `@webomage/ui` `Button` + `Dialog` pre-flight guard (plus a persistent `⚙️` rebind/reset control), intercepted inline `a[href^="obsidian://"]` clicks inside `.obsidian-content` via Svelte action `use:interceptContentLinks` (blocking foreign-vault and `path=` URIs fail-closed), warned explicitly about Obsidian iOS/Android's missing-vault fallback to the last active vault, and surfaced 1-tap copy for the engagement's R2 WebDAV URL and JWT token alongside validated local vault confirmation (`Checkbox` + `Input` + `Label`).
- [x] **AC3 — Multi-Engagement Wikilink Query Preservation & `/admin/vaults` Mobile Guard (`vault-parser.ts`, `KnowledgeHub.svelte`, `vaults.astro`)**: Fixed `preprocessWikilinks` in `vault-parser.ts` to join `file=` with `&` when `clientBaseUrl` already carries query parameters (`14/14` tests passing in `vault-parser.test.ts`), scoped `effectiveClientBaseUrl` in `KnowledgeHub.svelte` with `?engagement=<engagementPublicId>` when `vaults.length > 1` (plus client-side `.obsidian-wikilink` navigation), and restricted raw `obsidian://open` anchors in `apps/cp/src/pages/admin/vaults.astro` to desktop viewports (`hidden sm:inline-flex`) in favor of `👁️ View Hub` on mobile.
- [x] **AC4 — TDD Verification & Design System Conformance (`vitest`, `ds-conformance`, `cp` build)**: Verified `39/39` passing Vitest assertions across `obsidian-launch.test.ts` (`10/10`), `vault-parser.test.ts` (`14/14`), `vault-reader.test.ts` (`9/9`), and `vault-security-probe.test.ts` (`6/6`), passed `w0m-web` Design System token & control conformance gates (`T207`, `T93`, `oxlint` 0 warnings/0 errors, `svelte-check` 0 errors), and verified `pnpm --filter cp build` (`dist/` CSS verified across 8 bundles).
