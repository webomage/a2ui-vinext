# T791 — Align client milestones with hybrid quest tracks, render CF security audit coverage ledger, badge migration teaser, and fix billing portal role check

## Summary

Four client CP portal surface defects identified during live review:

1. **Client Milestones Empty State**: On `/o/[org]/projects/milestones`, `milestones.astro` only queries `client_milestones` linked to `public.contracts`. For client organizations with 0 direct contracts (e.g. `webomage`), it displays "No milestones found on your account", while the Knowledge Hub right next to it displays 9 milestones (44% complete) synthesized from `projects.metadata.quest_tracks`.
2. **Cloudflare Security Audit Skill Panel Blank**: In `SecurityAuditReportViewer.svelte`, the panel title promises "Structured Findings & Coverage Ledger". When a domain has 0 actionable findings, `findings` is empty and the `#each` block renders a 0-height empty white card with no clean-posture indicator, while `coverage_ledger` (trust boundaries, entry points, sinks, follow-up actions) is never rendered.
3. **Misleading Cloud Migration Teaser**: In `SecurityAuditReportViewer.svelte`, `runK7SmartInfraAndMigrationAudit()` synthesizes a canned mock migration plan from AWS to Cloudflare with hardcoded toolchain cards and claims of extracted AWS/K8s resources, presenting it as an active discovery without stating it is an interactive sample/simulation.
4. **Billing Portal Role Check Rejection**: In `w0m-api/supabase/functions/stripe-portal/index.ts`, role verification still queries the legacy `public.user_roles` table for `role = 'client' OR role = 'admin'`, rejecting modern client stakeholders wearing engagement hats with `403 Forbidden: Client or Admin role required`.

## Acceptance criteria

- [x] AC1 — `/o/[org]/projects/milestones` resolves hybrid quest track milestones via `loadProjectDeliveryTelemetry` / `questTracksToRawMilestones` when contract-linked milestones are empty, rendering the 9 delivery tracks in `MilestoneList.svelte`.
- [x] AC2 — `SecurityAuditReportViewer.svelte` renders a clean-posture empty state when `report.cfSecurityAudit.findings` has 0 items, and always renders the `coverage_ledger` (trust boundaries covered, entry points reviewed, sinks checked, and follow-up guidance).
- [x] AC3 — `SecurityAuditReportViewer.svelte` badges the cross-cloud migration plan explicitly as an Interactive Simulation / Sample Migration Calculator, preventing confusion with live discovered customer infrastructure.
- [x] AC4 — `stripe-portal` Edge Function accepts active engagement hats (`client`, `client.member`, `client.stakeholder`, `admin`) and verified client organization membership, eliminating false 403 rejections for modern client stakeholders.
- [x] AC5 — Unit and component regression tests in `w0m-web` and `w0m-api` prove clean posture rendering, quest track milestone fallback, teaser badging, and authorization checks.
- [x] AC6 — `security-audit.astro` and `SecurityAuditReportViewer.svelte` enforce project and client tenancy boundaries: when wearing an active project hat (e.g. Solar Mobile), scope audit targets to the project/client domain and hide Webomage first-party estate domains from non-estate views.
