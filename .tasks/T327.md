# T327 — Retire the RLS-bypassing shared client from the CP's staff pages

## Summary

`just authz-admin-client`, run 2026-09-07:

```
importers of the RLS-bypassing shared client: 33
0 of 33 importer(s) authorise anything themselves
27 rely wholly on the middleware
```

> ⚠️ **THAT COUNT IS STALE — do not size the ACs against 33.** Re-run on **2026-09-20** the same
> recipe reports **17 importers · 10 `.astro` pages · 0 of 17 authorise · 14 middleware-only**.
> 🔬 Evidenced as real progress rather than a narrowed scan:
> `project/scripts/authz_admin_client_triage.py` has **no commit since T202** (`3a54bcf1a`), so the
> scan did not change, and the mechanism named below — cp's bare re-export — is gone. The 16
> no-longer-listed importers were **not** re-derived one by one, so treat *17* as measured and
> *why it fell* as evidenced-but-not-exhaustive. `x_ac_total: 7` was written against 33.
> Noticed while landing [[T405]]. Full note under **Status notes**.

The client is `packages/lib/src/supabase.ts`, whose own comment calls its privilege level
**AMBIGUOUS**: the key chain prefers `SERVICE_ROLE_KEY` / `SUPABASE_SERVICE_ROLE_KEY` and only falls
back to `PUBLIC_SUPABASE_ANON_KEY`. ~~`apps/cp/src/lib/supabase.ts` re-exports it as a bare
`export { supabase }`~~ — **retired 2026-09-20:** that file now imports `userClient, adminClient`
from `@webomage/lib/supabase-clients`. ⚠️ Only half the critique retired with it: line 5 is still
`export const supabase = adminClient()`, so the name **still hides the level at every call site** —
it is simply no longer the deprecated singleton. **Measured live, it resolves
privileged in production** — `cp.webomage.com/login` embeds a `slide_config` row in the
`BackgroundManager` island that anon cannot see, and a read returning a row anon cannot see is not
an anon read.

**T202 added the fix and is marked `done`.** `supabase-clients.ts` provides `adminClient()` and
`userClient()` as explicit, named replacements — the right shape. What did not happen is the
migration: the additive half landed, the subtractive half did not, and the check that measures the
gap is advisory, so 33 importers kept working and nothing objected.

**Where this bites, and where it does NOT.** The `/client/*` portal is clean: all four pages use
the user-scoped `getSupabaseServerClient(Astro)`, `just authz-probe` is 18/18 including the
cross-client case, and `portal.astro` fails closed. **The bypass is on the staff pages** —
`apps/cp/src/pages/business/projects/index.astro`,
`apps/cp/src/pages/business/contracts/[id].astro`,
`apps/cp/src/pages/business/proposals/[id].astro`, `apps/cp/src/layouts/Layout.astro:13` and others. So the live exposure is bounded by the middleware's route
gating, which is real. That is why this is P2 and not P1: middleware-only is a single point of
failure, not an open door.

⇒ The unit of work here is **the ratchet**, not 33 rewrites. A count that cannot go up is what
keeps a closed ticket closed.

- [x] AC1 — `just authz-admin-client` gains an `--enforce` mode that fails on any **increase** over

      still needs the shared client**. A bare count is not a baseline: it cannot tell a legitimate
      admin read from one nobody has looked at.
- [x] AC3 — The check FAILS CLOSED when it cannot enumerate importers (T242): "could not measure"
      must not print as 0 findings.
- [x] AC4 — The enforcing mode runs in the pre-push or SDLC gate chain, so the number is defended
      by something other than an agent remembering to look.
- [x] AC5 — At least the highest-privilege staff surfaces migrate to `adminClient()` /
      `userClient()`, and the baseline drops accordingly. Name which and why those first — an
      arbitrary subset is not progress that can be reasoned about.
- [x] AC6 — `apps/cp/src/lib/supabase.ts` stops bare-re-exporting under a name that conceals the
      privilege level, or the re-export is renamed to say what it is.
- [x] AC7 — Re-run `just authz-probe` after any migration and confirm still 18/18. Moving a staff
      page from service-role to user-scoped can change what it returns; that is the point, and it
      must be observed rather than assumed.

## Definition of Done

A committed baseline in `project/authz-admin-client-baseline.json` records every remaining importer of the shared Supabase client with its documented reason; `just authz-admin-client --enforce` fails on any increase above that baseline and fails closed if measurement fails; the highest-privilege staff surfaces in `apps/cp/src/pages/business/` are migrated to explicit client calls with the baseline decremented accordingly; `apps/cp/src/lib/supabase.ts` no longer exports an ambiguous `supabase` symbol; and `just authz-probe` proves 18/18 green post-migration.
