# T400 — wom7func Reliability: Retry policies, DLQ handling, and structured health logging for Cloudflare Workflows

## Summary

Enhance reliability and observability for background workflows running in `wom7func` and `wom7api`. Establishes standardized retry semantics, dead-letter queue (DLQ) storage for failed workflow steps, and structured health logging for monitoring.

## Acceptance Criteria

- [x] AC1 — Configure explicit exponential backoff retry policies for all scheduled workflow steps (`DEFAULT_WORKFLOW_STEP_RETRY`, `buildStepRetryConfig()`, `computeBackoffMs()`, and `runReliableStep()` wired across `wom7func/src/workflows/*.ts` and all 19 Cloudflare Workflow classes in `wom7api/src/workflows/*.ts`).
- [x] AC2 — Implement DLQ capture mechanism storing failed execution payloads for replay and analysis (`WorkflowDlqCapture`, `captureWorkflowDlq()`, and `replayWorkflowDlqEntry()` with recursive secret redaction, bounded in-memory storage, KV persistence, and step replay verification).
- [x] AC3 — Standardize structured JSON logging across all handlers in `wom7func` and workflows in `wom7api/src/workflows/` (`logWorkflowEvent()` and `logHandlerHealth()` emitting structured JSON envelopes for step/handler start, retry, completion, skip, DLQ capture, and failure).
- [x] AC4 — Author automated unit tests verifying retry boundaries and error propagation (`wom7func/src/__tests__/workflow-reliability.test.ts` — 10 tests; `wom7api/src/workflows/__tests__/workflow-reliability.test.ts` — 3 tests).
- [x] AC5 — Verify `pnpm test` and `pnpm exec tsc --noEmit` pass cleanly in `wom7func` (0 TypeScript errors; 8 test files / 56 tests passing in `wom7func`, plus 4 workflow test files / 39 tests passing in `wom7api`).
