# T172 — the governed serena config is not the one in effect

## Summary

Found 2026-08-06 while clearing [[T166]]'s archive gate — and found *by* clearing it, which is the
point. [[T166]] required serena to be proven by a **real tool call** rather than `serena --version`.
The call succeeded. It also returned the paths that showed T166 governs the wrong files.

`find_symbol` returned name paths rooted at **`@wom/`**:

```
@wom/wom7web/project/scripts/state_doctor.py
```

That is not `wom7web`'s project. serena had activated **`/Users/proto/Projects/@self/@wom/.serena/project.yml`**
(`project_name: "@wom"`), the **umbrella directory**.

🔴 **`@wom` was not a git repository.** Measured 2026-08-06:

```
./.serena          git repo: NO      ← the config actually in use
wom7web/.serena    git repo: true    ← versioned, tracked, governed by T166
wom7api/.serena    git repo: true    ← versioned, tracked, governed by T166
```

⇒ **T166 versioned the two configs a session at `@wom` never reads, and the one it does read was
versioned nowhere.** T166 reads 7/7 and is otherwise genuinely done; this is not a reason to reopen
it, it is the reason its archive should carry this ticket forward.

✅ **Re-measured 2026-09-08 — the first half of that finding no longer holds:**

```
./.serena          git repo: true    ← casualuser/w0m, since 2026-09-02; project.yml TRACKED
wom7web/.serena    git repo: true
wom7api/.serena    git repo: true
```

The workspace root became **`casualuser/w0m`** (PRIVATE, default `beta`, 100 tracked files) on
**2026-09-02**, and `@wom/.serena/project.yml` is tracked in it — so **D32 is paid down** (under
[[T312]], commit `30963813`) and this ticket's *unversioned* premise is closed.

🔴 **What is NOT closed is the reason the ticket exists.** All three configs are versioned and
**nothing reconciles them**: the root still declares `typescript, svelte, python` against
wom7api's `typescript, python`, and a session rooted at `@wom` still silently activates a
different config from the one T166 governs. ⇒ **Versioned is not reconciled.** Scope T172 to the
divergence, not to the versioning — and do not re-file the versioning half.

## Why this is the same class of error the estate keeps hitting

This is the **seventh** recorded instance of *a confident measurement whose method looked in the
wrong place* (see `STATE.md` §0z/§0n/§0u, T135's preflight, the Astro 4/5 `content.config.ts` path,
`state_doctor`'s 0-of-155 board rows). The shape is identical: the check was well-formed and passed;
it was pointed at the wrong object.

And it is the specific sub-shape T166 already warned about in its own AC1b correction — *verify by
using it, not by starting it*. Using it is exactly what exposed this. **The lesson generalises:
after proving a tool works, read WHICH artefact it reported on before concluding the governed one
is live.**

⚠️ Note what T166 AC2 actually says: *"`.serena/` is gitignored in every repo where it appears
(`wom7api/`, monorepo root, …)"*. **The monorepo root was named.** The AC was satisfiable as
written and still left the gap, because at the root there is no repo to gitignore *into* and no
history to version *in*. An AC can be met and miss.

## Consequences today

1. **serena's coverage at `@wom` is a property of one laptop.** The whole point of versioning
   `project.yml` (owner decision 2026-08-05) was that which languages serena can see must not be a
   per-machine accident. At the umbrella it is exactly that again.
2. **The `@wom` config is the one that decides real behaviour** for any session whose cwd is the
   umbrella — which is the common case, since `@wom` is the workspace root.
3. **Its language set differs from the per-repo ones and nothing reconciles them.** Measured
   2026-08-06: `@wom` declares `typescript, svelte, python`; `wom7api` declares `typescript,
   python`. A drift here is silent.
4. **serena rewrites these files in place.** See [[D33]] — on 2026-08-06 it migrated all three and
   stripped their T166 headers.

## Acceptance criteria

- [x] AC1 — **Decide which config is authoritative, and record the decision.** Three coherent
      options, and this ticket does not presume one:
      (a) make `@wom` a git repo (it is currently an unversioned workspace directory — a big change
      with consequences well beyond serena);
      (b) treat the umbrella config as **generated** from the per-repo ones by a `just` recipe, so
      it is reproducible even though it is untracked;
      (c) **stop using an umbrella project** — require serena sessions to activate a per-repo
      project, and fail loudly if the active project is `@wom`.
      **DONE 2026-10-21 — Option (a)+(b):** `@wom` is a versioned git repository (`casualuser/w0m`),
      so `@wom/.serena/project.yml` is versioned and authoritative for umbrella sessions, and its
      language set is reconciled against the exact union of member repo `.serena/project.yml` configs
      (`wom7web` ∪ `wom7api`: `typescript`, `svelte`, `astro`, `python`) by
      `wom7web/project/scripts/serena_config_check.py`, which also enforces that all three configs
      remain git-tracked and carry the T166/T172 governance comment header (closing the [[D33]]
      silent-header-stripping detection gap).
- [x] AC2 — **The active project is verifiable, not assumed.** A `just` recipe (or an extension of
      `just tools-check`) reports **which** serena project is active and whether that config is
      version-controlled. Today the only way to learn this is to read the name path prefix out of an
      unrelated tool result.
      **DONE 2026-10-21:** `wom7web/project/scripts/serena_config_check.py` accepts `--cwd <dir>`
      (defaulting to current working directory), walks up parent directories just as
      `serena start-mcp-server --project-from-cwd` does, and reports the activated `project_name`,
      resolved `.serena/project.yml` path, language list, git-tracking status (`git ls-files --error-unmatch`),
      and governance header status.
- [x] AC3 — **Language-set drift between the umbrella and per-repo configs is detected**, or made
      structurally impossible by AC1's choice.
      **DONE 2026-10-21:** `serena_config_check.py` verifies that every member config's language set
      (`wom7web`, `wom7api`) is a subset of `@wom/.serena/project.yml` and that `@wom/.serena/project.yml`
      equals the exact union (`wom7web` ∪ `wom7api`), exiting `1` on any missing or extra language or
      untracked/ungoverned config. Restored T166/T172 governance headers to `@wom/.serena/project.yml`,
      `wom7web/.serena/project.yml`, and `wom7api/.serena/project.yml`.
- [x] AC4 — **Proven RED before green**, per the T130/T164 precedent: point the check at a
      deliberately unversioned/ungoverned config and show it fails. A check that has only ever been
      seen passing is a hypothesis.
      **DONE 2026-10-21:** Proven RED both against the live workspace before restoring the D33-stripped
      governance headers (`❌ serena-config-check FAILED (4 issue(s))`, exit 1) and via automated
      regression suite `wom7web/project/scripts/tests/test_serena_config_check.py` (5/5 tests:
      untracked temp `.serena/project.yml` exits 1, dropped `svelte`/`python` or extra language exits 1
      naming the language-set drift, stripped governance header exits 1, `--cwd` parent walk resolves
      `@wom`/`wom7web`/`wom7api`, and live estate exits 0).
- [x] AC5 — **[[T166]]'s AC2 is annotated in place** with what it did and did not cover, rather than
      silently re-scoped. T166 is finished work; this is the correction, not a reopening.
      **DONE 2026-10-21:** Annotated AC2 in `.tasks/T166.md` in place recording the completion of
      `@wom/.serena/project.yml` governance and cross-repo language-set reconciliation under [[T172]].
