# T317 — Master the client-hat CP flow: audit, spec, test, then apply real DS components

## Summary

Owner ask 2026-09-05: *"I want to master user flows step by step for 1. client 2. PM 3. TPM
4. Dev — first in specs and tests and then visually with real DS components."* This is the
**first of four sequential per-hat flow-mastery tickets** (client → PM → TPM → Dev), scoped
here to the **client** hat only; PM/TPM/Dev follow as their own tickets once this one closes.

Four prior tickets already proved pieces of this, and none is being re-done: [[T283]] proved the
exact technique this ticket generalizes — *"walking a surface is not a slower version of probing
it; it answers a different question"* — by walking the client flow as the real client and fixing
3 concrete UX defects (a fabricated demo-data invoice on a real account, `/client` 404ing, and an
unstyled link caused by a CSS cascade-layer bug), leaving `client-portal-firstrun-test` (10/10,
blocking) as the regression guard. [[T266]] proved the client persona's tenancy and first-run
flow with real data and a real sign-in (`just artemio-tenancy-probe` 9/9,
`client-page-tenancy-test` 22/22, `eva@webomage.com` signed in live 2026-08-25). [[T313]] AC7
smoke-tested that wearing the client hat exposes `/client/portal`, `/client/milestones`,
`/client/invoices`, `/client/proposals`. ⚠️ [[T207]] AC4 (2026-08-13) also names a client-portal
defect (`ClientLayout` linking to a nonexistent `/client` route) — that specific line is now
**stale**: [[T283]] AC4 closed it 2026-08-25, three weeks before this ticket, so it must not be
re-reported as a fresh finding. None of the four turned their findings into a **systematic
inventory**, a **flow-level spec**, or a **comprehensive real-`@webomage/ui` application** across
the client hat's pages — that gap is this ticket. Confirmed live via codegraph 2026-09-05:
`ClientLayout.astro` already imports `DemoBanner`/`Walkthrough`/`AuthWidget` from `@webomage/ui`,
but its own sidebar nav markup is still raw Tailwind — a concrete AC5 target, not a guess. Uses
[[T310]]'s universal hat switcher (admin can wear the client hat on any project without a
separate real account) and the Playwright / Chrome DevTools MCPs for live verification against
`localhost:4321` (`just redev`).

## Definition of Done

T317 is done when a client — or an admin wearing the client hat via [[T310]] — can walk
sign-in → portal → milestones → invoices → proposals → account as one continuous live-browser
session with zero dead ends and zero fabricated demo data on a real account, every native or
ad-hoc-styled control on those pages replaced by a shipping `@webomage/ui` primitive per the
`client-cp-flow` spec's scope boundary against unbuilt [[T92]], and [[T283]]'s
`client-portal-firstrun-test` extended (not replaced) and green. Proven by AC6's live walk and its
captured screenshots/snapshots, not by inspection of the diff alone.
