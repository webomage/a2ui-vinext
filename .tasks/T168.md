# T168 — Retire the dead Upwork content collections + dead `lib/vault.ts`, or wire them up

## Summary

`apps/{web,cp}/src/content.config.ts` each define an Upwork `proposals` and `contracts` Astro
content collection — ~90 lines of zod apiece, with `z.preprocess` normalisation for Upwork's
inconsistent field names — that **Astro never loads**. Found 2026-08-05 while doing
[[T165]] Phase 0.4; deliberately not fixed there, as it is outside that ticket's scope.

**They are dead three times over**, each verified live on 2026-08-05:

1. **Not exported.** `apps/web/src/content.config.ts:267` and `apps/cp/src/content.config.ts:349`
   both read `export const collections = { cases, pages, tracks };`
2. **Pointed at a directory that does not exist.** Both loaders use
   `base: 'src/content/upwork_vault/…'`. **`src/content/upwork_vault/` is absent from both apps.**
   The 859 markdown files live at `src/data/upwork_vault/`. Exporting the collections as-is would
   therefore not fix anything — it would fail or yield an empty collection.
3. **No consumer, and never had one.** The only `getCollection` calls anywhere in `apps/` are
   `getCollection("cases")` ×2. Nothing has ever referenced `proposals` or `contracts`.

⚠️ **This is dead-on-purpose, not an accidental omission** — established from git history, which
changes the fix. Commit **`3640ee69` (2026-02-10)**, *"chore: reduce worker size < 3MB by static
prerendering and fs-loader for vault"*, did all of this in one move:

```diff
-export const collections = { blueprints, cases, pages, tracks, proposals, contracts };
+export const collections = { blueprints, cases, pages, tracks };
```

…and simultaneously `git mv`'d `src/content/upwork_vault/` → `src/data/upwork_vault/`. **The
removal was load-bearing: the content layer bundles into the Cloudflare Worker, and the vault
pushed it over the 3 MB limit.** The collection *definitions* were simply left behind. The Astro 6
rewrite (**`46b2ffb6`, 2026-04-30**) then re-authored `content.config.ts` from scratch and **copied
the dead definitions forward**, so they are now dead code that survived a full rewrite.

**The replacement is dead too.** `apps/{web,cp}/src/lib/vault.ts` (124 lines) reads the vault with
`import.meta.glob('/src/data/upwork_vault/…', { eager: true })` — but it has **zero importers in
either app**, re-verified 2026-08-05. [[T121]] measured the same thing on 2026-07-25 and recorded
it as *"a separate cleanup, not a security issue — noted here rather than filed"*. **This ticket is
that filing.** ⚠️ T121 also guessed the cleanup *"overlaps the vault work already tracked under
[[T90]]"* — **it does not.** T90's "vault" is the Supabase-backed admin contract/proposal managers
and the `/business/vault` page; this is the markdown corpus. Two different things sharing a word.

⚠️ **The two apps have already diverged over this.** [[T115]] (2026-07-22, `12e4d0a5`) reports it
*"`_`-prefixed 2 dead content collections the oxlint ratchet surfaced"* — but **only in `cp`**:

| | web | cp |
|---|---|---|
| collection names | `proposals` / `contracts` | **`_proposals` / `_contracts`** |

So the same dead code is marked-dead in one app and not the other, and the linter is satisfied in
exactly one of them. Any fix must land in **both**.

**Why this is P3 and not P2:** nothing is broken at runtime. Dead code that never executes has no
user-visible effect. The cost is that four separate sessions have now had to re-derive that these
collections are dead — [[T115]], [[T121]], [[T165]] Phase 0.4, and this ticket — which is precisely
the tax that a TECH-DEBT row exists to stop.

**⚠️ Do not delete blindly — the zod is the only written description of the vault's shape.**
`lib/vault.ts` performs **zero validation** (`@ts-ignore`, bare `module.frontmatter || {}`, and an
in-file comment recording an unfixed large-number YAML precision bug). If both are deleted, the
corpus that [[T155]] curates and [[T165]]/[[T167]] consume has no schema anywhere. Salvage the zod
into T165's importer, or record where it went — AC4.

Still recorded honestly: removing the zod lost the last written *schema* but **zero enforcement** — nothing ever loaded it and `lib/vault.ts` validated nothing.
