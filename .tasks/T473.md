# T473 — Deploy from tagged releases in an isolated worktree

## Summary

Owner, 2026-09-27: "do release tag versions for deploys at git across all repos and check out a separate worktree to
call deploy independently from there without any mutations from outside"; "the main worktrees could be dirty at any
time and receive simultaneous updates from agents and people"; "keep as an option to force deployment from the local
dirty beta worktree, but the default and safe common way is from separate worktrees with a git tag version across all
parts involved". Four deploys in a row on 2026-09-27 tested and shipped another session's uncommitted drafts (spec
drafts, ticket fields, a migration not in any commit).

## Acceptance criteria

- [ ] AC1 — `release.py cut` tags `origin/beta` of the umbrella and every declared repo as `release/<version>` (local),
  refusing a repo without `origin/beta` or a tag pointing elsewhere; manifest in `~/.w0m/releases/<version>/`.
- [ ] AC2 — `release.py worktree` checks the release out detached under `~/.w0m/releases/<version>/w0m`, copies the
  gitignored project links (`.infisical.json`, `supabase/.temp`) and installs locked dependencies.
- [ ] AC3 — `just deploy` / `deploy-all` ship a release by default (cut → worktree → verify → deploy from the worktree →
  re-verify → publish tags only on success); `deploy-local` / `deploy-all-local` force the working tree and print what
  they will ship; the confirm gate works inside a worktree.
- [ ] AC4 — A trial release: the offline suite passes inside the release worktree while the main checkouts are dirty.
- [ ] AC5 — First production deploy through a release by the owner; tags published; `/api/health` shows the release.

## Definition of Done

T473 is done when the default deploy ships only pushed, tagged code from an isolated worktree, a forced local deploy
is explicit and loud, and one production deploy has gone through a release.
