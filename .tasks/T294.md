# T294 — adopt workspace mode, and put the contract one level up

## Why

[[T268]] built workspace mode and closed at 7/7: `clients-policy.schema.json` carries `repos` and
`canonical_repo`, the mode is **derived** from whether `repos` is present rather than from a flag
that can disagree with the shape, a workspace `root` may be a non-repo, every declared repo must be
a git repo root, and ten probes hold it — including the red probe for a root that is a *subdirectory*
of an enclosing repo.

🔴 **And not one project uses it.** Measured 2026-09-01: all five registered projects are declared
**simple**, w0m included — and w0m's `root` is `wom7web`, so the estate's own seven-repo shape is
invisible to its own registry. A capability with ten passing probes and zero production callers is
indistinguishable, from the outside, from one that was never built.

The cost stopped being theoretical the same week. The AGY registration of BridgeRoad declared the
**simple** shape against a root that is not a git repo, and `just client-inventory` hard-failed at
exit 2 — *"registry integrity — measurement not attempted"* — for the whole estate. The workspace
shape would have passed on the first try. Nobody reached for it because nothing in the estate
demonstrates it.

🔴 **The harder half: [[T268]] AC7 and [[T265]] AC8 contradict each other for a client repo we do
not own.** AC7 decided the contract must live *inside a declared repo* so it is always git-tracked,
specifically so that **D32** — configuration at an untracked parent — is not expressible. For
BridgeRoad the only declared repo is `BridgeMvp`, i.e. `github.com/BridgeRoad/bridgeroad-app`, a
third-party org. That is not hypothetical: the AGY run wrote `.w0m/{sdlc,skills}.json` into it,
untracked and unignored on branch `dev`, carrying our Infisical invocation (`--env=beta`, the live
env), `gh_account: casualuser` and a roles block naming one person in five positions.

**Owner direction 2026-09-01** resolves it: *"for managed projects we should support our stack and
tools to be installed and integrated one level up from app code repos… meanwhile we can create there
also repo but own it in our GH org separately per project."* Making the workspace level a repo we own
satisfies all four constraints at once — one level up from app code, inside a declared repo,
git-tracked, and not in the client's repo. It is the only shape where AC7 and AC8 both hold.

🔑 **Orca makes this structural rather than stylistic.** Orca's headline feature is git worktree
isolation, and `git worktree add` requires a git repo. Orca has no workspace abstraction: no project
or workspace list in `Preferences`, panes keyed by absolute path, and the only BridgeRoad pane it
recorded is rooted at `BridgeMvp` — the repo — not the parent. So **a non-repo workspace parent can
never receive Orca worktree isolation**, which is the owner's own experience stated generally:
*"a lot of tools have issues if you map top folder to project and it's not git repo."*

## What already exists (do not rebuild)

- **Workspace mode itself** — schema, `client_inventory.py` branch, and ten probes ([[T268]] AC1–AC4,
  AC6). This ticket is **adoption**, not new capability. Do not re-derive the shape.
- **`wom7web/.w0m/`** — the estate contract. 🔴 **Do not move it.** `wom7api/scripts/supabase_limits.py:66`
  resolves it from a hardcoded `API.parent / "wom7web" / ".w0m" / "sdlc.json"`; relocating it breaks
  that reader silently.
- **The preserved BridgeRoad registration** — `project/clients/bridgeroad/PENDING-registration-T265-AC1.patch`
  plus the two generated configs. AC6 re-applies these; it does not start over.
- **D32** — the recorded debt this closes: `@wom` is not a repo, so its config is versioned nowhere.

## Definition of Done

`just client-inventory` reports w0m as a workspace of seven repos rather than as a single repo called
`wom7web`, and reports BridgeRoad as a workspace whose one app repo belongs to someone else — both
green, with the four simple clients' rows byte-identical to today's. The estate root is a git repo in
our org whose `.gitignore` provably swallows none of the seven, whose first commit was secrets-scanned
before it existed rather than after, and which carries the hook stack from that commit forward. D32 is
closed by something that fails when estate configuration goes unversioned again, not by the fact that
someone once committed it. The contract's location is declared rather than derived, so `wom7web` keeps
the estate's `.w0m/` and BridgeRoad keeps its own at the workspace root — while an *untracked* parent
remains as unexpressible as [[T268]] AC7 made it. `BridgeMvp` contains no w0m file, asserted directly
rather than inferred from a green gate. And a pane opened at a workspace repo receives a real git
worktree, measured in Orca rather than predicted from the fact that a repo now exists.
