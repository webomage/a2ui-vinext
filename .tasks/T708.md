# T708 — k7 WASM Git Navigation Browser in TUI with GitHub, GitLab & New LLM Git Flavours Support

## Summary

Build and integrate a WASM-compatible Git Navigation Browser inside the `k7` Rust TUI ecosystem (`~/Projects/'!self'/k7` / `k7hub` / `k7s`) with first-class provider adapters for **GitHub**, **GitLab**, and **new LLM Git flavours** (Hugging Face Hub repositories/datasets/spaces, Forgejo/Gitea/Codeberg, Agent-Git / GitButler virtual branches, and LLM prompt/skill/checkpoint git trees).

## Acceptance criteria

- [ ] AC1 — **Multi-Provider Git Remote & Provider Abstraction (`GitHub`, `GitLab`, `LLM Git Flavours`):** Implement a unified provider trait and URL/tree parser supporting GitHub (`github.com` REST/GraphQL/git), GitLab (`gitlab.com` & self-hosted API v4), and LLM-native Git flavours (Hugging Face Hub `hf.co` models/datasets/spaces, Gitea/Forgejo, and LLM agent checkpoint/worktree branches).
- [ ] AC2 — **Interactive TUI Git Navigation Browser (`ratatui` + WASM target):** Provide tree/blob/commit/branch/PR/diff keyboard navigation in the TUI with syntax-highlighted file preview, commit graph traversal, and LLM artifact inspection (model cards, `SKILL.md`, prompt diffs, safetensors/GGUF metadata headers).
- [ ] AC3 — **WASM Compilation & Browser/Portal Embed Readiness (`wasm32-unknown-unknown`):** Ensure the Git navigation core and TUI renderer compile cleanly to WASM so the same TUI git browser can run natively in terminal and inside browser/xterm/canvas surfaces.
- [ ] AC4 — **Automated Unit & Provider Fixture Tests:** Add unit tests covering GitHub, GitLab, and LLM Git flavour URL parsing, tree navigation, diff rendering, and WASM target compilation.

## Definition of Done

Per [`w0m-web/openspec/SPEC-AUTHORING-STANDARD.md`](../w0m-web/openspec/SPEC-AUTHORING-STANDARD.md):
- Acceptance criteria AC1–AC4 verified by `cargo test` and `wasm32` build check.
