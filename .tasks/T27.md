# T27 — SDLC-as-quests — automate team dev work

## Summary

Team members pick up **coding quests** (mapping real repo work — features/fixes/reviews —
onto the gamification `adventures/quests/units` already live) with **skills + tools
integration** (the T23 lifecycle + WebMCP/MCP tools + the SDLC skill pack) so a quest
carries its own explore→spec→TDD→review→verify→deploy pipeline. Needs a spec (overlaps T23
+ cp-guild-operations + gamification-v2).

## 🔴 RE-SCOPED 2026-08-11 ([[T203]] AC3) — the premise "already live" does not hold

This ticket's summary says it maps repo work onto *"the gamification `adventures/quests/units`
**already live**"*. Measured 2026-08-11 against the live database:

```
adventures 0    raids 0    quests 0    gamification.units 0    unit_members 0
adventure_role_slots 0     project_questmasters 0
```

**The SCHEMA is live; the DATA is not.** So this is not "wire up an existing system" — it is **the
first thing that will ever write to it**. That is a materially different job: it has to decide the
shape of a quest, who may create one, what a `source_ref` points at, and how a completed quest
reaches `xp_ledger` — none of which is "integration".

🔴 **And there is already an economy running without it.** `xp_ledger` holds **20 rows**,
`badge_awards` 3, with **zero quests in existence** — so something writes XP today on a path this
ticket does not know about. ⚠️ **Reconcile with that before writing a second XP writer**; whatever it
is will still be running the day this ships. Tracked as [[T203]] AC1.

✅ **Settled 2026-09-17 via Model A ([[AgDR-0022]]):** Owner selected pure event-driven gamification.
The 8 phantom hierarchy tables are retired, eliminating redundant data synchronization. Real engineering
events directly award XP to `gamification.xp_ledger` and `wallets`.
