# T424 — Orca as the one worktree factory: orca.yaml setup with computed estate parent shims; delete worktree_agent.py

## Summary

Phase 1 of the accepted plan
([report](../.agents/reports/2026-09-23-parallel-agents-isolation-and-merge-proposal.md) §0.2, §4
Phase 1, decisions Q3/Q4).

Root cause, measured 2026-09-23:
- Every Orca worktree for a w0m repo is the **main checkout on `beta`**.
- Orca has made one linked worktree estate-wide (`wom7mlx/eval-gemma4`).
- No w0m repo has an `orca.yaml`.

Blocker to just "using worktrees":
- Member repos contain **30 tracked symlinks that escape the repo** (wom7web 25, wom7api 4,
  wom7func 1), e.g. `wom7web/project/deps-policy.json → ../../project/policies/deps-policy.json`.
  They resolve only at `@wom/<repo>`.
- In Orca's layout (`~/orca/workspaces/<repo>/<name>`) and in T411's symlinked layout they **dangle**
  (scratchpad simulation). The pre-commit hooks read those policies.
- Resolution works when the worktree's parent directory carries a shim per escaping target, e.g.
  `~/orca/workspaces/wom7web/project → @wom/project`. The hand-made
  `~/orca/workspaces/wom7web/wom7api` symlink is an existing instance.
- Decision Q4: shims first (generated, outside every repo), cutover later ([[T427]]).
- Decision Q3: T411's `scripts/worktree_agent.py` is broken by construction (symlinked members, no
  bootstrap, no merge, second factory beside Orca), so **delete it**, no wrapper.

## Acceptance criteria

- [ ] AC1 — A committed `orca.yaml` exists in wom7web, wom7api and wom7func, with `scripts.setup` →
  `scripts/worktree_setup.py`, `scripts.archive` → `scripts/worktree_archive_check.py`, and
  `setupAgentStartupPolicy: wait-for-setup`. `worktree.sharedDirectories` is **not** used for
  `node_modules`.
- [ ] AC2 — `worktree_setup.py` **computes** the escaping tracked symlinks (`git ls-files -s` mode
  `120000` + resolve), ensures one shim per distinct target in the worktree's parent directory, and
  then verifies that **every** escaping link resolves. It stops, naming the link, if one doesn't. It
  never uses a hand-kept list.
- [ ] AC3 — `worktree_setup.py` also: verifies hooks resolve ([[T408]]), runs
  `pnpm install --frozen-lockfile` where a lockfile exists, copies the gitignored allowlist
  (`.infisical.json`, `.env*` if present), and prints a banner (worktree, branch, "land with
  `just land`"). Any failure exits non-zero, so the agent does not start.
- [ ] AC4 — `worktree_archive_check.py` refuses to archive while the branch has commits not on `beta`,
  unless forced. Tested.
- [ ] AC5 — End-to-end: `orca worktree create --repo name:wom7web --base-branch beta --name t424-probe`
  produces a worktree in which a trivial commit **runs the full hook set and passes**. The hook log is
  pasted into Status notes, then the worktree is removed.
- [ ] AC6 — Clean cutover: `scripts/worktree_agent.py` and the `worktree-agent*` recipes (root
  `justfile:126-134`, `wom7api/justfile:4303-4310`) are deleted. The two divergent
  `test_agent_concurrency.py` copies (root `scripts/tests/` vs `wom7web/project/scripts/tests/`) are
  collapsed to one. `just search worktree-agent` returns only historical docs.
- [ ] AC7 — `AGENTS.md` documents the launch command:
  `orca worktree create --repo … --base-branch beta --comment T<id> --agent <any>`.
