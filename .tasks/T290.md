# T290 — stage-4's actual work

## Summary

Stage-4 *"Money"* declares its exit as *"Invoices reconcile against real Stripe activity, and
`simulate_payment` is out of the production path"* — and names **[[T9]]**, which is
**AI token/neuron cost accounting from epic §11**. Different work, different epic. The stage has
never had a ticket that covers what it asks for; this is it.

⚠️ **Plan↔ticket drift, not a rounding note.** Stage-4 would have read as progress every time T9
moved, while its exit stayed untouched. Stage-2 had the identical defect on 2026-08-18 (it listed
T2, stage-1's ticket) and it was caught the same way — by reading the exit next to the ticket.

## What is actually there, measured 2026-08-26

**1 · `simulate_payment` is live, unreferenced, and duplicated by the real path.**
`client-api/index.ts:223` marks an invoice `paid` and credits a `gamification.billing_circles`
treasury. 🔴 **An authenticated client can call it on their own invoice** — the ownership check
passes, and the invoice is marked paid without anyone paying. There is **no caller in
`apps/*/src`, `packages/*/src` or `tests/`**; the UI never invokes it.
🟢 `stripe-webhook/index.ts` already does the same two writes on `checkout.session.completed`, and
its own comment says so: *"Add to gamification treasury (like simulate_payment did)"*. So the real
path exists and the simulated one is dead weight carrying a live risk.
⚠️ **Impact today is small and that is luck, not design:** one invoice, `platform=direct`,
already `paid`, no Stripe activity yet. Stage-4 exists to close this BEFORE money is real.

**2 · Nothing reconciles.** `invoices` holds 1 row with `external_invoice_id` NULL. There is no job
that compares invoices against Stripe, so the exit's first half has nothing to run.

## Definition of Done

An authenticated client calling the DEPLOYED `client-api` with `simulate_payment` is refused —
proven by the call, not by a grep, because an edge function keeps serving its last deploy. Invoices
are compared against real Stripe activity by something that exits non-zero when they disagree,
reports UNMEASURABLE separately from MISMATCHED, and refuses to report success over an empty
comparison. Exactly one code path credits a billing-circle treasury. Stage-4's exit is then wired to
a command instead of carrying a reason.

🔄 **AMENDED 2026-08-26 — a precondition was discovered, not a scope change.** Recorded here
rather than silently edited.
· **ADDED AC0.** Stripe is not connected: zero Stripe secrets among the 107 in `beta`, the deployed
webhook returns `500 Server config missing` on every call, and `invoices` holds one direct row with
no external id. ⇒ The reconciliation clause above **cannot be satisfied by engineering**, and this
ticket does not close until an owner connects an account.
· 🔴 **The DoD is NOT weakened to match what is buildable.** A reconciler written against an absent
account would compare an empty set to an empty set and report success forever — it would satisfy a
softened clause while proving nothing. The clause stays; the ticket stays open. That is the accurate
state, and an open ticket is cheaper than a green one that lies.

🔴 **Not done while stage-4 still names [[T9]].** A stage pointed at a ticket from another epic reads
as progress whenever that ticket moves, and the exit it actually declares never advances — the same
defect stage-2 carried until 2026-08-18.
