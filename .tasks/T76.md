# T76 — Verify observability_map.md rows against reality

## Summary

The 2026-07-17 sweep edited two `observability_map.md` rows on the decommission pattern; only `gamification-event-worker` was evidence-checked. Verify every row's infra + file/spec links exist/run — esp. **`telegram_integration`** (does a queue actually run on `wom7cfworkers`? edited on consistency, not evidence), `crypto_payouts` settlement APIs, `upwork_pipeline` cron, and dead `.spec`/path links. Folded into the T75 scheduled run.

## Acceptance criteria

- [ ] **AC1 — every row of `openspec/specs/observability_map.md` is evidence-checked**, not
      consistency-checked. 🔴 **This is the whole ticket**: the 2026-07-17 sweep edited two rows on
      *the decommission pattern* and only **`gamification-event-worker`** was actually verified —
      the rest were changed because they looked like their neighbours.
- [ ] **AC2 — `telegram_integration` is the first row done**, because it is the one edited purely on
      consistency: **does a queue actually run on `wom7cfworkers`?** Evidence is a live binding or a
      deployment, not a matching table cell.
- [ ] **AC3 — `crypto_payouts` settlement APIs and the `upwork_pipeline` cron are verified live.**
      ⚠️ For the cron, check the **account** level: Workers Free allows **5 cron triggers per
      account** and all 5 are on `wom7cfworkers` by decision — a 6th is refused with `code 10072`, so
      "declared" and "running" can differ.
- [ ] **AC4 — every `.spec` / file path in the map resolves.** Dead links are the cheapest half and
      the easiest to check mechanically.
- [ ] **AC5 — a row that cannot be evidenced is MARKED, not deleted or quietly left.** An unverifiable
      row is a finding; removing it loses the fact that something was believed to exist.
- [ ] **AC6 — the check is repeatable and folded into [[T75]]'s scheduled run**, so the map cannot
      silently rot again between audits.
