# T143 — Cross-browser support for `wom7ext`

## Summary

**Owner ask, 2026-07-26:** *"extension-ff was a Firefox version and potentially completely stale — we
should add P2 task for supporting different browsers for wom7ext"*.

The suspicion is confirmed by measurement, and it is stronger than "potentially stale":
`extension-ff/` is **abandoned**, not merely behind.

## Evidence that `extension-ff/` is dead (measured 2026-07-26)

| Signal | `extension-ff/` | `extension/` |
|---|---|---|
| Tracked files in git | **0** — fully gitignored (`.gitignore:62: extension-ff`) | tracked |
| Files modified since 2026-01-01 | **0** | active |
| `manifest_version` | **2** (deprecated) | **3** |
| `version` | `0.1.0` | `2026.12.25.495632` |
| `name` | "Context Agent for Upwork & LinkedIn" | "Webomage Agent" |
| On-disk size | 268K | — |

It is **untracked**, so nothing in git depends on it and deleting the directory is a local-only act.
It is also **Manifest V2**, which is the wrong starting point for a 2026 Firefox build regardless.

⇒ **Do not resurrect `extension-ff`.** Cross-browser support should be derived from the live MV3
`extension/`, and `extension-ff/` should be deleted from disk as stale (owner's call — it is
untracked working-tree content, not repo content).

Related finding already on record: the T135 preflight counted `extension-ff/package.json` as a
manifest until it was corrected to ask **git** instead of the filesystem — this directory has
already caused one wrong measurement.

## Acceptance criteria

- [ ] AC1 Decide and record the target browser set (Chrome/Edge Chromium, Firefox, Safari?). Do not
      start porting before the set is written down — Safari in particular is a different
      distribution model, not just a manifest difference.
- [ ] AC2 Establish how one codebase serves them: a build-time target switch over the single MV3
      `extension/` source. **Not** a second forked directory — that is precisely how `extension-ff`
      became stale.
- [ ] AC3 Firefox MV3 differences are handled explicitly: background `scripts` vs `service_worker`,
      `browser.*` vs `chrome.*` (polyfill or wrapper), and Firefox's add-on ID requirement.
- [ ] AC4 `extension-ff/` is deleted (or its useful remnants extracted first, if any — measure,
      don't assume there are none).
- [ ] AC5 A `just` recipe per target, declared in `project/stacks-policy.json` per T130's `commands`
      contract, so the build is not a raw `pnpm`/`web-ext` invocation.
- [ ] AC6 The e2e suite runs against at least one non-Chromium target. ⚠️ Depends on [[T142]] —
      `wom7ext`'s e2e specs are currently Gherkin and are being migrated to Gauge; do not build a
      second cross-browser harness on the vocabulary that is being retired.
