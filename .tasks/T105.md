# T105 — Type-check the Hono worker (wom7api/src)

## Summary

`wom7api/src/` — the Cloudflare Worker that `wrangler.jsonc` names as `main: src/index.ts`
(35 `.ts` files) — is **not type-checked at all**. [`wom7api/tsconfig.json`](../../../wom7api/tsconfig.json)
has `include: ["tests/**/*", "scripts/**/*"]` and never lists `src/`, so a deliberate type error
in `src/index.ts` produces zero tsc output. The pre-commit `deno-check` hook covers only
`supabase/functions/*/index.ts`, not the worker. Deliver a real type-check over `src/` and gate it
in pre-commit — **without a hook that passes while checking nothing** (the trap that made the gap
invisible in the first place).

## The real problem (grounded 2026-07-21, see Status notes)

The original framing ("install `@cloudflare/workers-types`; src/ may already be clean") is **drift**.
Reality:

- **wom7api is deno-managed** (`node_modules/.deno/` symlink farm), unlike wom7cfworkers (pnpm-flat).
  `@hono/zod-validator` will **not materialize into `node_modules` even after `deno install`**, so
  **both `deno check src/index.ts` and `tsc` fail to resolve the worker's npm imports** out of the box.
  This resolution issue — not a missing types package — is the ticket.
- The repo's worker-type convention (matching cfworkers) is the generated
  `worker-configuration.d.ts` via `wrangler types`. That file **exists** (506 KB) but is **stale**
  (missing current bindings, e.g. `TELEGRAM_BOT_TOKEN`) **and untracked**. `@cloudflare/workers-types`
  (deprecated) is not the fix.
- `@types/node` is absent, and `nodejs_compat` is on — Node globals need a home in whatever config we land on.

## Design (spec gate, 2026-07-21)

**Spec form:** ticket design note, not an OpenSpec change — this is a tooling/quality-gate change,
not a product capability (OpenSpec is for observable product behavior). The config's `openspec`
system degrades to an in-ticket design note here.

**Checker: `tsc` + generated `worker-configuration.d.ts`** (wom7cfworkers' proven pattern) — **not
`deno check`.** Spike evidence: deno always injects its own runtime globals (no Workers lib); with
`lib:["deno.ns"]`, `src/` went to **34 errors** from Deno/Workers global collisions. Deno can't
model a `nodejs_compat` Cloudflare Worker. wom7api uses deno *only* for the edge functions under
`supabase/functions/` (their own `deno.json`); `src/` is a wrangler/npm program.

**Resolution: pnpm owns root `node_modules`.** wom7api is already pnpm-managed
(`packageManager: pnpm@10.32.0`, tracked `pnpm-lock.yaml`, in T112's deps-policy). The resolution
wall (`@hono/zod-validator` unresolvable) was an **artifact of a stray `deno install`** (from the
deno.lock task) overwriting pnpm's flat layout with deno's `.deno` store. `pnpm install` restores
it and everything resolves. ⚠️ **Gotcha to document:** `deno install` at the wom7api root clobbers
pnpm's `node_modules` and breaks the worker check — the worker toolchain is pnpm; don't `deno
install` at root.

**Changes (all in wom7api):**
1. `tsconfig.worker.json` — `target/module es2022`, `moduleResolution: bundler`, `lib:["es2022"]`,
   `types:["./worker-configuration.d.ts","node"]`, `strict`, `skipLibCheck`, decorators on;
   `include:["src/**/*.ts"]`.
2. Add `@types/node` (devDep) — clears the 6× `TS2591` node-global errors (`process`/`Buffer`
   under `nodejs_compat`).
3. Declare secret env bindings — add a tracked `worker-env.d.ts` that augments the generated `Env`
   with the secrets `wrangler types` can't see (`TELEGRAM_BOT_TOKEN`, …) — clears the 3× `TS2339`.
4. `worker-configuration.d.ts` stays gitignored; the recipe **regenerates it fresh** (`wrangler
   types`) before each check so it never goes stale against `wrangler.jsonc`.
5. `just typecheck-worker` = `wrangler types && tsc --noEmit -p tsconfig.worker.json`.
6. Wire into `.pre-commit-config.yaml` as a hook scoped to `wom7api/src/**` (parallel to the
   existing `deno-check` hook for edge functions, which is untouched).

**Grounded error budget:** after 1–3, `src/` reaches **zero** (spike: 14 → 9 → 0 as each cause is
removed). Gate proof: `const _probe: number = "x"` in `src/index.ts` must fail the hook.

**Requirement → acceptance-criterion trace:** changes 1&2&5 → AC1 (src/ checked) + AC2 (imports
resolve); 4 → AC3 (types current); 2&3 → AC4 (zero); 5&6 → AC5 (recipe+hook) + AC6 (gate proof);
6 → AC7 (no edge-fn regression). Every AC covered; every change traces to an AC.
