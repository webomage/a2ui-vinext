# T145 — STATE.md self-maintenance

## Summary

**Owner ask, 2026-07-26:** *"let's make in our sdlc and git hooks triggers to update STATE.md"* and
*"we already should have save/load STATE.md skills"*.

`STATE.md` is the designated "read me first" handoff surface, and it is maintained **purely by
convention**. It went stale *within a single session* twice on 2026-07-26 — its repo table claimed 1
unpushed commit when there were 2, then 0; its "next action" pointed at a section that was already
finished.

## Surveyed state, 2026-07-26 — the gap is real

- 🔴 **There is NO save/load STATE skill.** `wom7skills/skills/w0m/w0m-handoff` looks like it but is
  **not** it: it emits a copy-pasteable **prompt** for a fresh context window, is **interactive**
  (asks 5 questions, so it can never run from a hook), **never reads or writes `STATE.md`**, and is
  **not in the T127 registry** (`.w0m/skills.json`).
- 🔴 **Zero mechanical enforcement.** `STATE.md` appears in **no** `.husky/*` hook, **no**
  `.pre-commit-config.yaml` entry, **no** justfile recipe and **no** `.w0m/sdlc.json` stage. Nothing
  can notice it is wrong.
- §0q of `STATE.md` has recorded "a STATE.md schema" as needed, unticketed, and *needing zero owner
  input*, across several sessions. This ticket is that item, with the owner's decisions attached.

## The load-bearing design constraint

`STATE.md` is mostly **editorial judgement** — the hot-10 ranking, "the lessons worth carrying",
which owner action matters most. **A hook cannot author that, and should not try.**

But the parts that actually went stale are **purely mechanical**: the per-repo dirty/unpushed/HEAD
table, gate exit codes, ticket counts. **Those should never be hand-written.** Split the file on
exactly that line: a marker-delimited *managed block* that is generated, and narrative prose that is
not.

## Owner decisions ALREADY MADE (2026-07-26) — do not re-litigate

1. **Phase: `pre-push`, BLOCKING.** Matches where `docs-check` already lives; a push is the natural
   handoff boundary, and commits are far too frequent to gate on a handoff file.
2. **Mode: VERIFY-ONLY — the skills do the writing.** The hook measures, compares, and fails with the
   exact diff plus the command to fix it. It **must not rewrite or re-stage `STATE.md` itself**: a
   hook that mutates a tracked file mid-commit needs re-staging and can fight the commit.

## Notes

- Keep the managed block **small**. Every fact in it is a fact that can go stale, and the point is to
  shrink the hand-written surface, not to mirror the whole file.
