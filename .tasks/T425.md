# T425 — just land / land root — the local merge queue and single committer to beta

## Summary

Phase 2 of the accepted plan
([report](../.agents/reports/2026-09-23-parallel-agents-isolation-and-merge-proposal.md) §3, §0.4,
§4 Phase 2, decision Q2).

Owner decisions:
- no PRs (solo operator);
- a local merge queue lands on `beta`;
- 2–3 concurrent agents.

Design: rebase-then-fast-forward, **one unit at a time** (a merge queue of batch size 1). The owning
agent resolves its own rebase conflicts in its own worktree.

Root repo (`@wom`: `.tasks/`, registers, policies, scripts): **one shared checkout, single committer**
`just land root`.

Measured:
- `TASKS.md` is touched by 35 of 70 root commits since T411 because the skills tell agents to render
  it.
- `STATE.md` is mixed: generated `W0M-STATE:BEGIN/END` block (lines 3-77) + hand-written handoff +
  generated archive.

**Ticket-ID race (found 2026-09-23):** IDs are "next free `T<n>.md`", with no lock. Two agents can
claim the same number, so `land root` must catch it.

## Acceptance criteria

- [x] AC1 — `scripts/land.py` + recipes `land <worktree|name>`, `land root [--ticket T<id>]`,
  `land --check` (`git merge-tree --write-tree` dry run vs current `beta`) and `land-status` (queue +
  predicted conflicts). **One lock** under the root `.git/`; a second `land` waits or exits, never races.
- [x] AC2 — Member land runs these steps, and every failure reports and stops:
  1. the main checkout is clean (fail closed);
  2. fetch;
  3. rebase the unit onto `beta` **in the unit's worktree**;
  4. regenerate the lockfile if touched;
  5. run the full pre-push gate set there;
  6. `--ff-only` `beta` in the main checkout;
  7. offer push;
  8. archive via Orca.
- [x] AC3 — Cross-repo lineage groups (same `--name`, `--parent-worktree`) land as a set in order
  `wom7api → wom7func → wom7web → root`, and the set stops at the first red step. The ticket's status
  change lands **after** its code.
- [x] AC4 — `land root` stages **only** the unit's paths: its `.tasks/T<id>.md`,
  `.agents/reports/*t<id>*`, and declared register appends. It never runs `git add -A`. Other tickets'
  uncommitted files are listed and left alone. Tested against the swept-files incident shape
  (`LESSONS.md:299-318`).
- [x] AC5 — Generated files (decision Q2): agent edits to `TASKS.md` and to `STATE.md`'s generated
  blocks are **discarded and regenerated**. `land` prints one line per file
  (`discarded agent edit to TASKS.md — regenerated from .tasks/`) and records it in a land log.
- [x] AC6 — Registers (`LESSONS.md`, `TECH-DEBT.md`, `ROADMAP.md`, `docs/DECISIONS.md`, and the
  hand-written `STATE.md` sections): additions-only hunks land. A hunk that rewrites or deletes
  existing lines stops the land and names the file.
- [x] AC7 — Policies and tooling (`project/policies/*`, `scripts/*`, `justfile`, `.agents/rules/*`)
  land only with an explicit `--include` plus a green verify. They are never implicit.
- [x] AC8 — `land root` runs the state-check the root repo lacks today (the root has no pre-push), and
  **refuses a new ticket whose ID already exists on `beta`** (the ID-race guard).
- [x] AC9 — Atomic caller update (AgDR-0025): `w0m-sdlc-start` / `-new` / `-archive` / `w0m-state-save`
  are edited in **wom7skills** (canonical), then stamped, relocked and synced to `.agents/skills` and
  the root copy, so agents stop running `tasks-render` / committing `state-save`. The `AGENTS.md`
  line "STATE.md blocked your push → `just state-save`, commit, push" is replaced with "`just land`
  regenerates it".
- [x] AC10 — Commits made by `land` set `W0M_LAND=1` (visible in the [[T423]] observer log).
