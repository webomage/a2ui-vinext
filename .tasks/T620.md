# T620 — Audit all required and actively used host, agent, and custom-fork tools across workstations

## Summary

Perform an end-to-end audit of every tool required by the `w0m` SDLC/deploy estate or actively used across our Linux (`Ubuntu 22.04` / `Bodhi 7.0`, `x86-64-v2`) and macOS (`Apple Silicon`) workstations. Today `project/policies/tools-policy.json` and `scripts/tool_usage_probe.py` govern 35 `brew`-centric host CLIs, leaving gaps across Linux package sources (`apt`, AppImage, `gh` releases), ephemeral `pnpm dlx` / `npx` / `uvx` invocations (`T617`), agent harnesses and MCP servers (`agy`, `claude`, `codex`, `orca`, `serena`), and custom-patched `w0m-pr/*` forks vs. stock auto-updaters (`T618`, `T619`).

## Acceptance criteria

- [ ] **AC1 — Complete Tooling Inventory & Usage Probe Coverage (`scripts/tool_usage_probe.py`)**: Enumerate all tools required or actively invoked across estate repos, `justfile` recipes, Git hooks, CI workflows, ephemeral `pnpm dlx` / `npx` / `uvx` runners, agent harnesses/CLIs (`agy`, `claude`, `codex`, `orca`, `orca-cli`), MCP servers, and desktop/security tools (`obsidian`, `virtual-fido`, `moksha`), extending `scripts/tool_usage_probe.py` where real invocation surfaces are currently uncovered.
- [ ] **AC2 — Required vs. Optional Classification & Cross-Platform Policy (`project/policies/tools-policy.json` & `scripts/tools_check.py`)**: Reconcile `project/policies/tools-policy.json` and `scripts/tools_check.py` so every inventoried tool is classified (`required: true`, `required: false` workflow-specific, or `out_of_scope` / retired) with accurate Linux + macOS install sources (`apt`, `brew`, `rustup`, `npm`/`pnpm`, `uv`, AppImage, `gh` release) and hardware/ABI floors (`glibc >= 2.35`, `x86-64-v2` non-AVX2 compatibility per `T617`).
- [ ] **AC3 — Update Channel & Custom-Fork vs. Stock Provenance Matrix**: Map each active tool's update mechanism—stock package manager / `just tools-upgrade`, pinned deploy binaries, self-healing fork overlay feeds (`webomage/orca` + `orca-overlay-update` per `T619`), or local distro backport packages (`moksha` `.deb` per `T618`)—flagging version drift, duplicate `PATH` shadows, or unpinned auto-update risks.
- [ ] **AC4 — Audit Report & Toolchain Gate Verification**: Store a structured audit report in `.agents/reports/` detailing findings, version floors, and cleanup/pinning actions across hosts, with `just tools-check`, `just tools-check-test`, `just tools-upgrade-test`, `just toolchain-chain-test`, and `python3 scripts/tool_usage_probe.py --check` exiting `0`.
