# T720 — Sync `w0m-api/deno.lock` and Enforce `--frozen=true` + Workspace Parity Across `deno-check`, `deno-test` & Pre-Commit to Prevent Release Worktree Mutation

## Summary

During `just deploy-all` (`release/2026.11.11-1794403906`), `just _deploy-all-chain` completed 100% of live deployments (`api`, `web`, `cp`, `me`, `demo`) and `smoke-live`, but `scripts/release.py verify` exited `1` before publishing git tags (`w0m-api: changed since checkout: M deno.lock`).

`w0m-api` maintains two separate Deno lockfile surfaces: `w0m-api/supabase/functions/deno.lock` (checked when `just deno-check` and `just deno-test` run inside `w0m-api/supabase/functions/`) and root `w0m-api/deno.lock` (where Deno 2 embeds `w0m-api/package.json` under `workspace.packageJson.dependencies`, and which `supabase functions deploy` resolves when `scripts/deploy_functions.py` invokes `supabase` from `w0m-api/`). When [[T717]] bumped `fast-xml-parser` to `^5.12.0` in `w0m-api/package.json`, no pre-commit or pre-push gate verified `w0m-api/package.json` ↔ `w0m-api/deno.lock` parity, causing `supabase functions deploy` to rewrite two lines of `w0m-api/deno.lock` inside the detached release worktree.

Synchronized `w0m-api/deno.lock` with `w0m-api/package.json`, built `w0m-api/scripts/deno_lock_parity_check.py` (`just deno-lock-parity` / `just deno-lock-sync`), enforced `--frozen=true` across `just deno-check`, `just deno-test`, and `w0m-api/.pre-commit-config.yaml` (`deno-check` + `deno-lock-parity` + `api-pre-push`), and published `release/2026.11.11-1794403906`.
