# T214 — Universal System Standards & RFC Adherence — Single Source of Truth for Schemas, Models, Interfaces, APIs & MCP

## Summary

Establishes an ecosystem-wide architectural mandate and technical enforcement pipeline ensuring that every entity, data model, database schema, REST/Edge API contract, MCP tool definition, and client interface across the `w0m` ecosystem strictly maps to an approved, recognized Standard or RFC (e.g. JSON Schema Draft 2020-12, OpenAPI 3.1, Model Context Protocol 2024-11-05, PostgreSQL SQL DDL, W3C WebMCP, OpenSpec 1.x, OAuth 2.0 / RFC 6749, Conventional Commits). Enforces **strictly ONE single source of truth (SSOT)** per domain with unidirectional generation/validation, permanently eliminating dual-definition drift and ad-hoc unvalidated payloads.

## Acceptance criteria

- [ ] AC1 — **System Standards & RFC Master Matrix (`docs/standards/SYSTEM-STANDARDS-MATRIX.md`)**: Comprehensive catalog mapping every architectural layer (Database, Internal RPC, Public API, MCP Tools, Frontend Types, Authz/RBAC, Prompt Skills, Logging/Telemetry) to its exact assigned RFC/Standard specification and version.
- [ ] AC2 — **Single Source of Truth (SSOT) Authority Graph & Rules**: Formal specification declaring the authoritative origin and unidirectional flow for every data shape (e.g. Postgres Migrations → generated TypeScript DB types; JSON Schema Draft 2020-12 → MCP Tool definitions; CSS Brand Tokens → `@webomage/ui` runtime). Any out-of-band hand-rolled duplicate shape is explicitly forbidden.
- [ ] AC3 — **Ecosystem Standards Audit & Gap Analysis**: Deep scan across `wom7web`, `wom7api`, `wom7cfworkers`, `wom7skills`, `wom7sec`, and `wom7ext` identifying all non-standard payloads, unvalidated endpoints, hand-rolled schemas, and contract drift between layers.
- [ ] AC4 — **Automated Standards Validation Gate (`just standards-check`)**: Linting and schema conformance tool integrated into `just sdlc-doctor` and pre-commit hooks to validate that MCP tool definitions, API specs, and schema declarations strictly parse against their declared RFC/JSON-Schema standards without errors.
- [ ] AC5 — **OpenSpec Proposal & Standard Authoring Blueprint**: Formal OpenSpec change (`openspec/changes/2026-08-14-universal-system-standards-and-rfcs/proposal.md`) detailing the lifecycle, deprecation path, and exception policy for introducing or updating standards across the ecosystem.
- [ ] AC6 — **Repository Meta-Asset Schemas (`TASKS.md`, `project/tickets/*.md`, `.w0m/*.json`)**: Formal schema contracts and automated linters for markdown and configuration meta-assets (JSON Schema for ticket frontmatter, row grammar for `TASKS.md`, and strict schema for `.w0m/sdlc.json`).
- [ ] AC7 — **Continuous Verification & Coverage Accretion Engine**: Measurement harness integrated into `just standards-check` reporting the ecosystem-wide standards coverage percentage (validated artifacts ÷ total system interfaces/assets) and guiding incremental schema adoption across all 6 monorepos.

## Definition of Done

Per [`../../openspec/SPEC-AUTHORING-STANDARD.md`](../../openspec/SPEC-AUTHORING-STANDARD.md):
Standards matrix documented, SSOT flow diagrams committed as `.mmd` graphs, audit completed, automated validation recipe live in `justfile` and passing cleanly, OpenSpec change validated, and synced across all tracking surfaces.
