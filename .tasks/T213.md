# T213 — Job-board sources fail open on a dead credential, and the credentials are unmanaged literals

> Split out of [[T94]] on 2026-08-14 while grounding it for the owner's connector ask.
>
> 🔻 **FILED AS P0, CORRECTED TO P2 THE SAME DAY — the original framing was wrong.** It was filed
> as *"four credentials leaked in live code"* on the strength of the shape alone. The owner pushed
> back — *"this looks like just a token automatically created, I never created it manually, let's
> review it closer"* — and testing showed the exposure claim did not hold:
>
> | claim as filed | measured |
> |---|---|
> | leaked | **both repos are PRIVATE**; neither live key appears in public GitHub code |
> | four live credentials | **two** live (Adzuna, Jooble), **one dead** (Reed → 403), one is an app id |
> | *"the fallback is probably the only value used"* | ✅ **confirmed**, by the code's own comment |
>
> ⇒ **Severity is set by exposure, and nobody had measured the exposure.** A credential-shaped
> literal in source is a strong *prior*, not a finding. The lesson is in `LESSONS.md`.
> ⚠️ The ticket survives because testing found something **worse than the thing it was filed for**,
> and unrelated to leakage — see finding 1.

## What was measured (2026-08-14)

Each key tested against its provider, with a deliberately-wrong key first to distinguish a
rejection from a rate-limit or an outage:

| credential | bogus key | committed key | verdict |
|---|---|---|---|
| Adzuna `app_id` + `app_key` | `401 AUTH_FAIL` | **`200`**, 790,740 results | 🟢 live |
| Jooble | `403` | **`200`**, real listings | 🟢 live |
| Reed courses | `403` | **`403`** — identical | 🔴 **dead** |

Provenance: introduced by `dcdad84` (2026-06-16, *"chore: put wom7api worker + migrations under
version control"*) — a bulk tree import, not a hand-authored line. Consistent with the owner's
recollection of never creating them manually. Neither live value appears in public GitHub code, so
they are **not** copied from a tutorial: they were provisioned for this project by someone, and are
now **unowned** — no one recalls creating them and nothing inventories them.

## 🔴 Finding 1 — all three sources FAIL OPEN, and one is failing right now

Every fetcher ends its error path the same way:

```ts
if (!res.ok) { console.error(`… returned ${res.status}`); return []; }
```

`job-aggregator.ts` then records `{ source, count: jobs.length }`. Its `catch` fires only on a
**thrown** error, so a returned `[]` is logged as **`count: 0` with no `error` field — i.e. a
successful fetch that found nothing.**

⇒ **Reed's credential is dead and the aggregator has been reporting it as a successful zero-result
fetch.** A dead credential, a rate-limit, a provider outage and a genuinely empty search are all
the same observation. This is [[T69]]'s rule exactly — *where an empty result and a failure look
the same, the code must distinguish them* — and it is why this ticket is worth keeping.

## 🔴 Finding 2 — the literal is the ONLY credential path, confirmed by the code itself

`job-aggregator.ts:42-43` carries an unresolved author note:

> *"Wait, Cloudflare Workers do not have `process.env`. The original `fetchAdzuna` might use
> `process.env.ADZUNA_APP_ID`. I will need to patch the utils to accept Env or use globalThis!"*

The patch was never made. None of `ADZUNA_APP_ID`, `ADZUNA_APP_KEY`, `JOOBLE_API_KEY`,
`REED_COURSE_API_KEY` is declared in `wom7api/worker-env.d.ts`, and none appears in any policy or
registry file. ⇒ **`process.env.X || "literal"` is not a fallback — the literal is the credential,
on every single call.** The `||` makes it read like a dev convenience, which is why it survived.

## 🟠 Finding 3 — `gitleaks` is blind to this shape

`gitleaks detect` over `wom7cfworkers` returns **0** hits for these values. The shape
`process.env.X || "<literal>"` is the most likely form for a real credential in application code,
precisely because it keeps working when the env is unset. This finding stands regardless of the
severity correction, and it generalizes beyond these three services.

## Acceptance criteria

- [ ] **AC1 — a failed fetch is distinguishable from an empty one.** Each source returns a typed
      result that separates *"provider returned no matches"* from *"the call failed"*, and
      `job-aggregator` records the failure in `results[].error` rather than as `count: 0`.
      ⚠️ **Verify by breaking a credential on purpose** and confirming the run reports a failure —
      a fail-open path that has never been observed failing is not proven fixed.
- [ ] **AC2 — the Reed credential is resolved.** Either re-provision it (and confirm `200`), or
      remove the source and say so. It is currently dead code that reports success.
- [ ] **AC3 — credentials reach the code by injection only.** Adzuna and Jooble move to infisical →
      worker secrets, declared in `wom7api/worker-env.d.ts`, consumed with **no `||` literal**.
      Resolve the `process.env`-in-Workers question the code comment raises, rather than inheriting
      it. No new `.env` (`CLAUDE.md`).
- [ ] **AC4 — a missing credential fails loudly at startup or first call**, naming the variable.
- [ ] **AC5 — the two live credentials are rotated, and ownership is recorded.** Not because they
      were published — the repos are private — but because **nobody knows who provisioned them or
      which account they bill**. Record the owning account in the same commit; an unowned live
      credential cannot be rotated in an incident.
- [ ] **AC6 — the duplication is resolved, not copied.** The same three files exist in both
      `wom7api/src/utils/job-sources/` and `wom7cfworkers/src/utils/job-sources/`. `wom7api` is the
      Workflow host; state what the other repo does instead.
- [ ] **AC7 — 🔑 a red-probed gate for the shape.** A rule that fires on a secret-shaped literal
      used as an `||`/`??` fallback for an env var. gitleaks misses all of these, so this is an
      `ast-grep` rule in `project/ast-grep/rules/` (structural — it matches the *shape*, not the
      value, so it keeps working after rotation). Ship it with a probe that proves it goes red and
      cite this incident, per `LESSONS.md`.
- [ ] **AC8 — sweep the estate with AC7's rule** and record the count, including zero.

## Definition of Done


Per [`../../openspec/SPEC-AUTHORING-STANDARD.md`](../../openspec/SPEC-AUTHORING-STANDARD.md):
a failed job-board fetch is distinguishable from an empty one — the defect that let sources fail open on a dead credential and look like a quiet market. Credentials reach the code by injection only, a missing one fails LOUDLY at startup or first call naming the variable, the Reed credential is resolved either way, and the two live ones are rotated with ownership recorded. 🔑 AC6 is the clause that stops it recurring: **the duplication is resolved, not copied** — the same three files exist in two places, so a fix applied once is a fix applied half. And AC7/AC8 give it a red-probed rule for the SHAPE, swept across the estate with the count recorded **including zero**.
