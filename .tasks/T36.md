# T36 — AI provider-adapter seam + lib hygiene

## Summary

Keep the `ai_models` registry + `routeChat`/`routeEmbed` **hand-rolled (the moat)**; make
the `provider → adapter` seam explicit behind them. **Provider policy (user 2026-07-12):**
`cloudflare` (raw-fetch, primary) + `google` (**resumable on FREE tier**) only — **no
third-party inference gateways/proxies** (don't route inference through anyone else's
aggregator) and **no new external keys**. Keep the Vercel AI SDK (`ai@7.0.9` +
`@ai-sdk/google@4.0.4`) **pinned** as the google-only *client* adapter (direct to Google
w/ our key — the drift that 404'd chat came from an unpinned bump; pinning mitigates);
re-verify the google adapter when resumed. Adopt **promptfoo** (or evalite) — a *local*
eval lib, not a proxy — for the eval harness (gap #3 / `scripts/ai-eval.ts`). x-ref:
guardrails=T8 (llama-guard, CF-native), durable memory=T7 (CF Agents SDK).

## Acceptance criteria

- [ ] AC1 — Explicit `provider → adapter` seam behind the hand-rolled registry + `routeChat`/`routeEmbed`
- [ ] AC2 — Provider set limited to `cloudflare` (primary) + `google`; no third-party gateways, no new keys
- [ ] AC3 — Vercel AI SDK kept pinned (`ai@7.0.9` + `@ai-sdk/google@4.0.4`); google adapter re-verified when resumed
- [ ] AC4 — promptfoo (or evalite) adopted as a local eval lib for `scripts/ai-eval.ts`
- [ ] AC5 — 🆕 filed 2026-09-18, owner request: *"we have to have all ai solutions with model
      selection possible to have real reasons to use specific model in that case."* Every
      model-selection decision, on **every surface**, cites a real, checkable reason — persisted
      where the next reader finds it (the `ai_models` migration or the ticket), not left in
      chat scrollback or research-doc prose. Two shapes, because not every surface is a chat model:
      - **Chat agents** (consultant/architect/admin tiers) — an `ai-eval.ts`/promptfoo scorecard
        (grounding, identity, refusal, latency, cost) run and its result cited by the swap migration.
        Gap measured 2026-09-18: `scripts/ai-eval.ts` already runs this and prints it, but the six
        `consultant_model_*`/`architect_admin_*` swap migrations cite none of its output — the
        harness exists and nothing points at a result.
      - **Non-chat surfaces** (classifier/guardrail, embedding, local inference) — `ai-eval.ts`'s
        pass/fail-on-chat-response shape does not fit these; each needs its own stated reason
        (fit-for-purpose + provider-policy compliance, since there's nothing to benchmark them
        against inside the CF/Google-only fence). Named gaps: [[T8]]'s `llama-guard-3-8b` has zero
        comparative reasoning recorded (picked for catalog fit, not evaluated against alternatives —
        see the AgDR this AC should produce); [[T225]]'s retired embedding default was never
        re-justified when chosen; `wom7mlx`'s local model pick (Gemma 4) sits outside the
        `ai_models` registry entirely, so it isn't even in scope for a citation today.
      ⇒ Closes when every live `ai_models` row (and `wom7mlx`'s local pick) traces to one of the
      two shapes above, and the AgDR/backfill practice this session flagged for the guardrail
      choice exists as a template other model swaps reuse.
