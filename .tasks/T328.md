# T328 — Resolve or re-tier the failing `stage2-schema` suite

## Summary

`reports/suites/stage2-schema.log`, read 2026-09-07:

```
status: FAIL   exit: 1   checks: 33
tier: offline  blocking: False
```

A suite that fails and cannot block is a suite that has been switched off without anyone deciding
to switch it off. It still runs, still costs time, still writes a log, and still reports FAIL —
and because `blocking: False` absorbs it, the FAIL is indistinguishable from noise. The estate has
been here before: [[T135]] left two gates advisory for weeks behind a vaguer one, and the lesson
recorded from it is that an advisory gate nobody promotes is a gate nobody reads.

**Two outcomes are acceptable and one is not.** Either the 33 checks are real and get fixed, and
the suite becomes blocking; or some are obsolete, and they are deleted with the reason. What is not
acceptable is the current state, where a red gate is load-bearing for nothing.

⚠️ **Do not promote it to blocking before triaging.** Turning a 33-check failure into a hard gate
mid-queue blocks every other ticket, and the estate's own rule is that a gate crying wolf gets
switched off — which is exactly how it got here. Triage first, promote last. Equally, **do not
adjust a threshold to make it green**: that is the same act as deleting a failing test.

## Acceptance criteria

- [x] AC1 — All 33 failing checks are triaged into: real defect · obsolete assertion · environment
      artifact (the `offline` tier cannot see the live DB). Counts published, summing to 33.
- [x] AC2 — Every "obsolete" verdict removes the assertion **with its reason recorded**. Deleting a
      failing check silently is indistinguishable from hiding it.
- [x] AC3 — Every "real defect" is fixed, or filed with a T-id linked from this ticket. None is left
      only as a log line.
- [x] AC4 — The suite ends the ticket either **green and blocking**, or explicitly and permanently
      advisory with the reason recorded in the suite config — not defaulted to advisory by inertia.
- [x] AC5 — If any check fails because the `offline` tier cannot reach the live database, that is
      reported as **unmeasurable**, distinct from failing (T242). A check that cannot run must not
      report the same word as a check that ran and found a violation.
- [x] AC6 — `just test` / `just test-all` surfaces the suite's tier and blocking flag in its
      summary, so the next reader sees "red but advisory" without opening the log.
