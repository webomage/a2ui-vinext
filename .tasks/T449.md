# T449 — Local full-stack development environment with *.w0m.local wildcard domains and SSL/TLS proxy

## Summary

Owner ask 2026-09-25: "launch local stack with all the apps and let's make it working with *.w0m.local local dev domain with ssl if possible, let's research how to launch full stack of apps locally".

Currently, local development relies on `just redev` which only launches the 5 Astro apps in parallel under individual localhost ports (`4321`, `4322`, `4323`, `4324`, `4325`), without SSL/HTTPS, without edge worker (`wom7func` on `8788`), and with auth middleware / cookie scoping strictly tied to `.webomage.com` or `.w0m.xyz`. Navigating across apps on localhost loses session context because cookies cannot share domain scope across different localhost ports or subdomains without proper configuration.

This ticket designs, verifies, and ships a unified local development stack:
1. `mkcert` wildcard certificates for `*.w0m.local`, `w0m.local`, and `localhost`.
2. Reverse proxy routing port 443 (HTTPS) and port 80 to all 5 web apps and `wom7func`.
3. Multi-app auth domain awareness (`isAdminDomain`, `isMemberDomain`, `cookieDomainFor`, `defaultPortalUrl`) supporting `*.w0m.local` with `.w0m.local` cross-subdomain session cookie scoping.
4. Supabase Auth `uri_allow_list` update to permit `https://*.w0m.local/**` redirects.
5. Unified orchestration commands (`just dev-stack`, `just stop-dev`) with process injection via Infisical.

## Acceptance criteria

- [x] AC1 — **Local SSL & Reverse Proxy Config.** A declarative Caddy configuration (`Caddyfile.local`) terminates TLS on port 443 using `mkcert` certificates (`~/.w0m/certs/w0m.local.pem`), proxying:
  - `w0m.local`, `web.w0m.local` -> `127.0.0.1:4321` (web)
  - `job.w0m.local` -> `127.0.0.1:4322` (job)
  - `join.w0m.local` -> `127.0.0.1:4323` (join)
  - `demo.w0m.local` -> `127.0.0.1:4324` (demo)
  - `cp.w0m.local`, `admin.w0m.local` -> `127.0.0.1:4325` (cp)
  - `func.w0m.local`, `api.w0m.local` -> `127.0.0.1:8790` (wom7func, port 8790 avoids T402 collision)
  with complete WebSocket upgrade support for Vite HMR.
- [x] AC2 — **Domain & Cookie Scoping in Auth Lib.** `cookieDomainFor(host)` returns `".w0m.local"` for `*.w0m.local` hosts; `defaultPortalUrl(host)` resolves `https://cp.w0m.local`; and `apps/cp/src/middleware.ts` recognizes `admin.w0m.local` as admin domain and `cp.w0m.local` as member domain. Tested via `packages/lib/src/auth/portal-redirect.spec.ts` (12/12 passing).
- [x] AC3 — **Subdomain-Aware Astro Bases.** `apps/job`, `apps/join`, and `apps/demo` support root path base (`/`) when accessed via dedicated subdomains in local development (preventing unwanted `/job/`, `/join/`, `/demo/` prefixes) when `SUBDOMAIN_DEV=1`.
- [x] AC4 — **Supabase Auth Redirect Allowed.** Supabase Auth project configuration has `https://*.w0m.local/**` and `https://*.localhost/**` added to `uri_allow_list` via the Management API.
- [x] AC5 — **Local Stack Orchestration Recipes.** `just dev-stack` starts all 5 Astro apps + `wom7func` + Caddy proxy concurrently under `infisical run --env=beta --silent`, and `stop-dev` cleanly terminates all associated listeners and worker processes.
- [x] AC6 — **Hosts Configuration Guide & Validation.** A command (`just hosts-check`) verifies `/etc/hosts` contains the required loopback mappings and guides setup if missing. Direct `*.localhost` domains also supported out-of-the-box without editing hosts.
