# T343 — unify estate resource governance

## Summary

Four disk-consuming subsystems — iOS Simulators (`simctl`), local LLM weights (Hugging Face/Ollama
caches), Tart/UTM virtual machines, and Docker storage — are each invisible to the others and to
any single audit. There is no `just` recipe that reports or reclaims across all four, so this host
was measured at **9.5% free disk (87.8 GB free of 838.6 GB)** on 2026-09-11 before anyone had a
combined picture of where the space was going: 147.5 GB Tart VMs + 128.6 GB Tart OCI image cache +
32.0 GB UTM (`evercred` 87.5 GB, `bridgeroad` 20 GB) + 74.5 GB Docker storage + 7.6 GB HF weights +
593.1 MB Ollama, against a simulator footprint already wiped to 29.3 KB. This ticket builds a
standing, unified audit/prune surface — `just resources` / `just resources-prune` — plus a
low-disk warning threshold, rather than another one-off cleanup pass.

## Acceptance criteria

- [ ] AC1 — `project/scripts/resource_monitor.py` reports combined usage across all four subsystems
      (`simctl list`/data dirs; HF cache `~/.cache/huggingface` + Ollama `~/.ollama`; `tart list` +
      OCI cache dir + UTM `~/Library/Containers/com.utmapp.UTM`; `docker system df`), each broken
      out by name/size, plus total host free-disk percentage
- [ ] AC2 — `just resources` (report-only) and `just resources-prune` (interactive/confirmed
      reclaim — simulator runtime wipe, dangling Docker images/volumes/build cache, stale Tart OCI
      cache entries) are declared recipes reachable per `AGENTS.md`'s "all stack tools via `just`"
      rule, not raw `simctl`/`docker`/`tart` invocations in tracked automation
- [ ] AC3 — A threshold guard warns (non-blocking, matching `commands.preflight`'s report-don't-block
      pattern) when host free disk drops below 10%, surfaced in `just preflight`/`just resources`
      output rather than only discoverable by manually running `df`
- [ ] AC4 — `evercred` and any other deliberately-unmanaged VM (per
      [[sandbox-substrate-direction]] / [[T265]] AC8) is reported on (visibility) but never pruned
      or reconfigured by `resources-prune` — the tool must not cross the managed/unmanaged boundary
      it did not decide

## Definition of Done

`just resources` gives one combined answer to "where did the disk go" across simulators, local LLM
caches, VMs and Docker, sourced from real measured commands rather than each subsystem's own
siloed tool; `just resources-prune` reclaims only what is safe and reversible (caches, dangling
images, stale runtimes) and never touches a VM outside its own declared boundary; a free-disk
warning is visible before the host is critically full, not after.
