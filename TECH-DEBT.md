# w0m — Tech Debt Register

Plain, git-tracked, diffable. **This is the single place for *decided* tech debt** — things we know
are wrong, why they matter, and what closing them looks like.

**How this works**
- One row per debt item. Add a row when you *decide* something is debt; delete the row when it's
  paid down (git history is the audit trail — no `resolved` flag to rot).
- `Tracked` links the TASKS.md row when the fix is planned work. Debt without a T-row is fine —
  it means "known, not yet scheduled".
- **Occurrences are not debt.** A `TODO` in a file is already in the code and greppable
  (`just tech-debt`). Only put something here once it's a decision worth carrying.

**Why this replaced a database** (2026-07-21): the previous `public.tech_debt` census store was
retired after measurement. Of its 69 rows, **78% were noise** — 33 from `.wrangler` build output
(third-party code: *"remove this when we drop Node"*), 7 from generated reports, and 2 were the
tech-debt dashboard page describing itself. The remaining "real" TODOs numbered **zero** in app
source. Its god-nodes were false positives by construction — `Logger`, `Layout.astro` and the Gauge
step registries are *supposed* to be highly connected. It also never marked anything resolved
(0 of 69), only ran on deploy, and the SQL embedded in the `w0m-sdlc-start` skill referenced four
columns that don't exist, so agents silently skipped consulting it. A markdown file in git is
reviewable, diffable, needs no credentials, and cannot drift from the repo it describes.
